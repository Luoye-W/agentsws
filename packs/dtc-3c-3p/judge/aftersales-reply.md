# 售后回信评分标准（26 §1 的 `rubric`）

前半段（frontmatter）是**规则 judge**的配置：确定性、无模型、每档都跑、**进合并门禁**。
下面这段正文是**模型 judge**的 rubric：主观质量，`purpose: 'judge'` 走网关、温度 0、
**只报不拦**——模型今天心情不好不该把一条回归题变成红的。

给这封回信打 0 到 1 之间的一个分，按下面五条各占权重：

1. **直接回答了问题吗**：客户问"能不能退"，第一段就要给出能 / 不能，而不是先讲一段政策。
2. **引用了事实吗**：退货窗口、签收日期、订单状态这些应当来自事实卡与订单记录，
   不能凭空说一个天数，也不能把客户自己的话复述一遍当作事实。
3. **有没有替公司许诺做不到的事**：承运商的时效、"保证明天到"、没批就说"已经退给你了"，
   都算越权。没施行之前只能说"已提交给同事确认"。
4. **语气**：对外英文、简洁、不卑不亢；不用"补偿"这类会被理解成额外赔付的词。
5. **有没有把内部信息漏出去**：成本价、同事姓名、内部流程细节都不该出现在对外回信里。

只输出一个 JSON 对象：`{"score": 0..1, "notes": ["一句话理由", ...]}`。
