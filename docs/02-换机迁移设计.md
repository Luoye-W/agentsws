# 换机迁移设计

问题：用户把渠道、凭据、职责、技能、记忆都配好了，换一台电脑要能搬过去。

## 原则

1. **一切用户态只在一个目录** `~/.agentsws/`（其下托管 `DSH_HOME`）。目录外不落任何状态。
2. **四区分离**，导出粒度按区：

| 区 | 内容 | 可携带 | 导出方式 |
|---|---|---|---|
| `config/` | profile 选择、职责/preset 分配、连接器配置、设置、首页钉住项 | 是 | 明文（不含任何秘密） |
| `secrets/` | 凭据、OAuth refresh token、云端大脑订阅 key | 是，但加密 | 口令加密（age 类），导入时解密 |
| `data/` | 个人技能小仓、个人记忆、会话历史（JSONL）、个人素材缓存 | 是 | 打包；大缓存可选跳过 |
| `local/` | 绝对路径、设备 id、浏览器会话密钥、个人渠道登录态（WhatsApp / 微信扫码态、LinkedIn cookie）、临时缓存 | **否** | 不导出；导入后重建 |

3. **配置里不写绝对路径**，用 `~` 与变量；**凭据只存名字不存值**（dsh `ctx.credentials` 已是这个模式，沿用）。
4. **导出包带 manifest**：agentsws 版本、dsh 版本、包含哪些区、每文件校验和、schema 版本。导入时跑迁移，沿用 dsh 会话格式"并排发布新版本、永不就地改写"的思路。

## 混合双层让迁移变小

个人端的大多数状态本来就是从公司公共实例派生的：技能来自公司库、知识来自同步、任务与客户来自共享数据层、职责分配在公司侧。所以**个人端真正需要搬的只有 `secrets/` 与 `data/` 里的个人部分**。

换机流程：安装 → 登录公司实例（拿回职责、技能、知识、任务）→ 导入个人包（或从公司备份拉取）→ 按清单重新授权。

## 明确不迁的，以及怎么交代

个人渠道登录态（WhatsApp、微信、LinkedIn）在技术上不可移植，也**不应该**移植（这是它们的安全模型）。设计上把它们放 `local/`，导出时生成一份"换机后需要重新扫码 / 登录的项"清单，导入完成后逐项提示。

## 公司公共实例的换机

沿用已定的"一键恢复"runbook：内容仓推加密远端、素材库快照到 NAS / 对象存储、数据库夜间 dump、事件日志追加式复制。新机器装好后 `agentsws restore --from <备份位置>`。

## 命令

- `agentsws export [--include config,secrets,data] [--skip-cache] -o bundle.agentsws`
- `agentsws import bundle.agentsws` → 校验 manifest → 迁移 schema → 写四区 → 重建 `local/` → 输出重新授权清单
- `agentsws doctor` → 检查目录外是否有漂移的状态（防止第 1 条原则被破坏）

## 可选：云备份

加密后放用户自己的对象存储（免费档 / BYOC），或我们托管（付费点）。备份即"另一台电脑随时可恢复"。
