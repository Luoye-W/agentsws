## 结构：先急后缓

1. **页头**：图标 + 名字 + 一行状态「3 张等你定 · 5 件在办 · 今天 1 个待办」，每段能点（点了跳到下面并筛好）；右边「⋯ 岗位设置」。真缺必需连接时，页头下一行细横幅；不缺不出。
2. **交给它**：一行输入 + 一排建议，点进去才展开成三行，带「附件」「职责：自动」。
3. **要你处理**：这个岗位等你批 / 等你选的卡，横排最多 3 张，卡上直接批；「全部 N 张」进卡片流。没有就一行字。
4. **工作**：事项 + 待办 + 排期合成一份，Notion Database 那样一条视图栏；默认列表，按「等你 / 进行中 / 等别人 / 已完成（折叠）」分组；视图、筛选、分组记在这个岗位上。日历只显示本岗位的。
5. **数字**：每条职责一行、3–4 个数，要看图再点开。数据已由接口中台满足的照常出，不催连接。
6. **页签三个**：工作 / 记录 / 设置。

## 我自己定的几处（可改）

- 列表第一组叫「等你」不叫「等你批」：里面除了要你批 / 选的卡，还有你自己的待办（如「私信版主」）。悬停问号有解释。
- 状态图标颜色 + 形状双编码：等你 = 橙色圈里一点、进行中 = 绿色半圆、等别人 = 蓝色虚线圈加钟、已完成 = 绿底勾（色弱也分得开，同 docs/36 §7 的思路）。
- 每行前面一个灰色小图标区分「卡 / 事项 / 待办 / 排期」，悬停才说是什么。
- 数字带不放火花线，只放数和涨跌；图在「看图表」里。
- 快捷视图在稿里只画 Reddit 这两个（自家版待处理、发帖排期）；社媒岗位就是「排期日历」「群发」，红人是「红人工作台」，B2B 是「开发信」，同一个位置。
- 空岗位不画空图表、不铺步骤：每块一行字，引导全压在「交给它第一件事」。

## 要 Luoye 定的事

1. **「要你处理」和列表「等你」组会重复同几件事。** 我的建议：留着两处——上面是能直接批的快捷动作，下面是全量清单。另一个选择是去掉上面那条，只留列表。
2. **列表第一组叫「等你」（批 / 选 / 你自己的待办）可以吗？** 工作单写的是「等你批」，但那样你的待办就没地方放。
3. **职责「Reddit 运营」（`social.reddit`）跟岗位同名。** 稿里先叫「自家版」（我们自己的 r/INMO），要不要正式改名？叫什么？
4. **设置 · 连接里「可选」那几行**现在是摊开的；要不要收成一行「还有 3 个可选」，点了才展开？
5. **一条职责移走 / 拆出去时**，它手上没做完的事跟着走，还是留在原岗位？稿子按「跟着走」画。
6. **默认视图是列表**（工作单定的）。如果某个岗位以排期为主（社媒），要不要让岗位模板自带默认视图（比如社媒默认日历）？
