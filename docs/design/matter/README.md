## 结构

### 1. 短标题
- 标题是 AI 起的总结，中文 16 字左右：「Rollout 英文首页 · 深色科技风」。原来是用户原话前 120 字，四行大字。
- 首轮开跑时用便宜模型起；起好之前先显示原话前 20 字加「…」。点标题就地改，人改过的不再自动覆盖。
- 原话全文是对话第一条（右边气泡），一字不丢。左栏事项名也是这个短标题，不再截半句。
- 这会替代 WP259 的「首句 ≤40 字」口径（决策 167 要跟着改）。

### 2. 页头一行（约 72px，原来约 260px）
- 标题下一行灰字：**职责小标签**「Shopify 网页模板 ⇄」（点了换）· **状态**（在跑 / 进行中 / 等你批 / 卡住了 / 已完成，小点和左栏同一套颜色）· 参与者头像 · 最近活动。
- 「换职责 / 复制链接 / 归档 / 关闭事项」收进右上「⋯」。在跑或有卡等你批时「归档」灰掉，右边一句为什么。
- **待办有才出**：灰字行尾一个蓝色「3 个待办」，点开就在页头下面展开、能勾；没有就什么都不出。
- 结果摘要（`context.summary`）不再单独一行，就在对话里。固定记录（pinned）也挪进「⋯」或右栏（稿子没画，Rollout 这件事没有）。
- 页头吸顶，往下翻时一直在。

### 3. 对话式时间线（像 Claude）
| 事件 | 怎么画 |
|---|---|
| 你说的（`human_message`） | 右边气泡，超过 6 行先收起；钟点悬停才显 |
| AI 说的（`agent_message`） | 左边，职责头像 + 名字 + 钟点，正文按 Markdown（标题、列表、行内代码、链接）；长回答先露一屏，「展开全文」 |
| 预览好了（`preview`） | 嵌在那条 AI 消息里的结果卡：缩略图、主题名、「未发布 · 线上没动」、改了几处、检查结果；主按钮「打开预览」，次按钮「发布上线」（点了出审批卡）、「看改动」小链接 |
| 审批 / 选择（`card`） | 内嵌成能直接批的卡（琥珀边）；批过缩成一行「你批了 · 发布上线」 |
| 卡住了（`blocked`） | **是最新一条时是卡**（红边，「去连接」「接着做」）；连上并接着做之后缩成居中一行「卡在缺连接 · 14:29 已连上」 |
| 跑了一次 / 换了职责 / 路由（`run`、`status`、`route`） | 居中一行灰字：用了多久、读 / 改了几个文件、检查结果、推送。点开是步骤清单（读了哪些文件、改了哪些、主题检查、推成未发布主题） |
| 运行中 | 左边一条「正在做…」+ 当前一步（「正在跑主题检查 · 第 5 步」，字面上有一道流光），点开是实时步骤；头像外圈呼吸 |
| 日期 | 同一天只出一次分隔线 |

### 4. 输入卡（Luoye 10-08 追加两条）
- 明显的圆角卡：一圈正文色 14% 的边 + 两层阴影，明暗都看得清；两行高，打字自动长高（最多约 10 行），聚焦时边框加深。
- 发送是卡内**右下角的圆形箭头**：空时灰，有字变主色；运行中变成墨色方块「停」，有字时又变回箭头（发出去排在这一轮后面）。原来的「发」字按钮去掉。
- 「↵ 发送 · ⇧↵ 换行」一行小字，只在聚焦或有字时出现。
- **问 AI 并进来**：左下「私聊 AI」开关。打开后整张卡变蓝、顶上一行「只你看得见，不会让它去做事」、发送钮也是蓝的，一眼和「交代给 Agent」分开。原来底下单独那一块「问 AI」去掉。
- 左下预留「+」附件、「@」提及两个图标位（悬停说「以后」）。
- **建议输入**：框是空的、又有合适的下一步时，浅灰字直接显示在框里，右边一个很小的「Tab」键帽；按 Tab 收下变成正文（正常颜色），开始打别的字建议就消失。没有合适的就是普通占位字「回复，或交代新要求…」，不硬给。`states` 稿第 ⑤ 组有「有建议 / 没建议 / 收下之后」并排对比。

## 我自己定的几处（可改）
- AI 正文不套气泡，直接排在页面上（像 Claude）；你的话才有气泡。长文好读，左右也分得开。
- 过程事件默认收起；「跑完了」那行用绿色勾、「卡在缺连接」用琥珀插头，别的灰色。
- 预览卡的缩略图画的是商家自己站的颜色（深底红点缀），不是工作台的颜色。真做时用预览页截图或主题配色拼。
- 运行中的「当前一步」用人话（「正在跑主题检查」），不露工具名；工具名只在开发者视图。
- 已完成（关闭）的事项输入框照样留着，占位字「这件事已关闭，说一句就重新打开」。
- 私聊 AI 的一问一答画成蓝色虚线框、带锁、右上角能关；稿子按「关掉就没了、不进事项记录」画。

## 要 Luoye 定的事
1. **短标题谁起**：A 首轮开跑时用便宜模型单独起一次（稿子按这个，最快出来、几乎不花钱）；B 从首轮结果里让主模型顺手给。建议 A，起不出来退回原话前 20 字。
2. **私聊 AI 的问答留不留**：A 关掉就没了（稿子按这个，最干净）；B 留在对话里但只自己看得见、默认折叠。建议 A，真有用的让人一键「转给 Agent」。
3. **建议输入从哪来、什么时候不给**：建议只从三个地方来——① AI 最后一句里明说的下一步（「要发布说一句」→「发布上线」；影响面里「只想首页深色跟我说」→「把深色只用在首页」）；② 有卡等你时的主按钮动作（等你批 →「批准发布」）；③ 固定规则（卡住了缺连接 →「连好了，接着做」）。**不给**的情况：正在跑、刚发完一句、AI 最后一句没有明确下一步、建议会花钱或对外发东西（发布、给客户回信）时只给字不自动发——按 Tab 也只是填进框，还要人按发送。建议同意这三处来源，规则 ① 靠 AI 在回复里带一个结构化的「下一步」字段，不从正文里猜。
4. **发送钮怎么取舍**：A 只要图标（稿子按这个，Luoye 10-08 原话）；B 图标 + 悬停提示「发送（Enter）」。建议 A + 悬停提示，不占地方。
5. **私聊 AI 的入口形式**：A 左下小开关（稿子按这个，一眼看得出现在是哪种）；B 模式下拉（「交代给 Agent / 私聊 AI」）。建议 A；以后要是还有第三种模式再改下拉。
6. **过程事件**：默认全收起（稿子按这个），还是最近一次默认展开？建议全收起，运行中那一条除外（运行中默认露当前一步）。
7. **已完成的事项**：输入框留着（说一句就重开，稿子按这个）还是收成一个「重新打开」按钮？建议留着。
8. **决策 167**：WP259 的「首句 ≤40 字当标题」改成本稿的「AI 短标题 + 原话进第一条」，需要你点头后改决策记录。
