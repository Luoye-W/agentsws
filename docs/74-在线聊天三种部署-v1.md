## 0. 一句话

一份转发器（`packages/chat-relay`），三种部署，**职责只有转发**——不存对话正文、
不跑 AI、不判任何业务；两档同一个挂件、同一段嵌入代码，切档 = 换"对面是谁"。

| 路 | 适合谁 | 上限 | 对面是谁 |
|---|---|---|---|
| 官方托管（免费） | 大多数人 | 每月 200 个对话 | 商家本机（主动外连） |
| 自建（Docker / 自己的 Cloudflare） | 想自己掌握或不想要上限 | 无上限 | 商家本机（主动外连） |
| 客服增值服务（30 积分/月） | 电脑经常关机 | 无上限 | **托管实例**（同一份 `apps/server`） |

修订第 2 条：**没有第二份云端客服运行时**（WP124 原案的 `SupportTenantDO` 已删）。
收费在线档 = 按 `packages/standby` 的方式把**同一份 `apps/server`** 托管在云端
（Node / 容器形态），订阅后转发器把对端从商家本机换成托管实例；
本机上线后按现有同步机制对齐。这一刀顺手收掉了 WP114 留下的
「在线值守在 Cloudflare 形态未开」——托管实例跑在哪见 §5。

## 1. 三条路对照

| | 官方托管 | 自建 Docker | 自建 Cloudflare Worker |
|---|---|---|---|
| 部署 | 我们运维，`/relay/<ws>/*` | `docker compose up -d`（`deploy/chat-relay/`） | `wrangler deploy`（`deploy/chat-relay/worker/`） |
| 计数 | limits.json：`chat.conversations.monthly = 200` | 无 | 无 |
| 持久化 | DO storage（SQLite）：配对哈希、计数、留言密文、挂件外观 | 卷上 JSON（同前四样） | 内存（redeploy 丢未拉走的留言） |
| 密钥 | 配对密钥 / 留言密钥由云侧签发，只显示一次 | 首启打印一次，卷里只有哈希 | 自己 `wrangler secret put PAIRING_TOKEN` |
| 离线留言 | 密文入箱、7 天、50 条上限 | 同 | 同（内存） |
| 适合 | 大多数人 | 长期自用 | 试用 |

自建部署的逐步说明（给非运维）：`deploy/chat-relay/README.md`。

## 2. 协议（本机 ↔ 转发器的长连接）

商家本机**主动外连**（商家电脑不开端口、不要公网 IP）。帧是 JSON 文本。

**握手**：连接上来后第一帧必须是 `hello`——`{protocol_version, workspace,
pairing, peer: 'server'|'hosted', config?}`。转发器三道校验：
1. **版本协商**：`supported = [1]` 取交集，空即 `hello_err{version_mismatch, supported_versions}`；
2. 配对密钥 sha256 哈希比对（错与工作区不存在回同一句 `bad_pairing`，不给探测的人多余信息）；
3. 路径里的工作区与 hello 里的必须一致（一条连接冒充不了两个工作区）。
同一工作区同一类对端重连踢旧（幂等）。**两头都在时托管实例赢**——
它连着就说明订阅在效，且它 7×24 在线。

**投递解耦**（docs/72 §6.3 #1，FR-047）：访客侧 `POST /message` 只确认收到
（`202 {status:'forwarded'}`），回复从 SSE / 长连接异步回来。
Workers 的请求生命周期扛不住同步等一个 60 秒的话轮。

**一次话轮恰好一条回复**：转发器给每条访客消息编 `turn`；`reply` 帧必须带它，
第二条同 `turn` 的回复判 `turn_already_answered` 丢弃。**被废弃的生成照常计费**
——真实成本不隐藏（计费发生在发起生成那一侧的模型网关里，转发器看不见钱）。
话轮之外的插话（教 AI 的改写）走 `note` 帧，不占话轮账本。

**打字信号只承载布尔**（FR-035）：`{type:'typing', session, active}`——
`parseClientFrame` 结构性拒收任何多余键（输入框内容、字符数、片段都不可能进来）；
访客上报节流 ≤1 次/2 秒、停止判定 3 秒；对客的「正在输入」是三个点的纯动画。

**心跳**：`ping`/`pong`，15 秒一拍；本机侧两个心跳没收到任何帧即断线重连，
指数退避（1s 起步 ×2，±20% 抖动，上限 60s）；密钥错（`hello_err`）不重试——
重试只会把对端刷屏。

**四道门**（访客面，与本地档公开访客面同款）：来源白名单（**空 = 全拒**；
服务端自己读 Origin，请求体里没有 origin 字段，连误读都不可能）、限流
（建会话按来源 10/min·60/h，发消息按访客）、访客令牌（HMAC，不落库）、
凭据不进 URL（SSE 用 fetch + ReadableStream）。

## 3. 200 上限与「一个对话」的口径（修订第 4 条）

判定在 `packages/chat-relay/src/quota.ts`，数据在 `packages/metering/src/limits.json`：

- **访客发出第一条消息才算一个对话**；挂件加载、开会话都不算；
- **同一访客 30 分钟内刷新 / 重开算同一个**——这个窗口同时是「在途」的定义：
  **到顶后已在进行的会话放行到结束，只拦新会话**（窗口外即新对话，被拦）；
- **商家设置页试聊不计**，AI 费用照算（费用在本机那一侧）；
- **到 80% 提醒**：只在跨越那一刻发一次（幂等锚），落成站内提醒行，
  owner 从 `GET /v1/chat/relay/status` 读走；
  **IM 推送依赖云侧 IM 通道（还没建），本轮留口**——这是本次实现与修订原文的
  一处差距，见 §7；
- **订阅 `support.service.monthly` 的不受限**（计数照记，报表要看）；
- 改 200 这个数 = 改 `limits.json` 出一个版本，不用发版。

## 4. 离线留言（修订 §B）

本机不在线（或免费额度到顶拦新）→ 转发器对访客回 `{status:'offline'}` →
挂件自动切留言表单（邮箱必填 + 问题必填 + 订单号选填）→ 留言**以密文暂存**
转发器（AES-256-GCM，密钥 = 配对时签发的那把留言密钥；不做端到端是
21 §4.1 定过的口径，这里是「静态加密」那一层）→ **最多 7 天、每工作区 50 条**
（满了顶最旧）→ 本机上线后第一帧 `pull_offline` 拉走并**清除**（拉走即删，
不留第二份），进「消息」页（`MessageSource = 'chat'`，63 的扩展位只加这一格）
按邮箱续聊；求助触达率 100% 的兜底仍是邮件（没绑 IM 时静默丢失 = 0）。

**隐私**：转发器看得到过路内容但**不落盘**——对话正文在转发路径上没有任何
写入存储的调用（Proxy 记录守卫测试钉住）；落下去的只有配对哈希、计数、
留言密文与挂件外观。

## 5. 托管实例跑在哪（WP128 改定：Cloudflare Containers）

> **09-23 Luoye 改定**：托管实例只放 Cloudflare 或 Vercel（他只想管这两个平台）。原先这一节
> 推荐的「一台小机器（Node 容器）按 `packages/standby` 托管」**作废**，改落 **Cloudflare Containers**
> ——同一个 Cloudflare 账号、同一份账单。全文（上游评估、费用、上线步骤、以后改共享容器）在
> **`docs/64` §13**，这里只留要点。

- **每个订阅的工作区一个容器**（`HostedInstanceDO`，`idFromName(工作区)`），容器里跑**同一份
  `apps/server`**（`deploy/Dockerfile.hosted`）；没订阅的不起容器。
- **常驻不休眠**：官方没有「永不休眠」的开关（`sleepAfter` 只是「多久没请求就停」），所以
  `HostedInstanceDO` 的 alarm 每 3 分钟打一次容器的 `/v1/health`——心跳 + 保活；没在跑就按退避重起。
  WP124 报告否掉 Containers 的理由（冷启动对聊天窗不可接受）就这样解掉：订阅了的容器不睡。
- **对端切换**：容器里的 `apps/server` 以 `peer: 'hosted'` 外连转发器，用的是**托管自己的那把配对**
  （`hrp_…`，与商家本机那把分开验）。转发器两格对端并存：**托管在就给托管，否则给本机**——
  本机开机不再把托管挤下线（WP124 的 `RelayCore` 只有一格，后连的顶掉先连的，与本节原文「托管赢」相反，WP128 修了）。
- **起停跟着订阅**：开通 → 起；取消 → 当期用完再停；欠费 → 30 天宽限内照跑，宽限到期停；
  停了快照留 30 天。
- **数据**：容器盘是临时的，`apps/server` 每 6 小时 + 收到 SIGTERM 时把工作区包推回 R2，起来先拉最新那份；
  商家本机「用本机这一份更新云端」/「把云端那一份取回来」两颗按钮在聊天窗设置页第三项。
- **AI 费用**：托管实例的默认模型换成「agentsws 云（用积分）」，走 `/v1/ai/*`、按 `ai` 块扣这个组织的积分。
- **容器费用**（每工作区、常驻一个月、按官方单价）：basic 约 **$8.5**、lite 约 **$2.3**；30 积分 ≈ $4.2。
  **basic 盖不住月费**，选哪档要 Luoye 定（WP128 报告第 3 节）。

## 6. 订阅与计费

- 订阅复用 WP118 引擎：`subscriptions.json` 里 `support.service.monthly` 翻
  `available: true`（同价同机制 30 积分 / 月）；开通当场扣第一期（幂等键
  `chargeKeyOf`），取消当期用完为止，余额不足进 30 天宽限（服务暂停、数据不动），
  宽限不解除转发上限。
- **第三块改名通用**：`pricing.json` 的块 `kol_service` → `service`（修订第 2 条
  点名提醒）；`PricingBlock` 契约同步，`pricingBlockOf` 对老数据里的
  `kol_service` 归一化、对 `*.service.*` 前缀兜底；工作台 / 运营后台的分组
  文案同步——红人与客服两个增值服务归同一块。

## 7. 工作台与不做清单

- 「网站在线客服」职责默认启用；新页「聊天窗」：外观（主色 / 欢迎语 /
  允许域名 / 求助等待时长——全预设与单行）、转发方式三选一、嵌入代码 + 预览、
  测试连接、本月对话数；进行中的对话 + 对话界面。
- **对客直发入口数 = 0**（修订第 1 条）：界面上只有「教 AI」——商家用中文说一句，
  AI 改写成客户语言、以 AI 口吻回；指导原文泄漏守卫（WP125 的
  `evaluateLeakGuard` / `containsInstructionLeak`）必须带上；
  有 grep 守卫测试（`apps/workstation/test/no-direct-reply.test.ts`）钉住；
  沙盒页的接管开关同步拆掉。
- 求助等待时长：默认 30 秒，可自定义 10–600（快捷项 30s/1/3/5/10 分钟），
  非法回落 30；**死线在求助那一刻固化**进会话行（`assist_deadline_at`），
  巡检不回读设置；超 3 分钟的档才有中途提醒且措辞与 T+0 不同
  （T+0 的话术已经要过一次邮箱——KA 勘误 12-C）。
- 页面上下文随会话带上（只留 host + path，不采 query / 输入框内容）。
- 不做（继承 KA 的永不做清单）：Pre-chat 留资表单、CSAT 弹窗、快捷回复库、
  分流路由矩阵、工单字段构建器——没有第二个客服，也就没有这些的第二种答案。
- Shopify Theme App Extension：`deploy/shopify-theme-app/`（一个 toml +
  一个 Liquid block，商家在主题编辑器打开开关即上线，不贴 script，
  工作区号不暴露在前台）。
