## 1. 用户视角：三个场景

**场景 A · 一个运营装客服包。** 打开桌面 App 的"市场"，搜"客服"，看到"独立站客服职责包（免费 · 官方）"。点安装 → 一页权限说明（"这个包要：读你的 Shopify 订单、读写客服邮箱、读知识库；不会：改价格、退款不经你批准"）→ 点"先试试"：在一个沙盒工作区里用合成店铺跑一遍，看到队列里出现三封客户来信的草稿 → 满意 → "连接我的店铺"（Connect 走 OAuth）→ "谁负责这个职责"（自己）→ 完成。队列里出现真实的第一封草稿。**全程没有终端、没有配置文件。**

**场景 B · 升级成付费版。** 用了两周，市场里那张卡片下面一直有一行"升级到 KefuAgents：懂行业话术、L2 自动回复、多平台买家消息"。点升级 → 登录 / 创建 KefuAgents 账号（或用 agentsws 账号一键开通）→ 权限多了两项（"访问 KefuAgents 云端知识库"、"按用量扣积分"）→ 装上。**界面、队列、审批流一个都没变**，只是草稿变懂行了，L2 可以开了。

**场景 C · 老板给 15 人公司装起步包。** 市场里有"跨境 DTC 15 人公司起步包"：六个岗位、二十几个职责、默认额度、首页配置、一套 skill。装上 → 岗位分配向导（"谁是运营主管？谁管投放？"）→ 连接器清单（"需要接：Shopify、公司邮箱、飞书、Klaviyo、Meta 广告"，逐个走 Connect）→ 完成。**部门 Join 进来时，个人装过的包自动映射到起步包里的对应职责。**

## 2. 什么是一个"包"

安装单元统一为**包（Package）**。一个包是一个带清单的目录，内容全部是**声明**，默认不含可执行代码。

```yaml
# package.yml
id: agentsws/dtc-customer-care          # 命名空间/名
version: 1.4.0
kind: role-pack                          # 见 §2.1
name: { zh: 独立站客服职责包, en: DTC Customer Care }
publisher: { id: agentsws, tier: official }   # official | verified | community
license: Apache-2.0
pricing: { model: free }                 # free | credits | subscription | one-time

provides:
  roles: [dtc.presales, dtc.aftersales, dtc.reviews]
  positions: []
  skills: [customer-care, returns-policy-calc, chargeback-evidence]
  blocks: [aftersales.pending_replies, aftersales.overdue_orders]
  scenarios: [customer-email-roundtrip, angry-customer, injected-instruction]   # 模拟场景，也是"先试试"的脚本
  backends: []                            # 付费包才有：Backend provider 的远程实现

requires:
  contracts: { roles: ^1, approval: ^1, executor: ^1, knowledge: ^1 }   # 契约版本范围
  connectors:                             # 装完必须连上的；ownership 决定 Join 时归谁
    - { service: shopify_admin, grants: [read_orders, write_orders], ownership: workspace, required: true }
    - { service: email, grants: [mail.read, mail.send], ownership: workspace, required: true }
    - { service: tracking, required: false }
  permissions:                            # 给用户看的权限说明，也是安装时的同意书
    - { domain: order, ops: [read] }
    - { domain: customer, ops: [read, stage] }
    - { domain: discount, ops: [stage], caps: { max_presales_discount_pct: 10 } }
  model_budget: { per_run_tokens: 20000, per_day_tokens: 500000 }
  packages: []                            # 依赖的其他包（付费包依赖它的免费基础包）

upgrade:
  breaking_permissions: false             # 为 true 时升级要重新同意权限
  migrations: []

signature: <Sigstore bundle>
```

### 2.1 包的种类与风险等级

| kind | 内容 | 含代码？ | 谁能发 |
|---|---|---|---|
| `role-pack` 职责包 | 职责定义、skill、积木、场景、默认额度 | 否 | 任何人 |
| `position` 岗位模板 | 一组职责的默认组合 | 否 | 任何人 |
| `starter` 起步包 | 岗位 + 职责 + 首页 + 策略层默认值 + 合成数据（按行业 × 规模） | 否 | 任何人 |
| `skill` 单个技能 | Agent Skills 规范的 SKILL.md + 资源 | 否 | 任何人 |
| `block` 积木 | 组件注册表条目 + 命名查询 | 否（查询是声明） | 任何人 |
| `connector` 连接器 | OpenConnector provider（executor 代码）+ 渠道适配器 | **是**，但只在 OpenConnector runtime / 渠道进程里跑，受 token 策略 | verified 以上，过审核 |
| `backend` 远程能力 | 一个实现 Backend 契约的 HTTP 服务地址 + 鉴权方式（付费插件的云端大脑就是它） | 否（代码在发布者自己的服务器） | verified 以上 |
| `dsh-plugin` | dsh 插件（无沙箱，全进程权限） | **是** | official / verified（经审核的社区插件 wrapper）可进公司端；community 只在个人端（16 文档 §4） |

规则：**市场里的第三方包默认不含在 dsh 进程里跑的代码；例外是经审核并包装的 verified dsh 插件（16 文档）。** 第三方要加能力，走三条安全的路：声明（职责 / skill / 积木）、OpenConnector provider（隔离进程 + 策略 token）、远程 Backend（他们自己的服务器）。这条是 dsh 无沙箱的直接后果，也是市场能开放给社区的前提。

## 3. 安装流程（非技术用户的六步，每步都能退出）

| 步 | 界面 | 背后 |
|---|---|---|
| 1 浏览 | 市场 Tab：按岗位 / 平台 / 行业分类；"官方""已验证""社区"标签；采纳率、安装数 | registry 搜索 API |
| 2 权限同意 | 一页人话："会读什么、会写什么、什么永远要你批准、花不花钱" | 从 `requires.permissions` 与 `pricing` 生成；同意记录进事件日志 |
| 3 先试试 | 沙盒工作区 + 合成数据跑 `provides.scenarios`，用户看到队列里的效果 | **复用模拟回路**：替身 provider + 真实内核；付费包的远程 Backend 也给一个试用端点 |
| 4 连接 | 逐个连 `requires.connectors`：自带账号 或 agentsws Connect | OpenConnector 连接 + 签发 role-read / role-apply token |
| 5 分配 | "谁负责"：个人工作区默认自己；公司工作区选人或按岗位模板 | 生成 Assignment；职责定义写入内容仓（带来源包与版本） |
| 6 完成 | 队列出现真实工作项；首页多了该职责的 focus 候选卡 | 分发协议 report / sync / ack 把包内容送到相关成员的客户端 |

**卸载**：撤销 Assignment → 收回 token → 职责定义标记停用（不删，事件日志要能回放）→ 该包产生的数据（客户、事实卡）**留在工作区**，属于公司不属于包；连接器问是否断开。

**升级**：公司工作区里升级是一条审批项（与上游哨兵同型）；`breaking_permissions: true` 时重新走权限同意；升级前在沙盒跑一遍该包的场景，指标不劣化才放行。

## 4. 三个 SaaS 怎么进市场

每个 SaaS = **一个付费包，依赖一个免费基础包**。装付费包时基础包自动装上，所以"免费能用、付费更好"在包关系里是显式的。

| 付费包 | 依赖的免费包 | 付费包里有什么 |
|---|---|---|
| `kefuagents/pro` | `agentsws/dtc-customer-care` | 同名高级 skill（覆盖 open 版）；`backend`：指向 KefuAgents 无头 API 的 Backend provider（领域大脑、行业知识底座、多平台买家消息）；额外 connector（Amazon / TikTok Shop 买家消息，走 Connect）；L2 / L3 的自动化上限解锁；role_view 面板（质检、抽检） |
| `kolagents/pro` | `agentsws/kol-marketing` | 高级 skill；`backend`：KOLAgents 的远程 MCP（M1–M4）作为 Backend provider（公共红人库、数据供给、匹配评分）；浏览器插件的登记；role_view（红人池、campaign、归因） |
| `btobagents/pro` | `agentsws/b2b-sales` | 同上模式；海关数据、序列、会议中心 |

**账号与计费**：agentsws 账号是身份；SaaS 侧接受 agentsws 工作区的授权 token（SaaS 要加一个"外部接入模式"，08 文档已定）。积分：短期各 SaaS 自己的积分账户通过"关联账号"绑定；中期做**市场钱包**——一个余额，所有付费包按用量从里面扣，SaaS 通过授权 API 报用量。定价保持已有体系（1 积分 = $0.01）。

**SaaS 自己的后台**保留给直接注册用户；对市场用户，SaaS 后台退化为账单与账户页，加一个"在 agentsws 中打开"。

## 5. 市场平台的架构（契约 #18）

```
发布者（我们 · 伙伴 · 社区）
   │ agentsws publish（CLI）或 工作台"发布到市场"（公司库 → 市场 = 晋升再上一级）
   ▼
Registry（我们托管；公司 / 伙伴可建私有 registry；离线可镜像）
   ├─ 元数据与搜索        包、版本、分类、发布者、标签
   ├─ 制品存储            签名的包 tar（Sigstore）；connector 代码另走审核队列
   ├─ 审核管线            自动：schema 校验 · 契约版本兼容 · 一致性套件 · 模拟场景跑通 · 权限声明与实际调用比对 · 策略 lint（不许 dsh-plugin）
   │                     人工：connector / backend 类
   ├─ 授权（Entitlement） 免费 / 积分 / 订阅 / 一次性；按工作区发放；试用期；撤销
   ├─ 包健康              匿名回传：安装数、留存、采纳率、干预率、卸载原因（opt-in，只有计数）
   └─ 评价与举报
   │
   ▼ 分发协议 report / sync / ack（teamai HTTP 模式的形状；#11 本地包管理消费它）
客户端（桌面 App / 共享工作区）
   ├─ 本地包缓存 · 已装清单 · 签名校验 · 允许源（official / verified / 公司私有 registry）
   └─ 安装向导（§3 六步）· 卸载 · 升级审批项
```

**外部源（07 P6）就是 registry 的别名**：默认源是我们的市场；公司可以加自己的私有 registry（部门 / 公司库对外的形态）；伙伴（代运营、服务商）可以给客户开专属源。

**发布路径与晋升是同一条**：个人 skill → 部门库 → 公司库 → 市场，每一级都是审批项 + eval 不回归 + 段级 diff。区别只是最后一级的审核者是市场（自动管线 + 人工），且要签名。

## 6. 免费与付费在市场里怎么分

| | 免费 | 付费 |
|---|---|---|
| 官方职责包、岗位、起步包、开源 skill、积木 | ✅ 永远 | — |
| 官方 connector（Shopify、邮件、飞书……） | ✅ 代码免费；自带账号连接免费 | Connect 托管 OAuth 应用超限额后按席位 / 按量（07 P1） |
| 三个 SaaS 的 pro 包 | 基础包免费 | 积分按量（云端推理、数据查询） |
| 伙伴 / 社区包 | 发布者自定 | 发布者自定；平台抽成 |
| 行业起步包（含合成数据与话术） | 官方基础版免费 | 伙伴的深度版可收费 |

分界线仍是 07 §3.1 那条：跑在用户自己机器上、用用户自己账号的免费；用到我们或发布者的基础设施、平台身份、数据、人的付费。

## 8. 待拍板（09-08 答复：1 第一阶段就要；2 待议见 12 §4；3 同意；4 私有 registry 免费、不抽成）

1. 市场是否第一阶段就要（我倾向：**包格式与本地安装（#11）进第一阶段**，registry 与付费授权（#18）第二阶段；但 `package.yml` 现在就定，否则职责包写出来不是包）

3. 社区能不能发 `role-pack`（声明类）不经人工审核——我倾向能，自动管线过了就上，标 community
4. 伙伴分成比例与私有 registry 是否收费
