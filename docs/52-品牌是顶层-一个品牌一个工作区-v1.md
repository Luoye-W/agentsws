## 0. 一句话

**品牌 = 工作区。** 一个品牌一个工作区，连接、知识、职责分配、面板、卡片、账本全部天然隔离——因为 20 之后所有数据本来就按 `workspace_id` 切，不用再造一层。公司变成工作区**上面**的一个"组织"：账号、余额、成员名单、同事发现在组织级；进哪个品牌干活、看哪个品牌的面板，靠顶栏的**品牌切换器**手动切。多品牌 = 多个工作区挂在同一个组织下，互相看不见对方的任何数据。

## 1. 为什么这样定（而不是在一个库里加 brand_id）

| 方案 | 做法 | 代价 |
|---|---|---|
| A 在一个工作区里加 `brand_id` 列 | 每张表、每条查询、每个面板加一维过滤 | 20 之后 60+ 张表、几百处查询要改；漏一处就串味（KOLAgents 的 `campaign` 名互相泄露就是这么来的）；44 的范围与 45 的合并都要重写 |
| **B 品牌 = 工作区，公司 = 组织** | 工作区不动；加一个组织对象与切换器；成员、账号、余额上提到组织 | 改动集中在身份层（20）与首次设置（46）；隔离由现有机制保证 |

选 B。隔离不是"加过滤器"得来的，是"根本不在同一个库里"得来的。

## 2. 方案（O1–O5）

### O1 对象层：组织 → 品牌工作区

```
Organization（公司）
├─ profile：公司全称、邮箱域名、发现开关（46 §1 ① 从工作区档案上提到这里）
├─ members：人 × 组织角色（owner / admin / member）—— 一次邀请，进组织
├─ account：agentsws 云账号、余额、订阅（49 M1）
└─ brands：[ Workspace（品牌 A）, Workspace（品牌 B）, … ]
      每个品牌工作区：品牌名、你卖的是（实物 / 虚拟）、网站平台（51 N0）、店铺连接、知识库、
      职责分配（人 × 职责 × 范围）、面板、卡片、账本、事项、待办、复盘 —— 全部只属于这个品牌
```

- 契约：新对象 `Organization { id, legal_name, domain?, discoverable, owner_id, members[] }`；`Workspace` 加 `org_id?` 与 `brand: { name, logo? }`；`WorkspaceProfile` 里公司级字段（`legal_name` / `domain` / `discoverable`）迁到 `Organization.profile`，工作区档案只剩品牌级（`vertical`、`storefront_platform`、时区、币种）。
- 个人用户（46 I4 / 45 H1）：组织 = 一个人、一个品牌工作区；界面上不显示组织概念，直到加第二个品牌或第二个人。
- 44 的范围模型改一句：**范围只在品牌内**（店铺、账号、市场、产品线）；"品牌 = 范围组"这一条作废；范围组保留为品牌内的"店铺组"（可选，默认不露）。
- 45 的合并（个人 → 公司）改为：个人的品牌工作区**整个挂到组织下**（不合并进别人的品牌）；只有"两个人各自建了同一个品牌"时才走对照合并（唯一键 = 品牌名归一化 + 店铺域名）。

### O2 切换器：手动切，不混

- 顶栏一个品牌切换器（当前品牌名 + 下拉）；切换 = 换 `workspace_id`，整个工作台重载（首页、岗位、连接、知识、设置全部换）。
- 一个人在多个品牌有岗位：每个品牌各自的岗位、各自的卡片队列；**不做跨品牌合并收件箱**（Luoye 的原话：不混）。想看全公司只有组织页的一张"品牌一览"（每个品牌一行：待审卡数、今日销售、告警数，点进去就是切换）。
- 快捷键 ⌘K 里可以搜品牌名切换。

### O3 组织级只放三样：人、钱、发现

- **人**：邀请进组织一次；每个品牌里再分配职责（44 的岗位）。离职（40 E2）按组织一次撤全部品牌的分配。
- **钱**：49 的账号与余额在组织级；每个品牌的积分消耗分开记（面板数字块"本周积分消耗"按品牌）。
- **发现**（46 I1–I3）：公司名归一化钥匙在组织级；同事申请加入的是组织，进来后 owner 决定他进哪些品牌。
- 其余一律品牌级：连接、知识、职责分配、模型设置（可选"跟随组织默认"）、通知偏好。

### O4 首次设置改三处

- 第 ① 步"公司"→ 两块：公司（全称、域名、发现开关 → 组织）与**第一个品牌**（品牌名、你卖的是、网站平台 → 品牌工作区）。
- 多品牌：组织页"加一个品牌"= 建一个新工作区，走一遍品牌级设置（连接、职责）；可"从某个品牌复制设置"（职责分配与模型设置可复制，连接与知识不复制）。
- 46 §1 表、§2 的 `company_key` 计算、`Workspace.profile` 相关代码随之改。

### O5 托管档与旧 SaaS 迁移按品牌走

- 49 / 48 的"在线值守"按品牌订阅（一个品牌一个云上服务进程），账单在组织级汇总。
- D 期迁移：KefuAgents 的一个后台 = 一个品牌（它本来就是"一个后台只服务一个品牌"），KOLAgents 的一个组织 / 品牌 = 一个品牌工作区；两边进同一个组织。

## 3. 不做什么

- 不做跨品牌的合并视图、合并队列、合并知识库；品牌之间零共享（想共享的知识走导出 / 导入）。
- 不做"一个工作区多品牌"（A 方案）。
- 不做品牌间的自动同步设置；"从某个品牌复制"只在建品牌时一次性。

**这一版没做的**（记在这里，别让它变成"以为做了"）：

- 服务进程仍然**按 bootstrap 工作区装配一套业务模块**。切到第二个品牌之后，按
  `actor.workspace_id` 走的那些面（岗位、队列、知识、事项、数据）是对的；按装配期闭包
  走的那些（活数据源 / 连接面 / 模型面）还跟着第一个品牌。所以品牌一览里"今日销售"
  只有当前品牌有——界面上照 36 §3 明说"切过去才看得到"，不画一个 0。
  真正的"一个进程装配多套品牌模块"另开一条。
- 连接与模型设置目前是**一台机器一份**（模型 key 与 49 的余额本来就在公司级）。
  "从某个品牌复制"的回执因此照实说"模型设置本来就共用，没什么可复制的"。

## 5. 请拍板

- O1 品牌 = 工作区，公司 = 组织；范围只在品牌内，"品牌 = 范围组"作废
- O2 顶栏手动切品牌，整站重载，不做跨品牌合并视图（组织页只有一张品牌一览）
- O3 组织级只放人、钱、发现；其余全部品牌级
- O4 首次设置第 ① 步拆公司 + 第一个品牌；"加一个品牌"可从已有品牌复制职责分配与模型设置
- O5 值守按品牌订阅；旧 SaaS 一个后台 = 一个品牌迁入同一组织
