# 96 卡片流与组件化复盘 v1（10-09）

> 起因：10-09 Luoye 在 Windows 真机上用 Rollout 店铺（个人模式）跑了一遍，原话：「我们核心是卡片流……很多其他的设计也应该学习 React 的组件化，例如数据看板之类的……提前设计好一些组件（或者也叫卡片），简洁明了的展示，适当时机的出现。整个工作流我感觉也有些乱了，我们得再重新复盘一下当前情况。」
> 参照：Claude Dashboards / Motion（10-08 测试版：一句话问出一块会自己刷新的看板）、ChatGPT Intelligent UI（回答直接是图表 / 按钮 / 表单）与 Pulse（每天主动推一组可扫一眼的卡）。
> 方法：盘点了现有全部页面、卡片类型、组件、重复与散落的决定（文件路径见文末附录），加上 10-09 真机遇到的问题。

## 0. 一句话

**要人拍板的事，只在卡片流里出现；其余一切都用事先设计好的组件来展示，而且只在该出现的时候出现。**（10-15 决策 847 改：决定可以在对话里就地完成，卡片流汇总所有待定的事，见文末 WP341。） 页面是放组件的容器，不是写说明的地方。

## 2. 现状盘点：乱在哪

1. **决定散落在卡片流外面**（至少 9 处）：事项时间线里的内联卡 / 选择卡 / 卡住卡；交接条的「接下 / 不接」；约时间收件箱；公司页的入会申请；首页「待认领」；消息页「待确认」与「交给谁 / 我自己回」；知识库「要复核」三选一；撞车卡三选一。同一个决定常常一处是卡、另一处又有一套按钮。
2. **同一个信息到处出现**：「N 张等你定」至少 8 处；复盘 3 处（卡、首页复盘 / 战报、deck 空时的战报）；同一批数字在首页岗位卡、首页数字块条、岗位页数据看板各一份；记忆 / 定时任务在岗位设置标签和右栏各一份；「问 AI」4 个入口。
3. **定时卡刷屏**：`review`（每岗位每天 20:00 + 周 + 月，没有空内容拦截）、`daily_plan`、`skill_lesson` / `skill_promotion`、`seo_report`（0 条也出「今天值得动的 0 件事」）、`weekly_review`——五种定时产物各出各的。
4. **卡片种类太多**：33 种 `ApprovalKind` + 2 种 deck 专用，11 种排版，约 70 种改动细分；按钮说法按排版硬配（键盘提示因此对不上）。
5. **组件体系是半成品**：服务端注册表只有 6 种组件（数字 / 表格 / 折线 / 时间线 / 键值 / 文字），48 条职责的积木大多是表格；数字块库 19 个只能从 ⌘K 加；「对话定制卡」只有契约和一个不落盘的接口，前台不渲染；B2B / 红人 / 社媒 / GEO 面板是手写的，不在注册表里；视觉原件有两层包装；右栏另有一套面板注册表，里面还有没做完、被开关藏起来的格子。
6. **页面太多、太长**：左栏 15 项以上；消息页 1565 行、公司页 1176 行、设置「通用」堆了约 12 张卡和 34 个问号提示；首页约 12 块。
7. **问答没有自己的样子**：问一句的回答是文字气泡，查到的商品、订单、数据也只能用文字念出来——这正是 Claude Dashboards / ChatGPT Intelligent UI 解决的事。

## 3. 原则（v1）

- **P1 决定只在卡片流**：凡是要人点头 / 选择 / 接下的，**只**以卡出现在卡片流里（首页 deck、岗位页 deck、事项里同一张卡的内联投影）。别的地方最多放一个「去处理这张卡」的链接，不另设按钮。
  - **10-15 改（决策 847，见文末 WP341 一节）**：决定可以**就地在对话里完成**（按钮、表单、审批都画在对话里），卡片流**仍汇总所有还没定的事**——同一个审批对象两处显示，哪处点了另一处同步。
- **P2 其余都是组件**：信息一律由**组件目录**里的组件展示：数字、趋势、表格、清单、时间线、对比、图集、进度、简报、提醒条。组件有固定样子与数据格式；AI 只能**从目录里选组件、绑查询**，数字不经模型手（docs/29 三原则不变）。页面只是放组件的容器。
- **P3 适当时机**：每个组件、每种卡都写明**出现条件**和**不出现条件**——没有内容不出、和昨天没变化不出、同一件事一天最多一次、个人模式下通知类不出卡。推（像 Pulse：早上一份简报）和拉（问一句才出）分开。
- **P4 问答就是组件**：问一句，回答由「一句话 + 组件」组成（问「店里有哪些产品」→ 商品表格组件；问「这周卖得怎样」→ 数字 + 趋势组件）。看着有用就「钉到看板」，下次打开自己刷新——这就是对话定制卡（docs/29 §4）要做实的样子。
- **P5 一个数一个地方**：同一个信息只有一个权威出处，别处要么引用同一个组件，要么不放。
- **P6 页面零说明**：页面不写解释性文字；状态用图标 / 颜色表达，出问题才出一行提示；长说明进教程，短的进问号提示（界面少字）。

## 4. 组件目录 v1（草案）

### 4.1 决定类（卡）：33 种收成 6 个家族

按钮由家族定，键盘提示由**实际按钮**生成（不再按排版硬配）。

| 家族 | 收的现有 kind（举例） | 主 / 次按钮 | 出现条件 | 不出现 |
|---|---|---|---|---|
| **发出去** | `outbound_draft`、开发信、社媒回复 | 发送 / 改 / 不发 | 有草稿要外发 | — |
| **改东西** | `staged_change`、`knowledge_update`、`content_update`、`official_plugin` | 通过 / 改 / 不要 | AI 要写 / 改、超限要再确认 | 人自己改的（①② 当场生效） |
| **选一个** | `ai_question`、`b2b_sender_choice`、`image_pick`、撞车 | 选项本身就是按钮 | AI 缺信息、有几个候选 | 能按规则自己定的（如职责路由） |
| **接 / 交** | `claim`、交接、`membership`、`join_mapping` | 接下 / 不接 | 有人把事交给你、有人要加入 | — |
| **定规矩** | `policy_change`、`skill_promotion`、`scheduled_task` | 记下 / 不用 | AI 提「以后都这样」、新定时任务 | — |
| **花钱 / 风险** | `image_budget`、`b2b_fraud_alert`、`computer_use`、超额 | 继续 / 停 | 要花超出预期的钱、有风险 | — |

`review` / `daily_plan` / `seo_report` / `weekly_review` / `skill_lesson` **不再是卡**：并进「简报」组件（见下），里面引出的具体决定才各自出卡。

### 4.2 信息类（组件）

| 组件 | 用在 | 出现条件 | 不出现 |
|---|---|---|---|
| **简报**（Pulse 式） | 首页顶部、岗位页顶部 | 每天早上一份，汇总昨天发生的事 + 今天的计划 + 引出的卡数 | 昨天什么都没发生 → 一行「昨天很安静」或不出 |
| **数字** | 看板、简报、问答 | 有数据源 | 数据源没接 → 不出（不出 0） |
| **趋势**（数字 + 小折线） | 看板、问答 | 有 ≥ 3 个时间点 | 点不够 |
| **表格 / 清单** | 问答（商品、订单、客户）、看板 | 有行 | 0 行 → 一句话「没有」 |
| **时间线** | 事项、日程 | — | — |
| **对比** | 竞品、A/B、报价 | 有两个以上可比对象 | — |
| **图集** | 生图挑图、素材库 | 有图 | — |
| **进度** | 建站、批量任务 | 有长任务在跑 | 跑完收起 |
| **提醒条** | 页面顶部（连接过期、余额不足、模型没接） | **只在出问题时** | 正常时不出（正常 = 一个绿勾） |

每个组件：固定外观 + 数据格式（payload schema）+ 出现 / 不出现规则 + 可「钉住」。B2B / 红人 / 社媒 / GEO 的手写面板逐步拆成目录里的组件组合。

## 5. 页面与流程收敛（草案）

- **左栏**（10-09 画板修订，决策 333 / 334）：首页 · 岗位们 · 消息 · 日程（待办 + 日历 + 会议）· 我的助理（原「随便聊」+「我的代理」合并：聊天、替你答同事、约时间）；底部可展开的「更多」：知识与技能（知识库 · 技能 · 规矩）、岗位与品牌（② 团队 / ③ 公司）、连接（含消息渠道）、设置；「场景」挪进设置；品牌切换与账号在最底。
- **首页**：简报 + 跨岗位卡片流。只有一个岗位的人，首页就是那个岗位页（已是）。
- **岗位页**（决策 339 修订）：数据看板放最上面（有数据才出）→ 输入框（问 / 交办）→ 当场回答（组件）→ 卡片流；「工作」列表默认折叠；记录、设置进右栏 / 「···」（WP288）。
- **事项页**：对话时间线；里面的决定都是**同一张卡的投影**，处理一处另一处同步消失。
- **右栏**：只放「看着什么来决定」：证据、变更、记录、记忆 / 规矩；删「问 AI」和没做完的格子。
- **卡片流外的 9 处决定**：逐个改成出卡（或删掉那处按钮，只留跳卡链接）。

## 6. 我们自己的开发流程也要改

- **问题**：最近一个月按「真机发现一处 → 派一单补一处」走，单子小而多，补丁叠补丁；工具参数表这种「一启动就挂」的错，测试和模拟全绿却漏到真机。
- **改法**：
  1. **装包前真机冒烟**：每次给 Windows 装包前，在本机用真 dsh 跑一遍「岗位里问一句 / 交办一件 / 出一张卡 / 点掉」的端到端，挂了不装。
  2. **先定组件和出现时机，再派单**：新功能的派工单必须写「用哪个组件 / 哪个卡家族、何时出现、何时不出现」，不允许新造卡种或页面区块。
  3. **按阶段派，不按症状派**：下面的路线一阶段一阶段走，阶段内并行，阶段间先给 Luoye 看一眼再进下一阶段。

## WP324：连接卡 / 配置卡（决策 690，10-14）

Luoye 原则：任务要先设置 / 先连接时，**在对话流（卡片流、事项时间线）或第三栏弹卡，就地补完，补完原任务自动接着做**；「连接」「消息渠道」「设置」那几页保留作总览与管理，不再是唯一入口。只把通用机制做成固定功能，具体哪一家服务怎么连由连接目录 / 渠道登记表说了算，不做专属界面。

| 组件 | 家族 | 出现 | 不出现 | 补完 |
|---|---|---|---|---|
| **连接卡**（`connect_request`） | 暂按「选一个」家族的变体做（主按钮在卡身里：连接 / 授权 / 配对；卡底只有「先不连」「稍后」）；要不要单列第七个家族「补一样」待 Luoye 定（决策 721） | 一件事跑到一半，工具回 `not_connected` / 缺凭据 / `needs_connection` / 建站与管店的结构化缺项 | 缺的都已连上；同一缺项已有一张在等（新事项挂到那一张上） | 卡上连好 → 卡自己「接着做」；在连接页 / 第三栏连好 → 连接清单一变服务端复查、卡收起；等着的每件事都按原话接着跑（只跑一次） |
| **配置卡**（`setup_request`） | 同上（主按钮「保存并接着做」） | 工具回 `needs_setup:<目标>` / 建站「不知道是哪家店」/ 开发信「公司地址没填」 | 已经设好；同一个设置目标已有一张在等；**秘密格一律不收**（改走连接卡的本机表单） | 保存（建议值预填，不改直接存）→ 服务端存进那个设置目标 → 接着跑；填得不对说一句、再出一张 |
| **第三栏连接卡**（`agentsws://connect/<service>`） | 信息组件（不进卡片流，不挂事项） | 数据看板 / 数字块 / 岗位缺连接 / 岗位设置 / 社媒 / 消息页 / 红人数据接口的「去连接」 | 平时不占图标（只按地址开） | 连好那一样画绿勾 |

卡上每一样用哪种接法按 `service` 挑现成组件：连接目录 provider → 授权页 / 本机原生表单；`shopify_admin` → 一键授权；`site_theme` → 建站岗位那一行（装 CLI / 登录 / 选店）；`shop_admin` → 管店授权；`im:feishu` / `im:dingtalk` → 团队机器人卡；`extension` → 插件配对码；认不出的给「去连接页 / 消息渠道」。花钱 / 能动东西的（广告、管店、插件）在卡上加一行风险告知。

## WP334：连接卡第二轮——AI 自己要卡、IM 与模型 / 账号就地连（决策 724 / 725 / 726，10-15）

- **AI 自己要卡**（724）：所有职责多一个通用工具 `request_setup`（连 X / 设 Y + 一句为什么 + 建议值）。工具**不出卡**，只回一格结构化缺项；这一轮收尾时照上表的规则出卡、去重、补完按原话接着做——AI 要卡与工具撞上缺项是同一条路。「为什么」「建议值」里像口令 / 密钥的整条拒收（不回显）。stub / direct / dsh 三个运行时同一份参数表（dsh 严格参数表钉了测试）。
- **卡里就地连的接法**多了几样（按 `service` 挑现成组件，不为谁写专属界面）：

| service | 卡上的接法 |
|---|---|
| `im:wecom` | 企业微信机器人那张本机原生表单（与消息渠道页同一个件；只有负责人 / 公司管理员能填） |
| `im:wechat` | 个人微信扫码（与消息渠道页同一个件；条款风险一行留在卡上） |
| `model` | 接模型（与开工向导第 ① 步同一个件：工坊接口 / DeepSeek 官方 / 自己的 key 走本机原生表单） |
| `deepseek_account` | DeepSeek 账号登录（与设置页同一个件） |
| `workshop_account` | 关联 Agents 工坊账号（与设置页同一个注册 / 登录表单） |
| `imap_smtp` | 连接目录里的「邮箱」（发信邮箱；本机原生表单） |

- **配置卡**多一个设置目标 `company.profile`（公司档案：一句话介绍 / 客服邮箱 / 币种）。
- **谁会出这几种卡**：AI 调 `request_setup`；工具回 `needs_connection:<service>`（机器码）/ `not_linked`（工坊账号没关联）/ 开发信一只邮箱都没有；用 DeepSeek 账号跑、登录过期（`unauthenticated` 或登录失效停下）。

## WP341：genui 完全融合——决定可以在对话里就地完成（决策 847，10-15）

Luoye 原话大意：在一段对话里自然、连贯地把事做完，比跳到别的页面好；按钮、表单都放进对话，不为担心加太多限制。**P1「决定只在卡片流」改为：决定可以就地在对话里完成，卡片流仍汇总所有待定的事。**

| 原来 | 现在 |
|---|---|
| 回话里只许信息类组件（数字 / 表格 / 图…），按钮、表单、图片、链接一律滤掉 | 插件的全部组件都能画：按钮、表单（输入 / 选择 / 勾选 / 日期 / 数字 / 文本域 / 滑块 / 提交）、图片音视频、链接、svg（消毒后画）、mermaid、3D、表格过滤 / 排序 / 导出 |
| 决定只在卡片流 | 对话里点了就做：发一句话 / 交表单（变成用户的一条结构化回话）、开页面或第三栏、开连接卡、调工具 |
| 工具只有 AI 在运行里调 | 对话里的工具按钮走**同一个工具执行器**：只读的当场跑、结果就地画；会改外部的照旧进账本出审批卡——**审批就地画在对话里，卡片流里同一张**，哪处批了另一处同步 |

**两条不动**：
1. 口令 / key / token 格子（`password` 或名字像密钥的）换成宿主画的「口令格」：值只走本机原生表单进加密库（同连接卡那条路），AI 只收到「已填好」；事件、时间线、日志、落盘文件里都没有值（决策 814）。
2. 会改外部的进账本、走审批；直接写外部的工具按钮不收。

**出现规则**：
- 要人从几个里挑、要人填几样、要人确认时出按钮 / 表单；只是告诉人的事不加按钮（写进给模型的规矩）。
- 不收话的地方（教程文章、报告）只看不点：按钮画成禁用的。
- 外部图片 / 媒体：店铺 CDN、本机文件、工坊截图、常见平台图床直接加载；其他外部网址先显示「点开看 · 域名」。链接悬停显示真实域名、外部浏览器打开。
- 聊天软件（个人微信 / 飞书 / 钉钉 / 企业微信）：按钮变编号选项、表单变要回答的问题；人回编号就当说了那句。

插件以后新加的组件仍默认不过，升级按 docs/42 评估后再加。
