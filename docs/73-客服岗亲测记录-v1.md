## 通的
- 客服岗位页：4 张卡（策略变更 / 回复草稿待审 / 变更待批 / 今天的安排），筛选、中英摘要切换、快捷键提示都在；「超过退货窗口一周怎么办」这张策略卡把三个选项做成单选、批了沉淀成策略——这条体验是对的。
- 快捷提示（起草退货回复 / 查这单到哪了 / 超时没回的来信 / 退款算一算）贴合岗位。
- 后端零件齐：`/v1/chat/sessions/*`（建会话、发消息、接管、教一句）、公开访客面四道门（来源白名单、限流、访客令牌、凭据不进 URL）、无依赖的嵌入脚本 `widget.js`、`packages/standby` 在线值守。

## 问题清单
| # | 现象 | 严重 |
|---|---|---|
| 1 | **在线聊天没有商家看得见的入口**：没有「聊天窗设置」页（外观、欢迎语、允许的域名、拿嵌入代码），没有「正在进行的对话」列表，没有人工接管的对话界面。工作台里只有一个 `/chat` 沙箱页，导航上找不到 | 阻断 |
| 2 | **本地装不了聊天窗**：公开访客面与 `widget.js` 只在「在线值守（托管）」那一档才挂；而托管档在 Cloudflare 形态里**没开**（WP114 留尾）。也就是说今天没有任何一种部署形态能让商家把聊天窗贴到自己网站上 | 阻断 |
| 3 | demo 里客服岗位只启用了「网站客服」「社群管理」两条，**「网站在线客服」职责没启用**，左栏看不到、无从测试；岗位页却写「这个岗位下的 5 条职责」 | 高 |
| 4 | 「连上这 12 个就能开工 · 未就绪」：十二张连接卡一长串，其中九张是社群管理要的社媒渠道（多数可选）。客服最要紧的两张（店铺、邮箱）被淹掉，违反减字原则。应只列必需的，可选的折叠成一行「还有 10 个可选」 | 中 |
| 5 | 聊天对话与「消息」页（WP113）没有关系：邮件在消息页，聊天不知道在哪。统一收件处应该把聊天会话也收进去（WP113 的模型已留 `MessageSource` 扩展位） | 高 |
| 6 | 没有移动端：KefuAgent 有 Flutter 客户端做通知与回复；我们目前只有 IM 渠道卡片（飞书 / 钉钉 / 企微）这条路，未验证 | 中 |
| 7 | 红人那边发现的共性问题这里同样存在：职责没有 persona（WP120）；真模型下没测过 | 高 |

## 下一步
等 WP123 的对标报告回来，按它的 P0 清单派工。预判 P0 三件：① 在线聊天在 Cloudflare 形态跑起来（每会话一个 Durable Object + 挂件静态资源 + AI 走积分）；② 工作台的聊天窗设置页 + 对话列表 + 接管界面，并收进「消息」；③ 连接清单减字与在线客服职责默认启用。

## 在线聊天两档（09-19 Luoye 提，Fable 方案，待 Luoye 定两个数）
- **免费 · 本地档**：云只做转发（每工作区一个 Durable Object 当管子，不存对话、不跑 AI），访客消息转给商家本机的 Agents 工坊处理；AI 用商家自己的接口或积分；关机 = 聊天窗自动变留言表单，留言进「消息」页走邮件回。设每月对话上限（建议 200，**待定**）防滥用。
- **收费 · 在线档**：「客服增值服务」按月订阅（月费**待定**，参照红人 30 积分 / 月），云端全天 AI 应答、对话存云端并同步回本地、转人工推手机 / IM；AI 用量另计。
- 两档同一个挂件、同一段嵌入代码，设置里切档，商家网站不用改。
- 不进主流程的高级选项：商家自建 Cloudflare Tunnel 暴露本机（完全不经我们；非开发者做不了，只写文档）。
- 为什么免费档也要过云：挂件在公开网站上，访客浏览器必须连得到一个公网地址，商家电脑在内网后面连不进来。

**09-19 Luoye 已定**：方案同意；免费档每月 200 个对话；收费档「客服增值服务」30 积分 / 月；另加**用户自建转发**（同一份开源转发器：Docker 一条命令或一键部署到自己的 Cloudflare 账号，本机主动外连、填地址 + 配对密钥即可，无上限）。落成 WP124（`docs/briefs/WP124-live-chat-three-ways.md`），等 WP116 / 118 合并与 WP123 结论后开工。
