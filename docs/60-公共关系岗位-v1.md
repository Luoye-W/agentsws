## 1. 职责骨架（U1）

| 职责 | 读 | 写（→ ChangeKind） | 额度 | 上限 |
|---|---|---|---|---|
| `pr.press` | 媒体名单、过往稿件、公司事实卡（19：数字不编）、分发记录 | `draft_release`（`press_release` 草稿 L2；**发布 / 分发 L1**）、`pitch_media`（`outbound_message` 给媒体的 pitch，L2 → L3，日配额 + 抑制名单复用 WP55） | `max_pitches_per_day` 20、`max_releases_per_week` 2 | 分发永远人审 |
| `pr.reddit` | 目标 subreddit 列表与版规、热帖、我们的历史露出与反馈 | `stage_post`（`community_post` **L1**：外部社区发帖）、`reply_thread`（`outbound_message` L2 → L3：答题 / 评论） | `max_external_posts_per_day` 2、`max_replies_per_day` 20、`cooldown_per_subreddit_hours` 72 | 发帖永远人审；同一 subreddit 72h 内不重复发；版规禁自我推广的 sub block |
| `pr.forums` | 论坛 / Quora / 知乎目标板块、问题列表 | 同上两条，`mode: browser`（无官方接口） | 同上 | 同上 + 浏览器模式：写先出卡、失效人接管 |

## 2. `pr-core`（U2）

`release.ts`（新闻稿结构：标题 / 导语 / 事实段（只引事实卡）/ 引语 / 关于我们 / 联系方式；引语必须是人给的，模型不编）、`media.ts`（媒体名单与 pitch 序列，复用建联的日配额 / 抑制）、`subreddits.ts`（版规解析：`no self-promotion` / `flair required` / 发帖频率 → 判可不可发）、`monitor.ts`（提及归一 + 情绪分级 + 去重 + 客户问题 vs 舆情分类，复用 `social-core/triage`）、`channels/{reddit,forums-browser,alerts}.ts`。

## 3. 面板与卡（U3）

分块：提及流（按情绪）、负面预警、待发新闻稿、pitch 漏斗、Reddit / 论坛露出记录与反馈；卡：新闻稿发布卡（L1）、外部发帖卡（L1，带版规检查结果）、负面预警卡（L3）、转客服卡、回应草稿卡。

## 4. 模拟（U4）

3 人 pack +3：`pr/external-post-needs-approval-and-rules`（版规禁自我推广 → block；允许的 → L1）、`pr/negative-mention-routes`（客户投诉 → 转客服；舆情 → 回应草稿）、`pr/press-release-facts-only`（新闻稿里的数字必须引事实卡，编的被拦）；15 人 pack +1：`pr/subreddit-cooldown`。

## 5. 派工（U5）

**WP78 公共关系骨架**：契约（`media_contact` / `press_release` / `mention` / `external_post` 四个对象、`press_release` / `community_post` / `mention_triage` 三个 ChangeKind）、`pr-core`、四条职责 yml + 岗位模板"公共关系"（默认全勾）+ `SEED_POSITIONS`、guardrail（外部发帖 `HARD_L1`、版规 block、事实卡引用检查）、连接：Reddit 复用 `reddit` 卡、`google_alerts` 新卡（RSS）、论坛浏览器模式、新闻稿分发"待增加"；数据面进 `BrandModules`；面板与五张卡；模拟四条。后置：真账号、分发渠道、Quora / 知乎适配。
