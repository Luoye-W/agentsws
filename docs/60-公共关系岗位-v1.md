## 2. `pr-core`（U2）

`release.ts`（新闻稿结构：标题 / 导语 / 事实段（只引事实卡）/ 引语 / 关于我们 / 联系方式；引语必须是人给的，模型不编）、`media.ts`（媒体名单与 pitch 序列，复用建联的日配额 / 抑制）、`subreddits.ts`（版规解析：`no self-promotion` / `flair required` / 发帖频率 → 判可不可发）、`monitor.ts`（提及归一 + 情绪分级 + 去重 + 客户问题 vs 舆情分类，复用 `social-core/triage`）、`channels/{reddit,forums-browser,alerts}.ts`。

> **WP78 实现**：`packages/pr-core`，与 `kol-core` / `social-core` 同一条纪律
> （纯逻辑 + 注入 IO，没有 `Date.now()`、没有 `fetch` 实现、碰不到一个凭据），
> 79 条单测。三处"同一份代码"是这个包的骨头：
>
> - 数字出处：`release.ts` 的 `checkFacts` import `@agentsws/core` 的
>   `uncitedFigures`，与 guardrail 那道门读的是同一份，不存在"面板说 3 个、门说 4 个"；
> - 版规：`subreddits.ts` 的 `reasons` 与 guardrail 那一侧的 hit 名**逐字相同**，
>   `/v1/pr` 那一跳先查一次、结论原样递给 guardrail，不是各判一次；
> - 客户问题：`monitor.ts` 那一档复用 `social-core` 的 `triageThread`，
>   同一句话在 Discord 里与在 Quora 上是同一个意思。
>
> 两条刻意的保守：`subreddits.ts` **判不准就当禁**（在别人的地盘上 fail-closed
> 的代价是少发一条，fail-open 的代价是被永久赶走），只有版规**明写着**欢迎厂商
> 才放行（`SELF_PROMOTION_ALLOWED_TERMS`，禁优先）；`channels/alerts.ts`
> **拉不到 ≠ 今天没人提我们**，没配地址 / 404 / 回来的不是 feed 各说各的话。

## 3. 面板与卡（U3）

分块：提及流（按情绪）、负面预警、待发新闻稿、pitch 漏斗、Reddit / 论坛露出记录与反馈；卡：新闻稿发布卡（L1）、外部发帖卡（L1，带版规检查结果）、负面预警卡（L3）、转客服卡、回应草稿卡。

> **WP78 实现**：五块积木在 `packages/deck/src/blocks.ts` 的 `PR_MONITORING_BLOCKS`
> 等处，按两层摆——我们自己库里那四块走 `pr` 源（永远算连上），
> **只有提及流**走 `google_alerts`（36 §3「没连就明说」）。这一刀是有意的：
> 一张空的提及流等于说"今天没人提我们"，而那是这条职责上最贵的一种谎；
> 负面预警空着的意思是"现在没有着火的"，那句话是真的。
>
> 待发新闻稿那一块有**两列**（「有几个数」与「有出处的」），不合成一个"合规"钩子
> ——合了之后人看不出差在哪儿。卡上三个新芯片（版规 / 数字出处 / 舆情与传播量）
> 在 `apps/workstation/src/components/deck/evidence-chips.tsx`，全从结构化字段取；
> 版规那一格给告警色。数据面在 `apps/server/src/pr.ts`（四张表按品牌进 `BrandModules`）
> 与 `packages/api/src/routes/pr.ts`；定时那一跳是 `HANDLERS.prMonitor`
> （`pr.monitor_sweep`，15 分钟一轮，按品牌各跑一轮）。
> 截图：`docs/assets/workstation/pr-position.png`。
