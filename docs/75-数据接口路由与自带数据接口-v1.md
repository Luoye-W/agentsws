# 75 · 数据接口路由与自带数据接口 v1

状态：**WP126 实现，待审**（2026-09-21）。本文是「数据从哪里来、谁为数据付钱、
自带接口怎么接」的一份总说明：路由表（§1）、官方数据接口的计费新规则与三条口径
（§2，Luoye 09-19 定，Fable 提的口径②③由 Luoye 确认）、自带数据接口的公开格式
与参考实现（§3）、边界（§4）。

## 0. 一句话

**每个渠道 × 每种动作都过同一张四级路由表；官方数据接口没有免费动作了，命中缓存
与未命中同价；用户有自己的数据接口就自己接（本机适配、不扣积分）；对外绝不出现
任何第三方数据平台的名字——官方那一侧永远只叫「Agents 工坊官方数据接口」。**

## 1. 路由表

每个渠道（youtube / instagram / tiktok / facebook / x）× 每种动作
（搜人 `search` / 主页数据 `profile` / 深度体检 `audit` / 联系方式 `contacts`）
都过这张表：

| 级 | 来源 | 谁付钱 | 什么时候走 |
|---|---|---|---|
| ① | 用户自己的官方平台 key（连接页那张卡） | 用户对平台付，工坊不收费 | 配了 key 且该级支持这个动作 |
| ② | 用户自带的数据接口（高级卡） | 用户对那个服务付，工坊不扣积分 | 配了且该级支持这个动作 |
| ③ | **Agents 工坊官方数据接口** | 用户付积分（单价常显在界面上） | ①②没配或被关掉 |
| ④ | 都没有 | —— | 一句人话 + 两个入口：关联官方账号（送 10 积分）/ 接自己的数据接口 |

实现落点：`apps/server/src/kol-service.ts` 的 `search()`（四级全在）；顺序与开关
从设置来（`data_source_routing`，键 `kol.<渠道>`，可调顺序、可关某一级）；连接页
每张红人渠道卡上有「数据从哪里来」控件。

**逐级回退的规矩**：

- 上一级「**没配**」或「**这一级不支持这个动作**」→ 落下一级；
- 上一级「**配了但报错**」→ **不静默回退到花钱的那一级**。回执带
  `failed_level`（哪一级失败）与 `fallback_offer`（「改用工坊官方数据接口
  （约 N 积分一次）」）；用户点头之后带 `fallback: 'workshop'` 重发一次，
  才真的走③。

**来源标注**：结果上始终标「这份数据来自：我的 YouTube key / 我的数据接口 /
公共红人库」（`source_label`）。

**默认值跟初始化第一步走**（WP121b）：第一步选了官方 AI 接口的用户，五条渠道的
路由默认把③提到最前；选自有模型的默认「我的」，缺什么回退什么（默认顺序本来就是
①→②→③）。

## 2. 官方数据接口的计费规则（Luoye 09-19 定）

**推翻** 48 §5 / 49 / WP61 / WP116 里「浏览免费」那一套。官方数据接口本身就是
增值服务：

| 动作 | 能力 | 现价 |
|---|---|---|
| 浏览 / 搜索 / 类目基准 | `data.kol.lookup` | 0.2 积分 / 次 |
| 体检报告（GET audit 与 POST deep-audit） | `data.kol.audit` | 3 积分 / 次 |
| 联系方式揭示（reveal） | `data.kol.lookup` | 0.2 积分 / 次（价不变） |
| 社媒取数（refresh） | `social.fetch` | 0.05 积分 / 次（价不变） |

WP131：上表是现价；重算建议（揭示单列 0.8、社媒刷新 0.4 等）在 docs/77，未定前不改。

四条硬规矩：

1. **命中缓存与未命中收同样的钱**——库本身就是缓存，「命中」不是用户的功劳。
2. **取数失败 / 超时 → 预扣释放不收钱**（两形态同此：Compose 直接释放；Workers
   由入口预扣、`KolPublicDO` 出释放单、回 `WalletDO` 照单执行）。
3. **查无此人 / 搜到 0 条 → 不收钱**（预扣释放；基准桶不够 k 也一样——收钱换来
   一个空结果说不过去）。**体检报告样本不够、只能给部分结论也一样**（WP129，Fable 拟、
   Luoye 09-23 同意）：报告照出（`insufficient_samples: true`），`credits` 为 0，`note` 末尾
   写「样本不够，这次不收。」——界面显示的就是这句，GET audit 与 POST deep-audit 同口径。
   "样本够、但同量级可比的人不到 k（分位那一格缺）"**照价收**：粉丝真实度是这个人自己的
   样本算出的完整结论，缺的只是"和别人比"，报告里已经说清。
4. **我方成本照实进账本**：命中缓存时我方成本为 0、收入不变——后台毛利会更好看，
   这是对的。

### Fable 定、请 Luoye 确认的三条口径（已实现并用测试钉住）

1. **一次提交的搜索算一次**：同一 (subject, 查询串) 10 分钟内翻页 / 重排不重复收。
   实现是**幂等窗口**（`KolStore.searchChargeAt` / `putSearchCharge`，键 =
   sha256(工作区 | 渠道 | 查询串 | 粉丝下限 | 类目)，**刻意不含 limit**——翻页
   就是 limit 在变）；窗口内的重复搜索记一条 0 积分计量事件（用法照常可见）。
   输入过程中的空查询不算搜索。云侧两形态共用同一个服务实现，窗口天然两边都有。
2. **查无此人 / 搜到 0 条 = 不收钱**（预扣释放；不算「命中」也不算「失败」）。
3. ~~**贡献返额度保留**：插件 / 自带接口贡献公开数据照旧换 `granted` 积分。~~
   **09-23 Luoye 定（WP130 落地）：贡献不发积分**——红人观测、联系方式、内容观测一律
   不返 `granted`；贡献照旧免费、不预扣、照旧记账（`CONTRIBUTION_REWARDS_ENABLED = false`）。

**「先看价」随之简化**：官方接口的每个取数动作都有价，界面上在动作旁常显单价
（不弹确认框打断；单次 ≥ 1 积分的才二次确认——体检报告 3 积分在 confirmation
那一档，搜索 0.2 不需要）；余额不足说人话并给充值入口。Agent 工具调用受岗位
额度与自主权限门约束（沿用 guardrail，不另起一套）。

**入口预扣表**（`packages/kol-public/src/charge-map.ts`）与 service 的收费点
一一对应：GET 的三条读路由（creators / benchmarks / …/audit）与 POST 的三条
（reveal / deep-audit / refresh）都在表里；上报、回填、争议、插件配对仍然不收
——它们是往库里加事实，不是从库里取价值。WP129 加的内容观测两条
（`POST /v1/data/kol/content-observations` 与插件令牌那条 `plugins/content-observations`）
同理不收费，并且照红人观测的口径**返贡献额度**（日配额与红人观测合算）。

## 3. 自带数据接口（BYO）

新连接卡「自带数据接口（高级）」，每渠道可挂一个：

- **字段**：服务地址 + 密钥（原生表单 → 本机加密库，文件里只有引用）+ 返回格式
  （固定 `byo/v1`，见下）。
- **「测试连接」**：打一次最小的 profile 请求；服务回 200 或 404（查无此人）
  都算通——听懂了就是通了。
- **适配器跑在本机**，走用户自己的额度，**不扣积分**；超时 10 秒；限流 / 超时 /
  密钥不对 / 回得不对，各有一句人话，服务自己的错误文案原样带回去（不吞、不编）。
- 走自带接口取到的公开红人数据，登录了云账号的照常共享到公共红人库（与插件同一条
  规则，窄行）。
- 卡上一句人话：「用你自己的账号取这些平台的数据，是否合规由你与该服务的条款决定。」

### 公开格式（`byo/v1`）

契约在 `packages/contracts/src/byo-data-source.ts`（只加不删）：四个动作各一个
端点形状 + JSON Schema，返回**归一化**的红人 / 指标 / 内容 / 联系方式对象：

| 动作 | 端点（相对 `<服务地址>/byo/v1`） | 返回 |
|---|---|---|
| 搜人 | `POST /search` | `{ creators: ByoCreator[] }`（0 条 = 空数组，不是错误） |
| 主页数据 | `POST /profile` | `{ creator, recent_content? }`（查无此人 404） |
| 体检 | `POST /audit` | `{ creator, sample_size, insufficient_samples, … }`（样本不够就明说，不编） |
| 联系方式 | `POST /contacts` | `{ contacts: ByoContact[] }`（没有 = 空数组） |

鉴权就一种：`Authorization: Bearer <密钥>`。错误也是 JSON：非 2xx 回
`{ code, message }`，`message` 是一句给人看的话。

参考实现：`examples/byo-data-source/server.mjs`（Node 单文件、假数据、可运行，
`node examples/byo-data-source/server.mjs` 即起）。能照着这份格式回 JSON 的服务
都能接——接的是什么服务由用户自己决定。

## 4. 边界

- **不做任何平台预设（Luoye 09-19 定）**：界面、文档、示例、代码注释里不出现任何
  第三方数据平台的名字，也不告诉用户市面上有哪些这类服务；只提供通用格式。代价是
  非开发者基本用不了这张卡——Luoye 明确接受。守卫测试
  （`apps/server/test/guard-upstream-names.test.ts`）扫面向用户的面，出现名字即失败；
  内部成本表、`packages/kol-public/src/sources/*`、部署运维文档（64、65）不算违规。
- **对外统一叫法**：官方那一侧在界面、文档、错误信息、开放 API 描述里只叫
  「Agents 工坊官方数据接口」。
- 自带接口取数不经过工坊的钱包，工坊对那一侧没有计量数据（用量看板只见工坊侧）。
- 本版的 `audit`（basic）与 `deep-audit` 同价同源；真的深度分析（评论真实性抽样、
  受众画像、跨渠道对照）留给后续 WP——收了钱就要说清楚现在买到的是什么，
  报告 `note` 里写明。
