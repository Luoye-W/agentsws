## 0. 一页结论

1. **两家后台本来就有「表格批量改」的官方入口，正好给插件用。** Google 后台叫「批量上传」，Meta 后台叫「批量导入广告」。都可以用表格新建广告系列、广告组、广告和关键词，改预算，暂停或启用，而且**上传之后都会先给一个预览，确认了才生效**：Google 是先预览再应用，Meta 是先导成草稿，再点「审核并发布」。所以插件不用一格一格去填后台的表单，只需要做三件事：替人上传表格、截屏留证、在人确认后点那一下「应用 / 发布」。
2. **我们现在的插件做不到这些。** 仓里的插件（红人助手）只在 YouTube、Instagram、TikTok 三个网站上读页面，不会点按钮、不会上传、不会截屏，也收不到本机服务发来的指令。要补的是一个「动作通道」。仓里真正做过「登录状态 + 审批卡 + 浏览器执行」的是 **Reddit 官方号浏览器通道**（WP249）：每个动作的步骤都是写死的，只放行白名单里的点击，执行完回读页面确认，严格限速。广告这边**直接照搬它的规矩**，只是执行的地方从「另开的浏览器」换成「用户日常用的 Chrome 里的插件」。
3. **风险说实话是灰色地带，但能压得很低。** Meta 的服务条款明文写着「未经许可不得用自动化手段访问或收集数据，登录状态下也一样」。Google 广告条款也禁止「用自动化手段或抓取来收集广告相关信息」。写操作两家都没有明文禁止，但「规避系统」类违规一旦认定就是重罚，Google 甚至可以不预警直接封号。我**没找到**「正常商家用插件改自己账户被封」的公开、可核实的案例。Chrome 商店里已经有几千人在用的「Meta 广告后台批量改」插件。降风险的办法：**用后台自带的导出、导入按钮，不去抓页面上的数据；每一步都过审批卡；慢、少、不并发；不做任何伪装；付款、账单、权限、账户设置这几块一律不碰。**
4. **第一期分四块**：①看数据（插件点官方的「导出报表」，AI 来分析）；②改广告（AI 生成官方格式的上传表 → 审批卡 → 插件上传 → 平台预览 → 人再确认一次 → 提交，前后都截屏留档）；③小改动（暂停、改预算，按审批卡由插件去点，前后截屏）；④**素材流水线**（Austin 的做法：标题和描述各一个子 Agent，设计岗批量出图，再加一份实验记忆）。第④块不碰钱，也不依赖插件，可以最先做。
5. **拆单建议**：开源仓 6 单，约 4–5 周。插件动作通道和素材流水线可以同时开工。第二期再做 Computer use 兜底和官方 API 加速。要 Luoye 定的事有 15 条（550–564），见第 6 节。

## 1. 我们现在有什么、差什么

### 1.1 浏览器插件（`apps/extension`）

| 项目 | 现状 | 依据 |
|---|---|---|
| 是什么 | 「Agents 工坊 · 红人助手」，Chrome 插件（MV3）。仓里这份是**参考实现**，内测用户装的完整版不开源（私有 Release 包） | `apps/extension/README.md` 第 3 行；docs/68、docs/76 |
| 能去哪些网站 | 只有 YouTube、Instagram、TikTok，加上本机服务 `127.0.0.1` | `wxt.config.ts` 的 `host_permissions` |
| 权限 | 只有 `storage`、`activeTab`、`alarms`。没有 `tabs`、`downloads`、`scripting`、`debugger` | 同上 |
| 怎么和本机服务说话 | 页面脚本先发给插件后台，插件后台再调本机 `http://127.0.0.1:<端口>`（6 位配对码换令牌，令牌 30 天有效，绑定插件来源）。**只能插件主动找本机，本机没法给插件下指令** | `src/lib/local-client.ts`、`messages.ts`；docs/76 |
| 在页面上能做什么 | **只读**：用户点了按钮才解析当前页面。没有点击、填表、上传、下载、截屏 | `src/lib/parse/*`、`bulk.ts` |
| 审批卡 | 插件里完全没有 | — |

**结论：广告要用的「动作」能力，插件一项都没有。**需要补的见 1.4。

### 1.2 仓里已有的「登录状态 + 审批卡」做法

| 做法 | 怎么工作 | 对广告有什么用 |
|---|---|---|
| **Reddit 官方号浏览器通道**（WP249，决策 89，已合并） | 用用户电脑上装好的 Chrome / Edge，**每个品牌一个独立的浏览器目录**。用户自己在可见窗口里登录，我们不碰密码和 cookie。每个动作都是**写死的一串步骤**（打开哪页、点哪个按钮、往哪个框填卡上的哪段字），不让模型自己找按钮。执行时**只放行这个动作白名单里的点击，网络上也只放这个动作需要的那几个提交请求**。做完回读页面确认（「读回自证」）。限速：两次写操作至少隔 20 秒，一天最多 30 次。遇到验证码或被限流就停下交给人。**不做任何伪装自动化的开关**。动作先出审批卡，有 2 分钟取消窗口，再交给执行器，最后记进变更账本 | **规矩全部照搬**：固定步骤、白名单、读回确认、限速、被拦就停、不伪装。代码在 `packages/social-core/src/channels/reddit-browser.ts` 和 `apps/server/src/reddit-official-browser/` |
| Facebook 群组浏览器动作（只有骨架） | 用 `BrowserAction{网址, 目标, 步骤, 校验, 写什么}` 描述一个动作，没有审批编号就不执行。**服务端还没接上** | 可以复用这个「动作描述」的形状 |
| 智能体浏览器（docs/55，dsh 官方 browser-use 和腾讯 BrowserSkill） | 服务端现在所有运行都是 `executor` 档，浏览器的写操作实际上全被门禁拦着 | 广告不走这条路 |
| Computer use（docs/80） | 默认关闭，按职责勾选，每次运行先出一张「允许操作 N 分钟」的卡。遇到密码、支付、验证码必须停下交给人。截图给模型看，**但不存进我们的记录** | 第二期兜底用。注意：广告这边要的「前后截屏留档」和 docs/80 的「截图不存」不一样，要单独定（决策 556） |
| 审批级别（docs/14、docs/95） | L1：每一条都要人点；L2：在额度内自己做（抽 10% 给人看）；L3：自己做，事后告知。批了不等于立刻执行：执行器会重新核对，还有 2 分钟取消窗口 | 沿用 |

另外要注意，Google 账号登录页会拦「被自动化软件控制的浏览器」（[Google 帮助：使用受支持的浏览器登录](https://support.google.com/accounts/answer/7675428?hl=en)）。Reddit 那种「另开浏览器目录、用调试协议驱动」的做法，在 Google 登录这一步有被拦的风险。插件跑在用户本来就登录好的 Chrome 里，没有这个问题。这也是广告该用插件、不该照搬 Reddit 执行器的一个理由。

### 1.3 投放岗和广告代码现状

- **docs/57 投放岗（WP75）的审批级别**：新建广告系列 L1，而且是写死的硬上限（`HARD_L1`），岗位配置里也再写了一遍；额度内改预算（加幅 ≤ 20%）L2；额度内改出价（≤ 15%）L2；止损暂停 L3，自动执行，事后发「已止损」卡；换素材 L2；向设计岗下需求单 L3。日花费总闸 ¥1000（四个平台加起来算），每天最多 20 次变更。超额提预算、调高总闸永远 L1。**现在没有单独的「激活 / 开始投放」这一类。**来源：`docs/57`、`packages/roles/roles/ads/meta.yml`。
- **`packages/ads-core`**：素材规格（尺寸、字数）、预算闸门计算、A/B 变体计划、归因对照、保本 ROAS，这些都是能直接用的纯计算。Meta / Google 的 API 适配器只在测试里跑过，服务端没接（`apps/server/src/ads-service.ts` 只出卡，从不调平台）。**现在没有生成上传表的代码。**
- **设计岗**（`packages/roles/roles/design/ads.yml`）：出变体是 L2，每份需求单最多 6 个变体，每天最多 30 次生成；入库永远 L1。Austin 那种一批几十上百张的量，现在的上限不够，见决策 559。
- **实验记忆**：代码里没有。只在 docs/100 里提过；docs/91 也把「实验」列成了缺口。
- **帮助文档** `docs/help/conn-google.md`、`conn-meta.md`：还在教用户「自己建 Google Cloud 项目 / Meta 应用、申请开发者令牌、贴长期令牌」。这和「用户零开发者配置」冲突，Google 那段在 9 月 10 日取消开发者令牌以后也过时了。要改成「装插件 → 在自己的浏览器里登录广告后台 → 完成」。
- **一个小坑**：`packages/skills/src/bundled.ts` 把「批量上传」「bulk upload」列成了**技能文本禁用词**，防止模型把它读成「可以自己上传」。所以广告技能里描述这个流程要换个说法（比如「出上传表、等卡批了由插件提交」），或者给这一条单开例外。拆单时写进 WP 要求。

### 1.4 差距清单：插件要补什么

| 缺什么 | 怎么补（建议） | 难点 |
|---|---|---|
| 去广告后台的权限 | 加 `ads.google.com`、`adsmanager.facebook.com`、`business.facebook.com`，**做成「可选权限」**，用户点「连接 Google 广告」时才弹窗申请，老用户升级时不会弹警告 | 动了权限，商店审核要重新过（内测走私有包，暂时不受影响） |
| 接收指令 | 插件定时问本机「有没有批好的活」（长轮询 `127.0.0.1`）。**还是插件主动找本机**，本机永远不能直接伸手进浏览器，安全模型和现在一样 | — |
| 按步骤点和填 | 照搬 Reddit 那套：每个动作一张写死的步骤表，只放行白名单，执行完回读确认 | 后台改版后选择器会失效，要有「对不上就停」的机制和每周巡检 |
| 上传文件 | 页面脚本把文件放进上传框（浏览器标准的 DataTransfer 做法）。**Meta 的导入框本来就支持「粘贴文字」**，可以完全不用传文件 | 能不能在两家后台用，要开发时实测 |
| 下载导出文件 | 加 `downloads` 权限，知道文件存到了哪，由桌面端去读 | — |
| 截屏 | `chrome.tabs.captureVisibleTab`。官方文档写明要 `<all_urls>` 或 `activeTab` 权限（[Chrome 文档](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-captureVisibleTab)）。建议把「再确认一次」放在广告后台页面上方插件的横条里，用户点一下就自然拿到 `activeTab`，不用申请 `<all_urls>` | 需要实测「点了横条以后后续几次截屏是否都有效」 |
| 审批绑定 | 每次执行都带审批编号和上传表的指纹，表被改过就拒绝上传 | — |
| 看得见、停得住 | 执行时广告后台标签页顶上显示「AI 正在操作（第 3/7 步）· 停止」，和 docs/80 托盘变红是同一个思路 | — |
| 名字 | 「红人助手」装进了广告功能，名字对不上了 | 见决策 551 |

## 2. Google Ads 后台能做什么

### 2.1 批量上传（Bulk uploads）

- **格式**：Google 表格、.xls、.xlsx、.tsv、.csv。**单个文件 ≤ 50MB、≤ 100 万行**，处理超过 2 小时会超时。网址要写全（带 https://）。**新建的条目如果「状态」列留空，默认就是「启用」**，所以我们生成的表里**新建的一律写成「已暂停」**（见决策 553）。删一行不等于删除，要删得在状态列写 Remove。改关键词的文字或匹配方式，等于删旧的、建新的。广告系列的类型建好后不能改。来源：[设置表格格式](https://support.google.com/google-ads/answer/10702623?hl=en)
- **能做哪些改动**（看官方模板清单）：
  - 广告系列：新建、改预算、改名称 / 起止日期 / 语言 / 设备、暂停 / 启用、删除、加减标签
  - 广告组：新建、改名、暂停 / 启用、删除
  - 广告：新建自适应搜索广告、自适应展示广告
  - 关键词：新增、删除、改最高单次点击出价；否定关键词列表
  - 附加信息（附加链接、宣传信息、结构化摘要、图片、电话、应用）、地理位置、受众出价调整、商品组

  来源：[模板和示例](https://support.google.com/google-ads/answer/10702525?hl=en)
- **在哪里传**：单个账户在「广告系列 / 广告组 / 广告 / 关键词」表格右上角的三点菜单里选「上传」。经理账户在「工具 → 批量操作 → 上传」。**上传后先预览**，能看到可能出的错，确认后再「应用」；不想要的可以直接移除。预览只显示前 1,000 行（其余行照样会处理），上传记录保留 90 天，应用后可以下载结果文件。来源：[上传表格并应用更改](https://support.google.com/google-ads/answer/10702433?hl=en)、[批量上传简介](https://support.google.com/google-ads/answer/10702932?hl=en)
- **能撤销吗**：**能，但只有一次。**在「工具 → 批量操作 → 所有批量操作」里，对某次上传点「撤销」，系统会再生成一次反向的批量改动。已经删掉的东西撤不回来；撤销一次后按钮就消失了。来源：[用「撤销」还原批量操作](https://support.google.com/google-ads/answer/10591951?hl=en)。另外「更改历史记录」里**最近 30 天**的大多数改动也能逐条撤销（[查看账户历史记录](https://support.google.com/google-ads/answer/2454137?hl=en)）。Google 自己也建议上传前先保存一份原始导出，我们会把这一步做成固定动作。

### 2.2 报表导出

- 每张统计表都能下载，格式有 Excel CSV、TSV、PDF、XLSX、XML、Google 表格。报表可以保存下来，设成按天 / 按周等频率**用邮件定时发送，但只能发给有这个账户访问权限的人**。18 个月没人打开的保存报表会被自动删除。来源：[从统计表创建、保存和定时发送报表](https://support.google.com/google-ads/answer/2404176?hl=en)
- 「报表编辑器」里有预设报表（广告系列、关键词、搜索字词、地理、设备等），可以加减列、保存、定时发送。来源：[创建和管理报表](https://support.google.com/google-ads/answer/6201327?hl=en)
- **我们怎么用**：第一次连接时，插件在用户后台建好一份「工坊日报」保存报表（出 L3 告知卡）。之后每天插件点一次「下载 CSV」，桌面端读取。**备用路线**：让 Google 把定时报表发到用户自己的邮箱，再由我们已有的邮箱连接（docs/63）去读。这条路完全不需要在后台里自动操作。不过邮件里是附件还是链接没核实到（见第 7 节）。

### 2.3 Google Ads Editor 合不合适

- 它是 Google 免费的**桌面程序**（Windows / Mac。官方说明 Mac 版从 2.9 起需要 macOS 12 以上，[2.10 版说明](https://support.google.com/google-ads/editor/answer/16320144?hl=en)）。工作方式是先把账户下载到本地离线改，最后「发布」。它也能导入 CSV，导入的改动先变成「待确认」，可以全部接受、全部拒绝或逐条看（预览只显示前 100 行）。**发布之前可以随时还原，发布之后没法自动撤销**，Google 建议大改之前先导出存档。来源：[在 Editor 中导入 CSV](https://support.google.com/google-ads/editor/answer/30564)、[还原更改](https://support.google.com/google-ads/editor/answer/30577?hl=en)、[导出 CSV](https://support.google.com/google-ads/editor/answer/38657?hl=en)
- **判断：不作为默认路线。**理由：①插件够不着桌面程序，只能靠 Computer use 去点，风险和成本都高；②要用户另外装一个程序，和「零配置」冲突；③网页版的批量上传已经有预览和撤销，够用了。**留两个口子**：会用 Editor 的老手可以拿我们生成的表自己导入（帮助文档里写一段就行，Editor 的列名和网页版不完全一样，要做个对照）；第二期 Computer use 兜底时再重新评估。

### 2.4 顺带一提：后台自带的自动化

Google 后台自带「自动规则」和「Google Ads 脚本」，都是官方在账户里运行的自动化，不需要申请接口审核。脚本能把报表写进 Google 表格，也支持批量上传（同样分预览和应用，[脚本批量上传](https://developers.google.com/google-ads/scripts/docs/concepts/bulk-upload)）。第一期不用。第二期可以考虑由插件替用户装一条官方「自动规则」作为止损的第二道闸（见决策 563）。

## 3. Meta Ads Manager 能做什么

### 3.1 批量导入 / 导出（Import ads in bulk）

- **入口和格式**：Ads Manager 的「广告系列 / 广告组 / 广告」标签下，点「更多 → 批量导入广告」。**可以粘贴文字，也可以上传 Excel 文件**，同一步还能批量上传图片和视频。**只能在电脑上用。**文件大约 **2MB 封顶**。来源：[批量上传和导入广告](https://www.facebook.com/business/help/122918328469908)、[导入广告](https://www.facebook.com/business/help/232961787388181)
- **新建**：先下载空白模板（[下载导入模板](https://www.facebook.com/business/help/837176152970474)），或者导出一个现有的广告系列照着改。**新建的时候要把各种编号列清空**（[模板导入排错](https://www.facebook.com/business/help/216243691909235)）。
- **修改**：先导出（CSV、XLSX 或文字），改完再导入。**除了广告编号、广告系列编号、图片哈希，其他字段都能改。**Meta 提醒：改某些字段**会让广告重新进入学习期，或者重新过一遍审核**。来源：[用 Excel 编辑广告](https://www.facebook.com/business/help/158169530916536)、[导出广告](https://www.facebook.com/business/help/849477685213347)
- **列名和后台显示的名字不一样**：比如「标题」在表里叫 Title，「正文」叫 Body，主页要写成 `o:主页编号`，图片可以填已上传图片的哈希，也可以填随表一起上传的文件名。另外，导出时凡是以 `+ - = @` 开头的内容，前面会被加上 `< >`，这是防止 Excel 把它当公式执行，不能删，我们解析时要处理。来源：[字段名与表格列名对照](https://www.facebook.com/business/help/1462433740708893)、[导出广告](https://www.facebook.com/business/help/849477685213347)
- **有预览吗**：有。导入完先给一份摘要，列出导入了什么、有哪些警告、哪些是阻断错误（可以「在 Excel 中查看错误」）。**导入的内容是草稿**，要点「审核并发布」，勾选要发布的条目，再点「发布」才生效。这一步正好就是我们的「平台预览 → 人再确认 → 提交」。
- **不支持的情况**：A/B 测试里的广告系列导出再导入后测试会被去掉；带优惠的广告组会丢掉优惠；品牌合作广告会丢掉合作主页；多语言广告最多保留 10 种语言；预订型广告系列、带版位定制的轮播广告会变成发不出去的错误草稿。来源：[含不支持功能的导入导出](https://www.facebook.com/business/help/1552289101641057)
- **新账户的功能可能不全**：Meta 说新建的商务账户或广告账户不一定能用所有广告功能（同上「导入广告」页）。
- **能撤销吗**：**没查到 Meta 有一键撤销批量导入的功能**（见第 7 节）。我们的办法是：导入前先导出一份「改前表」，出了问题就用改前表反向导入（也要出 L1 卡）。

### 3.2 报表导出和定时报表

- 「广告报告」（Ads Reporting）里保存的报表可以导出成 .xlsx / .csv，也可以生成分享链接。需要广告账户的管理员、广告主或分析师权限。**最多能查 37 个月。**来源：[导出和分享报表](https://www.facebook.com/business/help/276601619787641)
- **定时邮件**：报表可以设成定期发邮件，**只支持单个广告账户的报表，跨账户报表不能定时**，而且**只有对这个广告账户有权限的人才能打开**。来源：[定时发送报表](https://www.facebook.com/business/help/596403700379202)
- Meta 还有 Excel 插件「Ads Manager for Excel」，每天或每 15 分钟刷新一次（[介绍](https://www.facebook.com/business/help/248094205618729)）。那是给 Excel 用的，我们用不上。
- **我们怎么用**：和 Google 一样，插件第一次在用户后台建一份「工坊日报」，之后每天点一次导出。备用是定时邮件发到用户自己的邮箱，再由邮箱连接去读。

### 4.1 条款原文怎么说

| 平台 | 条款 | 大意 | 对我们的影响 |

| Google | [广告计划条款](https://support.google.com/adspolicy/answer/54818?hl=en) 第 2 节 | 客户不得「用任何自动化手段或抓取、数据提取，从任何资源访问、查询或收集 Google 广告相关信息，除非 Google 明确许可」，也不得干扰广告计划的正常运作 | 条款里的「资源」指的是投放广告的版面，主要针对抓搜索结果页上的广告。用户在自己后台点导出算不算，**原文没说清**。办法同上：只用导出按钮 |

### 4.2 有没有因为这个被封的公开案例

- **没找到「正常商家用插件改自己的账户而被封」的、可核实的公开案例。**能找到的都是零散的论坛帖子。比如有位 Shopify 商家说用了某个 Google 广告应用之后账户被封，但没有证据证明是那个应用导致的（[Shopify 社区帖](https://community.shopify.com/t/why-did-google-ads-suspend-my-account-for-a-circumventing-systems-policy-violation/113656)）。
- **真实存在的风险是恶意插件。**有冒充广告工具的插件专门偷 Meta 广告账户（[eSecurity Planet](https://www.esecurityplanet.com/news/chrome-add-on-steals-meta-ad-accounts/)、[ThreatDown](https://www.threatdown.com/blog/criminals-target-businesses-with-malicious-extension-for-metas-ads-manager-and-accidentally-leak-stolen-accounts/)），所以 Meta 对「插件在 Ads Manager 里动手」本身就比较警惕。我们的插件权限必须少、行为必须透明。
- **同类插件确实存在**：「Meta Ads Manager Helper」（Kitchn.io）在 Chrome 商店里，约 3,000 用户，2026-07-15 还在更新，能在 Ads Manager 里批量关闭创意优化、复制广告（[商店页](https://chromewebstore.google.com/detail/meta-ads-manager-helper-b/jodnncgnhfdaoikfecnjiehncbnhcpki?hl=en)）。另一个「Meta Ads Manager Assistant」据第三方统计在 2026-05-20 被商店下架，原因不明。
- 「怀疑你的账户有自动化行为」这类 Facebook 账号检查确实存在，但官方说明没查到，只有第三方说法。

### 4.3 怎么把风险压到最低（写进插件的硬规矩）

1. **只做人本来也会做的那几个动作**：上传官方格式的表、在平台预览页点「应用 / 发布」、暂停 / 启用、改预算、点「导出」。别的按钮全不在白名单里。
2. **以导出 / 导入为主，少点表单。**改 3 条以上就走上传表。逐个点表单只用于暂停和改预算这两类。
3. **每一步都有审批**：写操作按 docs/57 的级别出卡。批量上传因为里面有新建，一律 L1，还要「平台预览后再确认一次」。
4. **节奏慢、量少、不并发**：同一个广告账户同一时间只做一件事；两步之间留足间隔；每个账户每天的写操作不超过 docs/57 的 20 次；读报表一天一两次。**这是限速，不是伪装**：不加随机抖动去「装得像人」，不改浏览器标识，不绕验证码（与 Reddit 通道同一条纪律）。
5. **绝不碰的区域写死**：付款方式、账单、发票、余额、用户和权限、商务管理平台设置、账户验证、申诉、新建广告账户、像素和转化设置、删除广告系列。插件一进入这些页面就停下，把页面交给人。
6. **只在看得见的标签页里做**：不在后台偷偷开无界面浏览器，用户随时能点「停止」。
7. **新建的一律先暂停**，「激活 / 开始投放」单独出一张 L1 卡（决策 553）。
8. **前后截屏 + 前后导出表 + 上传表**一起进变更账本，出了事能对、能还原。
9. **连接时如实告知**：用一段白话说明这是在你自己的后台替你点、平台条款对自动化有模糊地带、最坏的情况是账户受限需要申诉，用户勾选同意后才开通（决策 562）。

**整体判断**：按这些规矩做，风险在「低到中」。读数据这一侧（尤其 Meta）是条款上最敏感的。如果以后真出现封号案例，最快的退路是把「读」先切到官方只读接口（Meta 的 `ads_read`），这条已经在 docs/100 里调研过（决策 564）。

### 5.1 第一期：四块

#### ① 看数据

> **WP315 实现（10-15，待审）**：见 `docs/briefs/reports/WP315.md`。步骤表在 `packages/browser-action/src/ads/report.ts`
> （`setup_daily_report` 写、L3 告知卡编号当审批编号；`export_daily_report` 读、只点下载 CSV；Google 五份、Meta 一份，

> （按天存 90 天，「今天」那份同步进广告库；每小时一拍、本地 9 点后导一次；插件一天没来领活改读邮箱附件）；
> 投放岗三个工具 `query_ads_data` / `fetch_ads_data_now` / `stage_ads_stop_loss`；日报不是固定功能——
> 第一次有数后在「广告日报」事项里种一条每天 10 点的官方自动化任务（提示词 = 默认日报要求，用户说一句就改）。

#### ② 改广告（主路线：官方上传表）

1. **改前快照**：插件导出受影响的那部分（作为对照和「撤销底稿」）。
2. **AI 出上传表**：按官方模板生成（Google 用 CSV，Meta 用 Excel 或可粘贴的文字）。生成后先在本地检查：字数（Google 标题 30 字符、描述 90 字符等，规格已在 `ads-core/spec.ts`）、必填列、文案禁用词（已有的 `AD_COPY_FORBIDDEN`）、**新建的一律写成「已暂停」**、预算改动不能超过 docs/57 的额度。
3. **审批卡（L1）**：用白话一句话说清楚（「新建 2 个广告组、12 条广告，都先暂停；A 系列预算从 ¥200 改到 ¥230」），附表格预览，可下载原表。卡上字要少（照「界面少字」的规矩）。
4. **批了 → 插件上传**：在用户已登录的后台标签页里上传（Meta 可以直接粘贴文字），等平台生成预览。
5. **平台预览 → 截屏 → 再确认一次**：插件把平台的预览页截下来，并读出平台报了几个错误 / 警告，回到工坊。用户在广告后台页面顶上的插件横条，或工坊的卡上点「确认提交」。平台报了阻断错误就不给提交，直接退回 AI 修改。
6. **提交**：Google 点「应用」，Meta 点「审核并发布 → 发布」。提交后截屏。
7. **读回核对**：等平台处理完，再导出一次，和上传表逐行比对（照搬 Reddit 的「读回自证」）。对不上就照实报告。
8. **记账**：上传表、改前 / 改后导出表、平台预览截图、提交后截图、审批编号，一起进变更账本。
9. **撤销**：Google 在「批量操作」里有一次性撤销，或者 30 天内在「更改历史」里撤销。Meta 用改前表反向导入。两家的撤销都要出 L1 卡，由插件执行。

> **WP316 实现（10-15，待审）**：上面九步与 ③ 小改动都接上了，见 docs/57 §8 与 `docs/briefs/reports/WP316.md`。
> 与原设想不同的两处：「再确认」除了插件横条，还在职责页「广告改动」那一块（投放这条职责自己点，不用老板那把权限）；
> Google 表单那几下（暂停 / 改预算）的撤销是反着点一遍，没走「更改历史」。

#### ③ 小改动（插件直接点，但只限白名单里的动作）

| 动作 | 级别（沿用 docs/57） | 插件怎么做 |

#### ④ 素材流水线（Austin 的做法，第一期头号功能，不依赖插件）

- **数据进来**：导出现有广告和表现数据（来自 ①），挑出表现差的。
- **两个子 Agent**：一个专写标题（Google 自适应搜索广告最多 15 条，每条 ≤ 30 字符），一个专写描述（最多 4 条，每条 ≤ 90 字符）。Meta 那边对应写正文和标题。都要对照品牌语气（`brand-design.ts` / DESIGN.md）、产品事实和平台写法。
- **设计岗批量出图**：投放岗下需求单（L3）→ 设计岗出变体（L2，给人挑）→ 入库（L1）。这对应 Austin 用的 Figma 插件。现在「每单 6 个、每天 30 次」的上限对广告批量来说太低（决策 559）。
- **实验记忆**：每一轮记三样东西：假设（例如「标题里带价格点击率更高」）、改了什么、结果如何。下次出变体时把这些带进上下文。按品牌存，归投放岗的记忆（docs/54 的岗位记忆）。
- **出口**：拼成 ② 里的上传表，走同一个审批流程。所以 ④ 可以先做，② 没好之前用户也能下载这张表自己去后台上传（这正是 Austin 当时的做法）。

## 6. 要 Luoye 定的事（决策 550 起）

| 号 | 要定什么 | 我的建议 |
|---|---|---|
| **550** | 广告的执行载体：**用户日常用的 Chrome 里的插件**，还是照 Reddit 那样另开独立浏览器目录、由本机服务驱动 | **用插件。**用户本来就在日常 Chrome 里登录了广告后台，不用再登录一遍；Google 登录页会拦被自动化控制的浏览器；用户看得见、停得住。Reddit 那套的**规矩**（固定步骤、白名单、读回确认、限速）原样搬过来，**执行的地方**换成插件 |

## 7. 没核实到的事（别当事实引用）

1. **Google 批量上传的「新建广告系列」模板支持哪些广告系列类型**（搜索类肯定支持；效果最大化 / 购物类能不能用表格新建，官方模板页没写列名，没下载模板核对）。
2. **Google 定时报表邮件里是附件还是链接**：官方页面只说「按你选的格式发」，没写清楚。如果只是链接，邮箱备用路线就读不到数据。
3. **Meta 批量导入有没有撤销**：官方帮助里没找到；只知道广告账户有「活动记录」，但那是看记录，不是撤销。
4. **Meta 批量导入的确切行数上限**：官方只写了「约 2MB」。第三方说一批 200 条，没核实。
5. **Meta 定时报表邮件的内容**（附件还是链接）同样没核实。
6. **Meta 广告标准「规避系统」原文**：官方页面打不开（Transparency Center 返回「页面不可用」），内容来自 Jon Loomer 的转述。
7. **Google 广告计划条款第 2 节里的「资源」（Property）是否包括广告后台本身**：从定义看是指投放广告的版面，但这只是我的理解，不是法律意见。
8. **robots.txt 是否适用于用户自己装的插件**：两家都没说明。
9. **插件把文件塞进上传框（DataTransfer）在两家后台能不能用**，以及「点一下横条拿到 activeTab 后，后面几次截屏是不是都有效」：要开发时实测。
10. **「Meta Ads Manager Assistant」被 Chrome 商店下架的原因**：只有第三方统计站的下架日期（2026-05-20）。
11. **Facebook「怀疑你的账户有自动化行为」检查的触发条件**：只有第三方说法，没有官方说明。
12. **Google Ads Editor 的 Windows 系统要求**（64 位 Windows 10 以上）：只有第三方说法。Mac 要求 macOS 12 以上来自官方版本说明。
13. **Google 和 Meta 报表的确切生成时间**：Google 两篇帮助页分别写的是凌晨 1 点和 3 点，互相矛盾。

## 附 B：给 AI 用的广告 CLI 调研（10-14，Luoye 问）

- **Google Workspace CLI（`gws`）**：Justin Poehnelt（Google 开发者关系）2026-03 发布，仓库在 googleworkspace 组织下但不是官方支持产品，Apache-2.0、Rust、约 3.1 万 star。覆盖 Drive / Gmail / 日历 / 表格等，**不含 Google 广告**。授权要用户自己的 Cloud 项目和 OAuth 客户端。https://github.com/googleworkspace/cli
- **Google 广告**：没有官方能改广告的 CLI。官方 `google-ads-mcp` 只读（Apache-2.0）；官方开发助手只生成代码；社区 `google-ads-open-cli`（TS、Apache-2.0、只读）、`gaql-cli`（Python、Apache-2.0）。都要开发者令牌 + 用户自己的 OAuth 客户端。
- **Meta 广告**：官方 Ads CLI（PyPI `meta-ads` 1.2.0，**专有许可**，Python 3.12+）能读能写、新建默认暂停，但要用户建系统用户、生成长期令牌；社区 `attainmentlabs/meta-ads-cli`（MIT、半年没更新）；`pipeboard` 为 BSL 不能用。
- **结论**：都不打包进安装包（要装 Python / gcloud、要用户出开发者凭据，违反零配置；Meta 官方 CLI 许可证进不了开源仓）。借鉴它们「给 AI 用」的设计放进我们自己的 TS 适配器：统一 JSON 输出（错误也是 JSON）、先预览再执行（预览喂审批卡）、可查每个操作的参数与返回、新建默认暂停、只读 / 读写 / 花钱三档权限、返回内容做提示词注入扫描、精简工具数。官方 API 加速那一档（决策 564）凭据由我们出，CLI 只作内部开发测试参照。
