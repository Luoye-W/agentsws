## 0. 一句话

**今天的软件只有一种样子——公司的样子。** 一个人刚装好，左栏就有「公司」，公司页里有负责人、成员、上级、品牌与产品线、加入一家公司、并进来；职责规矩里写着「主管定」「老板定」。这份文档把每一样东西归到三种用法里：① 只给一个人看他用得上的；② 给几个平级的人加上「互相看得见、能把事交给对方」；③ 才有「有人管人」的那一整套。

**三句话判别：**

- **① 个人**：这里只有你一个人（品牌可以有好几个）。
- **② 同事互联**：好几个人，平起平坐，谁也不批谁。
- **③ 公司集体**：有人管人——有主管、有老板、有人批你的活。

## 1. 三种模式的定义

| | ① 个人使用（默认） | ② 同事互联 | ③ 公司集体使用 |
|---|---|---|---|
| 谁在用 | 一个人；可以管好几个品牌（你现在的 INMO + Rollout 就是这种） | 两个以上平级的人 | 一家公司，老板 / 管理员**主动开启** |
| 岗位与 AI | 有，全部 | 有；每人各有各的岗位、卡片、待办 | 有 |
| AI 对外动作要人点 | 要，**点的是你自己**（安全闸） | 要，**谁的岗位谁点**（安全闸） | 按职责规矩：本人点 / 主管批 / 老板批（审批流） |
| 互相看得见 | — | 同事名单、谁在做什么、问同事的代理、约时间 | 同 ②，再加部门视图 |
| 共享 | — | 同一个品牌里的知识、素材、客户、工具箱本来就是一份 | 同 ②；成员能看到哪些由「范围」切 |
| 把事交给别人 | — | 「交给对方」，**对方点接下才算**（§4） | 平级之间同 ②；上级可以直接派（§8 第 10 条） |
| 上下级 / 部门 / 组织架构 | 没有 | 没有 | 有 |
| 审批流（主管定 / 老板定 / 超时升级） | 没有 | 没有 | 有 |
| 成员额度 | 没有 | 没有（共用一个余额，按人只显示用量） | 有 |
| 权限范围（店铺组 / 产品线切分） | 没有，自动管整个品牌 | 没有，人人看整个品牌 | 有 |
| 离职交接 / 审计视图 | 没有 | 只有「退出」与「请他离开」 | 有 |
| 管家务的人 | 你 | 一位「发起人」：只管请人进来、请人离开、删品牌，**不批任何人的活** | 老板（所有者）与管理员 |
| 数据放哪 | 本机（或托管） | 要一个大家都连得上的地方：发起人的电脑 / 常开机器 / 托管（§3.3） | 同 ② |

### 1.1 要分清的两个「公司」

1. **公司主体**：营业执照上的全称、实体地址。它是**生意的事实**——开发信页脚（法规要求带地址）、报价单、单证都要用。一个人做跨境也常常有个公司主体，所以 ① 里它**不是要删的东西**，只是换个地方、换个叫法（§8 第 2 条）。
2. **公司模式（③）**：有人管人的组织形态。上级、审批路由、成员额度、范围、离职交接都属于它。

今天的界面把这两件事混在一个「公司」字下面，这是「一个人装好就看见公司」的主要来源。

### 1.2 品牌数量与模式无关

一个人管三个品牌，仍然是 ①。但今天的代码用「人数 ≤ 1 **且** 品牌数 ≤ 1」判断「个人用户」（`apps/server/src/organizations.ts` 里的 `solo`），品牌一到两个就被当成「不是个人」：设置页冒出「公司」卡、工作区的 `kind` 被改成 `shared`（`apps/server/src/boot-brand-org.ts`）。你自己那台机器就是这样。模式应该只看「有几个人、有没有开公司模式」，不看品牌数。

### 1.3 三种模式与三档部署是两回事

13 §5 的三档（个人电脑 / 公司常开机器或 NAS / 我们托管）说的是**数据放在哪台机器上**；本文的三种模式说的是**人和人之间什么关系**。① 也可以托管；② 只要大家连得上同一个地方就行，不要求一定是公司机房。

## 3. 模式怎么开、怎么升、能不能降

### 3.1 今天的数据模型（白话）

- 每台机器一启动就有一家「公司」（组织），里面一个品牌、一个人，这个人是公司的所有者、品牌的负责人。
- 「是不是个人用户」不是存下来的，是每次现算的（人 ≤ 1 且品牌 ≤ 1），只用来藏顶栏切换器、设置页「公司」卡、⌘K 的品牌搜索三处。
- 第二个人进来的唯一路子是「加入一家公司」：申请 → 所有者批 → 他成了公司成员。从这一刻起，审批路由、职责分离、上级、范围全部按「公司」算——**今天没有「平级」这种状态**。
- 职责分离（提的人不能自批）按人数开关；超时升级、离职交接、范围都不看任何开关，一直开着。

### 3.2 要加的东西（只加不删）

1. **组织上加一格「模式」**：`Organization.mode?: 'solo' | 'peers' | 'company'`，再加谁在什么时候改的（`mode_changed_at` / `mode_changed_by`）与一条事件 `organization.mode_changed`。契约只加；老数据没有这一格时按 §3.7 推。
2. **一个地方说了算**：服务端一个函数回答「这个组织现在是哪种模式、哪些公司功能开着」，审批路由、职责分离、超时升级、范围、离职、额度、邀请都问它；工作台拿到 `OrgView.mode`，按模式收起与换词（两套词放在 i18n 里，不在组件里写判断字句）。
3. **一个接口**：`PUT /v1/orgs/:id/mode`（开公司模式 / 回到同事互联），只有所有者能调；② ← → ① 不用人调，由人数自动走（§3.3、§3.6）。
4. **交给对方要的那几样**（§4）：待办与事项的「交出去 / 接下 / 不接 / 撤回 / 超时退回」，一种新卡（或复用现有的认领卡 `claim`），事项可以换主人。
5. **建分配时的默认范围**：① ② 一律「整个品牌」，不再出现「没给范围」。

### 3.3 ① → ② 同事互联

- **怎么开**：在「岗位与品牌」页（今天的公司页）点「和同事一起用」→ 打开「让同事找到我」→ 发邀请码，或者同事那边输入你的码 / 在局域网里看见你、点申请。**第一位同事被同意进来的那一刻，就是 ②**——同意这个动作本身就是你主动做的，不需要另一个开关。
- **数据放哪**：② 要一个大家都连得上的地方。三个选法（§8 第 5 条）：发起人自己的电脑（最省事，但他关机、睡眠，同事就用不了）/ 一台常开的机器或 NAS（13 §5 第二档）/ 我们托管。同事那边的桌面端用「连到别人的服务」那一档（壳已有 `remote` 模式）。
- **他原来的东西**：照 45 H1——他的品牌工作区整个挂进来，一个字节不动；两人各自建了**同一个品牌**才出对照表，由发起人确认。
- **进来以后**：每人各自的岗位、卡片、待办；同一个品牌里的知识、素材、客户、工具箱本来就是同一份；人人看整个品牌；没有任何人批别人的活。

### 3.4 ② → ③ 公司集体

- **谁能开**：只有发起人（组织所有者）。人再多也不会自己变过去。
- **要填什么**（一屏）：公司全称（必填，这时候它就是公司了）；谁是老板（默认发起人）、谁是管理员（可不选）。部门、上级、范围、额度**都可以开完再慢慢设**——不设的时候，「主管定」落到老板，范围是整个品牌，额度不限，所以开的那一刻没有任何人突然看不到东西或干不了活。
- **现有同事怎么变成成员**：身份从「同事」变「成员」，手上的岗位、分配、事项、待办一样不变；每人收到一张卡「X 把这里改成了公司模式：以后报价超限这类事要主管或老板批」，按钮「知道了」「我要退出」（§8 第 8 条）。
- **数据怎么并**：不用并。② 时大家已经在同一个组织、同一个品牌里了。
- **从开的那一刻起**：之后新出的卡按规矩路由（本人定 / 主管定 / 老板定）；之前已出、还没定的卡**不改派**，免得卡在半路换人。职责分离、超时升级、成员额度、离职交接、范围、审计视图打开。

### 3.5 ① → ③ 直接开

允许。老板先一个人装好、开公司模式、设好岗位与规矩，再请员工进来——这正是「公司集体使用」最常见的起法。流程同 §3.4，只是没有现成的同事要通知。

### 3.6 能不能降

| 方向 | 允许吗 | 怎么处理 |
|---|---|---|
| ③ → ② | 允许，只有老板能降（§8 第 9 条） | 上级、范围、额度、部门这些**收起不删**，再开时原样回来；还没定、正在等主管或老板的卡退回给「这件事是谁的」那个人；离职中的流程先做完才能降 |
| ③ → ① | 不直接降 | 先到 ②，人走到只剩一个时自动到 ① |
| ② → ① | 自动 | 同事都退出、只剩一个人时就是 ①；同事界面收起，数据都在 |
| 某人退出 ② | 允许，随时 | 03 §7.4 的退出规矩照旧：个人渠道（个人微信等）跟人走；共享品牌里的客户、知识留下；他手上没做完的事退回原处或交给别人（对方要接下）。要不要让他带走一份自己建的东西的副本，见 §8 第 8 条 |

### 3.7 老安装怎么归档

新加的「模式」那一格，老数据里没有。建议按这条规矩一次性推出来（§8 第 1 条）：

- 公司里**除了你还有在职的人** → ③（行为与今天完全一样，谁也不会少东西）；
- 只有你一个人（不管几个品牌）→ ①。

你那台机器（INMO + Rollout，一个人）会落到 ①：公司页变「岗位与品牌」，上级、范围、成员这些收起，数据都在。
