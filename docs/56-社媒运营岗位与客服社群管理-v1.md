## 0. 一句话

九条渠道职责骨架相同、各自一个连接器，分两组只是模板里的摆法：**内容账号组**（Meta / TikTok / X / YouTube）写的是发布、排期、回评论，**发布永远人审**；**社群组**（Facebook Group / Reddit / Discord / Telegram Group / WhatsApp）写的是入群审核、群规、群发、私信，接抑制名单与频率上限，**群发永远人审**。共用能力进 `social-core`。群里冒出来的客户问题由岗位路由转给客服的"社群管理"。

## 1. 前置（P0）

- 连接按渠道各一张卡（凭据原生表单进本机加密库，按品牌隔离，WP66）：`meta_graph`（一把 token 管主页 + IG）、`tiktok_content`、`x_api`、`youtube_data`（**与红人岗位的 `youtube_data` 是同一张卡**）、`reddit`、`discord_bot`、`telegram_bot`、`whatsapp_business`；Facebook Group **没有卡**——Groups API 已停，走第三栏受控浏览器（36 §9 / docs/55 的浏览器执行器），职责里标 `mode: browser`。
- 接口现实写进连接卡的准备说明：TikTok 申请制、X 付费档、WhatsApp 要模板消息 + opt-in + 24h 窗口。

## 2. 职责骨架（P1）

| 组 | 职责 | 读 | 写（→ ChangeKind） | 额度默认 | 上限 |
|---|---|---|---|---|---|
| 内容 | `social.meta` / `social.tiktok` / `social.x` / `social.youtube` | 账号资料、帖子 / 视频列表与表现、评论、私信（只读）、粉丝数 | `stage_post`（`social_post`：发布 / 排期）、`reply_comment`（`outbound_message`）、`stage_profile_edit`（`social_profile_edit`） | `max_posts_per_day` 3、`max_comment_replies_per_day` 50 | **发布永远 L1**；回评论 L2 → L3（承诺扫描 + 抑制名单）；改资料 L1 |
| 社群 | `social.facebook-group`（browser）/ `social.reddit` / `social.discord` / `social.telegram-group` / `social.whatsapp` | 成员 / 入群申请、帖子与讨论、群规、活跃度 | `approve_member`（`community_membership` L2）、`stage_broadcast`（`community_broadcast` **永远 L1**）、`reply_thread`（`outbound_message` L2 → L3）、`stage_rules_edit`（`community_rules` L1）、`moderate`（`community_moderation`：删帖 / 禁言 L2，封禁 L1） | `max_broadcasts_per_week` 1、`max_dm_per_day` 30、`max_moderations_per_day` 20；WhatsApp 另加 `max_template_messages_per_day` 100 且 `opt_in_required: true` | 群发 L1；私信 L2；WhatsApp 模板消息 L1 + 无 opt-in 即 block |

- 所有出站文案过 `commitment_scan` + `suppression.ts`（WP64 那份全仓唯一规则）；社群组的私信与回帖还过"是不是客户问题"分类（`social-core/triage`）→ 是 → 出"转客服"卡（54 岗位路由到客服的社群管理），社媒运营不答。
- 面板（36 积木）：内容组：内容日历（本周 / 下周排期）、待发布队列、近 30 天表现（曝光 / 互动 / 涨粉）、待回评论；社群组：待审入群、活跃度、待处理帖子、群发队列、转客服计数。数据源没连就明说。
- 卡：发布卡（L1，带预览与排期时间）、回评论草稿卡、群发卡（L1，带受众数与抑制剔除数）、入群审核卡、转客服卡。

## 3. `social-core`（P2）

同 `kol-core` 纪律：`calendar.ts`（内容日历 / 排期 / 撞车）、`triage.ts`（评论 / 私信 / 帖子分类：客户问题 / 夸 / 投诉 / 垃圾 / 合作询问→转红人 / 其它）、`voice.ts`（品牌话术：从公司层技能取，不在这里编）、`broadcast.ts`（受众 / 抑制 / 频率）、`moderation.ts`（群规匹配、分级：删 / 禁言 / 封）、`channels/{meta,tiktok,x,youtube,reddit,discord,telegram,whatsapp}.ts` 适配器接口（`profile / posts / comments / publish / reply / members / broadcast / moderate`，每个渠道只实现它有的），`channels/facebook-group.ts` = 浏览器模式接口（动作 = 受控浏览器脚本，写动作仍先出卡）。

## 4. 客服岗位加一条：`dtc.community-support` 社群管理（P3）

- 干什么：群与私信里的**客户问题**（售前问答、订单、售后）——由社媒运营的 triage 转过来，或直接从这些渠道的私信收件；答法与 `dtc.support` 同一套（知识、事实卡、额度、承诺扫描），只是渠道不同。
- 读：转客服卡、该渠道私信 / 帖子（只读）、订单 / 知识；写：`reply_customer`（`outbound_message` L2 → L3）、`stage_refund` 等沿用 `dtc.support` 的动作与额度（同一份 caps，不另起）。
- 岗位模板"客服"= 网站客服 / 网站在线客服 / Amazon 客服 / **社群管理**，默认全勾。
- 与社媒运营的分界写在两条职责的 description 里（54 路由判据靠它）：社媒运营 = 内容、氛围、活动、群规；社群管理 = 客户的问题。

## 5. 模拟（P4）

3 人 pack +3（三运行时）：`social/post-needs-approval`（排期发布永远出卡）、`social/comment-reply-within-quota`（回评论额度内 L3 自动，承诺词被拦改写）、`community/customer-question-routes-to-support`（Discord 里有人问"我的单什么时候到"→ triage → 转客服卡 → 社群管理答）；15 人 pack +1：`community/broadcast-respects-suppression`（群发剔除抑制名单 + 永远 L1）。

## 7. 额度默认值（P6）

发帖 3 / 天、回评论 50 / 天、群发 1 / 周、私信 30 / 天、审核动作 20 / 天、WhatsApp 模板消息 100 / 天；改动走职责额度 → `policy_change` 审批。
