# 100 让 AI 员工直接管 Google / Meta 广告：现成方案调研

> 调研日期：2026-10-13（只上网查、没登录任何账号、没调付费接口，仓库一个字没改）
> 给谁看：Luoye。尽量少用术语，每个关键事实后面都附了链接。没核实到的统一放在第 6 节。

## 0. 一页结论

1. **推特上那个说法是真的，但跟大家想的有出入。** 当事人叫 Austin Lau，是 Anthropic 第一个增长营销，不会写代码，有大约 10 个月一个人管付费搜索、付费社媒、应用商店、邮件和 SEO。「几百组广告」说的是：Austin 让 Claude Code 读一张装着**几百条现有广告和投放数据**的表格，挑出表现差的，**几分钟生成几百条新广告**。**关键在于 AI 没有直接去广告后台花钱**：Google 广告是导出成表格、**人看过以后再手动上传**；Meta 那边做的工具只用来**读数据**。
2. **2026 年两家都放开了**：Meta 4 月出了官方托管的广告 MCP，能建广告、改预算、开投放，新建的广告默认是暂停状态；7 月起任何开发者的应用都能接进来。Google 官方 MCP 到今天仍然**只能读**，要改东西得自己调 Google Ads API。9 月 10 日 Google 把开发者令牌（developer token）取消了，改成按 Google Cloud 项目审批，基础权限在品牌验证后几分钟内就能批下来。
3. **「零开发者配置」能做到**：由工坊统一申请 **1 个 Google Cloud 项目 + 1 个 Meta 应用**，用户只需要点「去授权」。我们这边要过四道审核：Google 品牌验证、Google 登录授权验证、Meta 商业验证、Meta 应用审核。**整体估计 3–8 周**，其中 Meta 最慢。
4. **推荐路线**：第一期先接「读数据」，再加「生成批量上传文件 + 审批卡、由人上传」（也就是 Austin 的做法）。第二期等审核都过了，再让 API 直接写，**每一笔花钱的写操作都过 L1 审批卡**，Meta 后台再设一道预算上限作为第二道闸。
5. **开源代码能拿来用的**：Google 官方 MCP 是 Apache-2.0，可以参考或移植。Pipeboard 是 BSL（2029 年才转开源），armavita 是 AGPL，brijr 没有许可证，这三个**都不能抄**。我们仓里 WP75 已经有 Meta / Google 的 TS 适配器骨架，直接在那上面接就行，不必引入 Python 运行时。

### 1.2 Austin 具体怎么做的（以官方白皮书和官方博客为准）

**用的工具**：Claude Code，加上Austin 自己让 Claude 写的小工具。没用任何商业广告 SaaS。

| 做了什么 | 怎么做 | 动没动钱 | 来源 |
|---|---|---|---|
| **Google 搜索广告批量出文案** | 把几百条现有广告连同表现数据导出成 CSV，交给 Claude Code。Claude 挑出表现差的，生成符合字数限制的新版本（标题 30 字符、描述 90 字符）。拆成**两个子 Agent**，一个专写标题，一个专写描述，几分钟能出几百条新广告 | **没动**。导出成可直接上传的 CSV，**人审过再手动上传** | 白皮书第 15 页；博客 |
| `/rsa` 斜杠命令 | 自定义命令：Claude 问 Austin 要 campaign 数据、现有文案和关键词，再对照几份 Skill（品牌语气、产品事实、Google 响应式搜索广告的写法）出 15 条标题、4 条描述，最后拼成上传用的表格 | 没动 | 博客 |
| **Figma 插件批量出图** | 让 Claude Code 写了个 Figma 插件，大约 45–60 分钟写完。插件认出画板，替换标题和描述，**一次最多生成 100 个广告变体**，原来几个小时的复制粘贴变成半秒一批 | 没动 | 白皮书第 15 页；博客 |
| **Meta 广告 MCP** | 自己做了一个 MCP 服务，接 Meta 广告 API，在 Claude 桌面版里直接问花费、表现、哪条广告有效 | **只读**，用来分析 | 白皮书第 15 页 |
| **简易记忆** | 把每轮的假设和实验结果记下来，下次生成新变体时带进上下文，越测越准 | 没动 | 白皮书第 15 页 |

**效果**（Anthropic 自报，没有第三方核实）：

- 写广告文案从 2 小时降到 15 分钟，素材产量 10 倍（白皮书第 16 页）。
- 单条广告从 30 分钟降到 30 秒（博客）。两个数字说的不是同一件事，第一个算的是整轮文案，第二个算的是单条出图。
- 网上流传的「转化率比行业平均高 41%」只在 ClickMinded 一篇文章里出现过（[链接](https://www.clickminded.com/claude-code-marketing/)），**没有官方来源**，别引用。

**Austin 给的三条建议**（白皮书第 16 页）：先找「有 API、又重复」的活，比如广告平台、设计工具、分析平台；复杂流程拆成专门的子 Agent；动手写代码前先在 claude.ai 里把整个流程想透。

### 1.3 对我们的启示

- **「AI 管几百组广告」的真实含义是 AI 批量出创意、人把关上线**，不是 AI 自己拿着钱包去改预算。连 Anthropic 自己都是「AI 写，人看过再上传」。这和我们「花钱必过审批卡」的原则完全一致。
- Austin 价值最大的两块（批量文案变体、批量出图）**不需要任何广告平台审核**，今天就能做。我们的投放岗（docs/57 的 `variants.ts`）加上设计岗（`design.ads`），已经有这个形状了。

### 2.1 官方 MCP / API

**几个要特别注意的事实**

- **Google 9 月 10 日的大改**：开发者令牌退役，访问级别改挂在 Google Cloud 项目上，申请入口从 Google Ads 后台的 API Center 搬到了 Cloud 控制台。新申请 Basic / Standard 都**必须先做品牌验证**。据报道，做完品牌验证后，Basic 申请**几分钟内自动审完**（以前要 5 个工作日左右）；9 月 10 日还在排队的申请全部作废，需要重新提交。来源：[PPC Land](https://ppc.land/google-drops-developer-tokens-from-ads-api-access-decisions/)、[Relevant Audience](https://www.relevantaudience.com/google-ads-en/google-ads-api-developer-tokens-sunset-cloud-project-access/)，Google 官方访问级别页（2026-09-30 更新）也写的是「按项目申请、Basic 前须品牌验证」。
- **Google 各访问级别的额度**：Explorer 每天只能对真实账户做 2,880 次操作，而且不能建账户、不能用规划工具。Basic 每天 15,000 次。Standard 不限量，但要人工审计（约 10 个工作日），还要满足「最低功能要求（RMF）」。**这些额度是整个 Cloud 项目共用的**，也就是我们所有用户加起来算。来源：[访问级别](https://developers.google.com/google-ads/api/docs/api-policy/access-levels)、[RMF](https://developers.google.com/google-ads/api/docs/api-policy/rmf)（RMF 只对 Standard 项目适用）。
- **Google 登录授权这道关**：OAuth 同意屏幕如果停在「测试」状态，用户的授权 7 天就失效（[Google Ads 常见错误页](https://developers.google.com/google-ads/api/docs/get-started/common-errors)）。没通过验证的应用会弹「未验证应用」警告，而且**整个项目生命周期内最多 100 个新用户**（[Google Cloud 帮助](https://support.google.com/cloud/answer/7454865?hl=en)）。敏感权限验证 Google 写的是约 10 天，但有开发者反映卡了 10 周以上（[论坛帖](https://discuss.google.dev/t/oauth-data-access-verification-stuck-under-review-since-april-no-trust-safety-email-ever-received-sensitive-scope-adwords/371776)）。
- **Meta 官方 MCP 是逐个账户放开的**：同一个商务管理平台下，有的广告账户能用，有的会报「Ads MCP is gradually being rolled out」。有用户 37 个账户里只开了 8 个，5 月初估计只开了一成左右。这些说法来自 Pipeboard（竞品，[链接](https://pipeboard.co/meta-ads-mcp-not-enabled)），Meta 官方博客也承认「工具访问在逐步放开」。**所以 Meta 必须留一条 Marketing API 直连的备路。**
- **Meta 有「服务端规则」这第二道闸**：可以按广告账户禁止 Agent 加预算超过某个百分比或金额、设预算上限、禁止新建、禁止改定向 / 素材、禁止改投放状态。可以在 Business Suite 里设，也可以用 API 批量设（需要 `ads_management` 或 `business_management` 权限）。这个功能还没完全放开。来源：[规则最佳实践](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-rules-best-practices)。
- **其他平台顺带一提**（[Markifact 汇总](https://www.markifact.com/blog/state-of-advertising-mcps)）：TikTok 官方 MCP 能读能写，已经上了 Claude 连接器目录；Amazon Ads 官方 MCP 能读能写，只对合作伙伴开放；Microsoft 广告 MCP 处于只读试点；LinkedIn 没有官方 MCP。

| **Adzviser** | **只读** | $48.99–148.99/月（竞品转述） | 用户自己订 | [AdKit 对比](https://adkit.so/comparisons/adzviser-vs-meta-ads-mcp) |
| **Adspirer** | 读写（新建默认暂停；自称没有删除、改现有预算的工具） | 免费 15 次调用 / $49 / $99 / $199 每月 | 用户自己订；已上 Claude 连接器目录 | [价格](https://adspirer.com/docs/knowledge-base/pricing) |
| **Markifact** | 读写，写之前要批准 | $79 / $249 每月（第三方转述） | 用户自己订 | [汇总文](https://www.markifact.com/blog/state-of-advertising-mcps) |
| **Zapier MCP** | Google Ads 只有「加客户名单」「回传离线转化」这类动作，**不能管 campaign** | 按任务数计费 | 不适合 | [Google Ads](https://zapier.com/apps/mcp-client-by-zapier/integrations/google-ads) |

**判断**：除了 Pipeboard，其他平台都是「用户自己订阅、自己授权」，跟「零配置」的原则冲突，而且数据要多经过一家公司。Pipeboard 合作伙伴计划是**唯一能让我们今天就上线、不等审核的现成路子**，代价是每个账户每月 $10、数据经过第三方、授权页上会出现 Pipeboard 的品牌，而且不能写进开源仓的默认路径。

### 2.4 Claude / Anthropic 官方连接器

- 我查了 Claude 连接器目录（MCP 注册表）：**Anthropic 自己没有出 Google Ads 或 Meta Ads 连接器**。目录里和广告相关的都是第三方：Adspirer（两个）、Supermetrics、Windsor.ai、AdWhispr、Abency，还有 **TikTok 官方**的「TikTok for Business」。搜索时间 2026-10-13。
- Meta 官方 MCP 不在目录里，但 Meta 文档写明支持 Claude Code（`claude mcp add --transport http --client-id <Meta 应用编号> meta-ads https://mcp.facebook.com/ads`），也支持 ChatGPT，以及「任何能填远程 MCP 地址的客户端」。我们的 DeepSeek Harness 作为客户端，原理上同样可以接。
- Google 官方 MCP 不是托管服务，Google 不提供公共地址。

## 3. 推荐路线

总原则：**用户只点「去授权」，读和写分开，花钱的写操作一律 L1 审批卡**（docs/57 已经定了：新建 campaign、超额提预算、提日花费总闸永远 L1；额度内改预算 / 出价 L2；止损暂停 L3）。

### 第一期：先读数据，写操作先出「上传文件」（不用等写权限审核）

| | Google | Meta |
|---|---|---|
| **读** | 我们自己的 TS 适配器直连 Google Ads API，用 GAQL 查表现。查询写法参考官方 MCP（Apache-2.0）。**不在用户电脑上跑 Python** | 优先接 Meta 官方托管 MCP（`mcp.facebook.com/ads`），我们的 Meta 应用作为客户端，零代码。账户没被放开时，自动退回 WP75 的 Marketing API 适配器 |
| **写** | **不直接调 API**。走 Austin 的路子：Agent 批量出文案 / 素材变体，生成 Google Ads 批量上传表格，过一张审批卡，再由人上传（[批量上传说明](https://support.google.com/google-ads/answer/10702623?hl=en)） | 同样：生成 Ads Manager「导入 / 导出」用的表格，过审批卡，由人导入 |
| **审核期间的兜底** | 授权验证没过之前，前 100 个用户能用，但会看到「未验证」警告 | 应用审核没过之前，只有加进应用角色的人能用，适合内测 |

第一期最值钱的部分，是**素材流水线**：文案变体（两个子 Agent 分别写标题和描述，按平台字数限制）、设计岗批量出图（对应 Austin 的 Figma 插件）、「假设和结果」记忆。这一块**不碰钱，也不用等任何审核**。

### 第二期：API 直接写（审核全部过了以后）

- **Meta**：通过官方 MCP 直接建 campaign、广告组和广告。新建的默认暂停，所以「建」可以给 L2 审批卡，「激活」（开始花钱）一律 L1。改预算按 docs/57 的额度规则走 L1 或 L2。另外**替用户在 Meta 后台设一条服务端规则**（预算上限或加幅上限），作为第二道闸：就算我们这边的护栏漏了，Meta 也会拦。
- **Google**：直接调 Google Ads API 写。每次写之前先用 `validate_only` 试跑一次，把结果放到审批卡上，人点头后再真正提交。Google 不允许直接改正在投放的广告文案，只能「建新的、停旧的」（docs/57 已记录），这个要做成一张卡里的两步。
- **止损暂停**按 docs/57 保持 L3 自动（暂停只会少花钱），事后补一张「已止损」通知卡。
- **额度**：Basic 每天 15,000 次操作，全体用户共用。用户多了要申请 Standard，到时得满足 RMF（全功能工具要能建、能管、能出报表）。

### 不推荐

- 把 Pipeboard、Composio 之类的第三方作为默认路径：多一层数据经手，每个账户每月还要付钱，而且写不进开源仓。可以作为「审核卡太久时的临时备选」，见决策 513。
- 用 computer use 操作广告后台去点「改预算」：一点错就是真钱，而且没有试跑。浏览器只适合帮用户上传文件、截图核对。

## 6. 没核实到的事（别当事实引用）

1. **推特原帖全文**：x.com 要登录，抓不到，内容来自转载。Austin 的确认回复也只见到二手转述（TechFlow、Sapt），没看到原帖。
2. **「转化率比行业高 41%」**：只有 ClickMinded 一篇文章这么说，没有官方来源。
3. **Google `adwords` 权限属于「敏感」还是「受限」**：Google 官方权限清单里没查到明确分类。开发者论坛帖称是敏感权限（验证要录视频，不需要 CASA 安全评估）。如果实际是受限权限，就要做年度安全评估，时间要按月算。
4. **Google 品牌验证和 Basic 访问的实际耗时**：「几分钟自动审完」出自 PPC Land 转述的 Google 开发者博客，Google 原帖我没打开。
5. **Meta 应用审核（`ads_mcp_management` 高级访问）要多久、要什么材料**：Meta 文档只说「代管其他企业要申请高级访问并提交审核」，具体材料和时长没写。「几天到几周」是第三方说法。
6. **Meta 官方 MCP 的放开比例**（「5 月初约一成账户」「37 个开 8 个」）：出自竞品 Pipeboard，没有官方数据。
7. **Meta 官方 MCP 工具总数**：29、42、91 个都有人说，应该是陆续加的，官方工具页没给总数。
8. **Meta 用户授权时能不能选「只读 / 读写 / 含财务」三档**：只在第三方文章里看到，Meta 文档没写。对第三方应用这条路是否同样适用也不确定。
9. **Meta 官方 Ads CLI 的许可证**：文档没写，没法判断能不能复用。
10. **Composio 的 Google Ads 工具包是否需要我们自带 Cloud 项目**，以及它现在的价格：官网连不上，只看到第三方汇总，且数字互相矛盾。

12. **Pipeboard 合作伙伴计划的数据条款**（数据归谁、能不能留存）：页面没写，要找他们要合同。
13. **Google Basic 每天 15,000 次的额度是否完全按项目共享**：官方页面说访问级别挂在项目上，我按「全项目共享」理解，但没看到明确写「所有终端用户合计」的原文。
