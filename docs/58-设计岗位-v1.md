## 1. 职责骨架（S1）

五条骨架相同，差别只在**规格表**与**需求来源**：`design.dtc`（首页 / 产品页 / 落地页 / Banner / 图标；来源：网站运营、建站）、`design.amazon`（主图 / A+ / 旗舰店 / 视频封面；Amazon 规格；来源：Amazon 运营）、`design.social`（帖子 / Reels 封面 / 故事 / 头像；各平台尺寸；来源：社媒运营、红人）、`design.ads`（各平台广告素材与变体；读 `ads-core/spec.ts`；来源：投放）、`design.exhibition`（展位 / 易拉宝 / 画册 / 名片；印刷规格 CMYK / 出血；来源：人手动）。

| 读 | 写（→ ChangeKind） | 额度 | 上限 |
|---|---|---|---|
| 需求单（事项）、品牌系统（公司层技能：色 / 字 / 版式 / 禁忌）、素材库、规格表、参考图 | `draft_brief`（`design_brief`：把需求单变成 brief + 规格 + 变体计划）、`generate_variants`（`design_variant`：调图片模型出初稿变体，N ≤ `max_variants`）、`stage_asset`（`asset_publish`：把选定稿入素材库并回给需求方） | `max_variants_per_brief` 6、`max_generations_per_day` 30、`max_brief_per_day` 10 | brief **L3** 自动；变体 **L2**（出卡给人挑）；入库回给需求方 **L1 永远人定**——人没点"就这张"之前什么都不算定稿 |

- 连接器：图片生成走模型网关（22）的图片能力（DeepSeek 无图片 → 走 OpenAI 兼容口或 agentsws 云按积分），没有就明说"只出 brief 与规格，不出图"；Figma / Canva 登记"待增加"。
- 素材库：blob store（41）按品牌；每张素材带来源（brief id、模型、提示词哈希、人定稿时间）。

## 2. `design-core`（S2）

`brief.ts`（需求单 → brief：目标 / 受众 / 尺寸 / 文案 / 禁忌，纯函数）、`specs.ts`（Amazon / 各社媒 / 印刷规格表；广告规格 import 自 `ads-core/spec.ts`）、`variants.ts`（变体计划与提示词组装，品牌系统注入）、`library.ts`（素材库索引：按品牌 / 用途 / 尺寸 / 定稿状态）、`brand.ts`（从公司层技能取品牌系统，缺就出"先设品牌系统"卡）。

## 3. 面板与卡（S3）

分块：需求单队列（按来源岗位）、进行中（brief / 出图 / 待挑）、待定稿、素材库（按用途）、本周产出；卡：brief 卡（L3，看完即用）、变体挑选卡（L2，N 张图 + "就这张 / 都不行再来"）、定稿入库卡（L1）、缺品牌系统卡。

## 4. 模拟（S4）

3 人 pack +3：`design/request-routes-from-store`（网站运营下需求单 → 岗位路由到 `design.dtc` → brief 自动出）、`design/variants-then-human-picks`（变体卡 → 人挑一张 → 入库 L1）、`design/no-image-model-says-so`（没图片模型 → 只出 brief 并明说）；15 人 pack +1：`design/brand-system-missing-card`。

## 5. 派工（S5）

**WP76 设计骨架**：契约（`design_request` / `design_brief` / `design_asset` 三个对象、三个 ChangeKind、`DESIGN_SPECS`）、`design-core`、五条职责 yml + 岗位模板"设计"（默认全勾）+ `SEED_POSITIONS`、其它岗位的"向设计岗下需求单"动作（网站运营 / 社媒 / 投放 / 红人各加一条 `request_design` → 开事项路由到设计岗）、guardrail、模型网关图片能力接口（假实现）、素材库进 blob store、面板与四张卡、模拟四条。后置：真图片模型、Figma / Canva、真账号。

## 6. 额度默认值（S6）

每 brief 变体 6、每日出图 30、每日 brief 10。
