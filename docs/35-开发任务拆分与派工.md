## 2. 共同约束（写进每个派工单）

- 只改自己的包目录（含其 package.json 依赖）；不动根配置；需要契约改动 → 在报告里提，不自己改 `packages/contracts`
- TypeScript strict + exactOptionalPropertyTypes；ESM；`import type`；不 `any`
- 测试 vitest，放 `test/`；目标 100% 行覆盖（至少所有公开函数有用例）
- 存储：SQLite 用 `better-sqlite3`（同步 API）；所有 SQL 参数化；不共享其他包的表
- 时间经注入的 `Clock`；随机经注入的 seed；不用 `Date.now()` / `Math.random()` 裸调
- 秘密：任何 key 只从环境变量读；测试用假值
- 提交 `git commit -s`；conventional commits；分支 `wp/<n>-<name>`
- 报告：实现了什么 / 测试结果 / 与规范的偏离及理由 / 需要契约改动的地方 / 未完成项

## 3. 审核清单（Fable）

1. `tsc -b`、`biome check`、`vitest run` 全绿；覆盖率报告
2. 契约一致性用例逐条对照规范章节
3. 安全修正是否落地（31 §3 逐项）
4. 不引入未批准依赖；不改契约
5. 合并：`git merge --no-ff wp/...`；pnpm-lock 冲突以重生成解决
