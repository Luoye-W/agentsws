# 工作台积木与命名查询规范 v1（契约 #15）

| | |
|---|---|
| 日期 | 2026-09-08 |
| 对应 | 06 §1（首页四区、placement）、§5.5（对话定制卡三条硬约束）；Commerce Agents A8（积木 = 工具契约 + payload schema + enrichment + 注册表）；AG-UI 事件对齐 |
| 原则 | ① 组件只能来自注册表 ② 查询以本人身份在服务端执行 ③ 数字不经模型手 ④ 卡片定义是数据，可分享可随 Join |

## 1. 对象

```ts
type Component = { name: string /* stat_tile | table | list | timeline | chart_line | chart_bar | approval_lane | staged_change_list | order_table | alert_list | kv | markdown */; payload_schema: JSONSchema; actions?: ActionSpec[] /* 动作回宿主执行器，永不回模型 */; version }
type NamedQuery = { name: string /* 'orders.overdue' */; params_schema; executor: 'sql_readonly' | 'service'; sql?; service?; returns: JSONSchema; acl: 'actor' /* 以调用者身份 */ }
type Block = { id; placement: 'queue' | 'alert' | 'focus' | 'digest' | 'role_view'; component; query: { name; params }; refresh: { every?: Duration; on_events?: string[] }; pinnable; adaptive; source: 'role' | 'package' | 'user' | 'agent' }
type CustomCard = Block & { owner: person_id; created_from: { conversation_id; message_ref }; shared_to?: RangeRef[] }
```

## 2. 渲染管线

`GET /blocks/{id}/data` → 校验 actor 对 query 的权限（Casbin）→ 执行 NamedQuery（服务端）→ **enrichment**（用 id 补全展示字段、丢弃 actor 不可见的、留 note）→ 按 component.payload_schema 校验 → 返回 payload；前端按 component 名查注册表渲染，未知 → UnknownBlock。模型只在"对话定制"时生成 Block 定义，从不生成 payload。

## 3. 首页装配（06 §1.2；**09-09 起按 36 §3 改为三区，focus 归岗位面板**）

`GET /home` 返回四区：queue（合并所有职责车道，排序 14 §8）、alerts（immediate 通知）、focus（候选 = 各职责 focus 块 + 用户自定义卡；钉住优先；自适应只动未钉住区，≤ 1 次 / 天并附 reason；上限个人设置默认 6）、digest（一份）。`GET /roles/{id}/view` 返回该职责工作面的 role_view 块。

## 4. 对话定制

Agent 工具 `blocks.propose({ title, component, query, params, placement })` → 服务端校验 component 在注册表、query 存在且 actor 有权 → 渲染预览返回对话 → 用户确认 → 写 CustomCard（钉住）。分享："给客服组都加上" → `policy_change`（职责模板 focus 候选变更）审批项。

## 5. 动作

组件 `actions`（批准 / 驳回 / 打开 / 运行）一律 `POST` 到宿主 API（14 decide 等），带 decision_token；动作不经模型；digest 卡的 triage 按钮只预填输入框（Commerce Agents）。

## 6. 事件对齐

工作台事件流沿 17 §2 事件 + `ui` / `ui.partial`；命名与结构对齐 AG-UI 类协议的 TEXT / TOOL_CALL / STATE / CUSTOM 分类，便于第三方前端。

## 7. 一致性用例

1. 未注册组件名的 Block → 拒绝写入
2. 查询含 actor 不可见字段 → enrichment 丢弃并留 note，payload 通过 schema
3. 模型提出的定制卡引用不存在的 query → 校验失败，对话里提示
4. 自适应一天内两次重排 → 第二次被拒
5. 12 个职责的人打开首页 → 四区形状不变，focus ≤ 上限
6. 动作按钮点击不产生任何模型调用（事件日志断言）
