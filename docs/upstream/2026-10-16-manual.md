## ① 一句话结论

1. **dsh 已升到 0.2.1-alpha.4**（WP354，行为零漂移，修了一处账号登录的隐患）。
2. **有三处安全问题建议尽快各开一个小单**：本机连接器里的 nodemailer（「邮箱」连接正好用它）、随包 npm 自带的 tar、MCP SDK 的一条高危公告。另外我们自己的邮件渠道和云端也用着有公告的 nodemailer（没登记，哨兵看不到）。
3. **两个上游出了破坏性改名，不能只改版本号**：OpenConnector 1.9.0 把 `shopify_admin` 并进 `shopify`；BrowserSkill 0.3.3 把六个工具改名 `bsk_*`。
4. **许可证：52 条全部没变**，没有一条变成 AGPL / GPL 或闭源。AGPL 的仍只有 Proma（只学思路）和 new-api（原样当独立服务跑）；漏登记里又找到两家 AGPL（GEOFlow、Postiz），代码里都写明一行没搬。
5. 登记表本身有几处要修：两条盯错了地方、一条仓库搬家、Proma 没记上今天决策 911 学的是它。

## ③ dsh 0.2.1-alpha.2 → alpha.4：官方所有包的变化，对照我们已有的

| 官方变化 | 我们已有的 / 判断 |
|---|---|
| headless 组合默认关掉本机凭据库（只认启动环境与 `.env`） | **碰到，已修**：完整 profile 里选了账号登录，按官方写法三行一起开 |
| 账号模块诊断只在失败时打、改走错误输出；`watch` 默认不报身份变化 | 碰到测试，已改；产品不受影响 |
| DeepSeek 官方适配器：空文本块不发（修旧会话重放失败） | 我们移植的那份同步改了 |
| 定时任务「标题」说明改成"简洁、不带时间频率" | 我们抄的那份照官方原文改了 |
| 新包：插件市场（四件） | **重复**：我们的「官方插件」审过清单就是我们的市场；它经插件管理装任意包，判 B，不放 |
| 新包：网页端密钥遮挡（粘贴的密钥在屏幕上只露前 8 位） | 我们没有；**可以借这个做法**（工作台对话框），不能直接用（它是官方网页端的界面插件） |
| 新包：非 owner 访问控制（`remote-access`，进 base 组合） | 本机、只收紧权限，A 类，组合里开着；和「同事互联 / 公司模式」方向接近，等有 Web 以外的入口再看 |
| 新包：电脑操控对象库 + macOS 原生提供方（experimental） | 我们走 cua-driver MCP（WP144），重复；等转正 |
| 新包：harness 开发上下文 | 只给官方网页 GUI 的维护者，用不上 |
| 账号模型目录改从账号的 `/models` 列表取 | 我们设置页的账号模型是写死的两个——**值得另开小单跟上** |
| SDK 新 `resumeSession`（恢复持久化会话） | 两档用内存会话，现在用不上；长程任务"断了接着跑"时可用，记一笔 |
| 网页搜索 / 抓网页 / 浏览器那几包 | 只改了显示文案，没有新搜索 / 浏览器插件；WP179 接的官方网页工具照旧 |
| 持久 PTC（代码执行环境常驻） | 我们不用 PTC |
