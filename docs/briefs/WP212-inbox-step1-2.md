## 定案（Luoye 09-30）
一件要你决定的事只在**卡片流**出现；消息页只管 ① **兜底**（默认「没人接的」）② **原件档案**（「全部」）。Agent 在办的只挂「X 在办 · 有 N 张卡等你 →」链到卡片，消息页不重复批。人在 Agent 在办的对话里亲自发出即自动接管、Agent 停下直到交还（这一条属第 4 步，本单不做）。

## 本单做（docs/88 落地第 1、2 步）
1. **分拣加「类型」与改判**：
   - 每条进来的消息（先邮件）多判一个**类型**（docs/88 的十种，单选）+ 把握；现有 11 个标签降为次要标签行；
   - 「要不要你」在消息页只有两种事实状态：**没人接**（没岗位接、你也没处理）/ **已交出去**（交给了岗位，或你已回、标通知、归档）；
   - 每个判断（类型、岗位）都能点开改；勾「记住」生成发件人规则（下次同一发件人直接按规则、不花模型钱），纠正走学习回路并在「你教过它」里可见；
   - 契约只加不改。
2. **「没人接的」主视图**（消息页默认）：照方向 A 定稿——
   - 顶上一行「已交给岗位 N · 客服 x · …」+「卡片流里 N 张等你批 →」；
   - 列表只放**没人接的**：每条 AI 摘要、类型（拿不准写把握）、一句原文、三个建议按钮（**交给 X ▾** / **只是通知** / **我自己回**），AI 挑一个做主按钮；
   - 「交给 X」= 现有「这是客服」推广到所有岗位：交出去即成为那个岗位的一件事（走 54 路由、进卡片流），消息页不再催；
   - 「只是通知」成捆处理；是否同时在邮箱标已读，跟随「客信怎么动邮箱」开关；
   - 「全部」切换进原件档案视图：本单只做到**现有列表 + 挂「X 在办 · 有 N 张卡等你 →」链接到卡片**（完整原件档案是第 3 步）；
   - **WP208 的阅读区 AI 助手改成兜底助手**：只在没人接的信上生成摘要 / 建议（花 token）；岗位在办的信只挂「有卡等你 →」，不生成建议。
3. 卡片那头：卡片的证据区加「看原件 →」跳回这封信（原件档案视图）。
4. 模拟：分拣「类型」进不进模拟报告要评估；有漂移按惯例说明并重写基线（新增列）。测试覆盖：类型判断与改判、记住规则生效且不再调模型、交给岗位后进卡片流且消息页不再列、只是通知成捆、AI 助手只对没人接的生成。
