## Luoye 原话（10-16）
助理这里对话再加一栏感觉有点太多了，要不要助理就一直在一个对话里？这对上下文管理是很大的考验：新对话可能和之前完全无关，上下文压缩怎么做比较合适。（Fable 给了「一条长对话 + 四层上下文」方案，Luoye：做。）

## 要做
1. **界面**：助理页去掉左侧会话列表那一栏，只有一条连续对话；往上滚是完整历史（按日期分隔、话题之间一条淡分隔线 + 一行小结）；顶部一个搜索（搜历史原话与小结，命中跳到那里）；「换个话题」小按钮（或说一句）手动切段。老的多条会话迁移成按时间拼进这条线（还没有真实用户，不做复杂兼容）。
2. **四层上下文**（每次运行由服务端拼，不把整条历史塞给模型）：
   - ① **当前段原话**：最近这一段的原文，超过预算（按模型窗口的约 50%）就把段内较早部分压成段内小结；
   - ② **自动分段**：间隔超过 2 小时 / 跨天，或模型判断话题变了（便宜的一问或规则），就切段；旧段压成一条「话题小结」（谁、要做什么、定了什么、派了哪些事 / 批次），存本机；
   - ③ **长期记忆**：WP343 助理记忆，每次只带条目；
   - ④ **按需翻旧账**：给助理一个只读工具「查以前聊过的」（按关键词 / 时间搜小结与原话，返回片段与出处），用户提到「上周那份会议记录」时它自己去查。
3. **事情的进度不靠对话记**：派出去的事、批次、待确认、各岗位状态都现查（WP343 / WP350 已有工具），小结里只记编号与一句话。
4. **dsh 运行时**：dsh 会话按「段」轮换（新段开新会话，把小结 + 记忆作为开场上下文），避免单个会话无限变长；stub / direct 同一份拼法。
5. **成本与观测**：每次运行记录拼进了多少原话 / 小结 / 记忆（token 估算），写进事件，方便以后调预算。
