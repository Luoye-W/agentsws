# WP331 周报「能力化」：拆掉专用的 Reddit 周报功能，改成通用积木 + 工坊被几句话自己配出来（Luoye 10-15）

worktree `../agentsws-wt/wp331-reportcap` · 分支 `wp/331-reportcap`。先读 `_common.md`、`docs/briefs/reports/WP330.md`（被拆的专用周报）、`docs/briefs/reports/WP328.md`（Reddit 巡查数据）、`docs/briefs/reports/WP323.md`（发出记录 / 记录去处）、`packages/dsh-adapter/src/official-schedule.ts` 与 `apps/server/src/schedule.ts` / `automation.ts`（dsh 官方「自动化任务」四个工具，已内置）、`docs/96`。

## Luoye 的原则（以此为准）
周报**不是固定功能**。要测试的是：用户说「我要加周报，内容是……，每周五下午 5 点」，**工坊自己用通用能力配出来**；改格式也是说一句。我们只做通用积木，不写某个客户 / 某个平台的专用周报。同理飞书记录（WP323 已按此做）。

## 要做
1. **拆专用**：去掉 WP330 的专用部分——Reddit 周报专用定时任务、`/v1/reddit-weekly/*` 路由、专用周报卡 / 报表区位置、`get/set_reddit_weekly_format` 两个工具、专用存储。WP328 里「周五那次巡查由周报触发」的耦合一并去掉（巡查照自己的每日节奏）。可复用的纯计算（窗口、计数、按话题归组）保留为下面积木的内部实现，不保留「周报」这个概念。
2. **通用积木**（AI 工具，按职责权限开放，不带平台 / 客户名）：
   - 查巡查数据：按时间窗、自家 / 外部、判断档、话题、关键词查 WP328 入库条目，能给计数与按话题归组。
   - 立即巡查一次：让 AI 在出报告前自己决定要不要先跑一轮。
   - 查发出记录：按时间窗 / 平台 / 类型查我们发出去的条目与计数、链接（WP323 已有接口，补成工具）。
   - **发布报告**：任何一次运行（含定时运行）都能发布一份「报告」——标题、周期、Markdown 正文；出现在该岗位的报表区，同一周期再发是同一份的新版本；带「复制整份 / 导出 .md」；可选按 WP323「记录去处」写一行。这是通用的报告卡，不叫「周报」、不认平台。
3. **定时**：用已内置的 dsh 官方自动化任务（AI 自己建「每周五 17:00 跑一次，按以下要求出报告」），改格式 = AI 改那条自动化任务的说明；要先出卡的照现有规则。
4. **验收（重点）**：
   - 场景测试（stub 运行时、脚本化工具调用）：用户一句「每周五下午 5 点给我出一份 r/inmoxr 周报，数据周日到周五：①帖子数评论数 ②有效 VOC / UGC ③外部舆情按话题归组带判断和原文链接 ④我们本周回复数和链接」→ AI 建自动化任务 → 到点运行 → 调查数据 / 发出记录工具 → 发布报告；再说「把第三节放最前面」→ 改任务说明 → 下次报告顺序变了。
   - 真模型评测用例：把上面两句写成评测用例（`evals/` 或现有评测目录的格式），可用 DeepSeek 真跑；本单只写好并在报告里给出怎么跑，跑不跑由 Fable 决定（不调真付费接口）。
5. 文档：docs/102 周报那节改成「由工坊配出来」的说明。
