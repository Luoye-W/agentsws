# WP348 配置卡改成「AI 先查、先定方案，人只确认」（Luoye 10-15，决策 887）

worktree `../agentsws-wt/wp348-planfirst` · 分支 `wp/348-planfirst`（从 main 拉；收尾前合一次最新 main）。先读 `_common.md`、`docs/briefs/reports/WP324.md`、`WP334.md`、`WP340.md`、`WP346` 派工单（品牌档案第二版，在做）、`apps/server/src/setup-targets.ts`、`apps/server/src/reddit-watch/suggest.ts`、`settings.ts`、`apps/workstation` 里的配置卡组件、记忆 `strategy-defaults-with-user` 的精神（AI 先调研给建议，人只确认）。

## Luoye 原话（10-15，指着 beta.7 上「先设好 Reddit 巡查」那张空表单）
不是应该人和 AI 沟通或者下任务的过程中，AI 自己查资料、自己判断、自己规划、自己设置好，然后最后交由人确认吗？

## 现状
WP324 / WP334 的配置卡是表单：缺什么就让人填。WP340（已合 main，未发版）给 Reddit 巡查卡预填了 AI 建议值，但只读品牌档案、问一次模型，卡面仍是一张待填表单 +「保存并接着做」。

## 要做（通用机制，不做 Reddit 专用）
1. **出卡前先干活**：任何配置目标（`registerTarget`）可以声明一个「怎么查」：读品牌档案（WP346 后有人群 / 关键词 / 竞品）、读已连的数据（插件登录态里的账号、店铺、已连渠道）、必要时联网搜索（官方 web search 工具，限次）、按需问一次模型整理。AI 在**这件事的运行里**把这些做完，再出卡；查的过程在时间线上留几行（查了什么、看到什么）。
2. **卡面是「方案」不是「表单」**：标题写成「我打算这样设」；正文按格子列出 AI 定的值 + 一句理由（来源可点开：哪条档案、哪个网页、哪个已连账号）；底部「就这样」「改一下」「先不设」。「改一下」才展开表单（预填方案值）。真查不到 / 不该 AI 猜的格子（凭据、要人选的账号）才留空并标「需要你填」。
3. **Reddit 巡查按此改**：自家版块（档案 / 插件已登录账号的版主关系 / 搜索）、外部关键词与重点版块（档案关键词 + 竞品 + 搜索 Reddit 上的相关版块、带频率）、告警词、标签词、品牌号（**读插件里已登录的 Reddit 账号**，不让 AI 猜）、频率（默认每天一次）。
4. **其他已注册的配置目标**同样接上「怎么查」：至少公司档案（WP334）、广告账户（WP315，读插件已登录后台里的账户）、Reddit 上限（WP338，默认不限、无需出卡）。每个目标在报告里列「查什么 / 查不到怎么办」。
5. **request_setup（WP334）**：AI 自己要卡时同样带方案值与理由（已有字段沿用），卡面同上。
6. **已设好再改**（WP340 决策 841）：并进来——对已设好的目标，AI 可以出一张「我打算改成这样」的方案卡（现值 → 新值 + 理由），人确认后生效。
7. **genui**：卡面用现有卡片组件；WP341（genui 按钮 / 表单）合了以后，对话里同一张方案也可以就地画，不另造。

## 测试
- 服务端：出卡前跑了「怎么查」（stub 返回的档案 / 已连账号 / 搜索结果进了方案值与理由）；查不到的格子留空并标需要填；「就这样」直接保存并接着做；「改一下」改了的值以人为准。
- Reddit：品牌号来自插件登录态（替身），不来自模型。
- 已设好再改：现值 → 新值，确认后生效、不确认不动。
- 工作台：方案卡默认不展开表单；「改一下」展开且预填。
- 模拟三包照跑；装包前冒烟。截图：Reddit 巡查方案卡（收起 / 展开）、改设置方案卡。
