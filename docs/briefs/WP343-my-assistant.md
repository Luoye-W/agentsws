# WP343 「随便聊」改成「我的助理」：能聊、能问全局、能替你派活（Luoye 10-15 再提，落实决策 334；本单决策 859）

worktree `../agentsws-wt/wp343-assistant` · 分支 `wp/343-assistant`（从 main 拉；收尾前合一次最新 main）。先读 `_common.md`、`docs/96` §5、决策 333 / 334 / 641 / 847 / 853、`apps/server/src/free-chat.ts`、`free-chat-store.ts`、`secretary.ts`、`apps/workstation/src/pages/free-chat.tsx`、`components/free-chat/*`、`components/secretary/*`、`pages/profile.tsx`、`components/app-shell.tsx`（WP271 个人模式收起「我的代理」那段）、`docs/briefs/reports/WP320.md`（记忆提醒）。

## Luoye 原话大意
随便聊要和「我的助理」融到一起并改名。它就像 ChatGPT / Claude 网页的那个对话框；页面上用两三句话说明：可以随便和它聊，也可以把它当助理，像对其他岗位、职责那样交代事情。再想想要不要加快捷问题按钮或别的功能。

## 要做
1. **改名合并**：左栏「随便聊」改成「我的助理」（仍在最上面），路由保留旧地址跳转。「我的代理」（41 §1，替你答同事 / 约时间 / 公开资料）并进这一页：个人模式不出（照 WP271）；同事互联 / 公司模式在页面右上角一个「替我答同事」入口（谁问过我、约时间、我的公开资料），不再单独占左栏。包名 / 事件名不动。
2. **空状态说明（≤3 句，界面少字）**：标题「有什么要我做的？」，下面一行小字，意思是：随便聊、问什么都行；也可以直接交代事情，我会交给对应的岗位去做，做完回来告诉你。具体措辞你定，别超过两行。
3. **能问全局（只读，直接答）**：给助理加只读工具：各岗位 / 职责在做什么、今天要我处理的卡、最近发出去的、某件事进展。答案用 genui 组件画（WP336 / WP341）。
4. **能派活**：去掉 free-chat 提示里「不能开事项或派活」那句，加一个派活工具：按用户的话挑岗位 / 职责（拿不准时用 genui 按钮让人选，WP341 合了就用按钮，没合就用一句话问），走现有交办入口开事项；对话里回一行「已交给 Reddit 运营 · 自家版运营」带链接，事项有结果 / 要拍板时回到这段对话提一句。改外部的事照旧由那个岗位出审批，助理自己不直接改外部。旧的「交给岗位去做」按钮保留成 genui 按钮或删掉，你判断。
5. **快捷问题**：输入框下最多 4 个，按当前状态生成，不写死：例如有待处理卡时出「今天有什么要我处理的？」，有岗位时出「{岗位} 今天做了什么？」、一条按该品牌已有岗位举例的派活句，没有岗位时出「帮我建一个岗位」。开始对话后收起。
6. **其他**：输入框里 `@` 可选岗位 / 职责（直接派给它）；左侧会话列表（`session-list.tsx`）沿用，按日期分组、可搜索；联网搜索 / 用公司资料回答 / 图片保留。模型选择由 WP342 挪进输入框，本单不动模型选择钮。
7. **记忆**：助理这一层的记忆按 WP320 的提醒机制接上（决策 641 等的就是 333 / 334）。
8. **docs/96** §5 左栏那条与组件目录同步改；教程里「随便聊」改「我的助理」。

## 测试
- 服务端：助理派活工具开事项到对的岗位 / 职责、拿不准时不乱派；只读工具不产生任何 staged / applied；三个运行时（stub / direct / dsh）同一份参数表，dsh 严格参数表测试加上。
- 端到端（真服务进程 + stub）：在助理里说「让 Reddit 运营查一下今天的新帖」→ 开出事项 → 事项回结果 → 助理对话里出现回报。
- 工作台：个人模式不出「替我答同事」；同事模式出；快捷问题随状态变化、开始对话后收起；旧路由跳转。
- 模拟三包加一个场景：助理派活后由岗位出审批，助理本身无写操作。
