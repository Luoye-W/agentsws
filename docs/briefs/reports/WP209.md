# WP209 报告：技能页与知识库页——先分类、再展开

实现方：Claude Opus（子代理）。worktree `agentsws-wt/wp209-library`，分支 `wp/209-library`（已合一次 main，docs/35 两边都留）。没推远端，没碰 4317，截图拍在自己起的 4399 demo 上（拍完已关）。

**一句话**：技能页改成「按岗位分组的小卡，点开才看段落」，知识库改成「按类型分组，每条标状态和来源，可按品牌 / 范围、状态筛、可搜」。分组逻辑是一份纯函数，第三栏的技能 / 知识面板也换成了同一套。

## 1 做了什么

### 技能页（`/skills`）

- **按岗位分组**。归属从哪来：
  - 职责 yml 里的 `skills:` 反查：哪几条职责在用这个技能，这几条职责挂在哪几个岗位下；
  - SKILL.md 新加的可选字段 `positions`（只加）。
- **一个技能挂在几个岗位下，就在几个组里都出现**，卡上标「共用」（问号里写「N 个岗位都在用它」）。
- **排序**：
  1. 本人开了的岗位，摊开；
  2. 「通用」，摊开；
  3. 其余岗位收进一组「没开的岗位」，这一组默认收着，里面每个岗位也收着。
  - 岗位顺序照工作单列的：客服、红人营销、社媒运营、B2B、投放、建站、设计、公共关系，最后网站运营。
- **小卡上只放四样**：
  - 中文名（原描述放在名字旁的问号里）；
  - 一句话说明；
  - 哪几条职责在用（最多 3 个小标签，多的折成「+N」）；
  - 「N 条建议待看」徽标，没有建议时不挂。
- 段落、三层改动、版本和「不用这个技能」**点开才看**（卡片就地展开成两栏宽）。
- **顶上的工具**：
  - 搜索：名字（英文 id、中文名、英文名）、一句话、原描述、段落标题和正文、改动正文、职责名都能搜到；
  - 两个筛选芯片：「只看有建议的」「只看我在用的」。
  - 搜索或筛选生效时，所有组自动摊开；什么都对不上时说一句人话。
- 「昨天学到的（待你定）」那块保持原样。

### 知识库页（`/knowledge`）

- 原来的「上传的文件」列表和「知识清单」合成一块「知识」，**按类型分组**：
  - 产品事实、政策、物流与时效、B2B 事实卡、品牌话术、上传的文档、其它；
  - 每组带条数，空组不显示。
- **一条一行**：
  - 正文。从文档导进来、以 `# 标题` 开头的，标题单独一行，正文压成一行；
  - 它是哪一份：政策分退换 / 运费 / 隐私 / 条款 / 保修，B2B 分六类（价格与 MOQ、认证清单等）；
  - 适用范围；
  - 来源：上传 / Agent 提议 / 手填；
  - 状态：已生效 / 待确认 / 已过期 / 冲突。
- **状态怎么判**（重的压轻的）：
  - 冲突：卡上记着 `conflicts`；
  - 已过期：已退役、过了 `valid.until`、源页改过还没复核（stale）、被人停用（quarantined）；
  - 待确认：还是提议（proposed）；
  - 其余算已生效。
- **筛选和搜索**：
  - 「品牌 / 范围」下拉（问号里说明）；
  - 状态芯片：全部 / 已生效 / 待确认 / 已过期 / 冲突，后面跟条数；
  - 搜索框搜正文和标题。
- 上传区（拖进来 / 选文件、一份一份传、失败原因原样显示）保持原样。传上去的文件进「上传的文档」那一组，点一份照旧在第三栏预览，删除按钮也还在。
- 复核卡、宣称规则、缺口、业务边界这几块没动。

### 第三栏（与 WP208 相关）

- **技能面板**：只列当前这一层在用的技能。
  - 岗位层：挂在这个岗位下的；
  - 职责层：这条职责在用的。
  - 名字换成中文显示名，其余功能（不用它、提到这一层）不变。
- **知识面板**：多一行「这一层常用的知识」，按岗位挑几类，显示每类几条。职责层按它所属的岗位挑。

### 契约与数据（都是只加）

- **`SkillSummary`**（`packages/api/src/types.ts`，工作台 `lib/api.ts` 同步）加了这些可选字段：
  - `display_name` 和 `summary`（`{zh,en}`）、`description`；
  - `positions`：`SkillPositionRef[]`，含 `id` / `name` / `mine`；
  - `roles`：`SkillRoleRef[]`，含 `role_id` / `name` / `position_ids` / `mine`；
  - `in_use`；
  - `sections[].body`。
  - 老服务进程不回这些字段也能看：名字退回英文 id，全部归「通用」。
- **SKILL.md**：17 个自带技能的 frontmatter 只加了 `display_name`、`display_name_en`、`summary`、`summary_en` 四个字段。`policy-review` 和 `workspace-basics` 另加 `positions: common`。正文和版本号一个字没动。
- **`MemorySkillRegistry.frontmatterOf(name)`**：新方法，按层从近到远取 frontmatter。
- **服务端 `apps/server/src/skill-catalog.ts`**：新文件，`enrichSkillSummaries` 是纯函数。`GET /v1/skills` 在 `learning.summaries` 的结果上往每行加字段，`learning.ts` 没改。
- **工作台 `KnowledgeCardRow`**：只是把服务端本来就回的几格认下来：`scope`、`provenance`、`created_by`、`conflicts`、`valid`、`domain`、`structured`。

## 2 给 WP208 的组件接口（第三栏「设定」里复用这一套）

纯函数都在 `apps/workstation/src/lib/library.ts`：

| 函数 | 用途 |
|---|---|
| `skillsForScope(skills, { tier: 'position' \| 'role', scope_id })` | 按当前岗位 / 职责过滤技能。服务端没回分组字段时原样返回全部 |
| `skillLabel(skill, lang)` / `skillSummaryLine(skill, lang)` / `sharedAcross(skill)` | 显示名、一句话、跨了几个岗位 |
| `groupSkills(skills)` → `{ mine, common, others }` | 分组，技能页用它 |
| `filterSkills(skills, { query, onlyProposals, onlyMine })` | 搜索和两个筛选 |
| `knowledgeGroupOf(card)` / `knowledgeStatusOf(card, now?)` / `knowledgeOriginOf(card)` / `policyKindOf(card)` / `b2bCategoryOf(card)` | 知识条目的类型、状态、来源、政策种类、B2B 类别 |
| `filterKnowledge(cards, { query, scope, status })` / `groupKnowledge(cards)` / `countByStatus(cards)` | 筛选、分组、按状态计数 |
| `knowledgeGroupsForPosition(position_id?)` | 一个岗位先看哪几类知识。认不出的岗位给全部 |
| `scopeLabel(ref, rangeGroups, t)` / `statementParts(statement)` | 适用范围怎么显示（内部 id 不上屏）；正文拆出 `# 标题` |

## 3 我自己定的事（白话）

1. **「通用」怎么算**：`common.owner`（公司设置与授权）和 `common.member`（工作区成员）在每个岗位模板里都有一份。如果按岗位算，「工作台入门」会出现在全部十个岗位里。所以这两类职责用到的技能一律归「通用」。只挂在没进任何岗位模板的职责上（比如已经拆掉的 `social.meta`）的技能不算那个岗位；一个岗位都没有的，也归「通用」。
2. **显示名和一句话写在 frontmatter 里**，没有写死在工作台。以后公司自己写的技能也能带上这几个字段。这些中文名是我起的，见第 5 节。
3. **知识的类型从 `subject` 和 `layer` 判断**，没有新加字段。
   - 先认 `b2b:` 前缀，再认话术层，然后是物流时效词（截单、承运商、时效、丢件……），再是政策（退换、运费、隐私、条款、保修），最后是产品，剩下的进「其它」。
   - 历史案例（47 J2）一律进「其它」。
   - 运费按工作单归在「政策」下；时效、截单、丢件归「物流与时效」。
   - 这套判断是规则匹配，会有判错的条目（第 5 节第 3 条）。
4. **「上传的文档」是另一张表**（原件），不是事实卡，所以单独成组。它没有状态、没有适用范围，所以按状态或范围筛时不列它们，只按文件名搜。
5. **来源怎么判**：
   - 出处是一份文档，算「上传」；
   - Agent 建的，算「Agent 提议」；
   - 其余算「手填」。
6. **默认只展开本人开了的岗位和「通用」**。一个岗位都没开的新人，「没开的岗位」这一组默认展开，免得整页只剩一个收着的组。

## 4 偏离工作单的地方

1. **「按品牌筛」做成了「品牌 / 范围」筛**。按 docs/52，品牌就是工作区，每个品牌一个知识库、互相看不见，知识库页本来就只显示当前品牌。所以这个下拉筛的是品牌内部的适用范围（`FactCard.scope`：店铺组 / 店铺 / 产品线 / 市场）。
   - 选了某个范围 = 那个范围的条目 + 通用的条目。
   - 所有条目都不带范围时，这个下拉不出现。现在的导入流程（知识包、官网建档、上传）给的范围都是空的，所以真实数据里暂时看不到它。
   - 为了截图，我在 **demo 里种了三条带范围的政策卡**（`apps/cli/src/demo.ts` 的 `seedScopedKnowledge`，只影响 demo，不影响模拟）。
2. **技能折叠的两张截图是模拟的**。demo 里只有王岚一个人，而且十个岗位全开了，拍不出「没开的岗位」。所以截图脚本在浏览器里把 `/v1/skills` 返回数据里的 `mine` 改成「只开了客服、B2B、网站运营」，其余数据原样。这是 `skills-grouped.png` 和 `skills-others-open.png` 两张。真实所有者视角另拍了一张 `skills-owner.png`。
3. **小卡上不写「没有待你看的建议」**（少字）。原来的测试断言了这句话，我改成断言「没有建议时不挂徽标」。老词条留着没删。
4. 报告按这次派单的要求写在 `docs/briefs/reports/WP209.md` 并提交了，没写 `_common.md` 说的 worktree 根目录 `REPORT.md`。

## 5 要 Luoye 定的事

1. **「品牌」筛到底要什么**（见第 4 节第 1 条）。有两个方向：
   - 保持现在这样，筛品牌内部的适用范围，大多数时候隐藏；
   - 改成顶栏品牌切换的快捷入口：选另一个品牌 = 切过去看它的知识库，整个工作台会重载。
2. **17 个技能的中文名是我起的**，要改就改对应 SKILL.md 的 `display_name`：
   - 广告文案、受众研究、询盘接待、品牌话术、拒付举证、开发信、客服回信；
   - 邮件短信营销、跟单与单证、红人合作、政策核对、找客户、报价；
   - 退换货计算、内容与搜索、展会、工作台入门。
3. **知识按类型分是规则匹配**。截单、时效这类词看键名，会有归错的条目。如果以后想让人手动改归类，要在事实卡上加一个 `category`（契约只加），这一单没做。
4. **「品牌话术」这个技能挂在 29 条职责上**，所以它在 7 个岗位的组里都出现，卡上显示「+25」。要不要把这种几乎处处都用的技能只放进「通用」？现在是按事实挂的。
