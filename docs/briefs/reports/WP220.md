## 1. 两份源码怎么做研究、怎么取数，我们换成了什么

### 1.1 mvanhorn/last30days-skill（MIT，© 2026 Matt Van Horn，钉 `5103ba47`）

**方法**：话题 → 拆主体与意图词 → 规划若干子查询 → 各平台并行取数 → 归一 → **硬时间窗**（窗外不进） → 按归一地址合并重复（留信息更全的那份）、同平台近似文本合并 → **主体对不上重罚**（互动救不回来） → 打分（相关 × 互动 × 新鲜 × 来源可信度，互动取对数）→ 加权 RRF 融合多路结果 → 每作者上限 → 聚类出「证据簇」 → 由模型按固定格式综合（不许编标题、不许把原始证据簇贴出来、没有站得住的就说「Nothing solid」、某源没取到不许写成「这里没人聊」）。

**取数**（全在 Python 引擎里）：

| 平台 | 上游怎么取 | 要 key 吗 | 我们换成 |
|---|---|---|---|
| Reddit | 第三方抓取 API（ScrapeCreators）；无 key 时**直接抓** Reddit 公开 `.json` / shreddit 页面片段 / arctic-shift 镜像；Bright Data | 可选 | ① 接口中台 `social.reddit.search/posts/comments` → ② 本机浏览器只读（单独会话、限速） |
| X | 打包的 Bird 客户端拿**浏览器 cookie**（AUTH_TOKEN / CT0）调 X 内部 GraphQL；或 xAI 的 x_search；或 X API bearer | 要 | 品牌连上的 X 官方接口；没连只用搜索结果摘要；网页抓取不开 X 页面 |
| YouTube | yt-dlp 抓搜索与字幕 | 不要 | 品牌连上的 YouTube Data API；没连用网页搜索、标明只看到标题与摘要 |
| TikTok / Instagram | 第三方抓取 API | 要 | 接口中台（按账号取；按关键词搜列进待接） |
| HN / Polymarket / GitHub | 各自公开 API | 不要 | HN 列进待接；预测市场、GitHub 不做（与 PR 无关） |
| 全网 | 宿主 WebSearch + 无 key 的搜索页抓取 | — | 官方网页搜索 / 抓取（WP179） |

### 1.2 ScrapeCreators/social-media-research-skills（MIT，© 2026 ScrapeCreators，钉 `64ba7b4d`）

**方法**（13 份 SKILL.md，纯提示词）：爆款帖——取 ≥20 条、**按账号自己的中位数**做基线、各平台各算、5 / 2 / 1.5 倍三档、<10 条置信低、再解释为什么火；评论挖掘——九类归档、按频次 × 强度聚主题、保留原话、一人吵 ≠ 普遍；竞品拆解——先确认账号、同窗口、各自基线找爆款、看支柱 / 形式 / 钩子 / 节奏、找空白、「看起来」不当事实；广告库——在投 ≠ 效果好、重复是信号、不编花费与定向；趋势——至少两源才叫趋势、看地区、要合品牌；舆情简报——主题 × 情绪、不假装全量。

**取数**：全部走 ScrapeCreators 的抓取 API（`x-api-key`，110 个端点，27 个平台）。→ 我们一律不用；换成上表那几路，没有的（按关键词搜 TikTok / IG、别人帖子的评论、X 关键词、Meta / Google 广告库、LinkedIn / Threads 帖子）列进待接清单，技能里照实说「这一路还没接」。

## 3. 自主做的决定（白话）

- **技能名**：`trend-research`（显示名「话题与舆情研究」）、`social-research`（「社媒研究」）。没叫 `audience-research`，那个名字已被投放的技能占了。
- **方法写进代码而不只写进提示词**：时间窗、去重、主体判定、打分、爆款倍数这些「数」由 `social-core` 的纯函数算，技能里写「数字由规则算好交给你」——上游自己踩过模型乱编排名的坑（它的 LAW 1–6），我们直接不让模型算。
- **只读工具挂在 grounding 上**：职责 yml 没有「数据路由」这一格，grounding 的工具名本来就进运行白名单，所以 Reddit 四条各加一行 `tool: read_reddit`；意图词故意写成窄短语，不改岗位路由（测试照旧全过）。
- **浏览器只读那一路的「单独会话」怎么认**：只有 `launch`（新起的无痕浏览器，不带任何登录态）算；`attach`（桌面壳的「工作用的浏览器」，人在里面登品牌号发帖）与 BrowserSkill（人日常的浏览器）一律拒。服务进程现在没有能程序化开页面的只读执行器，所以这一路如实「没配」，不拿 Agent 自己的浏览器凑——这样「绝不用发帖会话」在路上就成立。
- **`pr.forums` 白名单保留 `*.reddit.com`**，注释写明只读、取数正路是 `read_reddit`；其余三条 Reddit 职责**没有**加浏览器白名单（加了等于让 Agent 自己的浏览器去开 Reddit，绕过限速与会话判定）。
- **回退方向**：接口中台失败自动落浏览器只读，是「花钱 → 不花钱」，与 docs/75「报错不静默回退到花钱的那一级」不冲突。
- **网页抓取不开 Reddit / X**：在三个运行时共用的计数器里拦（不占次数），对所有职责生效——红人、内容那几条以前也能抓 x.com，现在不能（X 页面不登录本来也抓不到正文）。
- **网页工具**给了公关四条与社媒内容渠道八条（研究要上网查）；群聊类（Discord、Telegram、WhatsApp、FB 群组）与已拆分的 `social.meta` 不挂两份技能、也不加网页工具。
- **危机说明**只取结构与几条纪律（先出站得住的说明、不说无可奉告、对记者不说假话、最多三条主信息、先内部后外部、一个对外口径、不删帖、分四档），**没搬**上游模板里的「高度重视」「首要任务」和「给出下次更新时间并兑现」——时间由人在卡上填，不写完成式、不承诺。
- **「这周什么在起来」放进两份技能**（公关看借势 / 回应，社媒看能拍的选题），替换掉社媒那份原来的「看趋势」一节（两源才叫趋势、看地区、要合品牌这几条并进去了）；只认三个免费公开来源，选品类付费数据一个都不在白名单里（测试钉住）。
- **示例任务上限 3 → 4**（`quick-prompts.test.ts`）：品牌监控与 TikTok 各加一条研究的例子，派工单要的；别的职责不变。
