## 0. 一句话

公司模式只能由发起人主动开：设置页最底下 / 团队页最底下一行小字「开公司模式…」，三步（公司全称、谁是老板、管理员）。开了以后每位同事收一张「知道了 / 我要退出」，上级、主管定 / 老板定、超时升级、职责分离、店铺组、离职交接这些才生效。只有老板能「回到同事互联」：这些设置收起不删，再开原样回来；正等主管 / 老板批的卡退回本人；同事首页一行通知。③ 里上级给下属派活直接生效，平级之间仍要对方接下。

## 2. 我自己定的（白话）

1. **老板选别人就是真的转所有者**，不是另记一个「老板」字段：审批路由、离职卡、职责规矩里「老板」读的都是品牌的 `owner_id`，另起一格要改几十处。原发起人留管理员、保留自己的「负责人」那条。降回 ② 之后，这位老板就是发起人。
2. **新老板那张卡只有「知道了」**：老板不能退出（他是所有者），给他「我要退出」是个点了也没用的按钮。他那张说「定了你是老板：超了授权的事、没设上级的岗位都转给你批」。
3. **「收起不删」靠的是什么都不删**：上级挂在岗位上、店铺组 / 产品线 / 额度各在各的库里、管理员角色在组织名单里——降级只改模式那一格，这些照存；② 里各处本来就按模式不读它们。
4. **降级退卡只退「等主管 / 老板 / 升级来的那几位」**，按卡上收件人的 `via` 判；找不到「这件事是谁的」（系统提的）或那人已经不在品牌里（例如申请加入的人）就不动。
5. **离职交接没做完不让降**：按还开着的离职卡算（`target: offboard` 的那几张 + B2B 客户交接卡）。
6. **开公司模式时品牌里的同事进组织名单**：③ 的离职、设管理员都按组织名单走，不进去就办不了。
7. **降级的同事通知不做成卡**（派工单「收一条通知」），读组织上「谁、什么时候改的」；谁点掉过记在组织上（`Organization.mode_seen_by`，只加），换电脑也不再出——工作台不许往 localStorage 里存这类东西（40 §1.2，`local-cache.test`）。
8. **派活的判据**只看直接上级（发的人是对方某个岗位的上级）；隔级（上级的上级）不算派，走交给对方。
9. 入口那一句问号不出「主管 / 老板 / 审批」（② 团队页也出它，决策 256）；向导里面才说老板。

## 3. 要 Luoye 定的事（同时列在对话里）

1. **老板选别人 = 真转所有者，原发起人变管理员；降回 ② 后发起人就是这位老板。** 建议保持（不另起「老板」字段）。
2. **同事选「我要退出」时个人渠道还没跟人走**（沿用 WP276 的退出，WP276 待定第 3 条）。建议并入那条一起定：退出时把他自己接的、标「个人」的连接断开，共用的留下。
3. **上级派活下属不能拒**，只能事后再交给别人；隔级不算派。建议保持（docs/95 §8 第 10 条的原意）。
4. **老缺口：挂在底座职责上的卡（WP276 的「知道了 / 撤回」部分、有人申请加入等）在只有一个岗位的人那里看不到**（他的首页就是岗位页，岗位页按职责筛卡）。这单只修了自己那张。建议另开小单：岗位页「要你处理」也收底座职责的卡。
5. **离职交接接口在 ① ② 回 409**（以前只是界面不出）。建议保持。
