## 一、一句话

AI 钮上还是写「8 折」「1.3x」，字段名也没变，变的是两个数的意思：

- **折扣** = 我们卖给你的价 ÷ 这家 AI 官方标价；
- **消耗速率** = 我们卖给你的价 ÷ DeepSeek v4 Pro 官方标价。

两个数都按 token 算：用这个模型平时「读多少、写多少、命中多少缓存」加权。云上没给这两个数时，本机按同一个口径用内置的官方价目兜底。

## 三、做了什么（白话）

1. **契约**（`packages/contracts/src/cloud-entry.ts`）：
   - `discount`、`consumption_rate`、`rate_source` 三格**名字不动，只改注释里写的意思**：
     - `discount`：只在 `< 1` 时给，只是说明，结算不乘它；
     - `rate_source`：`stats` = 近 30 天真实构成，`list_price` = 典型构成。
   - 只加不删，新加的有：
     - `TokenMix`（一份 token 构成：未命中输入 / 缓存命中 / 输出）；
     - `TYPICAL_TOKEN_MIX = { input: 3, cached: 0, output: 1 }`；
     - `tokenMixCost`（按构成加权的平均单价）；
     - `tokenMixRatio`（同一构成下两份价之比）。

     私有云算折扣与倍率、本机兜底，用的都是这几个函数，两边口径不会各说各的。
   - `MeteringEvent` 加可选 `cached_tokens`（含在 `input_tokens` 里，不另加），白名单同步加上。私有云要靠它分出缓存命中。
2. **本机兜底同口径**（`apps/server/src/model-rates.ts`）：价目里这一行没有 `consumption_rate` 时：
   - 我们的价 = 积分价 × `credit_cny`，折成每百万 token 多少人民币；
   - 官方价 = 本机内置价目（`@agentsws/model-gateway` 的 catalog，只看按量那几家），按价目里的 `fx` 折成人民币；
   - 倍率 = 典型构成下 我们的价 ÷ v4 Pro 官方价；
   - 折扣 = 典型构成下 我们的价 ÷ 这家官方价，保留两位，`< 1` 才给。

   云上给了倍率的那一行，倍率和折扣都照云上；云上没给折扣，就是「不到折」，本机不另算。本机价目里连 v4 Pro 的官方价都没有时，退回 WP362 的老办法。
3. **本机估价不再乘折扣**（`chatCredits`）：跟云上结算一个口径，三格单价本身就是实收价。
4. **文案**（`apps/workstation/src/lib/i18n-shell.ts`，中英两份）：
   - 问号：「消耗速率按 token 算：这个模型常见的用法下，我们收的价是 DeepSeek v4 Pro 官方原价的几倍；折扣是我们的价比这家官方标价……」；
   - 来源两种：「按近 30 天真实用量的 token 构成」「按典型 token 构成（输入 3 : 输出 1）」；
   - 折扣悬停：「按 token 算，我们的价是这家官方标价的 80%……」。
5. **云替身样例价目**：`kimi-k3` 的示意折扣从 0.1 改成 0.8，demo 里显示「8 折」。
6. **帮助文档**（`docs/help/agentsws-credits.md`）：加了一节「AI 钮上的『1.3x』和『8 折』是什么」，白话写了两个数怎么来、会自己跟着变、以用量记录为准。
7. **跟 WP370 的协调**：模型选择器的结构一行没动。只改了 AI 钮上「折扣 / 倍率」那几条文案和服务端取数，组件里只多了一行注释。

## 五、自己做的决定

1. **算法放进契约**：私有云和本机共用 `tokenMixCost` / `tokenMixRatio` / `TYPICAL_TOKEN_MIX`，免得两边各写一份，以后改了一边忘了另一边。
2. **字段名不改**：`discount` / `consumption_rate` / `rate_source` 留着，只改含义。老客户端照样能读，显示的位置也不变。
3. **云上给了倍率、没给折扣，就是「不到折」**：本机不拿自己的内置价目另算一个，免得跟云上说法不一致。
4. **先找现成的**：这一半只是改口径和文案，没有新能力；价目来源的调研写在私有仓报告。
