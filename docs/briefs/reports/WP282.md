## 2. 我自主做的决定（白话）

1. **本机路由另立一条** `GET /v1/cloud/usage/members`，不往老的 `/v1/cloud/usage?group=` 里塞 `member`：老那条「看多少由令牌说了算、本机不裁」，按人这条偏偏要本机裁，混在一起会让老那条的规矩变得说不清。老那条照旧只认三个分组。
2. **这条路由不挂策略元组**（同 WP194 额度那几条）：③ 普通成员多半没有 `store_config.read`，挂了他连自己那一行都看不到；谁看得到谁全在实现里按模式判。
3. **③ 普通成员给别人的 `member` 也只回自己**，不报 403——界面上从来不会这么问，接口上静默收窄最省事，也不会漏。
4. **按名册补 0 行只补「还在的成员」**；离开了的人如果这个月有用量，云上会回他那一行（名字照样能翻出来），没用量就不出现。
5. **① 个人不出这块**：只有自己一个人，和上面积分卡的「本月用了」是同一个数，再摆一张表只是多字。
6. **③ 老板 / 管理员在设置 → 账号里也看到全员表**：以前 ③ 这里没有按人那块（公司「积分」tab 在 WP206 搬去了网页）。现在服务端按人判了，就让管理者在工作台也看一眼谁花了多少；分额度仍在网页。
7. **「没标注」只在全员视图出**：只看自己时那一行不是他的。
8. 表格只看本月，没做月份切换（接口和路由都支持 `month`，界面少字，先不加）。

## 3. 要 Luoye 定的事（每条附建议）

1. **普通成员在设置 → 账号里看到「还没关联」（老问题，这单撞见的）**：积分卡的余额 / 本月用量 / 价目 / 充值档几条本机路由挂了 `store_config.read`，② 里不是发起人的同事、③ 里普通成员都没有，回 403，界面就当成「还没关联」，和下面的按人积分对不上（见截图 2、3）。**建议**：余额、本月合计、价目、充值档对所有人只读开放（② 本来就是「共用一个余额、大家看得见」），充值按钮仍只给有权限的人；另开一小单。
2. **云上生图 / 改图不带归属头**（配合清单第 5 条查出来的）：对话、搜索数据、公共红人库、`/v1/data/*` 都带 `X-Agentsws-Member`，但 `models.ts` 里走 Agents 工坊官方接口的生图那条（`/v1/ai/images/generations` / `edits`，WP273 的 `ai.image_edit` 0.8 / 张）只带了 `X-Agentsws-Region`，这部分会落进「没标注」。改法是给生图 provider 也接上对话那条 `requestHeaders`。这几行和 WP281（删数据不出境）正在改的 `X-Agentsws-Region` 挨着，我没动。**建议**：WP281 合并后开一小单补上（几行 + 一条测试）。
3. **③ 老板 / 管理员在设置 → 账号也看全员表**（第 2 节第 6 条）。**建议**：保持；嫌多就改成只在网页看。
4. **按人表格要不要能翻上个月**。**建议**：先不加；真有人要再加一个「上个月」小切换（接口已支持 `month`）。

另外两件不用定、提一句：私有仓可以另起小单把 `member-usage.ts` 里本地那几个类型换成 import 契约（名字已对齐）；开源仓里那份旧的云端代码 `packages/cloud-entry` 没跟着加 `group=member`（会回 400，契约里本来就有 400），它要整体搬去私有仓，不值得改。
