# WP145 报告：语音转写留一个「本机识别器」的口

分支 `wp/145-speech-slot` · worktree `agentsws-wt/wp145-speech-slot` · 实现：Claude 子代理 · 09-24

## 1 实现清单

1. **识别器选择层** `packages/model-gateway/src/speech.ts`（从 `@agentsws/model-gateway` 导出）
   - `createSpeechToText({ gateway, defaultProvider?, language? })`，形状对齐官方 `ctx.speechToText`（`dsh-experimental-speech-to-text` @ `dsh-v0.1.7-rc.1`）：
     - `register(provider)` 注册具名识别器，返回撤下函数；撤下时正在跑的转写收到取消信号。
     - `resolve({ input, providerId?, language? })` → `transcribe(spec, meta, model?)`：先定下用哪一个、什么语言，再执行；识别器被撤下或换掉就拒绝，不偷偷换一个。
     - `languages` 校验（`resolve` 和 `configure` 都查；空数组 = 不限制、原样转交）。
     - `prepare(providerId, { downloadSource })`：下载源必须是该识别器 `downloadSources` 里的一个。
     - `providers()`（带准备状态）、`selection()`、`configure()`。
     - 出错一律 `SpeechError`：`provider_missing` / `provider_duplicate` / `provider_withdrawn` / `unsupported_language` / `bad_download_source`。
   - 内置识别器只有一个：`model-gateway`（`gatewaySpeechProvider`），原样交给模型网关的 `transcribe`。走「云端（积分）」还是「自带模型 key」照旧由模型设置决定。
   - `localTranscription()` / `speechAudioDigest()`：以后不经网关的本机识别器用它们补齐 `Transcription`（用量记 0，`model` 记成识别器本身，音频只留摘要，和网关同一条纪律）。
2. **会议转写接上选择层** `apps/server/src/meetings.ts`
   - `MeetingsOptions.speech?` 可选。不传就建一个只有 `model-gateway` 的选择层；装配结果上加了 `speech`，以后在 server 装配处 `meetings.speech.register(...)` 即可。
   - 管线的 ASR 槽由原来的 `options.models.transcribe(audio, meta)` 换成 `speech.transcribe(speech.resolve({ input: audio }), meta)`。
3. **测试**
   - `apps/server/test/speech-slot.test.ts`（派工单点名的那条）：注册替身识别器并选中后，会议转写走它，网关没有账目，也没有 `model.usage`（不扣积分）；没注册时，会议事件、处理结果、网关账目与事件都和 WP145 以前的接法（管线直连 `models.transcribe`）逐字相同；网关转写失败时，错误话术（`transcribe provider failed`）、失败事件、系统卡也逐字相同。
   - `packages/model-gateway/test/speech.test.ts`：默认只有网关、入参原对象交出；替身不经网关记账；语言补默认 / 拒不认的语言且不保存；没注册 / 重名 / 下载源不对都报错；撤下时取消正在跑的、旧解析结果不能再用。
4. **docs**：`docs/37` §4.3 在「22：模型网关加 transcribe」下面补了三小段：为什么现在不做本地、口在哪、以后怎么接。

没有加任何依赖，`speech-to-text-sensevoice` 等本机识别器包一个都没进依赖树，也没下载模型；设置页没改，不露「本机识别」。

## 2 自主决定（白话）

- **放在哪**：选择层放在 `model-gateway` 包里、单独一个新文件（派工单点名了这个包）。`index.ts` 只加了一段导出，没动 `gateway.ts`，尽量不和并行的 WP143 撞。
- **「云端（积分）」和「自带 key」合成一个识别器**：现在这两种其实是同一条路（模型网关），按模型设置里配的是哪一家决定。硬拆成两个识别器就得替网关挑模型，反而改了行为。所以只注册一个 `model-gateway`，名字写「云端（积分）或自带模型 key（跟随模型设置）」。
- **语言不替调用方补**：官方每次都会把语言定下来；我们默认不补（没配默认语言、调用方没给，就不加这个字段），这样网关收到的入参和以前一模一样。以后本机识别器要强制语言，建层时传 `language` 就行。
- **准备口只做校验和转交**：下载、进度、取消都归识别器自己，选择层只查下载源在不在它自己列的清单里。
- **选择不落盘**：官方把默认识别器存进设置；现在只有一个识别器、界面上也没这个选项，所以只存在内存里。等真有第二个识别器、设置页要露出来时再持久化。
- **本机识别器不经网关**：所以不扣积分，也没有 `model.usage`。网关的急停、驻留、预算这几道管的是出网的模型调用，本机识别不过这几道。以后如果要把本机转写也记进审计，再加一条专门的事件。
- **设置页**：docs/36 没有「预告位」的惯例，按派工单选前者，一行都不露。

## 5 偏离

- 派工单说在「会议 / 知识入库等所有调 `transcribe` 的地方」前面加这一层。实际查了全仓，只有会议装配这一处调 `transcribe`，知识入库现在不做音频转写，所以只接了会议。以后知识入库要转写，用同一个 `meetings.speech`（或另建一个 `createSpeechToText`）就行。
- 「云端（积分）」「自带 key」没拆成两个识别器，合成一个 `model-gateway`，原因见第 2 节。
- 官方的 `SpeechPreparationState` 只对齐了主干，没做 `steps` 逐步明细，也没做下载失败的分类诊断；这些归以后的本机识别器自己出。
