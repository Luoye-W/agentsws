## 2. 自主做的决定（白话）

- **评论文本红线做在 schema 形状里**：`content-observations` 的 zod `.strict()` 白名单里根本没有评论这一格——多一个键整批拒，靠自觉的字段约定总会被绕过。
- **余额不足回 200 + `payment_required` 而非 HTTP 402**：插件侧的错误分支只有一条（看 `code`），人话里指路充值入口；与 `docs/76` 的错误码人话表一致。
- **`report` 里 `tenant_pool.email` 是明文**：这是用户自己库里已有的联系方式（他自己存的），返回明文省一次 reveal；没有的照走 reveal 计费。
- **`attached_creators` 恒 0、`avg_views` 回 null**：本机库没有这些格子的历史可对，如实回空不编数（面板视为正常结果）——遗留 §8 第 2/3 条。
- 守卫测试逮到子会话在注释里写了 "ContactPanel"（私有组件名），已改写为中性说法——守卫真的在工作。

## 3. 需要 Luoye 定的事

- **内容观测的云端转发**：云端公共库目前只有红人观测路，`content-observations` 先落本机（新表 `content_observation`），云端开放内容路后再接转发——要不要排进云端那一侧的下一单。
- 深色主题触发线是 `prefers-color-scheme`（shadow root 里没有 `<html class="dark">`）；工作台若做成手动切换主题，插件需要加一条消息通道跟随。
