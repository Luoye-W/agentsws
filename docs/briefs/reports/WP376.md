## 2. 做了什么（白话）

1. **Anthropic 的 API key 改走原生口**。卡上这个方案现在是「Anthropic 官方的原生接口」，地址 `https://api.anthropic.com`，拉清单、测试、AI 钮都和 WP374 那张中转站卡同一套。名字、看图、上下文、思考档照官方 Claude 目录。
2. **老配置自动迁**。启动时看到「OpenAI 兼容 + `api.anthropic.com/v1`」的那条，就只换两样：种类（换成原生口）和地址（去掉 `/v1`）。别的一样不动：编号不变（所以加密库里的 key、默认模型、按用途选的模型、上次测试结果都照旧对得上），名字、模型、勾进 AI 钮的那几个、清单、价格都不动。迁完落盘，并在这一条上记下「迁之前是什么样」。
   - **幂等**：再启动、再迁，文件一个字节都不变。
   - **可回退**：环境变量 `AGENTSWS_ANTHROPIC_NATIVE=off`（或 `0` / `false`）启动 = 不迁，并把迁过、人没再改过地址的那几条原样改回去；去掉开关再启动又迁回来。
   - 从老品牌复制设置、或者有人在 OpenAI 兼容卡里填了 `api.anthropic.com/v1` 保存，同样换成原生口。
   - key 一直在本机加密库，迁移不读不写它（决策 814）。
3. **思考程度**。迁过去以后，Claude 官方型号在 AI 钮旁边出「快 / 标准 / 深度」；没选就按「标准」发（决策 1032「显示什么就发什么」，WP374 那一套直接用上）。WP373 的独立小钮读的是同一份 `thinking`，合进来就是它（预合了一下，代码不冲突，见 §6）。
4. **自己接的 OpenAI 兼容口（决策 1027）**：
   - 用户填的地址和官方目录里各家的地址逐字比（主机名大小写、结尾 `/` 不算差别），模型名在那家目录里才算认得；只认 OpenAI 兼容的两种协议（Chat Completions、Responses）。
   - **认得的**：请求、流式、工具、思考全走官方 pi-ai 那家的协议；名字、上下文、看图、思考档照目录。档怎么发也照目录：OpenRouter 发 `reasoning.effort`，百炼 Token Plan 的 Qwen 发 `enable_thinking`，OpenAI 本家走 Responses 口发 `reasoning.effort`……我们一行都没写。只声明了「不想」和一档的型号，合进 WP373 之后自动是开关。
   - **认不得的**（中转站、自建网关、本机 Ollama、百炼按量那个地址、智谱通用那个地址、Google 的兼容层、目录里没有的型号名）：官方没声明档位，不出思考钮，请求照旧走我们原来的通道，一个字节不变。为什么不连它们也改走 pi-ai，见 1042。
   - 拉清单、向量、语音识别：官方 pi-ai 没有，一直走原来的通道。
5. **「Anthropic 兼容（自定义）」那张卡默认地址留空**。原来它默认填 Anthropic 本家；现在本家的 key 有了自己的方案，两张卡又是按地址认的（同一个地址会认串，点开一张另一张跟着展开），所以这张卡不再预填，表单里地址必填、框里给个样子 `https://relay.example.com`。见 1043。
6. **顺手修了一个 WP374 的坑**：我们的工具名带点（`orders.get`），Anthropic 和 OpenAI 都只认字母数字下划线短横线。WP374 那条 Anthropic 兼容口是直接把带点的名字发出去的（假中转站不查，所以测试没发现；真 Anthropic 会拒）。现在走官方 pi-ai 的两条路都先换成合规名（`orders__get`，和原来 OpenAI 兼容通道同一条规矩），回来再换回原名；强制某个工具时也一样。
7. **报错说人话**：照 WP374 那一套——key 不对 →「API key 不对」，额度 / 余额没了 →「余额不足」，原文里没有 key。
8. **中英教程**：`docs/help/model-anthropic`（中英）「方式二」改成原生接口、写了老配置会自动换；`docs/help/model-openai-compatible`（中英）加一节「思考程度」，Anthropic 兼容那一节改成「本家 key 走 Anthropic 卡、这张不预填地址」，「深想」改成「深度」（1037）。

## 4. 我自主做的决定（白话）

1. **认地址用官方整份目录**（`providers/all`），启动时读一次（只读、不联网），之后同步查；配了认得的地址就重装一次网关，让看图的声明跟上。
2. **同一个地址上几家都有同一个型号**（百炼 Token Plan 国际版两家共用一个地址）取先读到的那家。
3. **测试 / demo 注入了替身网络、又没给官方协议那条路的替身时，OpenAI 兼容口一律走原通道**：替身不会让请求漏到真网络上（新加的 `piFetch` 只有测试会给）。
4. **`seed`** 在 Chat Completions 那种上照原样发（官方协议不管它，原通道发过）。
5. **强制某个工具时 Anthropic 不开思考**（WP374 原样，Anthropic 规定）；OpenAI 那两种照官方，不拦。
6. **迁过来的那一条人只改了名字 / 模型**（种类、地址没动）仍记着原样，回退开关照样能改回去；改了地址就不再记。
7. **迁移时丢掉向量 / 语音识别模型那两格**：Anthropic 的 Messages 协议没有这两种接口（老的 OpenAI 兼容层也没有，留着只会报错）。
8. **契约只加**：`ReasoningReplay.kind` 多 `openai-completions` / `openai-responses`；`readPiAssistant` 多两个可选参数；`ModelsOptions.piFetch` 可选。已有签名一个没改。本体已重出，SDK / 云契约无变化。
