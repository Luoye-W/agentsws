## 1. 做了什么（白话）

一条路，五种写都走它：**回收件箱里的回复 / @（楼中楼）、回自家版块帖子、楼中楼（回别人的回复）、在别人版块评论、发新帖**。

0. **从哪来**：WP328 每日巡查读到要回的条目 → 本单自动起草、出卡（条目标「起草中」）；人在工作台点「起草」也一样。
1. **起草**（`POST /v1/social/reddit/draft`，`apps/server/src/reddit-write/draft.ts`）：Reddit 专用提示——原帖标题 / 正文、被回的那句话、这个版的版规原文（插件借品牌号会话只读 `about/rules.json` 读回来的，巡查时顺手读，决策 764；都是外部文本，包进 `<external_data>`）、知识库检索命中（WP322 的 FAQ 卡也在里面；「参数、价格、政策只能用这里有的」）、品牌话术（`brand-voice` 技能原样引用，经 `social-core` 的 `voicePrompt`）、人的一句要点。**提示里没有任何推广规矩**（测试钉住不含冷却 / 占比 / 表明身份）。没接真模型就给一句照原话语言的开头，照实说「没用 AI」。只起草，不出卡。
2. **出卡**（`POST /v1/social/reddit/stage`）：`outbound_draft` + `form: 'reddit_write'`（docs/96「发出去」家族）。**永远 L1**、审批人就是本人（669）；带承诺词打回不出卡。卡上：被回的那句话、**能改的标题 / 正文**、依据（用上的 FAQ 卡、WP328 的判断理由）、版规条数（原文进问号）。「发送」在卡身里，改过字就带着改过的那一版批（`approve_edited`）。
3. **批了**：过两分钟取消窗口（批准那一刻排一次、每分钟补扫一次）→ 执行器交给插件动作通道（WP313 那条，加了 `reddit` 平台）。卡的施行结果记 `ok` + `outcome_ref.type = 'reddit_fill'`（与「人自己发」的 `manual_send` 同一个意思：系统这侧做完了，剩下那一下是人点）。**这时不记发出记录**。
4. **插件**（用户日常 Chrome 里的「Agents 工坊助手」）：领到活 → **新开一个看得见的标签页**（不抢用户正在看的 Reddit 页）→ 打开那条评论 / 帖子 / 发帖页 → 点 reply、把草稿填进框 → 横条「AI 正在操作 · 6/6 · 填好了，等你点发送 · 停止」→ **人自己点发送** → 插件认出页面上**新出现**的那一条（填草稿之前先记底账，老的不算），读回 `t1_/t3_` 编号与链接 → 回报。发新帖时页面会跳到帖子页（脚本被扔掉），插件放回脚本接着认。等 30 分钟没看到 / 撞上验证码 / 没登录 / 「you are doing that too much」/ 点了停止 → 停下照实报，**不重试、不代点**。
5. **读回之后**：WP328 那一条标「回过了」并挂上发出记录那一行；本地发出记录多一行（WP323；渠道 reddit、动作 reply / comment / post、版块、原帖标题与链接、对方与原话、我们发的全文、**编号与链接**、回的是哪一条、用了哪些 FAQ、谁批的）。配了「记录去处」就按映射照写（WP323 机制，没改）。对方之后回我们，WP328 读收件箱时按 `parent_id` 调 `addFollowUp` 就挂回这一行（端到端测过）。
6. **没发出去**：进度里记「没发出去 + 原因」（`GET /v1/social/reddit/writes`），不记发出记录；连接页「浏览器插件 → 广告动作」最近 5 件里也看得到、能停。

### 修掉 / 关掉的
- **关掉自动发**（663）：`social/reddit.yml` 与 `pr/reddit.yml` 的 `reply_thread` 从 L2→L3 改成**硬 L1**（升不上去）；测试钉住。Reddit 的写卡一律 L1，不看职责等级。
- **`submitApprovedPost` 没人调**：公关的外部发帖卡（`community_post`）批了以前什么都不发生。现在 `backendApply` 里认出 Reddit 那一条 → 交给插件填发帖页（或回帖子）；`submitApprovedPost`（OAuth 应用）接在「插件不在线时直发」那条备用路上，**按 761 默认关**。发出去之后帖子标「已发」并带编号与链接。
- **插件不在线不走程序直发（761）**：做成开关（`redditWrites.settings().direct_fallback`，存在 `<品牌目录>/reddit-writes/state.json`），**默认关**——插件不在线时批过的那一条排着、进度里写「插件不在线，等你打开 Chrome（24 小时内来领都行）」。开关没出界面（Luoye 定了关，暂不需要）；帮助文档 `docs/help/browser-extension(.en).md` 加了一节写清。
- **楼中楼**：插件那条路支持；社媒库线程加了 `permalink`（自家版队列入库时带上），社媒的 Reddit 回帖卡也改走插件（评论有链接就楼中楼；没链接退回原来的出口）。官方号浏览器那条回不了楼中楼时，提示改成「去插件里连 Reddit」。

## 3. 与 WP328（读）的对接（已接上）

WP328 10-15 合进 main，本分支 `git merge main` 后按协调方给的接口接好了：

1. **待处理 → 起草出卡**：`server.ts` 里 `redditWatch.onPending(entries => …)`：每条 `status === 'open'` 的 `RedditWatchEntry` → `redditTargetFromItem(entry)`（帖子 → 回帖，评论 / 收件箱回复 / @ → 楼中楼，用 `url` 当那条评论的链接；私信不回）→ `redditWrites.draftAndStage(actor, { target, reason: entry.judgement.reason })`。起草的人 = 担「自家版运营」（`social.reddit`）的那个人；没人担就不起草，条目留在待处理里。人在工作台点「起草」走 `POST /v1/social/reddit/draft|stage`，`target.source = { type: 'reddit_watch_item', id }`。
2. **状态回写**：出卡 → `redditWatch.setStatus(id, 'drafting')`；读回确认发出去 → `setStatus(id, 'done', { outbound_record_id })`（`settleRedditWrite` 加了 `reddit_watch_item` 分支）。没发出去条目留在「起草中」，不改。
3. **后续挂回**：发出记录的 `external_id` 写 Reddit 全名（`t1_…` / `t3_…`），WP328 读收件箱据此挂后续。
4. **共用一本账**：插件动作通道的排队按活换账本（`paceFor`）：Reddit 写活记在 `redditWatch.pace`，键 `reddit:<品牌号>` 与 `redditPaceKey(品牌号, ws)` 一致——插件领走写活时 `begin`、回结局时 `end`；写活占着号时巡查领不到（端到端钉住），反过来也一样。品牌号用 WP328 设置里的 `brand_username`（没配按品牌算）。
5. **插件**：scope `reddit.write`（与 WP328 的 `reddit.read` 成对）；可选权限用 WP328 的 `REDDIT_HOST_PERMISSIONS`（我那个同值常量删了）；设置页两行 Reddit 并成一行（连上了读写都用，连上时也马上问一次有没有要填的回复）。
6. **版规（764）**：WP328 的只读路加了 `sub_rules`；巡查时顺手读自家版块、以及起草时要过但还没读过的版（起草读不到就 `wantRules` 记一笔，下一轮读）。起草 / 卡面先用插件读回的那份，读不到才退回 OAuth / 官方号浏览器。
7. **两条通道**不变：读走 `/v1/extension/reddit/*`，写走 `/v1/extension/actions/*`（平台 `reddit`）。

## 4. 我自主做的决定（白话）

1. **复用 WP313 的动作通道，不另起一条**：派工单与 docs/102 都写「复用」。平台加 `reddit`、Reddit 不要广告那份风险告知（插件不替人点发送）、新加一个只看不点的步骤 `await_sent`。广告那边一个字节行为没变（WP313 真浏览器 13 项重跑全过）。
2. **交给插件 = 卡记「已施行」**：插件要等人点、可能等很久，执行器不能挂着锁等。照「人自己发」那种卡的做法：系统这侧做完就记 ok，真发没发出去看进度；**发出记录只在读回之后写**。
3. **新开标签页**做 Reddit 的活（广告是复用已开的后台页）：用户可能正在别的 Reddit 页面上看东西。
4. **认「发出去的那一条」**按正文：去掉 Markdown 记号与空白后比「包含」，在那条评论的直接下一层 / 帖子的顶层评论 / 新帖页里找，填草稿之前先记底账（同样正文的老评论不算）。
5. **插件不在线就等**（761 关）：直发（OAuth 应用 / 官方号浏览器，WP249 留的备用路）做成开关、默认关；关着时批过的一律排进插件通道等 24 小时，进度里写「插件不在线，等你打开 Chrome」。社媒的 Reddit 回帖卡也一样（WP254 的服务端测试打开开关钉住备用路还在）。
6. **没发出去不自动重出卡、不重试**；只记原因（docs/102 §4「没确认到就照实说，不自动重试」）。
7. **卡上「发送」在卡身里**（同 WP324 连接卡），底下那排与键盘 → 不再有「发送」——否则改过的字会被键盘那一下丢掉。
8. **私信（`t4_`）不回**、发新帖不自动起草（要人给一句要点）。
9. **卡面减字**：版块与回复谁只在标题里；版规原文、FAQ 原文进问号。
10. **卡 payload 里写到哪叫 `reddit` 不叫 `target`**：审批总线把 `payload.target` 当 `ObjectRef` 算执行快照，叫 `target` 批完施行会「快照对不上」（踩过）。
11. **动了 WP328 的代码（只加）**：版规读法加在它的只读路里（`sub_rules`）、巡查顺手读；动作通道排队可以按活换账本，Reddit 写记在它那一本。WP328 自己的服务端测试改了一处期望（读的路多了一条 `rules:inmoxr`）。
