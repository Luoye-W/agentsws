## 2 我自主做的决定（白话）

- **多个变体都在、没有规范名时挑谁**：挑服务器清单里排第一个的那只（不去比谁的信多）。规范名在就一定用规范名。
- **文件夹清单多久重列一次**：10 分钟。每分钟列一次等于每只邮箱每分钟多登录一次；新建的那只我们自己会补进清单，所以不用等过期。
- **岗位文件夹一只都没有时先不扫**：原来是硬扫 `kefuagents`，服务器上没有这只时每分钟报一次「扫不动」。现在等第一次挪信建出来再扫。
- **B2B 那只不进缺省扫描**：还没有 B2B 岗位，扫了也没用。界面「B2B 往来」按「消息库里有没有 B2B 那只的信」决定显示与否——没有岗位就不会有信，也就不显示。B2B 那张单接上时，把 `b2b` 加进扫描清单、界面改成按岗位判断即可。
- **归档文件夹 `null` 真能关掉**：原来 `options.archive_folder ?? ARCHIVE_FOLDER` 会把 `null` 当成「没给」，注释说的「null = 关掉归档」其实不生效。顺手修了（就在要改的那一行）。
- **老默认 `agentsws` 仍算归档文件夹**：对账时在 `agentsws` 里搜到的信照样记成「归档文件夹找到」，也仍在对账搜索清单里——升级前归档过去的信不会被当成没发出去。
- **演练 / 演示数据直接写规范名**：它们不是真邮箱，不需要认变体；界面按语义把真名不同的几只并在一起显示。
- **`agent_status` 状态带只给客服 / 红人**：`b2b` 还没有 Agent 在处理，不出状态带（公共接口类型没改）。

## 3 需要 Luoye 定的事

1. **客服渠道把「处理过的每一封」都归档，现在归进 `KefuAgents`**。WP55 的客服收信那一路（`channels.ts` 里的 `EmailChannelAdapter`）对它处理成功的每封 INBOX 来信都会 MOVE 到归档文件夹，不看分拣结论、也不看客服岗位开没开。以前归到 `agentsws`（消息页不扫这只，信在消息页里就看不见了）；按 63 §D 改成默认 `KefuAgents` 之后，信能在「客服在处理」里看见，但**非客服的信（订阅、通知）也会进这只**，与「岗位没开就不挪信」那条对不上。这是 WP55 与 WP113 两条收信路本来就有的冲突，不是本单造成的；建议另开一单：让归档只对分拣成 `support` 的信生效，或在消息同步接管后关掉渠道归档（`archive_folder: null` 现在真能关了）。
2. 有的服务器（Dovecot / Courier 的 `INBOX.` 命名空间）自建文件夹必须带前缀，比如 `INBOX.KefuAgents`。本单只认「名字本身不分大小写相同」，**不认带前缀的**（老产品也没处理）。要不要支持，等真遇到再说？
