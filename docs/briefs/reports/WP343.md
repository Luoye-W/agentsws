# WP343 报告：「随便聊」改成「我的助理」——能聊、能问全局、能替你派活

分支 `wp/343-assistant`（从 10-15 main 建，收尾前合了一次最新 main：WP336 genui、WP334 就地补设置）。没合 main、没打 tag、没发版。

## 一句话

左栏最上面那一项现在叫「我的助理」，就是一个像 ChatGPT / Claude 网页那样的对话框：可以随便聊；问「各岗位今天在做什么」「今天有什么要我处理的」它先去查再答；说「让 Reddit 运营查一下今天的新帖」它就把这件事交给那个岗位，回复下面一行「已交给 Reddit 运营 · 自家版运营」，那件事做完或要你拍板时，它回到这段对话里说一句。原来的「我的代理」并进来了，在页面右上角「替我答同事」（只在和同事一起用时出现）。

## 1. 做了什么

**界面（工作台）**

1. 左栏「随便聊」改名「我的助理」，仍在最上面；地址换成 `/assistant`，老地址 `/free-chat`（带会话 id 的也算）自动跳过来；`/secretary` 跳到助理页并打开「替我答同事」。左栏不再单独有「我的代理」。
2. 空状态：标题「有什么要我做的？」，下面一行小字「随便聊、问什么都行；也可以直接交代事情，我交给对应的岗位去做，做完回来告诉你。」输入框里的灰字也改成「问点什么，或交代一件事…（@ 选岗位直接交）」。
3. 快捷问题：输入框下面最多 4 个，服务端按你现在的情况现出，不写死——
   - 有要你处理的卡 →「今天有什么要我处理的？」
   - 有岗位 →「{岗位}今天做了什么？」（在办的事多的岗位排前面，最多两个）
   - 一句派活的例子，从你已有岗位里那条职责自己的快捷提示里挑「真去做一件事」的那条（例如「让客服起草退货回复」）
   - 一个干活的岗位都没有 →「帮我建一个岗位」（点了直接去建岗位那一页，不发话）
   - 开始对话之后收起。
4. 输入框里打 `@`：弹出你的岗位和岗位下的职责，↑↓ 选、回车定；选了输入框上方一个小胶囊，这句话**直接交给它**（不经模型挑），气泡上方标「@ 谁」。
5. 交出去的事：回复下面一行「→ 已交给 X · Y」，点了进那件事。回来报的那句画成一条小通知（✓ 做完了 / 要你拍板 / 没做成），旁边「去看」「去拍板」。这段对话里还有没报完的事时，页面每 5 秒问一次。
6. 原来回复旁边的「交给岗位去做」按钮删掉了（助理自己会交）。⌘K 里交给岗位的入口照旧。
7. 右上角两个小按钮：「记忆」（助理这一层记的几条，能删）；「替我答同事」（同事互联 / 公司模式才有，打开是 谁问过我 / 约时间 / 我的公开资料 / 问同事）。
8. 「记住了」小提醒（WP320）：助理这一层记下的那条，点它回到助理页、「记忆」自动打开并亮那条。
9. 教程新增一篇「我的助理：随便聊，也能替你把事交出去」（中英）；教程和设置里「模型用途」的「随便聊」改成「我的助理」。

**服务端**

1. 模型手上多了五个工具（参数表全仓一份，在 `@agentsws/stand-ins` 的 `runtime/assistant.ts`；dsh 那一侧原样转，严格参数表测试加上）：
   - 四个只读：`work_overview`（各岗位 / 职责在做什么、最近做完的、等你的卡几张）、`my_pending_cards`（今天要你处理的卡）、`recent_sent`（最近发出去的，只给你在做的职责发的，负责人看全品牌）、`matter_progress`（按关键词找某件事到哪了）。出参是白名单（名字、标题、状态、时间），不产生任何事项 / staged / applied。
   - 一个派活：`hand_to_position`。挑岗位的判据是 `@agentsws/roles` 的 `pickDispatchTarget`（服务进程和模拟世界同一份）：模型点了岗位名就照点的；没点名就看那句话里提到了哪个岗位名 / 职责名，只认出一个才派；你只有一个干活的岗位时派给它；**其余一律不派，回候选**，模型拿着候选问你一句。派了就走岗位原来的交办入口（`mode: task`、不等跑完），助理自己没有任何对外的写口——要改外部的事，由那个岗位照常出审批卡。
2. 系统提示改成「我的助理」：去掉「不能开事项或派活」那句；加上「问全局先查再答」「交代的事交给岗位、自己不做不改外部」「拿不准先问、把候选列出来」；你的岗位清单（派活时用这些名字）；助理记忆。WP336 的 genui 写法照旧加在后面，回答可以画组件。
3. 回报：助理交出去的每件事记一根线（对话 ↔ 事项，存在这个品牌的 `free-chat.sqlite`）。读会话、列会话、答完一轮时，看那件事的时间线：出了还在等你的卡 →「要你拍板」；跑完有回话 →「做完了」；没跑成 →「没做成」。同一步只报一次，交出去 3 天后不再看。那段对话正在答的时候先不插，答完再补（不然会插到回复前面）。
4. `@` 直接交：不经模型，回一句「好的，交给了 X。做完或要你拍板时，我在这里告诉你。」岗位不在你名下了就照实说；职责不是你名下的就不带（让岗位自己分）。
5. 助理记忆（WP320 等的那一层，决策 641）：记在**本人名下**、只在助理对话里用、不进岗位 / 职责的运行。提炼与过滤与 WP320 同一套（明说「记住…」、回答末尾的 `<remember>`、「以后 / 下次 / 一律…」；一次性的、密钥账号、敏感信息不记；一轮最多 3 条；删过的不再记回来，除非你又明说）。每记一条进记忆账本（`tier: personal`）冒「记住了」，事件日志记 `memory.added`（不带正文）。「自动记忆」开关沿用设置里那一个。新接口 `GET /v1/free-chat/memory`、`DELETE /v1/free-chat/memory/:id`（只能删自己的）。
6. 新接口 `GET /v1/free-chat/assistant`（快捷问题与 `@` 能选的岗位）；发一句可以带 `target`（`@` 选的）；SSE 多一帧 `dispatched`；会话里的一条话多 `dispatches` / `report` / `to` 三格。契约只加不删，SDK 重出。
7. 顺手堵了一个口子：以前模型点名 `web_search`，只要这个进程装了搜索就会执行——哪怕这一轮联网开关没开。现在只执行这一轮真挂出去的工具。
8. demo 的「Agents 工坊（用积分）」替身会点助理的工具（说「让 X…」派活、问「要我处理的」「在做什么」「发出去」查），岗位那边的运行回一句「（演示）做好了」，不再把助理的使用说明当成岗位的回答。

**模拟**

新事件 `assistant.dispatch`（助理派活：同一份挑岗位判据，只在这个人配过的岗位里挑）+ 新断言 `assistant_dispatched_to`（按顺序交给了哪几个岗位，拿不准的写 `-`；同时查助理名下零写）。三包各加一条「助理派活 → 岗位出审批，助理本身无写操作」：dtc-3c-3p / dtc-15p 是「让网站运营把 A 商品降价 10%」→ 网站运营 · 店铺管理出改价卡 → 点头施行，外加一句「帮我把这件事办了」不派；b2b-3c-3p 是「让 B2B 把英国那封询盘回了」→ 业务出 `b2b_reply` 卡。

## 2. 我自己定的（白话）

- **页面不换文件名**：组件、事件、包名都沿用 `free-chat`（派工单说包名 / 事件名不动），只换地址和字。这样和同时在改输入框的 WP342 冲突最少。
- **挑岗位只认名字，不再调一次模型猜**：拿不准就问一句，宁可多问不乱派。只有一个干活的岗位时直接派（这时候问「交给谁」很傻）。
- **`@` 选了就不经模型**：你都点名了，再让模型判一遍只会多花钱、还可能判错。
- **回报不另发通知**：落在那段对话里，会话排到最上面；要拍板的那张卡本来就在卡片流里，不重复提醒。只报三种：做完 / 要拍板 / 没做成。
- **重新生成那一条如果已经交出去过事，这次不再挂派活工具**，免得点一下「重新生成」就开出第二件一样的事。
- **助理记忆放在本人名下，存在助理自己的库里**，不放进技能库的个人层——那一层会被技能页列出来、也可能混进岗位运行。
- **「替我答同事」保留了「问同事」那一格**（原「问代理」）；原来「把一件事丢给代理」（秘书路由）那一格不放了，交代事情直接跟助理说。服务端那条路由没删（契约只加不删）。
- **「谁问过我」的字改了**：「还没有人问过你的代理」→「还没有同事问过你」，「代理拒答了」→「没替你答（要问你本人）」。
- **拿不准时用一句话问**（WP341 的 genui 按钮还没开工）；合了 WP341 再把候选换成按钮。

## 5. 偏离

- 报告按这次的要求写在 `docs/briefs/reports/WP343.md` 并提交（`_common.md` 说的是根目录 `REPORT.md` 不提交）；收尾前合了一次 main（派工单要求）。

- 模拟里「岗位出审批」那一步用的是场景里写好的岗位动作（`shop.price_change` / `b2b.inquiry`），因为模拟的 stub 运行时不会自己去改价 / 起草回信——这与现有的岗位入口场景同一个写法。

- 回报靠「读会话 / 答完一轮时补」+ 页面开着时每 5 秒问一次，没有接推送（和 WP320 小提醒一样用轮询，最省事）。没开助理页时回报要等下次打开才落进对话。
