## 2. 我自主做的决定（白话）

1. **五份正文放在技能包里（`packages/skills/bundled/`），没有分散到各个领域包。** 原因有三个：邮件营销没有自己的领域包；seo-core 正被 WP158 / WP159 并行改；五份放在一处，一份守卫测试就能全部盯住，读口也和加载器在同一个包里。
2. **附录并进正文，不另放 `references/`。** 我查了加载器（`frontmatter.ts` / `parse.ts` / `registry.ts`），它只读 SKILL.md 一个文件、按 `##` 切段，`references/` 读不到（客服那份的 `references/` 只有测试在读）。所以翻新附录、短信合规速查、UGC 附录都写成正文最后几段，测试里也钉了「不许有 `references/`」。
3. **frontmatter 的 `license` 写 `MIT`**，因为这五份改编自 MIT 项目。客服那份写 Apache-2.0，是因为它改编自 Apache 项目。MIT 要求保留版权与许可声明：出处写在每份的第一行，许可证全文放在 `THIRD-PARTY-NOTICES`。
4. **两个新技能起名 `email-sms`、`influencer-marketing`**，都按需加载，和另外三个一样。这样不动提示词里技能正文那一段，token 基线也不变。
5. **没有出处的行业数字一律删掉，不放附录。** 派工单允许把它们作为「行业说法」放附录，但附录也会进提示词，模型一样会引用。删掉的包括：AI 概览出现率、引用率提升比例、短信打开率、各层达人报价区间、健康指标区间、TCPA 罚款金额等。平台技术事实保留了，比如短信 160 / 70 字符分条。法律规则也保留了，比如静默时段、同意要求，罚款数字没留。
6. **平台字数表不在技能里重抄**，改成指向投放包的素材规格表（`ads-core/src/spec.ts`，全仓唯一）。上游那张表会过期，两份也会对不上。
7. **考题是静态的**：每道题有「期望」和「技能正文里必须有的那句规矩」。测试只查规矩在不在：没有那句，模型答这道题就没有依据。不调模型，也不花钱。
8. **守卫连否定句也不许写**：「不许自动发送」照样可能被断章取义，所以这几个字样一律换个说法。
9. **投放的止损**：meta 那条职责写着「只有止损可自动」，技能里只写「止损那一档能不能不问人，由职责设置决定，不由这份技能决定」，不重复，也不放宽。
10. **邮件的自动化流程**：和职责 YAML 的受保护字段对齐。技能明说触发条件由人去平台后台改，技能只提流程的开关与文案。

## 3. 需要 Luoye 定的事

1. **按需加载的技能正文还没有进提示词的通路。** 现在的 `skillPromptSections` 只取 `load: always`，运行时也没有「按需读技能」的工具，所以这五个技能（以及原来登记的 seo-judgment 等）在提示词里只出现在技能索引那一行。可选：(a) 改成 always（token 会上浮）；(b) 做一个按需读技能的工具；(c) 服务端启动时把自带技能种进技能库的包层，让技能页看得到、学习回路有地方落。我倾向 (b) + (c)，另开一单。

3. **行业数字的附录**：我全删了。要不要留一份标着「来源不明、不许引用」的附录给人看？
4. **audience-research 还挂哪里**：派工单说品牌建档也可以引用。我没找到品牌建档对应的职责，只挂了投放四条。社媒、内容要不要也挂？
