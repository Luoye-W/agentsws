## 一、一句话

用 ChatGPT 订阅登录以后，订阅里的模型（gpt-5.5 等，清单来自官方 pi-ai 的目录）会出现在「设置 → AI → 模型」的默认模型下拉里，也出现在每个输入框左下角的 AI 钮里，都标「ChatGPT 订阅」。选了它，岗位、事项、助理、随便聊就真的用订阅跑；联网搜索也先用 ChatGPT 自带的那一路。只在个人档有，公司档 / 托管档不出。

另外按 Luoye 10-16 的新要求，AI 钮改成了 Proma 那样：顶上能搜，按来源分组，每行有厂商图标、模型名和右边一格（消耗速率 / 订阅额度 / 用你自己的 key）。

## 二、订阅这一半做了什么（白话）

1. **订阅进两处下拉**。登录以后，模型面现算出一条「ChatGPT 订阅」来源，名字固定是 `openai-codex`。它不写进 `models.json`：「已配的」列表里没有它，复制品牌设置时也不会带走别人的订阅。默认模型下拉里显示成「ChatGPT 订阅（gpt-5.5）」这样；AI 钮里单独一组。订阅目录里的每个模型都能选，选了就真用那个。只登了订阅、没接别的模型的人，设置页也会出「默认模型」那一块（以前要先有一条「已配的」才出）。
2. **三个运行时都能跑**。订阅在模型网关里就是一条普通来源：stub / direct / dsh 都经网关问它，网关再经服务进程里的订阅登录树，交给官方 pi-ai 去打 `chatgpt.com/backend-api/codex/responses`。dsh 那一档不再在每次运行的树里挂官方订阅适配器，子进程档也一样只经 RPC 问宿主要补全，所以令牌不会跨进程。
3. **令牌不经手**。令牌只在本机加密库和 pi-ai 的内存里。我们只把消息和工具翻成 pi-ai 的格式，再把正文、工具调用、token 数翻回来。测试里查过：结果、请求体、事件、错误信息里都找不到令牌。
4. **花费记 0**。订阅不按 token 收钱，所以花费恒为 0，预算只按 token 判。用量页照样看得到用了多少 token。
5. **按人取订阅**。运行时把「这一次是谁」带给模型网关：在 `ModelMeta` 上加了一个可选的 `person_id`，没有改别的字段。点了名就只用这个人自己的订阅，别人的不借，和 WP355 同一个规矩。不在哪次运行里的零碎调用不会点名；这时如果这台机器上只有一个人登录过，就用他的（决策 955）。
6. **没登录、过期、被限流都出卡**。网关把这三种情况分开说人话：没登录或过期是 `unauthenticated`，限流是 `rate_limited`。不会悄悄换另一家模型去跑。运行收尾时出「ChatGPT 订阅」连接卡，卡里就是设置页那块订阅登录，可以重登，也可以换个账号。服务端判断不了「修好没有」：过期的记录还留在库里，限流时也还登着。所以卡不会自己接着跑，等人登好了点「接着做」（决策 953）。
7. **WP355 收尾**。
   - 系统提示「网页」那一段对订阅的运行改成说实话：「每一次先用 ChatGPT 订阅自带的联网搜索（花的是这个订阅的额度），搜不成才在工坊的内置浏览器里打开搜索页」。判法看这次运行的模型来源，没动契约，模拟基线字节不变。
   - 随便聊 / 助理判名单，改成看**这一轮真在用的模型**。以前看的是品牌默认，这段对话选了订阅、默认却不是订阅时会判错。
8. **订阅卡上加了一个问号**：「登好了，『默认模型』下拉和输入框的 AI 钮里就有『ChatGPT 订阅』这一组，选它就用订阅干活。」

## 三、AI 钮学 Proma（决策 956 / 957，单独一节）

截图：`docs/assets/wp362/model-picker-light.png`、`model-picker-dark.png`。

- **一个件，五处共用**：岗位页、事项、线程、助理、⌘K 交给岗位用的都是 `ComposerModelPicker`。
- **顶上搜索**：按模型名、厂商、来源过滤，对不上就写「没有对得上的模型」。↓ 从搜索框进清单，↑ 从第一项回搜索框，Esc 收起。
- **按来源分组**，组标题带图标：
  - 「Agents 工坊（积分）」：列出**云端价目里所有按 token 计价的模型**，不再只有一个，而且都挂上了网关，点了真用它。组标题右边：个人 / 同事互联写「余额 X 积分」；公司模式下这个人设了每月上限就写「本月还剩 X 积分」，没设上限就写公司余额。个人模式不出「企业分配」。问不到就不画，不编数字。
  - 「ChatGPT 订阅」：订阅目录里的模型。
  - 自己接的各家：一家一组，组名就是那条来源的名字。
- **每行**：厂商图标、模型名（默认那个标「默认」）、看图小标签（看不了图的是划掉的眼睛）、右边一格、选中的打勾。右边那一格：
  - 工坊积分：消耗速率，比如「1.0x」「2.3x」，价为 0 的写「限免」；
  - 订阅：「订阅额度」；
  - 自带 key：「用你自己的 key」。
- **消耗速率怎么算（决策 957）**：
  - 价目里带了 `consumption_rate` 就照它显示。这个数由私有云按用量账本长期统计，那边另派。
  - 没带，就按官方原价、相对 DeepSeek v4 Pro 折算。积分价等于官方价乘同一个倍率，所以两个模型积分价之比就是官方价之比。一个模型的价按输入 3、输出 1 加权取。
  - 组标题的问号里写：「消耗速率以 DeepSeek v4 Pro 官方原价为 1x，按后台长期统计换算；实际消耗以用量记录为准。」
  - **基准对不上时照实处理**：价目里没有 `deepseek-v4-pro`，或者它的价是 0（名字对不上 / 限免），就退回到当前默认模型算 1x，问号里多一句「这份价目里没有 DeepSeek v4 Pro，这里按 X 算 1x」。连默认模型都没有价，就不显示倍率。现在开源仓的样例价目里有 `deepseek-v4-pro`，不需要退回。
- **钮上**：「来源 · 模型名」，比如「ChatGPT 订阅 · gpt-5.5」「DeepSeek 官方 · deepseek-flash」。来源取名字里「·」前面那半。工坊积分那组沿用决策 853，只画工坊标记，读屏念「工坊」，悬停出「Agents 工坊（积分） · 模型名」。
- **底部**：所有者多一项「设为默认」；「管理模型…」打开设置弹窗的「AI → 模型」（WP356 已合进 main，地址 `/settings/models`）。
- **往哪边开**：按钮上下各剩多少地方现量。输入框在页面中间时，往上开会顶出窗口，这时改往下开；清单高度也不超过那一边剩下的地方。
- **厂商图标（先找现成的）**：用 LobeHub 的 `@lobehub/icons-static-svg` 1.95.1，**MIT 许可**（Copyright 2023 LobeHub）。只挑了 11 张，原样拷进 `apps/workstation/src/assets/vendors/`，许可证全文与「哪张来自哪个文件」写在同目录的 `LICENSE` 里，没把整个包打进来。
  - 11 家：OpenAI、Anthropic、Kimi、DeepSeek、通义、智谱、MiniMax、Gemini、豆包、Meta、Mistral。
  - 彩色的按原图画。单色的三张（OpenAI、Anthropic、Kimi）改用 CSS 遮罩，深色模式下跟着变浅。
  - 商标归各家所有，这里只用来标明模型是哪家的。

## 四、契约与数据（只加不删）

- `ModelMeta.person_id?`（contracts）：模型网关把「这一次是谁」递给 provider，只有订阅那一条看它；网关不把它写进用量事件。ontology 已重出。
- `PricingModelEntry.consumption_rate?` / `rate_source?: 'stats' | 'list_price'`（contracts）：云替身用的样例价目给 5 个模型补了示意值，其余故意不带，好演示「按官方原价折算」那条退路。
- `FreeChatModelChoice` 加 `group?` / `vendor?` / `price?`；`FreeChatModelsView` 加 `rate_base?` / `rate_note?`（api）。
- `BUILTIN_CONNECT_NEEDS.chatgpt_subscription`（contracts setup-card）。
- `DshRuntimeOptions.subscriptionRoute?: 'adapter' | 'gateway'`（dsh-adapter）：缺省是 `adapter`，即 WP90 老路，服务端给 `gateway`。
- dsh-adapter 新子路径 `./subscription-chat`（只读订阅目录，几十毫秒，不碰凭据）。
- 模型网关：`rate_limited` 与 `unauthenticated` 同样原样往上抛，不降级到别家。

## 五、真机验收脚本怎么跑（主会话和 Luoye 一起）

```bash
cd agentsws-wt/wp362-subscription   # 或合进 main 之后在主仓
npx tsc -b
node scripts/live-subscription-run.mjs            # 可加 --model gpt-5.6-sol、--question "…"
```

- **起什么**：在进程里起一个真服务，不监听端口，所以不碰 4317。数据目录是临时目录；秘密库密钥是临时生成的，只在这个进程的内存里。不带你机器上的环境变量，别的 key 一个都不碰。
- **登录**：屏幕上会出一个网址和一串码。用手机打开网址、输入那串码、确认授权就行，脚本每 2 秒查一次，最多等 6 分钟。
- **打印什么**（依次）：
  1. 登好了没有（账号只显示头尾各四位）；
  2. 订阅进没进「默认模型」下拉和 AI 钮；
  3. 默认模型设成了谁；
  4. 随便聊问一句「用联网搜索查一下 site:reddit.com smart glasses，挑三条……」；
  5. 这一轮用的来源；
  6. 搜了什么、搜到哪些站；
  7. **搜索来自哪一路**：「ChatGPT 自带搜索（用订阅搜的）」，或者没走成的原因；
  8. 用量（订阅那几笔花费都应该是 0）；
  9. 回答的头几行。
- **令牌**：脚本不读、不打印任何令牌。服务进程自己的日志不上屏，只放 `web-search:` 那几行；所有输出再过一道脱敏，像令牌的长串一律换成 `***`。
- **收尾**：成没成都会把临时目录整个删掉，最后一行写「临时目录已删」。
- **不连别的搜索服务**：自带搜索没搜成就照实说。加 `--fallback` 才会退回公开搜索服务。
- **先演练一遍**：`node scripts/live-subscription-run.mjs --dry-run` 用假的 OpenAI 演练，一个包都不出网，只看这条路通不通。我本机演练过一次，结果「通过」：

  ```
  ③ 默认模型设成了：openai-codex/gpt-5.5
     搜：site:reddit.com smart glasses
     这一轮用的来源：ChatGPT 订阅（openai-codex/gpt-5.5）
     搜到 1 条，站点：reddit.com
  ⑤ 搜索来自：ChatGPT 自带搜索（用订阅搜的）
       free_chat：2 次 … 花费 0
       web_search：1 次 … 花费 0
  临时目录已删（wp362-live-…）
  ```

- **真跑时要留意两件事**：
  - 默认那种 `web_search` 写法 Codex 后端认不认，至今没有实测结论（WP355 的决策 939）。如果第 ⑤ 步写「没走成自带搜索」，并且 `web-search:` 那行带 400，就跑一次 WP355 的 `scripts/live-codex-search.mjs --login --variants` 看哪种写法过了。
  - ChatGPT 订阅的 Responses 接口第一次真跑带工具调用的多轮对话。如果第 ④ 步报错，把那一行原样贴回来（已经脱敏）。

## 六、要 Luoye 定的事（953–955）

- **953　订阅过期 / 被限流时出连接卡，但卡不自己接着跑。**
  原因有两个。一是服务端判断不了「修好没有」：过期的那条记录还留在库里，限流时也还登着。二是自动重试会在限流时再把额度耗一轮。所以人在卡上重新登录（或者干脆等一会儿）之后，点一下「接着做」。
  **建议**：同意。
- **954　「有折扣的显示折扣」这次没做。**
  云端价目里没有折扣这一格，现在只有 `consumption_rate` / `rate_source` 两格。价为 0 的模型我写成「限免」。没有 `consumption_rate` 时的折算口径：积分价按输入 3、输出 1 加权，同一个模型有好几行时取第一条价不为 0 的那一行。
  **建议**：私有云那边如果要显示折扣，在价目条目上再加一格（比如 `discount: 0.1` 表示一折，只加字段）。这边读它，在倍率旁边写「1 折」，改动很小。没有这一格之前先不显示。
- **955　用谁的订阅、Claude 订阅暂不进下拉。**
  - 点了名（运行、随便聊、助理都会点名）只用这个人自己的订阅，别人的不借；
  - 没点名的零碎调用，这台机器上只有一个人登录过就用他的，好几个人登录过就不猜；
  - Claude 订阅那张登录卡保留，但这次**不进下拉、不能跑活**。决策 938 只说了 ChatGPT；Claude 订阅用于第三方工具的条款风险更大。

  **建议**：同意。Claude 订阅等有人要了再单开一单评估。

## 七、我自己做的决定（白话）

1. **订阅经模型网关走，不在 dsh 树里挂官方订阅适配器**。挂适配器的话，凭据插件要进每一次运行的树，子进程档还得把凭据带过进程边界。走网关这一跳，三个运行时一条路，凭据只在服务进程里，记账、预算、事件、降级规则都是网关那一套。官方适配器那条路（WP90）留着没删，`subscriptionRoute` 缺省仍是它，只是服务端不再用。
2. **pi-ai 只装 openai-codex 一家**：用 `createModels` + `openaiCodexProvider`，实测 46 毫秒。全家桶 `providers/all` 要四秒多。目录（能选哪几个）也从这一家读，不联网、不碰凭据。WP355 的自带搜索还用它原来的装法，没动。
3. **订阅是一条虚的来源**：id 就叫 `openai-codex`，和 dsh 那层、WP355 名单认的是同一个名字，所以 WP355 的判定自动接上。不写进 `models.json`。
4. **订阅目录、云端价目里的模型全挂上网关**。每个只是一个对象，不花钱建；不挂的话，选了等于白选（网关会退回同一家的第一个）。
5. **能不能看图照订阅目录**：pi-ai 的目录里写着收不收图（gpt-5.5 收图，gpt-5.3-codex-spark 不收）。
6. **token 口径**：pi-ai 报的「输入」不含命中缓存的部分，我们的口径（和 OpenAI 兼容口一样）是含缓存，所以加回去。
7. **AI 钮：自己接的一家一组**，钮上来源取短名，看图改成小标签。
8. **演练模式**：验收脚本加了 `--dry-run`，复用 dsh-adapter 测试里的假 OpenAI（Node 直接跑 `.ts`），好让主会话真跑之前先看一眼这条路通不通。
9. **先找现成的**：
   - 订阅补全用官方 pi-ai，dsh 官方的 `dsh-llm-pi-ai` 适配器理由见第 1 条，社区的 `dsh-codex-subscription` WP355 已评估过不用；
   - 厂商图标用 LobeHub（MIT），也看过 Simple Icons（仓里已在用，但缺通义 / 智谱 / Kimi / MiniMax / 豆包这几家）；
   - 都不用用户申请 key。
