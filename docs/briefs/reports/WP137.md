# WP137 报告：聊天转发三种形态的密钥兜底改成「没有真密钥就拒绝」（P0 安全）

分支 `wp/137-relay-secret`（worktree `../agentsws-wt/wp137-relay-secret`，从 main 44b5abcb 起；收尾已 `git merge main`，只带进来一处无关的 `packages/ontology/src/registry.ts`，没有冲突）。
Claude 子代理，2026-09-24。没 push、没部署。协议版本没动（仍是 1），已有公共签名一个没改，只加了可选项。

**一句话**：三种形态都不再有外人能推算出来的访客密钥。官方托管没配 `AGENTSWS_CHAT_RELAY_KEY`（或不到 32 字节）时，访客面一律 503「聊天窗暂时不可用」，health 标红。自建 Worker 没配 `VISITOR_SECRET` 整台拒绝服务。自建 Docker 改成首启随机生成一把服务端秘密存在卷里，访客密钥从它派生。留言密钥没签发就不收留言，常量封箱删了。

**部署前必须做**：`wrangler secret put AGENTSWS_CHAT_RELAY_KEY`（至少 32 字节，生成办法见 docs/64 secrets 表）。不配的话，新代码上去后所有商家网站上的聊天窗都打不开。这是有意这样设计的。

## 2. 我自主做的决定（白话）

1. **官方那边只挡访客面，不挡商家本机的长连接。** 派工单说的是「访客面一律 503」。种子是我们运维的事，商家自己补不了；让本机照常连上，状态页和测试连接还能工作。访客那边照样打不开，health 标红提醒我们去补。
2. **自建 Worker 没配 `VISITOR_SECRET` 时连本机连接也拒。** 这一档的密钥是商家自己配的。如果只挡访客面，商家点「测试连接」会显示在线，以为一切正常，其实网站上的聊天窗打不开。整台拒绝，他在设置页就能发现连不上，再按 README / `wrangler tail` 的提示补上。
3. **32 字节门槛三种形态统一，包括测试注入的种子。** 按 UTF-8 字节数、去掉首尾空白后算。`openssl rand -base64 32` 生成的是 44 个字符，能过。短的一律当没配，不会因为「好歹配了一个」就放行。
4. **官方种子派生没改（`sha256('chat-relay:' + 种子 + ':visitor:' + 工作区)`），自建 Worker 仍直接用 `VISITOR_SECRET` 当 HMAC 密钥。** 已经正确配了密钥的部署，访客令牌不会因为这次升级失效。只有 Docker 档的访客令牌会失效，因为它原来就没用过任何秘密，只能换。
5. **自建 Worker 的留言另加一把 `MESSAGE_KEY`（选填），没有让它跟着 `VISITOR_SECRET` 走。** 留言密钥要填回本机才能开箱，访客密钥不该出现在第二个地方。两把分开，泄露一把不会连带另一把。
6. **核心里「宿主没给 `seal`」也算不收留言。** 原来的约定是没给 `seal` 就原样存明文，注释里写的是测试用。现在访客面遇到这种情况一律拒绝。核心直接调用 `leaveOfflineMessage` 的老测试行为不变。
7. **顺手给工作台加了「留言密钥」输入框。** 严格说不在派工单里，但不加的话，本单「没留言密钥不收留言」这条对自建两档就只剩「永远不收」：Docker 打印出来的留言密钥和 Worker 的 `MESSAGE_KEY` 都没地方填回本机。本机后端和契约早就支持这个字段（`PUT /v1/chat/relay/settings` 的 `message_key`），界面上只多了一个密码框。
8. **挂件被拒时如实显示「现在还不能留言」，不显示服务端那句「商家还没完成配对」。** 挂件跟着网站语言走（可能是英文），而「配对」这个词是说给商家听的，访客看不懂。服务端的人话留在 API 回包和日志里。
9. **Docker 卷文件权限收到 0600。** 卷里现在有一把真秘密，顺手收紧。某些挂载不支持 chmod，失败就跳过，不影响功能。

## 3. 需要 Luoye 定的事

1. **部署时配 `AGENTSWS_CHAT_RELAY_KEY`**（Fable 部署时补上即可，不用拍板；列在这里是因为不配聊天窗就全挂）。它丢了或换了都没关系：换了只会让正开着的访客会话需要重建，不丢数据。所以**不必**像 `AGENTSWS_HOSTED_KEY_SEED` 那样一定进密码管理器。
2. **很早期的 Docker 自建用户（卷里有配对哈希、没有留言密钥）升级后不收留言。** 想要留言功能只能删卷重新配对（README 已写）。估计没有真实用户处在这个状态（留言密钥是 WP124 同一轮加的），所以我没另做「补签留言密钥」的入口。如果有这样的用户，要另开单。

## 5. 偏离

1. **自建 Worker 模板补了 `nodejs_compat`。** dry-run 打包时发现，产物里有两处 `from "node:crypto"`（`http.ts` 的 HMAC 在 main 上就有，本单又经 `sealed.ts` 用了 AES-GCM）。模板原来没开这个标志，照 README 部署会在上传时报「No such module」。这是 WP124 就有的问题，一行配置就能修，我顺手修了。
2. **工作台加了留言密钥输入框**（§2 第 7 条），派工单没点名。
3. **原有的 `ChatRelayDoOptions.sealKey` 没删。** 它一直没被用过，属于已有公共签名，按规矩只加不删。
