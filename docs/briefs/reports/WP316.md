## 1. 一句话

投放的 Google / Meta 两条职责，从「只出卡」接到了完整执行：一批改动按 552 分路出卡（上传表卡带着一句话、预览和可下载的原表）→
批了交给插件 → 在用户自己的后台里上传 / 点 → 平台预览截图 → 人再确认（插件横条，或职责页「广告改动」那一块）→ 提交 → 截图 →
再导出一份逐行读回核对 → 记进每品牌一本的**广告变更账本**（上传表、改前 / 改后导出、截图、审批编号、读回，180 天）。
新建的一律先暂停，做完自动出「开始投放」卡；止损截不到图也先停；每个账户有 14 天磨合期；做完的能撤销。

## 3. 执行那一半怎么走（白话）

1. 卡批了，变更账本的执行器调到广告这一环：只认 Google / Meta、账户在库里、这台机器装了插件通道的；别的照旧走原来那条路（托管实例、X / TikTok、改出价、换素材）。
2. 上传表卡：执行前按卡上的字节再算一遍指纹，对不上就不传（审批绑的是这一份）。Google 一层一张表，**一张做完再进下一张**；改前导出只在第一张之前导一次，读回导出只在最后一张之后。Meta 用制表符文字粘贴（WP313 / WP314 约定）。
3. 进了队就回 ok（照 WP329 Reddit 那条：回 `unknown` 会让对账把整个出站停住）；真正的结局记在广告账本里，做不成另出提醒说清楚。
4. 插件回来：截图挂到账本那一条上；下载的导出账本自己存一份（这份也成了这个账户「最近一份导出」，Meta 改已有要它）；结局「退回」时后面的表不传、记下平台原话；做完的最后一件 → 拿改后导出逐行读回核对。
5. 新建的做完、读回拿到了编号 → 自动出一张「开始投放」卡（L1，带上平台给的编号；新预算这时才算进总闸）。
6. 止损（L3 自动批）：截不到图也先停，停前停后两份导出作证，记一条止损记录 + `ads.stop_loss_applied` 事件。
7. 排队 24 小时没人领：作废，原样重出一张（只重出一次，免得插件一直不在时每天自动出一张）。

## 4. 与 WP315 的对接

- **插件事件**：`server.ts` 里 `createAdsActionsService({ onEvent })` 现在同时交给 Reddit（WP329）和广告账本（本单）。广告账本**只认自己进过队的活**（按 job id 找账本那一条），WP315 的 `export_report` 活、它的 `report` 下载一概不碰——WP315 在同一个 `onEvent` 里再加一行自己的处理就行（合并时这一处会有相邻冲突，两行都留）。
- **导出文件**：本单读插件报上来的下载路径只认 `.csv / .tsv / .txt`、≤ 20MB，解析用 WP314 的 `decodeExportBytes` + `parseAdsExport`；WP315 补的报表列名别名（619）会让本单的读回核对也跟着认得更多列。
- **止损**：WP315 日报里「要不要止损」出的是 `pause_ads` 卡（`ads-service.pauseCampaign`，`reason: 'stop_loss'`）——判据成立就 L3 自动批，本单接着执行（截不到也先停、前后导出作证、记止损记录）。WP315 不用另接执行。
- **读额度（555）**：本单 Meta 改已有没有改前导出时会自动排一件只读导出（`export_snapshot`），和 WP315 每天的报表导出共用「每账户每天读 ≤ 2」那本账。
- **账户**：两单都用广告库里的 `AdAccount.external_id` 当插件账户编号（Google 的 `ocid` 没有，WP313 已列风险）。

## 7. 自主做的决定（白话）

1. **进了队就算「已施行」**，真正的结局记广告账本、另出提醒——照 WP329 Reddit。回「不确定」会让对账把整个出站停住。
2. **多张表一张做完再进下一张**，中间退回就不传后面的；改前导出只导一次、读回导出只在最后。
3. **上传表的字节放在卡上**（base64），执行前按卡上的字节再算指纹——审批绑的就是卡上那一份，人下载的也是这一份，不另存一个仓库。
4. **Meta 用粘贴文字**（`.tsv`），卡上给人下载的也是它（WP313 / WP314 约定「Meta 优先 paste_text」）。
5. **再确认多一处**：职责页「广告改动」那一块给投放这条职责自己点（新路由 `POST /v1/ads/ledger/:id/confirm`，权限是 `ad_account` 的 stage），不用老板那把 `policy` 权限。
6. **首页提醒不是卡**：等你确认 / 退回 / 读回对不上进告警区（`system_alert`），点了去职责页那一块；决定在那一块里点。
7. **Google 表单改动的撤销是反着点一遍**（暂停 ↔ 启用、预算改回原数），没走「更改历史」（多一套选择器、没核过）；Google 上传用一次性撤销，倒着撤；撤成了才记「撤过了」。
8. **新建 campaign 的老卡**也带一张上传表（Google 能出；Meta 新系列还缺广告组那一层，表出不了就在卡上照实写「批了插件也建不了」，执行时照实失败，不假装做了）。
9. **改出价、换素材第一期不由插件执行**（552：改出价不点表单，WP314 也没有改出价的表；换素材走新建广告），这两种卡批了照旧走原来那条路。
10. **托管实例不装**：没有插件通道就一律掉回原来那条路，磨合期也不适用。
11. **截图 / 账本只存本机**（`<品牌目录>/ads-ledger/` 与 WP313 的截图目录），180 天到期按名字逐个删；没做云同步。
12. Run 工具只给 Google / Meta 两条（插件第一期只接这两家）。
