# WP252 报告：一台电脑多个品牌共用连接器时，连接按品牌隔开（决策 125）+ 上游名单补 npm 运行时

分支 `wp/252-conn`（worktree `agentsws-wt/wp252-conn`），Claude 子代理。

## 0. 一句话

一台电脑一个 OpenConnector、INMO 和 Rollout 都连 Shopify 时，现在**各是各的一条**：新建连接在上游叫
`default--<品牌段>`，每个品牌只看得见、只用得了、只签得出自己那条；老的 `default` 连接归启动品牌，名字一个不改。
WP252 之前两个品牌都用 `default` 连过同一家服务的，升级后第一次启动自动补记归属：归启动品牌（提醒它点一次「测试」核对账号），
另一个品牌看到一行「请重新连接」。上游名单登记了 npm 那条运行时（钉 1.8.0 + 锁文件），`check-upstreams` 能对账，docs/42 写了升级步骤。

## 2. 迁移说明

- **在哪、什么时候**：服务进程启动时、任何品牌列连接之前，开 `<数据目录>/connect-owners.json`（启动品牌的目录，没有就建），
  扫启动品牌的 `connect-adapter.json` 与 `brands/<ws>/connect-adapter.json`，把记过的「连接 id → 品牌」补记进来。
- **不动什么**：上游一条连接都不改名、不删、不重写凭据；各品牌老的 `connect-adapter.json` 不改。
- **规则**：只有一个品牌记过 → 归它；两个以上品牌都记过同一条（都用 `default` 连了同一家服务，上游是同一条）→ 归启动品牌，
  其余品牌各留一条「请重新连接」；启动品牌没记过它时归 workspace id 排序最前的那个（确定性，见 §4 第 2 条）。
  谁都没记过的老连接不在启动时处理：启动品牌第一次列到时认领（不带品牌段的才认）。
- **幂等**：已经有主的一条跳过、冲突不重复记；连跑两次 / 重启后再跑，`connect-owners.json` 逐字节不变（有测试）。
- **真机上会发生什么**（Fable 10-07 的数据：INMO `ws_0llwvcm2` 是启动品牌、Rollout `ws_19cxxs7l` 后加）：
  - 两个品牌都还没连 Shopify → 什么都不发生；之后 Rollout 连正式店会是上游的 `default--ws_19cxxs7l`，INMO 的连接不受影响。
  - 只有 INMO 连过 → 归 INMO，Rollout 看不见它（以前看得见）。
  - 两个都用 `default` 连过 → 上游其实只有一条、凭据是后连那家的；归 INMO（黄条「请核对账号」），Rollout 一行「请重新连接」，
    Rollout 再连一次就是自己的一条。**INMO 那条若测出来是 Rollout 的店，INMO 要断开重连**。
- **回退**：删掉 `connect-owners.json` 即回到「重新迁移」的状态（下次启动重新补记）；老版本不认这个文件，不受影响。

## 4. 要 Luoye 定的事（建议附后）

1. **启动品牌新建的连接也带品牌段**（不再叫 `default`；它已有的老 `default` 照用不改名）。这样「哪条是谁的」只靠名字也认得出，归属表丢了也找得回。**建议：保持。**
2. **两个都不是启动品牌的品牌用 `default` 连过同一条**（现在只有 INMO + Rollout 两个品牌，INMO 是启动品牌，碰不到）：归 workspace id 排序最前的那个，另一个提示重新连接。**建议：保持（真碰到时留下那边也有「请核对账号」提醒）。**
3. **留下的那条可能存着对方的账号**（上游同名 PUT 是就地覆盖的，后连那家的凭据把先连的顶掉了）：我们只提醒启动品牌「点一次测试核对账号，不是本品牌的就断开重连」，不自动断。**建议：保持，不自动断——断了 INMO 的数据面板会立刻空掉，让人看一眼再决定。**
4. **给 Rollout 连正式 Shopify 店的时机**：**建议：等这一单合并、真机装上新版后再连**；新版之前连的会和 INMO 共用 `default` 那个名字（就是老问题本身）。

## 5. 偏离

- 派工单没点名界面，但「另一品牌提示请重新连接」要有地方出，所以 `ConnectionView` 加了可选 `brand_conflict`、连接页那一行加一条黄条（沿用 WP44「老办法接的」那条黄条的样子），i18n 只加 3 个键（`connections.brand_conflict.*`）。
- 「留下的那条」也加了一句核对提醒（派工单没要）：老问题里上游那条的凭据是后连那家的，归启动品牌后不提醒的话，INMO 可能拿着 Rollout 的店在跑。
- `upstreams.yml` 加了两个新字段（`npm_lock_file` / `npm_pin_in`），`check-upstreams` 的校验跟着扩了一项（⑥）；没有改已有字段的语义。
- 没碰 WP251 的文件（onboarding / identity / org / AI 上下文）；`server.ts` 只在 `assembleBrand` 前后加了几行装配。

## 6. 未完成 / 给 Fable 的真机复测点

- **上游连接名的字符限制没在真 runtime 上验过**：这台机器上没有 1.8.0 的包（WP247 装在 scratchpad 里、用完删了），按「不下载不可信来源 / 不连远程」没去拉。
  名字只用了 `[a-z0-9_-]` 加用户别名（别名本来就原样透传给上游），风险低。**真机第一次给 Rollout 连 Shopify 时看一眼**：
  连接页出现那一条、`<数据目录>/connect-owners.json` 里它记在 `ws_19cxxs7l` 名下、INMO 的连接页看不见它；若上游拒收这个名字（400），回报一下，换分隔符是一行的事（`BRAND_NAME_SEPARATOR`）。
- 真机升级后第一次启动：`connect-owners.json` 出现；两个品牌之前若都连过 Shopify，按 §2 的「真机上会发生什么」核对。
- Docker 档（`scripts/dev-real.sh`）同样生效（一台机一个 runtime 的形态一样），没单独在真容器上跑。
