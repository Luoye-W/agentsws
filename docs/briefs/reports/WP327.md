## 1 版本目录 + `current` 联接（决策 630 / 730）

```
%LOCALAPPDATA%\Programs\agentsws\
  current\          目录联接 → 下面某一版（开始菜单 / 桌面 / 任务栏固定 / 开机自启 / 卸载图标都指它）
  app-0.2.1\        上一版（留着回滚）
  app-0.2.2\        当前
  Uninstall Agents 工坊.exe、layout.json、agentsws-install.txt
```

- **安装器**（`apps/desktop/build/installer.nsh`，electron-builder 自动 include）：
  - 首装 / 走安装程序的更新：NSIS 照常把文件解到根上，`customInstall` 再把**这一版的条目**（afterPack 按 win-unpacked 根生成 `agentsws-app-entries.nsh`，只挪我们自己的文件）挪进 `app-<版本>`、`mklink /J` 建 `current`、把开始菜单 / 桌面 / 任务栏固定的快捷方式与卸载图标改指 `current\agentsws.exe`、写一份卸载登记位置。**建不了联接（FAT32 / exFAT / 网络盘）就挪回去照旧平铺**，应用认出平铺就走老路。
  - 「只摆不装」：`Setup.exe /S --agentsws-stage /D=<根>` 在 `.onInit` 里只把这一版解到 `app-<版本>.part` 再改名、写记号，**不结束进程、不卸旧版、不动登记与快捷方式**。复用同一个安装包——发版产物、`latest.yml`、差分下载都不变。
  - 卸载：先删联接再删整个目录；作为「安装程序更新前卸旧版」被调用时只删联接（旧版本目录留作上一版）。
- **应用**（`apps/desktop/src/fast-update.ts` + `layout-fs.ts`，接在 `main.ts`）：
  1. 后台准备：electron-updater 照旧下载、校验 sha512 → 低优先级跑「只摆不装」→ 核对 exe / 记号 / 版本 → 用**新版自带的 Node** 把新版服务入口 import 一遍。都过了按钮才变「重启并更新」（进度条前 90% 下载、后 10% 准备）。准备不好就照旧走安装程序（日志写原因）。
  2. 点「重启并更新」：「正在更新」小窗 → 停服务进程 → 藏窗口与托盘、放开单实例锁 → `current` 改指新版 → 起新版 → 旧版在后台等新版写「起来了」（或新版服务报新版本号），最多 60 秒 → 旧版退出。
  3. 回滚：60 秒没等到、或新版还没报起来就退了 → 结束新版进程树、`current` 指回旧版、记一笔、重开旧版；重开的旧版弹一句「x.y.z 没能打开，已回到原来的版本，数据都在」。
  4. 新版服务第一次正常：确认切换、把卸载登记里的版本号改成新版；3 分钟后低优先级删掉更早的版本目录（留当前 + 上一版；正在准备的那一版不删）。
  5. 开机自启指 `current\agentsws.exe`（版本目录会被清理）。单实例锁、AppUserModelId 不变；CI 核过切换后再起一次立刻退出。
- **回滚演练**：用户数据目录放 `update-drill.json`（`{"break": "<版本>"}`），那一版启动时用掉它、不起服务进程。只有 CI 用，正常用户不会有这个文件。

## 2 服务进程打包瘦身（Luoye 10-14「安装包为什么这么大」）

**为什么大 / 慢**：asar 关着（服务进程跑在随包 Node 上），安装目录 1.8 万个小文件——业务代码与依赖、dsh / cordis 那七十多个包、随包 npm 2009 个、工作台构建吐出的类型声明 572 个。装 / 更新 / 杀毒扫描的时间几乎和文件数成正比。

**做了什么**（`apps/desktop/scripts/bundle-app.mjs`，afterPack 第 ⑪ 步）：
- 用 esbuild 把桌面壳主进程、服务进程、**dsh / cordis 那一整串**打进 `<resources>/app/bundle/`：多入口 + 共用分块，同一个源文件只有一份（cordis 按包名动态加载插件、拿到的也是同一份实例）。入口 = 每个 `@agentsws/*` / `@deepseek-ai/*` 包 `exports` / `bin` 里登记的每个具体 JS 路径，原位置换成一行「桩」——按名字 import、按 bin 起 dsh CLI、桌面壳 `import('@agentsws/server')`、按路径 spawn 服务进程，照常落到桩上。
- 每个模块里的 `import.meta.url / dirname / filename / main / resolve`、CJS 的 `__dirname / __filename` 改写成**它原来所在文件**的位置；算出来的 `import(x)` 相对路径按原位置解析。**字符串与行注释里的不改**（CI 第二次就撞上：桌面壳交给 `node -e` 的脚本字符串被改坏）。
- 不打的（整串留在 node_modules）：原生模块（better-sqlite3 / sharp / koffi / node-pty 及其依赖）、playwright、electron-updater、被 `await import()` 的 CommonJS 包（Node 才给得出具名导出；CI 实测 undici 的 `getGlobalDispatcher` 打进去会丢）、运行时按名字 require / resolve 的包（如 Lark SDK、bonjour、open）。按位置读数据 / 起 worker / 给浏览器的静态资源（dsh web 前端、inspector devtools）原样留下。
- **dsh / cordis 登记 `./src/*` 的那类**：核过可以打——它们实际被加载的都是 `lib/` 里登记的具体入口；`./src/*` 通配不做入口（运行时没人按它加载），源文件留着不删。
- 打完把 bundle 每个文件解析一遍（撞名之类当场报错），再走原来的冒烟（捆绑 Node import 服务入口、开内存库、找钉版本表）。
- **npm**：安装包里只带 npm 的 tgz + `npm.json`（版本与 sha512），服务进程第一次要 npm 时校验后解到自己的工具目录（不联网）；解开版不再进包（-2009 个文件）。
- 工作台构建吐出的 `.d.ts`（572 个）不进包。

**还剩 7.4 千个文件里有什么**（mac 包同口径 7,394 个）：bundle 约 1,140 个 + 桩约 720 个；dsh inspector 的 devtools 静态站 779 个；dsh web 前端 132 个；原生模块与 Playwright、electron-updater 那几串约 900 个；我们自己按位置读的数据（角色 / 技能 / 本体等）约 300 个；dsh 各包的 package.json / 说明 / 图标 / 语言包约 1,500 个；Electron 本体与工作台约 900 个。到不了「几百个」——要再往下就得动 dsh 自带的静态资源（见决策 748 / 749）。

## 3 分两版发的注意事项（决策 745）

- **第一版（带本单的那一版，比如 beta.6）**：老用户（beta.5 及以前，平铺）点更新时，跑的是**老版本里的老更新代码**——照旧下载安装包、静默装（NSIS）。新安装包在装的时候顺手迁移成版本目录布局。这一跳仍要 **1.5–2 分钟**（CI：105 秒；有 beta.5 自带的「正在更新」小窗吗？beta.5 没有 WP325 的修复，小窗可能不出现），但比以前的 3 分多钟快（安装目录文件少了 6 成）。
- **第二版起（beta.6 → beta.7）**：新代码在跑，后台准备好，「重启并更新」只切换，**几秒**。
- 所以 beta.6 要尽早发、发完再发一版 beta.7 才看得到效果；发版说明里可以写「这次更新会慢一点，下次起就快了」。
- 新装用户直接就是版本目录布局。
- 磁盘多占上一版一份（约 650 MB），新版起来 3 分钟后清掉更早的。

## 5 自主做的决定（白话）

1. **后台准备复用同一个安装包**（加一个「只摆不装」开关），不另出 zip：发版流程、下载站、差分下载一样都不用改。代价：安装包里 app 压缩包要被 NSIS 的数据块去重认出来（CI 产物大小没变大，见第 0 节）。
2. **旧版在后台等新版**（不是立刻退）：窗口、托盘先藏起来、单实例锁先放开，用户看到的是新版几乎立刻出来；旧版等新版报「起来了」才退。这样回滚逻辑在我们自己的 TypeScript 里（有单测），不依赖 PowerShell 小窗。
3. **60 秒回滚**按派工单；认「起来了」两种都算：新版写的确认、或新版服务报新版本号。
4. **清理**留当前 + 上一版；比当前新的（回滚剩下的）只在没在准备更新时删。
5. bundle 的删除策略保守：拿不准的（会按自己位置找文件的、运行时按名字加载的）整包留下；dsh 的 inspector 静态站整棵留下（见 748）。
6. CI 的迁移段用 **GitHub Releases 上真发过的 beta.5**（平铺）做老版本，把它的更新源改指本机——比用本分支再打一个「假老版本」更真。
