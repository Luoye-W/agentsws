# WP258 报告：建站岗位登录 Shopify 后自动取店铺地址，不再让用户手填

分支 `wp/258-store`（worktree `agentsws-wt/wp258-store`），Claude 子代理。没推送，没合并。

## 0. 一句话

一键登录 Shopify 成功后，服务端用这个品牌自己的 CLI 会话跑 `shopify store list --json`，看这个账号下有几家店：
- **只有一家**：自动定下来（`store_source: 'cli'`），岗位页那一格不再出现。
- **有好几家**：给一个下拉框（店名 · 域名 · 套餐），选了就存。选好之后还留一行「改哪家店」，可以换。官网里读到的 `xxx.myshopify.com` 如果和其中一家对得上，就默认选那家。
- **一家都没有**：照实说「这个 Shopify 账号下没有店铺」，给「换个账号登录」「去 Shopify 开店」两个按钮。
- **命令没跑成**：退回手填，旁边加一个「再找一次」。

手填一直留着兜底（「都不是？手动填」），手填过的地址永远不会被自动覆盖。

## 1. 核对 CLI 4.8.5（`npm pack @shopify/cli@4.8.5` 到临时目录看源码，没有全局安装）

- `store list` 的参数：`--json`、`--organization-id`（整数，env `SHOPIFY_FLAG_ORGANIZATION_ID`）、`--type`，**没有 `--auth-alias`**。
  - 输出：`{ stores: [{ id, store, createdAt, organizationId, organizationName, name, type, plan }], organization: { id, name }, notice?, truncated? }`
  - 只列状态为 active 的店，最多 250 家。
- **账号属于好几个组织**，并且在非交互环境（我们带 `CI=1`）里运行、又没带 `--organization-id` 时，会直接报错：「An organization ID is required to list stores non-interactively.」
  - 账号下没有组织：返回 `{ stores: [] }`。
  - 会话里认不出账号：返回 `stores: []`，外加 `notice: "Couldn't resolve a Shopify account…"`。
- `organization list --json` 返回 `{ organizations: [{ id, gid, name }] }`。没有组织的时候返回 `{ organizations: [] }`，不报错。

我们的顺序是：
1. 先跑 `store list --json`。只有一个组织时，这一条命令就够了，Fable 真机上就是这种情况。
2. 如果 CLI 说要组织 id，再跑 `organization list --json`。
3. 然后逐个组织跑 `store list --json --organization-id <纯数字>`，最多 10 个组织。

## 3. 自主做的决定（白话）

- **先列店，要组织 id 时再列组织**：多数商家只有一个组织，一条命令就够。`organization list` 走的是开发者平台那一路，商家账号在那边可能看不到组织，所以不拿它当第一步。
- **官网对上了就直接定下来，不只是在下拉框里预选**：派工单写的是「默认选它」。按「能自动拿到的不让用户填」，对上了就直接存下（`store_source: 'cli'`），那一行不再拦人。下拉框没有消失，变成一行「改哪家店」，选错了随时能换。
- **只有一家但和官网对不上，照样定这一家**：派工单写的是「只有一家就自动定」。这种情况多半是登错了账号，我列进了 §4 第 2 条。
- **从下拉框选的店，换账号后也会重新判断**：重新登录后，如果选过的那家不在新账号下，就清掉重新定。还在就不动。手填的不在这个规则里。
- **没找成不每次重试**：存下来，5 分钟后或者点「再找一次」才再跑，免得岗位页每 2 秒刷新一次就起一个 CLI 进程。
- **事件里只记个数**（几家店、有没有和官网对上），不记店名和域名。命令原文不进界面。
- **`shopify_domain` 不进设置页**：它是机器读来的线索，不是用户说过的话，所以只在档案里存一格，不显示。

## 4. 要 Luoye 定的事（附建议）

1. **Rollout 现在那条店铺地址算「手填」**：10-07 Fable 是经 `PUT /v1/site/theme/store` 填的，按规则不会被自动覆盖，所以 Rollout 真机上看不到自动找店。**建议：保持不动**，地址本来就是对的，而且「手填不覆盖」是派工单的硬规矩。真机验收换 INMO，或者在 Rollout 里先清掉 `site-theme.json` 的 `store` 再登一次。
2. **账号下只有一家，但和官网读到的不是同一家**：现在照派工单，自动定这唯一一家。**建议：改成不自动定，在那一行提示「官网那家（xxx）不在这个账号下，要换个账号登录吗」**，因为多半是登错了账号。要改的话下一单很小。
3. **账号下超过 250 家店（代理商账号）**：CLI 只返回最近的 250 家，我们照单全列。**建议：先不管**，品牌用户碰不到。
4. **「去 Shopify 开店」打开 `https://www.shopify.com/`**：**建议就用它**；以后有推荐链接再换。

## 5. 测试结果

- `apps/server/test/wp258-store-lookup.test.ts`（19 条，假 `shopify` 是真脚本、真子进程），覆盖：
  - 一家：一条命令就定下；命令环境里有 `CI` 和本品牌会话，没有店铺、令牌、`AGENTSWS_SECRETS_KEY`

  - 多家：下拉框、选了就存、选不在清单里的店会被拒
  - 和官网对上就默认选中；官网那家不在账号下就不瞎选

  - 老版本 CLI 不认识这条命令；会话过期回到登录
  - 没登录或连了店时，一条找店命令都不跑
  - 手填不覆盖（包括 WP253 存下的老地址）；「都不是？手动填」
