## 2. 查出并修掉的问题

**所有平台都有、这次本机打包才暴露的（WP111 起的安装包装好就不能用）：**

1. **安装包里没有工作台**。服务进程只在给了 `AGENTSWS_STATIC_DIR` 时托管工作台，桌面壳从没给过、包里也没带——装好点「打开工作台」是 404。现在带进 `<resources>/workstation` 并传下去；afterPack 缺了就失败。本机 mac 包已验证首页能开（截图见 §8）。
2. **sharp 的平台二进制一直没进包**（`@img/sharp-<平台>` 是 optionalDependencies，补依赖时解析不到）。新加的冒烟当场抓到；现在从 pnpm 的 `.pnpm/node_modules` 补。
3. **mac 写死了两个架构**：`--mac --arm64` 也会去打 x64、因为没有 x64 的捆绑 Node 而失败——WP111 的 release 矩阵原本就会挂。
4. **只有 dmg 时 electron-builder 不写 `latest-mac.yml`**，mac 的「有新版」提示没东西可读。加了 zip 目标。

**Windows 特有的：**

5. **停不干净**（最要紧）：Windows 没有 SIGTERM，`kill()` 就是直接结束，服务进程的收尾（关场景、关库）永远跑不到，它起的 dsh 场景 `node.exe` 变孤儿、锁住安装目录 → 更新 / 卸载「文件被占用」。现在壳**关 stdin 请服务进程收尾**（服务进程认 `AGENTSWS_STOP_ON_STDIN_END=1`），8 秒没退再 `taskkill /PID … /T /F` 按进程树强杀；服务进程停场景也按树结束。
6. **黑窗口**：服务进程没控制台，它再起的 headless dsh、git、shopify、cua-driver、bsk 没加 `windowsHide`，每跑一次弹一个黑窗口。都加上了。解包改用 `%SystemRoot%\System32\tar.exe`（PATH 上要是先找到 Git 带的 GNU tar，不认 zip 还把 `C:` 当主机名）。
7. **子进程环境变量不全**：补 `PATHEXT`、`ProgramFiles*`、`ProgramData`、`SystemDrive`、`HOMEDRIVE/HOMEPATH`、`USERNAME`、`COMPUTERNAME` 等与系统代理（国内网络常见）；headless 子进程白名单补 `APPDATA/LOCALAPPDATA/USERPROFILE/windir/PATHEXT`。密钥类照样不传（有测试）。
8. **工作用浏览器拿到的是空环境**，且被按「隐藏窗口」起——现在给白名单环境、按有窗口程序起。
9. **服务进程入口判定**：只比 URL，遇到 8.3 短名（中文用户名常见）或盘符大小写不同就**直接退出 0**、被壳反复重启。改为再按真实路径比（Windows 不分大小写）。
10. **工作目录**：服务进程继承 Electron 的 cwd，开机自启时是 `C:\Windows\System32`。固定为用户数据目录。
11. **托盘**：mac 的黑色 template 图在 Windows 深色任务栏上看不见 → 染成品牌青绿；左键点托盘没反应 → 弹菜单；没设 AppUserModelId → 通知可能不归「Agents 工坊」；窗口挂着 Electron 默认 File/Edit/View 菜单 → 去掉。
12. 逐项核实过、本来就对的：数据目录 `%APPDATA%\agentsws`（不在安装目录，升级 / 卸载都不碰）；单实例锁；服务进程、dsh 场景、浏览器调试口都只听 `127.0.0.1`（不弹防火墙；CI 里用 `Get-NetTCPConnection` 再查一遍）；DPAPI 加密本机密钥；捆绑 Node 的 `node.exe` 路径；dsh 与官方场景由捆绑 `node.exe` 直接跑 `bin.js`，不经 `.cmd`、不靠 PATH，`DSH_HOME` 在 `%APPDATA%\agentsws\dsh`；**连接器不需要 Docker**：桌面版不起 OpenConnector，本机凭据库那 23 张卡照常用，只有标「需要 Docker（可选）」的 6 张要用户自己装 Docker Desktop（与 mac 一样）。

**没修、写清楚的：**

- **AI 的「跑命令」工具在 Windows 上是 `bash -c`**（`dsh-bash-sandbox`），没装 Git Bash / WSL 就跑不了（`bash.exe` 可能是 WSL 启动器）。官方有 `dsh-pwsh-local` 执行器，但我们这层有凭据注入、沙箱、门禁，换执行器不小，建议另开一单。
- **长路径**：没法在 mac 上量 Windows 安装目录；CI 作业会打印最长的 5 条、≥260 失败。
- shopify CLI 在 Windows 上是 `shopify.cmd`，不经 shell 起会报「没装」；Dev MCP 的 `npx` 同理（默认关）。等 WP216 那条线一起改。
- `reg query` 输出按 UTF-8 读（实际是 GBK），中文安装路径的官方桌面端探测会乱码（有 LOCALAPPDATA 兜底）。
- Windows 注销 / 关机时，`before-quit` 的「官方场景还开着」确认框可能挡一下（`powerMonitor shutdown` 只在 mac / Linux 触发）。

## 7. 偏离

- **release 不再打 Linux AppImage**：Luoye 10-05 的分工只说 Windows / mac；Linux 包没人用、也没地方放（downloads.json 没有 Linux 项）。`updatePolicy` 的 Linux 档留着。
- **Intel mac 用 `macos-15-intel`**：`macos-13` runner 已下线。
- **NSIS 差分包从关改成开**：WP111 关它是为了「宁可整包」；electron-updater 差分失败会自己退回整包、下完一律校 sha512，这次照工作单要求打开。
- **两份 workflow 的「Windows 真跑」是同一个脚本**：release 里 Windows 包真跑不过就不发（比工作单多一步，防止发出装不上的包）。
- **工作台按钮放在「场景」与账号块之间**（账号区正上方），不是左栏最上面。
- **托盘也加了下载 / 重启并更新**：这个应用平时没有窗口，不开工作台的人也该看得见。
- 没做「两个真实版本之间点了更新」的端到端（要在 CI 里打两次包、起本地下载站）；更新逻辑由替身更新源单测覆盖四条主路。建议下一单把它加进 `desktop-windows.yml`。
