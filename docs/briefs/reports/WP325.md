# WP325 报告：「正在更新」小窗在 CI 上没起来（WP319 遗留）+ 决策 630 的方案

分支 `wp/325-splashfix`（worktree `../agentsws-wt/wp325-splashfix`）。桌面包 vitest 46 个文件 606 条全过、biome 过。本单按协调方许可 push 了这个分支、在它上面跑了 `desktop-windows.yml`；没碰 main、没打 tag、没发版。

## 1 小窗为什么没被看到、改了什么

**现象**（main 上 run 38548057345，update-e2e）：「点了『重启并更新』10 秒内没看到『正在更新』小窗」。旧版 N 的 `desktop.log` 里有「「正在更新」小窗起了 to=0.0.1-ci.25」，「正在更新」单也在——说明壳那一侧写了单、起了进程，但 10 秒内进程表里找不到这个 PowerShell。

**根因（真机实测确认）**：桌面壳用 Node 的 `spawn(powershell.exe, …, { detached: true })` 起小窗。`detached` 在 Windows 上是 `DETACHED_PROCESS`——**PowerShell 5.1 没有控制台时一行脚本都不跑，退出码 0，120–200 毫秒就退了**。在 Windows 测试机上只用临时目录做的对照（`resources\node\node.exe` 起一个只写一个文件的脚本）：

| 起法 | 结果 |
|---|---|
| 不脱离，管道收输出 | 脚本跑了（输出 `ran-script`） |
| `detached: true`（加不加 `-WindowStyle Hidden`、`windowsHide` 四种组合） | 都是 0 退出、120–200 ms、脚本没跑 |
| `conhost --headless` 包一层 | 同样没跑 |
| 脱离起 `cmd /d /s /c "start "" /min powershell … -File …"` | 脚本跑了，**父进程退出后还活着** |

第一次 CI 修法（`6994b87d`，改 Application.Run + 心跳）在 run 38555931105 上照样「没起来」：脚本在临时目录里、桌面壳记了 pid 2812，但一笔心跳都没有——正好印证「脚本根本没开始跑」，不是 ShowDialog 的问题。不脱离起又不行：Node 把非脱离子进程放进「父进程退出即杀」的 job，桌面壳一退小窗就没了。

**改了什么**：
- `6994b87d`：小窗改用 `[Application]::Run($form)`（`ShowDialog` 在没有交互桌面时会抛）、`$ErrorActionPreference = 'Stop'` + try/catch，画不出来就在后台照样等；小窗自己写**心跳** `update-splash.json`（`starting` / `shown` / `headless` / `closed`、错误、是否交互会话、会话号），新版启动时把小窗状态记进「更新用时」；PowerShell 用系统目录绝对路径；`win-update-e2e.mjs` 改按心跳核对（点了 15 秒内有心跳 → N 退出、安装中还活着 → 新版起来后 `closed`、单子收掉）。
- `8fe2f3ed`：小窗的输出写 `logs/update-splash.log`、启动器退出记退出码；e2e 没起来时把这些带出来。
- **根因修复**（`ecd7f96e`）：经 `cmd /d /s /c "start "" /min <PowerShell> … -File <脚本>"` 起（`viaCmdStart`，`windowsVerbatimArguments`）。PowerShell 拿到一个新的最小化控制台，起来就按 `-WindowStyle Hidden` 藏掉；cmd 自己马上退，PowerShell 不在任何 job 里，桌面壳退了它照样活着。真机 session 0（SSH，无交互桌面）跑真代码：心跳 `starting` → `shown` → 删掉单子 0.5 秒内 `closed`。
- 代价：交互桌面上 PowerShell 刚起来那一下任务栏可能闪一个最小化的控制台（不到一秒）。真桌面上的样子要在下一版真机上看一眼（SSH 进去是 session 0，看不到桌面）。

## 2 决策 630 的可行方案：旧版开着时把新版装到旁边目录，重启只切换

Luoye 10-14 定：目标是「旧版关掉 → 新版打开」的空窗要短，不要求整个更新 10 秒内。现在空窗 = NSIS 静默卸旧装新（CI 实测 3 分半；瘦身后静默装 146 秒、17,949 个文件），要把这几分钟挪到「旧版还开着」的时候做。

### 推荐方案：版本目录 + 目录联接（junction）切换，仍用 NSIS 做首次安装

```
%LOCALAPPDATA%\Programs\agentsws\
  current\          ← 目录联接（junction），指向下面某一版；快捷方式、开机启动、卸载登记都指它
  app-0.2.0-beta.6\ ← 一版一整套（Electron + resources）
  app-0.2.0-beta.7\ ← 后台准备好的新版
  Uninstall Agents 工坊.exe
```

1. **后台准备**（旧版开着、用户照常用）：下载新版的整包（electron-builder 加一个 Windows `zip` 目标，或继续用 NSIS 包里的 `app-64.7z`；差分下载照旧靠 blockmap），校验 sha512，低优先级解到 `app-<新版>\`（杀毒逐个扫也在这时候，用户无感）；解完用随包 Node 冒烟一次（import 服务入口、跑 npm --version），过了才算「准备好」。
2. **点「重启并更新」**：停服务进程 → 旧版退出 → 把 `current` 联接改指新版（删联接 + 建联接，普通用户权限就能做，毫秒级）→ 起 `current\agentsws.exe --updated`。空窗 ≈ 旧版退出（1–2 秒）+ 新版冷启动到窗口出来（几秒），估计 **5–10 秒**，期间「正在更新」小窗照旧挂着。
3. **回滚**：新版 60 秒内服务不健康 → 联接改回旧版、起旧版、记一条失败；旧版目录保留一版，再下一次更新成功后删。
4. **NSIS 那一侧**：首次安装装到 `app-<版本>\` 并建 `current` 联接（`customInstall` 宏）；卸载时删联接与所有 `app-*`（`customRemoveFiles`）；快捷方式 / 开机启动 / 协议注册都指 `current\agentsws.exe`。之后的应用内更新不再跑 NSIS；只有大改动（安装器本身要变）才退回「下载整个安装包、静默装」那条老路。
5. **迁移**：现在的平铺布局（`agentsws\agentsws.exe` 直接在根上）第一次走新更新时，由那一版的 NSIS 静默装（老路）完成一次性迁移：把根上的老文件收走、建 `app-<版本>` + `current`。所以要分两步发：先发一版「会迁移的安装器 + 会准备旁边目录的更新器」，再下一版起空窗才变短。

**要核实 / 风险**：① Electron 单实例锁、`AppUserModelId`、任务栏固定、开机启动项在联接切换后是否照常（预计照常：路径都走 `current`）；② 磁盘多占一版（约 700 MB），清理策略要写死；③ 杀毒偶尔锁住新目录里的文件导致切换后起不来——回滚兜底；④ electron-updater 的 `NsisUpdater` 不再用，要自己写「下载整包 + 校验 + 解压 + 冒烟」那一段（下载 / 校验 / 差分可复用 electron-updater 的底层 `builder-util-runtime` 或 `DifferentialDownloader`）；⑤ mac 不受影响（仍是「只提示」）。

**工作量**：约 **4–6 个工作日**（一单）：更新器后台准备与切换 / 回滚 2 天；NSIS 首装 / 卸载 / 迁移宏 1–1.5 天（只能在 Windows CI 上验）；CI 两段 e2e（老布局 → 迁移、新布局 → 切换，量空窗秒数）1 天；文档与真机验收 0.5 天。

### 备选：换 Squirrel.Windows（electron-builder 的 `squirrel` 目标）

Squirrel 本身就是「版本目录 + 后台准备 + 重启切换」，现成的。不推荐当主路：要从 NSIS 迁过去（老用户得先装一次新安装器，或我们写迁移）、只支持按用户安装、不能选安装目录、社区维护已经很弱、差分包与我们自有下载站 / R2 那套 `latest.yml` 流程不兼容，返工面比推荐方案大。

| 38558028657 | 取消 | 只加诊断的那一次，真机已经复现，没等它跑完 |
| 38560129134 | update-e2e 红 | 改成 cmd start 后小窗 **3–5 秒内起来了**（交互会话 2），但 e2e 在 `app.close()` 之后才看「安装中还活着」——Playwright 的 close 在 N 已退出后挂了 3 分半，等它回来新版早起来、小窗已正常关掉。是测试的毛病，改成 close 之前看 |
| **38562661135** | **两个作业全绿** | 下表 |

**38562661135 的数**（Windows CI，安装目录名带中文和空格）：

| 项 | 数 |
|---|---|
| afterPack 瘦身 | 删 3,237 个文件（30 MB）：安装目录 21,231 → **17,994 个文件、710 MB** |
| 全新静默装 | **189 秒**；装好后 17,992 个文件、707.8 MB |
| 点「重启并更新」→ 小窗起来 | **约 3 秒**（心跳 `starting`，交互会话 2；真机上量的是 0.76 秒起来、1.06 秒画出窗口） |
| N 退出后 2 秒 | 小窗**还在**（`shown`，窗口画出来了） |
| 点「重启并更新」→ 新版桌面壳启动（小窗关掉那一刻） | **193 秒** |
| 点「重启并更新」→ 新版服务健康 | **202 秒** |
| 小窗 | 新版起来后**关了、单子收掉了**；数据都在；安装目录里是 N+1 |

对照 WP319 之前（run 37922723813）：N 退出 → 新版健康 215 秒、全新静默装 186 秒。瘦身只少了 15% 的文件，装的时间几乎没变（CI 机器每次波动也有 ±10 秒），**空窗还是 3 分多钟**——现在全程有小窗挂着、不再「像被删了」，但要真变短得靠第 2 节的方案。

另外：CI 的 runner **是有交互会话的**（会话 2），所以第 1 节里「ShowDialog 在无交互桌面会抛」不是 CI 上的原因；改 Application.Run 只是顺手的防御。
