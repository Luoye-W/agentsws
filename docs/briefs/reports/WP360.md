## 0. 一句话

用户选了 Reddit、红人、广告这类要用浏览器插件的岗位，工坊现在**自己先开口**：首次设置第 ④ 步第一项就是「先装好浏览器插件」；岗位页顶上常驻一张装插件卡；第一次在这个岗位说话，AI 先说一句、把装插件那张卡带进对话。装好配上之后，卡自己换成「还差一步」（比如插件里点「连接 Reddit」），做完再接上 Reddit 巡查的方案卡。哪些岗位要插件不写死名单，由岗位定义里的一格声明推出来。

## 1. 哪些岗位命中「需要插件」

每条职责（岗位里的一条活）在定义文件里多一格 `browser_extension: { uses: [...] }`，写明拿插件做什么。岗位要不要插件 = 它那几条职责里有没有写这一格。现在写了的七条：

| 职责 | 拿插件做什么 | 在哪个岗位 |
|---|---|---|
| 自家版运营 `social.reddit` | 读 Reddit（巡查收件箱 / 自家版块）、把批过的回复填进页面 | 社媒运营（默认不勾）、自建的「Reddit 运营」 |
| Reddit 营销 `pr.reddit` | 读别人版里的帖子与版规、把批过的回复填进页面 | 公共关系（默认勾）、自建的「Reddit 运营」 |
| YouTube 红人 / Instagram 红人 / TikTok 红人 | 在这三个平台的页面上看红人、一键收进红人库 | 红人营销（默认勾 YouTube / Instagram） |
| Google 广告 `ads.google` | 在自己的 Google 广告后台执行批过的改动、每天导数据 | 投放 |
| Meta 广告 `ads.meta` | 同上，Meta 后台 | 投放 |

按出厂模板默认勾的职责算：**红人营销、投放、公共关系**这三个岗位命中；社媒运营默认不勾自家版，不命中（勾上就命中）；自建的「Reddit 运营」命中。

没算进来的：Facebook / X 红人（插件没有这两个平台的面板）、TikTok / X 广告（插件动作只做 Google 和 Meta）、客服的社群管理和公关的品牌监控（也挂着 Reddit 连接器，但 Reddit 只是它们十几个渠道里的一个，不靠插件读写——算进来的话整个客服岗位一上来就被要求装插件）。这一条请 Luoye 看一眼（决策 948）。

拼错用途（比如 `redit`）在加载时就报错，不会静默变成「不需要插件」；有一条测试钉住这七条，加一条要在测试里加一行。

## 2. 用户看到的

**首次设置第 ④ 步**（截图 1）：勾了要插件的职责，清单最前面是一张「先装好浏览器插件」：一句为什么（按用途拼，如「这个岗位要靠它读 Reddit、把批过的回复填进页面、在 YouTube / Instagram / TikTok 上收红人」）+ WP345 那块「打开插件文件夹 / 打开 Chrome 扩展页 + 三步小字」+ 配对码。右上「稍后再装」只收起这一屏，不挡「完成」。没勾要插件的职责，这张不出。

**岗位页顶上**（截图 2、4）：
- 要插件、还没配上 → 「先装好浏览器插件」（同一块：一句为什么 + 装 + 配对码）；
- 配上了 → 自己换成一行「插件配上了，还差一步」：Reddit 岗是「在插件里点『连接 Reddit』，并在这个 Chrome 登录品牌号」，投放岗是「在插件里连上 Google / Meta 广告后台」，做完自己打勾（卡每 4 秒问一次）；
- 都连好、方案还没设 → 一个按钮「下一步：Reddit 巡查」（或「下一步：广告账户」），点了出 WP348 那张方案卡，进「要你处理」；
- 再没事 → 整张不画。
- 右上「稍后」：今天（品牌本地日）不再出，同一品牌所有岗位一起收，第二天再出来。新建 / 新分配到这类岗位一样会出。

**第一次在这个岗位说话**（截图 3）：插件还没配上 → 这件事的时间线里先一句「这个岗位要用浏览器插件读 Reddit、把批过的回复填进页面，还没装。在下面这张卡上装好、配个对就行。」，下面就是装插件那张连接卡（少字版：装 + 配对码 + 只连本机那句承诺），卡头写「连上就能用」。然后 AI 照常回你那句话——它不等插件，原话照跑。
- 同一条分配只主动带一次；今天点过「稍后」就不带（下次说话再带）；
- 一个品牌只一张：第二个要插件的岗位第一次说话时，复用已经在等的那张，只说一句「这张卡之前已经出过，在『要你处理』里」；
- 真跑到要插件的那一步（巡查、广告动作），和以前一样会撞上同一张卡、挂上「连好接着做」。

**装完自动接着走**：Reddit 岗——插件刚连上 Reddit 时工坊会先让它看一眼登着哪个号（WP348 就有的那一件）；交回来以后，还没设巡查的品牌**不等人开口**直接出「Reddit 巡查：我打算这样设」方案卡（品牌号就是插件里登着的那个，一天最多一张）。投放岗——不自动出，岗位页那张卡给「下一步：广告账户」按钮（见决策 950）。红人岗——配上就能用，没有下一步。

**系统级打扰**：一个都没有。不弹窗、不发通知，只在这三处画卡。

## 4. 我自己做的决定（白话）

1. **声明写在职责上，不写在岗位上**：岗位可以自建、合并（「Reddit 运营」就是自建的），职责是固定的。岗位要不要插件 = 它的职责并集，一处定义，首次设置 / 岗位页 / 运行三处共用。
2. **用途写成四个词**（reddit / kol / google_ads / meta_ads），不写一句话：界面按词拼说明、按词决定配对后的下一步，中英文都好办。
3. **「配对后自动消失」做成「装的那块消失，换成一行还差一步」**：派工单第 3 条说配对后消失，第 4 条又要接着引导授权和方案卡；我让装 + 配对码那块在配上后立刻消失，同一个位置只剩一行步骤，做完再变成一个按钮，全做完整张不画。
4. **「稍后」记在服务端、全品牌一起收**：派工单要求「同一品牌多个岗位只出一张」，所以收也一起收；记成一条事件、当天查，不加新表。本地日按品牌的时区。
5. **第一次对话不挡原话**：AI 先说一句、带卡，原话照常跑（卡不挂「连好就重跑」，免得配好后同一句话又跑一遍）。真跑到要插件的地方，还是 WP324 那一套：撞上同一张卡、连好接着做。
6. **今天点过稍后，对话里也不带**：「稍后」就是今天别提醒；下次（第二天）说话再带。
7. **Reddit 的方案卡自动出，广告的不自动出**：Reddit 方案卡要的品牌号插件一交回就有了；广告账户编号要等插件领活时在后台网址里看到（WP348），自动出多半是一张「需要你填」，所以只给按钮（决策 950）。
8. **对话里那张连接卡用少字版**：以前「先连上插件」那张卡里铺的是连接页整节（广告动作十个开关、令牌清单……），只缺配对时现在只给装 + 配对码 + 「只连本机」那句承诺；要连广告后台那种仍是完整那一节（同意与开关在里面）。
9. **连接卡判「插件配上了没有」补上了**：以前这一样落到连接目录里查不到，服务端永远当「不知道」，同一缺项判重靠运气；现在看配对表。
10. **查过的现成方案**：这是工坊自己的引导流程（读职责定义、配对表、巡查状态），没有对应的 dsh 官方包 / 社区插件 / 开源库可用，直接在现有组件上做（装插件那块、配对码、连接卡、方案卡都是原样复用）。
