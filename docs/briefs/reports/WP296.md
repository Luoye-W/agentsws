## 4 已有工作目录怎么办（Rollout 那一份 v0.9.2）

**不自动升。** 流程：

1. 建站运行里每次调主题工具，服务端看这家店起底时记的版本（`site-theme.json` 的 `stores.<店>.base.version`）。比钉的旧 → 工具回话里带 `base_upgrade`，原话是「这份主题是 v0.9.2，新版 v0.10.0 要迁移（块名、设置名改了）。出了一张卡『升级到 v0.10.0（会跑迁移）』，人点了才升，升之前自动留一份备份。这一次接着用 v0.9.2 这一份做……」。出错的回话把这一句接在原因后面。stub 回话第一句照实说同样的意思。
2. 同时出**一张**卡：审批项种类用现成的 `upstream_upgrade`（契约里本来就有，排版是 `policy`、类别「上游升级」，不新造卡种），标题「升级到 v0.10.0（会跑迁移）」，挂在这件事上，卡上写从哪版到哪版、哪家店、发版说明链接、建议。同一个版本只出一张；人点「不升」后一天内不再出（照样说一句），过一天再问。
3. 人批了（决定钩子）→ `upgradeBase`：
   - 下新钉子那一份（同一个 sha256，下不来就不动）；
   - 在暂存目录里解开新版，把这家店的东西叠上去：**改过的** templates / section 组 / `settings_data.json` / `custom-*` 原样带上（没改过的用新版的）；locales 以新版为底，带上 `custom` 开头的键，店面文案（不是 `.schema.json`）里新版还有的键用这家店改过的那句；新版删掉的键不带回来（v0.10.0 把编辑器标签从 3469 条合到 2769 条，带回来会撞 Shopify 的 3400 条上限）；人删掉的店铺内容照旧删；
   - 在暂存目录里跑主题自带的 `node scripts/migrate-blocks.mjs`（就是 `npm run migrate`；用服务进程自己的 node，环境只给 PATH，限时 2 分钟）；
   - 跑成了才把旧工作目录**整份挪去** `<数据目录>/theme-work/<品牌>/backup/<店>-v0.9.2-<时间>/` 当备份（不删），新目录换上来；跑不成 → 暂存目录删掉，工作目录一个字节不动；
   - 记成 v0.10.0；「改了哪些文件」从此相对新版原样那一份算；事项时间线记一句「主题升到 v0.10.0 了：迁移改了 N 个文件（M 处要人手动挪）；旧的一份留作备份。线上主题没动，推一份预览看过再发布」，没升成也照实记一句。
4. 线上主题一个字节不动。升完照常推未发布预览、人看过再发布。

**用真的两版走了一遍**（临时测试，没提交）：用本机主题仓 `git archive v0.9.2` 起底（267 个文件），像人那样改了产品模板、加了一个 custom 块，再按 v0.10.0（真 codeload 包）升级：迁移改了 1 个文件（产品模板里的 `product-*` 全换成 `_product-*`），升完在工作目录里跑主题自己的 `migrate-blocks.mjs --check` 回「Nothing to migrate.」、`lint.mjs` 只报我那个测试 custom 块缺 `{% doc %}`（测试文件本身的问题），`block-allowed` / `template-settings` 都过，编辑器标签 2775 条。

**没做的**：发版说明第 4 步那几件人手动的事（购物车页的礼品包装商品要在主题设置里重选一次、自写文件里 `section-intro` 改 `section-heading`、横幅遮罩颜色、命名高度换成像素档）脚本管不了，我们也没管；`npm run build` / `npm run verify`（要 `npm install` 和 Tailwind）也没跑——升完靠官方 `theme check` 和推预览把关。

## 7 自主做的决定（白话）

1. **升级卡用现成的 `upstream_upgrade`**，不新造卡种：契约里本来就有这一种、意思就是「上游升级」，排版和类别现成；卡片家族属于「改东西」。
2. **备份 = 把旧目录整份挪走**，不是复制一份再在原地改：迁移在暂存目录里跑，跑成了才换，所以「备份」和「失败不动原目录」一步做到；工作目录不是 git 仓库，没走 git 提交。
3. **人点「不升」一天后再问**（照 docs/96「一天最多一次」）；同一版本没定的卡不重复出。
4. **locales 怎么合**（第 4 节那三条）：以新版为底是为了不撞 3400 条上限、新共用设置的标签都在。
5. **升级后「改了哪些文件」相对新版原样那一份算**：发布卡上的文件清单还是「这家店相对起底那一份改了什么」。
6. 没在岗位页上加版本提示（只走卡与运行里那一句，不新加页面区块）。

## 8 要 Luoye 定的事（每条附建议；决策号从 376 起是建议编号）

1. **（376）随安装包带的兜底起底包（决策 140）其实没接上**：服务端认 `AGENTSWS_THEME_BASE_DIR`，但桌面壳 / 打包脚本里没有任何地方下这份包、也没设这个环境变量，所以这次「一并换」无物可换。**建议**：另派一小单在打包时按 `theme-base-pin.json` 下好这份 tar.gz（核 sha256）放进 resources 并设好环境变量；GitHub 下不动的用户（国内网络）最需要它。
2. **（377）人点「不升」之后多久再问**：现在是一天后再问一次。**建议**保持；如果嫌烦，可改成「同一版本只问一次，下一个新版本再问」。
3. **（378）备份目录不自动清**：每次升级留一整份（一份几 MB）。**建议**先不清，以后在「设置 → 诊断」加一个「清理旧备份」按钮。
4. **（379）Rollout（Windows 真机上那份 v0.9.2）的真机走一遍**：我没连远程机器。**建议**合并、装包后在 Rollout 的建站岗位里说一句「首页再改一版」，看到那句话和卡 → 点批准 → 推预览看一眼；顺带核一下发版说明第 4 步里手动那几件（礼品包装商品、遮罩颜色）有没有用到。
5. **（380）主题仓那处前后不一致**（发版说明写 `rounded`，AGENTS.md §4 写 `rounded_top`）：**建议**转给主题会话改 AGENTS.md，我们这边不受影响。
