## 3. 我自主做的决定（白话）

1. **哪几条进硬顶**：报价、展会缴费、放单、付款指示、平台花钱——要么是钱、要么是货权。回询盘与开发信不进，它们靠承诺词表管（回信转人审、开发信直接拦）。
2. **报价谁批的落点**：yml 里 `stage_b2b_quote` 的 `route_to` 写 `scope_manager`（超授权转上级），授权内落回业务员自己由 `b2b-core` 的 `quoteApprover` 算。模拟世界已经按它路由；**服务端这一单没有 B2B 的写动作口**（那是「B2B-询盘与报价」那一单），所以真工作区里还没人调它，见 §6。
3. **业务员批自己那张授权内的报价不算"一人既提又批"**：提的是 Agent，批的是人，所以那一张 `separation_of_duties` 关着。
4. **guardrail 认的是调用方报上来的几格**（`footer_unsubscribe` / `footer_address` / `contacts_missing_source` / `sender_auth` / `suppression_checked` / `countries` / `account_matches_fact_card` …），**不报就按没过算**（fail-closed，照 `campaign_send` 的老办法）。真正去查 DNS、查抑制名单是「B2B-开发序列」那一单。
5. **德奥**：按 Fable 09-28（WP170 终审）只拦没有往来的潜在客户，已有往来的报 `existing_relationship` 照常出卡。
6. **红卡是一种审批**（`b2b_fraud_alert`），落老板、业务员同收，卡上**不抄那串账号**。
7. **契约加了 `RoleDefinition.status`**（派工单说"标未启用或等价方式"）：`planned` 的那条 YAML 写全、岗位里默认不勾。向导里没另加"第二批"字样（界面少字）。
8. **展会复用 `stage_b2b_outreach` / `stage_b2b_list_import`**（邀约与跟进就是开发信那套闸）；平台运营回 RFQ 复用 `stage_b2b_reply`。
9. **面板源只有一个 `b2b`**，授权挂 `b2b_account`（五条职责都有这个域）。
10. **日历那张卡放在「邮箱」分类**（它不只 B2B 用），名片识别 / B2B 数据 / 海关数据放新的「B2B」分类。
11. **模拟包是手写的**（synth 只会 dtc 家族），没有线程与评分标准，六个场景全靠事件驱动。
12. 两处从契约源码抠联合成员的测试正则放宽到带数字（`b2b_*` 里有个 2，原正则 `[a-z_]+` 认不出来）。
13. **承诺词表里"保证""usd "这类词比较宽**：宁可多出卡（回信那一支只是转人审）。开发信那一支是 block，被误拦的话改一句重提。

## 11. 终审追加（Fable 终审，合并前在同一分支改）

1. **「都要」不勾 B2B**：向导第 ③ 步「都要」只按齐红人营销与客服；B2B 只有用户明确按了那一项才勾，
   已按的 B2B 按「都要」也原样留着，松开「都要」只去掉红人与客服（`toggleBoth`，`preset-roles.ts`）。
   英文「都要」改回 Both。用例：纯函数一组 + 界面一组（按「都要」发出去的是 `['kol','care']`；只按 B2B 时「都要」不亮）。
2. **平台运营标「第二批」**：契约 `PositionInstance.roles` 与向导的 `OnboardingPositionView.roles` 各加可选 `planned`
   （只在职责定义 `status: planned` 时出现，服务端按定义填）；工作台新组件 `components/ui/planned-tag.tsx`——一个短标签
   「第二批 / Later」+ 问号（说明："这条职责先建好了，第一版还不做；默认不勾，想先试可以勾上。"），向导的职责行与
   岗位页「这个岗位下的 5 条职责」里都用它。
3. **「仍默认不勾」落到实处**（顺手发现的洞）：原来勾一个岗位 = 模板里的职责**全勾**（不看 default），于是勾「B2B」
   会把平台运营一起带上。现在服务端 `expandRoles` / 清单与工作台 `expandPick` 同一条规矩：**勾岗位不带第二批的职责**；
