# WP237 报告：合并岗位后「走哪条职责」——同岗位自己选、选择卡按钮对、选完要开跑

分支 `wp/237-routechoice`（worktree `agentsws-wt/wp237-routechoice`），Claude 子代理。

## 0. 一句话

同一个人、同一个岗位里几条职责打平时**不再问人**，按分高的那条直接开跑，时间线上挂「换成「Reddit 营销」」一键改派并重跑；
只有真看不出（一个判据词都没命中 / 谁都不太像）才出选择卡，卡上和事项页上的按钮就是候选职责「走「X」」，**点了立刻钉到那条并起运行**；
还没定职责时在事项里补一句话，点了名就钉那条、没点名按原话 + 这句再路由，**绝不落到负责人的通用助手**。
另：`read_reddit` 描述里的单价按价目表每次运行现填（#67）；CI update-e2e 那次不是慢，是一直没分到 Windows 机器。

## 2. 自主做的决定（白话）

- **「不同的人才出卡」这条在现在的机制里碰不到**：岗位入口只在请求人自己名下的职责里路由（54 §4，防借岗位扩权），所以候选永远是同一个人的。我没去改这条边界，而是把「出卡」收窄成「真看不出」——一个判据词都没命中，或者第一名自己都不到 0.3（四条各沾一点）。这两种替人选就是瞎猜，照旧问一句。
- **分数完全一样时按岗位里职责的先后**取（合并时被并入的那条在前）。Reddit 那个现场两条打平 0.5 : 0.5 的话，按字典序会落到「Reddit 营销」，跟人的直觉反。
- **老卡也能用**：已经出过的「认领 / 不是客户问题」卡，升级后投成「走 X」；老卡被人按了不带选项的「认领」（非工作台入口）也按分最高那条开跑。Luoye 机器上那件已经批过卡、卡死的事项：升级后事项页标题下会出「走「Reddit 运营」/ 走「Reddit 营销」」，点一下就开跑；在事项里说一句点了名的话也行。
- **选卡、点事项页按钮、续话点名三条路共用一个「钉上并开跑」**（`reroute {run}`），钉上后顺手把挂着的卡按同一选项定掉；定卡的回调看到事项已在那条上就不再跑，所以不会跑两次（测试钉住）。
- **已定职责的岗位事项，续话改用事项钉的那条分配**（本人持有的前提下）。之前是请求头上那条——工作台当前站在负责人上时，续话会被派给负责人那条。
- 「开始做了」的那次运行不在时间线上伪造一句人话，只记一条「按「X」开始做了」；原话在开事项时已经记成第一句人话（没定职责时也记，这样事后选了才有原话可用）。
- 模拟世界里的岗位路由用同一个判据（`settleCloseCall`），选择卡按钮同样写「走 X」；三包 × 三档全过、基线无漂移（场景里那条「拿不准」是四条各 0.25，不受影响）。
- 单价：一个工具背后三项能力，**三项同价才写数**；价不一样就不写（一句「约 N 积分一条」说不准）。

## 3. 要 Luoye 定的事

1. **跨人的候选要不要进路由**？现在岗位入口只在你自己名下的职责里挑（54 §4），所以「候选分属不同的人 → 出卡」这条实际碰不到。要是一个岗位里 A 职责是你、B 职责是同事，你交给岗位一件更像 B 的事，现在是派给你自己的 A（或者问你）；要不要改成「出卡让你选交给同事」？这会动 54 §4 的边界，需要你拍板。
2. **「一个判据词都没命中」要不要也直接按岗位的默认职责做**（不问）？现在是问一句。真机上像「你好」「看看这周」这类话会出卡。
3. **「换成 X」要不要停掉前一次还在跑的运行**？现在是并行：旧的照跑完（换职责不改历史），新的同时开始。
