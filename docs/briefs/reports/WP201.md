# WP201 报告：插件采集红人 → 本机红人库 → 公共红人库 → 本机查到，真跑一遍

实现方：Claude Opus（子代理）。三个 worktree，分支都叫 `wp/201-kol-e2e`：

- 开源仓：`agentsws-wt/wp201-kol-e2e`
- 插件私有仓：`agentsws-extension-wt/wp201-kol-e2e`
- 云端私有仓：`agentsws-cloud-wt/wp201-kol-e2e`，这一单没有改动

**一句话结论**：Luoye 那台正在跑的服务上，采集能进本机库，也能上公共库，这两段是真线上跑通的。但插件面板在真 Chrome 里有一半功能是坏的：所有 GET 都回 401，面板上写着「这把配对已经不能用了」。另外，本机「看得到 / 查得到」这两段在 Luoye 的工作区里跑不了，因为他还没有「红人营销」这个岗位。修复一共五处，都在我自己起的第二个服务实例上加替身云跑通了，前后四段全绿。修复要合并、并重启 Luoye 的本机服务之后才会生效。积分花了 **0**。

## 1 四段各自的结果

证据都在 `docs/assets/wp201/`。文件名带 `live-` 的是在 Luoye 真服务上拍的，带 `standin-` 的是在我自己的实例上拍的。

### 怎么跑的

- **插件**：完整版插件用 `pnpm build` 构建（WXT，产物里没有 `.map` / `.ts`）。浏览器用本机已装的 Playwright Chromium（chromium-1243，无头），持久化上下文，`--load-extension` 只装这一个插件，没碰 Luoye 的 Chrome。「按工具栏图标」这一步，是让插件后台给当前页发 `toggle-panel`，和 `background.ts` 里 `action.onClicked` 走的是同一句。
- **采集对象**：5 个公开的 YouTube 3C 测评频道，都是中小博主：@TheTechReviewer（3.6 万）、@MobileReviewsEh（54.6 万）、@T3CHUP（9960）、@ZubairRaz（2.75 万）、@PowerBankExpert（2800）。YouTube 界面用中文（`zh-CN`），订阅数原文是「3.6万位订阅者」这种写法，插件能读出来。没有登录、注册或填表。
- **IG / TikTok**：这一单没有去试。那两家的主页不登录基本看不全，按规矩跳过。

### ① 插件显示「已收进」：真线上通过（但面板上同时有误报）

- 5 个频道的面板底部都写着「已收进红人库」。截图：`live-02-panel-thetechreviewer.png`、`live-02-panel-mobilereviewseh.png`。
- 同一块面板上还有两句**假话**。「数据同步」写着「这把配对已经不能用了……重新配一次」，「存入红人池」写着「读取工作区失败」。设置页上显示「已配对 / 没连上」（`live-01-options-paired-but-offline.png`）。原因见断点 1。

### ② 本机红人库里有这 5 位：真线上只能从接口证明，工作台页面看不到

- **接口证据**（`live-local-calls.json`）：5 次采集的回执都是 `status: ok` 并带 `creator_id`。第二次再采 @TheTechReviewer 回的是 `deduped`，说明第一次那条真的写进了库。
- **工作台红人页**（`live-03-workbench-no-kol-role.png`）写的是「这个品牌还没有人持有红人职责。先在「组织」里把它分配给自己」。Luoye 的工作区里只有「负责人」和「客服」两个岗位，没有红人营销岗。红人库的读接口 `GET /v1/kol/creators` 对负责人那条分配回 403（`creator.read range=assigned`）。建这个岗位属于改他的设置，我没有动。见断点 2 和第 5 节。
- **替身验证**：我在自己的实例上建了红人营销岗，红人页列出了这 5 位加批量采的 20 位（`standin-03-workbench-library.png`、`standin-kol-creators.json`）。

### ③ 本机上报公共库成功：真线上通过

- 每次采集回执里的 `forwarded_to_public_library` 都是 1（`live-local-calls.json`）。这个数**只数云端回了 2xx 的条数**，见 `extension-contribute.ts`。插件那边的排队是 0 条，没有卡住。
- 本机转发这一跳实测一次要 **2.9 到 6.5 秒**，是插件等着的时间，而插件只等 8 秒。单个主页勉强够用，列表页一块 20 行一定超时。见断点 3。
- Luoye 那台服务的输出里以前**不记转发**，所以「日志里是 2xx」这件事只能从回执看。修复后每一轮转发会记一行，例如 `standin-server-forward-log.txt`：`[公共红人库] 转发 19 条：2xx 19`。

### ④ 公共库里真有了（通过本机「查公共库」查一次）：真线上没能验证，替身通过

- **真线上**：本机查公共库的正常入口是红人面板里的搜索（`GET /v1/kol/search`，失败后可改走「工坊官方接口」），它要求持有红人职责。Luoye 的工作区里没有这个职责，所以这条路走不到，一分钱也没花。能间接证明的只有一点：云端对 5 条观测都回了 201，也就是收下了。
- **替身**：在我自己的实例上搜 `thetechreviewer`，走的是公共库那一档，搜到了（`standin-kol-search-public.json`），替身钱包扣 0.2。
- **KOLAgents 那 723 个红人有没有搬进线上公共库**：因为查不了，**无法从用户侧确认**。搬家脚本也没有跑。

## 2 断点清单

| # | 现象 | 根因 | 修法 | 在哪 · 提交 |
|---|---|---|---|---|
| 1 | **真 Chrome 里插件所有 GET 都是 401**（hello / setup / report / reveal-pricing / 取邮箱 / 自动评分）。面板说「这把配对已经不能用了」「读取工作区失败」，设置页显示「没连上」，只有 POST 采集能进去 | 插件在 manifest 里拿了 `127.0.0.1` 的 host 权限。Chrome 按 Fetch 规范，**不给这种 GET 带 `Origin`**（POST 照带），只带 `Sec-Fetch-Site: none`。本机服务认令牌时又要求 Origin 必须在。单测一直手塞 Origin，所以从来没撞上。我在同一个 Chromium 里用回显服务实测确认过 | 没有 Origin、并且浏览器说 `Sec-Fetch-Site: none` 时，照样验令牌，认出来的是配对时绑定的那个扩展。带了 Origin 的请求照旧必须是那个扩展。网页的请求永远带 Origin，所以挡网页的那道闸没有松 | 开源仓 `868dd0e9`（`packages/api` 两档配对表 + 路由，测试 5 条，docs/76 §1 补一段） |
| 2 | 插件说「已收进」，工作台红人页却说「还没有人持有红人职责」；本机查公共库这条路也走不到 | Luoye 的工作区没有红人营销岗。插件配对和采集不要求这个岗位，但看库和查库都要 | **没改代码**：这是工作区配置，要 Luoye 定（第 5 节）。建议配对页或插件上提示一句「还没分配红人职责，收进来的人在工作台看不到」 | — |
| 3 | 本机转发公共库是一行一个请求、一个接一个，全部回来才回插件。线上一次往返 3 到 6.5 秒，而**列表页一块 20 行要一分钟**，插件等到 8 秒就当「应用没开」把整块排队，5 分钟后重发，批次 id 也丢了。转发失败时以前直接丢，没有人补 | 同步串行转发，没有重试 | 本机最多等 4 秒就回插件，没送完的在后台接着送（4 个并发）。回执只加一格可选的 `public_library_pending`。断网、408、429、5xx 退避重试，最多 5 次；400 这类云端明确不收的不重试。每一轮在输出里记一行 | 开源仓 `3cd338ae`（测试 4 条；同一组测试放到修复前的代码上跑是 3 红，记录在 `prefix-test-run.txt`；docs/76 §11.2bis） |
| 4 | 插件「获取邮箱」按钮写「⊙ 0.2」，点下去云端扣 0.8 | `reveal-pricing` 报的是搜索那一项 `data.kol.lookup` 的价，而云端取邮箱扣的是 09-23 单独拆出来的 `data.kol.reveal` | 按钮报价改取 `data.kol.reveal`，装配和回执共用一个常量 | 开源仓 `1e311273`、`936db6af`（docs）、`f665b2d6`（重新生成的 SDK） |
| 5 | 频道把订阅数藏起来时，插件照样送 `followers: 0`，公共库就会记成「0 粉丝」 | 从旧插件移植来的快照把读不到的数垫成 0，I/O 那一层原样送出 | I/O 层遇到 0 就当成没读到、不带这一格。移植来的算法本体一个字没改 | **插件私有仓** `9886f8e`（测试 2 条） |
| 6 | 工作台红人清单里显示 `@@TheTechReviewer` | 插件收进来的 YouTube handle 自带 `@`，界面又加了一个 | 显示时统一成一个 `@`，库里的值不动 | 开源仓 `109fccbc`（测试 1 条） |

**看到了、这一单没修的**（范围外或者需要先定）：

- demo 装配里，插件转发用的是全局 fetch（打到 `.invalid` 地址），没用 `cloudFetch` 替身。所以 demo 里插件永远上不了替身公共库。这只影响 demo，改一行装配就行，没做。
- docs/76 §4 写着「hello 不需要令牌」，实际要。这一单没动文档的这一句。
- 本机「账号与积分」那里的 scopes 显示 `ai, wallet:read`，但转发公共库（要 `data` 权限）是通的，说明这一格的显示可能不准。没有深查。
- 重试队列只放在内存里：本机服务重启会丢掉还排着的那几条。那几条在本机库里都在，再采一次就会再送。

## 5 要 Luoye 做或定的事

1. **合并并重启本机服务**。断点 1、3、4、6 要合并开源仓，再重启你那台 4317 才会生效。断点 1 不修，完整版插件在真 Chrome 里就是半瘫的。断点 5 要插件私有仓出一个新 zip。**顺序**：先上本机服务（断点 1 是服务端的修复，旧插件 zip 也能直接受益），插件 zip 可以晚一点。
2. **定一下断点 1 的放宽口径**：「没有 Origin，并且浏览器说 `Sec-Fetch-Site: none`」也算扩展的请求。我的判断是没有变松：网页过不来；本机上的 curl 这类进程本来就能伪造任何头，这道闸从来挡的不是它们。docs/76 §1 已经写明。你要是更想「插件去掉 host 权限、本机服务给扩展开 CORS」那条路，得两边一起改。
3. **给自己分配「红人营销」岗位**（组织或初始化向导里勾上）。分配之后工作台能看到这 5 位，查公共库这一段也能真线上补测一次：搜一次 0.2 积分，10 分钟内重复搜不另收。另外要定：配对插件的时候，如果还没有红人职责，要不要提示一句，或者顺手分配？
4. **测试留下的东西**：
   - 你工作区里有一把插件令牌，名字叫「WP201 端到端测试」。可以在「连接 → 浏览器插件」里撤掉，我没撤，撤销也算改设置。
   - 本机红人库里多了这 5 位。
   - 公共库里多了这 5 个 YouTube 频道的观测，来源记为 `plugin`。
   - 我用 owner@localhost 登录过工作台两次（第一次的会话过期了）。
5. **KOLAgents 那 723 位**：从用户侧确认不了。做完第 3 条之后，用公共库搜一个已知在那 723 位里的 handle，就能看出搬没搬。
