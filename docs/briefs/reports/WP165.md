## 2 我自主做的决定（白话）

1. **价目拿不到时不报错，回一份空的价目**（带 `source: 'unavailable'` 和一句人话）。这样界面、老客户端都不会因为一个错误码白屏，也不会编数。
2. **同步读价钱的地方从不打网**。生图单价、看一次邮箱 / 体检的价是同步读的，读的是手上存的那份；否则每个测试、合成世界都会悄悄去敲真云。代价：一台新机器第一次启动、还没取到价目之前，这几处显示不出价（插件面板那头是「每位约 0 积分」，见 §3）。生产入口起来就取一次，所以正常情况下看不到。
3. **红人搜索问价只在关联了账号时去云上刷**（以前也是关联了才打云），没关联就读手上那份。
4. **Workers 形态的 `/v1/pricing` 在前门直接回**，不进 `WalletDO`：它不认人、不碰钱，没必要每次叫醒一个组织的对象。
5. **契约包里的托管环境变量那份连 build / parse 两个纯函数一起搬了**（派工单写的是「常量 + 类型」），因为两头要的正是这一对，只搬名字表的话 `apps/server` 还得依赖 hosted。
6. **本机价目 / 充值档位接口的返回类型改成 `LocalPricing` / `LocalTopupTiers`**（`Pricing` / `TopupTiers` 的超集，只多几个可选格），SDK 里的描述名跟着变。
7. **`kol-public/sources/{apify,youtube}` 不拆**：查过，本机自带 key 那一档直连 YouTube 等渠道的是 `apps/server/src/kol-channels.ts` 自己的代码，从没用过这两个云端取数源（它们只给公共红人库的云端刷新用）。
8. **替身靠「一致性测试」防两张皮**：每个替身都在云端那一侧有一条把同一串动作同时喂真服务和替身的比对测试。所以将来私有仓要以 npm / git 依赖用开源仓的 `@agentsws/stand-ins`（`contracts`、`search-providers` 本来就要）。
9. **公共红人库替身的体检只出骨架**（样本量、近 30 天活跃、一句话、收不收钱），粉丝真实度 / 分位 / 风险标记不编；本机那一侧的测试只看收钱与状态，够用。
10. 模拟里注册赠送用替身里的样例（10 积分、granted、90 天）；一致性测试钉住它与云上 `bonuses.json` 同形。

## 3 需要 Luoye / Fable 定的事

1. **开源仓里的价目样例是 09-27 真价的快照**（`packages/stand-ins/src/cloud/pricing-sample.ts`，历史上本来就公开过）。要不要换成明显是示意的数字？换了的话模拟里扣的积分跟着变、要重定三个运行时的基线，demo 上看到的也是假价。我没换。
2. 样例与云上真价之后会慢慢不一样（例如今天 main 把 AI 问答改成 0.2，我手动跟了）。要不要在云端那一侧加一条「样例 = 真价」的测试逼着同步？我倾向不加（价格是生意，开源侧不必跟），现在没加。
3. 新机器第一次启动、断网、从没取到过价目时，插件面板的「每位约 N 积分」与「看一次邮箱 N 积分」显示 0。要不要改成「价钱暂时拿不到」的文案（要动插件那头的契约）？
4. 价目刷新节奏：刚取过 5 分钟内不再打、失败 1 分钟内不重试。
5. 私有仓搬家时（第 3 步）：`@agentsws/stand-ins` 也要能被私有仓引用（一致性测试要它）。
