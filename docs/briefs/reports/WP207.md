## 1 做了什么

### ① 左栏三级「+」（`apps/workstation/src/components/app-shell.tsx`、`components/sidebar/*`）

| 位置 | 怎么显示 | 点了做什么 | 谁看得到 |
|---|---|---|---|
| 「岗位」标题旁 | 常显 | 就地展开「新建岗位」：名字 + 勾职责（同公司页那套接口与 `pickableRoles` 过滤，拆过的老职责不列）；建完**自动分给自己**（范围不设 = 整个品牌）并展开 | 所有者 |
| 岗位行 | 悬停 / 键盘聚焦才出现 | 就地展开「加职责」：只列这个岗位还没有的；存的时候原有职责与默认勾选原样带上，新职责分给自己（范围沿用我在这个岗位上的那份） | 所有者 |
| 职责行 | 悬停 / 键盘聚焦才出现 | 打开 ⌘K，只剩一格「一句话说要做什么」，标题是「岗位 › 职责」；回车 = `POST /v1/positions/:id/matters` 带 `role_id`（与快捷提示同一条路，跳过岗位内路由），进事项页 | 所有人（只列本人持有的职责） |

- 每个「+」都有 tooltip（一句话），同一句写进 `aria-label`；悬停才出现的那两个只是 `opacity-0`，Tab 仍能落上去（`focus-visible:opacity-100`）。
- 「有权改组织」按公司页的口径 = 持有 `common.owner`。

### ② 职责下挂进行中的对话 / 任务

- 新接口 `GET /v1/work/rail`：按本人持有的岗位 → 职责，列**本人看得见的**进行中事项（参与人里有他，或者是用他名下分配开的），按最近活动排。
- 状态小点（图形，不是字；意思在 `title` 与读屏里）：品牌色会呼吸 = 在跑（运行时 `activeRuns`）；琥珀 = 等你批（本人队列里挂在这件事上的卡）；绿 = 做完待看（最后一句是 Agent 说的、而且本人之后没点开过）；不画 = 开着等下一步。
- 默认 5 条 +「更多（n）」（一次取 20 条，就地展开），最底下「已归档（n）」。
- 岗位右侧的数字改成**等你处理的** = 等你批的卡（与原 `pending_cards` 同一口径）+ 做完待看的事；tooltip 写明。取不到左栏那份（老服务进程）时照旧显示待审卡数。
- 「做完待看」怎么灭：事项页打开时调 `POST /v1/matters/:id/seen`（页面开着时 Agent 又回了也算看过）。
- 事项归属职责的判法：`role_id` 对得上（职责入口的老事项没有 `role_id` 时按 `position_id` = 本人那条分配认），并且 `position_template_id` 为空或是这个岗位。

### ③ 自动归档

- 契约只加 `Matter.archived_at?`（归档不是状态，`status` 不动）；`@agentsws/work` 加 `archiveIdle` / `unarchive`。
- 规则：开着（open / waiting）的事超过 N 天没新活动就归档；默认 3 天，「设置 → 通用 → 自动归档」可选 1–30 天或「不自动归档」（`GET/PUT /v1/settings/work-archive`，存品牌目录下 `work-archive.json`）。
- **在跑的运行、等你批的卡所在的事不归档。**
- **新活动自动取消归档**：时间线上新一条（人回话、Agent 说话、运行、定时触发、卡片回填）或运行结束写摘要时，拿掉 `archived_at`，审计 `work.unarchived{by: activity}`。
- 归档只移出左栏与默认列表：`GET /v1/matters` 只加 `archived=exclude|only|all`（缺省 exclude）；「正在进行」（`/v1/work/in-progress`）与岗位层上下文也不含归档的。内容、记忆、卡片历史一样不少，事项页照样能打开，顶上一条「这件事已归档…」+「放回左栏」。
- 什么时候扫：**读左栏时懒扫**（只扫这个人看得见的），不起定时器。所以模拟、测试里一件都不会被归档。

### ④ 找回

- **按职责列**：「已归档（n）」→ 列表（`GET /v1/work/archived`），按时间（7 天 / 30 天 / 更早）、岗位、职责筛，带搜索框，每条「恢复」（`POST /v1/matters/:id/unarchive`，`by: user`）。
- **搜索**：标题、摘要、正文（时间线最近 40 条）全文搜，空格分开的词都要出现；归档列表的搜索框与 ⌘K 都能用（`GET /v1/work/search`）；⌘K 里多一组「对话与任务」，归档的标「已归档」。
- **AI 找回**：
  - 只读工具 `find_archived_work`（契约里定了名字、入参 `FindArchivedWorkInput`、出参 `ArchivedWorkCandidate`）。
  - 检索：关键词（中英混排：拉丁按词、中文按相邻两字；先去掉「找回来 / 对话 / 的」这类套话与时间字眼）+ 时间段（「上周 / 昨天 / 3 天前 / last week」拆成窗口，**加分不硬筛**）+ 参与人 / 岗位加分；语义那一路见第 5 节「偏离」第 1 条。
  - **随便聊**：这个人有归档的事时才把工具挂给模型（没有就一个字不多，老对话行为不变）；模型一轮最多找 3 次（可以换同义词 / 英文再找）；找到的候选以 SSE 帧 `archived_candidates` 推给界面、存在那条回复上（只加字段），画成 3–5 张卡。
  - **⌘K**：打两个字以上，最后一项「让 AI 找回『…』」→ 候选卡。这一路先用关键词捞，再把命中的 + 最近归档的（最多 24 件）交给默认模型重排（只排序；模型回的 id 不在这一堆里的一律丢掉）；没接模型就按关键词顺序。
  - 归档列表底下也有一格「让 AI 找回…」。
  - 三处都是：**卡片上点一张才恢复那一张**（`by: ai_suggested`），没有「全部恢复」，模型手上没有恢复这个动作。审计 `work.unarchived{by: user | ai_suggested | activity}`。

## 2 自主做的决定（白话）

1. **归档是一个时间戳，不是新状态。** 事项原来的 open / waiting / closed 一个没动，「归档」只是「这阵子没人动，先收起来」。这样恢复就是把戳拿掉，别的什么都不用改。
2. **不开定时器，读左栏时顺手归档。** 你打开工作台、左栏刷新（事件来了 + 一分钟兜底轮询）的那一刻才去收。好处：模拟与测试里没人读左栏，一件都不会被归档，零漂移是结构上保证的，不靠运气。代价：长时间没人打开工作台时，归档会晚到下一次打开那一刻——反正那时也没人在看左栏。
3. **只扫这个人看得见的事。** 谁的左栏谁来扫；别人的事不会因为我打开左栏被归档。「等你批的卡不归」判的也就是本人队列里的卡。
4. **放回来算一次活动。** 恢复时把「最后活动」拨到现在，否则下一次扫又把它收进去了；它也就排到那条职责最上面。
5. **自动归档天数按品牌存（不是按人）。** 事项是这个品牌的，归档状态只有一份；多人各设各的会互相打架。
6. **「做完待看」要记"看过了"**，我记在同一个 `work-archive.json` 里（谁、哪件事、什么时候看的），不是业务数据，丢了最多多亮几个绿点。
7. **找回打分里，岗位 / 职责名只是弱信号**：只中了「红人营销」这种岗位名的不进候选（同一个岗位下的事个个都带着它）。
8. **⌘K 的「让 AI 找回」用默认模型重排一次**（用途记 `judge`，照常过网关计量）；随便聊那一路不重排——聊天模型自己就在读候选、还能换个说法再找。
9. **加职责直接改岗位模板再分给自己**，和公司页「加减职责」同一条路；新建岗位建完自动分给自己、范围留空（= 整个品牌，与向导里不挑范围一样）。
10. **左栏职责下只列本人看得见的事**，与 WP69「别人那条分配不能拿来开事」同一个口径。

## 3 要 Luoye 定的事

1. **自动归档天数按品牌还是按人？** 现在按品牌（这台机器、这个品牌一份）。如果公司里多人用、各自想要不同天数，要改成"按人算左栏里显不显示"，归档就不再是事项上的一个字段，而是每人一张表。
2. **语义检索要不要真上嵌入？** 仓库里现在没有本机嵌入（知识库那边也只留了接口），默认模型大多是 DeepSeek（没有嵌入接口），硬调会报「提供方挂了」并计费。所以语义那一路现在是「模型重排 + 让聊天模型自己换说法再找」，`rankArchived` 留了语义分的口子。要不要配一个专门的嵌入模型（本机小模型或云端）？
3. **要不要手动「归档」按钮？** 这一单只有自动归档（Claude 那种悬停出「归档」的手动按钮没做，brief 没要）。
4. **加职责 / 新建岗位的职责清单**与公司页一样列出全部职责（包括「公司设置与授权」这种底座职责，见截图 10）。要不要在左栏这里把 `common.*` 滤掉？
5. **「更多」一次最多 20 条**，再多要去「已归档」列表或搜索找——左栏不做无限滚动。可以吗？

## 5 偏离

1. **语义检索没用嵌入**：brief 写「语义用本机已有的嵌入或模型重排，没有就退化为关键词」。本机没有现成的嵌入（见第 3 节第 2 条），所以用的是后两者：⌘K 那一路默认模型重排、随便聊那一路聊天模型读候选并可以换说法再找（最多 3 次）；都没有模型时退化为关键词。
2. **「全文搜（本机索引）」没有建 FTS 索引**：现在是在本机库里逐件扫（标题 + 摘要 + 最近 40 条时间线）。一个品牌几百到几千件事的量级下毫秒级；真到上万件再给工作模型的 SQLite 档加 FTS5（中文要用 trigram 分词）。
3. **随便聊的截图（12）里那条回复是拦下来的假回复**：合成世界的替身模型不会自己调工具，所以这张图用真服务端 `find` 接口的结果当回复里的候选画出来（卡片、点选恢复走的是真的接口）；「模型真调工具 → 推卡片 → 存在回复上」由服务端测试 `apps/server/test/wp207-free-chat-recall.test.ts` 覆盖。
4. **「在跑」的小点没拍到**：合成世界里的替身运行一瞬间就跑完，截不到；由服务端与工作台测试覆盖。
5. **没有归档的随便聊会话**：brief 说的「对话 / 任务」我按「职责下的事项」做；随便聊的会话本来就不挂在职责下、也不进左栏，没给它加归档。
6. **新建岗位后的展开**：展开态记成"显式展开"（与点箭头同一条存法），下次进来还开着。
7. **jsdom 里点「+」用的 `fireEvent`**：Radix tooltip + 焦点被新开的面板拿走时，jsdom 里 userEvent 的整套指针序列会卡死（真浏览器里没有这个问题，截图脚本里点的都是真点击），测试里注明了。
