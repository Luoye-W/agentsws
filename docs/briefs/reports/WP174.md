## 1. 实现清单

1. **上级怎么表达（契约只加不改）**
   - `packages/contracts/src/roles.ts`：`Position.supervisor_person_id?: PersonId`，只在工作区存下来的那份岗位上有，包里的模板不填。
   - `packages/contracts/src/approval.ts`：`Recipient.reason?: string`（卡上那一句「转给了谁、为什么」）；`RerouteInput`；`ApprovalBus.reroute?()`（可选方法）。
   - `packages/api/src/routes/org.ts`：`PositionView.supervisor?: { person_id, name }`；新路由 `PUT /v1/org/positions/:id/supervisor`（body `{ person_id: string | null }`，`null` 表示清掉）；`OrgPort.setPositionSupervisor?` 是可选方法，宿主没装时回 501。
   - `apps/server/src/org.ts`：上级存在 `org_positions` 那一行的 JSON 里，没加新表；上级必须是工作区里还在的人，否则回 400。改上级写 `position.supervisor_set`，清掉写 `position.supervisor_cleared`（`reason: manual | left_workspace`）。改上级不动版本号和 `source`，因为这不算改模板。
   - 工作台 `components/org/positions-tab.tsx`：每张岗位卡上加一个「上级」下拉，候选是工作区里还在的人，第一项是「不设（转老板）」。说明放在问号里，卡上不铺字。`pages/org.tsx` 里一改就存。
2. **路由：一个解析函数**
   - `packages/roles/src/supervisor.ts`：`resolveScopeManager` 是纯函数，规则是：先找发起这张卡的职责所在岗位的上级；没设、上级就是本人、上级已不在工作区、或这条职责不在任何岗位里，就落到老板。职责挂在几个岗位里时，先看提的人自己在做的岗位，再看这条职责默认勾上的那个岗位，都按 id 排序。`scopeManagerReasonText` 生成卡上那一句，只写人名，不印 id。
   - `apps/server/src/supervisor.ts`：`createScopeManagerRouter` 把岗位表、提的人在做哪几个岗位（按分配现算）、谁还在工作区、人名接到服务进程里。岗位表晚绑定：各品牌服务装配时公司页还没装好。
   - 接入的地方：公关（`pr-service` 两处）、建站（`site`）、社媒（`social-service` 两处）、SEO（`seo-service` 机械第一稿）、投放（`ads-service` 三处）、B2B（`b2b-service`：报价超授权和 `route_to: scope_manager` 的动作），外加 `POST /v1/approvals`（给了 `rule: scope_manager` 但没给收件人时）。结果写进 `recipients[0].via`（`scope_manager` 或 `owner`）和 `reason`。
   - 卡面：`packages/deck` 的 `DeckCard.routed_note?` 取第一条带理由的收件人；`deck-card.tsx` 在标题下面显示这一句。
   - 超时升级链没动（`createApprovalDirectory`），最后一层仍是老板。
3. **离职 / 移出**
   - `org.onMemberLeft(person, by)` 会清空这个人当上级的所有岗位，并写事件。他手上还没批、`via: scope_manager` 的卡逐个改派给所在工作区的老板（`txn` 的 `reroute`：只换他那一格，revision + 1，旧 token 作废，重新投递，写 `approval.rerouted`，卡上理由写「上级 X 已经离开工作区，改派给老板 Y」）。另外给老板发一张 L3 只通知的卡：「某某岗位的上级空了」，提醒他去「公司 → 岗位」重新设。
   - 两条路都接上了：`removeMember`（移出成员）和离职编排 `offboard`（新可选项 `onLeft`）。打开岗位页时再兜一次底（`positions()`），处理没走这两条路就离开的人。
   - 解析函数本身也会检查上级还在不在，所以就算没清成，新卡照样落老板。
4. **模拟**：`packages/simulation/src/world.ts` 的 B2B 写动作改用同一个 `resolveScopeManager`。包里 `scope_manager: true` 的那个人就当 B2B 岗位的上级，卡上也带那一句理由。`b2b-3c-3p` 里「报价超授权转上级」在真服务进程里也按上级走，见 `apps/server/test/supervisor.test.ts`。

## 2. 我自主做的决定（白话）

1. **上级存在岗位那一行上，没另开表。** 存下来的岗位本来就是「这家公司有哪些岗位」，上级是它的一格，备份和导出跟着走。改上级不升版本号，因为这不是改模板。
2. **只解析 `scope_manager`。** 规则写 `owner` 的卡（比如建站开 App 付费那张）和 `role_holder` 的卡一律照旧。
3. **各服务里的路由口是可选的。** 服务进程里全都装上了；单测和没装公司页的进程不给这个口，行为和以前一样（落在提的人自己身上）。所以老测试一条都没改期望。
4. **上级就是老板时，仍记 `via: scope_manager`。** 卡上写「转给了上级王岚」，因为这是「按上级走」的结果，只是人碰巧是同一个。
5. **只改派「转上级」的卡。** 离职的人手上 `via: role_holder`（他自己的活）和 `escalation` 的卡不在这一单里挪，那是离职编排里「接手人」那一步的事。
6. **提醒老板用一张 L3 只通知的卡**，形状和「品牌范围变了」那张一样。重设上级是老板自己的事，不需要他点头批准。
7. **离职编排的「接手在办的事」仍然落老板**（`offboard.ts` 里 `fallbackSuccessor` 没改，只补了注释）。把一个业务员的全部在办事项默默压给他上级，应该由老板点名。

## 3. 需要 Luoye / Fable 定的事

1. **上级不做这条职责时，卡在哪里看？** 岗位页的卡片队列按「这个岗位的职责」过滤（`workstation.ts` 的 `itemsFor` 带 `role_id`）。上级自己如果不做这条职责（比如老板没挂公关那条），卡只出现在他的待办 / 今日那一类全量视图里，岗位卡片队列里看不到。截图里给李默也挂了「B2B 业务」这条职责，卡才出现在他的 B2B 岗位下。
   - 以前 B2B 超授权转老板时也是这样；这一单之后，公关、建站、社媒、SEO、投放没设上级的卡也会转老板。
   - 要不要给「等我批的、但不是我这条职责」的卡一个入口，比如老板岗位下一个「等你批」。建议下一单做。
2. **行为变化，请确认**：在多人工作区里，公关稿、外部发帖、社媒排期、SEO 改动卡、投放花钱卡以前落在提的人自己手上，现在没设上级就落老板，提的人自己不能再批这些卡。单人工作区不受影响，因为老板就是提的人。
3. 以后按部门扩：现在只按岗位设上级。一个人同时做两个岗位、两个岗位上级不同时，按「这张卡的职责在哪个岗位」找上级。
4. 顺手看到一处不属于这一单的问题：B2B 报价卡的摘要写成「超了授权（amount、margin）」，括号里是英文字段名，来自 `b2b-service.ts` 的 `breaches.replace(...)`，WP172 就这样。建议换成「金额、毛利」。
