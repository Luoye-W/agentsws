# WP345 报告：浏览器插件跟着工坊一起更新（不上架商店）

分支 `wp/345-extupdate`（worktree `../agentsws-wt/wp345-extupdate`），派工单 `docs/briefs/WP345-extension-autoupdate.md`，决策 871。
按要求推了分支跑 Windows CI；没合 main、没打 tag、没发版。要 Luoye 定的事编号 873–877。

## 0 一句话

用户只在第一次「加载已解压」时动一次手：连接卡上两个按钮（打开插件文件夹 / 打开 Chrome 扩展页）+ 三步小字。
之后每次工坊启动，把安装包里的插件**整体换进同一个文件夹**；插件每分钟问一次「文件夹里是哪一版」，不一样就**等手上的活做完**再自己重新加载。
id 固定（manifest 里写了公钥），所以配对、插件里存的东西、给过的权限都不丢。不用再去 Chrome 里卸旧装新。

截图：`docs/assets/wp345/install-card.png`（连接页「浏览器插件」一节，还没装时的样子）。

| 工坊更新后 | 什么都不用做。插件空闲时自己重载一次；Chrome 没开就下次打开直接是新版 |

| 插件设置页 | 多一行「版本」 |

帮助文档（`docs/help/browser-extension*.md`）和 `docs/68` 改成这一套，不再让人下载 zip。

## 2 实测（能测到的照实写，测不到的写明）

### Mac 本机，品牌版 Chrome 155.0.8059.41，临时用户目录（不碰 Luoye 自己的 Chrome）

脚本 `scripts/probe-ext-chrome.mjs`，原始结果 `docs/assets/wp345/probe-chrome-mac.json`。装插件走 Chrome 调试协议的「加载已解压」（和人点「加载已解压」一样：位置记为 UNPACKED、重启后还在）。

1. **新版插件多要权限时：不弹窗、不停用。** 文件夹换成多要 3 条有警告的权限（读写书签、浏览历史、标签页）+ 一个新站点的版本，插件自己 `reload()` 之后：照常开着（ENABLED，没有任何停用原因），新权限**直接生效**，扩展详情页里多出两行权限说明。
   - 说明：「有没有弹窗」我截不了屏（这台电脑没给录屏权限），所以用的是「插件状态 + 权限是否已生效」来判断；Chrome 对商店插件多要权限时的做法是先停用再弹窗请人同意，这里状态一直是开着、权限已经给上，说明没走那一套。
2. **开发者模式插件启动时：没有提示。** Chrome 155 的界面文字里已经**没有**老的「停用开发者模式扩展程序」那句（只能从文字包判断弹不弹，弹窗本身截不了屏）；不带任何调试开关正常打开 Chrome，插件照常开着、开发者模式照常开着。
3. **额外发现一（要紧）：关掉开发者模式，插件马上被停用**（停用原因 `unsupportedDeveloperExtension`），再打开就回来。Chrome 155 文字包里有对应的两句（「开发者模式关了，部分扩展被停用」）。所以三步小字的问号与帮助文档里加了「装好后别关开发者模式」。
4. **额外发现二：Chrome 不让外面直接打开 `chrome://extensions`。** 命令行带上这个地址，不管 Chrome 开没开着，都只开一个新标签页（已开着时新进程把它交给开着的那个就退出，这一步是好的）。网页也打不开 `chrome://`。所以「打开 Chrome 扩展页」现在 = 把 Chrome 叫出来开好新标签页 + 把 `chrome://extensions` 复制好，卡上说一句「在地址栏粘贴、回车」（决策 876）。
5. **Chrome 关着时工坊换了新版**：再打开 Chrome 直接是新版（UNPACKED，开着）。

### 真 Chromium 端到端（Mac，Playwright 自带 Chromium）

`node scripts/e2e-ext-update.mjs`：**24 项全过**（结果 `docs/assets/wp345/e2e-ext-update-mac.json`）。用的是真插件构建、桌面壳真的那段换文件夹代码、插件真的那段更新代码，只有本机服务和广告后台是本地假的。

- 加载已解压 → 扩展 id 就是公钥算出来的 `mlbfinfiigagllemohnopbhfdghagijg`；
- 设置页里配对；存一个记号；点一下授一条可选权限；
- 插件正挂着领活的长轮询时，工坊放新版（多要一条权限）→ 插件发现新版、关闸；本机这时把一件活交给挂着的那个 → **插件先把这件做完、回了结局，之后才重载**；那件活只领了一次；
- 重载后：开着（没停用）、版本换了、id 没变、配对在、记号在、之前授的可选权限在、新多要的权限直接生效；插件报上来「从旧版换来」；重载后再排一件活，新版照常领走做完；
- Chrome 关着时换版 → 再开直接是新版，存的东西都在；
- 本机说文件夹里是一个插件永远换不成的版本 → 插件**只重载一次**、报「放弃了」，之后再问也不再重载。

顺带撞出的一点：Playwright 的 Chromium 默认开发者模式是关的，这时插件一重载就被停用——和第 3 条同一件事；测试里先打开开发者模式（和真人装的时候一样）。

### Windows（CI，windows-latest 自带的品牌版 Chrome 155.0.8059.40；run 38718023727，两个作业全绿）

我不连远程机器（派工单纪律），Windows 只靠 CI。原始结果 `docs/assets/wp345/probe-chrome-win.json`。

- **与 Mac 完全一样**：多要权限重载后照常开着、新权限直接生效；界面文字包里没有老的开发者模式提示那句；正常重开后插件开着；关掉开发者模式就被停用、再打开回来；命令行带 `chrome://extensions` 只开新标签页；Chrome 关着时换的版下次打开直接生效。
- **Chrome 开着、插件正加载着的时候整体换文件夹**：实测脚本的第 ① 步就是在 Chrome 开着、插件已加载的情况下把文件夹挪开、换进新的——Windows 上换成功了（没被占用挡住）。这只证明「插件空着时」换得动；Chrome 正在读某个文件的那一瞬间没法造出来测。挡住时的处理：重试 3 次，还不行就保留旧版、照实说、下次启动再试（单测模拟过）。
- **「版本之间点更新」**（发布过的 beta.5 → V1 → 回滚演练 → V2）每段核了插件文件夹，全对：

  | 段 | 文件夹里的版本 | 状态 |

  Windows 上的文件夹是 `C:\Users\<用户>\AppData\Roaming\@agentsws\desktop\chrome-extension`。

## 5 我自己做的决定（白话）

1. **每次启动都同步，不等「第一次需要时」**：文件夹几百 KB、一样就不动，启动时放好最省事——连接卡一出来文件夹就在。
2. **比对用「每个文件的内容摘要」，不只看版本号**：同版本号重打的包也换得进去；插件那边比对用带 beta 号的完整版本（`version_name`）。
3. **「新版已到位」的通道是插件每分钟来问一次**（还是插件找本机，本机不伸手进浏览器），同一条请求里顺手报自己的版本——不另开推送。代价：没配对的插件不跟着更新（这条要配对令牌）；装好就会配对，影响很小。
4. **空闲 = 广告 / Reddit 的领活轮询没在挂着、手上没有正在做的一步**：要换版时先关闸不领新活，挂着的长轮询照常等它回来（回来时若带了活就先做完）。最多等 40 秒，等不到就下一分钟再看。红人采集是用户点按钮时才发生的，不算「活」；重载会让已经开着的 YouTube 页面上的面板失效，刷新一下页面就好（Chrome 对所有插件重载都是这样）。
5. **重载了还是旧版就放弃这一版**：不然从别的文件夹装的那份会每分钟重载一次。工坊再换一版会再试一次。
6. **正在跑的版本只放内存**：本机重启后等插件下一次来问（最多一分钟）就又有了；历史在事件日志里。少一次数据库迁移。
7. **「打开 Chrome 扩展页」**：直接起 Chrome 带上地址（已开着就交给开着的那个）。Chrome 不认（实测），所以同时把地址复制好请人粘贴。找不到 Chrome 但有 Edge 就开 Edge、复制 `edge://extensions`。
8. **点「打开插件文件夹」顺手复制路径**：Mac 的文件夹在隐藏的「资源库」里，Chrome 的选择窗口里不好找，⌘⇧G 粘贴最快。
9. 顺手修了：撤掉的配对不再算「连上了」。
