这份简版只写开源这一侧需要知道的事，不含私有仓里的实现细节与任何密钥信息。

## 1 做了什么

1. **带历史搬**：在开源仓 main（`ec2ca087`）的临时克隆上用 `git filter-repo` 只留云端路径（`apps/{cloud,cloud-worker,cloud-admin}`、`packages/{cloud-entry,metering,hosted,kol-cloud,kol-public,standby}`、`deploy/` 的云部分、`scripts/{demo-cloud-admin,import-kol-public,gen-cloud-openapi}.mjs` 与 `kol-migrate.test.mjs`、`docs/{49,61,64,65,83}` 与云端几单的报告），作者与日期原样，推到私有仓 `main`。主仓没跑 filter、没改代码、没 push。搬前扫过：这些路径里没有 MkSaaS / Plasmo 模板代码。
2. **私有仓怎么用开源仓**：开源仓作 git submodule 钉在私有仓的 `vendor/agentsws`（`ec2ca087`），pnpm 工作区逐个引入云端用到的开源包（`contracts`、`search-providers`、`stand-ins` 与它们的依赖链，共 39 个）。**没有发布任何 npm 包。**
3. **三层各自部署**（docs/83 §1）：一个 Worker 拆成 ① 账户与钱包（沿用原名，入口与自定义域不挪）、② 能力网关、③ 产品云，②③ 经 Service Binding 调 ① 的内部入口验令牌、动钱，自己不记余额。对外路径与 `packages/contracts/cloud-openapi.json` 一字不变：WP164 那整份契约用例在拆开的形态上又跑了一遍，全过。
4. **线上数据**：Durable Object 一个都没挪，七个类与迁移标签原样留在原来那个 Worker 里，另两层远程绑定。要不要真正挪进另两层待 Luoye / Fable 定。
5. 私有仓 CI：install / tsc / biome / vitest（含 WP164 契约一致性、WP165 真服务 ↔ 替身比对）/ wrangler dry-run；开源仓的对外契约在私有仓里对着 submodule 再核一遍零漂移。
