## 0. 一句话

插件第一次在用户后台建好「工坊日报」保存报表（出一张 L3 告知卡），之后每天本地 9 点后（电脑和 Chrome 开着才做得成）打开那几份报表、点「下载 CSV」；桌面端读下载的文件、用 WP314 的解析器认成**按天**的表现行入库，「今天」那份同步进广告库（面板数字块、日花费总闸、止损卡读的都是它）。插件一天没来领活就改读邮箱里平台发来的定时报表附件。**日报不是固定功能**：第一次有数后，在「广告日报」事项里种一条每天 10 点的官方自动化任务，提示词就是默认日报要求；到点 AI 用三个新工具取数、用 WP331 的 `publish_report` 发布，越线的提止损卡；改时间 / 改内容 / 停掉都是用户在那件事里说一句。

## 2. 给 WP316 的接口

- **广告库里的对象就是看数据同步进去的那一份**（`apps/server/src/ads.ts`）：`AdAccount.id = google:<客户编号>` / `meta:<广告账户编号>`（编号不带横杠、不带 `act_`）；
  `AdCampaign.id = <平台>:<账户>:<平台编号>`，`external_id` = 平台那一侧的编号——**导出里没有编号列时是 `name:<名字>`**（真站首跑看列补上没有；WP316 拼暂停 / 改预算活时遇到 `name:` 开头的应照实停，不能按名字点）。
  `metrics` 是「今天到导出时」的口径（止损判据、日花费总闸都按它），今天没数就没有 `metrics.spend`。
- **插件动作账户**：`brand.adsData.actionAccount('google' | 'meta')` → `buildAdsJob` 要的 `ActionAccount`（Google 带横杠的客户 ID + `ocid`）；回 `undefined` = 没设账户，回 `needs_setup: 'ads.accounts'` 就出同一张配置卡。
- **止损**：投放岗到点跑日报时用 `stage_ads_stop_loss` → `adsService.port.pauseCampaign(reason: 'stop_loss')` → 账本 L3。之后「批了交给插件暂停 + 已止损卡 + 截不到图先停（600）」是 WP316 的执行器那一段，本单一行没碰 `ads-service.ts`。
- **插件事件**：`server.ts` 里 `createAdsActionsService({ onEvent })` 现在依次转给 `redditWrites` 与 `adsData`（`adsData.onActionEvent` 只认自己排的 `adsrep_*` 活，别的事件原样放过）——WP316 接自己的 `finished / evidence / download` 时在同一处加一行即可。
- **节奏**：看数据的导出每账户每天占 1 次「读」（≤ 2）；WP316 的改前快照照 WP313 记在写操作里，不冲突。`fetch_ads_data_now` 再导一次会用掉第 2 次。
- **新动作种类**：`AdsReportAction`（`setup_daily_report` / `export_daily_report`）与原来的 `AdsAction` 并列（`adsPlan` / `buildAdsJob` 收两者的并集），没改 `AdsAction` 的成员，WP316 加撤销之类的种类不会撞。
- **想要最新数据**（比如读回核对前）：`brand.adsData.fetchNow({ platforms })`；导进来的行 `brand.adsData.rows({ since, until, platform })`。

## 4. 自主做的决定（白话）

1. **按天存、不只存最新一份**：日报要比昨天 / 前天、看走势；平台会回补几天前的转化，所以每天把最近 7 天整段重导、按「平台 | 账户 | 日期 | 对象」覆盖。留 90 天。
2. **同步进广告库只写「今天」的数**：广告库里 `metrics` 的口径是今天（总闸、止损卡都按今天算），今天没数的清掉旧数，不让昨天的数冒充今天。名字、状态、预算取最新那一天的。
3. **Meta 一份报表、Google 五份**：Meta 一行一条广告、上两层名字编号都在行里，广告组 / 广告系列由同一天的广告加出来；Google 的关键词、搜索字词加起来不等于广告系列（还有别的流量），所以各层单独一份。
4. **ROAS**：表里有平台那一列就照抄；没有就用**同一行**的转化价值 ÷ 花费（两样都是平台口径），跨天一律合计重算。工具结果里标了来源。
5. **账户怎么来**：插件打开后台要账户编号；不让用户找「客户 ID」，配置卡里贴一下地址栏的网址就行（认 `__c` / `ocid` / `act`），也认直接填编号。
6. **缺插件出专门一种连接卡**（`ads_backend`，接法还是插件配对）：只认「配对过」会在插件没连广告后台时就把卡判成已连上；复查认的是插件里勾过这家后台的风险告知。
7. **下载的文件按内容认**：自动化浏览器里下载是随机文件名，真 Chrome 也可能改名，所以不靠扩展名；Excel / PDF / 压缩包按文件头认出来就不读，说一句「导出时选 CSV」。
8. **工具里不写结论**：查数工具只给数（合计、排序、判据原话），哪条算差、怎么写、分几节由到点那次运行按用户的要求定。
9. **看数据的活不进审批**：导出是读（每账户每天 ≤ 2），只有建报表那一下是写（L3 告知卡编号当审批编号，满足 WP313「写必须带审批编号」）。
10. **种日报走官方工具同一条路**：自动化任务加了 `seed()`，由宿主替岗位建，上限、出卡规则与 AI 调 `schedule_create` 完全一样，之后 AI 用官方工具改得动（同一件事里）。

## 6. 偏离

- **告知卡不是「自动放行」**：审批总线只对 `staged_change` 自动放行，所以 L3 告知卡会留在卡片流里（见 803）。
- **派工单第 1 条「两家后台建立步骤」**：步骤表写了、在假后台上跑通，但选择器全是照帮助页推的英文界面写法，没对真站核（纪律不许开真后台）。
- **报表列名对照（619）「按真导出格式补全」**：没有真导出可拿，按两家帮助页与中文界面常见叫法补了别名（英文 + 中文），认不出的列照样留在 `raw` 里；真站首跑拿真导出再补。
- 没写 worktree 根的 `REPORT.md`（这次要求报告写在本文件并提交）。
