# WP338 报告：Reddit 不替用户定推广规矩（决策 664 / 783）

Luoye 10-15 在主对话**本人直接指令**：「783 这三个限制全部去掉，然后 C 改成可设置」。子代理两次被自动权限判定以「削弱安全护栏」拦下（转达的确认不算），之后由 Fable 在主会话照 Luoye 的直接指令完成。

## 做了什么
- **a 去掉「禁推广」推断**：`pr-service` 对 Reddit 不再按「保守默认版规」当成禁推广拦下；版规原文（插件借品牌号会话只读读回的那一份，WP328 / 764）放上卡：卡面「版规 N 条」/「没读到版规」，原文进卡的详情（notes）。论坛等别的平台照旧。
- **b 去掉冷却**：`pr/reddit.yml` 的「同一个版 72 小时」与冷却通知去掉；模拟世界 `world.ts` 同口径。
- **c 每天条数改成可设置、默认不限**：`pr/reddit.yml`（外部发帖 2 / 天、回帖 20 / 天）、`social/reddit.yml`（回复 30 / 天、群发 1 / 周）写死的数去掉；新 `apps/server/src/reddit-write/limits.ts`：四种上限用户设、默认不限、滚动窗口、只数出了卡的，到了不出卡并照实说；落盘在品牌目录 `reddit-writes/limits.json`；对话内配置卡目标 `reddit.limits`（人要设 / 改时才出卡）。接进公关外部发帖与 Reddit 写（社媒回复 / 发帖）。
- **不动**：版务类（管理动作 20 / 天、改版规 2 / 周）、`pr/forums.yml`、插件动作通道的限速与被拦就停。
- 快捷提问 / 任务示例文案改成「版规原文给人看、人判」。
- 场景：`pr/external-post-needs-approval-and-rules`（禁推广的版也出卡，两条都进队列）、`pr/subreddit-cooldown`（第二条照样出卡）；角色测试 Reddit 不再断言写死条数。

## 验证
新测试 `apps/server/test/wp338-reddit-no-rules.test.ts` 7 条 + WP332 测试共 24 条过；角色测试 29 条过；tsc 0 错；本体重出；其余见合并门禁。
