## 2 做了什么（白话）

**两种卡**（通用机制，不为哪一家写界面）：

- **连接卡**（`connect_request`）：要连哪几样（每样一行：标志 + 名字 + 绿勾 / 接法）、一句为什么，花钱 / 能动东西的（广告、管店、插件）多一行风险。接法按 `service` 挑现成组件：连接目录里的 → 授权页 / **本机原生表单**（`SecureForm`，口令只打连接面的 `/submit`）；Shopify → 一键授权；建站 → 装 CLI / 登录 / 选店那一行；管店 → 授权那一行；飞书 / 钉钉 → 团队机器人卡；插件 → 配对码；认不出的 → 「去连接页 / 消息渠道」。
- **配置卡**（`setup_request`）：缺哪几格就出哪几格（下拉 / 文字 / 数字 / 开关），**建议值预填**（如「官网就是这家店」），一个「保存并接着做」。秘密格一律不收。

**出在哪**：卡片流（首页 / 岗位页 deck）、事项时间线（同一张卡的投影，就地连 / 填）、第三栏（「去连接」开的连接卡：`agentsws://connect/<service>`，平时不占图标）。

**运行时**：一轮收尾时，工具回过 `not_connected` / 缺凭据 / 结构化缺项 → 出卡（同一缺项已有一张在等就把这件事挂上去，不重复出）→ 时间线记「在下面这张卡上连好，我就接着做」+ 那张卡。

**补完自动接着做**（照 WP304「选完按原话接着做」）：
- 连接卡：卡上那几样都连上了 → 卡自己点「接着做」（决定里**没有任何值**）→ 服务端复核真连上了 → 等着的每件事按原话再跑一次（时间线「连好了，接着做」）；没连上就说一句、再出一张新卡（等着的带过去）；
- 在连接页 / 第三栏连好：连接清单一变服务端复查，缺的都连上了 → 卡自己收起、接着做（只跑一次）；
- 配置卡：保存 → 只认登记过的格子、没改的用建议值、必填空着就再出一张 → 存进那个设置目标 → 接着做；
- 「先不连 / 先不设」：说一句，这件事停在这儿（不用写理由）。

配置页（连接、消息渠道、设置）一个字没删，仍是总览与管理。

## 3 通用卡的接口（给 WP322 / WP323 对齐）

契约在 `packages/contracts/src/setup-card.ts`（`@agentsws/contracts` 导出）。

**最省事的接法——工具回一格就行**（运行时自动出卡、补完自动接着跑，不用自己管去重与接着做）：

```ts
// 缺一样能就地连的（连接页 service / 'im:feishu' / 'im:dingtalk' / 'extension' …）
return { status: 'ok', data: { ok: false, needs_connection: 'im:feishu', connection_name: '飞书' } }
// 缺一步设置（先在服务端登记这个目标）
return { status: 'error', reason: 'needs_setup:sink.feishu_table 先选记到哪张表' }
// 或 data: { needs_setup: 'sink.feishu_table' }
```

**服务端直接要卡**（确认流程里用）：`setupCardsOf(ws)`（`apps/server/src/server.ts`，一个品牌一份）→ `SetupCardsAssembly`（`apps/server/src/setup-cards.ts`）：

```ts
askConnect({ needs: ConnectNeed[], why?, risk?, actor, matter_id?, run_id? })
  → { item: ApprovalItem; attach: boolean } | undefined   // 都连上了回 undefined；同一缺项复用那一张
askSetup({ target, why?, suggestions?: Record<string,string>, actor, matter_id?, run_id? })
  → 同上                                                    // 设好了回 undefined
registerTarget({ id, name, why, fields(), satisfied(), apply(values) })   // 登记一个设置目标
```

- `ConnectNeed = { kind, service?, name, required, state?: 'not_connected' | 'reauth' }`；
- `SetupField = { key, label, kind: 'text'|'url'|'number'|'select'|'toggle', options?, suggested?, suggested_why?, required, placeholder? }`——**没有 secret 这一种**：`isSecretLikeSetupKey()` 认出来的格子登记 / 出卡时就拒，秘密一律走连接卡的本机原生表单；
- 给了 `matter_id`（+ actor）= 补完后按这件事原来那段话再跑一次；不给 = 只出卡不接着跑；
- 去重键：`connectRequestDedupeKey(ws, needs)`（只看缺哪几样）/ `setupRequestDedupeKey(ws, target)`；
- 决定：连接卡 `approve`（无值）= 「连好了，接着做」；配置卡 `approve` + `edited_payload: { ...payload, values }`；`reject` 不用理由。

**工作台**：卡片流 / 时间线里自动按 `payload.form` 画（`components/setup/setup-deck-body.tsx`），不用另写；要在第三栏开连接卡用 `useOpenConnect()(service | services)`（`components/setup/use-open-connect.ts`）；要新加一种接法，在 `components/setup/connect-widgets.tsx` 的 `ConnectWidget` 里按 `service` 加一个分支、复用已有组件（飞书记录这类「能力」不需要新加：飞书机器人卡已经在）。

## 4 自主做的决定（白话）

1. **新加两种卡**（`connect_request` / `setup_request`），没塞进 `ai_question` / `policy_change`：它们补完要「复核真连上了 / 存进设置」再接着跑，复用别的卡会被别的决定钩子接走。排版借「策略」那一种的骨架，主按钮放卡身里（连接 / 保存），卡底那排去掉 approve，只剩「先不连 / 先不设」「稍后」；键盘提示跟着实际按钮走。
2. **去重只看缺哪几样，不看哪件事**：两件事撞上同一缺项只有一张卡，补完两件都接着跑。
3. **在别处连好也算**：连接清单一变服务端复查（只对查得到的接法）；人点「接着做」时查不了的（企业微信、微信扫码这类）就信人。
4. **建站工具 / 管店授权当「连接」**：卡里直接放岗位页那一行（装 CLI、登录、选店 / 授权），不另造一套。「不知道哪家店」单独是配置卡（选一家，官网那家当建议值）。
5. **配置卡的建议值**目前来自规则（官网那家店），模型还不能自己要卡（决策 724）。
6. **第三栏连接卡不占图标**（注册表加了 `hidden`，只按地址开）——界面少字少图标。
7. **消息页「去连邮箱」原来跳 `?service=email`，连接页认的是 `imap_smtp`，落不到那张卡**——顺手改对（现在开第三栏 `imap_smtp` 表单）。
8. 「先不连 / 先不设」不要求写理由（不是对内容说不，没有学习信号）。
9. 连接页本身（`pages/connections.tsx`）一行没动；卡里那条「就地连」是另写的一个小 hook（`use-connect-flow.ts`），与连接页同一条接口、同一套凭据纪律。没为了复用去拆连接页，免得动到总览页。
