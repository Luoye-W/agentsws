## 2 我自主做的决定（白话）

1. **币种是最弱的信号**：美元 / 欧元多国通用，只认一国一币的（英镑、加元、日元…），而且只在别的信号一个都没有时才用、标「请确认」。欧元一律不猜。
2. **「卖全世界」不算目标市场**：国家切换或店里配的市场超过 25 个，那是没设限，不是目标——不填（否则每周探测会乘出几十倍的钱）。
3. **中文站的「国内 / 全国 / 大陆」算中国**，「只发香港、澳门与台湾」认得出港澳台；「其余国家暂时不发」这类否定句不算。
4. **出处的归属**：品牌分析确认时，证据全是 Amazon 站点那一条记 `amazon`，否则 `site`；人在档案卡或设置页改过的记 `human`，之后自动推断与店铺校正都不再覆盖——人说了算。设置页原样保存（没动市场）不发 `markets`，服务端也按「一样就不改出处」兜一层。
5. **店铺校正只做一次**（每条连接一次），挂在「连接清单变了」那一声上；读不到不记「校正过」，下次再试。「告诉用户改了什么」= 那一句写进档案出处，设置页常显 + 事件日志；没另出一张卡（它不是要人拍板的事，36 §「只有要人拍板的才是卡」）。
6. **每日 SERP 人群核对**：有一个市场人群对就可以写新页（选题卡带每个市场的结论），每个市场都不对才划掉；次数上限从「一天 5 次」改成「每个市场一天 5 次」——市场多了花费跟着乘，与每周探测同一个口径。
7. **语言不跟市场换**：探测仍用品牌语言。问题是按品牌语言生成的，换成德语去问反而对不上；以后要按市场换语言再议。
8. **Search Console 不按国家拆**（docs/82 §8）：中小店曝光少，按国家切信号都响不起来；按市场分开只在「探测」那一层。
9. **读正文用 `list_*` 按 handle 查**：Shopify 的 `get_page` 等要 id，网址里只有 handle；`query: 'handle:<h>'` 再按 handle 精确对上，对不上且只回一行时才用那一行。正文截 4000 字符（约 600–800 个英文词），写成常量。
10. **公开网址的闸比品牌分析更严**：品牌分析抓的是用户贴的网址；这里抓的是 Search Console 给的页面，所以只认自家域名（品牌档案 + Search Console 认出来的），IP、内网名、保留域名一律不抓。
11. **面板上关市场只关探测**：`GeoSettings.markets_off` 存在内容与搜索的状态文件里，不碰公司档案；违规宣称规则仍按全部目标市场开组。

## 3 需要 Luoye / Fable 定的事

1. **多市场的花费**：卖三个市场时每周默认 6 × 3 × 3 × 0.2 = 10.8 积分（一个市场 3.6）。要不要在向导里选了好几个市场时提示一句「每周探测会按市场乘」？现在只在内容与搜索面板上写明，并能按市场勾掉。
2. **每日 SERP 次数上限按市场乘**（每个市场一天 5 次）——还是整体 5 次、多市场时少查几个词？我按「每个市场分别探」的口径选了前者。
3. **店铺校正的提示方式**：现在是设置页那一句常显 + 事件。要不要另在首页 / 消息里推一条？
4. **按市场换探测语言**（德国市场用德语问）：这一版没做（理由见上 §2 第 7 条）。
5. **Shopify 读正文的入参**：`list_pages` 等用 `{ query: 'handle:<h>' }`，按 OpenConnector 的 GraphQL 搜索语法写的，没连过真店核对（全是替身）。第一次真店冒烟时请看一眼卡上是不是「读过这一页的正文」。
