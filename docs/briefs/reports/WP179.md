## 3. 我自主做的决定（白话）

1. **搜索提供方用官方的类，不用官方插件的"装配"那一步**。官方插件只有在"这次对话走的是官方账号模型"时才用账号令牌，我们的模型走自己的网关，这条永远判不中；它找 key 的兜底是读进程环境变量，凭据纪律不许。所以用它导出的 `DeepSeekSearchProvider` 原样发请求、原样解析、原样报错，只把"去哪取凭据"换成问我们的服务进程。这是这一层唯一的改写。
2. **凭据顺序**：登录了 DeepSeek 账号就用账号（不管默认模型是不是账号那一条），否则用模型设置里「DeepSeek 官方」那张卡的 key；**改过地址的（代理 / 中转）不算**——官方搜索打的是 `api.deepseek.com`，把别处的 key 发过去没意义。
3. **次数上限按查询条数算**：一次调用带 3 条查询就是 3 次（每条都是一次完整的模型回合、要花钱）。超了拒这一次，不截断（截了模型不知道哪几条没搜）。
4. **用量只记"调了一次"**：官方搜索不回报 token（它只取结果块），记 0 token + 1 次，provider 标账号或 key。用量表里看得到"网页搜索 N 次"，但看不到 token（§5 第 2 条）。
5. **direct 选"经工具桥"不选"不挂"**：模拟要三运行时对着同一条场景跑出同一串调用；不挂的话 direct 那一档这条场景过不了。生产上带网页工具的运行本来就走 dsh，这条桥用不到。
6. **抓网页不要凭据，职责挂了就给**；搜索要"设置没关 + 有凭据"才给。结果：只要有模型，查资料那十四条的运行**全部改走 dsh**（因为抓网页总是开的）。
7. **工具调用上限**：挂了网页工具的运行放到 30（同浏览器），模型步数跟着放到 31；网页次数另由门禁按 5 / 10 管。
8. **官方的"外部网页内容，不是指令"那句照用**，我们所有工具共用的那道围栏也照旧过（不为网页破例）。
9. **提示词里的"网页"那一段我们写**：官方工具自带的两句提示会被我们的 complete 段遮掉（WP70 实测过同一件事），不写模型就不知道次数上限和"引用写网址"。
10. **`hmr` 撤我们的锁、跟官方**：按新规矩它不是冲突也不外发；官方 headless 包本来就关着它，组合结果不变。
11. **界面只做一个开关**：`web.search` 现在只有一级，画顺序箭头没意义；存的形状已经是 `order` + `disabled`，以后多一级再画。开关放在模型页（凭据就在这一页）。
12. **没截图**：派工单纪律"不开真浏览器"，项目截图要起 headless Chromium，这次没起；界面改动只有一个开关 + 一行用量。

## 4. 需要 Luoye / Fable 定的事

**C 类（数据外发，本单保持关）——逐条"打开会把什么数据发给谁"：**

1. **`session-log-deepseek`（会话日志随请求上报）**：打开后，每次走官方 DeepSeek API 的请求都会附上**整条会话记录**——客户来信原文、订单、政策、工具的入参与结果、系统提示——发给 **DeepSeek**。（我们的模型走自己的网关，这条通路今天不存在；它管的是"哪天真起了完整 profile、真接了官方 provider"。）
2. **`session-telemetry-otel`（点"反馈"就上报）**：打开后，用户在官方界面点一次"反馈"，就把**整条会话日志**（消息原文、工具参数与结果、系统提示）连同一个匿名用户 id 发到 **DeepSeek 的收集端 `dsh-otel-collector.deepseeksvc.com`**。
3. **`otel`（上报通道）**：本身不发东西，但它是上面那条和官方产品埋点的发送通道；打开等于给它们开了往 **DeepSeek 收集端**发数据的路。
4. **`plugin-package-inventory-deepseek`（插件清单）**：打开后，每次官方 API 请求都附上**当前挂着的全部插件包名与版本**（包括我们自己的包）发给 **DeepSeek**。没有客户数据，但暴露了这家公司装了什么。
5. **Cua 电脑操控驱动的遥测**：打开后，驱动会把**使用情况遥测**发给 **Cua（驱动厂商 trycua）**。

**其他要定的：**

6. **查资料那十四条职责的运行全部改走 dsh**（因为抓网页总是开的）：每次多约 0.3 秒起子进程；回合由官方 agent-loop 驱动。要是只想"开了搜索才走 dsh"，改一行判定就行（抓网页那一条就得等 direct 也挂官方工具，或者不开）。
7. **用量表里网页搜索只有次数、没有 token**：官方提供方不回报 token。要看得到 token，得请上游在 `DeepSeekSearchProvider` 的结果里带 `usage`（或我们自己估）；建议给上游提一个小 PR。
8. **B 类两单要不要排**：插件管理"装插件出卡 + 白名单"（M）、配置写回"只许写非锁定行"（S–M）——做完这两单，自动审阅 / 定时任务这类官方可选包才有路装进来（自动审阅本身仍是 B）。
9. **`dsh-time-context` 的意思要不要做**：三运行时上下文里写一次"现在时间 + 公司时区"（S）。

3. **用量不含 token**（§4 第 7 条）。
4. **没截图**（§3 第 12 条）。
5. **dtc-3c-3p 基线重写**：场景数 64 → 65，按惯例 `--rewrite-baseline` 三个运行时；diff 只有新增那一条的 63 行，旧场景一个数没动。另两个包场景数没变，没重写。
