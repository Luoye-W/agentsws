## 2. 自主做的决定（白话）

- **怎么读的**：agency-agents 浅克隆到会话临时目录（提交 `83294689`，2026-10-04），没进仓库。282 个角色文件用脚本逐个统计小标题与指标（有没有交付物、成功指标带不带数、有没有出处、写没写上下游）；和出海相关的约 40 个读了正文（十来个全文，其余读硬规矩、交付物、工作流、指标几段）；`strategy/`、`examples/`、`CONTRIBUTING.md`、`integrations/dsh` 全读。星数与许可证用 `gh api` 取。没有登录、没装任何东西。
- **对照的单位**：它的一个角色文件，在我们这边是 persona + 职责 yml + 技能 + 卡片四样拼起来的，所以写法对照是拿这四样合起来比，不是只比 persona。
- **「按人切」当判据**：它按工种切（付费广告 7 个角色），我们按 50 §0「中小公司里同一个人干的一摊」切。所以它的大多数角色我判成「落成技能或动作」，而不是「新开职责 / 岗位」；缺口六样都判成**不必新开岗位**。这一条写进了待定事项第 1 条，Luoye 不同意可以翻。
- **persona 骨架不动**：60 段 persona 中文中位数 242 字、三段已到 259 字（上限 260），而交付物模板、自检清单是按需才用的东西，所以建议补在技能（两个固定小节）与职责 yml（结构化 `handoffs`），不加 persona 的第七段。
- **改写示例没落盘**：示例 1（`ads.meta` 的 persona）在临时目录里用 `checkPersona` 跑过（六段齐、中文 248 / 英文 911 字），只贴在文档里；示例 2（`returns-policy-calc` 补三节）是改写示范。工单说「不批量改」，我理解为这一单一处都不改。
- **核实时改正了自己的两处初稿**：合规那条原来写「我们没有宣称合规」，查到 WP159 的违规宣称规则表已经有了（按市场分组、带出处），只是只接在内容那条的发布前质检上，于是改成「已有一半、要接到其他对外出稿上」；客服冲突那条按原文重写（它另一条「不给替代方案就别说做不到」其实可借）。

## 3. 需要 Luoye 定的事

见 91 §7，五件：
1. 后台六样（经营周报、合规、定价与单位经济、客户声音、实验、本地化）不开新岗位，落成技能挂现有职责，经营周报挂「公司设置与授权」。
2. 广告自动止损线维持固定「ROAS < 1」，还是改成按毛利算的盈亏线（毛利 40% → 2.5）；建议先只并排显示、跑两周再定。
3. 选品与趋势做不做（超出现在的范围，要第三方收费数据）。
4. 短视频成片归谁：设计岗加一条「视频」职责，还是暂不做。
5. 跨岗位活动模板（新品上市 / 大促）要不要做成产品里的东西。
