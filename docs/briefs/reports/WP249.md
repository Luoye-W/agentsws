## 1. Reddit 接口可用性结论（要做 1）

**结论：新用户基本拿不到官方 Data API，必须有不依赖它的主路线。**

- 2025-11-11 Reddit 发布「Responsible Builder Policy」，同日**关掉了 Data API 的自助申请**：开发者、研究者、
  版主要用 Reddit 数据都得先提申请、人工审批（官方说目标 7 天内答复）。版主被引导优先用 Devvit（Reddit 自家的
  应用平台），Devvit 满足不了再去申请。来源：r/redditdev 官方公告（2025-11-11，帖子
  `1oug31u/introducing_the_responsible_builder_policy_new`，经镜像站与搜索摘要核对；按纪律没打开 reddit.com 本站）；
  Reddit 帮助中心那篇政策原文对我们的抓取回 403，没读到全文。
- **已有 OAuth 应用的用户**：公告写明「现有访问不受影响」，照常能用。工作台里填了 client id / secret / UA 的，
  自家版队列、版务动作、发帖、置顶全走接口（`social-core/channels/reddit.ts`：`/r/<版>/about/modqueue`、
  `/about/unmoderated`、`/about/rules`、`/api/approve`、`/api/remove` + 移除理由 `/api/v1/modactions/removal_*_message`、
  `/api/friend`），每分钟 60 跳自己数。
- **拿不到的用户（多数，含 INMO 版主号）**：走「Reddit 官方号浏览器通道」（§3），这是默认主路线。
- **入群申请**：公开 Data API 里没有「私密版入群申请」的读口（只有「批准用户」名单与加人），old.reddit 也没有对应页面
  ——两条通道都照实显示「读不到」，不当 0 条（要定的事 3）。

## 3. 浏览器通道设计与账号风险（要做 5 的方案已按决策 89 实现为主路线）

**怎么保证「只执行批过的那一个动作」**：三道闸都在驱动层，不靠提示词——
① 执行器拿的是卡上的结构化字段，生成一串确定步骤；② 每一步先问 `stepAllowed`（按动作种类的白名单：
批准只能点那一条的 approve；回帖只能填那个框、填的字必须与卡上一致）；③ 网络层（CDP Fetch，每一跳都停下来问）
只放这个动作要的 POST（批准只放 `/api/approve`），点赞、订阅、页面里别的脚本发的写请求全掐。做完读回页面自证
（队列里没了 / 封禁名单里有他 / 评论区有这段字 / 落到新帖页），自证不过算没做成。

**我们不碰的**：密码（用户自己在窗口里登）、cookie 内容（只活在那个独立目录里，浏览器自己存）、任何「藏自动化 /
伪装 UA」的开关。

**账号风险（实话）**：Reddit 的用户协议不欢迎未经批准的自动化，浏览器代办有被判成机器人的可能——最坏是官方号被限流、
要验证码、甚至封号。我们压低风险的办法：每个动作都是人批过的（频率天然低）；写两次至少隔 20 秒、一天封顶 30 个；
读两页隔 4 秒、一天 150 页、只在打开这个视图或点「刷新」时读（不轮询，5 分钟内不重读）、版规 6 小时读一次；一次只开一页；一被拦就停、
不重试、不换身份，提示人去窗口里处理；读别的版不用官方号（决策 88，那是 WP246 的读号）。
有 OAuth 应用的话优先走接口，这一层风险就没有了。

## 4. 我自主做的决定（白话）

1. **读用 old.reddit 的 `.json`，读不回来再看页面**：old.reddit 每个列表都有 JSON 版本，和官方接口回的是同一个形状，
   两条通道共用一个解析器，比扒页面稳；页面那条退路认 `div.thing` 的 `data-*` 属性（old.reddit 多年没变的写法）。
2. **「AI 建议」先用规则判，不叫模型**：按这个版自己的版规名 + 广告 / 骂人词表 + 外链数判，引用的是版规原文短名；
   判不准就说判不准（「先别动，你看一眼」）。不花积分、离线可用、测试钉得死（要定的事 4）。
3. **「先不管」不出卡、不碰 Reddit**：只在本页藏起来（刷新会再出现）。Reddit 的「忽略举报」是另一个版务动作，没做。
4. **自家版的版务卡排成「改动卡」**：卡片表里 `community_moderation` 原本是「事后决定」（主按钮「解除禁言」），
   那是按「已经做了、问要不要撤」画的；自家版这一类是做之前的卡，按原样会让人点「解除禁言」去批准一次移除——
   所以只给这一类改排版（别的 `community_moderation` 一个字节没动，见要定的事 5）。
5. **移除理由在两条通道上做法不同**：接口走 Reddit 的「移除理由」口（公开留一条）；浏览器那条是在帖子下公开回复一句
   （评论的楼中楼这一版不做）。卡上写清会公开说什么。
6. **批了过 2 分钟才执行**：用账本原有的取消窗口（120 秒），批错了还来得及撤。
7. **登好之后自动收起登录窗口**：之后读写都在看不见的那个里做，不再弹窗；被拦了再点「登录官方号」开窗口处理。
8. 官方号浏览器写也限速（隔 20 秒）：同一刻批了两张卡，第二张会照实失败「要隔 20 秒」，在卡片流点「重试」即可。

   有余力再去申请一次 Data API（版主用途），批下来就自动走接口。**
3. **入群申请读不到**：两条通道都没有读口。**建议：先这样（视图里一行「读不到」+ 问号说明）；r/inmoxr 若是私密版、
   申请量大，再评估做一个 Devvit 小应用把申请转给我们。**
4. **AI 建议要不要叫模型**：现在是规则判（不花钱、可解释）。**建议：先用规则；看一两周 Luoye 改判的比例，
   高了再加「模型复核」（每条约 1 次小调用的积分）。**
5. **别的社群的 `community_moderation` 卡排版**：卡片表把它当「事后决定」（主按钮「解除禁言」），但社媒库现有的删帖 /
   禁言 / 封禁卡也都是「做之前」出的（风险档 medium，从不自动执行）——按钮字是错的。**建议：另开小单统一改成改动卡，
   顺便补上这类卡批了之后的执行（现在只有自家版这一类会真执行，见 §7）。**
6. **移除理由的公开说法**：现在是英文一句 `Removed: this breaks r/<版> rule "<版规>".`。**建议：就这样（版是英文版）；
   要更客气或带链接，给我一句模板。**
