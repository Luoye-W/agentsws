## 2 做了什么（白话）

**一条路**：知识库里传一份 xlsx / xls / csv → 后台看一眼是不是问答表 → 是就在卡片流里出**一张**「定规矩」卡 → 人点「记下」→ 表里一行变成一张知识卡 → 客服 / 聊天起草回复检索知识时就能用上。

- **读表**（`packages/knowledge/src/sheet.ts`、`sheet-xls.ts`）：xlsx 是 zip + XML，xls 是 OLE2 + BIFF8，自己读，**没加任何依赖**（服务端原来一个表格库都没有；工作台那份 exceljs 是浏览器用的，xls 它也不认）。合并单元格把左上角的值铺满整块；隐藏的工作表不读；每表最多 5000 行 × 50 列；zip 条目先看声明大小再解、解压带上限（防压缩炸弹）；读不懂就当它不是问答表，不出卡、不报错（上传本身照常成功）。
- **认列**（`faq-import.ts`）：每张表先找表头（前 20 行里找，上面有标题、空行、说明都行），按常见列名认「问题 / 答案 / 分类 / 适用产品 / 语言」，中英都认，括号里的注不算（「答案（英文）」= 答案），「问题分类」认成分类不是问题。**规则认不出问题和答案两列时才问 AI**（这个品牌配的模型、`extraction` 档、不思考、封输出上限），AI 回的 JSON 要验：表名对得上、行号在表里、列在表宽里、问题和答案不是同一列，不合格就当没认出来。没接真模型只按规则认。
- **读行**：空行、分节标题（合并后整行一样的）、中间重复出现的表头都跳过；只有问题没答案的记一笔「缺问或答」；问题那格竖着合并、答案分几行写的，把答案接起来。
- **和库里比**：按「问题」去重（全半角、标点、大小写、空格不算不同），范围是这个品牌所有的 FAQ 卡。结果分四种：新的、答案变了、没变、上次从**同名表**导进来但这次表里没了。
- **定规矩卡**（`policy_change` + `form: 'faq_import'`）发给传文件的人：每张表一行「问题 ← 客户常见问题」这样的列对照（AI 认的标一下）、新问答一两行预览、答案变了的一条改前改后、几个数（新 / 改 / 没变 / 表里少了 / 缺问或答，只出不为 0 的）、表里少了的问题一行灰字。按钮就是选项：「记下 / 不用」，既有新的又有改的时多一个「只加新的」；**只删了行、别的都没变**时是「撤下 / 留着」。什么都没变不出卡。
- **点了之后**：服务端按卡上的列对照**重读原件**（卡上不背整张表），一行一张卡：事实层、`subject.type = 'faq'`、分类进 `subject.id`、那句话是 `Q: 问题（适用产品）\nA: 答案`、完整原话在 `structured`、出处 `文件名 › 工作表 › 第 N 行`（ref 是原件那一版）。
  - ① 个人 / ② 同事互联：当场生效（人自己点的，docs/95 §5）；
  - ③ 公司：点的人就是负责人也当场生效；不是 → 卡落「待确认」，给负责人**一张**「改东西」卡（`knowledge_update` + `form: 'faq_batch'`），通过 = 整批生效，不要 = 整批退役（留痕）；
  - 答案变了的：新卡生效时旧卡退役（不删），两张卡上互相记的冲突收掉；
  - 表里删掉的行**不自动删卡**，只在卡上提示；只有删行时点「撤下」才退役。
- **检索**：核对了四条起草 / 回答路径——客服来信（`searchKnowledge`）、聊天窗、随便聊、运行时查政策（`searchPolicies`）——都是 `knowledge.retrieval.search`，不按 `subject.type` 过滤，所以生效的 FAQ 卡都检索得到（端到端里中英两条都命中）。**社媒 / Reddit 的回帖起草现在根本不查知识库**（`social-reply-draft.ts` 只看对方原话），要等 docs/102 的 O5 接，见 §3 决策 708。
- **工作台**：卡片流里两张卡的样子（`faq-import-body.tsx`）；知识库页多一组「常见问答」（FAQ 卡不再按里面的词散到物流 / 政策 / 其它），客服、社媒岗位第三栏先看这一组。
- docs/19 §1.3 补了一段 FAQ 表导入的规则。

## 3 要 Luoye 定的事（每条附建议）

| # | 事 | 建议 |
|---|---|---|
| 700 | 答案里带货币金额的 FAQ（「满 $50 包邮」「运费 9.9 元」）进库时会被现有的状态词闸（47 J2，「宁可误伤」）降成「历史案例」——检索仍命中，但模型会把它当「当时的情况」。要不要让 FAQ 表导入的行跳过「带货币金额」这一条（订单号 / 物流状态等其余状态词照降）？ | 建议跳过：FAQ 表是人自己写的现行口径，金额就是政策；本单没改，等你定 |
| 701 | 认列先按常见列名认，认得出就**不问 AI**（省钱、结果固定）；认不出才问 AI。 | 建议同意 |
| 702 | ③ 公司模式两步：传的人先确认列对照，内容再交负责人一张整批卡；负责人自己传只有一张卡。 | 建议同意 |
| 703 | 表里删掉的行只提示、不删卡；只删了行的那次卡上给「撤下 / 留着」。 | 建议同意 |
| 704 | 去重范围是整个品牌的 FAQ 卡（不分哪份表）：两份表里同一个问题答案不同，后导的那份会出「答案变了」。 | 建议同意（同一问题品牌里只该有一个口径） |
| 705 | 答案超过 500 字：卡上那句话按契约截到 500 字，完整答案在 `structured.answer`；检索回的是那句话，起草看不到超出的部分。 | 建议先这样，O5 起草时改读 `structured.answer` |
| 706 | 列对照认错了怎么改：服务端已支持（卡上「改」带新的对照），工作台卡上目前只有「记下 / 不用」，没做改列的下拉。 | 建议先不做（界面少字），等真用户反馈；认错时点「不用」、改表头再传 |
| 707 | 隐藏的工作表不读（多半是下拉选项的底表）。 | 建议同意 |
| 708 | 社媒 / Reddit 回帖起草现在不查知识库，FAQ 卡只有客服 / 聊天 / 随便聊 / 运行时用得上。 | 建议放进 O5（`reddit-ops` 起草）一起接，不在本单补 |
| 709 | Excel 95 那种更老的 .xls 不认（提示另存为 xlsx）；日期格读出来是 Excel 序号；判断「是不是问答表」最多读 8 MB 的原件。 | 建议同意 |
