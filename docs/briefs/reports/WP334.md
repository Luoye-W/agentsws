## 1 做了什么（白话）

**① AI 自己要卡（724）**：所有职责多了一个通用工具 `request_setup`。AI 干到一半发现「要先连上 X / 要先设好 Y」，就调它，给服务名或设置目标 + 一句为什么（+ 建议值）。

- 工具本身**不出卡**：它只回一格结构化缺项（`needs_connection` / `needs_setup` + 为什么 + 建议值）；这一轮收尾时运行时照 WP324 的老规则出卡、去重（同一缺项只一张）、补完按原话接着做。所以「AI 要卡」和「工具撞上缺项」走的是**同一条路**，没有第二套。
- 已经连上 / 设好了：工具直接说「已经好了，接着做」，不出卡。
- 认不出要的是什么：把能要的那几样列给模型，让它改。
- 卡面那一句「为什么」用 AI 给的；配置卡预填 AI 的建议值（只认登记过的格子，下拉只认可选的值）。
- **口令永不进 AI**：参数里没有任何一格收凭据；「为什么」「建议值」里像口令 / 密钥（`sk-…`、长串令牌、`password: …`、「密码是 …」）的整条拒收，回话里不回显那段字；像秘密的设置键也拒。
- 三个运行时同一份参数表：stub / direct 走 `assemblePrompt` 的工具表，dsh 走 `themeParams` 那条转法（严格参数表：嵌套对象关上、必填落到属性上），钉了测试。stub 有一段剧本：话里明说「先连上 X / 先填好 Y」就要卡。

**② 企业微信表单与微信扫码进卡（725）**：

- 连接卡上 `im:wecom` 那一样，就是消息渠道页那张**本机原生表单**（BotID + Secret；FormData 收、提交只打 `PUT /v1/im/wecom`、提交完清空）。只有负责人 / 公司管理员能填，别人看到「连接由负责人来连」。
- `im:wechat` 那一样，就是扫码那一块（条款风险那一行留在卡上）。
- 两块都从消息渠道页拆成共用的件（`components/im/wecom-bot-form.tsx`、`wechat-bind.tsx`），消息渠道页换成用它们，样子没变。
- **连好自动接着做**：卡上那几样都连上了，卡自己点「接着做」（决定里没有任何值）；在消息渠道页连好也算——企业微信 / 飞书 / 钉钉**第一次连上**现在记一笔 `im.connected`，服务端据此复查还在等的连接卡，连上了就收卡、接着做。

**③ 剩下几类改成就地卡（726）**：

| 缺什么 | 以前 | 现在 |
|---|---|---|
| 没接模型 | 顶栏胶囊 / 黄条、随便聊「去设置」 | 开第三栏「接模型」连接卡（与开工向导第 ① 步同一个件：工坊接口 / DeepSeek 官方 / 自己的 key，key 走本机原生表单） |
| DeepSeek 账号登录过期 | 「去设置 → 模型点一下重新登录」 | 用账号跑的那件事停下 / 没跑成时出连接卡，卡里就地重新登录，登好按原话接着做 |
| 工坊账号没关联 | 「去设置 → 账号与积分」 | 工具回 `not_linked`（红人公共库、红人搜索…）/ 生图没配 → 连接卡里关联（与设置页同一个注册 / 登录表单）；红人「关联官方账号」、值守「去关联」按钮也改开第三栏 |
| 没有发信邮箱 | 「先在连接页接一只」 | 开发信一只邮箱都没有 → 连接卡（连接目录里的「邮箱」，本机原生表单） |
| 公司档案没填 | 「去设置 → 公司档案」 | 新设置目标 `company.profile`（一句话介绍 / 客服邮箱 / 币种）走配置卡；开发信缺公司地址那句也改成「在卡上填好就接着发」 |

设置页、消息渠道页、连接页一个字没删，仍是总览与管理。在设置页接好模型 / 关联好账号也算：模型配置变了、云账号关联上了，服务端都复查一遍还在等的连接卡。

## 2 自主做的决定（白话）

1. **工具不直接出卡，只回结构化缺项**：这样去重、挂事项、补完接着做全用 WP324 那一套，AI 要卡与工具撞缺项不会出两张。
2. **一轮里有好几句「为什么」，用第一句**；建议值按设置目标合并。
3. **stub 剧本排在「店主问岗位 / 连接」前面**：「先连上企业微信」是要连，不是问连了哪些（不然店主职责会去列连接清单）。只在工具面里有 `request_setup` 时生效，模拟世界不挂这个工具，字节不变。
4. **个人微信跟人走**，服务端查不了「这张卡的人扫没扫」：卡上扫完由卡自己接着做；在消息渠道页扫完，回到卡上那一行变绿、卡自己接着做（服务端不自动收）。
5. **生图没配 → 「关联工坊账号」卡**（关联了就走云上生图，WP274 的规则），不是「接模型」卡。
6. **DeepSeek 账号**：用账号跑的运行以 `unauthenticated` 没跑成、或登录失效被停下，都在收尾时挂一样 `deepseek_account`；顺手把模型网关那两句「去设置 → 模型」改成「重新登录后就接着做」。
7. 连接卡里的「接模型」用开工向导第 ① 步那一个件（三张小卡二选一），去掉了「先逛逛演示数据」那条旁路（`onDemo` 改成可选，向导里照旧有）。
8. 第三栏开不出来（极少：没有外壳）时退回哪一页按 service 定：模型 / DeepSeek → 设置的模型那一档，工坊账号 → 账号那一档，IM → 消息渠道页。
9. `workshop_account` 用我们自己的标志图标；`model` / `im:wecom` 等没有专属图标的落通用插头（没动图标别名表，免得碰官网图清单的对表测试）。

## 3 需要 Luoye 定的事（决策 790–794）

1. **（790）`request_setup` 作为所有职责的通用工具**，工具只回结构化缺项、卡在收尾时出（与工具撞缺项同一条路）。**建议**同意。
2. **（791）卡面用 AI 的那句「为什么」，建议值预填**（只认登记过的格子、下拉只认可选值；像秘密的整条拒收、不回显）。**建议**保持。
3. **（792）个人微信扫码在别处扫完不会自动接着做**（服务端查不了是谁扫的，只有卡自己看得到）。**建议**先这样；以后连接卡带上「谁的卡」再改成服务端也能复查。
4. **（793）生图没配出「关联工坊账号」卡**（走云上生图），自己有生图接口的人仍去设置页「生图」那一块。**建议**保持。
5. **（794）还剩几处跳设置页没改**：开发信面板「公司地址去设置」（运行里已经出配置卡，面板上那个静态链接没改）、余额不足去充值、顶栏模型 / 积分芯片、Shopify 卡「重新登录工坊账号」、联网搜索没 key 那一句。**建议**：公司地址那一处下一单做（要一条「按设置目标在第三栏开配置卡」的路），其余是管理 / 充值不是「缺设置」，保持去设置页。
