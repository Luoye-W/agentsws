## 2. 我自主做的决定（白话）

1. **卡片上那一句用前端词条，不改服务端模板。** 服务端给的厂商介绍是只有中文的一两句话。我在前端给每家写了一句压好的中英文，服务端原话放进问号，于是一个字没丢，英文界面也不再显示中文长句。服务端的 `steps` / `links` 不动：契约只加不删，第三方模板也还在用。
2. **教程对照表放在前端**（`HELP_BY_VENDOR`，厂商 id 对应文章），没往模板契约里加 `tutorial` 字段。加字段就要重出 SDK、动契约，而现在只有六家。服务端测试里另写了一份同样的对照表，用来盯外链；两边对不上时测试会红。
3. **第三方模板没写文章的，「看教程」弹对话框**，把它自带的步骤与外链排出来。不然这些模板的步骤在界面上就彻底看不到了。
4. **浏览器 bsk 的「①②③」保留。** 每一步都挂着按钮（装扩展 → 一键装 bsk → 检查），它们是操作，不是说明书；每步底下的说明进了问号。**两个商店链接改成按钮**：那就是第一步的操作，不算参考外链（守卫认 `data-slot="action"`）。
5. **安全承诺压成一句、仍然可见，完整原话放在旁边的问号里。** 浏览器、电脑操控、订阅风险、Stripe 付款这四处都这么做。电脑操控原来那段 130 字的风险说明，卡面上只留「停下请你来、随时能停止」；「和坐在你电脑前的人一样」「截图发给模型」在问号里。
6. **用不了的选项，原因直接写出来**（例如「服务不在你自己的电脑上」）。它算状态，不算说明：灰掉却不解释，人会以为坏了。
7. **守卫的量法**：标题、带输入的 label（字段名、单选或勾选项的名字）、数据区（余额数字、清单）不算说明；汉字一个算一字，英文一个词算一字。量的是「人要读的解释」。这套口径写在 `less-text-guard.ts` 头注释里，下一轮直接照用。
8. **向导第 ④ 步按行量**：每个连接、技能、岗位各算一张小卡。它整体是一张「计划」清单，列出来的都是结果。
9. **教程面板不跟岗位走**（不 `scoped`）：「怎么接 DeepSeek」和当前在哪个岗位无关。
10. **i18n 里被搬走的两条（`settings.browser.scope`、`settings.browser.bsk.compare`）删了**，内容分别并进了问号和教程；其余长句改短，另加 `*.hint`。
11. **搜索数据那篇教程**：派工单写「WP155 合进来后补一句占位即可」。合进来时 WP155 已经有 docs/81 和卡面文案，我就照它写全了（三档、三家服务商、怎么接），没留占位。
