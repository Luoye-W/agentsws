## 一、第一版做法（外部 Chrome）实测：这条路走不通

派工单原写「本机 Chrome 无头打开 Google，被拦退 Bing，再退 DuckDuckGo」。动手前用**临时用户目录**的本机 Chrome（154/155）在这台电脑上探了 13 页（`site:reddit.com smart glasses` 等），跑完进程都结束了，临时目录逐个删了，没碰 Luoye 自己的 Chrome：

| 打开方式 | Google | Bing | DuckDuckGo |
|---|---|---|---|
| 无头、不开页面脚本（WP228 那套） | 跳到「要开 JavaScript」页 | 200，但结果**驴唇不对马嘴**（搜智能眼镜回新加坡兵役、Google 翻译） | 202，人机验证（anomaly） |
| 无头、开脚本 | 直接进 `/sorry/` 人机验证（「unusual traffic」） | — | 同上 |
| 有窗口（真 UA）、开脚本 | 还是 `/sorry/` | 还是乱给（只认第一个词） | **能搜到**，8 条 reddit.com |

结论：Google 按出口 IP 拦（这台电脑走代理，出口 IP 被标记了），换什么开法都进验证页；Bing 对自动化浏览器故意给无关结果；只有「有窗口的真浏览器 + DuckDuckGo」能出结果。这也是协调方改成「内置浏览器、被拦时人来点验证」的原因之一。

### 3.2 几个关键判断

1. **能不能接到我们 Electron 内置浏览器的 CDP 上**：技术上能（给 Electron 开 `--remote-debugging-port`，`dsh-browser-cdp` / `dsh-web-fetch-playwright` 都认 CDP 端点），**但不该这么做**：Electron 的调试口是**整个应用**的，开了之后本机任何进程都能连进来操控工坊主窗口（里面有登录会话），没法只把「搜索那一个视图」开放出去。而且 `dsh-browser-cdp` 是加 38 个工具的自动化插件，违背「只换后端、不改工具面」。所以浏览器类插件这条线**不推荐**。
2. **真正解决问题的是「免 key 的第三方搜索口」**：Exa、Parallel、Keenable、AnySearch 的公开匿名接口，`site:reddit.com` / `site:linkedin.com` 都是 10/10，比 DeepSeek 自带的 0/10 好得多，而且**不开浏览器、不会弹人机验证**，用户什么都不用配。代价：
   - 搜索词会发给这几家（美国公司），只发查询串、不发业务数据；
   - 匿名额度有限流（按出口 IP 算），这几家随时可能收紧或要求 key；把它们的匿名口嵌进一个分发给很多用户的产品，是否合它们的使用条款，**我判断不了**（见决策 913）；
   - X（推特）这一家仍弱（回镜像站）。
3. **`@240xu/dsh-websearch` 最合我们的口**：只注册一个搜索提供方、不加工具、零依赖、没有 `exec`、UA 不冒充、许可干净。缺点：作者小（5 星）、它依赖的 `@deepseek-ai/dsh-launch-environment` 在我们 dsh 那棵树里要补挂（pnpm 仓里已有同版本）；缺省会把缓存和搜索历史写到 `DSH_HOME/cache/websearch`（桌面版的 `DSH_HOME` 是壳给的 `<userData>/dsh`，可以接受）；没给 `launchEnvironment` 时会读进程环境变量里的 key 名——我们要显式给一份**空的**环境快照、显式列出只开免 key 的几家，免得它摸到环境里的 key。
4. `dsh-free-search` 名气最大、引擎最多，但它是「整个搜索套件」：加工具、加设置页、会自己 `pnpm add` 升级、抓 HTML 时冒充 Chrome——按我们「不改工具面」「不伪装」两条都不合适整包挂。它导出的单个函数（`searchExaMCP` / `searchAnysearch` / `searchKeenableMCP`）好用，但为了三个函数依赖一个五千行的包不划算。

### 3.3 建议（一句话）

**用 `@240xu/dsh-websearch` 加我们写的一层薄封装**：在 `dsh-adapter` 已改好的那个口（`1caad34a`）里挂它的提供方——钉死版本、只开 Exa / Parallel 两家免 key 的（DuckDuckGo 作兜底、SearXNG 关）、给空的环境快照、缓存目录指到品牌目录；我们这层管审计、7 天缓存、节流、「来自哪家」照实标。`web_fetch` 照旧官方匿名抓取。**内置浏览器先不做**，留作「匿名口被收紧时」的后备（决策 914）。随便聊 / 品牌分析（WP348 / WP349）那两处也改用同一个提供方。

如果 Luoye 不接受「查询串发给第三方匿名接口」，那就回到内置浏览器方案（Proma 思路那一套），但要接受 Google 在这台电脑的网络下基本一搜就进人机验证、主要靠 DuckDuckGo。

## 四、要 Luoye 定的事（912–915）

- **912　联网搜索改用社区插件 `@240xu/dsh-websearch`（免 key、不开浏览器），还是继续自己做内置浏览器？** 建议：用插件 + 薄封装（理由见 3.3；实测 `site:reddit.com` 10/10）。

- **914　内置浏览器（Electron 里那个，Proma 思路）还做不做？** 建议：这一单先不做，留作后备；等匿名接口真被收紧、或者要「人来点验证 / 登录后读」的场景再开单。
