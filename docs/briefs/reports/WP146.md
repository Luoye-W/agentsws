**E. 顺手修的真 bug：凭据库不在宿主目录里**

- dev-real.sh：重建前若宿主目录里还没有 `connect.sqlite`，先停旧容器、把它的 `/app/data` 拷出来；正在跑的容器不是钉住的那一版时打一行提示（不自动重建）。

## 2. 自主决定（白话）

1. **钉 v1.6.5，不是派工单写的 v1.6.3**：派工途中收到更正（W39 评估：latest 已漂到 v1.6.5）。两版都跑了，都全绿，钉最新的。
2. **磁带也换成在 v1.6.5 上录的那一份，并在磁带里记下是哪个镜像录的**：不然"镜像钉了 v1.6.5、磁带却是 v1.5.0 录的"，「在哪一版上验过」就说不清。代价：以后换镜像版本必须重录磁带（`--check` 会逼着你做），这正是 docs/42 要的。
3. **对账是"四处逐字相同"，不是"四处都不写 latest"**：tag 对、digest 错也要红，只写 tag 不写 digest 也要红。光秃秃地提到仓库名（注释里"起一个 ghcr.io/… 容器"）不算引用，不管。
4. **周报比的是 ghcr 上的 tag 表，不是 GitHub releases**：镜像能不能拉到以 registry 为准；GitHub 那边照旧列 releases。匿名读 ghcr 不需要任何密钥。
5. **数据目录那个 bug 顺手修了**（派工单没写）：升级镜像 = 重建容器，不修的话"按 docs/42 升一次级"就会把用户已连好的账号弄丢，钉版本这件事等于埋了个雷。修法选"显式设环境变量"而不是"把挂载点改成 /app/data"：以后镜像要是改了默认路径，我们这边也不跟着坏。
6. **dev-real 发现正在跑的容器不是钉住的那一版，只提示、不自动重建**：自动重建会动你本机那台常驻容器的数据，这件事该你点头。
7. **browser-skill 的两样东西用三个新字段表达**（`bin_version` / `bin_tag_prefix` / `bin_lock_file`），而不是塞进 `image_*` 或拆成两条登记：它们必须一起升，拆成两条就对不上"两边一起改"这条纪律。
8. **shadcn / tremor 的 wishlist 只写 "BREAKING"**：wishlist 是关键词匹配，写 "CLI"、"radix"、"aria" 这类词每次发版都会误报。

## 4. 测试结果

**一致性套件在所选版本上的结果**（本机 Docker，`RECORD_FIXTURES=1` 真容器录制 → 回放）：

| 镜像 | 真容器录制（全部场景 + 加固探针） | 回放 + 一致性套件（真适配器那一遍） | connect-adapter 全包 |
|---|---|---|---|
| **v1.6.5**（钉的） | ✓ 1/1 | ✓ 16/16 | 117 过 / 1 跳过（录制档） |
| v1.6.3 | ✓ 1/1 | ✓ 16/16 | 117 过 / 1 跳过 |

一致性套件 16 条：providers / actions 的 side_effect / connections 按 workspace 过滤且无凭据 / beginConnect + 过期 poll / 空 allowed_connections 拒签 / 空 allowed_actions 与未知连接拒签 / role-read 混写被拒 / 签发回带三个 allowed_* 且 proxies 恒空 / 读 Action 成功带 execution_id / 越权 Action 与无效 token 拒 / 未授权连接与跨 service 连接拒 / 幂等键重放与冲突 / proxy 一律拒 / transferConnection / revokeTokens 立即失效 / 凭据零泄漏——两版全过。

三版磁带逐条比（29 次交互）：请求序列、路径、状态码**完全一致**；body 差异只有 v1.6.x 的 `/v1/actions` 多 `operationType`、gmail `authTypes` 多 `custom_credential`、虚拟 no_auth 连接多 `itunes_search`（1.6.3）/ `osv`（1.6.5）。新磁带里只录到两种错误（`/v1/health`、`/api/connections` 的 401），`action_not_allowed` / `authorization_failed` 那两条错误码映射**没在新版上复核**（errors.ts 注释照实写了）。

**其余**

- `node scripts/check-upstreams.mjs --check`：过。手工把 compose 的 digest 改一位 → 退 1；把 dev-real 改回 `:latest` → 退 1。
- `scripts/upstreams.test.mjs`：101 条全过（原 71 条 + 本 WP 30 条）。其中验收那条：把整个仓库根软链进临时目录、只把 `docker-compose.yml` 换成 digest 改坏一位的版本，`run(['--check'])` 从 0 变 1。
- `scripts/verify-changed.sh`（merge main 之后）：增量 tsc / 改动文件 biome / connect-adapter 测试全过（biome 只剩一条原有的 `renderSection` 未用参数警告，不是本 WP 引入的）。
- `docker compose config`（填假的必填变量）：openconnector 渲染出钉住的镜像与 `OOMOL_CONNECT_DATA_DIR: /data`。
- `OOMOL_CONNECT_DATA_DIR=/data` 实测：起一个临时容器，日志 `dataDir: /data`，`connect.sqlite` 落在挂载目录。
- 周报本机演练：`--only open-connector` 镜像行「就是最新的」；`--only browser-skill,…` 那一趟 GitHub 匿名配额用完了（403），四条都如实写「查不到」，插件 npm 那行正确报出 0.3.0 → 0.3.1。`bsk` 那一行的比较逻辑由单测覆盖，真 release 表我另外从 GitHub 网页核过有 `cli-v0.3.1`。
