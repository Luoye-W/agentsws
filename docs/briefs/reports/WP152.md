## 2. 我自主做的决定（白话）

1. **改名放在服务端出参上，不改存储**：老用户 `models.json` 里存的是「DeepSeek 官方」和「用我的 DeepSeek 账号登录」，一个字节不动；每次给界面时换成新叫法。这样「已配的」、默认模型下拉、生图下拉三处名字天然一致，也不用迁移数据。
2. **用户自己改过名字的 DeepSeek key 那条不改名**（比如「我的 DeepSeek 代理」）：他可能接的是中转，不一定是官方；他起的名字他认得。只有还是默认名的才换成「官方 API 接口连接」。
3. **新建的 API key 那条，「显示名」默认就是新叫法**（模板 label 改了），存进去就是新名字——和老数据显示一致。
4. **「已经配过就默认显示他已有的那种」按接口地址认，对所有合并卡都生效**（不只 DeepSeek）：比如配过 OpenAI API key 的人打开 OpenAI 那张卡，默认也是 API key 方案。同一条规则，没有理由只给 DeepSeek。两种都配了取排前面的。
5. **向导里 DeepSeek 从「自己的接口」拿掉**：派工单说 DeepSeek 相关的合成一张，两处都能加就不是"一张"了。「自己的接口」剩 OpenAI 兼容 / 百炼 / OpenAI / Anthropic 四家，走查照样 4 个模板、不重名。
6. **向导 API 那种多放了原 key 卡的五步和开放平台链接**：原来「自己的接口」只有表单，但这一张是给不会建 key 的人看的，照着五步做就行。
7. **向导 API 那种接上后记成「自己的接口」**（`'own'`），账户登录记 `'account'`，和原来的语义一致。
8. **余额四舍五入按字符串算**：避免 28.115 这种被浮点算成 28.11；负数、`.5`、认不出的串都有处理。
