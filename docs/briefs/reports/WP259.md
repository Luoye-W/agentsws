# WP259 报告：「交给它」长文本被静默拒收 + 用职责开不起跑

分支 `wp/259-longtext`（worktree `agentsws-wt/wp259-longtext`），Claude 子代理。期间 main 有一条新提交（`ee27fd18` 网页模板运行预算），已合进来后重跑 tsc / gen-sdk / gen-ontology。

## 0. 一句话

「交给它」现在一大段多行也照收：标题取第一句（或前 40 字）加「…」，**完整原文**作事项描述，也是路由判的那段话和首轮运行收到的任务文本；选了具体职责再交（「用这条职责开」）**开完立刻用那条职责起首轮运行**，时间线第一条就是原话全文；任何一次没交出去，框下一句「没交出去：<服务端那句话>」，提交中按钮显示「正在交…」。服务端兜底：直接调接口传超长标题的也照同一条规矩拆，不再 400。

## 1. 查清的两件事

**summary 原来有没有进运行？** 服务端是进的，工作台从来没送：

- 岗位入口 `positions.open`：路由与首轮运行的任务文本是 `title + 空格 + summary`；运行时还会把事项的 `context.summary` 作为一条 `matter_summary` 上下文喂给模型。所以只要请求里带了 summary，它是进运行的（而且原文会被喂两遍）。
- 但工作台「交给它」那几个入口**只送 `title`**（整段话塞进标题），从来不送 summary；只有 ⌘K 从随便聊带过来时才有 summary（那是对话上下文）。
- 10-07 真机那次 400 走的是「职责：选了具体一条」→ `withRole` → `POST /v1/matters`，那条口子标题上限 120（岗位入口是 200）；前端 `useMutation` 没接 `onError`、也没显示 `error`，所以静默。

**用职责开为什么不起跑？** 不是有意设计，是漏了：`POST /v1/matters` 是通用「建一个事项」口子（CLI / SDK / 别的地方也用），从来只建不跑；WP69 让「用这条职责开」直接复用了它，事项建出来时间线是空的，等人在事项页再说一句才会起运行，界面上也没提示。岗位入口那条（不选职责）一直是建完立刻起跑。

## 3. 我自主做的决定（白话）

1. **拆分规矩放在契约包里，前后端各调一次**：工作台先拆好再交（老服务端也收得下），服务端再兜一次底（老客户端、CLI、直接调接口的也不 400）。两边是同一份代码，拆出来一模一样。
2. **标题后面一律加「…」**，即使第一句本身是完整的一句——一眼看得出「后面还有」，服务端也靠它认出「标题是从描述里摘的」。
3. **用职责开改成「开完立刻起跑」用的是新加的 `run: true`**，没有改成走岗位入口（`role_id` 指定职责那条）：走岗位入口会把事项的 `entry` 从 `role` 变成 `position`，右栏 / 记录里「从哪儿开的」就变了；`run` 是加字段，老调用不受影响。
4. **岗位入口那条（不选职责）时间线第一条仍是「路由到 X」那条状态，原话紧随其后**：这是 WP69 / WP237 的老顺序，界面靠它画「路由到 X · 换」；用职责开那条没有路由，第一条就是原话。
5. **错误文案统一「没交出去：<原话>」**，服务端的 message 原样带上（工单要求），403 判权限 / 连不上 / 5xx 沿用 `apiErrorText` 的人话。服务端那句 zod 原文（如 `title: Too big…`）现在基本不会再出现，空白也换成了人话。
6. **上限 4000 字**：与「在事项里说一句话」同一个数；输入框直接限到 4000，不另做字数提示（界面少字）。

## 4. 要 Luoye 定的事（逐条，附建议）

1. **标题取法**：现在是「第一句（≤40 字）或前 40 字 +…」。**建议：先这样**；以后若想要 AI 起一个短标题（多一次模型调用），再单独排。
2. **「用这条职责开」开完立刻起跑**：按 Fable 倾向直接起跑了（职责页那个按钮也一样）。**建议：保持**；如果哪天要「先建、等补一句再跑」，再加一个开关。
3. **超长上限 4000 字**：比这更长的（比如贴一整份需求文档）会被输入框截住。**建议：4000 够用；更长的走附件 / 知识库。**
