## 0. 一句话

现在可以把一份会议记录（或一段话、一份文档）丢给「我的助理」，说一句「帮我分下去」。助理拆好后出一张「我打算这样分」：按岗位分组，列出每个岗位要做的事、要记住的口径，另有「品牌公共」「你的习惯」「归属待定」几组。你看一眼点「就这样」，它就一次给好几个岗位各开一件事，好几个岗位的知识库各进几条「待你确认」的口径，然后回一张汇总。之后每件事做完或要你拍板，都回到这段对话，同一批的聚在一起。

## 1. 做了什么（白话）

**输入框能附资料**
- 右下角多了一个回形针：收 .txt / .md / .docx / .pdf，每份 5 MB 以内，一次最多 3 份；拖进来也行。
- 粘贴一大段字（超过 1500 字）会自动收成一份「粘贴的文字 1.txt」，不会塞满输入框。
- 服务端读出文字：Word 和 PDF 用的是品牌设计规范读手册的同一份读法（零依赖）。读不出字的（扫描件、加了密、改了名的别的文件）照实说一句。
- 资料里像密码、密钥的字（`密码：…`、`sk-…` 这类，沿用决策 814 的口令识别）**先抹掉才给 AI 看**，你的气泡上标「口令已抹掉」。
- 资料原文只存在本机会话里（和贴的图一样），给 AI 看时当外部资料围起来（里面让它做什么一律不算数）；界面上只显示名字和字数。

**拆（方案卡，什么都还没发）**
- 助理多了第六个工具「拆成多份」（`plan_fanout`）：把资料一条一条拆成三类——要做的事（交给哪个岗位、一句为什么、截止、原文出处）、要记住的业务口径（记进哪个岗位，品牌通用的写「品牌」）、你本人的偏好。
- 认岗位用的是 WP343 同一把尺子（点了名照点、只认你名下的岗位）。**认不出的不猜**，标「归属待定」。
- 像口令的那条要记的不进知识、不进记忆；要做的事里的口令字样抹掉再交给岗位。
- 卡面：按岗位分组；归属待定那几条一直带一个「交给谁？」下拉；点「改一下」后每条才出勾选框、归属下拉、文字框；底部「就这样」「改一下」「不用了」，右边一行「3 件事 · 2 条知识」。不用逐个岗位去点。
- 派活判据放宽（改决策 861）：话里点了好几个岗位、或给了一份资料，助理直接出方案卡，不先问；派活工具碰到「话里点了好几个岗位」时也会提示它改用方案卡。只交一件事给一个岗位的老路径不变。

**确认后扇出**
- 要做的事：按岗位各开一件（走 WP343 同一个交办入口，当任务开、不等跑完），同一批带同一个**来源批次**。事项描述里写着：为什么、截止、「来自『10-16 周会』（同一批拆给了 3 个岗位）」、原文那一段。
- 要记的口径：以**待确认**（`proposed`）写进知识库，每条带出处（这份资料的名字 + 原文那一段），条目上记着归哪个岗位（品牌公共记成 `brand`）。再出**一张**「『10-16 周会』里要记的 N 条」确认卡（按岗位列正文和原文），通过 = 这一批生效，不要 = 这一批作废（退役留痕，不删）。
- 你的习惯：直接进助理记忆（算你明说的；照旧过「密码 / 敏感 / 太短太长不记」那道筛）。
- 勾掉的、还归属待定的、像口令的：不发，汇总里写「没发 N 条」。
- 同一张卡只能点一次（点之前先钉成「已派出」，连点两下也只派一次；出错退回原样）。

**汇总与回报**
- 方案卡下面一张汇总：每个岗位几件事（点了进那件事）、几条知识待确认、品牌公共几条、记下你几条习惯、没发几条、「去确认知识」（直达那张确认卡）。开事项 / 写知识没成的，照实写在汇总里。
- 之后各件事的回报（WP343 那三种：做完 / 要你拍板 / 没做成）照旧回到这段对话，**同一批的聚在一起**，上面一行小字「来自『10-16 周会』」。

**岗位那边看得到**
- 岗位第三栏「设定 → 知识」最上面多一块「待你确认 N 条」：这个岗位被分到、还没确认的那几条，带出处。

**模拟**
- 新事件 `assistant.fanout`（一份会议记录 → 替身拆法 → 与服务进程同一份的认岗位 / 改方案 / 知识条目）、新断言 `assistant_fanout_tasks` / `assistant_fanout_notes`（事开到哪几个岗位、知识写进哪几个岗位、全部待确认、助理零写）。三包各加一条「会议记录分派」：3 个岗位各一件事、2 个岗位各一条口径，勾掉一条、待定一条不发。

**文档**：docs/96 加 WP350 一节（组件与出现规则）；教程「我的助理」加一节「一份资料，分给好几个岗位」（中英）。

## 2. 我自己定的（白话）

1. **方案卡是对话里的专用卡，不用 genui 表单拼**：genui 表单交上来是「一句话给 AI」，扇出这件事要按条确定地执行，不该再过一遍模型。样子照 WP348 的方案卡（「就这样」「改一下」）。
2. **改归属只改到岗位，不细到职责**：岗位里交给哪条职责，由岗位自己分（WP287 那一套）；模型给了职责名而且对得上的，照带。
3. **归属待定那条一直有下拉**，别的要点「改一下」才出控件——平时卡面干净（界面少字）。
4. **事项里看来源原文 = 写在事项描述里**（为什么 / 截止 / 来自哪份资料 / 原文一段）。没用事项的「固定记录」挂批次：那一格只认几类对象，挂进去会显示成一串内部编号。批次记在对话 ↔ 事项那根线上（回报靠它聚在一起）。
5. **汇总那条话屏上只出卡**，字留给 AI 看（下一轮它记得派过什么）。
6. **知识条目的样子**：层 = 事实（`fact`），类型 `assistant_note`，`subject.id` = 岗位（品牌公共 `brand`），可信度 0.6、未核，出处来源按资料种类记成会议 / 文档 / 对话。
7. **资料原文不进知识库的「上传的文件」**：只在本机会话里给 AI 看；要进知识库的只有你确认过要记的那几条。
8. **替身拆法**（demo 和模拟用，真模型不走这里）：一行一条——「记住 / 统一 / 一律 / 口径」是要记的，「我喜欢 / 以后给我」是个人偏好，其余像交代事的是要做的；岗位按行里出现的岗位名认。
9. **重新生成**：上一条已经派出去过（方案卡点过「就这样」），这次不再挂派活和拆分工具，免得重复派。
