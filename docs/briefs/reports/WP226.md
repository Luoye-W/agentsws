## 2. 自主做的决定（白话）

- **英文放在单独一个生成文件里，不写回 yml**：yml 是人写的，往里写机器产物迟早有人手改；单独一个 JSON 带哈希，`--check` 一眼看出哪条过期。代价：并行的 WP222 / 223 / 224 / 220 改 yml 里英文的地方会冲突——解法统一是**删掉 `en:` 块、合完跑一次 `node scripts/gen-persona-en.mjs`**。yml 里残留的手写英文（合并期间）仍能读进来当兜底，但若混了汉字会被 `checkPersona` 直接拦（加载报错），这是故意的：宁可合并时红，也别把混中文的英文放出去。
- **过期的英文不用**：中文改了、英文没重出时，读包不用那份旧英文，英文界面显示中文 + 「未翻译」。理由：旧英文少说或多说一件事，看着通顺反而误导。
- **公司覆盖选了「显示中文 + 未翻译图标」，不在保存时调翻译**：保存是 owner 点一下的事，挂模型调用就多了花钱、要 key、会失败、会慢；机翻失败时还得二选一（挡住保存 / 存未校验的英文）。Agent 读的本来就是中文，不受影响。
- **"没有汉字"也拦全角标点**（`（` `：` `，` `「` 等）：91 §3.3 那 14 条露馅的除了汉字还有全角括号。`→` 与弯引号不算。
- **英文小标题仍要求六个都在，但放在生成脚本那一刀**（不在 `checkPersona`）：工单说 `checkPersona` 对英文只查汉字与不为空；而串岗测试按 `Not yours` 找那一段，所以由生成 / 导入时把关。
- **规则文字比工单多半句**：「没有来信可对照时（主动开发信、发帖），用目标市场的语言」。开发信、发帖没有"对方来信"，不写这半句模型无所适从。另加「哪怕上面的说明是中文」，直接对着"中文提示 → 中文回复"这个风险说。
- **服务端那句规则按中文界面送**：服务端仍没有工作区界面语言这一格（69 §3.3 原来的留尾），所以 `replyLanguageSection('zh')`；模拟按 pack 的对内语言选。工作区有了界面语言后改一行。
- **60 段英文是怎么"生成"的（要照实说）**：本机环境里**没有任何模型 key**（`DEEPSEEK_API_KEY` / `AGENTSWS_SIM_MODEL_*` 都没设；按规矩没去翻 `.env*`）。所以这一轮翻译是我（Claude）做的：逐条对照中文核了原来的手写英文——46 条与中文一致的沿用原译，**14 条混中文的重译**了「Who you are」那句，另有 **6 条原英文比中文多说或少说**的改成忠实于中文（`social.facebook` / `social.linkedin` / `social.x` / `social.meta` / `social.youtube` 删掉中文里没有的半句；`kol.youtube` 去掉中文里没有的 UTM、补上「别装作算得出来」；`dtc.community-support` 删多出的半句），再用 `--import` 导入（同一套校验、哈希按当时的中文算）。脚本的模型那一路用本机一个假的 OpenAI 兼容服务（127.0.0.1，假 key）冒烟过一次：60 条全写入，第一条故意回混中文的被拒、重试成功；跑完把产物还原了。**有 key 时跑一次 `node scripts/gen-persona-en.mjs --all` 即可让模型重出。**
- **基线只重定 dtc-3c-3p、dtc-15p**：b2b-3c-3p 三个运行时门禁本来就过（漂移在 5% 以内），没动。

## 3. 英文客户来信的回复语言：没测成

**没跑成真模型**：本机没有模型 key，realistic 档整档跳过；fast 档的 direct 用的是确定性的「规则脑」替身，不读系统提示，回什么语言由规则决定，测不出这条规则管不管用。fast 档三包英文客户来信的场景（客户语言都是 en）回复照旧是英文、全部通过，只能说明没改坏。

能证明的是"规则真进了提示"：真 `createRuntime` 装出来的系统提示里，中文 persona 后面紧跟这一句、提示里没有英文 persona（`reply-words.test.ts`）；dsh 那条在唯一 complete 段里（`persona-sections.test.ts`）。

有 key 时这样跑（几分钱级，`--max-cost-base` 兜底）：

```
DEEPSEEK_API_KEY=… node apps/cli/bin/agentsws.mjs simulate --tier realistic --seed 42 \
  --pack packs/dtc-3c-3p --scenario 'scenarios/aftersales/*.yml' 'scenarios/amazon/*.yml' 'scenarios/chat/*.yml' --max-cost-base 1
DEEPSEEK_API_KEY=… node apps/cli/bin/agentsws.mjs simulate --tier realistic --seed 42 \
  --pack packs/b2b-3c-3p --scenario 'scenarios/sales/*.yml' --max-cost-base 1
```

看草稿正文是不是英文。若串成中文，备选方案（先不改口径）：① 英文客户 / 英文界面送生成的那份英文 persona（产物已经在了，`personaSections({ lang: 'en' })` 一行就通）；② 把规则从 order 22 挪到提示最末（离用户消息最近）。
