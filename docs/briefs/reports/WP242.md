# WP242 报告：第二个品牌调云模型 fetch failed + 第 ② / ③ 步体验

分支 `wp/242-brandmodel`（worktree `agentsws-wt/wp242-brandmodel`），Claude 子代理。

## 0. 一句话（根因是否如怀疑）

**不是怀疑的那样。** 第 ③ 步「帮我推荐」原来**一律用启动品牌（INMO）的模型网关和 INMO 那把云令牌**，
不管人在哪个品牌里点——Rollout 自己有没有令牌根本没参与。而且缺令牌时报的是 `missing api key`（发请求之前就停了），
不会是 `fetch failed`。`fetch failed` 是 Node 的网络层错误：**请求没能从应用的服务进程到达云**（连接被重置 / 超时 / 证书 / 解析之类），
真原因在 `cause.code` 上，而我们的错误只记了 `e.message`，所以 `provider_down` 里只剩一句 fetch failed，看不出是哪一种。

本机复现：起一个本机 HTTP 云替身（关联 / 补签 / 模型口都在它上面），服务进程用**真的 `globalThis.fetch`** 打它，
INMO 关联 → 加 Rollout（跟随公司）→ 两个品牌都点推荐：**改代码之前两边都走 AI 成功**（Fable 的路径在本机不出错）。
Windows 上那一次的真原因要等新包把 `cause.code` 带出来才知道（见 §4 给 Fable 的对照表）。

第 ② 步「已经读了 0 页」也顺带更正一点：**网站分析不经云**——是本机服务进程直接去抓店铺网页（`brand-intake` 包），
所以它卡住 / 读不到与第 ③ 步的云调用失败**很可能同源：那段时间服务进程的出站网络不通**；Shopify 对脚本回 429 是另一件事（已处理，见下）。

## 2. 自主做的决定（白话）

- **重发只一次、只对「连接被掐」那几种**：超时、证书错、域名解析不了重发也没用，照实报；multipart（上传文件）正文是一次性的，不重发。
- **按说法推的只推「默认勾」的几条**：「社媒」一说就推十二个平台太吵，只推模板默认的那四个（TikTok / YouTube / Facebook / Instagram），其余用户自己勾。
- **验证页只按标题认**：很多正常的店铺页面也挂着 Cloudflare 防护脚本，按脚本认会把正常首页当成被拦。
- **手填表都可以空着，至少一格才能存**；币种自动转大写；邮箱不像邮箱回 400。
- 工作单没附 Rollout 那句原话，测试用例是我按第 3 条列的说法拼的一句（`apps/server/test/wp242-fixtures.ts`）。

## 3. 要 Luoye 定的事

1. **一句话 / 客服邮箱 / 币种存在哪**：现在不管是网站分析出来的还是手填的，这三样都只留在那一轮分析记录里（进程内存，重启就没了），没有进品牌档案——这是 WP121 起就有的现状，手填表照同一条写法所以一样。要不要给品牌档案加这三格（契约只加），让它们长期保存、并喂给客服 / 话术？**建议加**，单独一张小单。
2. **网络被掐时自动重发一次**：极少数情况下请求其实已经到了云、只是回执路上断了，重发会多扣一次（几分钱级）。**建议保留**（真机代理环境下断连更常见）。

## 4. 给 Fable 的真机对照（新包装上后再点一次推荐，看 `model.provider_down` 里括号那段）

| 括号里是 | 意思 | 怎么办 |
|---|---|---|
| `ECONNRESET` / `UND_ERR_SOCKET` | 连接被代理 / 对面掐了 | 新包会自动重发一次；还是不行看 Clash 规则对 node.exe 的处理 |
| `UND_ERR_CONNECT_TIMEOUT` / `ETIMEDOUT` | 连不上（TUN / 节点不通） | 看 Clash 这会儿的节点 |
| `ENOTFOUND` / `EAI_AGAIN` | 域名解析不了 | 看 fake-IP / DNS |
| `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` / `SELF_SIGNED_CERT_IN_CHAIN` / `CERT_*` | 中间有人换了证书（安全软件 / 代理 MITM） | 需要 `NODE_EXTRA_CA_CERTS`（壳已透传） |
| `missing cloud workspace token` | 这个品牌真没令牌 | 那才是 Fable 原来怀疑的那条（本机测不出） |

同一时刻第 ② 步「连不上这个网站（错误码）」也会带同一类错误码，两边对得上就说明是服务进程的出站网络。
