## 2. 我自主做的决定（白话）

1. **连接教程按"家"分 8 篇**，不是 26 篇：同一家的几个连接准备工作几乎一样（同一个 Google Cloud 项目、同一个 Meta 开发者后台），合在一篇里人更好对照。Google Ads 放进「Google 家」，Google Alerts 也在；Meta 投放那张和社媒那张 Meta 卡都在「Meta 家」，文中写明是两张卡。
2. **卡上那一句写在工作台词条里**（`connections.line.<service>`，29 条中英），不改服务端的 `setup_guide`——与 WP156 模型卡同一个做法：契约只加不删，英文界面也不再显示中文长句；服务端测试盯着每个 service 都有这一句。
3. **成段介绍与「连上之后」合成标题旁一个问号**，不分两个：两个问号挨着很难看。原话一字不少，教程里也有。
4. **会花钱 / 要审核的事写进那一句里**，不藏：「X 的官方接口要付费档」「全站每天 10000 单位配额」「要过 Meta 审核」——按规矩扣钱提示必须可见。
5. **点不动的原因只留第一截**（到冒号 / 破折号 / 句号），原话进问号；「还没做」那三张直接写「还没做」。
6. **`SafetyNote` 可以带一个问号**：安全承诺压成一句后，条款出处、完整风险说明放旁边——消息渠道的微信条款就这么放。
7. **问号里去掉 `**`**：服务端与职责模板的原话常带粗体记号，问号不画 markdown，记号去掉，字不少。
8. **职责页顶上用第一句、并认粗体**：直接用 `SafeMarkdown` 的行内渲染；第一句要是把一对 `**` 切成半对，就不画粗体，免得露星号。
9. **聊天窗的免费额度和 30 积分 / 月留在卡上**，其余进问号——这两句是状态 / 扣钱提示。
10. **守卫拆成两个新文件**（见 §5）；**红人数据源那几张卡上的「数据从哪里来」排序表与自带数据接口表单**算操作，没动布局，只把说明进了问号。
11. **第三栏几条一句话的面板说明留着**（「这段话会进系统提示…」「岗位本身没有额度…」）：一个面板一句，没地方挂问号，挂了反而更绕；只去掉了露出来的文档编号。

## 3. 需要 Luoye 定的事

1. **连接教程分 8 篇合不合适**，特别是「Google 家」一篇六节偏长（Gmail / GA4 / GSC / YouTube / Google Ads / Google Alerts）。想拆可以把 Google Ads 挪到单独的「投放」篇。

4. **OAuth 那几张卡上的安全承诺**（「点下面的按钮会打开对方网站…密码只输在对方网站上」）在两栏布局里要折两行，想更短可以改成「密码只输在对方网站上，我们看不到」。
