## 2 自主决定（白话）

1. **LinkedIn / Threads / FB / IG 四条排在 YouTube 后面**（工作单写"加在内容账号组末尾"）。于是岗位模板里第一条变成 TikTok；向导里 FB / IG 在第四、五位。想让 FB / IG 排最前，改契约顺序就行，但那是"改"不是"加"，没动。
2. **`social.meta` 怎么迁**：原分配**就地改成 FB 主页**（id 不变——待办、卡、队列车道、定时任务、交接都挂在分配 id 上，一件都不用搬），再**复制一条 IG**（范围、额度覆盖、自动化状态与采纳率照抄）。先复制后改名，中途断电重跑也不会重复复制。社媒库里 `meta` 的账号按 URL 判给 FB 或 IG，帖子、线程跟着账号走。老数据上写着 `meta` 的照样读得进来（契约那一行没删）。
3. **Threads 自己一张卡**：Meta 官方把 Threads 做成另一次授权（单独用例、单独令牌），FB / IG 那把主页令牌调不动它。这不算"为同一件事连两次"。
4. **额度**（上限，不是目标）：YouTube 3→2、X 3→5、TikTok 不变；新：FB 2、IG 3（含快拍）、Threads 3（回复 100，因为这个平台回复与发帖一样重）、LinkedIn 1。
5. **LinkedIn 这一版只代发纯文字**；带图 / 文档 / 视频的要先走素材上传接口，没接——这种帖子到点也变待办，不会悄悄没发。回评论在这条渠道上只出草稿（读写评论也在审核后面）。
6. **"变成待办"只给契约里标了 `publish_fallback` 的渠道**（现在只有 LinkedIn）。别的渠道没连上照旧只记一句"没发"——改它们的行为超出了这一单。
7. **路由的一处真洞**：`reply_thread` 按下划线拆出的英文 `thread` 是 `Threads` 的子串，会把"给 Threads 发一条"判给 Reddit / Discord / 公关那几条；X 与红人 X 的意图词里也有 `thread`。补了一行 `ACTION_TERMS`，并把两处 `thread` 换成「推文串」。
8. **模拟里的 LinkedIn 场景放在 3 人 pack**：15 人 pack 里发布卡落在运营主管身上，但他不持有 LinkedIn 那条、批不了；靠升级到店主的话，升级会改动审批人名单，执行快照对不上、施行失败（txn 现有行为，不是这一单的事）。3 人 pack 的 `assignments.yml` 是 synth 生成的，所以改的是 `synth.ts`（运营多挂 `social.linkedin`）再重出，manifest 里分配数 19→20。
9. **开源技能一个都没引进**：只在 persona / 注释里用自己的话转述了几条做法，并在 yml 注释里写明出处与许可证。整包引进要按 docs/42 / 10 §3 走 `vendored` 流程，评估写在 docs/86 §8。
