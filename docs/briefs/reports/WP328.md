# WP328 报告：Reddit 读——插件读收件箱与自家版块 + 每日巡查 + 外部关键词监测 + VOC / UGC

分支 `wp/328-redditread`（从 10-14 main `8ac4c67f` 建，收尾时已 `git merge main`）。没推、没合、没打 tag、没发版。
全程没读 `.env*`、没碰任何 key / token / 账号、**没打开真实 Reddit**（全用替身 JSON / 替身插件 / 替身数据渠道）、没连远程机器、没碰 4317。
以 docs/102 文末「Luoye 10-14 定」为准：一天一次起步、周五 17:00 收尾、664 整组不要（没有冷却 / 占比 / 身份声明之类的格子）。

## 0. 一句话

社媒运营岗位里担「Reddit」那条职责的人，每天会自动巡查一次：**收件箱 + 自家版块**由用户日常 Chrome 里的「Agents 工坊助手」插件借已登录的品牌号会话只读（`mark=false`，不改已读），**外部社区**按关键词走现有第三方数据渠道；每条有一句 AI 判断「要不要回 / 为什么」，要回的进「待处理」交给 WP329 起草；统计、VOC / UGC、舆情话题按周存好给 WP330。缺版块 / 关键词出配置卡、插件没配对 / 没连 Reddit / 没登录出连接卡（都走 WP324）。

## 2. 给 WP329（写）的接口

- **待处理从哪来**：`brandModules.forWorkspace(ws).redditWatch`（`RedditWatchAssembly`）。
  - `onPending((items: RedditWatchEntry[]) => void)`：每轮新出的要回的几条（`judgement.reply === true`、不是我们自己发的、没被删）。起草就从这里接；也可 `items({ reply: true, status: 'open' })` 自己拉。
  - `setStatus(id, 'drafting' | 'done' | 'dismissed', { outbound_record_id })`：起草中 / 发出后挂上发出记录那一行 / 人说不回。HTTP 同名：`POST /v1/reddit-watch/items/:id/status`。
  - 条目上有回帖要的全部定位：`fullname`（`t1_…` / `t3_…` / `t4_…`）、`parent_fullname`、`link_fullname`、`url`（收件箱是带 `?context=3` 的链接）、`post_title`、`subreddit`、`inbox_type`。
- **发出记录挂后续**：WP329 记发出记录时 `external_id` 请写 Reddit **全名**（`t1_xxx`）；我这边读收件箱时按 `parent_id` 调 `addFollowUp`（全名与去掉前缀的 id 都试，记哪种都认）。
- **节奏共用一本账**：`redditWatch.pace` 是这个品牌的 `Pace`（`REDDIT_PACE_LIMITS`），键用 `redditPaceKey(品牌号, ws)`；写的时候 `beginKey(key, 'write', jobId, now)` / `endKey`，就不会和每日巡查同时开。
- **插件那一侧**：可选权限 `REDDIT_HOST_PERMISSIONS`（`@agentsws/browser-action`）与 `apps/extension/src/lib/reddit/permissions.ts` 共用，写不用再申请；本单令牌 scope 是 `reddit.read`，建议 WP329 加 `reddit.write`（见决策 756）。取数模块 `sessionFetch`（后台带会话 → 标签页兜底）写也能参考。
- **品牌号**：`redditWatch.settings().brand_username`（第一次读到就记下，见决策 758）。

## 3. 给 WP330（周报）的接口

- `redditWatch.onFinal((run, digest) => …)`：周五 17:00 那一次（或周六补的那一次）**整轮做完**才调（插件那两块交回或超时之后），`digest` 就是本周日 00:00 — 那一刻的汇总。
- `redditWatch.digest({ since, until })` / `GET /v1/reddit-watch/digest?since=&until=`（不给 = 本周日 00:00 到现在），回 `RedditWatchDigest`：
  - `own_sub`：自家版块窗口内新帖数、新评论数（按 Reddit 上的发帖时间，含我们自己发的，另给 `ours`）；
  - `voc` / `ugc`：自家版块与收件箱里**有效的**条目（`judgement.voc` / `judgement.ugc` 是一句概括，原文 / 作者 / 时间 / 链接在条目上）；
  - `external`：外部按话题归组（`topic`、`posts`、`comments`、组的评估判断取最要紧那档、`items` 原文引用），需跟进的在前；判断的中文用契约里的 `REDDIT_WATCH_VERDICT_ZH`（与甲方样式「日常讨论无需处理 / 相关度不高不建议回复 / 需跟进」一字不差）；
  - `inbox`：进来几条、要回几条；`runs` / `last_run_at` / `final_done`；`gaps`：哪一块这周没读成（照实写进周报，不当 0）。
- 「我们本周回了几条 + 链接」不在这里，在 WP323 发出记录（`outbound.list(ws, { channel: 'reddit', since, until })`）。

## 4. 自主做的决定（白话）

1. **定时一小时一拍、到点才读**：频率（一天一次 / 12 小时 / 6 小时…）放在巡查设置里，改频率不用动定时任务；没到点的那一拍什么都不读。
2. **一天一次时，本地 9 点以后跑**（`day_start_hour`，设置里可改）。理由：早上上班前出来，人一来就看到。
3. **第一次读只回看 7 天**：不把几个月前的老帖当新的堆进来。
4. **判新看编号**：每一路记「上次读到哪一条」，下次读到它就停；那一条被删了找不到时按时间兜底（早一小时余量）。翻到页数上限还没读到上次那条，照实写「可能有漏的」。
5. **一次巡查算一次读**（收件箱 + 自家版块一起），不是一页算一次；一天最多 24 次。
6. **自家版块读两样**：`/new`（新帖）和 `/comments`（整个版块的新评论）；「我们帖子 / 回复下的新回复」靠收件箱的帖子回复 / 评论回复两栏（发帖时默认开着送进收件箱）。
7. **我们自己发的只计数、不判、不进待处理**（认品牌号用户名）。
8. **外部社区**：自家版块里的搜索结果不算外部；拉丁字母关键词按**整词**认（INMO 不撞 inmobiliaria），没整词出现的按规则判「相关度不高」——这是事实判断，不是运营规矩。
9. **没有模型时的兜底**（stub / 没人担职责）：收件箱里冲着我们来的 → 需跟进要回；自家版块里在问 / 在抱怨的 → 需跟进要回；像广告的 → 相关度不高；其余日常讨论。VOC / UGC 只有模型判，规则不硬凑。
10. **卡一天最多一次**：缺设置 / 缺连接同一种一天只出一张（人点「先不连」后不会每小时再弹）；插件刚连上会马上补跑一轮，不用等一小时。
11. **Chrome 没开不出卡**：插件配过、只是没开着，排的活 2 小时没人领就记「Chrome 没开着」，下一拍再排；只有从没配对 / 没连 Reddit / 没登录 / 号不对才出连接卡。
12. **工作台入口放在「Reddit」职责的快捷视图**，不另开右栏图标（docs/96：信息是组件、只在该出现的地方出现）。

## 6. 需要 Luoye 提供的配置

## 8. 偏离 / 没做

- **没有新造卡种**：要回的条目不单独出卡（起草卡在 WP329）；「不回」的、统计进快捷视图与周汇总。docs/96 的「简报」组件还没有统一实现，本单没往里写（等简报组件落地再接一行「Reddit 昨天：N 条新、M 条要回」）。
- 关键词监测只搜帖子（数据渠道能不能搜评论 docs/102 §11 待核）。
- 插件读到的 Reddit 号节奏只在内存里记（进程重启当天读次数清零）；一天 24 次的上限远高于实际用量，影响不大。
- Reddit Chat / modmail 不读（决策 662）；私有 RSS 备选路线没做（10-14 定以插件为主）。
- 没做真 Chromium 端到端（派工单验证项没要求；本机假页面那一套留给 WP329 写的时候一起做）。
