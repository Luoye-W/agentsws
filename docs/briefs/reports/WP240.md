# WP240 报告：第二个品牌的首次设置（新建品牌 Rollout）

分支 `wp/240-brandonb`（worktree `agentsws-wt/wp240-brandonb`），Claude 子代理。

## 0. 一句话（含第 5 条核实结论）

**确认串品牌**：首次设置那一面整个按「启动品牌」（INMO）装配。先用测试复现了两处真写串：
在 Rollout 下**确认网址分析**，会把 INMO 的档案、INMO 的品牌名、公司全称一起改成 Rollout 网站上的样子，
首批知识（政策 / 商品卡）也进了 INMO 的知识库；在 Rollout 下**完成第 ④ 步**，分配建在 INMO 里、范围挂「整个品牌（INMO）」。
设置页在 Rollout 下改品牌名，改的也是 INMO。

**真机这一次大概率没写坏 INMO**：Fable 那一轮分析停在「0 页」（店铺有密码），没走到「看着没问题」，也没走到第 ④ 步；
`state` 里的 `brand_name: INMO` 与 `profile.legal_name: INMO` 是**读法**错（读的是启动品牌 / 公司全称的影子），不是存储被改。
唯一要请 Fable 真机看一眼的：Rollout 下有没有在「设置 → 公司档案」里点过保存——没改品牌名那一格就保存的话，INMO 的品牌名被写了一遍「INMO」（同名，无害）；
**要是在那一格改成过「Rollout」再保存，被改名的是 INMO**（看顶栏切换器 / 品牌一览里 INMO 那一行的名字就知道，改回来在 INMO 下的设置页改）。
修好之后这几条路全部按当前品牌读写，测试钉住。

### 第 5 条：迁移 / 自检

`brand_name` **不存在档案里**（读的是品牌工作区自己的名字），所以"档案里 brand_name 与品牌名不一致"在存储上不存在——
以前错的是读法（一律读启动品牌），读法改了就对了，没有可以按品牌名去纠正的存量字段。

真正要纠正的存量是②那份影子档案：启动时一次性跑 `wp240_added_brand_profiles`——非启动品牌、档案里只有建品牌时写的那几格（没有市场 / 地址 / 按市场语言）、
并且除负责人那一条外没人分过岗位的，标回 `provisional`，切过去就进首次设置；用户动过的（有市场 / 地址、或已分过岗位）一律不碰。跑过一次就记下、不再跑。
Rollout 在真机上符合条件，升级后切过去会进向导。

## 2. 自主做的决定（白话）

- **"加的品牌"怎么认**：不是启动品牌、而且启动品牌已经设过（公司那一层有了）。启动品牌还没设过时，加的品牌照第一个品牌那样走（含公司全称）。
- **分析结果不改公司全称、不改品牌名**（加的品牌）：网站上的公司名常是品牌的运营主体，不一定是 Luoye 的公司；品牌名用户在建品牌时亲手起过。档案卡上亲手改了品牌名才改。
- **走完向导就算设过**：哪怕第 ② 步跳过了分析，不然下次打开又被拉回向导。
- **「当前」看会话**，`currentWorkspace` 选项留着不删（契约只加不删）。
- **密码框只在读到密码页时出**，不预先摆着；解开失败另说一句（`password_wrong`）。没装解锁口（离线替身 / demo）时照样说「店铺有访问密码」，只剩「先跳过」。
- **429 只当场停首页那一跳**：首页就被拦才停整轮；首页读到、后面某页 429 的照旧记在那一页上（与以前一样）。
- 加的品牌第 ② 步不出「加入一家公司」（公司已经在了）。
- 品牌切换器那一行窄，后台小件照旧只画数字（tooltip 里有全文）；公司页一览才写「后台任务 N」。

## 3. 要 Luoye 定的事

1. **加的品牌的分析结果要不要改公司全称**：现在不改（公司全称只在第一个品牌那一轮、或设置页手改）。你说过 INMO、Rollout 都是你公司名下的客户品牌，这个默认应该对——确认一下。
2. **网站上读到的品牌名**要不要顶掉建品牌时起的名字：现在不顶（档案卡上亲手改了才改）。
3. **目标市场从 Shopify 国家切换器读到两百多国时**，要不要干脆判成「全球」、不往档案里写两百多个（现在照写，只是界面收起来；这会让搜索可见度探测按市场数算钱，见 markets 的花费提示）。
4. **店铺密码解锁**走的是 Shopify 公开的密码页表单；如果对方开了人机验证，解不开会说「店铺密码没能解开」并给「先跳过」。要不要再加一条路（比如连上店铺后台后改从后台读）？
