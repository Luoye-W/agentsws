## 2 做了什么（白话）

**① 390「当成任务做」不重跑只读问题**（服务端岗位面，所有岗位通用）

- 当场答成了、原话又不是交办（按 WP287 的规则看：没有改 / 发 / 写 / 上架…这类要动手的词、也不是一大段需求）→ 直接把这一问一答转成任务，时间线记一句「转成了任务，用的是上面这段回答，在岗位「工作」里跟进」，**不再起运行**，事项里回答只有一段。
- 原话要动手的（模型判成当场问答、规则看出是交办，比如「把蓝牙耳机降价 10%」），或者当场那次没答成 / 被停了 → 照旧按原话当任务重跑一次。
- 工作台不用改：还是那个按钮、那个接口（`POST /v1/matters/:id/promote {run:true}`），不重跑时回包里没有 `run_id`。

**② 507 IM 链接带品牌、打开自动切品牌**

- 服务端：岗位 Agent 回话里的岗位 / 事项链接、没答成 / 超时那句后面的根链接（知道是哪个品牌时）、个人微信卡片深链，都带上 `?brand=<品牌 id>`。只加这一格，没有 token、没有动作参数。
- 工作台：打开带 `brand` 的地址时——
  - 就是当前品牌 → 只把这一格从地址里去掉，照常开；
  - 本人进得去的另一个品牌 → 先切过去（与品牌切换器同一套：换会话、整站重载），再开链接里那一页；切的那一下不画那一页（免得先出一屏「找不到」）；
  - 品牌不存在 / 没权限 → 留在当前品牌、回首页，主区顶上一行「链接里的品牌你进不去（不存在或没有权限），先留在「X」。」，能关掉；切的时候出错 → 「没切到链接里的品牌，再点一次链接试试。」
- 帮助文档（消息渠道，中英）加一行。

**③ 480 旧的自带主题也出选主题卡**

- 工作目录是旧的自带主题（WP301 之前从 agentsws-theme 起底的，Rollout 那种）时，AI 叫起底没说用哪套 → 不再直接复制 Horizon，照 WP304 出选主题卡：高级主题一行排第一 + 店里已装的主题。不用等人说「换主题」，第一次起底就问。
- 已经买过高级主题的店，那一行是「（这家店已买）」，选了直接下载推一份未发布预览，不出花钱卡、不扣积分；没买的照 WP304 先出花钱卡。
- 选了哪份都先在店里起一份**新的未发布主题**（免费主题 = 复制那一份；高级主题 = 下载后推成未发布），**线上一个字节不动**；旧目录照 WP301 整份挪去 `theme-work/<品牌>/legacy/` 原样留着，时间线那一句按实际选的说（「复制了一份「Lumen」」/「Shopify 官方 Horizon」/「这次装的是我们的高级主题」）。
- 出卡之前旧目录、店里都不动；卡没定之前每次起底都是同一张卡，不重复出。
- 没接审批总线（出不了卡，比如测试 / 老装配）时照 WP301 老路在 Horizon 上新起一份。
- 给模型的那句旧目录提示、网页模板做法第 7 条、stub 剧本的回话、WP296 旧升级卡作废那句、docs/59 跟着改成「先选主题、新起一份」。

## 3 自主做的决定（白话）

1. **「只读」怎么判**：用 WP287 那套纯规则（`classifyEntryIntent`），不再问一次模型。当场问答那次本来就是「只查只答」，规则只用来挑出「模型判成问答、其实是交办」的少数情况；判错的代价小（多跑一次 / 少跑一次）。
2. **只读问题转成的任务留在「进行中」**，不自动标完成——人点「当成任务做」通常是想之后跟进。
3. **品牌放在地址参数 `brand` 里**，值是品牌（工作区）id；不是个人数据，没有 token。
4. **品牌进不去时回首页**，不停在链接那一页（那一页的 id 属于另一个品牌，停着只会是「找不到」）。
5. **旧目录第一次起底就出卡**（不要求人先说「换主题」）：派工单写「第一次起底 / 说换主题」，旧目录上第一次起底本身就是换主题。
6. **时间线那句按实际选的那一份说**：以前写死「复制了一份 Horizon」，高级主题那一路其实也会说成 Horizon（WP304 留下的小错），顺手改对。
