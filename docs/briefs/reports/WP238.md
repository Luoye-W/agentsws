# WP238 报告：岗位页两处快修——「连上就能开工」误报 + 权限清单藏深

分支 `wp/238-posfix`（worktree `agentsws-wt/wp238-posfix`），Claude 子代理。只修工作单里的两处与空状态，没动岗位页整体排版。

## 0. 一句话

Reddit 取数已经能经接口中台（或本机只读浏览器）拿到时，「Reddit API」不再算缺；「连上这 N 个就能开工」只列**真缺的必需项**，
可选的一律不进卡，全满足就整张卡不出。面板上 Reddit 那一节不再催「去连接」，改成一行灰字「数据经 Agents 工坊接口获取」。
职责页的「能看什么 / 能做什么 / 挂着的技能」收进默认折叠的「高级 · 这条职责能做什么」，翻成人话，原始 id 只在每行的 tooltip。
「还没登记号 / 群发没有去处 / 还没连接 X」这类空状态统一成一行灰字 + 一个去处按钮。

## 2. 自主做的决定（白话）

- **「满足」按授权项细分，不按整张卡**：Reddit 那张卡一把 key 管读和写。只有「这条职责要的全是读」才算被接口中台满足——「品牌监控」只要搜，所以不再算缺；「Reddit 运营 / Reddit 营销」要发帖、版务，Reddit API 照样留在清单里（它们本来就是可选，所以不进卡，只在连接页按职责列）。
- **「接口中台走得通」= 关联了账号 + 这一路没被关**，没有再去云上查一次那三项能力的健康。理由：岗位清单是同步算的，每次打开岗位页都打一次云不值；云上某项临时关了是运行那一跳的事，`read_reddit` 会照实说「没取到」。要是你想更严（云上健康为假就算缺），这里留了口子（`readRouteLevelOf` 一处改）。
- **浏览器只读那一路也算满足**（本机装了只读浏览器、找得到 Chrome/Edge 时），与 WP220 的两路路由同一口径；托管实例那一路本来就停用。
- **面板 Reddit 那一节选了「一行灰字说数据从哪来」，没去「给能出的数」**：活跃度那几个数是我们自己 subreddit 的统计，接口中台的三项能力（搜帖 / 读版 / 读评论）拼不出来，硬拼要每打开一次面板就扣一次积分。所以只说数据从哪来，要看就在上面交给岗位一件事。
- 「连上这 N 个」卡上去掉了「必需 / 可选」小字（现在卡上只剩必需的，标了也是废字）；「未就绪」徽章没动。
- 职责页「高级」里**用 tooltip 放原始 id，没做「开发者视图」开关**（工作单说二选一）。动作的人话只给 Reddit 相关的 10 个写了专门说法，其余按「改 / 对外发 + 对象」拼——全仓 300 来个动作逐个起名不是快修的量。
- 顺手补了三个技能的显示名（`social-research` 社媒研究、`trend-research` 话题与舆情研究、`shopify`），不然「高级」里会露 id。
- 社媒空状态的去处按钮落到**连接页那张渠道卡**：工作台目前没有「登记号」的界面，原文案本来就是「先去连接页连上再登记」。

## 3. 要 Luoye 定的事

1. **「接口中台满足」要不要再严一层**：现在是「关联了账号且这一路没被关」就算满足；要不要改成还得云上那三项能力当时健康（每次开岗位页多打一次云）？
2. **面板 Reddit 那一节**：现在是一行灰字「数据经 Agents 工坊接口获取」。要不要干脆整节不出？或者要真出数（每次打开面板扣积分）？
3. **职责页「高级」里原始 id 只放 tooltip** 够不够，还是要一个「开发者视图」开关整页切换？
4. 社媒「还没登记号」的去处现在是连接页那张渠道卡；连上 Reddit API 之后「登记哪个版」还没有界面——要不要排一单做「登记号 / 群」？
