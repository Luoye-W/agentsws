# WP260 报告：网页模板的运行真把活干完（回合上限、按工作类型压缩、只说不做续跑）

分支 `wp/260-themerun`（worktree `agentsws-wt/wp260-themerun`），Claude 子代理。已合 main（含 WP258 / WP259），未推送、未合并。

## 0. 一句话

ci.16 停下的主因是**回合上限 8**：工具调用放到 60 次之后，先到的是 direct 运行时的 8 回合（服务端从没传过回合数）。8 回合到了，运行照「做完了」收，最后一回合顺口说的「现在读…」被当成了答复。同时有两件事让它一直在读：工具结果围栏只放 1.2 万字，`faq.liquid`（2.5 万字）只看得到前一半，schema 恰好在文件尾巴；历史一过 1.2 万 token 就压缩，几乎每一步都把刚读的文件换成空占位。

现在网页模板的运行：回合 40、token 80 万；历史过 4.8 万 token 才压，最近 6 条不压，压掉的换成「读过哪个文件 + 要点」；主题文件按 2.4 万字分页，`CATALOG.json` 先给一页目录，再按 ids 取完整设置；没产出就说「我接下来要…」，会被续跑（最多 3 次）；工具面里不再摆订单 / 商品工具；提示词里多了一节「网页模板的做法」。回放测试按 ci.16 的形状走完了「起底 → 每个文件只读一次 → 写 → 检查 → 推未发布 → 预览好了」。

## 1. 停的原因（要做 1）

### 1.1 direct 运行时（服务端网页模板走这一档：没挂浏览器 / 网页工具 / 电脑操控）所有终止条件

| # | 什么时候 | 结果 | 改之前 ci.16 会不会撞 |
|---|---|---|---|
| 1 | 开跑前 / 每回合开头 / 模型这一跳回来时 / 每个工具执行完，`signal` 已停（看门狗：空闲 3 分钟、总时长 20 分钟；人点「停止」；DeepSeek 账号登出） | `run.cancelled`，时间线一句人话 + 部分结果 +「接着跑」 | 不会（57 秒、一直有动静） |

dsh 档（模拟三运行时与带浏览器 / 网页工具的运行）：agent-loop 在模型不调工具时结束（同 #7）；步数上限缺省也是 8（`maxStepsFor`），跨重试累计计数，用完以后**借 `max_seconds` 这一格**报 `budget.exhausted`；token、工具次数、`signal`、模型出错各一条，与 direct 一致。

### 1.2 为什么判断是 #9

- 57 秒、约 25 次工具调用、没有 budget 事件，结尾那句「现在读首页模板、FAQ/容器分区……」是**预告下一步**的话。真模型一回合读三四个文件（compact 进度里 1、4、3、1、4、4 条也对得上），8 × 3 ≈ 25，正好对上。
- direct 循环到第 8 回合，执行完这一回合的工具调用就出循环（`closeOpenToolUses('turn_limit')` 那时已经没有没收尾的调用），`finalText` 还是这一回合模型附带的那句话，`answered` 成立，于是 `run.completed outputs: [answer: "现在读…"]`。
- **#7 同样可能**：模型回一句不带工具调用的预告就收工。两种在时间线上长得一样。真机事件日志里能分开：最后一条 `text.delta` 后面还有 `tool.call` 就是 #9；没有就是 #7。两条这次都修了。

### 1.3 为什么一直在重读

- **工具结果围栏只放 1.2 万字**（`EXTERNAL_FENCE.fencePayload` 缺省 `MAX_FENCED_CHARS`）。`theme_read_file` 回的 `{path, content}` 又要转义成 JSON，实际看得见的更少：`sections/faq.liquid`（真主题 25,657 字）只看到前一半，`{% schema %}` 在文件尾巴上；`CATALOG.json`（真主题 504,171 字节）只看到开头几项。
- **压缩阈值 = min(max_tokens × 0.6, 1.2 万)**：提示词加两三个文件就过线，而且只压到刚好回到线下，下一步再读一个又过线，所以几乎每一步都压，而且总是先压最早的，也就是刚读的规矩和模板。换上去的是一行空占位，连文件名都没有，模型只能再读一遍。
- 还有一个隐患：`CATALOG.json` 离读取上限 512 KB 只差 8 KB，主题再长一版就整份读不了。

## 3. 自主做的决定（白话）

1. **工作法没写进 persona，单写一节提示词。** 职责 persona 有 260 字上限，英文版由脚本从中文翻出来，签着中文的哈希。改中文就要重新翻译，而纪律不许调真模型。persona 一个字没动。
2. **「回合用完照实记」对所有运行生效**，不只网页模板。以前任何职责跑满 8 回合，都把最后半句话当答复、标成做完。现在标 `budget_exhausted{max_turns}`，摘要说「预算不够（max_turns）就停了」，答复不进时间线。三包 × 三运行时 sims 全过、没有漂移，说明模拟场景里没有跑满 8 回合的。原来钉住旧行为的那条单测（`budget.test.ts`「turn 上限」）已改。
3. **续跑只对 `produce` 生效**，现在只有网页模板。普通问答、客服、红人……请求里没有这一格，一个字节不变（有测试钉住：同一句「现在读…」在没有 produce 时照旧收工）。
4. **产出 = 推未发布成功，或出了发布卡，或这次运行出了任何卡 / 草稿。** 只写了文件不算：写完不推，人看不到。
5. **订单 / 商品工具对网页模板一律不摆**（不管店铺连没连）。主推商品留空占位，由人在主题编辑器里挑，这也是 AGENTS.md 的规矩（不把店铺内容硬写进模板）。
6. **token 从 40 万放到 80 万**（Fable 早上定的 40 万）。这是累计输入，每回合把整段历史再送一遍，大半命中缓存。回放一轮 10 回合约 16 万、历史峰值 2.2 万；真模型回合可能多一倍，历史又可能压到 4.8 万附近，40 万有可能在推预览之前用完。花费另有 `max_cost_base` 兜底。见 §4 第 1 条。
7. **dsh 那一档没有加历史压缩**，dsh 本来就没有，官方 agent-loop 不压。网页模板在生产里走 direct（不挂浏览器 / 网页工具），dsh 只在模拟里跑到这条职责。dsh 档补的是续跑和步数。
8. **`site-theme.ts`（WP258 的地盘）只动了两处**：加读取上限常量、`readFile` 改用它。合 main 时自动合上，没冲突。
