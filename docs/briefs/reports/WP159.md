## 2 我自主做的决定（白话）

1. **Perplexity 只在"官方默认"这一层拿掉**：契约枚举、适配器代码、SerpApi 那家（本来就没有它）都不动；DataForSEO 适配器把它挪到"登记为不用"，于是官方和自带 DataForSEO key 两条路都不再问它。自带 key 的用户也不会被悄悄多扣服务商的钱。
2. **每周真问哪几个平台 = 默认三家 ∩ 这条路能探测的**：自带 SerpApi key 的那档只能探测 AI 概览（和 Copilot），就只问 AI 概览；Copilot 不在默认里，不问。
3. **模型写的是四格一起**（标题、描述、H1、开头两句），人可以在卡上删掉不想改的格；加小节写小标题 + 正文。模型只看得到查询、页面网址与标题、证据和那句建议——**没读页面正文**（服务端现在没有读页面正文的口），所以提示词里明确"不编任何数字、参数、价格、保修"。
4. **模型初稿不合规矩就整份不用**：读不出 JSON、有一格空的、超长、开头超过两句（和 guardrail 同一个数法）、命中违规宣称规则（按市场合成后的那一份）→ 退回规则版，卡上 / 5 件事报告里写一句"模型初稿没用上：……"。数字出处那一道不在这里查（发布前质检会查）。
5. **每天上限按"打出去的次数"算，先记数再打**：打出去就算花了，失败也算一次。默认 5（一天最多 5 件事）；阈值 `seo_model_drafts_per_day` 写进职责模板，0 = 不用模型。超预算不另做判断——模型网关超预算会报错，走兜底。
6. **模型走 `purpose: 'run'` 那一档**（写字的活），和 WP122b 成文那一口同样是"配了真 provider 才给、只有 stub 当没配"。
7. **品牌口吻 = 品牌档案那一段（品牌名、目标市场）+ DESIGN.md 的「气质」一句**。DESIGN.md 的颜色字体与写字无关，不注。定位、口吻原话目前没有落盘的地方（WP121 注释里也这么说），取不到就不写。
8. **规则表放知识库、改动直接生效**：知识库的老规矩是"Agent 的写只经审批卡"；这里是人自己在知识库页上拨的，所以提卡后由这个人当场激活（同导入那条路），旧卡退役不删。"关掉"用卡上 `enabled: false` 表示，不是退役——退役了系统会以为"没改过"又用回自带的。
9. **市场组**：通用组永远开；欧盟 27 国与英国合成一组（UCPD / 2024/825 与 CAP / CMA 放一起，用户认"欧盟 / 英国"更直观）。组开关人拨过就以人为准（存在品牌目录的 `seo-state.json`，不是知识库卡——它不是一条规则）。
10. **目标市场的来源**：品牌分析确认档案卡时写进工作区档案（`WorkspaceProfile.markets`，大写两位国家码、去重）；公司档案那一步不给就沿用。档案里没写 → 按探测国家（现在服务端写死 `us`）算，界面写明"档案里没写，按默认"。
11. **界面不露正则**：正则规则展示人看得懂的写法（`label`）；正则规则只能改理由、不能在界面上改字（人写的多半不是正则），人自己加的规则按字面匹配、可以改字。
12. **美国组的规则挑了"能从字面认出来"的**：FTC 的披露要求（代言有没有披露利益关系）从一句话里认不出，所以规则是"提到 as seen on / customers love 就提醒要真实、要披露"，由人判断。
