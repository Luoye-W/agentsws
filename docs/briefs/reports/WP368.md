**周报那一节怎么工作**（白话）：

## 2. 我自主做的决定（白话）

1. **从 WP355 分支起，不从 main 起**：派单说可以这样拿到 MCP SDK 1.32.1。代价是这单要等 WP355 合了才能合（或者一起合）。
2. **两条都顶，包括不会加载的 proxy-addr**：派单要求的；而且安装包会把正式依赖原样带上，不加载也在用户硬盘上，扫描工具照样会报。
3. **锁文件多了一些「换名字」的行**：顶完以后 pnpm 把 express 那一串重新解析，名字后面多了 `(supports-color@10.2.2)` 这样的后缀（一个可选的终端上色包，`apps/server` 里本来就有别的包这样解）。我专门对比过：不加覆盖、直接重装，锁文件一行都不变，所以这些变化就是覆盖带出来的，内容一样、只是变体名不同。`pnpm install --frozen-lockfile` 通过。
4. **`minimumReleaseAgeExclude` 没被动**：装之前把 `pnpm-workspace.yaml` 存了一份，装完逐字节比，除了我加的 10 行没有任何变化。
5. **构建期名单只放了两条**：工作台打进前端的包（echarts、exceljs、katex……）**算运行时**，因为它们真跑在用户的界面里；只有确定只在构建时跑的才进名单。
6. **周报提示同一个包合成一行**：不然 brace-expansion 一个包就刷六行。
7. **没有新占决策号**：发现编号撞车了（见 §4 第 4 条），下面要定的事用 A / B / C 标，等 Fable 统一编号。
8. 先查了现成方案：周报直接用 pnpm 自带的 `pnpm audit`（零依赖、零 key），没引入新库，也没接需要账号的扫描服务。

## 4. 要 Luoye 定的事（每条附建议）

**A. 这单怎么合**
建议：WP355 合进 main 之后紧接着合这单（这单是在 WP355 上面起的，单独先合会把 WP355 一起带进去）。

**B. 新一节第一次跑就查出的两个运行时高危包，要不要再开一单**
- `brace-expansion`（两条高危 + 一条中危，都是「嵌套花括号把栈撑爆 / CPU 卡死」）：一路从工作台的 `exceljs`（导出 Excel，跑在界面里）带进来，一路从 `packages/data` 和 `packages/roles` 的 `casbin`（权限判断，跑在本机服务里）带进来，分三个大版本。
- `http-cache-semantics`（高危，共享缓存可能把别人的缓存响应给出去）：从 dsh 的遥测包 `dsh-otel` → `got` 带进来。
建议：**再开一个小单**，照这单的办法先查会不会真加载（casbin 用 minimatch 只在匹配策略时、输入是我们自己写的规则；dsh-otel 我们是否开着要查），再用 `overrides` 按大版本顶（pnpm 支持 `brace-expansion@1` 这种按大版本写）。都是中低风险，不急，可以和下次 dsh 升级一起做。

**C. 构建期名单这条规矩要不要认**
现在「只在构建时跑」的名单是我判断的两条（静态官网、shadcn）。建议：**认**，以后加一条都要在注释里写清为什么碰不到用户，审核时看一眼就行。

**D. 编号撞车（要 Fable 处理）**
main 上 Fable 已经把 **WP355 / WP356 / WP357** 派给了「指定来源用自带搜索」「设置弹窗」「助理小改」，**决策 923** 是「设置改成弹出面板」；而几个侧会话分支上 WP355（安全修复）、WP356（BrowserSkill 0.3.3）、WP357（账号模型下拉）和决策 923–926（WP355 报告里待定的那几条）用的是同样的号。建议：**侧会话这几单合并时由 Fable 统一改号**（报告文件名、docs/35 记录、决策号一起改）；这单用的 WP358 在 main 上还没人用，如果 Fable 那边下一单也想用 358，就把这单改掉。

**E. 运行时有高危时要不要单独开一条 issue**
现在只是写进每周那条周报 issue（顶上小表 + 末尾提示）。建议：**先这样**，跑几周看噪音多大再说；真要单独提醒，加一个 `security` 标签是一行的事。
