## 0. 一句话

① 个人、② 同事互联现在**只有安全闸**：AI 要做对外、动钱、不可逆的事，问的是这件事是谁的那个人——本该「转给上级 / 老板」的卡落回本人，卡上不再写「转给了…」；超了你设的上限只要你**再点一次**；没人管的卡到点只提醒本人、不升级；提的人自己点不算违规。人自己改职责规矩、额度、自动化上限、工具箱合并、记忆 / 技能提层，保存前问一句、**当场生效、不出卡**；② 里改的是共用的，同岗位的人收到一张「知道了 / 撤回」卡。① 里会议 / 告警冒出来的活直接记到本人名下。③ 行为一点没变。

## 2. 我自己定的（白话）

1. **「超了上限再确认一次」做成界面上点两下**，服务端只把卡标出来（`reconfirm`），不再要第二枚凭证。理由：安全闸是「人看清楚再按」，不是防人；多一枚凭证要改决定接口，收益小。
2. **哪种卡算「超了上限」**：改动卡（`staged_change`）额度核对没过（护栏判「要人看」）就算；B2B 报价按它自己那四个数（金额 / 毛利 / 折扣 / 账期）算。别的卡没有额度这回事，不标。
3. **① ② 落回本人的收件人写 `role_holder`**（是他自己的事），规则那一格（`rule`）照留 yml 原样——事后查得出「这条在 ③ 里本该是主管定」。
4. **路由在出卡那一刻按模式定，职责分离与升级在决定 / 升级那一刻按当时的模式定。** 与 docs/95 §3.4「开公司模式前已出的卡不改派」一致；但 ③ 降回 ② 时（D 单），还没定的卡从那一刻起就不再升级、本人能自己点。
5. **没人管的卡在 ① ② 里「提醒本人」= 给原收件人再投一次**（卡在他那边重新冒出来），每级一次，与升级共用一个计数——以后开了 ③ 也不会把已经提醒过的那一级再补升一次。
6. **工具箱合并、记忆 / 技能提层在 ① ② 里「卡照出、本人当场点掉」**，而不是另写一份施行逻辑：施行代码一行没复制，决定记录里留着「自己改的，当场生效」。队列里看不到这张卡。改职责 / 策略层则直接落库（那条路本来就有「批了之后落库」的现成函数）。
7. **② 的撤回通知只给「职责规矩 / 额度 / 自动化上限 / 策略层」**：改之前那一份存着，撤回就落回去。通知卡复用 `policy_change` 的「两个选项」形状（选「撤回」= 维持改之前），不新加卡种。
8. **改收款账户 / 诈骗嫌疑红卡在 ② 里只给业务员**，不再抄发起人：发起人「不批任何人的活」（docs/95 §1）。硬闸本身没动：红卡照出、一律要人点。
9. **决策 259 只管「以后进池的」**，① 里以前已经在池里的老活没有搬（数量很少，首页「待认领」有活时照出）。
10. 模式在服务端同步读不到时（身份层没给 `membersSync`）按「不知道」处理，活照旧进池。

## 3. 要 Luoye 定的事（同时列在对话里）

1. **「再确认一次」只在界面上点两下，服务端不强制。** 建议保持；以后若接 IM 卡片按钮（手机上一下就批），再给那条路加一句「超了上限，回到工作台点」。
2. **② 里 AI 提的、不属于任何一个人的卡（工具箱晋升建议、内容更新、插件升级、并进来对照表）现在仍发给发起人。** docs/95 说「出卡给这件事是谁的那个人」，这几种没有明确的主人。建议：C 单里改成「发给用到它的那几个岗位的人，谁先点算谁的」；B 单先不动。
3. **② 的撤回通知只做了职责规矩 / 额度 / 自动化上限 / 策略层**；工具箱合并与记忆 / 技能提到岗位层，② 里当场生效但**不发通知、不能一键撤回**（撤回要另存「改之前那一层」的整份技能记录）。建议：并进 C 单（② 的界面本来就在 C 单）。
4. **② 里普通成员能不能改共用职责的规矩**：服务端这条路现在要「策略：提议」权限，② 的同事没有（今天只有 `common.owner` 那条职责带它），所以 ② 的「谁都能改、留名字、可撤回」实际只有发起人能用上。建议：C 单给 ② 的同事开这条权限（只开改规矩，不开删岗位）。
5. **「角色定位」在 ② 里还是只有所有者能改**（服务端 403）。docs/95 §8 第 12 条建议「谁都能改、可撤回」。建议同上并进 C 单。
6. **① 里「以后都这样」那张策略卡被批了以后没有地方真的落库**（今天 ③ 也一样，是老缺口，不是这单引入的）。建议另开一单，把「以后都这样」落成职责规矩里的一句话。

## 4.2 合并前的补改（界面少字）

审核方指出 ① 的超限卡上同一句「超了你设的上限…要你再确认一次」出现三遍（标题下、正文框、按钮旁）。改成只说一遍：
- 按钮旁那句「超了你设的上限，要再点一次才算」保留（它和点两下绑在一起）；
- 标题下只写超了哪几项：「超金额、毛利上限」（`reconfirmReasonText` 改短；审批总线对一般改动卡不再自己补那一句）；
- 正文那一句与标题下那行一模一样时不出正文框（工作台 `deck-card-body`，对所有卡生效）；B2B 报价 ① ② 的摘要就写这一句，所以框不出；
- ③ 的同一张卡也有一处重复（标题下「转给了老板」、正文「…转老板批」）：路由口给了理由时，摘要只写「超了授权（金额、毛利）」。这是 ③ 唯一的字面变化，行为不变；`supervisor` 一条老用例跟着改了期望（`b2b-store` 那条没装路由口、卡上没有那一句，摘要照旧说转给谁）。
- 补改后：工作台卡片相关 4 个文件 95 条过；verify-changed 5873 条只红 1 条（就是上面 `b2b-store` 那条，期望改错了，已改回、该文件与 supervisor / wp275 共 19 条过）；b2b-3c-3p × 三运行时 26/26、门禁通过、基线无漂移；三张截图重拍。


- 「② 改共用岗位 → 通知 + 可撤回」只覆盖职责规矩 / 额度 / 自动化上限 / 策略层（第 3 节第 3 条）。
