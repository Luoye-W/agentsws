# WP319 报告：Windows 真机三个问题（店铺已连仍说没连、更新慢像被删、卡在「进行中」的失败任务）

分支 `wp/319-winfix`（worktree `../agentsws-wt/wp319-winfix`），派工单 `docs/briefs/WP319-win-shopify-status-and-update.md`。没推、没合、没打 tag、没发版。

**真机说明**：Windows 测试机这次连不上——Tailscale 能 ping 通（6–12 ms），但 22 端口一直超时（本单期间前后试了 7 次），像是那台机上的 OpenSSH 服务停了或防火墙拦了。改系统 / 安全设置属禁止项，我没碰。三个问题的根因都改用**代码 + CI 真机日志**取证（见各节「证据」），真机那一侧的核对放在下面「下一版怎么在真机上验」。

## 1 店铺已经连上了，面板还说「还没连接店铺后台」

**根因**：工坊里「连没连上店铺」有三份记录——
1. 连接器里的老连接（`shopify_admin`，自定义应用令牌 / 客户端凭据，WP25 / WP46）；
2. 连接页 Shopify 卡的**云端一键授权**（WP265，店铺令牌只在云上）；
3. 岗位页的 **CLI 店铺授权**（WP261）。

运营工具（「查商品」那些）用的是 2 优先、没有才 3（`preferCloudShopAdmin`）；岗位就绪（「还缺必需的连接」）也认 2（`extraKinds`）。**只有面板（`live-data.ts`）只认 1**：`activeShop()` 只在连接器连接里找 `shopify_admin`，订单也只经连接器的 `list_orders` 拉。Rollout 是在连接页一键授权连的店，所以「查商品」查得到、面板却一直「去连接」。

**证据**：`apps/server/src/live-data.ts` 的 `activeShop()` / `sources()` 只读 `options.connections.liveConnections()`；`server.ts` 里 `cloudShopLinks` 只喂了 `extraKinds` 与 `preferCloudShopAdmin`，没喂活数据源。新测试 `wp319-shop-panel.test.ts` 的端到端那条在修之前就是这个现象（一键授权连上后分块 `connected: false`）。

**改了什么**（`17857d4f`）：
- 面板认同一份：连接器里没有店铺连接时，店铺管理授权（云端优先、CLI 其次）连着就算「店铺后台」连上；近 30 天订单经只读 Admin GraphQL（新查询 `AgentswsLiveOrders`，不带顾客个人信息，要切产品线时才带行项目、一页少拉几张免得超查询成本）拉，进内存缓存，规矩与 WP46 一样（订单原文不进事件 / 日志）。
- 授权失效 / 缺读订单权限 → 照实算没连（去连接页重新授权），不留一排旧数；断网 → 留上一份标旧；什么都没有 → 照旧「去连接」，一分钟内不反复去问。
- 云端连店缓存作废时（刚连上 / 撞上授权问题）面板下一次读之前重拉。连接器那条在的时候照旧走连接器，一行不变。
- **GA4、评价应用那几行**：核过，判断是对的——GA4 面板与 GA4 读数（`google-reads.ts`）认的是同一份连接（`ga4` / `google_analytics`），「转化率」那块本来就是 GA4 的数，GA4 没连就该说没连；评价应用（Judge.me / Loox）连接目录里还是「待增加」，那一行说「还没接上」不给「去连接」，是对的。

**还没做**：「库存告急数」在面板活数据里一直没有库存来源（连接器那条路也没有，现在显示 0）。见决策 633。

## 2 点「重启更新」后很久才起来、期间像被删了

**根因（慢在哪）**：慢在 NSIS 安装那一段，不在下载。CI 两个真实版本之间点更新（`desktop-windows.yml` 的 update-e2e，run 37922723813，10-09）：

| 这一段 | 用时 |
|---|---|
| 下载 N+1（本机更新源） | 约 2 秒 |
| 点「重启并更新」→ N 退出 | 约 1 秒 |
| **N 退出 → N+1 服务健康** | **3 分 35 秒** |
| 同一个包**全新**静默安装（没有卸旧那一步） | 3 分 06 秒 |

安装慢的原因：`asar: false`（服务进程跑在随包 Node 上，读不了 asar），安装目录是上万个小文件——业务代码与依赖、随包 Node + npm（npm 一家 2009 个文件）、dsh 那二十几个包（补齐依赖时整包拷进来，连 `.d.ts`、`.map`、TS 源码都在）。NSIS 静默更新时：① 跑三次 PowerShell 查 / 结束安装目录里的进程（安装程序、旧卸载程序各一轮）；② 旧卸载程序把旧目录里的文件**一个一个**挪到临时目录再删（`atomicRMDir`）；③ 新包里的文件一个个解出来，杀毒逐个扫。全程**静默**，所以窗口一关桌面上什么都没有；这几分钟里 `agentsws.exe` 已经被挪走、桌面快捷方式还留着（更新时保留快捷方式），点它就是「应用不存在」。

**改了什么**（`7a92ff3e`）：
- **看得见**：点「重启并更新」后，先起一个**不在安装目录里**的小窗（系统自带 PowerShell + WinForms，脚本放临时目录、带 BOM 免中文乱码）：「正在更新到 x.y.z」+ 走动的进度条 + 「装好会自动打开」，置顶、任务栏里也有。用户数据目录里同时写一张「正在更新」单；新版一启动就收掉单子，小窗看到就自己关，日志记一行「更新用时 N 秒」。装不上 / 新版起不来，小窗最多挂 15 分钟。起不来不挡更新。下载进度原来就有（WP218），静默装 + 装完自动开（`quitAndInstall(true, true)` + `--force-run`）原来也有。
- **装得快一点**：afterPack 加第 ⑩ 步瘦身——删 `.d.ts` / `.map` / `tsbuildinfo`、我们自己包里的 TS 源码与 `test/`、各包根目录的说明文件与 test / example 目录、随包 npm 的 `docs` / `man`；第三方包的 `src/*.ts` **不碰**（dsh / cordis 在 exports 里登记了 `./src/*`）。瘦身放在 afterPack 冒烟之前，删完照样要过「捆绑 Node import 服务入口 + 跑 npm」。Electron 语言包只留中英（少五十多个）。
- **量得出来**：afterPack 打一行「安装目录 A → B 个文件」；win-install-smoke 记「静默装 N 秒、安装目录 N 个文件 / MB」；win-update-e2e 记「从点重启到新版健康 N 秒」，并核对小窗起来了、新版起来后关了（没起来就红）。

**离 10 秒还差多远**：瘦身按本机依赖粗估能少三到五成文件（真数看下一版 CI 那一行），安装时间大致跟着降，但到不了 10 秒——要到 10 秒级，安装目录得从上万个文件降到几百个（把服务进程打成少数几个 bundle），见决策 630。这一单先做到「全程看得见 + 能量化」。

### 下一版怎么在真机上验（更新那块）

注意：小窗是**旧版**在点「重启并更新」时起的，所以 beta.4 → 下一版**还看不到**小窗（beta.4 没这段代码）；**下一版 → 再下一版**才看得到。瘦身则是新包本身，下一版装上就生效。

1. 发版前：手动跑一次 `desktop-windows.yml`，看两处日志——NSIS 作业 afterPack 那行「瘦身：删了 … 安装目录 A → B 个文件」与 smoke 报告「静默装 N 秒；安装目录 N 个文件」；update-e2e 作业「从点「重启并更新」到这里 N 秒」「「正在更新」小窗：起来了 / 关了」。对照本报告的 3 分 35 秒 / 3 分 06 秒。
2. 真机（Windows 测试机，SSH 恢复后只读）：在当前版本上点更新到下一版，等它自己起来；看 `%APPDATA%\@agentsws\desktop\logs\desktop.log` 里新版启动那一段——这一跳是从 beta.4 起的，没有「更新用时」；数一下安装目录文件数 `(Get-ChildItem -Recurse -File $env:LOCALAPPDATA\Programs\agentsws).Count`，与 beta.4 比。
3. 再下一版：真机点「重启并更新」，应当窗口一关就看到「正在更新到 x.y.z」小窗、点桌面图标前就有提示；新版起来小窗自己关；`desktop.log` 里有「更新用时」那一行（秒数）。

## 3 卡在「进行中」的「查询店铺当前在售产品」

**根因**：是**老数据**，不是新问题。那一条是 10-09 Rollout 真机「店里有哪些产品」那一轮（docs/35 10-09 热修：dsh 工具参数表不认，运行一启动就挂，当时界面却显示「跑完了 · 1 秒」）。那时的版本：时间线只记了「开始跑了」「跑完了」、没有「没跑成」那一句，事项摘要落的是原始错误「dsh 组合装配失败：…unsupported…」。岗位工作分组（WP244）看最近一轮的收尾：没有「没跑成」、没有 AI 的话、没有卡住标记 → 归「进行中」，旁边那行进展取的是摘要原文。WP287（10-09 同日，`5b418328`）之后新跑的：没跑成会记「没跑成：<人话>」+ 重试、摘要写人话——**但老事项不会自己改过来**。

**证据**：`runtime.ts` 收尾在 WP287 之后对 `failed` 写 `recordFailure` + 人话摘要（`5b418328`，10-09，早于 beta.2 / 3 / 4）；`position-work.ts` 的 `matterRunStateOf` / `openMatterPhase`：没有收尾信号 → `doing`。原始错误「dsh 组合装配失败」只可能出自 10-09 修复之前的版本。真机库没查成（SSH 不通），查法见「下一版怎么在真机上验」第 2 条同一条路：`events.db` 里按这条事项最近一轮 `run_id` 查 `run.failed` 的时间，应早于 10-09 17:46。

**改了什么**（`18a75326`）：开机自检（每个品牌装配时，那时还没有运行在跑）扫开着的事项，最近一轮**没收尾**的按本机事件日志补一句：
- 有 `run.failed` → 「没跑成：<人话>」+ 失败标记（界面出「重试」），原始错误仍只在事件日志；
- 只有开跑、没有任何收尾（跑到一半应用被关 / **被更新重启**）→ 「没跑成：上次没跑完（应用关了或更新了），点重试再跑一次」；
- 有 `run.completed` / `run.cancelled` 或查不到运行事件 → 不动（说不清的不编）；
- 摘要里挂着原始错误的换成同一句人话；幂等（补过一次就是收了尾的）。

自检之后那一条落到「卡住」组，进展一栏是人话，点「重试」按原话再跑一次。

## 5 自主做的决定（白话）

1. 面板**连接器那条优先**、没有才认店铺管理授权：老用户（连接器连着店）一行不变；新的一键授权用户也能出数。
2. 店铺管理授权缺「读订单」权限时，面板算「没连」并给「去连接」（点进去是连接页 Shopify 卡的「重新授权」），不显示一排 0。
3. 小窗用系统自带的 PowerShell 画，不改 NSIS 安装脚本：NSIS 那一侧我在本机编不了也跑不了（没有 Windows、没有 makensis），改坏了就是装不上；PowerShell 小窗起不来最多是「没有小窗」，更新照常。CI 的 update-e2e 会真起一次、核对它起来又关掉。
4. 瘦身只删点名的几类；第三方包的 TS 源码不删（dsh / cordis exports 里登记了 `./src/*`），README 只删包根目录那一份（数据目录里的 README 可能是内容）。
5. 开机自检把「跑到一半被关 / 被更新」也补成「没跑成」：更新重启正好会造成这种中断，不补的话它们也会永远挂在「进行中」。
6. 决策号从 630 起（main 上 580–584 已用，630 以后没人用）。
