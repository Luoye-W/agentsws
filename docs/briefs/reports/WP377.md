## 1. 调研（第一步）

### 1.1 怎么查的

- **上游官方**：DeepSeek 官方文档（思考模式页、价目页）；其余几家用官方 pi-ai 1.1.0 的生成目录（dsh 订阅那一条用的同一份，`thinkingLevelMap` 与 `compat.thinkingFormat`，各家官方地址那一行）。
- **我们的转发链路**：云端 `/v1/ai/chat/completions` 一直是**请求体原样转**（`packages/cloud-entry/src/ai.ts`），先走 New API，New API 不可用时 DeepSeek 模型退直连 DeepSeek 官方。New API 线上是 `calciumion/new-api:v1.0.0-rc.40`，我把这个 tag 的源码对过：它的请求结构保留 `thinking`、`reasoning_effort`、`enable_thinking` 三格；DeepSeek、智谱、月之暗面、阿里、OpenAI 这几种渠道都原样转（DeepSeek 渠道只在模型名带「思考后缀」时才改写，我们不用后缀）。另外 WP243 起云端已经在给 DeepSeek 转 `thinking: {type: disabled}`（关思考），线上一直正常——等于这条路已经被用过。
- **计费**：DeepSeek 价目页写的是「按输入、输出 token 总数计费」；OpenAI 兼容口的通行口径是思考 token 算在 `completion_tokens` 里（另在 `completion_tokens_details.reasoning_tokens` 标出）。我们按 `completion_tokens` 结算，**思考 token 已经照实按输出价收**，不用改，也不会重复算。

## 4. 我自主做的决定（白话）

1. **开源分支从 `wp/373-rc1` 拉**：小钮是 WP373 的，main 上还没有。要先合 WP373，再合本单。
2. **私有子模块临时指开源 `wp/377-thinking`（cdde7830）**，锁文件和工作区尾段跟着更新（WP363 的老做法）；合并时改指开源 main。因为 WP373 的 dsh rc.2 也一起进来了，私有锁文件变化较大，都是 dsh 包换号。
3. **对外只给档位，写法留在云端**：契约里只有 `efforts` / `default`，「这家怎么写」不进开源仓（换上游、换写法不用动客户端）。
4. **客户端发我们自己的 id，不发各家原生写法**：一套 id 走到底，云端翻译；这样以后打开别家，客户端一行不用改。
5. **别家先关着而不是不写**：表写全、测试写全，打开只改一个 `enabled`。
6. **样本回包是按官方文档构造的**（不是真录的，文件里写明了），因为本单不许调付费接口。
7. **冒烟多查一格**：真 workerd 上叠了渠道成本之后，价目那一行的思考档还在。
