## 2. 落地（第二步，只做了「能调」且现在开着的 DeepSeek）

1. **云端价目声明档位**（私有）：新表 `packages/metering/src/reasoning.json`（数据不是代码：每家怎么写、每个模型几档、默认哪档、哪家开着）；价目里 `ai.chat` 的模型行多一格 `reasoning: { efforts, default }`，老名字照抄正名。开源契约 `PricingModelEntry.reasoning` / `PricingModelReasoning` 只加不删，`cloud-openapi.json` 已重出（顺带一处枚举顺序变化，是生成器按类型创建顺序排的，零语义变化）。
2. **三档写明**（1054）：价目那一格多一个 `levels`（只加），云端写明三档各落哪一档——v4 Pro 快 = `off`、标准 = high、深度 = max；Flash 快 = low、标准 = high、深度 = max。客户端有 `levels` 就照它出，没有就按 WP370 的老规矩挑。
3. **云端转发**（私有 `ai.ts`）：客户端发我们自己的 id（`reasoning_effort: "max"` 等），云端按上游写法改写：DeepSeek = `thinking.type` + `reasoning_effort`，关 = 只写 `thinking: disabled`。别家的写法（智谱、OpenAI、通义）也写好了、有测试，等开。**不支持的**（没声明、那家没开、不是它的档、不认的值）→ 去掉这一格照常转、按模型默认跑，不报错。没带这一格的请求一个字节不改。
4. **开源客户端**：工坊积分的模型照价目那一格算出 WP373 的小钮（两个模型都是「快 / 标准 / 深度」），没写不出；选 v4 Pro 的「快」就发 `off`，云端翻成 `thinking: disabled`；选了哪档，打云端的请求体里就发那一档的 id（「显示什么就发什么」，1032）；调用方硬要「别想」（WP243）时只发关思考那一格。
5. **计费**：不改。思考 token 在 `completion_tokens` 里照实按输出价收（Fable 实测确认）；消耗速率（WP364）口径不变。
6. **没渠道的模型不进 AI 钮**（Luoye 10-17 让查）：查了——**会**。工坊积分的 AI 钮把公开价目 `/v1/pricing` 里每个按 token 计价的模型都列出来（WP362 `knownModels` → 价目），glm / gpt / kimi / qwen 等三十多个都在；New API 只有 DeepSeek 渠道，选了别家会回「模型服务暂时不可用，这个模型没有备用线路」（不扣钱，但用不了）。改动很小、只加不删，直接做了：
   - 私有 `pricing.json` 多一格 `ai_channel_vendors: ["deepseek"]`（New API 真接了渠道的那几家）；`buildPricing()` 给别家的模型行标 `available: false`。价照算、照旧在表里（结算和价目页不受影响）。百炼上的 deepseek-r1 / v4.1-flash 也算别家。
   - 开源契约 `PricingModelEntry.available`（只加；不写 = 能用，老云端行为不变）；客户端 `cloudRates` 只把没标 `false` 的列进 AI 钮和默认模型下拉。
   - 以后在 New API 加一家渠道：把那家 id 加进 `ai_channel_vendors`，重部署即可（想开思考档另在 `reasoning.json` 打开）。

## 4. 我自主做的决定（白话）

1. **开源分支从 `wp/373-rc1` 拉**：小钮是 WP373 的，main 上还没有。要先合 WP373，再合本单。
2. **私有子模块临时指开源 `wp/377-thinking`（cdde7830）**，锁文件和工作区尾段跟着更新（WP363 的老做法）；合并时改指开源 main。因为 WP373 的 dsh rc.2 也一起进来了，私有锁文件变化较大，都是 dsh 包换号。
3. **对外只给档位，写法留在云端**：契约里只有 `efforts` / `default`，「这家怎么写」不进开源仓（换上游、换写法不用动客户端）。
4. **客户端发我们自己的 id，不发各家原生写法**：一套 id 走到底，云端翻译；这样以后打开别家，客户端一行不用改。
5. **别家先关着而不是不写**：表写全、测试写全，打开只改一个 `enabled`。
6. **测试回包换成了 Fable 实测的真回包**（我先查过没有 key / 账号信息）。
8. **三档映射由云端写明（`levels`），不改客户端的通用规矩**：只有 v4 Pro 这种「官方有更浅档但实测没区别」的情况需要，写在云端数据里最小、也不影响订阅 / DeepSeek 账号那几条来源。
9. **「有没有渠道」写成一张静态名单**（`ai_channel_vendors`），不去实时问 New API：改动最小；代价是加渠道时要顺手改一行（已写进那张表的说明）。
7. **冒烟多查一格**：真 workerd 上叠了渠道成本之后，价目那一行的思考档还在。
