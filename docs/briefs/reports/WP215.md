# WP215 报告：每个品牌的后台同时跑（不管眼前切在哪个品牌）

分支 `wp/215-brands-bg`（worktree `agentsws-wt/wp215-brands-bg`），Claude 子代理；工作台与模拟两块各交给一个子代理做，由我审过、统一提交。契约只加不改。

## 0. 原来哪些后台活只跑第一个品牌

切品牌一直只是换视图、不停进程；问题在**装配**：

| 后台活 | 原来 | 后果 |
|---|---|---|
| 每日计划、晚复盘、周 / 月复盘、次日接力、闲置提醒 | 只按第一个品牌的工作模型、岗位、队列装配；系统任务只给第一个品牌建 | 第二个品牌一张计划 / 复盘卡都没有 |
| 会议记录源轮询、学习夜扫（每天 07:30）、技能周合并、组织对象查重 | 同上 | 第二个品牌的学到的东西、重复对象从不出卡 |
| 收信、Amazon SLA、出站对账、令牌刷新、红人 / B2B 开发信、社媒发布与群发、品牌监控（Reddit 等）、内容与搜索、聊天求助、首响 SLA | 处理器里循环所有品牌，但**任务只有第一个品牌那一条** | 能跑，但第二个品牌没有自己的任务、看不到自己的状态、停不了它一个 |
| 自建定时任务、官方「自动化任务」 | 自建定时的岗位校验只认第一个品牌 | 在第二个品牌里建定时直接 404 |
| 秘书、IM 团队渠道（企业微信 / 飞书 / 钉钉） | 全进程一份，工作区定死在第一个品牌 | 在第二个品牌里问秘书看到第一个品牌的事；IM 状态页直接 403 |

顺带查出几处**已经在串品牌**的：学习回路里 lesson 入池、`knowledge_update` 卡批了写知识库、技能晋升、周合并卡，一律落在第一个品牌——B 品牌批的口径会写进 A 品牌的知识库（测试钉住：撤掉修复即红）。工具箱的晋升卡施行、会议开事项与待认领池也是同一种写法。

## 2. 怎么做的（白话）

- **一个闹钟，多本账。** 电脑上只有一个调度循环；每条定时任务身上本来就写着它属于哪个品牌。以前「到点了干什么」只登记了一份，用的是第一个品牌的东西。现在每个品牌各登记一份，到点时按任务自己写的品牌去找那一份。找不到就让这一次失败（列表上看得见），**绝不拿别的品牌那一份凑数**。
- **每个品牌各一套任务。** 启动时给公司里每个没停用的品牌建齐它的任务（收信、巡检、计划、复盘、学习夜扫……）；新建品牌那一刻就建，不用重启。第一个品牌原来那些任务 id 一条不动（用户改过的时间、停过的开关都还在），别的品牌的 id 后面带 `__<品牌 id>`。
- **家务只一份。** 审批过期、幂等清理、原始材料保留期、备份、模型价刷新，这几件不属于哪个品牌，照旧挂在第一个品牌名下一份；品牌急停不停它们，状态里也不数它们。
- **眼前切到哪都不影响。** 前端切品牌只是换一张令牌、换视图；后台活全在服务进程里按品牌常驻。审计和事件照写各自品牌的 `workspace_id`。

## 3. 怎么保证不串品牌

1. **分发只看任务自己的品牌。** 品牌路由按 `task.workspace_id` 找处理器；不是这家公司的品牌一律不替它跑；没装配就失败，不退回第一个品牌。
2. **处理器里每样东西都现取这个品牌的。** 工作模型、活数据、连接、渠道、消息、队列、岗位，全部经品牌模块按这个品牌取（品牌模块被重建过也拿到新的那一份）。卡的 `workspace_id`、去重键、收件人、挂的岗位都是那个品牌的。
3. **把原来写死第一个品牌的地方全改掉**（见第 0 节最后一段），学习回路这一处有测试证明原来真的串、修完不串。
4. **找不到人就不出卡。** 某个品牌里找不到负责人时，它的学习卡、系统任务先不建，绝不挂到别的品牌的人头上。
5. **模拟也钉住。** 新场景里故意改坏四种（写进眼前品牌 / 只登记一份 / 急停一按全停 / 急停不生效），每种都红。

## 4. 自主做的决定

1. **并发默认 2、范围 1–4，全进程一个数。** 同一品牌永远一件接一件（同一只邮箱不会被两轮同时拉），品牌之间最多 2 件同时跑。
2. **全局急停开着时，所有品牌的后台定时也停**（家务除外）。原来全局急停只拦对外发送与模型，定时巡检照跑；既然叫「急停」，背景活也该停。这是一处行为变化。
3. **品牌急停 = 这个品牌的全部档位**（定时、对外发送、模型），不分档；只有这个品牌的负责人能按（与 `/v1/halt` 只给 owner 同一条线）。记 `halt.changed`，记在那个品牌名下、payload 多一位 `brand`。
4. **停用 = `Workspace.status === 'archived'`。** 停用的品牌整套后台不跑；删品牌整条路仍不在本单。
5. **「在跑的定时任务数」照实数**（品牌级任务里 `active` / `running` 的）。demo 里第一个品牌是 138 条，因为负责人一人挂了很多岗位、每个岗位四条计划 / 复盘任务——数字是真的，只是大。
6. **个人微信跟人走**，只在第一个品牌那一套上开（同一个微信号开两条长轮询会互相顶掉）；在别的品牌里去绑会被拦，提示「切回第一个品牌绑一次就行」。团队渠道（企业微信 / 飞书 / 钉钉）按品牌各一套，凭据按品牌存。
7. **跟随公司默认的品牌**借的是公司默认品牌的网关；我在外面再套一层这个品牌自己的急停，这样 B 按了急停，B 借来的网关也打不出去，A 照常。积分归属本来就按请求的岗位（WP194 的归属头），所以按品牌 / 岗位算。
8. **切换器下拉改成往上开。** 切换器在 WP207 之后挪到了左栏最底下，下拉往下开会被屏幕底边裁掉（拍截图时发现）。
9. **按职责才建的那几条定时**（红人 / 社媒 / 公关 / B2B / 内容）看的是**这个品牌里**有没有人持有那条职责（原来是全公司任何品牌有人就建在第一个品牌）。

## 8. 剩余限制

- **后台跟着这台电脑走：** 关机、睡眠、断网时所有品牌都停（醒来后按每条任务的错过规则补跑或跳过）。云上常驻按品牌订阅另议（52 O5）。
- 首次设置向导、Join、值守、离职编排仍按第一个品牌；工具箱「合并」按钮与手动加记忆这两条**请求路径**仍落第一个品牌（不是后台活，本单没动）。
- 启动时会把公司下每个品牌的模块都建出来，内存随品牌数线性涨（WP66 就有，没做闲置回收）。
- 两个真账号（真 Reddit / 真邮箱 / 真 Shopify）一次没跑过，全在替身与合成世界里过。

## 12. 第二轮（Fable 10-05 定五问 + 必修一条）

Fable 定：① 全局急停就是全停（五件家务除外），docs/52 写明；② 并发默认 2、上限 4 照旧；③ 微信里切品牌以后再做；④ **品牌急停公司管理员也能按**；⑤ 云端常驻以后再排。

这一轮做的：

- **品牌急停：负责人 + 公司所有者 / 管理员。** 服务端判（同一家公司的品牌、那个品牌的 `common.owner` 或组织 owner / admin，否则 403）；路由改成实现里判（`authzBypass`），因为公司管理员在这个品牌里未必有写策略层的岗位。工作台：组织页给没有所有者岗位的管理员也出「停后台 / 放开」，拿他自己的岗位发。测试：服务端「管理员能停、普通成员 403」，工作台「管理员拿自己岗位发」。
- **按职责即时建 / 停定时（必修）。** `RoleStore` 只加一个可选订阅 `onAssignmentChanged`（建 / 改 / 撤都喊一声）；服务端收到就把那个品牌的定时对一遍（同一品牌排队合并、不并发）：有人担了就建红人 / 社媒 / 公关 / B2B / 内容那几条和这个人的每日计划 / 复盘；没人担了就暂停并打记号 `params.auto_stopped`，又有人担了只放开带记号的——**人自己按的暂停不碰**。启动时也对一遍（离线期间撤掉的职责）。`server.background.settled()` 等这些异步装配做完。测试：建品牌 → 分配 `pr.reddit` → 监控任务立即出现、15 分钟后准点触发 → 撤销后暂停、到点不跑 → 再分配又放开；人工暂停的不被放开；分配新岗位每日计划立即建上、撤了就停。roles 包另有订阅的单测。
- docs/52 §4.2 写明全局急停全停、管理员可按、按职责即时建 / 停；剩余限制里删掉「要等重启」那一条。
