# WP196 报告：改名扫描（「店主」→「负责人」、用户看得到的「agentsws」→「Agents 工坊」、岗位可改名）

分支 `wp/196-naming`（worktree `agentsws-wt/wp196-naming`），已合并一次 main。实现方：Claude Opus（子代理）。

## 1 实现清单

**岗位名：「店主 / 负责人」→「负责人」（英文 Lead）**

- 种子岗位（`apps/server/src/org.ts`）：id 仍是 `owner`，中文「负责人」、英文「Lead」（导出常量 `OWNER_POSITION_NAME`）。
- 老工作区迁移：每次启动时看一眼 id `owner` 那个岗位，中文名**逐字**等于旧出厂名（「店主 / 负责人」「店主/负责人」「店主」）才换成「负责人」，英文名逐字等于「Owner / Shop Owner / Store Owner」才换成「Lead」；中英各判各的。用户改过的名字、别的岗位碰巧叫「店主」的，一律不动；跑几遍结果都一样（纯函数 `migrateOwnerPositionName`）。
- 模拟包合成数据：王岚的职位「店主」→「负责人」、「店主 / 售后」→「负责人 / 售后」，公司简介那句同步（`synth.ts` 与 `packs/*/people.yml`、`workspace.yml`、`packs/README.md`）。
- 官网静态稿（WP193 的 `docs/design/site/home*.html`）岗位格子里的「店主 / 负责人」→「负责人」（只改字）。

**职责名：「工作区所有者」→「公司设置与授权」（Company Settings & Permissions）**

- `packages/roles/roles/common/owner.yml`：名字、说明（「连接器授权」→「连接授权」）、persona「你是谁 / 你负责」中英两段同步；id `common.owner`、动作、额度一个字没动。
- 界面里指这条职责的：`need.duty.owner`（「你名下没有『…』这条职责」那句）→「公司设置与授权」；「找工作区所有者……」三句（公司页无权限、岗位没范围、连接页无权限）→「找负责人……」（英文 → your Lead）。
- 只读工具被拦时回给模型的那句 → 「只有『公司设置与授权』这条职责能看全部岗位与连接」。

**提示词与技能里把用户叫「店主」的**

- `policy-review`：「帮店主把……」→「帮负责人把……」，「列出来让店主选」→「让负责人选」，「装在工作区所有者上」→「装在『公司设置与授权』上」；评测集 `evals.json` 的 `must_include` 同步。
- `workspace-basics`：「提醒店主可以加一个岗位」「店主在职责设置里定的自动化级别」→「负责人」。
- 建站检查单两句「请店主自己去 Shopify 后台点一下」「域名要店主去注册商改解析」→ 直接说「你」（英文同步）；Shopify 支付设置不可写那句、红人「让店主把这条职责分给你」→「负责人」。

**岗位可改名（公司 → 岗位卡）**

- 岗位名旁边一个小「改名」（铅笔）；点开是中文名 / 英文名两格 + 问号说明（「只改显示的名字……职责、谁在做、活怎么分都不变」）+ 取消 / 保存；中文名空着存不了，英文名空着 = 英文名不变。英文界面下岗位卡显示英文名。
- 走原来的 `PUT /v1/org/positions/:id`（契约没加字段，`name_en` 本来就有），**职责原样带回**（连「可选」那几条的勾选也不动）。
- 服务端：只改名、职责一条没动时**不升版本、不把来源从 bundled 改成 custom**（改名不是改模板）；另记一条审计事件 `position.renamed`（`from` / `to` 各带中英）。加减职责照旧升版本。空名字 → 400。
- 路由核实：岗位内路由（`routeWithinPosition`）与秘书路由只看**职责**（id、职责名、判据词），不看岗位显示名；岗位名只进提示里的「岗位层上下文」那一行（`position_name`）和选择卡上给人看的名字。测试钉住：改名后在这个岗位上问「有哪些岗位和连接」照样交给 `common.owner`。

**用户看得到的「agentsws」→「Agents 工坊」**

- 服务端话术（进界面 / 进报错）：「还没关联 agentsws 账号 / 云账号」→「Agents 工坊账号」（值守、积分、红人库同步、公共红人库、插件贡献、渠道开关，十来句），「连不上 agentsws 云」→「连不上 Agents 工坊云端」，渠道开关「用 agentsws 的」→「用 Agents 工坊的」（与界面开关同一个叫法）；`kol-core` 公共红人库没连那句同步。
- 顶栏模型芯片：`agentsws/型号` 显示成「Agents 工坊 · 型号」（英文界面「Agents Workshop · 型号」），悬停说明同步，芯片放宽到能放下；id 不变、链接不变。
- 桌面壳：托盘悬停的产品名按界面语言（英文界面不再是中文「Agents 工坊」）；「导出诊断包」默认文件名 `agentsws-诊断-…zip` → `Agents工坊-诊断-…zip`。
- 红人云导出文件名 `agentsws-kol-cloud-…json` → `agents-workshop-kol-cloud-…json`。
- 命令行 `--help` 那句说明 → 「Agents 工坊的本地命令行（命令名 agentsws）」（命令名不变）。
- 浏览器插件设置页与商店文案、教程 `chat-window`（中英）：「Agents 工坊云账号」→「Agents 工坊账号」（与 WP188 定的账号页标题一致）。
- README 模型卡列表里「agentsws 云」→「Agents 工坊（用积分）」。

## 2 自主决定（白话）

1. **迁移只认 id `owner` + 逐字旧名**：别的岗位就算叫「店主」也不动（可能是用户自己建的）；中英分开判，所以「中文改成 CEO、英文还是 Owner」的只换英文。
2. **只改名不算改模板**：以前任何修改都会把版本号 +1、来源从「内置」变成「自定义」。改名只动名字，版本和来源不变——否则改个名，这个岗位以后就吃不到内置岗位的升级了。
3. **改名单独记一条 `position.renamed`**（带改前改后中英名），原来那条 `position.updated` 照发，不影响谁在听它。
4. **「工作区所有者」分两种**：指那条职责的（「连接由……管理」「找……指一下范围」）改成「负责人」；指身份的（「不能离职 / 不能被移出，先把所有者换给别人」）不动。
5. **建站检查单直接说「你」**：看这张检查单的通常就是店的负责人本人，「请店主自己去后台」对他是第三人称，改成「请你自己去 Shopify 后台点一下」。
6. **桌面安装包名没改**（理由见第 3 节第 1 条）。
7. 官网静态稿里的岗位名顺手改了（WP193 合并记录点名留给本单），`shots/` 截图没重拍。

## 3 需要 Luoye 定的事

1. **mac 安装包 / .app 叫不叫「Agents 工坊」**：改 `productName` 很容易，数据目录也不会跟着变（查过 electron-builder：它不往 package.json 里写 productName，数据目录按 package.json 的名字走）。但 mac 现在没有自动更新，内测同学是「下新的 dmg 拖进应用程序、覆盖旧的」（docs/62 §3）——一改名，拖进去的是「Agents 工坊.app」，旧的「agentsws.app」不会被覆盖，两个 App 共用一份数据、托盘上可能出两个图标。建议：等签名 + mac 自动更新上了再改（那时 Squirrel 原地替换，不会并存）；或者现在就改，发版说明里写一句「先删掉旧的 agentsws」。你定哪个，我按那个改（改的时候会把安装包文件名钉成现在的 `agentsws-…`，docs/62 的下载说明不用动）。
2. 账号菜单里身份那格中文界面显示英文「Owner」（`account.role.owner`）：要不要改成「负责人」？它说的是账号身份（建工作区的那个人），和岗位名是两回事，但用户多半分不清。
3. API 路由 summary / OpenAPI 标题里的「agentsws」要不要也换（会重出 SDK 与云端契约，给开发者看的）？
