# WP236 报告：研究任务 60 秒被静默取消 + 几处工具问题（Windows 实测）

分支 `wp/236-runtimeout`（worktree `agentsws-wt/wp236-runtimeout`），Claude 子代理。

## 0. 一句话

一次运行不再有「固定 60 秒」：**连续没动静才停**（缺省 3 分钟）、**再忙也有总时长**（缺省 20 分钟），三个运行时档同一个看门狗；
停下来时时间线说一句人话，模型说过的话和已经取回的数据作为部分结果留在事项上，点「接着跑」续跑同一事项。
另外：`read_reddit` 缺 action 能推断、默认只取 10 条、每次运行有取数积分预算；工具面只放真接上的工具；
Shopify Dev MCP 只有建站类职责第一次运行才启动。

## 2. 自主做的决定（白话）

- **看门狗放在宿主那一层**（`startRun`），不是每个运行时各写一套：三个运行时本来都认停止信号，宿主带着原因一停，谁都照实收尾。子进程自己那条线只当兜底（设置允许的最大值），免得和职责阈值打架。
- **「接着跑」不加新路由**：点了就是在这件事里替人说一句「接着上次没跑完的继续……」，时间线上看得到是人点的，权限、岗位、上下文全走原来那条路。
- **工具清单的筛法「没声明就不筛」**：只有真的记录源声明了自己能干什么；模拟世界与替身不声明，回放字节不变。
- 运行时长设置是**这台机器一份**（同浏览器设置）；改设置要店铺配置那一档权限（同浏览器设置）。
- 停下来的那句人话、部分结果是服务端写的中文（与时间线现有的 status 一致）；按钮与设置有中英两份。
- 社媒 Reddit 的「怎么做」（persona）没改：加一句就超 260 字上限，而且改中文要重出签名的英文产物；「先少取」写在它按需加载的研究技能和工具描述里。

## 3. 要 Luoye 定的事

1. **缺省数字**：空闲 3 分钟 / 总时长 20 分钟 / 每次运行取数 3 积分——照工作单定的；研究类职责要不要在 YAML 里直接放长（比如 `pr.monitoring` 总时长 40 分钟、取数 5 积分）？现在一条都没写，全走缺省。
2. 「取数预算用完」现在是**静默收住 + 让模型照实说**；要不要另出一张卡「这次预算用完了，要不要再给 N 积分接着取」？
3. 工具描述里的单价写的是 10-06 真机实测折算（约 0.05 积分一条）；价目表改了这句不会跟着变——要不要改成每次运行按价目表现填？
4. `route_to_community_support`（社群里冒出售后问题转客服）现在没接、不摆；要不要排一单接上？

## 5. 偏离

- 工作单「两个数进设置 / 职责阈值」：取数预算只进职责阈值（Fable 补充单只说职责阈值可调），没进设置页。
- `read-skill.test.ts` 有一条借 Dev MCP 文档工具当「普通只读工具」对照围栏，WP236 起邮件营销职责的工具面里没有 Dev MCP，换成记录源的「规矩与政策库」；`research-tools.test.ts` 那条中台入参断言补上 `limit: 10`；`stand-ins` 工具定义测试跟上「action 不必填」。
