## 2. 我自主做的决定（白话）

1. **B2B 库放在 `apps/server`**（照公关库 `pr.ts` 的位置），不塞进 `b2b-core`：`b2b-core` 的包说明写着"纯逻辑、碰不到凭据"。写法照 `packages/data` / `txn`：信封列 + JSON、`migrateSync` 版本迁移、每条查询钉 `workspace_id`；内存档就是同一份 SQL 跑 `:memory:`，不另写一份内存实现。
2. **报价版本"不可改"在库里再钉一次**：表上挂触发器，谁 UPDATE / DELETE 都报错（测试里绕过 store 直接写 SQL 也被挡）。
3. **加了一个 ChangeKind `b2b_record`**：WP171 那十三条都是"有钱或对外"的动作，没有"建一个客户 / 联系人 / 商机 / 展会 / 线索 / 出运单"这种。它 low 风险、不进硬顶，但每条都经卡；四条职责 yml 各加一个 `stage_b2b_record`，出卡规矩从 yml 读。
4. **"写都经卡"的边界**：九类对象只有执行器在卡批准后写。**邮件分拣落的询盘 / 往来记录、抑制名单不出卡**——它们是收信的记录（同消息库），docs/84 §5 第 5 条原话是"分拣时直接进抑制名单，不等 Run"。联系人的"已抑制"不回写联系人记录（那也是一次写），而是读的时候拿抑制名单现算。
5. **草稿与提交分两步**（`POST …/drafts` 不算数、`…/submit` 出卡）；CSV 导入是一步：解析 → 直接出一张 `b2b_list_import` 卡（导入本身就是那张卡）。库里已有的客户只借它的 id，不跟着导入卡再写一遍（免得盖掉别的卡改过的那一版）。
6. **服务进程里没有"部门负责人"**，所以报价超授权直接落老板（`quoteApprover(breaches, false)`）。服务留了 `scopeManager` 注入口，等组织里有部门负责人这个概念再接。
7. **抑制名单只存哈希**：`sha256(suppressionKey(地址))`，名单上给人看的是遮过的地址；比对时把收件人照同一口径算。**退订 / 退信不看 B2B 岗位开没开**——它只会拦主动外发，DTC 店的顾客说"别再发"也该记。
8. **分拣顺序**：B2B 的线程归并放在客服 / 红人线程归并之后、发件人规则之前；"发件人在 B2B 库里"放在用户教过的发件人规则之后（人教过的优先）；平台通知放在"自动信头"之前（这些通知都是 noreply、带退订头）。免费邮箱（gmail / outlook / qq / 163 …）的域名不算"这家客户"。
9. **"收 B2B 信"开关按邮箱**，缺省开（docs/84 §5 第 3 条：发开发信的那只邮箱也要开）。关着 = 这只邮箱上分拣不产出 `b2b`（不只是不挪）；人在「待确认」里点「这是 B2B」也交不出去。
10. **已经在 BtoBAgents 里的信**第一次被扫到：不开事项、不起 Run（与 WP167 对 KefuAgents 同一条），防的是第一次连上时回溯 30 天给老信花模型钱。
11. **平台询盘通知不起 Run**：正文在平台后台，起 Run 也只能对着一句摘要写回信；开一条「去 alibaba 后台回复这条询盘」的待办（浏览器模式是第二批）。
12. **红卡由分拣触发**（WP171 报告里记在"B2B-分拣"这一单）：信里要改收款账户 → 红卡、询盘照落、**不起 Run**；红卡没出成也不起 Run。
13. **左栏「B2B 往来」按岗位显示**：消息账户视图多一格 `b2b`（这只邮箱在收 B2B 信），有它或者已经有 B2B 那只文件夹的信就画（WP161 说"接上时改成按岗位判断"）。
14. **状态带文案**：B2B 那条路说「B2B Agent 在处理」，不借客服那一句（红人那条原来也借客服那句，本单没动）。
15. **`/v1/b2b/*` 放在路由表最后**：放在公关后面会让 SDK 生成物里后面几百条路径整体挪位，diff 没法看。
