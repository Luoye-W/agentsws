## 0. 一句话

岗位输入框换成事项页同一个输入框；发一句话**立刻进这件事的会话线程**，回答在线程里流式出现。问一句（查商品、看订单…）就是一段**会话**——左栏会话历史里找得到，不进岗位「工作」、不算「N 件在办」；要动手的（改价、发信、做一份…）才是**任务**，线程里一句话说「记成了任务」；会话答着答着出了卡，自动转成任务并说一句；会话页头有「转成任务」。岗位入口**永远不出「走哪条职责」的选择卡**，按分 / 岗位里的先后取，线程里一行「按「店铺管理」做的 · 换一条」（会话里这一行都不出）。运行没跑成（任何原因）时间线写「没跑成：<人话>」+「重试」，不再写「跑完了」；原始错误只进本机事件日志。复盘：全 0 不出、一个人一天一份、① 个人模式只记不出卡（岗位页「记录」里看得到）、第二天晚上自己过期、启动时把积压的老复盘卡收成过期。发给谁的卡谁就点得动；点不动的、到期了的不进「要你处理」、不算「N 张等你定」。键盘提示由卡上实际按钮生成。

## 3. 我自主做的决定（白话）

1. **问 / 交办先用规则判，不调模型**：有要动手的词（改、发、写一份、上架、退款、降价…）就是任务；问怎么做、问数、看看、一句话没动词都按问；一大段需求（多行或 ≥ 80 字、不以问号结尾）按任务。说的是已经发生的（「发了几封」「改过吗」）不算动手。规则判错的两头都有兜底：问被当成任务 = 老样子开一件事；任务被当成问 = 先答，答的时候真出了卡自动转成任务。
2. **会话也是一个事项**（带 `ask` 标记），不是另起一种东西：线程、流式、重试、换职责、左栏会话历史都现成能用；「转成任务」就是拿掉标记。
3. **会话只从三处隐身**：岗位「工作」、「N 件在办」、首页进行中；左栏会话历史、找回、归档照旧列（Luoye：「可以在记录 / 会话历史里找到」）。
4. **一开始就判成任务的，线程里也说一句**「这是一件要跟进的事，记成了任务，在岗位「工作」里看进展」（排在原话后面），与「会话转成任务」那句对称。
5. **`detach` 只给工作台用**，接口默认仍是跑完才回（CLI / SDK / 老测试一个字不变，回包里有 `answer`）。
6. **一个人一天一份复盘**，而不是「一个岗位一份」：卡数、待办都按人数，按岗位分也是同一份抄几遍。
7. **① 的复盘不出卡**：明天的安排要人确认时，早上那张「今天的安排」会问（没建议不出，WP244），复盘再问一遍就是两张卡问同一件事。复盘记在岗位页「记录」里。
8. **底座职责上的卡照样能点**：不靠改卡，而是决定时认「这个人名下有没有能批的分配」，所以已经发出去的老卡也点得动。
9. **到期了还没被清理的卡**不进牌堆、不算数（定时清理每轮才跑一次，中间那段会显示一张点不成的卡）。
10. **键盘**：→ ← ↓ 要求按钮露在动作行上（↓ 指导收在 `···` 里时按了开不了面板，所以不给）；↑ 稍后在 `···` 里也算（直接决定，不用开面板）。交给你的卡单岗位时 → 的字就是按钮上的字（岗位名），不再写「接下」。
11. **岗位页去掉「职责：自动」下拉**：Luoye 要求不让人选职责，岗位自己取，线程里能「换一条」。

## 4. 要 Luoye 定的事（同时列在对话里）

1. **问 / 交办用规则判还是加一次便宜模型判**？现在是规则（零成本、可测，判不准先答）。**建议：先用规则**，看一周真机误判再说；要加模型就在规则判成「问」的那一侧再问一次。
2. **① 个人模式复盘不出卡**（只记在岗位页「记录」里，明天的安排由早上那张「今天的安排」问）。派工单原话是「需要人确认明天安排时才出卡」。**建议：保持不出**，免得晚上复盘、早上计划两张卡问同一件事。
3. **复盘按人一天一份**（不是按岗位）。一个人做两个岗位时也只有一份。**建议：保持**；要按岗位拆，得先把卡数 / 待办按岗位数（现在都是按人）。
4. **会话要不要也进岗位页「记录」**（现在只在左栏会话历史里）。**建议：先不进**，左栏够找；记录页现在是卡与复盘。
5. **复盘卡的期限：第二天晚上过期**。**建议：保持**（隔天的复盘没人再看）。
