## 2. 我自主做的决定（白话）

1. **没照搬官方的「自定义协议 + 整页转发」**。官方是自己伺候前端文件、把每个请求转给 Host；我们起的是标准的 `dsh --profile web`，它自己就伺候页面。所以窗口直接加载本机网址，由壳在请求发出前把 cookie 补上。效果一样：token 不进网址、页面拿不到 cookie、只有这个窗口带凭据。这样官方前端不用走它的「桌面启动注入」那条路，少了一大块会跟着上游变的东西。
2. **退出确认问不到任务**：官方是在自己的 Host 进程里挂了个查询口，我们起的标准 dsh 没有这条通道。照官方「查不到就当有任务」的规矩：只要官方场景在跑（或它的窗口还在），退出就问一句。系统关机不问。
3. **官方桌面端的启动放在服务进程**（新增一条接口），不是只在桌面壳里做：这样工作台在浏览器里打开时也能点，托盘和面板走同一条路。启动时环境变量用白名单，连 `DSH_HOME` 都不给。
4. **Windows 上只认文件名是 `DeepSeek Harness.exe` 的协议处理程序**，别的程序抢了 `dsh://` 就不当它是官方桌面端。
5. **「在浏览器里打开场景」做成托盘上的一个勾选项**（持久），面板上不再加按钮，少字。
6. **桌面壳把 `AGENTSWS_DSH_WORKSPACE` 传给服务进程**：docs/79 一直说工作目录能改，但壳以前没把它传下去；e2e 也需要它，免得在 Luoye 电脑上建 `~/dsh-workspace`。另外透传 `AGENTSWS_OFFICIAL_DESKTOP_APP`（演示 / 测试用：指一个路径当作官方桌面端，写 `off` 就不找）。两个都不是机密。
7. **「切换场景」教程原来不存在**，新写了中英两篇，并在场景面板的说明后面挂了「看教程」。
8. 加了一条 Electron e2e（`apps/desktop/e2e/scene-window.spec.ts`），测试抓手多了 `sceneWindows()` / `skipQuitConfirmation()`（只在主进程 global 上，网页够不着）。

## 3. 需要 Luoye / Fable 定的事

1. **退出确认会不会太多**：现在只要官方场景在跑，退出就问。可以改成「只有它的窗口开着才问」，或加「不再提示」。
2. **场景窗口里的其他权限**（通知、剪贴板等）照官方默认给了（只限这个场景自己的源）。要不要收紧到只给麦克风？

## 5. 偏离

1. 凭据用「请求发出前补 cookie」，不是官方的「自定义协议整页转发」（理由见决定 1）。WebSocket 与 http 走同一条规矩。
2. 退出前的「查询运行中任务」查不到，统一当「可能有任务」问（决定 2）。
3. 多了一条服务端接口（`POST /v1/dsh-scenes/official-desktop/launch`）与一个可选契约字段，SDK / ontology 重出。
4. **e2e 第一次运行时，`electron` 包自己下载了 Electron 二进制**（这个 worktree 的 `node_modules/.pnpm/electron@44.3.0…/electron/dist`，306 MB，官方源，是 devDependency 的开发用二进制，不是官方桌面端，也不是捆绑 Node）。没有跑桌面打包，没有下载捆绑 Node。
5. 桌面壳透传两个非机密环境变量（决定 6）。

## 6. 未完成

1. 退出确认不能真的知道官方场景里有没有任务（要 dsh 官方给标准 web 场景一个查询口，或我们去读它的 RPC）。
2. Windows 没实测：注册表查询、exe 启动、Windows 上的关窗确认（官方 Windows 第一次隐藏前会问一句，这里没做）。
3. 官方桌面端的检测没在真装了它的机器上试过（这台电脑没装，按规矩也不装）；用覆盖变量和替身测。
4. 场景窗口的窗口位置 / 大小不记忆；macOS 上托盘应用没有 Dock 图标，场景窗口也就没有（与工坊主窗口一致）。
