## 2. 我自主做的决定（白话）

1. **共用函数放 `core`，不另开小包**：抑制名单也在 `core`，放一起；红人那边原名 re-export，一个调用方都没改。
2. **配额按"这个时区的自然日"算**，不按滚动 24 小时：否则早上 9 点那一拍，昨天 10 点发的还没"过期"，"排到明天"就不是明天。待批的卡里占着的也算进今天。
3. **预热从这只邮箱第一次发开发信那天算**（我们判断不了域名的注册日期）。选主域名的也照预热走——主域名发冷邮件同样是"新开始"。
4. **"不问不设"**：没选发信邮箱时，名单排着（原因 `sender_choice`），一封都不起草成卡；一只邮箱都没接就不出选择卡，只说"先接一只"。
5. **主域名**取公司档案里的域名；没填就把第一只接上的邮箱当主域名（宁可少认一只"单独域名"）。
6. **DKIM 必须签自己的域名**：测试信里 `dkim=pass` 但签的是服务商默认域名，算没过（对方那边照样对不上 DMARC）。SPF 除了查 DNS，测试信里 `spf=` 不是 pass 也算没过。体检一周重查一次。
7. **执行器发之前再查一遍**（体检、抑制名单、这个人批卡之前有没有回信）——fail-closed。
8. **公司地址存在「主动开发」设置里**：公司档案里没有实体地址这一格。公司名默认取档案全称。
9. **退订**：没有安全的公网落地页（聊天转发器只收商家站点来源的离线留言、而且不是每家都部署了），所以页脚写「回复 unsubscribe 即退订」+ `List-Unsubscribe: <mailto:发信邮箱?subject=unsubscribe>`；WP172 的分拣本来就认这种回信，进名单立刻生效。
10. **模板是英文**（收件人是海外买家）；**首封**让模型按 cold-email 技能写（每批最多 20 封），过不了自查就退回模板，卡上写几封是模型写的；跟进 / 收尾用模板。跟进回在同一条线程里（`Re:` 是真回信，不是假 Re:）。
11. **跟进 / 收尾也是一批一张卡**（按发信邮箱 + 第几封），等级按 yml（现在 L1 起步，所以仍是卡）。
12. **"不感兴趣"也进抑制名单**（docs/84 §2.2 原话；原因记 `declined`）；"晚点再说"只停不拉黑。
13. **回我们开发信的**：有意向 / 要资料 / 问价 → 询盘 + 事项 + Run 交给持「业务」的人；看不出的照旧开事项等人读；其余只记一笔往来，不开事项、不花模型钱。
14. **卡被驳回 / 过期**：那一批人停下（`card_rejected`），不自动重排——人说了不发。
15. **加拿大**（docs/84 §8）：没有「公开来源」的不发，顺手加进筛人。
16. **开过序列的人不自动重开**（走完、停了的都算）。
17. 模拟里"SPF 没过"那条**特意把卡递到 guardrail**，钉住最后那道闸（服务进程在更早就停了、不出卡）。
