# WP257 报告：进帖自动判类打标签、Discord 频道显示真名、Telegram 群只读拉帖（决策 152 / 155 / 156）

分支 `wp/257-tags`（worktree `agentsws-wt/wp257-tags`），Claude 子代理。

## 0. 一句话

自动进来的帖子（Reddit 自家版新帖、Discord、Telegram 群）**入库就按规则判一类、打标签**（关键词 + 渠道 + 是否 @品牌，沿用社群职责原有六类），**不出卡、不转客服**；「群里的帖子」上方一排标签按类筛、带条数，旁边一个「模型复核」小开关（默认关）；数据看板社群组五条职责多一块「进帖分类」（近 7 / 14 天 / 累计）。Discord 登记频道时读一次频道名（「#general」），读不到退回「#id 末四位」，老频道下一轮补名。**Telegram 群**照 Discord 那一套低频只读拉新消息（去重、断点续读、429 退避、缺什么照实说——隐私模式开着要写明怎么关），登记入口与空态照 Discord 做。

## 2. 我自主做的决定（白话）

1. **类目沿用社群职责原有的六类**（工单说「沿用社群职责已有的类目，没有就按这几类」）：客户问题 / 抱怨 / 夸奖 / 合作 / 广告垃圾 / 其他。工单列的「售后」「产品反馈」「闲聊」在这六类里的落法：售后（订单、物流、退换、保修）本来就在「客户问题」的词表里；产品反馈分到「夸奖」或「抱怨」；闲聊落「其他」（界面上这一类写成「闲聊 / 其他」）。没有新开类目——判类器只有一份是 56 那条老纪律，多一套类目两边就对不上。
2. **规则里「渠道」「@品牌」两条只往上加、不往下减**：词表命中的照旧；邀请链接只在聊天群里算垃圾；问到我们头上的问话才升成客户问题。没 @ 我们的闲聊问话（「这个能连 iPhone 吗？我也想知道」）仍是「其他」——宁可漏一条让人自己看到，也不把群里闲聊都标成客户问题。
3. **「@品牌」怎么认**：Discord 看消息的 mentions / 回的是不是机器人（要知道机器人 id：查权限那一跳顺手记下，没记下时只有这一页真有人 @ 了谁才多问一次「我是谁」）；Telegram 看 @机器人用户名的 entity / 回的是不是机器人；三条渠道都再看正文有没有品牌名（品牌名取这个品牌在工坊里的名字，少于 2 个字不认）；Reddit 自家版里的帖子一律算冲着我们来的。
4. **模型复核开关做在「群里的帖子」页头**（一个小开关 + 问号），一个品牌一份（所有渠道共用）。复核每拍最多 10 条、只看最近 7 天还开着的，不回头翻老帖；一条 = 一次很小的模型调用（8 个输出 token）。
5. **计数做成数据看板里一块表**（社群组五条职责各一块「进帖分类」），不是数字格：一类一个数要 6 格，超过数据看板一行 3–4 个数的规矩；表在「看图表」里展开。「群里的帖子」那排标签上也带条数（还没处理完的那些）。
6. **Telegram 只读群消息、不改机器人设置**：不调 `deleteWebhook`、不改 `allowed_updates`（那是机器人的全局设置，改了会影响别处）。设了 webhook 就照实说怎么办，不替人删。
7. **Telegram 读走即确认**：这是 Telegram 的规矩——下一次带上 `offset` 就算确认了，同一条不会给第二遍。所以一个群都没登记时干脆不读；登记了以后，没登记的群和私聊机器人的消息读到了也不记（过去了就没了），见 §3 第 3 条。
8. **Telegram 的默认名**：公开群用 `@群名`，私有群用「群 id 末四位」；登记那一下读到群名就换上（顺手把 `@群名` 换成数字 id，收件流里只认数字 id）。
9. **WP256 那几条测试的改动**：Discord / Reddit 入库「不判类」那两处断言改成「按规则打了标签、仍不出卡」；「Telegram 不会自动拉」那一处改成 WhatsApp。

## 3. 要 Luoye 定的事（逐条，附建议）

1. **跑一两周后，客户问题要不要自动出转客服卡**：现在只打标签。**建议：先看数据看板「进帖分类」两周的量和准头**（在「群里的帖子」里点「客户问题」看判得对不对），准头够了再开「客户问题自动出转客服卡」，且只对 @ 了我们的那些先开。
2. **模型复核默认关，要不要开**：开了每 5 分钟最多 10 条、每条约几十 token 输入 + 8 token 输出，记在持有那条社媒职责的人头上。**建议：先关着**，等第 1 条看出规则判错得多再开。
3. **Telegram 机器人收件流是「读走就没了」**：工坊读群消息时，同一个机器人收到的私聊和没登记的群的消息也会被读掉（不记）。如果这个机器人还给别的工具用（别处在 `getUpdates` 或设了 webhook），两边会抢。**建议：给工坊单独建一个 Telegram 机器人**（连接页文案可以加一句）；以后要做「私聊机器人的客户问题」再把私聊也记下来。
4. **真机核对一次 Telegram**：按纪律没连 telegram.org，`getUpdates` / 隐私模式 / `getChatMember` 的判断是按文档写 + 替身测的。**建议：用 INMO 的 Telegram 机器人在你看着时跑一次**：先不关隐私模式登记群 → 看那一行提示 → 在 @BotFather 关掉、移出群再拉回 → 等一轮（或把频率调成 5 分钟）→ 看进帖和标签。
5. **类目要不要和收件箱对齐**：收件箱（messages）那边的判类是「客户问题 / 售后 / …」另一套。**建议：先不动**（社群这边六类有转客服 / 转红人营销的路由挂着）；真要「售后」单独一类，下一单在六类里加，要连路由与面板一起改。
6. **夸奖类的词表偏窄**：demo 里那条「… fixed my USB-C flicker … Thanks team!」落在「其他」。词表「只可加行」，这单没动它。**建议：跑一两周后从「其他」里挑常见的夸奖 / 抱怨说法补进词表**（比如 thanks team、fixed、终于好了），比现在凭空加准。
