# WP204 报告：消息页按钮逐个过一遍并修好

实现方：Claude Opus（子代理）。worktree `agentsws-wt/wp204-msg-buttons`，分支 `wp/204-msg-buttons`，已合并一次 main。

**一句话**：消息页上能点的东西逐个真点了一遍。「显示图片」和「删除」确实坏了，而且原因不止一个；另外找出十来处「点了能用但没回音 / 失败被吞 / 行为不对」。全部修好：每个按钮点了要么马上看得见变化，要么底下冒一句话；失败说人话；删除先问一句，归档 / 删除能撤销；影子模式（只看不动）下归档 / 删除置灰，问号里说为什么；「显示图片」只对这一封生效，图片由本机代取，浏览器不直连对方服务器。契约只加不改。没碰 4317，截图拍在我自己起的 4399 demo 上，拍完已关。

## 1 按钮清单（原状 / 根因 / 修法）

先在 demo 上用 Playwright 逐个真点，记下请求和页面变化，再对着代码找根因。

| # | 按钮 | 应该发生什么（docs/63） | 原来实际发生什么 | 根因 | 怎么修的 |
|---|---|---|---|---|---|
| 1 | **显示图片** | 这一封的远程图片显示出来；防追踪 | 请求 200，**页面一点不变**：提示条还在，图还挡着 | ① 服务端只在回包里给了一份把 `src` 搬回去的正文，不写库；前端把回包扔了，紧接着刷新会话，拿回来的还是挡着的那份。② 就算显示了，也是让浏览器直连对方服务器，可桌面壳的 CSP 是 `img-src 'self' blob: data:`（WP99 定的，不加外域），外域图在壳里**永远显示不出来** | 服务端**本机代取**，内联成 `data:`（见 §2）。前端按信 id 把代取回来的正文记在页面里，只作用于这一封，会话刷新后也还在；不写库，下次打开仍然先挡着。取不到的照旧挡着，底下说「有 N 张没取到」。按钮取图时显示「正在取图…」；问号里写明是代取 |
| 2 | **删除** | 移到垃圾箱（不永久删）；回写邮箱 | 请求成功，但**阅读区还停在那封信上**，也没有一句话；一条会话里有两封收件箱的信时只挪最后一封，列表那一行还在；挪信要等 IMAP 几秒，这期间按钮没有任何状态；失败时是 500「internal error」，前端吞掉；影子模式下照样动邮箱；没有二次确认 | `act` 这个 mutation 没写 `onSuccess` / `onError`；只取 `messages.at(-1)`；服务端找不到信时抛的是裸 `Error`（变成 500）；`move()` 不看影子模式 | 先问一句「移到垃圾箱？之后还能移回来。」。确认后挪**整条会话里眼前这个文件夹的那几封**（已发送的那封不动），挪完离开这条会话，底下出「已移到垃圾箱 · 撤销」。挪的过程中按钮置灰。失败说人话；邮箱服务器没答应时说「这里改了，但邮箱服务器没答应」。影子模式下置灰（见 §3）。垃圾箱里的信不给「删除」，改给「移回收件箱」 |
| 3 | **归档** | 移到归档，回写邮箱 | 同「删除」：阅读区不动、只挪最后一封、没回音、失败被吞。另外**归档一下，分拣结论就被改成「你挪过这封信」**，「要不要回」也被清掉，右栏的回复建议随之消失 | 同上；服务端 `move()` 把所有挪信都当成「纠错」，一律改路由、改分拣结论 | 同「删除」，带撤销。服务端把挪信分成两种：**纠错**（移到客服 / 红人 / B2B、从岗位文件夹移回收件箱、勾了「以后都这样」）照旧改路由、记「人判的」；**收拾**（归档、删除、撤销它们）只换文件夹，路由和分拣结论不动。所以撤销回来原样不变 |
| 4 | **回复** | 打开写信框，收件人是被回的那封的发件人；发送走 outbox | 写信框能打开。但**发送失败时 500 被吞**：写信框不动，也不说话，人以为发出去了（demo 里就是这样，真机上急停或邮箱断了也是这样）；草稿自动保存失败没人接 | 服务端 `send()` 把失败抛成裸 `Error`；前端 `send` 没写 `onError`；`saveMessageDraft(...).then()` 没接 `catch` | 服务端：急停 → `halted`（503），没连邮箱 → `provider_unavailable`，原话带出去。前端：写信框留着，框里一行红字「没发出去：…」；发出去后写信框关掉，底下一句「已交给发件队列，马上发出。」；草稿存不上也说一句 |
| 5 | **全部回复** | 抄送其他人，不抄自己 | 能用；但「自己」一律按第一只邮箱算，多邮箱时会把另一只自己抄进去 | `me` 取的是 `accounts[0]` | 「自己」按这封信所在的那只邮箱算 |
| 6 | **转发** | 空收件人，主题 `Fwd:` | 能用；但发出去带 `In-Reply-To`，于是原信被标成「已回」并回写邮箱 | 转发沿用了回复的那一套 | 转发不带 `In-Reply-To`（仍在同一会话里） |
| 7 | **星标** | 切换星标并回写 | 能用；失败不说；影子模式下照样回写邮箱 | 没有 `onError`；`setFlags` 不看影子模式 | 回执里带 `writeback`；邮箱没答应时说一句；影子模式下只在本机标 |

| 11 | **附件** | 能看能下（composer 注释里写着「收那一侧已经能看能下」） | **只是一个名字标签，点不了** | 没有取附件字节的路由 | 新路由 `GET /v1/messages/:id/attachments/:attachment`，字节从受控原始材料区取；一律当下载给（`application/octet-stream` + `nosniff`，HTML / SVG 附件不会在工作台里被打开）。标签变成按钮，点了下载；取不到时说「这个附件取不到了（原件可能已过保留期）」 |

## 2 「显示图片」为什么改成本机代取

- 桌面壳的 CSP（`apps/desktop/src/csp.ts`，WP99 Luoye 定）`img-src` 只认 `'self' blob: data:`。`srcdoc` iframe 继承这份 CSP，所以直连的外域图在桌面里一张都出不来。这是「点了没反应」的另一半原因。
- 代取：`packages/channels/src/messages/remote-images.ts`。
  - 只取公网上的 http(s)，端口只认 80 / 443。
  - 先解析域名，**任何一个**解析结果落在回环 / 内网 / 链路本地 / 组播 / 保留地址就拒（防 SSRF：信里的地址是陌生人写的，不能让它借本机去打 `127.0.0.1:4317` 或局域网）。
  - 跳转手动跟，最多三跳，每一跳重新判地址。
  - 只收 `image/*`，类型串要干净（它会被拼进属性里），SVG 不收。
  - 单张 2 MB，一封最多 40 张，同一个地址只取一次，并发 4 个，8 秒超时。
  - 不带 Cookie，不带 Referer。
- 残余风险（写在文件头里）：判完地址到真正连上之间，DNS 可能换了答案（rebinding）。但响应必须是图片才会被用上，拿不到别的东西。
- 隐私上：浏览器不直连，所以追踪方拿不到浏览器指纹、Cookie 和 Referer。但**人按了「显示图片」，追踪像素仍然会被本机取一次**，对方知道「有人打开了」。这是人按下去才发生的，问号里写明了。

## 3 会改邮箱的动作怎么守「客信怎么动邮箱」那组开关

- 人按的动作只看**影子模式**这一个开关（另外三个——挪进 KefuAgents、标已读、接管——只管客服信的自动处理）：
  - **归档 / 删除 / 移回收件箱**：界面上置灰，旁边一个问号说「这只邮箱开着影子模式：归档、删除会动邮箱，所以先关着；已读、星标只在这里标。要改，去连接页那只邮箱卡上关掉影子模式。」。服务端兜底：影子模式下收拾类的挪信回 `409 conflict`，原话一样。按键盘 `e` 也只说这一句，不挪。
  - **已读 / 星标**：只在本机标，回执是 `local_only`，邮箱一下都不动。左栏底部挂一个「只看不动」的小标加问号，不每点一下都说。
  - **纠错类的挪信**（移到客服等）：影子模式下只改本机的路由，文件夹不动。这和同步那一路在影子模式下的做法一致。
- 删除要二次确认；归档和删除都能撤销（撤销就是按原来的文件夹反着挪回去；因为「收拾」不改分拣结论，撤销回来原样不变）。
- 回复 / 转发：照现有的出站规矩走。`/v1/messages/send` 挂 `outbound: true`，急停出站档照拦，进 outbox 七态 + 对账，幂等键齐全。**没有改成出卡**，原因见 §6 第 1 条。

## 6 要 Luoye 定的事

1. **人自己按的「发送」要不要出卡？** 工作单写「对外发送出卡审批，不直接发」。但 docs/63 §F 第 5 条写明「不出审批卡」（人按下发送就是拍板，36「只有要人拍板的才是卡」），现有代码也是这么做的：进 outbox，急停照拦。我**按 63 保留不出卡**，只把发送失败改成说人话。如果要改成出卡，这是一张新单。
2. **正文 iframe 要不要放开同源（仍然不给脚本）？** 放开 `allow-same-origin`（不带 `allow-scripts`）就能量内容高度，框能贴合正文。现在是粗估高度 + 框里滚。63 §G 写的是「无脚本、无同源」，所以我没动。
3. **邮件正文里的链接点不开。** 净化时给链接加了 `target="_blank"`，但 iframe 的 sandbox 里没有 `allow-popups`，所以正文里的链接点了没反应。要开的话是加 `allow-popups allow-popups-to-escape-sandbox`（桌面壳里还要确认 `window.open` 交给系统浏览器）。这动的是 63 的安全边界，我没改，列在这里。
4. **影子模式下归档 / 删除：现在是「置灰 + 说明」。** 另一种做法是「只在本机标」，但那样本机和邮箱就对不上了，下一轮同步时信的位置也说不清。我选了置灰，要换请说。
5. **「总是信任这个发件人」**：接口一直有（`always: true`），界面上没有这个按钮，我没加（工作单只要「只对这一封」）。另外 `GET /v1/messages/:id` 对信任过的发件人仍然把 `src` 搬回去让浏览器直连；界面不走这一条，但如果以后要加「总是信任」，应该也改成代取。
