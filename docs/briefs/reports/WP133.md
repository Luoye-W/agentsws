## 2. 我自主做的决定（白话）

1. **锁定没拆成单独的文件，而是让原来那份文件只放锁定。** 派工单说「挪进独立的 patch 文件」。dsh 给每个 profile 只留了一个配置文件的位置，要挂第二个文件只能走 bundle 这条路。我实测过：bundle 那一层的文件坏了或者缺了，dsh 只打一行提示就**照样启动**，被锁住的插件管理器等于重新打开；profile 自己那份文件坏了，dsh 会**直接拒绝启动**。锁定必须是「出错就停」，所以留在 profile 这一层。「一眼能看全、不和占位注释混在一起」这个目的，靠把占位注释挪走达成了。
2. **`session-log-deepseek` 那一行也纳入校验，总共七行，不是派工单说的六行。** 它不是 `disabled: true`，而是把 `enabled` 改成 false，但同样靠 id 字符串对上，而且多一个风险：上游改了字段名，这一行也会悄悄失效。所以它的字段名也一起校验。
3. **校验读的是 `x-cordis` 里的条目清单，不是直接拿 JSON Schema 去验 patch 文件。** 实测发现导出的 schema 对未知 id 是放行的（只约束已知 id 的配置形状），直接验的话，一个写错的 id 照样能过。
4. **不要求 `x-cordis.complete` 为 true。** 以后哪个无关插件的 schema 只导出一部分，`complete` 就会变成 false、退出码变成 1。这不妨碍按 id 校验，要求它为 true 会让测试为了无关的原因变红。我们只要求有输出。
5. **`eventAt` 换成边收事件边折，不是派工单说的 `read()`。** `read()` 在 0.1.7 里不存在，见 §5。上游说明文档给普通逻辑指的路就是「处理送到手的当前事件」。
6. **测试里保留了一份旧的 `eventAt` 折法当对照组。** 上游政策明确允许测试文件继续用这三个读接口。这样「新旧逐字段相同」是真跑出来比对的，不是推断。

## 5. 偏离

1. **① 没有新建 `lockdown.patch.yml`**。原因见 §2 第 1 条。证据是 `@deepseek-ai/dsh-app-boot/lib/types/profile.d.ts` 里 `loadProfile` 的说明「Unreadable or incompatible bundles are reported on stderr and skipped; profile manifest and user patch errors still throw」，加上实测：在临时 `DSH_HOME` 里做一个本地 bundle，`dsh.bundle.patch: ["./lockdown.patch.yml"]`。文件正常时锁定生效；把它写坏后 `dsh --dump-config` 退出码 0，`plugin-manager` 回到 `disabled: !!js '!ctx.get(''profileContext'')'`；把 profile 自己的 `cordis.patch.yml` 写坏，退出码 1。
2. **② 用的不是 `session.read()`**。0.1.7-rc.1 的 `Session` 上没有 `read()`，查过的地方：`dsh-session/lib/types/index.d.ts` 的 `class Session`、README「Read the log」、上游 `packages/core/session/src/index.ts` 在 `dsh-v0.1.7-rc.1` 与 `master` 两处。几个名字里带 `read` 的都不是它：`dsh-session-persistence` 的 `SessionHandle.read(offset, length)`，`dsh-session-query` 的 `read(sessionId)` / `readEvent()`。它们属于 JSONL 持久化 / 查询层，我们用内存 Session、不挂这些。Agent Note 原文（用 `gh api` 从上游 `.agents/notes/implemented/architecture/2026-09-09-deprecate-synchronous-session-event-reads.md` 取的，npm 包里没有）说，普通逻辑应当「reads the projection or processes the delivered current event」，异步分页只给「historical content presented on demand」。`summarizeTurn` 属于前一种。
3. **测试数比派工单预想的多**：锁定 7 行（多了 `session-log-deepseek`），见 §2 第 2 条。
