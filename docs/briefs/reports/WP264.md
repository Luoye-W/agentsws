# WP264 报告：事项页 v2 实现（AI 短标题、一行页头、对话式时间线、Claude 式输入卡 + Tab 建议）

分支 `wp/264-matter`（worktree `agentsws-wt/wp264-matter`），Claude 子代理。照 WP262 设计稿（`docs/design/matter/`）与决策 177–184 做。未推送、未合并。

## 0. 一句话

事项页换成像 Claude 的对话页：标题是首轮开跑时便宜模型起的短标题（点了就地改，人改过的不再被覆盖）；页头只剩一行灰字（职责 · 状态 · 参与者 · 最近活动 ·（有才出的）N 个待办），其余收进「⋯」并吸顶；时间线你在右、AI 在左，预览 / 审批 / 选择 / 卡住都是能直接点的卡，过程事件缩成居中一行灰字点开看步骤，正在跑的那次在底下「正在做…」+ 当前一步；底部是明显的输入卡（卡内圆形发送 / 运行中变「停」、私聊 AI 开关替代原来那块「问 AI」、AI 给的下一步浅灰显示按 Tab 收下）。

## 1. 实现清单

### 契约（只加不删）
- `Matter.title_source?: 'brief' | 'ai' | 'user'`（标题怎么来的；人改过 = `user`）。
- `MatterEvent.run_digest?`（一次运行跑完的摘要：秒数、结局、人话步骤）、`MatterEvent.next_suggestion?`（AI 交代末尾的下一步）、`MatterEvent.preview` 抽成 `MatterPreview` 并加 `theme_id? / changed_files? / check?`。
- `MatterView.live?: MatterLiveRun`（正在跑的那一次：开跑时刻 + 实时步骤，只在 `GET /v1/matters/:id` 那一屏上，不进库）。
- `RunResult.next_suggestion?`（运行时能结构化给就给；不给时宿主从答复末尾 `<next>…</next>` 取）。
- 新 `packages/contracts/src/matter-chat.ts`：`fallbackShortTitle`（原话前 20 字宽，中文一格英文半格）、`cleanShortTitle`、`shortTitlePrompt`、`splitNextSuggestion` / `cleanNextSuggestion`、`NEXT_SUGGESTION_RULE`。

### 工作模型（`packages/work`）
- `Work.retitle(id, title, by)`：`user` 永远生效；`ai` / `brief` 碰到人改过的原样返回。标题不进事件日志。
- `appendEvent` 收 `run_digest` / `next_suggestion` / 预览新三格。
- `Work.say`：已关闭的事项说一句就重新打开（决策 183；待办不动）。

### 服务端
- `apps/server/src/matter-title.ts`：**首轮开跑时**（时间线上还没有 `run`）便宜模型单独起短标题——品牌默认模型的 `extraction` 档、60 个输出 token、thinking 关、原话围栏截断；起不出 / 没接模型 → 原话前 20 字宽（`brief`）。与运行并行不阻塞；起标题途中人改了也不盖。装在 `server.ts` 包住 `startRun` 的那一层，用量记在这次运行那条分配上。老事项（跑过的）不动。
- `apps/server/src/run-steps.ts` + `runtime.ts`：每次运行按 `tool.call / tool.result` 记人话步骤（主题工具认出文件：「读 templates/index.json」「改 config/settings_data.json」「主题检查」「推成未发布主题「…」」；别的工具用统一人话表 + 一个关键入参，不露工具名）。`liveRun(matter_id)` 给事项页；收尾（跑完 / 停下 / 没跑成）记一条 `status` + `run_digest`，排在 AI 那段话前面（记成 `status` 不是 `run`：「跑了几次」照旧只数开跑那条）。
- 提示词公共段后面加一节「下一步建议」（order 27，所有职责同一份）：有明确下一步时末尾单独一行 `<next>…</next>`；宿主进时间线前拿出来记 `next_suggestion`、正文去掉标记，摘要里也去掉；被停下的那段不给建议。**不从正文里猜**。
- 新路由：`PATCH /v1/matters/:id`（改标题 → `user`）、`POST /v1/matters/:id/stop`（停这件事上正在跑的运行）；`GET /v1/matters/:id` 多 `live`。
- 主题工坊：最近一次 `theme_check` 结论按店记在内存（改了文件就作废），推未发布时带进「预览好了」：副本 id、改了哪些文件、检查结果。
- `positions.ts` 的 `briefOf`：标题换成短标题后，原话取这件事第一句人话（之前靠「标题是原话开头」认）。

### 工作台
- `pages/matter.tsx` 重写；新 `components/matter/`：`matter-model.ts`（怎么排 / 状态 / 给不给建议，纯函数）、`matter-header.tsx`、`matter-timeline.tsx`、`matter-composer.tsx`；字在 `lib/i18n-matter.ts`（中英齐）。
- 页头：标题按钮（悬停出铅笔，点了变输入框，Enter / 失焦存、Esc 取消）；灰字行职责标签（职责图标 + 名字 + ⇄，点了出本岗位职责清单换职责，只换不重跑）· 状态（在跑 / 进行中 / 等你批 / 卡住了 / 已完成，小点颜色与左栏同一套）· 参与者头像 + AI · 最近活动 · 有才出的「N 个待办」（点开就地展开、能勾）；「⋯」= 换职责 / 复制链接 / 固定记录（有才出）/ 归档（在跑、有卡等你批时置灰，右边一句为什么）/ 关闭事项（有没做完的待办才问「一并关掉 / 留着」）。吸顶。
- 时间线：你说的右气泡（>6 行或很长先收起「展开」，钟点悬停才显）；AI 左侧职责头像 + 名字 + 钟点，正文 Markdown（新 `SafeMarkdown` 的 `chat` 排法：小标题、列表、行内代码、链接；`#0B0D10` 这种颜色值前面带色块），长回答先露一屏「展开全文」，悬停「复制」；「预览好了」嵌进紧跟着的那条 AI 消息成结果卡（占位缩略图、主题名、改了几个文件、检查结果；「打开预览」主按钮、「发布上线」次按钮、「看改动」就地列文件）；审批 / 选择卡内嵌（琥珀边，按钮字与卡片流同一套动词），批过缩成一行「你批了 · …」；路由还没定职责时是选择卡（WP237 那几个按钮）；卡住了是最新一条时是红边卡（「去连接」→ 连接页、「接着做」= 说「连好了，接着做」），后来接着做了缩成一行；跑完了 / 跑了一次 / 路由 / 停下 / 其他系统话缩成居中一行灰字，有步骤的点开看（默认全收起，决策 182）；同一天一条日期分隔。
- 运行中：底部左侧「正在做…」+ 已用时 + 当前一步（流光字）+「第 N 步」，点开实时步骤；页面每 1.5 秒拉一次。
- 输入卡：圆角卡（正文色 14% 边 + 两层阴影，聚焦加深），自动长高到约 10 行；卡内右下圆形发送（空灰 / 有字主色 / 运行中空着时变墨色「停」，有字又是箭头——发出去在本页排队，这一轮跑完自动发）；悬停「发送（Enter）」；Enter 发送、Shift+Enter 换行，「↵ 发送 · ⇧↵ 换行」只在聚焦或有字时出；左下「+」「@」置灰（悬停「即将推出」）；「私聊 AI」开关（`role=switch`），打开整卡变蓝 + 一行「只你看得见，不会让它去做事」，问答画成蓝色虚线框在对话末尾，关掉就没了，「转给 Agent」把那句交给 Agent；已关闭事项输入框照留，占位「这件事已关闭，说一句就重新打开」。原来底下那块「问 AI」去掉。
- Tab 建议（决策 179）：只认三处——卡住了的固定规则「连好了，接着做」、等你批的卡的主按钮字（如「批准发布」）、AI 最后那条的 `next_suggestion`；在跑、刚发出去（还在等 / 排队）、最后说话的是人、私聊模式、没有明确下一步都不给。浅灰字 + Tab 键帽，按 Tab 填进框（变正文），打别的字就消失；只填不发，仍要人按发送。读屏有一句「建议：…，按 Tab 收下」。
- 明暗两套用现有 `--ws-*` 令牌；输入卡阴影与流光在 `index.css` 的 `ws-composer` / `ws-shimmer`（照设计稿 `composer.css`），减少动态时流光与呼吸关掉。

## 2. 我自主做的决定（白话）

1. **「起好之前先显示原话前 20 字」怎么落**：创建时的标题仍是 WP259 那个「首句…」（接口返回、老调用一个字不变）；首轮开跑那一刻起标题，起成了是 AI 短标题，起不出（没接模型 / 出错）才改成原话前 20 字宽。「20 字」按看上去的宽度数：中文一格、英文字母半格，不然「用 agentsws-theme 给 R…」太难看。
2. **「发布上线」按钮 = 在这件事里说一句「发布上线」**：现成的发布出卡只有 AI 调 `theme_publish` 那一条路（卡上要运行上下文、改了哪些文件），按钮就走它，AI 出的还是原来那张发布审批卡。代价是多跑一轮（几秒）。要直接出卡不经 AI，得另开一个接口（列在待定）。
3. **运行中发出去的话在本页排队**：设计稿说「发出去排在这一轮后面」，服务端没有排队（同时说两句会并行跑两次、花两份钱），所以在页面上先排着（气泡上写「等这一轮跑完就发」），这一轮一结束自动发。关了页面就没了。
4. **运行摘要记成 `status` 事件**而不是 `run`：不然「跑了几次」的统计和 WP237 那批测试都会多算一次。
5. **步骤只记「做了什么」**（读 / 改哪个文件、检查、推送），不记工具返回的内容；最多 40 步。摘要那一行：有改文件就写「改 N 个文件」，只读没改写「读了 N 个文件」，没有文件类步骤写「N 步」。
6. **服务端 `say` 碰到已关闭的事项直接重新打开**（决策 183 的「说一句就重新打开」需要它）；关的时候待办怎么处理的不动。
7. **内嵌审批卡**用卡片流同一份投影（`projectCard`）与动词表，按这件事那条分配取卡、批卡；选择题卡按选项出按钮。卡取不到（不在你的队列里）就一行字说明，不报错。
8. **预览缩略图先用占位**（一块深色小页面 + 几条色块，最底下一条用品牌色），没用设计稿里商家的红色（那是 Rollout 自己站的颜色）。
9. **固定记录**放进「⋯」菜单里（设计稿说放「⋯」或右栏）。
10. **页头换职责只换不重跑**（和原来「路由到 X · 换」一样）；时间线上路由那一行点开的「换成 X」照旧是换了立刻重跑（WP237）。
11. 「⋯ → 关闭事项」：没有未完待办就直接关，有才问「一并关掉 / 留着」。
12. 「复制」只在 AI 那条悬停时出；「看改动」先就地列文件清单（真 diff 以后接）。

## 3. 要 Luoye 定的事

1. **「发布上线」按钮要不要直接出卡、不经 AI 那一轮？** 现在是替你说一句「发布上线」，AI 再出那张发布审批卡（多几秒、多一点钱，但卡上的内容与 AI 自己出的完全一样）。建议：先这样；真机觉得慢再开一个「直接按这份预览出发布卡」的接口。
2. **运行中发出去的话排在本页**（关页面就丢）。建议：先这样；要可靠就服务端加一个「这件事的下一句」队列（另开小单）。
3. **老事项要不要补起一次短标题？**（工作单说可选，我没做）像 Rollout 那件已经跑过的事项，标题还是「用 agentsws-theme 给 Rollout 搭英文首页…」。建议：不补，人点标题改一下就行；要补就做成打开时后台起一次（只对标题是原话开头且较长的）。
4. **AI 起标题用的是品牌默认模型的 `extraction` 档**（没有单独的「便宜模型」设置）。用户只配了一个贵模型时也用它，每次约几十个 token。建议：先这样；以后模型设置里有「便宜档」再改指向。
5. **`<next>` 标记的提示词加给了所有职责**（公共段后面一节）。建议同意；真机看一周 AI 给的建议准不准，不准再收窄到建站 / 客服几条。
6. **等你批的卡的主按钮字也当建议**（如「批准发布」），按 Tab 填进框、发出去是一句话给 AI，不是直接批卡。设计稿规则 ② 如此；但人可能以为按 Enter 就批了。建议：保留建议，但以后改成「按 Tab = 聚焦到卡上的批准按钮」（另开小单）。
7. **决策 167 的记录**：WP259「首句 ≤40 字当标题」已按决策 184 改成「AI 短标题 + 原话第一条」，DECISIONS.md 那一行要不要标「被 184 取代」——请 Fable 合并时顺手改。
