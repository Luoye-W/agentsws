## 0. 一句话

AI 回答监测多了两个数——**比较胜率**（AI 把我们和竞品放一起比时，更推荐我们的占几成）和**描述准确度**（AI 说我们的名称 / 品类 / 价格 / 卖点 / 市场对不对，逐项标对 / 错 / 过时）；还会拿**官方事实表**去对官网、商品页、结构化数据、评测页，说法不一的按岗位分好出一张卡，批了就给建站 / 网站运营 / 公关各开一件事；每一张 GEO 改动都记「改了什么、看哪个数、哪天复查」，到期自动重问那组问题、前后一比，给「保留 / 扩大 / 修改 / 停」。周报每个数都标「实测 / 推算 / 估算」与样本量、日期，缺位写清主要原因、负责岗位、复查日期。

## 2. 我自己定的（白话）

1. **先找现成的**：查了 dsh 官方包与社区插件（没有 GEO / AI 可见度相关的）、开源里 open-seo（已在用它的思路）、GEOFlow（AGPL，只能看思路）。比较胜率、描述准确度、一致性、复查这几样没有现成可用的库，都是在我们已有的监测引擎上加；网页解析复用品牌分析那一口（`brand-intake` 的 JSON-LD / 正文读法与抓取纪律），图表复用 genui 渲染层。
2. **不多花一次模型钱**：比较与说法和情感在同一次调用里判（提示词多两格）；没提到我们的回答不判。
3. **「过时」怎么认**：官方事实表记了以前的说法；AI 或网页说的是以前的说法就是过时。价格按价格带的数字认（「about $39」落在旧价格带、不在新价格带 → 过时）。
4. **卖点那一格读品牌档案的「定位」**（没有就读一句话介绍）；品类带上子品类。人可以通过接口改官方事实（改的不被档案盖、旧值留痕），界面上先只读、指去品牌档案改（界面少字）。
5. **一致性检查跟着每周那一轮、约 28 天一次**（也能在看板上手动点）；取不到的页照实写「没取到」。上架页只能对**回答里引用过的**和人指定的（我们手上没有一份「各平台上架页网址」清单）。
6. **派给谁**：结构化数据 → 建站；官网 / 商品页 / 平台上架页的文字 → 网站运营；评测站 / 合作方 / 媒体 → 公关。批了之后每个岗位各开一件事（同一来源批次，事项里列出每一处「写的 → 官方」和原话），改外部的事照旧由那个岗位出审批。这一步没走助理的方案卡（那是对话里的卡），用的是 `geo_watch` 卡，卡上就能勾掉不派的。
7. **复查怎么跑**：到期即时问（不走排队档，免得再等一天）；官方那条路**不问 Claude**（单格约 3.6 积分，这一轮没人确认过）；复查那几轮不进每周的数（只问了一小组，进了会把那一周搅乱）；每天最多 3 条；没拿到够多的回答就再等一周，两次都不够就放弃。
8. **报告来路的口径**：规则从回答原文 / Search Console 数的 = 实测；要模型判断的（胜率、准确度）= 推算；积分预估这类 = 估算。
9. **缺位主因的判法**：先看硬信号（WP381 给的「AI 爬虫被挡 / 原始网页没正文」），再看说法（说错市场 = 买不了；说错名字 / 品类 = 认不出；说旧了 = 过时；外面说法不一 = 说法不一致），再看负面、比输了，最后按原来的车道兜底（交公关的 = 没人佐证，改页面的 = 没用）。
10. **GEO 周报模板**就是每周那张「AI 平台可见度」卡（摘要几行 + payload），没有另起一份模板文件。

## 5. 偏离

- **模拟只在 dtc-3c-3p 加了一条场景**（派工单写「模拟三包加一个 GEO 场景」，我理解为加一条、三包照跑）；另两包照跑全过。

- **官方事实没有界面编辑器**（接口有），见 1068。
- **截图里的分派卡**：demo 店在监测里认的自家域名是 `shop.example`（按 Search Console 页面认的），而 demo 夹具页在 `nordvolt.example`，所以截图里那张商品页按「站外页」归了公关；真品牌官网域名来自品牌档案，商品页归网站运营（服务端测试里钉了这一条）。
- 「AI 搜索里有没有我们」那一节的老规矩保留，改成五件事并指向新的几节（考题里的原句都在）。
