## 1. 新版改了什么（对我们有影响的）

版本口径：npm `latest` / `next` 仍是 0.2.0-rc.2，`alpha` = 0.2.1-alpha.4（10-15 发，内测线）。中间跨 alpha.3，941 条提交。兄弟包 cordis / schemastery / loader / include **又必须跟**到 `-alpha.2`。
仓库里写死的 58 个官方包新版全在。官方这一跳新写了 14 份升级指南，先读了。

| # | 官方改了什么 | 不修会怎样 | 怎么修的 |
|---|---|---|---|
| 1 | headless 组合**默认关掉本机凭据库**和它的两个使用方（授权、DeepSeek 账号），只认启动环境与 `.env` | 完整 profile 里选了「用我的 DeepSeek 账号登录」，账号模块缺两个依赖、挂不上（`--dump-config` 实测）。产品里目前不起完整 profile，所以是**潜在**的 | 照官方 README 的写法：选了账号登录时三行一起开；没选时三行由官方关着，我们这层一字不写。锁定测试钉住 |
| 2 | 定时任务工具里「标题」的说明改了：要求简洁、不写频率 / 时间 / 状态 / 括号备注 | 我们抄的那份和官方对不上（测试先红） | 照官方原文改。能建定时任务的运行里，模型看到的这两句说明变长了 |
| 3 | 官方 DeepSeek 适配器：空文本块不发（修旧会话重放失败） | 我们**移植**的那份没跟上，同样的旧会话可能重放失败 | 移植文件同步改，加一条测试 |
| 4 | 账号模块的诊断改成只在失败时打、改走错误输出 | 我们那条「令牌不进诊断」的守卫测试变成空转 | 测试故意让余额查询失败一次，逼出官方诊断再查 |

其余改动**碰不到我们**：持久代码执行环境（PTC）、子代理改用 preset、后台任务 id 格式、会话存储改插件、SDK 新的「恢复会话」、网页端一大批界面改进。
**网页搜索 / 抓网页 / 浏览器那几个官方包这一跳只改了显示文案**，没有新的搜索或浏览器插件。新进 9 个官方包的逐个判断见 §3。

## 3. 锁 / 开了哪些（官方功能优先）

**锁：一行都没新锁。** 原有五行锁定（会话日志上报、DeepSeek 账号默认登录、上报通道、反馈上报、插件清单上报）逐行复核：都在、指向的插件没换、组合后都关着。

**新进的 9 个官方包，逐个对照我们已有的：**

| 官方新包 | 判断 |
|---|---|
| 插件市场（四件：服务、网页标签页、索引格式、可选组合包） | **重复，不放**：我们的「官方插件」审过清单就是我们的市场；它经插件管理装任意 npm 包，会绕过清单与出卡（B 类）。测试钉住它不进清单 |
| 网页端密钥遮挡（粘贴进对话的密钥只露前 8 位） | 我们没有。它是官方网页端的界面插件、我们用不了，**但做法值得借**（建议派工单，见扫描文档第 15 条） |
| 非 owner 访问控制（`remote-access`，进了 base 组合） | 本机、只收紧权限（A 类），组合里开着；和「同事互联 / 公司模式」方向接近，等它出了网页以外的入口再看 |
| 电脑操控对象库 + macOS 原生提供方（实验） | 和我们走的 cua-driver（WP144）重复，等转正 |
| harness 开发上下文 | 只给官方网页 GUI 的维护者，用不上 |

**官方插件清单**：七项插进来的行逐字未变，只改版本号。
**官方改了、值得跟、但不在本单做**：DeepSeek 账号的模型列表改成从账号的模型接口取（我们设置页是写死的两个）——见 §4 第 919 条。

## 4. 要 Luoye 定的事（每条附建议）

**916. 这次升级（alpha.4）合进 main 吗？**
行为零漂移、测试全过，修了一处账号登录的隐患。仍是内测线（官方没标"推荐"）。
**建议：合，照常走主线的合并关口和 Windows 真机复测**（我按纪律没连真机）。

**917. 三个安全小单要不要马上开？**
① 桌面版本机连接器里的 nodemailer 9.1.1 有 2 条高危 + 3 条中危，「邮箱」连接正好用它（其中一条可能把一个邮箱的发信凭据发到另一个邮箱的服务器）——上游修复只改了这个版本号，我们留在 1.8.0 加一条覆盖就行，半天；
② 安装包自带的 npm 里的 tar 有 1 条严重级公告——Node 22.23.3 + npm 10.9.9 一起升，半天；
③ MCP SDK 1.30.0 有 1 条高危公告——升到 1.32.1，1–2 小时。
另外我们自己的邮件渠道（`packages/channels`）和云端（`apps/cloud`）也用着有高危公告的 nodemailer，没登记、哨兵看不到。
**建议：四件都马上开（可以并成两单：「连接器 + 我们自己的 nodemailer」「Node / npm / MCP SDK」）。**

**918. 两个上游的破坏性改名什么时候排？**
OpenConnector 1.9.0 把 `shopify_admin` 并进 `shopify`（没有兼容名；好处是能调到的 Shopify 写动作从 5 个变约 15 个：退款、取消订单、建专辑 / 页面 / 文章等），3–5 天；
BrowserSkill 0.3.3 把六个工具改名 `bsk_*`（门禁表必须一起改，否则域名白名单失效），1–2 天。
**建议：都单独开单、不和别的升级混；OpenConnector 迁移排在下一轮 Shopify 功能之前，BrowserSkill 这周或下周都行。** 先做 917 的 nodemailer，不用等迁移。

**919. 两件跟官方的小事：插件市场不放、账号模型列表跟官方？**
插件市场：我们的审过清单就是市场，它装东西会绕过出卡。账号模型列表：官方改成从账号取，我们写死两个，新模型上线要等我们发版。
**建议：插件市场不放（已按此做、测试钉住，你点头就算定）；账号模型列表另开小单跟官方，取不到时退回现在写死的两个。**

**920. 知识库文档解析接 anydoc，它的原生包（每个平台约 7 MB）随安装包带还是用到再下？**
anydoc 已有稳定的 npm 包（心愿单满足），我们知识库上传至今只收文件不解析内容。它有一个把扫描件发到云端识别的选项，接的时候必须关。
**建议：随安装包带**（7 MB 不算重型本机方案，离线也能解析）；Windows ARM 没有预编译包，退到浏览器版。

**顺带三件小事（不编号，照建议走就行，不同意再说）：**
- 两个私有仓 KOLAgents、KefuAgent 照 btobagents 的方式登记（只记来源和提交、不盯）——要你给一下本机路径和该钉的提交；
- Cloudflare 容器快照（公测，命中心愿单）先出一份只读评估，等转正再迁；
- MCP SDK 的 v2 迁移（v1 官方维护到 2027-01 底）12 月排一单。
