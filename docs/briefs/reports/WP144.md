## 2. 自主决定（白话）

1. **macOS 权限给「Agents 工坊」，不给 `CuaDriver.app`**（`mcp --direct`）。上游规定 macOS 的辅助功能、录屏权限记在「负责的那个应用」上。不加 `--direct` 的话，驱动会去 `/Applications/CuaDriver.app` 起一个常驻后台，那就得往系统目录装东西，而且我们点「停止」时它也不会跟着退。加了 `--direct`，驱动由我们的应用起、归我们的应用管，运行一结束就退。代价有两条：权限给的是整个 Agents 工坊（不只是驱动）；没有驱动自带的光标动画。另一条路列在 §3 给 Luoye 定。
2. **授权卡批了之后，「重跑这件事」**，而不是让正在跑的那次运行停下来等人批。现有的卡都是异步的（出了卡，运行就结束），服务端每次运行也只有 120 秒上限，让运行挂着等人不合适。所以流程是：第一次运行只能出卡，批了就带着授权自动再跑一遍这件事，这一遍才挂提供方。一次授权只给这一遍用。授权的起点是批准那一刻，N 分钟过了还没开跑，就不再带授权。
3. **「公司端（executor 档）永远不给」落在「只有本机档给」上**。原因是服务端现在**所有**运行的 `side_effect_policy` 都写死成 `executor`：如果门禁按字面判「executor 不给」，电脑操控就永远用不上。所以门禁里电脑操控单独一关，只看授权窗口，不看 `side_effect_policy`；「公司不给」由服务端判断：只在 `runtimeMode()==='local'` 时给，Docker、托管、公司服务器一律不给。
4. **服务端只有带 `computer_use` 的运行改走 dsh 运行时**。服务端平时用的是 direct 运行时，不挂任何 dsh 提供方（浏览器也是一样，WP86 报告里记过「服务端不跑 dsh 运行时」）。不这么改，设置页打开了也没有任何一次运行能真正挂上电脑操控。别的运行走的路一个字节都没变；没配模型的 stub 档不改。
5. **截图不进模型**。我们的组合没挂附件库，网关也不声明图片输入，官方 MCP 桥本来就会把图片换成一句诊断文字。但工具结果的「规范值」里还留着整屏的 base64，而门禁接受的正是这个值，所以我在门禁这一步把图片和长 base64 都换成一句说明。模型靠界面的无障碍树文字干活。要不要让截图进模型，列给 Luoye 定。
6. **硬拒名单**：`check_for_update`（会出网查新版本）、`set_config` / `get_config`（驱动的配置文件里就有遥测开关）、名字里带 update / telemetry / autostart / install 的工具、带 `screenshot_out_file` 参数的调用（会把截图写到任意路径）。这些即使在授权期间也拒。
7. **两个自有工具**：没批时只有 `request_computer_use`；批了以后多一个 `computer_handoff`，遇到登录、密码、支付、验证码时出一张「请你接手」的卡。调过它，这次运行就不能再碰电脑；人点「好了」，就再授权 N 分钟接着做。上游驱动没有「请人接手」这样的工具，所以只能我们自己加（照浏览器 `browser_handoff` 的做法）。
8. **批过授权的那一次运行，工具调用上限从 12 调到 40**。操作桌面是「看一眼、点一下、再看一眼」，12 次连一个小任务都做不完。token、时间和花费的上限都没动。
9. **驱动只用扁平的 `*-binary` 包**，macOS 用 universal 包（arm64 和 x64 共用，43 MB，不带 `.app`）。sha256 逐字抄自上游 `checksums.txt`。macOS 和 Windows 的包我都下载下来核对过 sha256 与包内结构；Linux 的两个包没下载，只抄了 checksum。
10. **遥测、查更新用环境变量关**，不去改用户的 `~/.cua-driver/config.json`。环境变量的优先级最高，不写用户家目录。官方提供方不接收 `env`，驱动继承我们进程的环境，所以挂之前把这两个变量写进 `process.env`（和 BrowserSkill 的 `applyBskEnv` 同一个做法）。
11. **设置页的职责列表默认只列有人在岗的**，其余收在「还有 N 条」后面。demo 里有四十条职责，全摆出来整张卡就被勾选框淹没了。没人在岗的职责，这台电脑上本来也不会有运行。
12. **截图里有替身数据**：demo 没有数据目录，我也不许真跑驱动，所以「驱动已装好」、自检结果、「正在操作」那一次，都是在浏览器里替换了响应（脚本里写明了）。托盘那张是把桌面壳的菜单模型（`buildTrayMenu`）照 macOS 菜单的样子画出来的，headless 环境拍不到真的系统托盘。
13. **哨兵复用 WP146 的 `bin_lock_file`**。我原先自己加了一个 `lock_json` 字段，合并 main 时发现 WP146 做的是同一件事，就删了自己的，把 `computer-use.lock.json` 的 `driver` 段改名为 `cli`（和 `browserskill.lock.json` 同形）。
14. **demo 的 `--card-gallery` 多了一张授权卡**，专门用来截图。它走的是和真卡同一条路（`approvals.create` → `projectCard`）。

## 3. 需要 Luoye 定的事

1. **macOS 权限给谁**：现在是给「Agents 工坊」（`mcp --direct`，见 §2 第 1 条）。另一条路是装 `CuaDriver.app`、把权限只给它，这样权限范围更窄，还有官方的光标动画；代价是要往 `/Applications` 装东西、常驻一个后台，而且「停止」只能断开我们这一侧。
2. **截图要不要进模型**：现在不进，模型只读无障碍树文字，隐私最好，但有些界面光靠文字看不懂。要进的话，需要支持图片输入的模型加附件库（接 WP143 的 DeepSeek Files 那条路），并且截图要在授权卡上单独问一句。
3. **授权卡批了自动重跑这件事，可以吗**：另一种做法是批了以后什么都不做，等人再说一句「接着做」。现在的做法省一步，但「批准」这个动作同时也启动了一次运行。
4. **一次授权只给一次运行**：同一件事连跑几次就要批几次。如果嫌麻烦，可以改成「这件事在 N 分钟内的所有运行」。
5. **驱动的平台**：lock 里有 Linux 的两条，但桌面版只有 macOS 和 Windows。Windows 的一键下载（用 `tar` 解 zip）和 SmartScreen 提示都没在真 Windows 上跑过。
6. **遥测关了以后，驱动可能还会在 `~/.cua-driver/` 留一个本机安装 ID**：上游说明是「关掉遥测仍保留本机安装 ID」，只是不上报。要连这个也不留，需要把 `CUA_DRIVER_TELEMETRY_HOME` 指到我们的数据目录，这会改驱动读配置的位置，我没有做。

## 5. 偏离

1. **授权流程是「出卡 → 批 → 重跑这件事」，不是「这次运行里等人批完接着挂」**。原因见 §2 第 2 条。派工单原话「批了这次运行才挂提供方」，现在是「批了，重跑的那一次才挂提供方」。
2. **「公司端（executor 档）永远不给」没按 `side_effect_policy` 判**，改成只在本机档给。原因见 §2 第 3 条：服务端所有运行都是 executor，按字面判的话电脑操控永远用不上。
