## 2. 你自主做的决定（白话）

1. **"装"官方插件 = 把 dsh 自带的可选包选进来，不下载。** dsh 0.2.0 把实验功能改成"可选插件包"，这几包随 dsh 一起装在本机、默认关着（上游 `OPTIONAL_BUNDLES`）。所以第一版清单只放它们：装卸就是改一个列表，离线、可撤、没有第三方代码进来。清单格式留了 `source: npm`，但这一版遇到 npm 来源直接拒（没有测过的装包路径不开）。
2. **官方插件管理服务本身在我们的服务进程里不挂**，用的是它和 `dsh plugin` 共用的那几个官方函数（建目录、读写清单、加载检查）。官方服务要 Loader + `profileContext`，只有 `dsh --profile` 起的进程里才有；我们的两档运行时不读 profile。完整 profile 那条路上它是开的，但写方法由守门插件拒掉——装插件要出卡，那条路只在「设置 → 官方插件」。
3. **插件装在哪**：数据目录下一个 profile 形状的"插件层"，不写仓库里的 `profiles/agentsws/`（装好的桌面版里那里是只读的，也是锁定表本身）。
4. **锁定表从文件现读**：`cordis.patch.yml` 里出现的每一个 id 都算（C 类四行、账号登录、电脑操控两行、守门插件）。以后加一行锁定，配置写回自动拦它；守门插件里那份常量由测试钉住与文件一致。
5. **"做完比一遍"比"事先禁止"更硬**：不管后端怎么实现，做之前把锁定 patch 的字节记下来，做完一比，变了就写回原样、撤掉这次选择、记被拒。测试用一个"装的时候顺手改锁定 patch"的坏后端钉住。
6. **时间上下文不挂官方 `dsh-time-context`**，三条硬伤：它是 dsh agent-loop 的 `agent/pre-step` 钩子，stub / direct 两档挂不上（破三运行时同一份提示词）；它自己读墙钟，模拟 / 回放的注入时钟管不到（基线钉不住）；它按浏览器报的时区定，我们的运行没有这个记录。意思照官方写，位置也照官方（最后一条 user 消息）。**官方的默认刷新频率是 10 分钟**（`refreshIntervalMs` 缺省 600000）；我们一次运行写一次、按小时取整（22 §2 缓存纪律）。装了「自动化任务」可选包的完整 profile 里官方那一行照样会挂。
7. **为什么排在最后、按 user 发**（第一版我放在事项材料中间当 system 消息，模拟跑出来学习场景花费 +41% / +165%：同一件事跨小时重跑，整段前缀吃不上缓存）。挪到最后之后缓存前缀（`static_prefix_hash`）与改前**逐字相同**，花费只多那几十个字。
8. **只有接了公司时区的运行才写这一条**（服务端装配时接上 `timeZone`）。运行时单元测试与老回放不接，字节与改前一样——WP148 / WP179 的两份老金样照旧逐字通过。
9. **没截图**：纪律"不开真浏览器"。

1. **装上的官方插件现在只在完整 profile（`dsh --profile agentsws`）那条路上生效**，而那条路今天没有人起——我们的两档运行时自己搭树、不读 bundle（16 §1「公司端不装第三方代码」）。要让「自动化任务」「团队协作」在 Agents 工坊的运行里真的用起来，需要逐包适配进两档运行时（自动化任务官方说要 Web 会话控制器，headless 挂不上；团队协作会关掉官方子代理工具换成团队工具；语音输入是官方网页里的麦克风）。建议另立一单先做「自动化任务」和我们自己的 `packages/schedule` 怎么并存。

4. **代答（秘书）运行**没加时间那一条：它的请求由 `@agentsws/secretary` 自己组，上下文由调用方给；要不要加（一行调用）请定。
