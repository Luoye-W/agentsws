## 0. 一句话

工作台上再也没有「数据驻留 / 数据不出境 / 境内境外」的开关、角标和说明；本机不再发 `X-Agentsws-Region`、网关不再按驻留拦任何一家；老工作区存的驻留设置读到就丢、不报错；云上默认生图型号统一成 GPT Image 2.5（262「不出境默认 Seedream」作废）。契约照「错误码先留着标 deprecated、其余删」的口径改，私有云还在引用的两个符号也先留着标 deprecated，免得私有仓升子模块就编不过。

## 2. 契约：删了什么、留了什么

口径（与私有云 WP280 同）：**错误码先留着标 `@deprecated`、不再产生；其余删。** 另加一条我自己的判断：私有云现在还 import / 还在写的符号也先留着标 deprecated——删了它私有仓一升子模块就编不过，而 WP280 还没动这两处（我只读看了 `agentsws-cloud` main 与 `wp280-openrouter` 分支，没改）。

**删了**

| 东西 | 在哪 |
|---|---|
| 请求头 `X-Agentsws-Region`（AI 四条、数据三条、红人库两条路由的 `headers`） | `cloud-api.ts` → `cloud-openapi.json` 里一处都没了 |
| `AiRegionHeaders`（路由改用 `AttributionHeaders`，形状一样少一格）、`DataRegionHeaders`（数据三条路由不再有 `headers`） | `cloud-api.ts`、`data-service.ts` |
| AI 口与数据口错误表里的 `422: 'residency_blocked'` | `cloud-api.ts` |
| 事件类型 `model.blocked_residency` | `events.ts` |
| 模型 API 的 `data_residency`（看 / 改两头） | `packages/api/src/routes/models.ts`（本机契约，不在 contracts 包） |

**留着、标 `@deprecated`**

| 东西 | 为什么留 | 什么时候可删 |
|---|---|---|
| 错误码 `residency_blocked`（`ApiErrorCode` 与 `CloudEntryErrorCode`） | 口径如此：老云端 / 老客户端回包里还可能有，解析不崩 | 私有云 WP280 部署 + 老客户端过一两个版本 |
| `KolPublicRefreshResult.reason` 的 `'residency'` | 同上（是云端回包里的原因码） | 同上 |
| `KOL_REGION_HEADER` 常量 | 私有云 `packages/kol-public/src/routes.ts` 还在 import | WP280 去掉那一处之后 |
| `PricingModelEntry.cn` | 私有云 `packages/metering/src/pricing.ts` 还在写这一格（对象字面量，删了就是类型错） | WP280 去掉之后 |

`residency_blocked` 还留在 `packages/api/src/errors.ts`、`packages/connect-adapter/src/errors.ts`、`packages/stand-ins/src/errors.ts` 三张状态码表里——它们是 `Record<错误码, 状态码>`，码在联合里就必须有一行；以及由此生成的 `apps/cloud/openapi.json`、`packages/sdk/{openapi.json,src/schema.ts}` 的错误码枚举。

## 6. 要 Luoye 定的事

1. **「欧洲客户数据不发 cloud_brain」那条也一起删了。** 它和「cn 驻留拦 global」写在同一个 `assertResidency` 里、共用 `model.blocked_residency` 事件；生产里从没启用（没有 `cloud_brain` 这家 provider，也没有调用方传 `eu_customer`）。——**建议：同意删**；真要做欧盟数据合规，到时按 GDPR 单独设计，不复用这条。
2. **模型接口的「国内 / 海外」`region` 字段留着当记录**（provider 配置、模板预设、`ModelRef.region`、DeepSeek 账号视图）：界面不展示、不拦，只是元数据；删它要动几十个夹具和 API 形状。——**建议：先留着**；以后有人真用不上再开小单清。
3. **契约里 4 个 deprecated 什么时候真删**（`residency_blocked`、`reason: 'residency'`、`KOL_REGION_HEADER`、`PricingModelEntry.cn`）。——**建议**：后两个等 WP280 把私有云里的引用去掉、合并部署后，下一单顺手删；前两个错误码 / 原因码再等老客户端过两个版本（比如 ci.25 之后）一起删。
4. **合并顺序**：本单保留了私有云还在引用的符号，所以私有仓升子模块到含 WP281 的 main 不会编不过；但私有仓若有断言「契约里有 422 / 有 `X-Agentsws-Region` 参数」的测试会红（我只读看了一眼没找到，`cloud-openapi.json` 的对照由 WP280 那边跑）。——**建议：先合 WP281，WP280 升子模块后再收尾**；WP280 去掉 `KOL_REGION_HEADER` import 与价目表 `cn` 那一格。
5. **云上生图型号名**：本机对云发的仍是我们自己的名字 `gpt-image-2.5-flare` / `gpt-image-2.5-sunburst`（与决策 292 选 A 一致）。WP280 改走 OpenRouter 后，OpenRouter 上的型号 id 多半不同。——**建议：云端把我们的名字映射成 OpenRouter 的 id**，本机不跟着改（老客户端也不用升级）。
6. **隐私政策那一句**改成「云端服务不提供『数据不出境』的单独选项；不想经过我们云端就只用自己的 key、只在本机跑，这时是否出境取决于你选的那一家」（原来那句「只用自己的 key、只在本机运行，避免数据出境」其实不准：自己的 key 打海外模型照样出境）。——**建议：Luoye 看一眼措辞**；上线前律师审阅时把跨境一节一起看（文件头注释本来就这么写）。
7. **开源仓里的云端旧副本（cloud-entry / kol-public / metering / apps/cloud*）也一起改了**，没有只改本机侧。——**建议：保持**；它们不部署，但留着驻留逻辑会让人以为还有这回事，测试也会和契约对不上。

## 7. 偏离

- 派工单说「请求头常量能删的删」；`KOL_REGION_HEADER` 和 `PricingModelEntry.cn` 我没删、标了 deprecated——私有云 main 和 WP280 分支都还在用，删了会让私有仓升子模块编不过（见第 6 节第 3、4 条）。
- `residency_blocked` 照口径留在联合里，但从 AI 口 / 数据口的路由错误表里拿掉了 422（那是「这条路由会回什么」，既然不再产生就不该写）；枚举本身还在，老回包照样能解析。
- Google 生图「地区不可用」原来借用 `residency_blocked`，改成 `provider_unavailable`，人话不变（那是 Google 自己按地区开放，不是我们的驻留）。
