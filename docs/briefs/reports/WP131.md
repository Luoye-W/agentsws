## 2. 我自主做的决定（白话）

- **出处写 6259a1c 而不是 `git log -1` 的 d25b877**：d25b877 是之后的 CI 提交，跟这几个文件无关；写真正带来这批改动的那一次，查起来才对得上。
- **批次 id 由服务端发、插件原样带回**（第一块不带、拿回执里的；插件自己编的形状整批 400）：满足「批次 id 由本机服务返回」，
  又让一次采集分 20 条一块发时仍是同一批。主页 / 内容页的单条观测不算批次。
- **深链多带一个 `channel`**：不带的话工作台总落在第一条红人职责（多半是 YouTube），TikTok 那一批会显示成空的。可省，省了就是老行为。
- **自动评分排队异步跑**，不在收进那一次请求里当场跑：20 个人的体检是 20 次云调用，插件那一块请求不该为它多等十几秒。回执只报「排了几位、最多约多少」。
- **30 天内体检过的人不再自动体检**：不为同一个结论花两次钱（与 reveal 的 30 天口径一致）。
- **积分不够就停体检不停打分**，这一轮后面的人不再逐个去撞 402。
- **「每位约 N 积分」的 N 由本机服务按价目表给**（体检价，现在是 3），插件不再用旧 SaaS 的常量 1；没关联云账号时 N = 0，本机打分不弹确认。
- **开关不再要求组织上下文**（旧插件要 `organizationId` 才画开关）：本机打分免费，谁都能开；花钱的只有体检那一半。
- **粉丝数换算用「列表筛选同一个解析器」**（而不是 `counts.ts` 那份）：同一个数在面板上筛掉与送进库是同一个读法。两份都补了 `억`。
- **大于 50 亿的粉丝数当读错**，不送。
- **生图结算顺手记我方成本**：不然后台永远看不出生图亏不亏，而 docs/77 恰好算出生图可能亏。
- **工作台清单上显示「体检 N」**：自动体检做了但界面上看不到，等于没做。
- **价目页只给员工看**，来历（含成本、倍率）不进用户界面（49 M4）。
