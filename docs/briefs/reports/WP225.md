## 3. 要 Luoye 定的事

1. **数据目录要不要改成好认的名字？** 现在是 `%APPDATA%\@agentsws\desktop`（mac `~/Library/Application Support/@agentsws/desktop`），来自 package.json 的包名。建议改成 `%APPDATA%\Agents 工坊`（或 `agentsws`）——用户找日志、卸载后手动删数据时好认。代价：要在 `app.ready` 之前做一次老目录迁移（老目录在、新目录不在 → 整个挪过去，挪失败就继续用老的；dsh 场景里记着绝对路径的配置要一起改），并且内测机上已有数据。**没改**，等你定；定了另开一单。
2. **PowerShell 起进程带 `-ExecutionPolicy Bypass`（只对那一个进程）**：不带的话 Windows 自带的 5.1 默认策略下 `npx` / `pnpm` / `shopify` 的 `.ps1` 壳一跑就「禁止运行脚本」。执行策略不是安全边界（微软原话），真正的两道墙（命令白名单、沙箱）不受影响。我按这个做了，你不同意可以去掉（去掉后没装 PowerShell 7 的机器上 AI 跑不了 npm 装的命令）。

## 5. 自主做的决定（白话）

- 「同一主版本」照 npm `^` 算：0.x 时次版本号就算「大」（0.3 → 0.4 要问）。工作单只说「同一主版本」，0.x 这样算更稳妥。
- `/v1/activity` 只回数量、跨品牌数：重启会把所有品牌一起打断，所以都要数；别的品牌的事项名不该从这条缝露出来。问不到按「没有」算，免得永远装不上。
- Windows 参数里有 `"` 或 `%` 的直接拒，不做 cmd 转义：这两个在双引号里 cmd 也会解释，转义规则不可靠，拒掉比装错命令好；正常的主题名、店铺域名、路径都不含它们。
- PowerShell 档另外拒掉变量 `$…`：变量展开成什么事先看不见，越界判断会被绕过；Windows 上 `node $env:USERPROFILE\x.js` 这种写法本来也不该是 AI 在主题副本里干的事。
- 更新源放行本机回环 http：只为端到端测试；回环出不了这台机器。
- 端到端用默认用户数据目录、不用环境变量覆盖：安装程序重开的新版本拿不到我们给的环境变量，用默认目录才和真用户一致。
- 冒烟顺手修了「壳不等服务进程就退」：不修的话「退出干净」那条一旦认对进程就会偶发红。
- 决定 ⑤ 写在 DECISIONS 的 WP225 名下但工作单没列，改动只有一行提示，就一起做了。

## 8. 补：CI run 37312571705 之后（Fable 推的第一次）

- `update-e2e` 一次过（N → N+1）；`nsis` 冒烟进程识别 7 个、子进程退出码 0、退出干净都过了，但父进程随后以 **0xC0000409**（fail-fast）崩。
- **判断的根因**：崩在「退出干净」之后的下一句——`fs.cpSync(<用户数据>\logs, …, { recursive: true })`。冒烟的用户数据目录是 `agentsws-smoke-数据`（带中文）；Node 22.23.3 在 Windows 上 `cpSync` 碰到这种路径整个进程 fail-fast、一行字不留。佐证：① WP218 第一次跑的 exit 127 也正好落在同一句（当时在 `finally` 里，退出之后 0.5 秒）；② Playwright 子进程不拷日志，退出码 0；③ `update-e2e` 也拷日志，但它的用户数据目录是 ASCII 的 `%APPDATA%\@agentsws\desktop`，没崩。mac 上复现不了（只有 Windows 上的那条路径会崩），所以是推断，下一次 CI 会确认。
- **修**：两份脚本都不再用 `fs.cpSync`，改成自己一层层 `readdir` + `copyFileSync`（`copyDirSync`，有测试，含中文目录名）；拷完打一行「日志拷出来了：N 个文件」。卸载那一步也按 Fable 的建议收紧：不再 detached + unref，`spawnSync` 等卸载程序返回、记下返回码（「开始静默卸载」「卸载程序返回：…」两行），再照旧等 exe 消失。这样就算还有别的崩点，报告也能看出停在哪一行。
