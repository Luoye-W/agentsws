# WP293 报告：dsh 升级 0.2.0-rc.1 → 0.2.1-alpha.2（跟 alpha）

分支 `wp/293-dsh-alpha`（worktree `../agentsws-wt/wp293-dsh-alpha`，从 main fb70dd21 起）。Claude 子代理，2026-10-10。
没 push、没合并、没打包、没部署——合并关口、合并、打包、装 Windows 由主线会话（Fable）做。
照 docs/42 七步走完：先钉基线、再动版本号，通过条件是「和钉住的那份一样」。完整的事实记录（逐包表、出处、证据）在
`packages/dsh-adapter/UPGRADE.md` 的 WP293 一节，这份报告只摘要。

**派工单原定升到 0.2.0-rc.2**；开工后 Luoye 说「要采用 alpha 的」，所以目标改成 **0.2.1-alpha.2**（分支名也从 `wp/293-dsh-rc2` 改成 `wp/293-dsh-alpha`）。
如实写清：npm 上 `latest` / `next` 仍是 0.2.0-rc.2，0.2.1-alpha.2 是**内测线**（10-09 发，升级时不到一天），GitHub 上全是 Pre-release。

**一句话**：升上去了，我们的行为没变——136 条运行指纹去掉版本号逐字节相同、提示词与工具表逐字节相同、三个模拟包 × 三个运行时的结果逐字节相同、
装包前冒烟 10 个岗位全过。但这一跳比上一跳大得多（跨三版、1122 条提交），**有四处官方改动会让我们的功能坏掉，已经修好**：
终端和浏览器挂不上、ChatGPT 订阅的默认模型被删、官方「自动化任务」插件被删、登录失败多了一种码。**这一跳没有新锁任何一行**。

## 1. 新版改了什么（对我们有影响的）

| # | 官方改了什么 | 不修会怎样 | 怎么修的 |
|---|---|---|---|
| 1 | 终端（`bash` / `pwsh`）和浏览器插件改成**必须**有一个新服务「会话当前目录」 | 建站岗位的终端工具不出现（模型调用报"没有这个工具"）；浏览器那一档直接起不来 | 有终端或浏览器的运行，挂上官方那两个服务（目录还是原来那个，沙箱边界不变） |
| 2 | 四个定时工具从 `dsh-schedule` 挪进新包 `dsh-tool-schedule` | 编译不过 | 改从新包取定义；我们抄的那份跟着改了一句说明 |
| 3 | 官方把「自动化任务」可选插件**删了**，改成网页版自己挂、默认就开 | 我们的开关是"这个插件装没装"，以后永远装不上 → 定时任务功能永久关掉 | 跟官方走：**改成内置、一直开**（见 §3 第 1 条） |
| 4 | 订阅登录用的 pi-ai 库升级，ChatGPT 订阅的模型目录**删了 gpt-5.4**——那正是我们的默认模型 | 用 ChatGPT 订阅的人，每次运行一个请求都不发、却显示"跑完了"（什么也没做） | 默认改成 gpt-5.5；另外补了一道：这种情况照实显示"没跑成"并带上原因 |
| 5 | DeepSeek 账号登录多了一种失败码「没收到回应」 | 编译不过 | 加一句人话："连不上 DeepSeek（没收到任何回应），检查网络或代理" |

其余改动（官方删了运行时自检插件、子代理改了委派方式、工具展示去掉 `both` 模式、网页版一堆界面改进等）**碰不到我们**，逐条见 UPGRADE.md §1。
兄弟包 cordis / schemastery / loader / include 这次**必须跟着升**（新版要的版本范围不包含旧号），内核测试全过。

## 3. 锁 / 开了哪些（官方功能优先）

**锁：一行都没新锁。** profile 层原有五行锁定（会话日志上报、DeepSeek 账号默认登录、上报通道、反馈上报、插件清单上报）逐行复核：都还在、指向的插件没换、组合后都关着。

**开了：**
1. **定时任务（自动化任务）改成内置、一直开**——官方把它从"可选插件"改成"网页版自带、默认就有"，我们跟着走。以后每次运行都能让 AI 建提醒 / 定时任务；
   我们包的那一层没变：只能动这件事里自己建的、会往外发的周期任务先出卡等你批、次数和频率有上限。右栏不再提示"先去装插件"。
2. **官方插件清单新加五个**（设置 → 官方插件，默认都关着，装要出卡批）：查找旧对话、接力循环、常驻终端、标题跟随、代码副本。都只在本机、不把业务数据发给别人。
   这些只在"官方完整界面"那一档里用得上，我们自己的岗位运行不挂。
3. 团队协作、语音输入两项：复核过没变，只改版本号；「自动化任务」那一项删掉（官方删了包）。

**没开、等你定**（见 §4 第 2–4 条）：思考过程翻译、调试工具、署名徽章。

## 4. 要 Luoye 定的事（每条附建议）

> **Luoye 10-10 定：七条都按建议来。** 即：定时任务保持一直开；思考翻译、调试工具、徽章三个插件不放进清单；接力循环照官方 64 轮；
> 老用户 gpt-5.4 自动换成 gpt-5.5 **另开小单**（不在本单做）；跟 alpha 照常走合并关口与 Windows 真机复测。

1. **定时任务改成一直开，可以吗？**
   以前要在「官方插件」里装上才有；官方现在默认就开，我按「官方功能优先」跟着改成一直开。代价：每次运行模型多看到四个工具，token 略多一点。
   **建议：保持一直开。** 想要开关的话，加一个设置项很简单（服务端已经留了口子）。
2. **思考过程翻译插件（`cot-translation-bundle`）：不放进清单。**
   它默认把 AI 的思考过程原文发给微软翻译（`edge.microsoft.com`），可选谷歌翻译；思考过程里会有你的业务内容。这是"把业务数据发给第三方"那一类。
   **建议：不放。** 如果想要，可以只放「用 DeepSeek 翻译」那一档（要我们把它的提供方锁成 DeepSeek，这算锁一行，需要你点头）。
3. **调试工具插件（`inspector-profile`）：不放进清单。**
   它会在本机开一个没有密码的调试口，本机任何程序连上去就能在我们的服务进程里执行任意代码，还会原样记下网络请求里的密钥。
   **建议：不放。** 这是开发者调试用的，普通用户用不上。
4. **署名徽章（`badge-skill-bundle`）：先没放。**
   技术上没问题，但 AI 可能把「powered by dsh」的小徽章加进给客户的邮件或网页里。**建议：不放**，价值低。
5. **接力循环一次最多 64 轮、没有花费上限，要不要压低？**
   这是官方默认值，只有你明确要求时 AI 才会用，但一次最多相当于 64 次完整的 AI 运行。清单卡片上已写「很费额度」。
   **建议：先照官方 64**，看实际用的人多不多再说。
6. **已经用 ChatGPT 订阅、存着 gpt-5.4 的用户怎么办？**
   新设置的人默认就是 gpt-5.5；但以前设置好的人，存着的还是 gpt-5.4，升级后他们的运行会显示"没跑成"（带官方原因），要自己去「设置 → 模型」重选一次。
   **建议：再开一个小单，启动时自动把这种"模型已经不在目录里、而且是当年默认值"的选择换成 gpt-5.5，并留一句提示。**
   这次没做，因为它要改用户已保存的配置，不该夹在升级单里。
7. **跟 alpha 的风险，知会一声**：这是内测版，官方随时可能出 alpha.3 / rc。这次的基线和测试都过了，但官方自己还没把它标成"推荐"。
   **建议：照常走主线的合并关口和 Windows 真机复测**；以后再升，可以等 0.2.1 出 rc 再跟。

## 5. 我自主做的决定（白话）

1. **"一轮出错却显示跑完了"这个洞顺手补了**：以前只有模型那条流里报的错才算"没跑成"；这次发现选的模型不存在时，请求根本没发出去，结果被当成"什么也没做、跑完了"。
   改成：这一轮官方报了错，就照实显示"没跑成"并带官方原因。三个模拟包 122 条场景、指纹 136 条一个都没变。
2. **「会话当前目录」只在有终端或浏览器的运行里挂**，目录就是原来那个（终端 = 这家店的主题副本目录，浏览器 = 进程目录），所以行为不变；
   代价是这两种运行里模型多看到一句「当前目录：……」（官方必选的）。路径里可能带电脑用户名，发给的是你选的模型服务商，不是第三方。
3. **服务端加了一个只给测试用的开关 `automationEnabled`**，缺省一直开；用来钉住"关掉就停、任务留着"这条老规矩还成立。
4. **测试和截图脚本里的示例插件**从被删的「自动化任务」换成「查找旧对话」。
5. **排除表里删了一条过期的**（`libreoffice-kit@0.1.1`，新版 0.1.5 早过静默期了）。
