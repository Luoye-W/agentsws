# WP243 报告：长一点的云模型调用在 Windows 上被中途掐断 + 首次设置推荐太慢太长

分支 `wp/243-longcall`（worktree `agentsws-wt/wp243-longcall`），Claude 子代理。

## 0. 一句话

**8859 个输出 token 几乎全是「思考」**：同样 21 条职责 + 6 个岗位，老写法的答案本身也就 600～1000 token
（按 DeepSeek 官方估算口径），剩下七千多个是模型在想。推荐这一次现在**关思考、封上限 2048、要紧凑数组 JSON**，
答案估计约 420 token。**长调用被掐**：「Agents 工坊（用积分）」那一条的所有对话调用（推荐、岗位运行、随便聊、模型验证）
现在一律在内部走流式，连接上一直有字节，代理不再当它空闲掐掉；流到一半断了不当成功，整段重发一次；每一次尝试都记错误码与耗时。

## 3. 自主做的决定（白话）

- **只给官方接口那一条开「内部走流式」**，用户自己填的 DeepSeek key / 别家不动：别家的流式各有毛病（有的不回用量、有的流式工具调用不全），没真机验证不敢一起改。见 §5 第 2 条。
- **关思考只在推荐这一处开**，岗位运行照旧（运行要不要想，影响质量，不该我顺手改）。
- **DeepSeek 账号登录那一路（Messages 口）不认这两个提示**：它走的是另一个协议，关思考在那边的写法没真账号验证过，发错了会 400、推荐就退回按词对——比现在还差。照旧。
- **上限给 2048 而不是 1500**：目标是实际输出 < 1500，上限留余量；万一云端没关掉思考，答案被截断，能救回的职责照样用，救不回就退回按词对（真机上 `output_tokens` 正好 2048 就说明思考没关掉，见 §6）。
- **重发只一次、整体重来**：第一次拿到的半截一律丢掉，不拼接。
- **测试里的「45 秒不回字节就掐」按比例缩成 250 毫秒**（回答要 800～900 毫秒），真 HTTP、真 `fetch`，行为一样、测试不用等一分钟。

## 4. 云端（私有仓没动，需要云端确认的）

开源仓里能看到的那份转发（`packages/cloud-entry/src/ai.ts`）：**流式支持**——边收边转（`meteredStream`，不缓冲），出站替我们补 `stream_options.include_usage`；
请求体**其余字段原样转给上游**（`withUsageOption` 整份拷贝），所以 `max_tokens`、`thinking` 都会到 New API。需要云端确认两件：

1. **New API 那一跳会不会把 `thinking: {type: disabled}` 转给 DeepSeek 渠道**（有的版本只认它自己结构体里的字段，多的会丢）。丢了的话思考关不掉——推荐就会撞 2048 上限。办法二选一：New API 渠道上加参数覆盖，或者云上 `deepseek-flash` 默认指向非思考档。
2. **私有云那一跳流式不缓冲**（Workers 本身边收边转；别在中间加压缩 / 整包读完再回）。缓冲了，本机这边改成流式也一样等几十秒没字节。

## 5. 要 Luoye 定的事

1. **流到一半断了整体重发一次——可能多扣一点**：云上流式「断了也按拿到的那部分结算」（`meteredStream` 的规矩），所以第一次断在半路、第二次成功，等于付了一次半。与决策 84（连接被掐重发一次）同一类，只是把「拿到回执之前」扩到「读回包读到一半」。**建议保留**（不重发的话，人看到的就是「这次没用 AI」）。
2. **「内部走流式」要不要以后也给 DeepSeek 官方 key 那条开**（用户自己的 key、直连 `api.deepseek.com`，同样经过 Clash / 火绒）。**建议先只开官方接口**，等 Fable 真机看到 `model.usage` 正常、`net_retries` 少了，再单开一张小单扩到 DeepSeek 官方 key。
3. **岗位运行要不要也默认关思考**：现在只有推荐关。**建议不关**——运行里要做判断，思考有用；慢的问题这次靠流式解决了（不会再被掐），只是久一点。
