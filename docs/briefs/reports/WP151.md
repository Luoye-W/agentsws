账号那一路是「DeepSeek 账号余额不足，充值后再让它接着做。」，API key 那一路是「DeepSeek API 余额不足，去开放平台充值后再试。」；

## 2. 我自主做的决定（白话）

1. **判定一字不自己编**：402 就算；别的状态码只看官方那种错误信封里的措辞（"insufficient balance""quota exceeded"之类，正则照搬官方）；
   401 / 403 永远先算"凭据问题"，不算余额。正文是纯文本（代理页之类）就不拿措辞判，也照官方。
2. **API key 那一路只对 DeepSeek 官方地址说"去开放平台充值"**：改过地址的（代理 / 中转）余额不足时充值去处不是 DeepSeek 开放平台，
   照旧用原来泛泛的"这个账号余额不足，去控制台充一点"（测试钉了）。别家（百炼等）的 402 完全不动。
3. **"提示什么时候收"**：账号那一路——下一次调用成功，或者卡片刷新余额时任何一个钱包大于 0（充值钱包或赠送钱包）；API key 那一路没有余额查询口，
   就等下一次调用成功（例如点一下「测试」重新验证）。登上 / 登出 / 登录失效也清掉。
4. **"余额不足"只记在内存，不落盘**：重启之后就没有那一行了，下一次撞上再出。理由：它是一时的状态，落盘了反而可能在充完值、重启之后还挂着一条旧提示。
5. **账号那一笔按机器一份，API key 那几笔按品牌**：账号就一个（与登录同一层）；key 是每个品牌自己存的。
6. **顶栏胶囊点了去「设置 → 模型」而不是直接开充值页**：胶囊不分是哪一条（可能两条都不足），到设置页每张卡上各有自己的「去充值」，不会充错地方。
7. **账号卡里余额不足时每 30 秒刷一次余额**：只在有提示时刷（刷余额会问一次平台）；从充值页回来窗口聚焦也会刷一次，一般用不到等 30 秒。
8. **三步验证第 ② 步和运行里用同一句**（派工单"统一口径"）：所以 `dsa.err.balance` 的文案也是"充值后再让它接着做"，验证场景读起来稍怪但口径一致；
   英文同步改。

## 3. 需要 Luoye 定的事

1. **真账号 / 真 key 撞一次 402**：没法离线核 DeepSeek 真实的 402 正文长什么样（官方包的判定是 402 或措辞，我们照搬，理论上够）；哪天余额真用完了，
   看一眼运行失败原因与卡片那一行就行。
2. **账号充值页与开放平台充值页现在是同一个地址**（官方 `platformOrigin` 默认就是 `https://platform.deepseek.com`，`/top_up`）：
   分法照官方做了（两条路各有各的来源、各说各的话），但实际打开的是同一个页；要不要在 API key 那句里再提醒"用建这把 key 的那个账号登录开放平台再充"，你定。
3. **"钱包 > 0 就收"可能收得早一点**：如果 DeepSeek 在余额还剩一点点时就回 402（例如不够扣这一次），卡片一刷新看到余额 > 0 就把提示收了，
   下一次运行再撞上再出。要更稳可以改成"余额比撞上时多了才收"，需要多记一笔撞上时的余额，本单没做。
