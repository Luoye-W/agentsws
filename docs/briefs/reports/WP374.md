## 2. 做了什么（白话）

1. **新的接口类型**。设置 → AI → 模型 →「加一个」里多一张卡「Anthropic 兼容（自定义）」，方案「自己填地址与 key」。默认地址是 Anthropic 本家 `https://api.anthropic.com`（有 Anthropic key 的人直接能用），中转站换成它给的那条，带不带 `/v1` 都行。key 走原来那个原生表单，只进本机加密库，不经 AI（决策 814）。
2. **拉模型清单**。保存时顺手拉一次；还没保存的草稿点「拉取模型列表」也能拉（表单会告诉服务端「这是 Anthropic 兼容口」，服务端就按 Anthropic 的地址和请求头去拉）。拉不到（有的中转站没开这个口）就退回手填，和 OpenAI 兼容那张一样。
3. **勾进 AI 钮**。WP370 那个「也在 AI 钮里显示」照样能用：勾上的模型挂上网关，AI 钮里和这条来源排在「自己接的」那一组，组名就是你给这条来源起的名字（比如「我的 Claude 中转站」）。设置页「默认模型」下拉和 AI 钮同一份。
4. **思考程度**。官方 pi-ai 支持这个协议的思考（老型号是 extended thinking 按预算，新型号是 adaptive + effort），所以接到了 WP370 的思考档上：官方目录里认得的 Claude 型号出「快 / 标准 / 深想」（例：Sonnet 4.5 是 low / medium / high），选了哪档就发哪档，没选就发界面上默认亮的「标准」（决策 1032，见 §3a）；目录认不出的型号不出这一行、也不发。上一轮的思考块（带签名）下一轮原样带回去（Anthropic 要求工具调用来回时这样做），换了模型就不带（签名跨模型不通用，官方同一条）。WP373 正在做的独立开关读的是同一份 `thinking`，不用再改。
5. **能力标签**。只照官方目录：看图（目录里写着收图）、长上下文（≥ 20 万 token）、显示名。官方目录**没写**自带联网，所以这一类不标「自带联网」。目录认不出的型号：看图的声明是「没验证过」（AI 钮里照旧带看图小标，这是 WP370 起的老规矩：只有测出看不了才去掉），点「测试」后以测试为准。
6. **报错说人话**。key 不对 →「API key 不对或者已经失效，去控制台重新生成一把」；Anthropic 本家的「credit balance is too low」和中转站常见的「额度不足 / quota / 余额」都归成「这个账号余额不足，去控制台充一点」；别的状态照原样（5xx 网关照常换备选）。报错原文截到 200 字，里面不会有 key。
7. **三个运行时**。stub / direct / dsh 都经同一个网关，测试里 direct 和 dsh（进程内）都真打到了假中转站，事件里没有 key。
8. **表单少一格**：这张卡的表单不出「向量模型」（Anthropic 的 Messages 协议没有向量接口）。
9. **中英文案与教程**。卡上那一句（中英）、首字母徽标「A」（说的是任何 Anthropic 格式的服务，不借 Anthropic 的标志，和 OpenAI 兼容那张同一个理由）；`docs/help/model-openai-compatible`（中英）补了「接 Anthropic 兼容服务（Claude 中转站）」一节，标题改成「接 OpenAI / Anthropic 兼容服务（Kimi、Ollama、Claude 中转站…）」，卡上的「看教程」指到这一篇。

## 3a. 1032「显示什么就发什么」：怎么做的、别的来源查了没有

**规则**：没选思考档时，发 AI 钮上默认亮的「标准」那一档（就是 `thinkingOptionsOf` 算出的 `default`，和界面同一个来源）。选了就照选的；调用方硬要「别想」（`thinking: 'off'`，后台分类 / 起标题这类短调用都这么传）和强制某个工具时照旧不发。

**WP370 的几个来源逐个查了**（看官方「不给档」时到底发什么）：

| 来源 | 界面默认亮的 | 官方「不给档」时实际 | 一样吗 | 处理 |
|---|---|---|---|---|
| Anthropic 兼容口（本单） | 标准 = medium（Sonnet 4.5 等） | 能关思考的型号发 `thinking: disabled`（不想） | **不一样** | 改：没选发 medium |
| ChatGPT 订阅（WP362 / WP370） | 标准 = medium | pi-ai 发 `reasoning.effort: none`（不想；`openai-codex-responses.js` 第 427 行起：模型能关思考就写 off 档） | **不一样，同样问题** | 一起改：没选发 medium |
| DeepSeek 账号 / API key 走 Messages 口 | 标准 = high | 不写字段，官方 `dsh-llm-deepseek` 声明默认就是 high | 一样 | 不动（请求字节和以前一样） |
| OpenAI 兼容口、工坊积分 | 不出思考那一行 | — | — | 不涉及 |

**改在哪**：网关的 Anthropic 兼容口多一个可选的 `defaultEffort`（现取，官方目录后读到也能跟上）；服务端订阅那一条（`subscription-model.ts`）同样多一个 `defaultEffort`。两处都由设置页后端按 AI 钮那一份 `thinking.default` 给，一处定义。dsh-adapter 里订阅那一跳没动（「没选不写」的测试仍成立，是服务端替它补上了档）。

**测试跟上**：网关测试多一条（给了默认档：没选按它发、`thinking: off` 不开）；服务端测试改一条、加一条（Anthropic：没选按 medium 开思考且预算小于「深想」、硬要别想发 disabled、中转站自己起名的仍不发；订阅：没选交 medium、选了交选的、硬要别想不交）。

## 4. 我自主做的决定（白话）

1. **直接调官方 `anthropic-messages`，不经 pi-ai 的模型集合 / 凭据库**：key 每次现取、只交给 pi-ai 的 `apiKey` 一格。我们这条来源的 id 不叫 `anthropic`，pi-ai 就不会去读 `ANTHROPIC_*` 环境变量和联邦身份；没 key 直接拒，不发请求。
2. **地址去掉一个结尾的 `/v1`**：官方 SDK 自己接 `/v1/messages`，中转站文档两种写法都有，照官方 discovery 的做法都认。
3. **目录怎么认型号**：先原样，认不出再去掉结尾的日期（`-20250929`）。
4. **认不出的型号**：照样把图送上去（能不能看以测试为准，不替上游说「看不了」）；输出上限按 8192 兜底；不发思考。
5. **去掉官方目录里的「服务端降级到别的型号」**（`allowedFallbackModels`）：那只对 Anthropic 本家有效，中转站不一定有那几个型号。
6. **强制某个工具时不开思考**：Anthropic 规定两者不能同时用。
7. **报错只归两类**：key 不对一律记 401，余额 / 额度没了一律记 402，人话层据此说那两句；其余照原状态码。
8. **契约只加**：`ModelProviderKind` 加 `anthropic_compatible`；`DiscoverModelsInput` 加可选 `kind`；`ReasoningReplay.kind` 加 `anthropic-messages`、块上加可选 `redacted`（被安全过滤遮住的思考块也原样回传）。已有签名一个没改。
9. **消息翻译器在网关包里放了一份**（照 `dsh-adapter/src/subscription-chat.ts` 的 `toPiContext` 改，头注释写了出处）：网关包不能反过来依赖 dsh-adapter；多出来的只有思考块的带回与收回。
10. **默认地址填 Anthropic 本家**，默认模型 `claude-sonnet-4-5`：拉到的清单里没有它就换成清单第一个（和别的卡同一条规矩）。
11. **官方目录启动时读一次**（只读、不联网、几毫秒），读完了且配了这种来源就重装一次网关，让看图声明跟上。
