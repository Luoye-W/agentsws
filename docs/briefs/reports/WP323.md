# WP323 报告：发出记录 + 用说话配的「记录去处」（本单先接飞书）

分支 `wp/323-sinks`（从 10-14 main `84d7b930` 建，收尾时已 `git merge main`）。没推、没合、没打 tag、没发版。全程没读 `.env*`、没碰任何 key / token、没连真实飞书或任何外部服务（飞书全用替身）、没碰 4317。

## 0. 先说清楚：哪些是固定功能，哪些只是能力（按 Luoye 补充的原则）

| | 是什么 | 界面上 |
|---|---|---|
| **固定功能 ①** 本地发出记录 | 工坊替你发出去的每一条都记一行，可查、可导出 | 右栏「发出记录」（纸飞机图标） |
| **固定功能 ②** 通用的「记录去处」机制 | 交代 → 读表头生成对照 → 一张通用的「定规矩」卡 → 照写 → 失败留本地补写 → 可改 / 停 / 删 | 卡片流里一张「记录去处：<用户起的名字>」卡；右栏那一块只显示用户起的名字、状态、停 / 开 / 删 / 补写 |
| **能力**（不是功能） | 飞书适配器（多维表格 + 电子表格 + 知识库里的表）；Google 表格 / 钉钉只留口子 | **没有**任何一家的设置区、按钮、卡种、默认开启；AI 在用户交代时按链接选用 |

## 1. 实现清单

1. **契约**（`packages/contracts/src/outbound.ts`，只加）：`OutboundRecord`（时间、渠道、动作、发到哪、原帖标题 / 链接、对方、对方原话、主题、我们发的全文、链接、平台 id、回的哪条、档位 / FAQ、谁批的、状态、后续）、`OUTBOUND_FIELDS`（19 个标准字段）、列对照（`SinkColumn`：标准字段 + 日期写法 / 截断 / 值替换，或固定值，或留空）、`RecordSink`、`SinkWrite`、错误种类。
2. **本机存储**（`apps/server/src/outbound/store.ts`）：一台机器一个 `outbound.sqlite`，行上钉品牌；`source_key` 唯一（同一条只记一次）、`(去处, 记录)` 唯一（同一条不写两次）；删去处连带删它排着的写入。
3. **写入点**（`outbound/capture.ts` + `server.ts`）：
   - 出站那一跳 `deliverOutbound` 回 ok → 一行（客服回信、聊天、社媒回帖…；批的时候改过正文记改过的）；
   - 「发出去」类变更施行成功 `backendApply` 回 ok → 一行或几行（`kol_outreach`、`b2b_reply`、`b2b_outreach` 一批一封一行、`review_reply`、`press_release`、`export_docs_send`）；
   - 社媒回帖（执行器，带平台 id 和回的那条 id，之后挂后续用）、到点发帖、群发 → 社媒服务发成功那一刻记；
   - **演练**（发给演练红人）和**内存桩**（没接渠道时回的 `dlv_N` / `exec_N`，其实什么都没发）不记。记失败不影响发送结果。
4. **后续与删除**：`addFollowUp`（按我们那条的平台 id 把对方回复挂上去；我们再回也挂回原来那一行）；`counterpartDeleted`（对方删了原话 → 清掉我们存的原话、标「对方已删」，我们自己发的永远留，决策 667）。接口 `POST /v1/outbound/follow-ups`、`POST /v1/outbound/counterpart-deleted` 给之后读收件箱的那一单调。
5. **记录去处机制**（`outbound/log.ts` + `log-impl.ts`）：
   - `inspect`：按链接选适配器读表头（列名、类型、单选项、已有几行）；
   - `propose`：表头 + AI 给的对照 → 校验（只认标准字段 / 固定值 / 留空，格式只认确定性的几种）→ 没给的列按列名猜（docs/102 的例子五列全对上）→ 表里没有的列照实回 `unknown` → 出卡；同一张表再说一次 = 改（出新卡，批之前照旧按老对照写）；
   - `onDecided`：「记下」→ 生效 / 换成新对照；第一次就「不用」→ 去处不留；
   - 写：记一条就当场写，另有每分钟一拍补到点的；临时错误按 30 秒 / 2 分 / 10 分 / 30 分 / 2 小时 / 6 小时退避；没权限 / 表没了 / 列对不上 / 值不收 → 去处标「写不进去」、这几条留「待补写」（之后新发的也继续排进去，不丢），人点「补写」一次全写；**列对不上时自动重读表头、沿用对得上的列、重出一张「定规矩」卡**；
   - 停 / 开 / 删；删一个还在等确认的，顺手撤掉那张卡。
6. **「定规矩」卡**（`outbound/card.ts`）：复用 `policy_change`（不新造卡种），`form: record_sink`，两个按钮「记下 / 不用」，卡面只有标题（去处名字）+ 一行预览（用最近一条真实记录；还没有就用示例并写明）+ 一句之后怎样（有筛选时加「只记：Reddit」）。卡上不出现表格是哪一家。① ② 交代的人自己点，③ 发老板（与「以后都这样」同一条路）。
7. **飞书适配器**（`outbound/feishu.ts`）：用「消息渠道」里已经接上的那个飞书应用（加密库里那份凭据，每次现取不留），应用身份令牌带缓存、过期重取一次；认 `/base/…?table=`、`/sheets/…?sheet=`、`/wiki/…`（先问知识库是哪种表）；多维表格按列类型转值（日期写毫秒、数字、单选 / 多选、链接 `{text, link}`、勾选），新建记录带 `client_token`（同一条不会写两次）；电子表格空表第一次写先写一行表头（按用户说的列）；飞书错误分成「临时」和「停下来」两类。**权限说明只在 AI 配置出错时按需给出**（`setupHint`：没接应用 → 先去消息渠道接；没权限 → 开哪几个权限范围、怎么把表格共享给应用）。
8. **AI 用的三个工具**（`packages/stand-ins/src/runtime/record-sink.ts` 定义，`outbound/tools.ts` 执行）：`read_record_target`（读表头，只读）、`propose_record_sink`（配置，只出卡）、`list_record_sinks`（列出）。**所有职责都有**（服务端接了发出记录才有；模拟世界字节不变）。stub / direct / dsh 同一份定义；stub 有一段剧本（话里有表格链接 + 「记到 / 写进」就配一次）。出参白名单：没有表格 token、应用凭据、记录正文。
9. **接口** `/v1/outbound/*`（`packages/api/src/routes/outbound.ts`）：查记录、导出 CSV（带 BOM，Excel 直接开）/ JSON、挂后续、对方删了、列去处、停 / 开 / 补写 / 删。**新建与改不在接口里**（只走说话 + 卡）。SDK 已重出；云契约无变化。
10. **工作台**：
    - 右栏「发出记录」（`rail/panels/outbound-panel.tsx`，`lazy()`）：上面一小块是记录去处（只在有的时候出；名字 + 状态点 + 已写 / 待补写；写不进去才出一句原因和「补写」；停 / 开 / 删是小图标）；下面一条一行（时间 · 渠道 · 动作 · 发到哪 / 我们发的那一句 / 回了几条 / 链接），能按渠道筛、能导出。图标徽标只在有待补写时出数。没有任何输入框、没有任何一家的设置。
    - 「定规矩」卡主体：一行预览（`deck-card-body.tsx`），「记下 / 不用」直接是两个按钮、键盘跟按钮走。
11. **教程** `docs/help/sent-log.md`（中英）：通用写法「你可以让工坊把每一条也写进你自己的在线表格（例如飞书、Google 表格）」，举一句交代的例子；不写任何一家的权限步骤（那一步由 AI 在配置时按需说）。

## 2. 飞书那边用户要做什么（AI 配置出错时会照这段说）

前提：这个品牌在「消息渠道」里已经接上了飞书应用（INMO 用我们自己的飞书、我们已有的应用，表也在我们自己的飞书里，所以没有跨公司的问题）。

1. **开权限**：飞书开放平台 → 打开那个应用 → 权限管理，开通
   - `bitable:app`（查看、评论、编辑和管理多维表格）
   - `sheets:spreadsheet`（查看、评论、编辑和管理电子表格）
   - 表放在知识库里的，再开 `wiki:wiki:readonly`
   开完**发布一个新版本**（企业可能要管理员审核）。
2. **把表共享给应用**：打开那张表 → 右上角「…」→「添加文档应用」→ 选这个应用，给「可编辑」。每张表做一次。
3. 回工坊在岗位里说一句，例如「以后每发一条 Reddit 回复都记到这张表（链接），列是 日期 / 版块 / 帖子链接 / 我们回复的内容 / 状态，日期写成 2026/10/14」→ 卡片流里点「记下」。

只能访问同一家公司飞书里的表（方案 A 的限制，docs/102 §5.3）。

## 3. 我自主做的决定（白话）

- 「发出去了」只认渠道真回了成功；没接渠道的「假发」和演练不记——所以 demo 里发出记录是空的（见决策 714）。
- AI 给的对照只能是「标准字段 / 固定值 / 留空」加三种简单格式；值从记录里直接取，不经模型（docs/29）。
- 写进表格的动作 / 状态 / 渠道默认写中文（回复、已发、Reddit），用户给了替换表就照用户的（见决策 711）。
- 写不进去时，之后新发的照样排进「待补写」，不丢；补写一次全写。
- 列对不上时不等人发现：自动重读表头、出一张新卡；没批之前停着。
- 改对照时，新卡没批之前老对照照用（不让记录断）。
- 记录去处在界面上只能停 / 开 / 删 / 补写；新建和改只能说一句（决定只在卡片流）。
- 「发出记录」面板放右栏「这一层」那组，品牌一份、不随岗位筛（见决策 716）。
