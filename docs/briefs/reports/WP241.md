## 1. 服务端「工作项」视图（先定、再动界面）

`GET /v1/positions/:id/work`（`getPositionWork`，`:id` 岗位模板 id 或本人分配 id 都认）→ `PositionWorkView`。
形状与规则一份、前后端同用：`packages/contracts/src/position-work.ts`；合并 / 挂卡的纯函数 `apps/server/src/position-work.ts`；
取数（归属规则）在 `positions.ts` 的 `work`，与 `instance` 同一套。

- **四类合一**：事项（本岗位，与页头「N 件在办」同口径）+ 本人待办（挂在本人这个岗位某条分配上）+ 本人定时任务 + 社媒排期
  （渠道 → 职责，只留本人在这个岗位做的那条）。**视图不是新对象**，每项 `kind + ref_id` 指回真那一行，这层没有写口。
- **统一字段**：标题、类型、所属职责（+ 本人那条分配）、分组（进行中 / 排着的 / 等别人 / 已完成）、原始状态、截止 / 下次时间、
  最近一句进展（摘要优先，否则时间线最后一句）、等你的卡数与卡 id、来源（你交的 / Agent / 定时 / 来信 / 会议）、最近更新、能不能拖。
- **挂卡口径 = 卡片流口径**：本人队列、这个岗位职责上、还没定、真是卡（与 `pending_cards` 同一个过滤）；事项按 `subject.matter_id`，
  待办按自己记的卡 id + 它挂的那件事项上的卡。所以「N 张卡等你」点过去卡片流一定翻得到。
- **看板拖动按现有状态机**：只有待办能拖（人是承诺人），在 进行中 / 等别人 / 已完成 之间拖 = `PUT /v1/todos/:id` 改 `doing / blocked / done`；
  「排着的」不收拖动（要给时间）。事项 / 定时 / 排期不许拖（状态由运行、调度、发帖结果推进），悬停说为什么。
- **截断**：已完成只带近 14 天；总数封顶 300，先保没做完的。系统例行定时（每日计划、复盘、巡检）不进工作，只在设置里列。
- **#73 核对**：WP234 现状已经是「跟着职责走」（事项按 `role_id` 改岗位；待办 / 定时本来挂分配，安放改了就跟着走），端到端测试钉住，代码不用改。

## 3. 与设计稿的偏差

1. **「自家版待处理」快捷视图没有**：产品里还没有「社群待处理队列」（入群申请 / 被举报帖 / 新帖待审）这个组件与数据，
   社群类职责的快捷视图先放现有的「群发」向导（`SocialBroadcast`）。要做得另开一单（见要定的事 3）。
2. **事项没有截止**：契约里事项没有截止时间，列表 / 表格那一格是「—」；设计稿里事项带「今天 18:00」是编的。
3. **表格没有「花费积分」列**：工作项里没有按事项累计的积分（要接计量）；列可选里先不放。
4. **职责行没有「用这条开」按钮**：设置 · 职责每行是「去职责页」（职责页上就有用这条职责开），岗位页上「指定职责开」挪进了
   「交给它」展开后的「职责：自动 / 某条」。加减 / 合并 / 移动 / 拆出的入口都落到公司页岗位卡（只有负责人能改，规则在那边）。
5. **设置 · 定时任务没有每条的「上次成功」状态图标与积分上限**：现有接口给的是 `last_result` 文字，没有逐次结果状态；照实列频率、下次、开关。
6. **高级里没有「运行上限」那一行**：运行上限在「设置 · 运行上限」（WP236）那一页，这里不重复。
7. **演示世界里「Reddit 运营」没有卡**：stub 运行时对 Reddit 没剧本，截图里这个岗位的卡片流是「队列清空了」；另拍了演示世界原样里卡最多的岗位
   （`demo-cards-*`、`demo-jump-to-card`）看卡片流 + 「N 张卡等你」怎么接。
8. **数据看板涨跌**：只在积木数据带 `delta_pct` 时出；Reddit 那两条职责在演示里没有数字块（取数走接口中台、没有 `stat_tile`），所以那一行是数据源状态。
9. **空岗位截图没有缺连接横幅**：演示里 `social.reddit` 的 Reddit 连接是 `required: false`，不真缺就不出；横幅由测试钉住。
