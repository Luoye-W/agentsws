## 1 一句话

`@agentsws/ads-core` 多了一个「上传表」模块：上游只说要改什么（新建系列 / 组 / 广告 / 关键词、改预算、暂停启用），它出 **Google 批量上传 CSV**（一层一张，按上传顺序）或 **Meta 批量导入表**（.xlsx + 可粘贴文字，新建与改已有分两张），出表前在本机查一遍（字数、必填、编号、禁用词、预算额度、日花费总闸），出表后再按**表里的行**复查「新建都是暂停」，附审批卡用的一句白话 + 预览行 + 表指纹 + 「开始投放」要启用的清单；另能解析两家导出文件（含 Meta 的 `< >` 前缀）、做读回核对、出 Google Ads Editor 用的 CSV 与列名对照。全是纯函数，没有 IO，插件 / 桌面端 / 云端都能跑。

## 3 公开函数与类型（给 WP313 / WP316 / WP317）

都从 `@agentsws/ads-core` 导出。

**意图（上游写这个）**：`AdSheetOp` = `CreateCampaignOp | CreateAdGroupOp | CreateAdOp | AddKeywordOp | SetBudgetOp | SetStatusOp`。平台无关的格子 + `google?` / `meta?` 各自的格子；状态没有口子可写（新建一律暂停）。Meta 的广告组（Ad Set）统一叫 `ad_group`。改已有对象用 `ref: AdEntityRef`（名字 + 编号）。

**WP317 素材流水线**：把子 Agent 出的标题 / 描述（Google）或正文 / 标题（Meta）拼成 `create_ad`，调

```ts
buildAdUploadBundle({ platform: 'google' | 'meta', ops, before?, context? }): AdUploadBundle
```

- `ok` 为假时 `files` 为空，`problems: SheetProblem[]`（`severity` / `code` / `op_index` / `field` / `message` 白话）直接给人或模型看着改；`warning` 照出表、上卡面。
- `files: AdUploadFile[]`：`name` / `mime` / `content`（CSV 字符串或 .xlsx 字节）/ `sheet` / `upload_from`（在后台哪里传，一句白话）/ `headers` / `rows`；Meta 的还有 `paste_text`。docs/101 §5.1④ 说「② 没好之前用户下载这张表自己传」——给人下载的就是这些文件。
- `summary: SheetSummary`（`sentence` 一句话、`counts`、`rows` 预览行：新建 / 改预算 / 暂停 / 启用 + 改前改后）。
- `approval_level: 'L1'`、`fingerprint`（SHA-256 十六进制）、`activation_ops: SetStatusOp[]`（「开始投放」那张 L1 卡要启用的东西，决策 553）。
- `context: SheetContext`：`caps`、`allow_over_cap`（这张就是「超额提预算」L1 卡时才给）、`spend_today_by_platform`（给了就按岗位级总闸再判）、`currency_symbol`、`banned_terms`（品牌禁用词）、`customer_id`。
- 只想先查不出表：`validateAdSheetOps(platform, ops, ctx)`；Google 字数用 `googleTextLength`（中日韩字算 2）；上限常量 `GOOGLE_RSA_LIMITS` / `META_COPY_LIMITS`。

**WP313 插件动作通道**：

- 审批绑定：卡上存 `bundle.fingerprint`；插件拿到文件后用 `bundleFingerprint(files)` 重算，对不上就拒绝上传。算法是同步纯 TS（不用 WebCrypto、不用 `node:crypto`），浏览器里算出来一样。
- 上传：Google 按 `files` 的顺序逐张在 `upload_from` 写的那张表上传；Meta 优先 `paste_text`（「批量导入广告 → 复制粘贴」），也可传 .xlsx；`meta_new` 与 `meta_edit` **分两次导入**。
- 改前快照 / 读回：插件下载的导出文件 → `decodeExportBytes(bytes)` → `parseAdsExport(text)` → `ParsedAdsExport`；改前那份交给 `buildAdUploadBundle({ before })`（Meta 改已有要它）；改后那份交给 `readBackCheck(ops, after)`（`ReadBackReport`：逐条 ok / mismatch / missing / unverifiable + 一句话）；「开始投放」前用 `attachIdsFromExport(activation_ops, after)` 补上平台给的编号。
- 走表还是直接点（决策 552）：`routeAdChange(ops)` → `{ route: 'sheet' | 'form', reason }`（有新建或 ≥ 3 条走表，`SHEET_THRESHOLD = 3`）。

**WP315 看数据**：`parseAdsExport` + `exportEntities(parsed)` → `ExportEntity[]`（层级、名字、编号、状态、预算、`metrics.cost / impressions / clicks / conversions / conversion_value`；Meta 一行拆三层、指标只记最细一层、按天拆的行会累加）。`parseExportNumber` 把 `--` 当「没数」不当 0。

**其他**：`buildGoogleEditorCsv(ops)`、`GOOGLE_EDITOR_COLUMN_MAP`（决策 561 帮助文档用）；`GOOGLE_BULK_COLUMNS` / `META_COLUMNS`（列名唯一一份，改列名只改这里）；`checkNewRowsPaused(files)`。

## 5 自主做的决定（白话）

- **一层一张 Google 表**：Google 是在哪张表上点上传就传哪一层，所以分开出、按系列 → 组 → 广告 → 关键词的顺序。全空的列不出（没改的列 Google 本来就忽略，少一列就少一个没核实的列名）。
- **Meta 新建与改已有分两张**：Meta 编号空着就当新建，混在一张里一旦漏填编号就多出一套广告。改已有那张照官方「导出 → 在原行改 → 导入」：给了改前导出就用原行原列只改那一格。
- **「新建一律暂停」查两遍**：op 里不给写状态的口子；出表后再按表里的行查一遍（`checkNewRowsPaused`），以后谁改了生成器这道还在。Google 新建的组 / 广告 / 关键词也逐个写暂停（553 原文「一律」）。
- **超额度预算默认拦**：超 docs/57 的 20% 是 error；只有调用方明说这张就是「超额提预算」L1 卡（`allow_over_cap`）才降为提醒。日花费总闸只算正在跑的预算往上提的那一截，新建（暂停）不算。
- **文案**：`AD_COPY_FORBIDDEN`（与 guardrail 同一份）和品牌禁用词拦；客服那套「承诺扫描」只提醒（「免费退换」这类广告里常见）。Google 超字数拦（平台会拒），Meta 超建议字数只提醒（平台折叠不拒）。Google 的格子以 `=` / `@` 开头拦（表格软件当公式）；Meta 照它自己导出的写法加 `< >`。
- **自己写 SHA-256、.xlsx、CSV，不加依赖**：本包要在插件里跑，`node:crypto` / `node:zlib` 用不了；锁文件没动。
- **不读 .xlsx 导出**：解析只认 CSV / 制表符文字（两家都能导出 CSV），读 xlsx 要解压缩，第一期用不上。
- **改已有要编号**：Meta 一律要（没编号 = 新建）；Google 改广告系列 / 广告要（帮助页写着 Campaign ID 必填），改广告组只提醒（Google 认名字）。Meta 在已有上级下新建，上级也要带编号。
