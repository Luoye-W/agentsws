## 2 我自主做的决定（白话）

1. **「近 7 天」不从今天往回数**。Search Console 的日子按美国太平洋时间算，最近两三天的数还没定稿。先探一次"最近一个有数的完整日"，以它为终点取 7 天、再往前 7 天——两段一样长、都定稿了。否则这一周里夹着两三个空日子，每个词都会被判成"在掉"。
2. **上周那一份没翻完就不填 0**。本周有、上周没出现的那一对：上周的行全拿回来了，就是真的 0 次点击；行数撞到上限没拿全，就不知道——不写（契约原本就这么要求）。
3. **GA4 只看自然搜索来的会话**。这张表回答的是"搜索带来的人买没买"；广告和邮件带来的会话混进来，转化率就不是这个问题的答案了。GA4 问的是和 Search Console **同一周**，好让点击和会话对得上。
4. **转化 = GA4 的购买（ecommercePurchases）÷ 会话**；关键事件另记一列（面板上没摆出来，卡的 payload 里有）。**收入以 Shopify 落地页为准**，GA4 那列叫「GA4 口径收入」，卡上一句话写明两边对不上是常态。
5. **只有一个站点 / 媒体资源就自动选上，不问**；两个以上才出"选一下"。选了立刻重读，并重出今天的 5 件事（换 GA4 只影响周收入表，不为它重出每日卡）。
6. **网址检查每天只查曝光最多的 10 页**（每站点每天 2 000 次额度，留足余量），查到"在跳转 / 规范网址不对 / 没收录"就走 WP154 的"交建站"车道；一页查不到就不写那一格，撞到配额就停。
7. **页面标题 Search Console 不给**：不去编，"有没有专门写这个词的页"没有标题时按网址里的 handle 比（Shopify 的 handle 就是标题转出来的）。
8. **缓存按天、只在内存**：同一天面板怎么刷新都不再打上游；配额用尽当天不重试，其它失败 30 分钟后才再试。选择（站点 / 媒体资源）落在品牌目录，换了 Google 连接就当没选（那个站点是上一个账号的）。
9. **令牌守卫做成两层**：我们手里本来就只有 OpenConnector 的执行令牌、没有 Google 的令牌；上游报错原话进事件 / 卡之前再抹一遍（执行令牌原样、`Bearer …`、`ya29.…`、`1//…`、`token=…`）。
10. GA4 的三个数字块（活跃用户、转化率）固定显示"读回来的那一周 vs 前一周"，不跟着面板上的"昨天 / 近 7 天 / 近 30 天"切换走（GA4 那一侧每天只读一周）。

## 3 需要 Luoye 定的事

1. **授权范围**：OpenConnector v1.6.5 这两家的 OAuth 会**同时申请只读和读写两个 scope**（`webmasters` / `analytics.edit`），它没有"只要只读"的开关。我们这边只签得出读口的令牌、写口一条都调不动，但 Google 授权页上用户会看到"管理"字样。三条路：a 就这样（教程 FAQ 已写一句解释）；b 给上游提一个"只读授权"选项（`authorizationOptions`，改动不大）；c 引导用服务账号（同样两个 scope）。我倾向 a + b。
2. **GA4 只算自然搜索会话**对吗？还是要全部会话？
3. **谁能选站点**：选择器挂在 `content` 域下，现在只有「内容与搜索」能选；数据分析（`dtc.analytics`）那条职责看得到 GSC / GA4 的数，但选不了。要不要也给它？
4. **页面标题**：现在按网址 handle 猜"有没有专门页"。要不要下一单从 Shopify 读页面 / 文章 / 商品标题（`update_page` 那几条的读侧已有）？读了之后"没专门页"会更准，改标题的机械第一稿也能用上真标题。
5. **open-seo 移植**：派工中途收到"可以移植 every-app/open-seo（MIT）的 GSC / GA4 客户端几段"。我用 `gh api` 读它的源文件时被本机的权限分类器拦下（判为"不受信代码引入"），所以**一行都没搬**，全部自己写；也没改 NOTICE / upstreams.yml。另外它的 `gscClient` 是直接拿用户令牌打 Google HTTP，而我们走 OpenConnector 的只读 Action、令牌不经我们的进程，架构上本来也接不上；能借的只有"GA4 取到三天前"这类公开事实（我们用的是与 GSC 同一周，效果相同）。要不要放开这条权限再对照一次，你定。
