# WP337 报告：有任务在跑时点「重启并更新」——三选一，暂停的新版起来自动接着做

分支 `wp/337-updatewait`（worktree `../agentsws-wt/wp337-updatewait`），派工单 `docs/briefs/WP337-update-with-running-tasks.md`。按派工单许可 push 了这个分支跑 `desktop-windows.yml`；没合 main、没打 tag、没发版。决策号 818–822。

## 0 一句话

点「重启并更新」→ 壳先问服务进程「在做什么」→ 没事直接重启；有事弹一句「还有 N 件在做」+ 三个按钮（现在重启 / 空闲时重启 / 稍后），清单折着、点「看看是哪些」才展开。选了重启：正在输出的停在安全点（已说的话、取回的数据都留在时间线上，记「因更新暂停」）、后台与定时挂起、落盘 → 新版开机读回（先删再做，只一次）→ 正在输出的自动「接着跑」、被打断 / 错过的后台与定时补一次。

截图：`docs/assets/wp337/restart-dialog.png`（折着）、`restart-dialog-list.png`（展开清单）、`waiting-button.png`（「等空闲后重启」）。

## 1 三类任务怎么暂停 / 恢复

| 类 | 算「在做」的口径 | 暂停 | 恢复（新版开机） |
|---|---|---|---|
| ① 正在输出（岗位 AI 正在跑的运行，所有已装起来的品牌） | 每一次在跑的运行 | `runtime.pauseRun`：在安全点中断（与「停」同一条路），已经说的话、取回的数据作为部分结果挂上；时间线那一句换成「因更新暂停：已经做到的在下面，新版打开后自动接着做。」（没出结果的：「…新版打开后自动重新做。」），运行摘要那一行是「因更新暂停」；最多等 10 秒收尾 | 按**同一个人、同一条分配**起一次运行（`work.run`），交给它的话与事项页「接着跑」同一段（「接着上次没跑完的继续：已经查到的在上面，别重复取…」）；会话引用在，能从断点续。时间线先记一句「更新好了，接着做」。同一件事好几次在跑只接最近那一次 |
| ② 后台作业（系统巡检：收信、对账、备份、计划 / 复盘…，`HANDLERS` 里那些） | 只算**正在跑**的（它们一直排着，不算） | 调度器 `hold`：到点也不动、不挪排期；正在跑的等它收尾（最多 10 秒） | 新进程照常跑；暂停时没等到收尾的那几条清掉上一版的租约、补跑一次 |
| ③ 定时任务（人建的定时与官方「自动化任务」） | 正在跑的，或 **15 分钟内**要到点的（含已过点没跑的） | 同上（`hold`） | 暂停期间错过的：`run_once_now`（人建的默认、自动化任务都是）由调度器第一拍补一次；`skip` 的（系统巡检默认）这里补一次——只补落在这次暂停窗口里的 |

- 落盘：`<数据目录>/update-pause.json`（暂停时刻、要更新到哪版、被停下的运行〔事项 / 人 / 分配〕、没等到收尾的任务 id）。新版开机**先删再做**：中途再崩也不会恢复第二遍。读不懂就跳过、删掉，不挡开机。
- **做不到无缝续接的，照实说**：事项没了 / 交接中 → 时间线补一句「更新前停下的这件事没能自动接着做，点「接着跑」继续」（按钮照旧在）；运行 10 秒内没停下来、进程就被换掉的 → 开机自检（WP319）照旧记「没跑成…点重试」，同时这里照样「接着跑」一次。
- **没重启成**（安装程序没起来）：壳调 `POST /v1/update/resume`，在原进程里放开调度器、把停下的运行接着做、删掉记录。自检没过时根本还没暂停。
- 「空闲时重启」：按钮变「等空闲后重启」（托盘同一项「等空闲后重启（点了取消）」），每 5 秒问一次；**空闲 = 没有正在输出的运行**；到空闲那一刻再暂停后台与定时、然后重启。点一下取消回到「重启并更新」。
- 官方场景（dsh 网页）问不到里面在不在做事：照 WP184 规矩算一件（清单里写「官方场景（重启会关掉）」），暂停不了，重启照旧关掉它。

**两条路都接上了**：
- **Windows**（WP327 只切换 / 老的安装程序路）：暂停在 `restartNow` 里、切换 / 装之前；更新小窗照旧（`beginUpdate` 不动）；回滚到旧版时旧版开机同样读回接着做（CI B 段就是这样）。
- **Mac**（只提示 → 用户自己退出、装）：点过「去下载」（工作台按钮或托盘）之后退出 → 有正在输出的就原生三选一「现在退出 / 空闲时退出 / 稍后」，没有就直接退；退之前暂停全部、落盘；装好新版打开后自动接着做。普通退出（没点过去下载）不变。

## 3 自主做的决定（白话）

1. 弹窗做在工作台里（能折叠清单、能截图），托盘点的 / 旧页面点的走原生框（原生框不能折叠，就直接列 6 行、列不下说「…还有 N 件」）。
2. 「定时任务」只把 15 分钟内要到点的算「在做」：不然几乎每个人都永远「有任务」，弹窗就成了噪音；远的那些重启几秒根本碰不到。后台巡检同理只算正在跑的。
3. 暂停失败（服务没回）不拦重启：最坏就是老样子（时间线「没跑成」+ 重试）。
4. 「空闲时重启」没有等待上限，随时可取消。
5. 「接着做」用 `work.run` 不用「在事项里说一句」：时间线上不伪造一条人话，只记「更新好了，接着做」。
6. 暂停窗口里错过的 `skip` 任务也补一次（备份这类一天一次的不该因为更新丢一天）；关机错过的仍按原规矩跳过。
7. 新路由给「策略层」权限（owner / 管理员）：清单跨品牌列事项名，只给看得到全公司的人；桌面壳的会话就是本机 owner。
8. `RunCancelReason` 契约没加新值（停的原因仍是 `user`）：「因更新」只体现在时间线文字上，契约只加不删、少动。

## 4 要 Luoye 定的事（决策 818–822）

| # | 事情 | 建议 |
|---|---|---|
| 818 | 第三个按钮：原话「三个选项、列了两个」，按 **「稍后」= 关框、什么都不动** 做了；「空闲时重启」没有等待上限、随时可取消 | 建议同意 |
| 819 | 「在做」的口径：正在输出 = 每次在跑的运行；后台 = 系统巡检**正在跑**的；定时 = 人建 / 自动化**正在跑或 15 分钟内要到点**的。只有这些才弹窗 | 建议同意（15 分钟可调） |
| 820 | 暂停期间错过的定时：`run_once_now` 的补一次（原规矩），`skip` 的（系统巡检，如每天备份）**这次也补一次**（只限暂停窗口内） | 建议同意 |
| 821 | Mac：只有**点过「去下载」之后**退出才三选一（现在退出 / 空闲时退出 / 稍后）并暂停全部；普通退出照旧不问不停。要不要所有退出都「暂停 → 下次打开接着做」 | 建议先只管更新这一种；普通退出另议 |
| 822 | 暂停不了、重启照旧打断的：官方场景（dsh 网页，弹窗里算一件、写「重启会关掉」）、平台 CLI 安装 / 店铺授权这类进程内一次性作业（人点的、几十秒）；广告浏览器动作队列本来就落盘、重启后自己接着跑，没算进清单 | 建议先这样；以后哪类常撞上再接 |
