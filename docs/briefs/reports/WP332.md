## 1. 做了什么（白话）

### ① 决策 762：没发出去 → 岗位页提醒 +「再填一次」

- Reddit 那一条（回复 / 回帖 / 发帖，来源不论是 WP329 的「发出去」卡、社媒回帖卡还是公关外部帖）交给插件后**没发出去**——等不到人点、点了停止、没登录、被 Reddit 拦、24 小时没插件来领——社媒岗位页顶上出**一行**：「没发出去：回复 maple_tree（Reddit · r/bluelamp）· 你点了停止，已停下。」右边「再填一次」和一个 ✕（收起）。原因就是插件回来的那一句，照实。
- **再填一次**：把同一份已批的草稿（写到哪 + 批过的正文 / 标题）原样交给插件，是动作通道里**新的一件活**，挂在同一张卡上；**不出新卡、不用重批**，人照样自己点发送。发出去了照常记发出记录、回写来源（WP328 条目「回过了」、社媒线程「已回」、公关帖「已发」）。
- **出现规则（docs/96 提醒条）**：只在出问题时出（排着 / 填好等你点 / 发出去了都不出）；同一条写只一行（再填不另起一行）；收起之后不再出，再填一次又没发出去会重新出；七天前的不出（进度里还在）；最多三行，再多写「还有 N 条」。
- 插件不在线时点「再填一次」也行：照样排着，那一行进度写「插件不在线，等你打开 Chrome」（761 关着，不走程序直发）。
- 帮助文档 `docs/help/browser-extension(.en).md` 加了一条。

### ② 公关「在别人帖子下回评论」带上被回那条评论的链接

- 公关提外部回帖（`POST /v1/pr/posts`，`kind: comment`，`parent_external_id: t1_…`）时，**出卡前**找那条评论的链接，按顺序：调用方给的 `parent_permalink`（新加，只加）→ WP328 巡查条目里的 `url` → 社群线程的 `permalink` → 公关提及的 `url` → **补读**：知道它在哪个帖子下（调用方给的是帖子链接，或巡查条目记着帖子）就读那个帖子的评论、按编号找到它（走 `read_reddit` 同一条只读取数路由）。
- 找到 → 帖子记下 `parent_permalink`，卡的 `after` 带 `parent_permalink` / `parent_url`，卡上（发布版式）多一个小字「原评论 ↗」；批了插件走**楼中楼**（打开那条评论、点 reply、填进它的回复框），发出记录带被回那条的链接。
- 找不到 → **不出卡**，稿子留着（草稿），回一句「没出卡：找不到被回那条评论的链接，插件找不到回复框（原因）。稿子留着；从巡查的待处理里点那一条重新起草。」
- 回帖子（`t3_`）、发新帖、别的平台不受影响。WP329 留下的老卡（库里没链接的）批了照实失败、不交给插件。

## 3. 我自主做的决定（白话）

1. **再填一次挂在同一张卡上、同一行进度里**：不出新卡、不改卡的状态（卡在交给插件那一刻已记「已施行」，WP329 定的）；进度换成新那件活的编号，老那件的迟到消息不认。
2. **能再填的条件**：没发出去 + 走插件那条路 + 记着草稿。WP332 之前就没发出去的老进度没记草稿，只能收起（见 784）。
3. **次数不限**：每次都要人自己点发送，重复填不会自己发出去；提醒只留七天。
4. **提醒条用担「Reddit」那条社媒职责的分配去问**（没有就用任一条社媒职责）；只有公关职责的岗位不出（见 781）。
5. **找链接先查本机已有的，最后才补读**：补读花的是 `read_reddit` 那条路由（接口中台按条计积分 / 只读浏览器限速），所以放最后、一次最多 100 条（见 782）。
6. **补不到时稿子留成草稿**而不是丢掉：人从巡查待处理里重新起草，或补一条链接再提。
7. **没加「保护字段」**：批卡时改 `after.parent_permalink` 没用——执行器按库里那条帖子的链接走，不读卡上那一格。
8. **截图**：只拍了岗位页提醒条（社媒运营岗位，替身插件回「你点了停止」），并在同一趟里点「再填一次」确认那一行收起。
