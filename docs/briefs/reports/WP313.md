## 1. 做了什么

### ① 公共执行模块 `packages/browser-action`（新包，`@agentsws/browser-action`）

把 Reddit 官方号通道（WP249）的规矩抽出来，插件与本机服务共用（纯逻辑，没有一个 `node:`）：

| 文件 | 管什么 |
|---|---|
| `types.ts` | 一件活的形状：步骤表（`goto / click / fill / wait / upload / paste / capture / download / read / expect_none / confirm`）、白名单、读回、审批编号、上传表引用、被允许进的区域 |
| `guard.ts` | 驱动层白名单 `checkStep`：按**动作种类**放行打开 / 点击 / 填写 / 上传框 / 导出按钮，填的字只能是卡上的；话术与 Reddit 原来一字不差 |
| `zones.ts` | 557 的十个「默认不碰」区域（付款 / 账单 / 余额 / 用户与权限 / 商务设置 / 验证 / 申诉 / 新建账户 / 像素与转化 / 删除系列）；网址认区域（窄的先认）、页面闸 `zoneGate`、进队闸 `allowedZonesFor`（没放开不进队；放开了也要 L1） |
| `pace.ts` | 555：同一账户一次一件、每账户每天写 ≤ 20、读 ≤ 2；两步之间固定 1.5 秒。**没有随机数**（测试钉住 `Math.random` 没被调） |
| `queue.ts` | 558：排队、领活、24 小时没人领作废、领走 45 分钟没音讯记失败（**不自动重跑**）、停、确认 |
| `fingerprint.ts` | 上传表指纹 `sha256:<hex>`（WebCrypto，插件与 Node 同一份） |
| `walls.ts` / `dom.ts` | 被拦了没有（验证码 / 登录 / 受限）；页面里的「手」（选择器只认唯一一个、`>> text=` 要完全相等；原生 setter 填值；DataTransfer 放文件） |
| `runner.ts` | 执行器 `runAction`：每步先看停没停、过白名单、看当前页还在不在后台 / 进没进不碰的区域；上传前再算指纹；平台报阻断错误退回；人不点头退回；做完读回自证。不重试、不换路 |
| `ads/*` | Google / Meta 两家的步骤表：上传表（改前快照 → 上传 / 粘贴 → 平台预览 → 截图 → 没报错 → **人再确认** → 应用 / 发布 → 截图 → 读回）、导出报表、暂停、启用、改预算。选择器全在一张表里，**按英文界面写、没对真站核过** |
| `protocol.ts` / `evidence.ts` | 插件 ↔ 本机的线上形状；截图存储接口（180 天） |

Reddit 通道的 `stepAllowed` 改用公共 `checkStep`（行为不变：wp249 单测 + 本机 Chrome × 假 old.reddit 实测 13 项全过）。

### ② 本机服务（`packages/api` + `apps/server/src/ads-actions/`）

- 插件令牌加 scope `ads.act`（只加；新配对才有，老令牌要重新配一次）。`hello` 改成照令牌上真有的 scope 说。
- 插件这一侧（令牌 + Origin，同 `/v1/extension/*` 那道闸）：`GET /v1/extension/actions/next`（长轮询，最多挂 25 秒；急停 outbound 时 503）、`…/:id/sheet`、`…/:id/progress`（回执带「工作台点了停」「卡上点了确认」）、`…/:id/evidence`（只收 PNG）、`…/:id/download`、`…/:id/result`、`POST /v1/extension/ads-consent`（562）。
- 工作台这一侧：`GET /v1/ads-actions/settings`、`PUT /v1/ads-actions/zones/:zone`、`POST /v1/ads-actions/consent/:platform/revoke`、`GET /v1/ads-actions/jobs`、`POST …/jobs/:id/stop`、`POST …/jobs/:id/confirm`（急停时 503）。
- **进队没有 HTTP 入口**：只有端口方法 `ExtensionActionsPort.enqueue`，给审批执行器调（WP316 接线）。测试钉住路由清单里没有「往队里塞活」的那一条。
- 每品牌一份 `createAdsActionsService`：落 `<品牌目录>/ads-actions/state.json`（排队 + 节奏 + 开关 + 同意 + 下载记录）、`sheets/<件>.bin`（做完就删）、`evidence/<年-月>/<id>.png` + `index.jsonl`（180 天，到期按索引点名删）。十分钟扫一次（作废 / 断了 / 截图过期）。托管实例不装。

### ③ 插件（`apps/extension`）

- 改名「Agents 工坊助手」（551）：清单、设置页、面板标题、商店材料、工作台与官网文案。安装包文件名没改（见决策 602）。
- 权限：加 `scripting`（无警告）；**可选**：`ads.google.com`、`adsmanager.facebook.com`、`business.facebook.com`、`downloads`——装 / 升级都不弹，设置页点「连接」才申请。
- 领活：每分钟一次长轮询；没配对 / 没连后台不问；整个插件一次一件；问到就找（或开）一个**看得见的**后台标签页去做。
- 页面脚本 `ads.content.ts` 运行时注入、不进清单（WXT 的 runtime 注册如果写 `matches` 会被自动塞进必需权限，所以没写）。
- 顶上横条：「AI 正在操作 · 3/7 · 打开页面　停止」；等确认时「确认提交 / 不提交」。等页面、等授权截图、等下载时点停止都停得住。
- 截图：只截正在执行的后台标签页，截之前横条先藏；截图 / 下载登记交不上去就不往下做（留不下证据的改动不做）。
- 设置页「广告后台」一节：一家一行（已连接 / 未连接 / 待同意 + 按钮），一句风险告知勾了才能连（文案占位，正式的在 WP318）。

### ④ 工作台

连接页「浏览器插件」一节下加「广告动作」：十个「默认不碰」开关（全部默认关，说明在问号里）、两家后台连没连（能断开）、最近 5 件活（在跑的能停、等确认的能在这里「确认提交」）。本机没装通道就整块不出。

## 2. 实测发现（docs/101 §7 第 9 条那两件）

真 Chromium + 本机假后台（`scripts/e2e-ext-actions.mjs`，13 项全过）：

1. **DataTransfer 放文件能用**：页面收到的就是批过的那份字节。（真站上两家后台认不认，仍要首跑核。）
2. **`captureVisibleTab` 只凭站点权限截不了**（对照实验：加 `<all_urls>` 立刻能截，不是无界面模式的问题）。而 `activeTab` 只在用户「调用插件」时给——**页面里横条上的点击不算**。docs/101 §1.4 设想的「点一下横条自然拿到 activeTab」不成立。现在的做法：截不到时横条请人「点右上角插件图标，允许截图」，点了再截；10 分钟没点就停下交给人。见决策 600。
3. `chrome.downloads` 能拿到导出文件的路径；MV3 长轮询、运行时注入、换页后重新放脚本都正常；验证码页认得出、停下交给人。

## 3. 与 WP314 / WP316 的对接口

**WP314（上传表）**
- 表就是一份字节 + 名字 + MIME。指纹用 `sheetFingerprint(bytes)`（`@agentsws/browser-action`），对**原样字节**算：文字表 UTF-8、不加 BOM、不改换行。审批卡绑 `SheetRef { name, mime, fingerprint, bytes }`。
- MIME 决定 Meta 那边粘贴还是传文件：`text/*` 或 `.csv/.tsv/.txt` → 粘贴；Excel → 传文件。Google 一律传文件。
- 导出文件：插件只报「下到了哪」（`ActionDownloadInput { tag: snapshot | report | result, path, name, bytes? }`，服务端 `downloads(id)` 取），解析交给 WP314 的解析器 / WP315 读文件。
- 平台预览读回的字在结局的 `reads.preview_summary`、`reads.platform_errors`（给 WP314 的读回核对用）。

**WP316（接线）**
- 拼活：`buildAdsJob({ id, workspace_id, account, action, approval_id, approval_level, title?, created_at })`；`action` 是 `upload_sheet / export_report / pause / enable / set_budget`（553 的「激活」= `enable`，L1 由审批那一侧定）。
- 进队：`deps.extensionActions.enqueue({ job, sheet_bytes })` → `{ ok, job }` 或 `{ ok: false, why }`（没审批编号、指纹对不上、要进没放开的区域、放开了但不是 L1，都在这里拒）。
- 事件：`createAdsActionsService({ onEvent })` 回 `expired`（重出卡）、`finished`（记变更账本）、`evidence`（截图 id 挂到账本那一条上）、`download`。**`server.ts` 里还没接 `onEvent`**——留给 WP316。
- 截图存储：`ActionEvidenceStore`（`put / list / read / prune`），本机按文件存 180 天；同步规则跟账本走在 WP316。
- 再确认：卡上「确认提交」= `POST /v1/ads-actions/jobs/:id/confirm`（或端口 `confirm`）；停 = `…/stop`。
- 磨合期（554）、撤销卡、技能禁用词那一条都在 WP316。撤销的步骤表（Google「批量操作 → 撤销」）本单没写。

## 4. 自主做的决定（白话）

1. **公共模块单开一个包**，不塞进 `contracts` 或 `ads-core`：插件要打包它，不想把整份契约拖进插件；`ads-core` 是 WP314 的主场。
2. **进队不给 HTTP 口子**：只有审批执行器能进队，「没过审批的活」在协议层就没入口。
3. **开始就记一次数**：领走那一刻占住账户、记一次；做到一半被停也算（后台里已经动过了）。改前快照的导出算在那件写操作里，不另算一次「读」。
4. **断了不自动重做**：领走 45 分钟没音讯记「没做成」交给人——写操作做了一半，再跑一遍可能改两次。
5. **截图 / 下载登记交不上去就停**：留不下证据的改动不做（556）。
6. **同意在插件里勾、工作台只能看和断开**：勾的那一页有告知原文；文案版本号 `2026-10-14.1` 放在公共模块，插件和本机共用，WP318 改文案时升号、老同意失效。
7. **十个开关在工作台、不在插件**：插件令牌不该能给自己放权。
8. **区域认网址宁可多拦**：认错了最多是停下交给人；「删除系列」不是页面，靠计划里写 `zones` 管。
9. **测试里的假后台用真站的网址写**（只在 jsdom 里渲染，一个请求都不发），这样「默认不碰」的网址规则也能在执行器里走一遍；真浏览器那一套用 127.0.0.1。
