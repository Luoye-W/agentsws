# WP230 报告：模型把「[calling …]」当文字吐出来

分支 `wp/230-calltext`（worktree `agentsws-wt/wp230-calltext`），Claude 子代理。

## 0. 一句话

根因与 Fable 的判断一致：`dsh-adapter/src/llm.ts` 与 `runtime-direct/src/runtime.ts` 回放历史时，assistant 消息里的工具调用**既**是结构化 `tool_calls`，**又**在 content 里写一行 `[calling 名字 参数]`——全仓只有这两处在写这行字。两处都改成 content 只留模型自己的话；另加兜底：最后一轮没有真工具调用、文字却像在调工具，就追加一句提示重试一次，还这样就照实报「模型输出格式异常」。

## 2. 自主做的决定（白话）

1. **提示语用 user 角色发，不用 system**。dsh 那一侧往会话里追加只能走 `followup`（user 消息）；Messages 口会把所有 system 抽到最前面，提示就离开了「紧跟在那段假文字后面」的位置。两个运行时统一用 user，开头写「（系统提示）」。送进网关的形状两边一致（测试钉住）。
2. **重试那一轮把模型自己写的假文字留在历史里**，紧跟提示——模型要知道「你刚才那样不对」指的是什么。这是模型自己说的话，不是我们代写的。
3. **只调工具时出线发 `null` 而不是空串**。DeepSeek 两种都收；OpenAI 规范与各家自己的回复都是 `null`，有的兼容口会把空串当「空内容」拒掉。Messages 口不变（空串本来就不发 text 块）。
4. **仍异常时按「失败」收尾**：`run.failed`（`provider_error`，`retryable: true`，原话「模型输出格式异常」），摘要走 `describeRun({ failed })` 那一句，三处同一份文案。已经真做成的事（例如之前已经起草出的卡）不撤回，只是不再拿假文字出答案 / 出卡。
5. **假文字不进 `text.delta`**，改成一条 `progress{step: 'tool_call_text', note: 'retry'}` 留痕（Model-visible ⟺ logged）。
6. **stub 不改**：它不经模型，答案是模板，碰不到这种情况；「三条一致」落在判定、提示语、失败文案都从 `@agentsws/stand-ins` 同一份读。
7. **事项时间线**：时间线上本来就没有单独的「工具调用」展示，Fable 看到的「[calling 「规矩与政策库」 …]」就是那段假文字被当成 Agent 的回复贴上来、再经 WP153 的工具名换人话。从源头断掉之后，给人看的「用过哪些工具」只剩摘要那一路（`describeRun` 按真读成功的工具拼，结构化来源）。服务端没再加一道过滤——只有这三个运行时产出 `answer`，两个经模型的都已兜住；端到端测试钉住时间线。
8. 查过别处有没有依赖这行字：摘要、记忆、事项时间线、审计、回放、缓存键（静态前缀只看 system 段）、规则脑（跳过 assistant 消息）——都没有；全仓写这行字的只有那两处。
