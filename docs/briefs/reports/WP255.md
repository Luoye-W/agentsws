## 0. 一句话

「自家版待处理」每一条、社群线程列表每一条都多了一个「**回复**」：点开一个小输入框，可以先点「AI 起草」（没接模型就给一句开头并照实说「这次没用 AI」），人改完点「出卡」——走 WP254 的 `POST /v1/social/threads/:id/reply` 出一张回帖卡进卡片流，**不直接发**；带承诺的话被打回时，原因就地显示在框里。上游名单登记了安装包自带的 **Node 22.23.2** 与 **npm 10.9.8**，`check-upstreams` 逐字对账 `node-runtime.lock.json`，docs/42 补了「Node 出安全版时连 npm 一起升」那一节。

## 2. 我自主做的决定（白话）

1. **线程列表是新做的**：工单说「社群线程列表每一条」，但工作台里原来没有这张列表（只有服务端接口）。我按「自家版待处理」同样的样子新加了一个快捷视图「群里的帖子」，社群组五条职责各有一个，放在「群发 / 自家版待处理」后面。
2. **自家版那一条要先「记成线程」**：回帖卡挂在社媒库的线程上，而自家版队列是现读 Reddit 的、不在库里。所以点「AI 起草」或「出卡」的那一下先把这一条记进库（同一条只记一次），**不判类、不出转客服卡**——只是为了让回帖卡有个挂处。打开输入框本身不写库。
3. **没接模型时给一句开头，不是假装 AI**：按 10-06 那条「AI 不在就照实说」，给的是「Hi u/bob, thanks for sharing this!」这种打招呼的开头，框下一行写「这次没用 AI，先给了一句开头，你接着写」。不编内容。
4. **AI 起草的那句也会被检查**：起草出来的话如果自己就带承诺，照样填进框里让人改，但提前一行黄字说「这句会被打回」，而不是等点了出卡才知道。
5. **打回原因换成人话**：原来那句给模型看的提示里带规则内部名（截图里能看到 `l3:refund#t3:en`），非开发者看不懂。回帖这条路改成一句人话（只改说法，拦不拦还是同一份规则）；客服 / 群发那几处没动。
6. **起草的成本**：一次起草 = 一次小模型调用（最多 300 个输出 token、不思考），记在点起草那个人头上，和其它「抽取」类调用同一档。只有人点了「AI 起草」才调，不预先起草。
7. **npm 的周报只看 10.x**：npm 上 latest 已经是 11.x，但我们跟的是「Node 22 配的那一版」，按 latest 比会每周误报「落后」。加了 `version_line`，只拿 10.x 的正式版比；Node 那条看 GitHub release，wishlist 里放「security release」，出安全版就单独提醒。
8. **截图用 4455 端口起 demo**（避开 4317，也避开别的子代理常用的 4399）。

## 3. 要 Luoye 定的事（逐条，附建议）

1. **群里的新帖还不会自动进「群里的帖子」**：社媒库现在只有经接口送进来的线程（`POST /v1/social/threads`）和演示数据，Discord / Telegram / Facebook 群组 / WhatsApp 都还没有「自动把群里新帖拉进来」的那一步，所以真用户打开这个视图多半是空的（空态和问号里照实写了）。**建议：下一单先做 Discord（读频道消息）与 Reddit（自家版新帖已在读，顺手进库）两条的自动拉取，其余渠道排后。**
2. **AI 起草要不要花积分**：现在点一次「AI 起草」= 一次小模型调用（约几百 token），记在这个品牌的模型用量里。**建议：接受**（只有人点才调；不点就不花）。
3. **自家版那一条回复后会出现在 Reddit 的「群里的帖子」里**：因为回帖要先记成线程，记过的那几条在 Reddit 职责的「群里的帖子」里也看得到（发出去后标「已回」就不在了）。**建议：接受**（同一件事两处都能看到进度）；若嫌重复，可以让「群里的帖子」不显示自家版那几条。
4. **回帖卡的语气模板**：没接模型时那句开头是固定的（英文「Hi <名字>, thanks for sharing this!」/ 中文「<名字> 你好，谢谢分享！」）。**建议：先这样**；你要更有品牌味的话给我一两句，按品牌存。
5. **Node 22 停维护的时间点**：Node 22 在 2027-04 结束维护。**建议：2027 年初另开一单换到 Node 24 LTS**（ABI 变，原生模块要重取、Windows 真机要复测），docs/42 那一节已写明不在日常升级范围里。
