## 2. 我自主做的决定（白话）

1. **分五段、每段起一个新 demo**。走到一半整站被限流锁死（阻断 #3），不分段后半程全是 429，测不出东西。这本身记成阻断 #3，修好后脚本可以合回一段。
2. **「发登录信」默认不点**。第一次跑时发现 demo 这一步真的在打生产云（`cloud.agentsws.com`），回归脚本不该每跑一次就往生产云发一封信。手测点过两次（一次 503、一次成功，收件人 `tester@example.com`，保留域名不投递），结果写进了那一步的「实际」；要验就加 `--live-cloud`。
3. **找被挡住的卡时，脚本照用户会做的来**：先按卡型筛；筛不出来就把前面的卡「稍后」；连「稍后」都没有、而挡路的是 campaign 名单卡时，就批掉它（用户本来就想要那个活动）。绕路本身记进那一步，判「部分」。
4. **客服聊天线单独起一段（C2），先走一遍向导勾「客服」**。demo 种子里店主没有「网站在线客服」这条职责，不先加上就连入口都不存在；加上之后才暴露出阻断 #1 的客服那一半。
5. **入口被挡时，聊天窗页用手输网址进去看页面本身**（身份是店主），把页面好不好用和入口找不找得到分开记。
6. **合并 main（含 WP134）后重建重跑了一遍**，文档和截图用合并后那一次；两次结果除第 1 步卡数（WP134 加了第三张卡，脚本跟着改）与探针次数外逐条相同。
7. 修复 WP 编号写成「建议」：派工单写的时候 main 上 WP136 / WP137 已经被占用，我从 138 往后排。
