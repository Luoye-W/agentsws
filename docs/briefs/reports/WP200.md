## ③ 分界修复（Fable 09-29 追加）

**现象**：光扫到右下那块时（约 +0.8～+0.9s），块中间出现一条竖直的明暗分界；+1.2s 左右那块上还有一条水平的。明暗两种主题、各个尺寸都有，96px 起肉眼可见，官网 180px 会更明显。

**根因**：是几何问题，和尺寸、精度都无关。

- WP195 的亮带是一个和外框一样大（65×65）的矩形，渐变用 `objectBoundingBox` 从矩形左下角拉到右上角。
- 这样一来，最亮的那条线正好是矩形的**另一条对角线**（左上 → 右下），亮带在矩形四条边上是被**切断**的。
- 亮带靠平移这个矩形来扫。平移时矩形竖直的右边扫过右下那块，那一刻这条边上的亮度大约是 0.2–0.35，于是切出一条硬边；上边扫过时切出水平的那条。

**量化（修前）**：在 24 / 40 / 96 / 180 × 明暗上逐 100ms 截图，测块内部（四周内缩 4 个单位，避开圆角和抬起）相邻像素的二阶差分。平滑渐变这个值接近 0，硬边会冒尖。

| | 24 | 40 | 96 | 180 |
|---|---|---|---|---|
| 修前（深 / 浅） | 24 / 16 | 27 / 17 | 26 / 20 | 28 / 20 |
| 修后（深 / 浅） | 7 / 6 | 4 / 4 | 4 / 5 | 4 / 4 |
| 基线：把亮带整个藏掉（深 / 浅） | 3 / 3 | 3 / 3 | 2 / 3 | 2 / 2 |

修前的最大值全都出现在同一块（右下，第 3 块）、同一时刻（+0.9s）、同一方向（竖直），和肉眼看到的一致。修后只比「没有亮带」高一两个点，那是亮带本身柔和的渐变。24px 那一格的 6–7 来自块在抬起、测量区贴到了块边的抗锯齿，不是分界。

**修法**（三处同改：品牌包 `svg.ts`、工作台 `brand-mark.tsx`、预览页生成脚本）：

- 亮带渐变改成 `userSpaceOnUse`，轴就是 `GRADIENT_AXIS`（14,77 → 79,12）。这和原来那个 65×65 矩形的左下 → 右上是**同一条线**，所以光的位置、宽度、亮度、速度一个像素都不变：修前 / 修后连拍里，除了那条分界，其余逐格一样。
- 矩形放大到新导出的 `SHEEN_BAND_BOX`：外框四周各放宽两个外框，325×325。平移最远时（单独的「流光」±65）它离标记四边仍有一个外框远，切断的地方永远落不到块上。
- 矩形本来就被每块自己裁着，放大不会多画出任何东西。多画的面积只在裁剪区外，开销可以忽略。

**字节变化**（照 Fable 要求写明）：

- **会变**：`apps/workstation/public/favicon.svg`、`docs/assets/brand/mark-idle-{dark,light}.svg`，以及 `BRAND_MARK_SVG_IDLE_DARK / _LIGHT`、`BRAND_MARK_SVG_README_*` 这几个常量。
  - 变的只有两处：亮带那条渐变的属性（`x1="0" y1="1" x2="1" y2="0"` → `gradientUnits="userSpaceOnUse" x1="14" y1="77" x2="79" y2="12"`），以及六个亮带矩形的尺寸（`x="14" y="12" width="65" height="65"` → `x="-116" y="-118" width="325" height="325"`）。
  - 原因就是上面这个修法：它们都内含「波 + 流光」的亮带。
- **不变**：静态的 `mark-{dark,light,mono}.svg` 与 `BRAND_MARK_SVG_{DARK,LIGHT,MONO}`，因为里面没有亮带。
- **私有仓**：运营后台用的 `BRAND_MARK_SVG_IDLE_DARK` 这次跟着变了（修的就是这条分界）。私有仓不用改代码，submodule 钉到含本单的提交就能带上。

## 2 自主决定（白话）

1. **浅色的光用「极淡的品牌青 + 力度一半多一点」，不是只调暗纯白**。我并排试了七种：
   - 纯白 0.21 / 0.26；
   - 淡青、暖黄；
   - 深底那套亮青 `#2FE0C8`、薄荷色。

   亮青最「有光」，但扫到领头那块时会把品牌黄染成绿，所以不用。纯白减半也可以，只是块还是往灰白那边偏一点。淡青在青绿块上几乎看不出色偏，又没有「刷白」的感觉。
2. **力度乘在亮带那一层的 opacity 上，不去改 stop 的数**。这样「波 + 流光」（0.42）和「流光」（0.5）用同一个变量一起变淡，CSS 只加两个变量。
3. 变量名用 `--ws-brand-sheen*`，不用 `--ws-brand-mark-*`。已有测试会把 `--ws-brand-mark-*` 当成「渐变端点」逐个数、逐个对，混进去会乱。预览页抠变量的正则改成两类都抠。
4. **README 那两张是另出的新文件**，没有改原来的 `mark-dark/light.svg`。静态那三张有 `assets.test` 钉着「与静态常量逐字节相同」，别处也可能在用。
5. README 标记从 88 挂到 99：留了 4 个单位的边，只有放大才能让标记本身和原来一样大。
6. `pad` 取 4：波 + 流光抬 3、波抬 4、眨眼探 3，都在 4 以内（有测试钉着）。
7. 分界修复用「换坐标系 + 放大矩形」，没用「把亮带做窄、离矩形边远一点」：后者会改变光的样子，前者一个像素都不改。放大取两个外框，不取一个：单独的「流光」要平移 ±65，一个外框时边缘刚好贴在标记边上，没有余量。
