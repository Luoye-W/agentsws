# WP250 报告：空 Shopify 店识别支持中文（简体 / 繁体）及其他常见语言（决策 95、103）

分支 `wp/250-freshzh`（worktree `agentsws-wt/wp250-freshzh`），Claude 子代理。只改了 `packages/brand-intake`。

## 0. 一句话

现在中文（简 / 繁）、日、韩、德、法、西的新店都认得出来。默认首页文字以 Shopify 官方主题仓库各语言的原文为准，没有自己翻译。
按**决策 103**（Luoye 10-07），仓库里**只存每句归一化后的哈希，不存原文**，WP244 收进来的英文原句正则也一并换成了哈希。
占位店名加了「我的商店」「我的店铺」「我的商店名称」三个候选，因为中文后台新店的默认店名没查到官方说法（见第 2 节）。

## 1. 做了什么

| # | 内容 | 文件 |
|---|---|---|
| 1 | **默认文字哈希表**：一共 10 处默认文字、69 条，每条只有「语言 + 出处（仓库、固定提交、文件、key）+ 逐句哈希」，**没有原文**。哈希是 SHA-256 的前 16 位十六进制。表是生成脚本出的：脚本运行时从固定提交的仓库文件里临时取原文，算完哈希就丢，脚本本身也不含原文。切句、哈希的规则直接取 `dist/text-hash.js`，和运行时用的是同一份代码 | `src/shopify-default-texts.ts`（生成的）、`scripts/gen-shopify-default-texts.mjs` |
| 2 | **切句 + 归一 + 哈希**：先把全角转半角（NFKC），再按句末标点切句，包括 `。` `!` `?`，以及后面跟空白或到结尾的 `.`（价格里的小数点不会被切开）。**换行不切**，因为页面上一句话常被排版拆成两行。每句再去掉标签、解开实体、转小写、去掉空白和标点，然后算哈希 | `src/text-hash.ts`（新） |
| 3 | **怎么比**：把页面上每个文本节点（标签之间的那段文字）都按上面的规则切句、算哈希。某段官方文案切出的几句哈希**全在页面上**，就算对上这一处。整段原样照搬、被拆进几个标签、嵌在更长的一段话里，都认得出；改一个字就对不上 | `src/site.ts`（`placeholderTextHits`）、`text-hash.ts`（`pageSentenceHashes`） |
| 4 | **按「同一处」合并计数**：同一处默认文字的不同语言版本、Dawn 和 Horizon 两种写法，都只算一处。中英混排照样算 | 同上 |
| 5 | **看整页文字**：Dawn 的公告栏在 `<main>` 外面，以前只看 `<main>` 里的正文，这句永远对不上 | 同上 |
| 6 | **WP244 的英文原句正则删了**，换成同一套哈希。现行 Dawn 里有的那 6 句，现在都从仓库取。另外两句是老主题的，Dawn 里已经没有，只留哈希，出处没核实（见第 3 节第 3 条） | `src/site.ts` |
| 7 | **占位店名**加了三个中文候选，照旧保留明文（这几个是通用短词）。比对时不管大小写和首尾空白 | `src/site.ts`（`SHOPIFY_PLACEHOLDER_NAMES`） |
| 8 | **政策关键词补上繁体、日、韩、德、法、西**：以前这几种语言的店一份政策都认不出来 | `src/site.ts`（`POLICY_WORDS`） |
| 9 | 测试 15 条，新夹具 8 份 | `test/wp250-fresh-store-zh.test.ts`、`test/fixtures/*` |

「对上两处以上才算空店」这条规则没变。

### 文案来源（只存哈希）

- **Shopify/dawn** @ `258f00f64365e2018ca4c62778a6bf55a5d3cd18`（main，2026-08-10）：
  - `locales/<语言>.schema.json` 里的这几项：公告栏、富文本标题、富文本正文、图片横幅标题、图片横幅说明，以及图文 / 多行 / 多列三处正文（三处原文相同，算一处）
  - `locales/<语言>.json` 里的 `onboarding.product_title`（示例商品名）
  - `templates/index.json` 默认首页横幅那句写死的英文。模板不跟语言走，所以各语言的新店上都是这句英文
- **Shopify/horizon** @ `5acd1b6b66c02f61d3216e3adace5dd9e0404fc9`：`text_defaults.welcome_to_our_store`、`html_defaults.share_information_about_your`，以及 `templates/index.json` 里同一句横幅英文。Horizon 是 Shopify 现在给新店的默认主题，它的中文写法和 Dawn 不同，两种都收了
- 语言：en、zh-CN、zh-TW、ja、ko、de、fr、es
- 两个仓库的版权方都是 Shopify Inc.，`LICENSE.md` 是带用途限制的 MIT 式许可（只可用于开发和 Shopify 对接的主题）。按决策 103，仓库里不留原文，只留哈希和出处

### 测试夹具

- 夹具是我们自己写的仿造页面。用到官方原句的地方，比如空店首页上的占位句、正式店上的公告栏欢迎语，在夹具文件头注明了出处
- 中文 / 日文的「自动生成政策」是我自己写的，**不是 Shopify 官方原文**
- 测试代码里不写官方原句：要用时用正则从夹具里取

## 2. 占位店名核实结论

- **英文有官方说法**：Shopify 帮助中心写的是 By default, your store name is "My Store"
- **中文 / 繁体没查到**：
  - help.shopify.com 的中文页面直接抓会碰上人机验证，我没有绕过
  - 用网页读取工具读，拿回来的是英文版，原文同样是 My Store
  - 搜索里也没有找到官方的中文默认店名
  - 默认店名是开店那一刻由服务端写进去的，公开的主题仓库里没有，没法从仓库核实
- **处理方式**：按候选收「我的商店」「我的店铺」「我的商店名称」。中文后台新店的店名照样是 My Store 的可能性也不小，这种情况原来就认得出来
- 就算店名没认中，只要首页没动过，靠默认文字也能认出来。测试里把三家空店的店名换成真名字，照样都认出来了

## 3. 要 Luoye 定的事

1. ~~许可证~~：决策 103 已经定了，只存哈希。**合并时请用 squash**，或者直接合现在这个分支。这次我已经把分支历史重整过：从 main 起只有两个提交，最早那版带原文的数据文件不在分支历史里了。WP244 的英文原句还留在 main 的历史里，这个改不了。
2. **公告栏和横幅那两句不单独作数（我自己加的收紧）**：公告栏欢迎语、默认横幅那句英文，正式店也常常原样留着。规则是两处里至少有一处是只有没动过的店才会有的文字，比如示例商品名，或者富文本、图片横幅的占位说明。**建议保留。**
3. **老主题那两句英文的哈希**：WP244 那两条正则是半句话，比哈希得用整句。我按记得的老主题整句算了哈希，「出处未核实」也写进了数据文件。**建议保留**，反正认不中也不影响别的规则；以后核实到原句就重算。
4. **中文后台新店的默认店名还是没核实**。**建议**：真机或开中文测试店时看一眼「设置 → 商店详情」。如果是 My Store，就把三个中文候选删掉。
5. **政策至少 200 字这条门槛对中文偏严**：200 个中文字的信息量差不多相当于英文 600 个字符。**建议**另开小单，按文字类型分别设门槛。
6. **`looksLikeDefaultPolicy` 里还留着三段 Shopify 自动生成政策的英文片段正则**（WP244 的，不在决策 103 点名的范围里）。如果也要换成哈希，得先拿到政策模板原文，需要登录后台生成一份。**建议**：先留着，片段都很短；要换的话另开一单。

## 4. 自主做的决定（白话）

- **Dawn 之外把 Horizon 也收进来了**：Horizon 是现在新店默认用的主题，只收 Dawn 会漏。
- **加了默认首页横幅那句写死的英文**：两个主题的默认首页模板里都有，中文新店上也是英文。它属于第 3 节第 2 条那类，单独不作数。
- **比哈希时要求「这段文案的每一句都在页面上」**：只对上其中一句不算。这样嵌在长段落里、被拆进几个标签都认得出，改了一个字就认不出，和以前「原文是页面的子串」的效果一样。
- **政策关键词顺手补了其他语言**：不补的话，日文等语言的店，政策连「是不是默认政策」那一步都走不到。
