# WP361 报告：设置弹窗三处收尾

分支 `wp/361-settings2`。决策 925 / 926 / 927（Luoye 10-16 同意 WP356 的建议）落地；中途加了一项决策 930（给用户看的「Agent」统一改成「AI」）。

## 1. 做了什么

### 925：「进行中」挪到账号菜单「工作内容」

- 「进行中」看板现在是一页，地址 `/in-progress`。账号菜单「工作内容」组里排在会议 / 知识库 / 技能后面；⌘K 也搜得到它。
- 页面里画的还是原来那个看板（按人分列、谁手上几件），上面加了标题和一句「大家手上正在做的事」。
- 只在同事互联 / 公司模式出。个人模式只有你自己，首页那块「进行中」就够了，菜单和 ⌘K 都不列（组织还没读到时也先不列，免得闪一下）。
- 设置弹窗「团队」组里那一节拿掉了。「工具箱」照旧留在弹窗（品牌 · 工具箱）。
- 老地址还能用：`/org?tab=inprogress` 和 WP356 那几天的 `/settings/inprogress` 现在不算设置地址，会跳到 `/in-progress`。别的 `/org?tab=…` 照旧打开设置弹窗。

### 926：账号菜单拿掉「语言」

- 账号菜单里的「语言」那一行删了，只能在设置弹窗 → 个人 → 通用里改（中文 / English 二选一）。
- 深浅色和「场景 ›」留在菜单里，没动。

### 927：开机自启做成弹窗里的开关

- 设置弹窗「这台电脑 → 桌面端」里，「更新」下面多一行「开机自启」开关。
- 托盘菜单里那一项照旧在。两边改的是同一份：弹窗里一拨，托盘那一项跟着勾上；托盘那边一点，弹窗里的开关马上跟着变。
- 桌面壳加了一条小桥 `launchAtLogin`，能读、能写、能听别处改了。三个通道：`agentsws:launch-at-login-get / -set / -changed`。和别的桥一样，只接受本地源窗口发来的调用，写的时候只认 true / false。
- Mac 和 Windows 还是沿用托盘原来的做法：Mac 只告诉系统开或关；Windows 新的版本目录布局下，登录项指向 `current\agentsws.exe`。原因是版本目录会被清理，指着它下次开机就找不到了（WP327）。这段逻辑从 `main.ts` 拆进了 `apps/desktop/src/launch-at-login.ts`，单测能直接测。
- 网页端没有「桌面端」这一节。没有这条桥的旧桌面壳里，这一节还在，但不出开关。
- 「托盘菜单」那一行原来写着「开机自启、暂停、导出诊断在托盘图标的菜单里」，现在改成「暂停、导出诊断在托盘图标的菜单里」。

## 2. 我自己拿主意的地方

1. **「进行中」页面只在 ② ③ 进菜单**：这样和原来一致（原来它就只在团队 / 公司页出），个人模式不多一个入口。个人模式下直接敲 `/in-progress` 也能打开，看到的是自己的那几件，不报错。见 951。
2. **开机自启以桌面壳的配置为准**：托盘一直读的就是它，弹窗也读它。没有去反读系统「登录项」的现状：未签名的包读写登录项会被系统拒，读回来的值靠不住。每次改都会把值再交给系统一次，所以就算有人在系统设置里关过，再拨一下也能对上。见 952。
3. **开关读到值之前不画**：免得先画个「关」，再跳成「开」。
4. **写失败就退回原样**：桥那边报错时，开关拨回去。
5. **没有另装库**：开关用项目里已有的 shadcn `Switch`；登录项用 Electron 自带的 `app.setLoginItemSettings`，托盘原来就用它。这件事不需要找外部方案。
6. **没加截图**：开机自启开关只在桌面壳里出，网页演示里看不到；菜单和页面的变化都有测试管着。
