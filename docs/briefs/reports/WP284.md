## 0. 一句话

卡上指导选「以后都这样」→ 出一张卡「以后都这样：…」，两个按钮「记进规矩 / 不用」→ 点了「记进规矩」，这一句就写进**这个品牌里这条职责的规矩**（留谁定的、谁提的、来自哪张卡）。之后这条职责每次运行，提示词里角色定位后面多一节「这条职责的规矩」，AI 照做；职责规矩卡和右栏「角色」面板里看得见、改得了、删得掉，改了删了下一次运行就跟着变。① ② ③ 都一样（③ 按现有路由批了才落）。另：③ 里只有「工作区成员」那条的同事，现在能点发给他本人、只关于他自己的卡（开公司那张「知道了 / 我要退出」、交给你），别的审批卡照旧不行。

## 2. 我自己定的（白话）

1. **规矩按「品牌 + 职责」存**，不是整个公司一份。理由：运行本来就绑在一个品牌上；同一条职责在两个品牌里口径常不同（一个卖 3C、一个卖衣服）。
2. **规矩不写进角色定位那段话里，单独一节**（排在职责角色定位后面、回复语言前面）。理由：角色定位是一整段话，塞进去就没法「一句一句地改、删、留名字和来源」；单独一节也让「包里原文 / 公司改写」那套还原逻辑不受影响。
3. **规矩里「改」不走审批**：① ② 当场生效（② 给同事发「知道了 / 撤回」，与 WP276 改共用东西同一套）；③ 只有老板与管理员能改删——他们本来就是批策略变更的人，再出一张卡给自己批没有意义。
4. **那张卡从「选一个 + 通过」改成两个按钮「记进规矩 / 不用」**：原来的卡上同一句话出现三遍（标题、「改之后：rule: …」、正文那句 + 「点通过以后都这样做」），还有一个「选一个，答案会沉淀成策略」的单选。现在标题说是哪一句、按钮说记到哪、正文一句说之后怎样与去哪儿改。句子太长被标题截了，正文才放整句。老卡（这单之前出的、还没点的）照旧是老样子，点「按提议改」照样落库。
5. **「只关于他自己的卡」只放两种**：开公司那张「知道了 / 我要退出」、「交给你」（交给对方 / 交出发起人 / 请你一起做）。派工单例子里的「申请加入」我没放——它问的是申请人的事，③ 里本来只发给老板（见第 3 节第 3 条）。
6. **决定路由的权限判定挪进处理函数**：要先读卡才知道是不是关于他本人的，网关那道判定是同步的读不了卡。没有批准权的人先放进来，处理函数里不是那几种卡就回与原来同一句 403；有批准权的人与 ② 走原路。
7. **事件里不记规矩原文**（只记 id、职责、来源卡）：规矩是用户写的业务口径。
8. **模拟里「选哪个」与工作台同一条路**：总线不单独存选项，工作台是把答案放进 `edited_payload`；模拟原来只把选项交给学习回路，这里对「以后都这样」那张照工作台的办法传，否则「不用」也会落库（负向验过：改成选「不用」，场景就红在 `role_rule.added` 与提示词两项）。
