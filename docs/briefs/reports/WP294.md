# WP294 报告：ChatGPT 订阅老用户的 gpt-5.4 自动换成 gpt-5.5

分支 `wp/294-codex-migrate`（worktree `../agentsws-wt/wp294-codex-migrate`，从 main 4b7300cb 起，WP293 已在里面）。
Claude 会话，2026-10-10。没 push、没合并。决策 375（Luoye 10-10 同意：自动换）。

**一句话**：老用户存着的 ChatGPT 订阅模型如果是 `gpt-5.4` / `gpt-5.4-mini`（WP293 升级带进来的 pi-ai 1.1.0 把这两个删了），
服务启动时自动换成 `gpt-5.5`、存回去，首页告警区出一行「ChatGPT 订阅的 gpt-5.4 停用了，已换成 gpt-5.5」，点开到设置页的模型那一块。
别的模型、别家一律不动。

## 1. 做了什么

老名字存在两个地方，两处都换：

| 存在哪 | 谁的 | 怎么换 |
|---|---|---|
| `subscription.json`（每人在订阅卡上选的模型） | 按人 | 启动读的时候换；记下「从什么换成什么、什么时候」 |
| `models.json` 里那条 ChatGPT 订阅（`kind: openai-codex` 的 `model`） | 这个品牌大家共用 | 启动读的时候换；默认模型、按用途选的模型里指向它的也一起换 |

- **只认一张退役表**（`packages/dsh-adapter/src/subscription-facts.ts` 的 `RETIRED_SUBSCRIPTION_MODELS`：`gpt-5.4` / `gpt-5.4-mini` → `gpt-5.5`）。
  用户自己填的别的名字（哪怕官方目录里没有）不动；OpenAI 兼容口、Claude 订阅上就算也叫 `gpt-5.4` 也不动。
  这个文件没有 dsh 依赖，服务端照旧不用为它装 dsh。
- **表对着官方目录核**：dsh-adapter 加了一条测试，拿装着的 pi-ai 目录比——退役的真不在、顶替的真在。哪天官方把 gpt-5.4 加回来或删了 gpt-5.5，这条先红。
- **提醒照 WP169 店铺校正那条现成的路走**（首页告警区一行 `system_alert`，不是要人拍板的卡）。挂 7 天；人自己去订阅卡上换了模型、或改了模型设置，就不再出。
  两处都换了、换的又是同一对「从 → 到」，只出一行。点开去 `/settings?tab=models`（和余额不足提示、顶栏用的是同一个链接）。
- 照 `models.ts` 里 WP88 那条（模板默认值不在清单里就换成清单第一个）的意思写：别让人存着一个上游不认的名字。

改到的文件：`packages/dsh-adapter/src/subscription-facts.ts`（退役表）、`apps/server/src/subscription.ts`、`apps/server/src/models.ts`、
新文件 `apps/server/src/retired-models.ts`（提醒那一行）、`apps/server/src/server.ts`（接到首页告警区）。契约、SDK、工作台界面都没动。
