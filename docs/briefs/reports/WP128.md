## 1. 实现清单

1. **新包 `packages/hosted`（`@agentsws/hosted`，纯逻辑）**：起停判定（`desiredFor`：active / cancelling / grace 跑，suspended / none 停）、
   四个状态（运行 / 启动中 / 休眠 / 停止）、保活与重起常量（3 分钟一拍、三次不应重起、退避 0 / 30s / 2m / 10m）、
   **容器环境变量契约**（`buildHostedEnv` / `parseHostedEnv`，DO 写、容器读，一份名字表）、
   **DO → 容器的形状按「一个容器 N 个租户」定**（`HostedContainerSpec = { cloud_base_url, key, tenants[] }`，本轮 N=1，多塞直接抛；
   工作区号在启动参数里只出现在 `AGENTSWS_WORKSPACE_ID` 一处，转发器地址容器里自己拼）、托管令牌格式、
   **按 Cloudflare 官方单价的费用估算**（`pricing.ts` 抄官网，`cost.ts` 算）。接进了根 `tsconfig.json` 与三个消费方
   （`apps/cloud-worker`、`apps/server`、`apps/cloud`）的 `references` 与 `package.json`。
2. **`apps/cloud-worker` 加 `HostedInstanceDO`**（`src/hosted-instance-do.ts`，每个订阅工作区一个，`idFromName(工作区)`）：
   用运行时的 `ctx.container` 起容器（同一份 `apps/server`）；alarm 每 3 分钟打一次容器的 `/v1/health`（心跳 + 保活），
   没在跑按退避重起、连续三次不应强停重起；每次起容器换一把托管令牌（库里只存哈希）；
   停 = 先 SIGTERM（让容器推最后一份快照）、一分钟后还在就 `destroy`，令牌与托管配对当场作废，快照留 30 天后删；
   快照进 R2（每工作区最多 3 份、单份上限 512 MB）；状态里有本月活着的秒数、**本月费用估算**与**常驻整月估算**。
3. **`ChatRelayDO` 切对端**：订阅开通 / 取消 / 六小时一拍扣费之后按订阅状态叫 `HostedInstanceDO` 起或停；
   托管那一头用**另一把配对**（`hrp_…`，转发器只存哈希，与商家本机那把分开验，互相冒充不了）；
   状态接口多了 `peers`（本机与托管各在不在）与 `hosted`（托管实例状态）两格。
4. **`packages/chat-relay` 的 `RelayCore` 两格对端**：以前一个工作区只有一格、后连的顶掉先连的——商家一开机就把托管实例挤下线，
   与 docs/74「两头都在时托管赢」正好相反。现在两格并存，访客消息给托管、没有才给本机；ping 的 pong、拉留言、报错
   **回给发帧的那一头**（否则本机的心跳 pong 会被送到托管那边、本机两拍收不到就断线重连）。`dropClient` / `onClientFrame`
   只加了可选参数，自建两档的老调用方语义不变。
5. **入口 Worker 的托管路由**（`src/hosted-routes.ts`）：`/v1/hosted/snapshot`（容器推 / 拉，**只认托管令牌**）、
   `/v1/support/hosted`（商家看状态）、`/v1/support/hosted/snapshot`（商家取回 / 覆盖，**只认工作区令牌**）；
   托管令牌另外只在 `/v1/ai/*` 与 `/v1/wallet` 上认（`hostedAwareVerifier`）——**AI 调用在这个组织的 `WalletDO` 里按 `ai` 块计积分**，
   与本机用云模型同一条路。
6. **`wrangler.toml`**：`HOSTED_INSTANCE` binding、`[[migrations]] v6 new_sqlite_classes = ["HostedInstanceDO"]`、
   `[[containers]]`（`class_name = "HostedInstanceDO"`、`image = "../../deploy/Dockerfile.hosted"`、`image_build_context = "../.."`、
   `instance_type = "basic"`、`max_instances = 50`）、R2 `HOSTED_SNAPSHOTS`、`[vars] AGENTSWS_HOSTED_INSTANCE_TYPE`。
7. **镜像 `deploy/Dockerfile.hosted`**：照 `Dockerfile.cloud` 的多阶段做法，只建 `apps/server`（不带工作台），不跑 apt、`pnpm deploy`、
   不用 root；镜像里**没有任何工作区号与密钥**；没有 `VOLUME`（盘是临时的）。仓库根新加 `.dockerignore`（三个镜像共用）。
8. **`apps/server` 托管模式**（`src/hosted-mode.ts`，开关 `AGENTSWS_HOSTED=1`）：起服务**之前**拉云端最新快照导进数据目录；
   每 6 小时与收到 SIGTERM 时推快照；托管令牌与转发器配对种进接托管那个品牌的秘密库（模型面与转发器客户端一行不改）；

   另有商家本机那一侧的 `createHostedOwnerClient`（订阅 / 看状态 / 取回 / 覆盖）。
9. **本机接口**（`packages/api` 的聊天路由，全是可选端口方法，没实现回 501）：`GET /v1/chat/relay/hosted`、

## 2. 我自主做的决定（白话）

1. **没有 `extends Container`，直接用 `ctx.container`**。那个类继承 Cloudflare 的运行时基类，普通编译器和测试里装不进来，而这个仓库
   所有云端对象都是「朴素类」、测试不起真运行时。那个类本身就是 `ctx.container` 外面包一层「每 3 分钟醒一次」的闹钟，
   我把这一层照着它的源码写成了我们自己的闹钟（顺便还要在同一个闹钟上做「停容器一分钟后强停」「快照 30 天删」）。同一个底座，少一个依赖。
2. **常驻 = 我们自己每 3 分钟打一次心跳**。官方文档里**没有**「永不休眠」的开关，`sleepAfter` 只是「多久没请求就停」且那是那个类里的逻辑。
   3 分钟取的是官方那个类自己的保活节奏。**这一条要在第一次真部署时亲眼确认**（见「上线要亲手做的事」第 6 步）。
3. **规格先用 basic（1/4 vCPU、1 GiB）而不是 lite（256 MiB）**：本机实测 `apps/server` 空闲约 45–75 MB（macOS 的 RSS），
   但跑话轮、推快照（VACUUM INTO + 打 zip）时会涨，256 MiB 余量薄，OOM 就是聊天窗掉线。代价是贵——列进了第 3 节请你定。
4. **欠费宽限期里容器照跑**：派工单写「宽限**到期**才停」，我照做；好处是充上钱不用再冷启动一次。
   与 docs/74 §6「宽限里服务暂停」的说法有出入——转发器的 200 上限在宽限里照样恢复，但托管实例还在回话。第 3 节请你定。
5. **托管令牌以 `wst_hosted_` 开头**：入口那一层只认 `wst_` 开头的令牌，换前缀就得改那句「与 Compose 形态一字不差」的鉴权——不值。
   令牌里带工作区号（base64url），入口据此去问对的那个托管对象；工作区号本来就在嵌入代码里公开。
6. **托管那一头用另一把配对，而且与本机那把分开验**：一把被偷了也冒充不了另一头。
7. **商家本机推上来的包删掉秘密库**：邮箱口令、Shopify 密钥、模型 key 都是本机那把钥匙加密的，托管实例打不开也不需要。
   托管实例自己推上去的那份保留秘密库（同一把派生钥匙，打得开）。
8. **「取回云端那一份」只落进备份目录、不自己导入**：与值守「搬回来」同一条（WP36：跑着的进程不换自己脚下的库）。
9. **后台这一块只读**：起停只跟着订阅走，不给后台留「手动开 / 停」按钮——不然「这个月扣了钱容器却停着」就说不清了。
10. **镜像的忽略表放仓库根**：`wrangler deploy` 是把 Dockerfile 从标准输入喂给 docker 的，按文件名找的 `<Dockerfile>.dockerignore`
    认不到（第一次 dry-run 实测：几个 G 的 `node_modules` 与本机编好的 dist 全传进去了，还会把 macOS 编的 `better-sqlite3` 带进 amd64 镜像）。
    根 `.dockerignore` 三个镜像共用，它们都在容器里自己装、自己编。
11. **DO 与容器之间按「一个容器 N 个工作区」定形状、本轮只放一个**（Luoye 09-23 补充）：以后切共享版不用改镜像和这张表。

## 3. 需要 Luoye 定的事

1. **容器规格与定价（最要紧）**：按官方单价，**basic 常驻一个月约 $8.5，30 积分（≈ $4.2）盖不住，每个订阅工作区每月亏约 $4.3**；
   lite 约 $2.3 盖得住但内存余量薄。三条路：① 先 basic 上线，看一周 Cloudflare 后台真实内存峰值，稳定在 180 MB 以下就降 lite
   （改 `wrangler.toml` 两处 + deploy 一次）；② 客服增值服务单独涨价；③ 订阅数上来后改共享容器（每工作区摊到约 $1.5）。
   我的建议是 ①，内测期亏几个工作区的钱换稳定。
2. **欠费宽限期里托管实例要不要照跑**（第 2 节第 4 条）：现在照跑（照派工单），最多白跑 30 天 × 每天约 $0.28。改成「进宽限就停」只改 `desiredFor` 一行。
3. **`max_instances = 50`**：同时最多 50 个订阅工作区。内测够；到 40 个就该准备切共享版或调大。
4. **追补分支 `wp/128-followup` 要不要合**（brand-design 的 references + 本报告）——不合的话托管镜像从干净目录建不出来。

## 5. 偏离

1. **没继承 `Container` 类**，用同一个底座 `ctx.container` + 自己的保活闹钟（第 2 节第 1 条）。
2. **「按 WP118 的同步机制」没照搬**：WP118 是红人库按对象的增量同步；托管实例这里是**整个工作区包的快照**（WP36 的导出格式）
   往返 R2——容器盘是临时的，要的是「重起之后完整接着跑」，整包最直接。按记录的双向合并留给下一张单（第 6 节）。
3. 派工单说「数据卷在容器内」：Cloudflare Containers 没有持久卷（盘是临时的），所以是「容器内临时盘 + 定时推 R2 快照 + 起来先拉」。
4. `ChatRelayDO` 的旧测试「托管实例赢」用的是**商家本机那把配对**冒充托管——这正是 WP128 要堵的，改写成「冒充不了」，
   「托管赢」的正面用例挪到 `wp128-hosted.test.ts`（用托管自己那把）。
5. 托管令牌前缀是 `wst_hosted_`（第 2 节第 5 条）。
6. 结尾流程：派工单要求的「报告提交在分支上 + docs/35 记待审 + HANDOFF 改待审」——我写报告时分支已被合并、worktree 已删
   （未提交的报告与 docs/35 那一条随 worktree 丢了），docs/35 与 HANDOFF 已由 Fable 记为「已合并」。所以报告重写后提交在
   追补分支 `wp/128-followup`，**没有**把 HANDOFF 改回「待审」（那会是倒退）。

## Luoye 上线时要亲手做的事

（与 `docs/64` §13.5 同一份）

1. 本机装好并**开着 Docker**（`wrangler deploy` 就地 build 镜像并推到 Cloudflare 自己的镜像仓库，不用 Docker Hub）；先合 `wp/128-followup`。
2. 建快照桶：`pnpm -F @agentsws/cloud-worker exec wrangler r2 bucket create agentsws-hosted-snapshots`。
3. 生成种子：`node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`，
   `pnpm -F @agentsws/cloud-worker exec wrangler secret put AGENTSWS_HOSTED_KEY_SEED` 粘进去，**同时存进密码管理器**——丢了就读不回已有的快照。
4. `pnpm -F @agentsws/cloud-worker exec wrangler deploy`（第一次 build amd64 镜像，Apple 芯片上十几二十分钟；之后有缓存会快）。
5. 用自己的测试工作区：工作台「聊天窗 → 转发方式」第三项点「开通」（扣 30 积分）。
6. 运营后台「组织 → 客服增值服务」：一两分钟内从「启动中」变「运行」，**放一个小时**，确认一直是「运行」、最近心跳一直在 3 分钟以内
   ——这一步验证「心跳保活」在真平台上成立（官方文档没保证）。不成立就告诉我，换成官方 `Container` 类的写法。
7. 关掉本机，从网站聊天窗发一句：有回复、积分里多一条 AI 扣费；再开本机，访客消息仍给托管（后台看得到两头都在线）。
8. 一周后去 Cloudflare 后台 → Containers 看真实内存峰值，决定 basic 还是 lite（第 3 节第 1 条）。

## 费用估算

按 Cloudflare 官方单价（2026-09-23 读的现行版本，`packages/hosted/src/pricing.ts`）：内存 $0.0000025 / GiB·秒、CPU $0.000020 / vCPU·秒（**只按真用的算**）、
盘 $0.00000007 / GB·秒；内存与盘按开着的规格算；睡着不计费（但订阅了的我们不让它睡）。一个月按 30 天 = 2,592,000 秒，CPU 按 10% 的时间在忙估。
账号每月包含的量（25 GiB·小时内存、375 vCPU·分钟、200 GB·小时盘）是整账号共享的，摊到每个工作区 ≈ 0，不扣。
**按每个订阅客户一个容器**：

| 规格 | 内存 | 盘 | CPU（10% 忙） | 每工作区常驻一个月 | 对 30 积分（≈ $4.2） |
|---|---|---|---|---|---|
| lite（1/16 vCPU · 256 MiB · 2 GB） | $1.62 | $0.36 | $0.32 | **≈ $2.31** | 盖得住，毛利约 45% |
| **basic**（1/4 · 1 GiB · 4 GB，本轮缺省） | $6.48 | $0.73 | $1.30 | **≈ $8.50** | **盖不住，每月亏约 $4.3** |
| standard-1（1/2 · 4 GiB · 8 GB） | $25.92 | $1.45 | $2.59 | ≈ $29.96 | 远远盖不住 |

- 与派工单估的「$4–6 / 月」差在规格：那个区间落在 lite 与 basic 之间。
- 例：内测 10 个订阅工作区、全用 basic ≈ **$85 / 月**（收 300 积分 ≈ $42）；全用 lite ≈ $23 / 月。
- 共享版（`docs/64` §13.4）：一台 standard-2 常驻约 $46 / 月，按每工作区 ~150 MB 装 ~30 个，每个约 $1.5。
  对 basic 超过 ~6 个订阅工作区、对 lite 超过 ~20 个，共享版更便宜。
- 另外：R2 快照每工作区最多 3 份、几 MB，≈ $0；托管实例的 AI 调用照常按积分扣（不在容器费里）；Workers Paid 的 $5 本来就在付。
- 后台组织抽屉那一格会按实际活着的秒数显示「本月已花」估算——**是估算不是账单**，真账看 Cloudflare 后台。
