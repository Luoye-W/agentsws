# WP246 报告：取数路线「首选 → 备选 + 体检」、Reddit 浏览器备选改用读号、YouTube 字幕、网页转文字

分支 `wp/246-routes`（worktree `agentsws-wt/wp246-routes`），Claude 子代理。照 Luoye 10-07 定的 87 / 88 做。
参考了 Agent-Reach（MIT）的「每平台一张有序后端表 + doctor 体检」思路，**没抄代码、没加任何依赖、没引 Python**。

## 0. 一句话

三条取数路线（Reddit、YouTube 字幕、网页转文字）用同一个结构表示：每平台一张「首选 → 备选」的级别表，每级都能体检
（通 / 不通 / 关着 / 还没接 + 一句原因 + 怎么修）；连接页多一块少字的「取数路线」，每平台一行、每级一个状态图标、
一键「重新体检」。Reddit 浏览器那一路从「无头、不登录」改成「用户自己登录的普通读号」：点「登录读号」有头打开
只读浏览器那份目录到 Reddit 登录页，关掉后自动体检显示「已登录：u/xxx」；认出是品牌登记的号（官方 / 版主）就拦。
另加两个零配置只读工具：`read_youtube_transcript`（读视频页里的字幕轨）、`read_webpage`（本机抽干净正文，第三方 Jina 默认关）。

## 2. 自主做的决定（白话）

- **浏览器那一路「没登录读号 = 没配」**，不再匿名去碰 Reddit。匿名在真机上基本都被拦，每拦一次还要暂停 6 小时；不如直接说「先登录读号」。
- **认不出登录的是谁，也先不读**（宁可这一路不通，也不冒「其实登的是版主号」的险）。
- **「品牌登记的号」怎么认**：用社媒那边登记的 Reddit 号（`social` 库里 channel 为 reddit 的那几个 handle），大小写、`u/` 前缀归一后比。现在登记的号没有「官方 / 版主」标记，所以登记过的 Reddit 号**全部**当官方 / 版主号拦——它们本来就是品牌自己的号。
- **体检看的是旧版首页的页头**（`old.reddit.com`，服务端画的，关着页面脚本也在）。新版页头要页面脚本，读不到。
- **自动读取默认「有头最小化」**（评估见 §3）；设置里能改无头（`PUT /v1/settings/read-routes` 的 `reddit_browser_window`）。界面上没摆这个开关——少字，等你定要不要摆。
- **登录窗口不让 Playwright 连进页面**：只问调试口的页面清单，登录页上不留自动化痕迹；关窗口用「体面地退」（SIGTERM / `taskkill` 不带 `/F`），让浏览器把登录态写完。登录窗口最多开 15 分钟，到点体面关掉。
- **YouTube 不引 yt-dlp / Python**，只读视频页与字幕轨；UA 照实是 `agentsws-reader/1.0`（不伪装）。接口中台那一级结构上留着，体检显示「还没接」。
- **网页转文字没挂 grounding**：挂到 26 条职责会改岗位路由；改成「能抓网页（`web_fetch`）的职责运行时自动多一个 `read_webpage`」，只在真有模型的运行里出现，模拟不受影响。
- **YouTube 字幕只挂两条 YouTube 职责**（红人营销、社媒运营各一条），意图词用「读字幕 / 视频字幕内容 / 视频文字稿 / transcript」、不带 cue 词——「字幕」这种常用词会让替身运行一碰就调它，也会改岗位路由。
- **体检的「上次结果」**：第三方转文字没开时不记那一级（免得体检里出现「上次没成：没开」）。
- **演示里装了只读浏览器替身**（WP228 那时演示不装）：替身不起浏览器、不出网，为了演得出「登录读号」。

## 3. 「有头最小化」还是「新无头」——评估（没碰真 reddit.com，按机理与本地实测）

| | 新无头（`--headless=new`） | 有头最小化（默认） |
|---|---|---|
| 站点在门口（不跑页面脚本）就看得到的 | UA 里写着 `HeadlessChrome`（我们不改 UA，docs/89「别谎报 UA」）——最常见的拦法就是认这个 | 普通 Chrome 的 UA；TLS / HTTP2 指纹两者一样 |
| 页面脚本那一层的指纹 | 我们本来就关着页面脚本，指纹脚本跑不起来；但这也意味着要跑脚本的验证页一律过不去 | 同左 |
| 登录态 | 读号 cookie 同样带着 | 同左 |
| 代价 | 看不见 | 读的时候任务栏 / Dock 里多一个最小化的 Chrome（闲 90 秒自己关）；起来那一下可能闪一下窗口 |

结论：**有头最小化更不容易被验证码拦**（门口那一刀主要认 UA），而且一样只读。真被验证码拦时照实停下，提示「点「登录读号」，在打开的窗口里手动过一次验证再关掉」——那个窗口开着页面脚本，人能过验证，过了之后的通行 cookie 留在同一份目录里给自动读取用，体检认出读号就解除暂停。
本机实测（mac + Chrome，本地假 Reddit）：读号那一档 cookie 跨页、跨重启都在，页面脚本照样关（页面想发的 POST 一个没发），全程只有 GET。有头最小化没在这台电脑上真跑（会弹窗口），请 Fable 在 Windows 真机上看。

## 4. 需要 Luoye 定的事（逐条，附建议）

1. **自动读 Reddit 时浏览器默认「有头最小化」还是「无头」**——建议**有头最小化**（更不容易被拦；代价是读的时候任务栏多一个最小化的 Chrome，闲 90 秒自己关）。要不要在连接页摆一个开关？建议**先不摆**（少字），真机上看效果再说。
2. **登记过的 Reddit 号一律当官方 / 版主号拦**（现在登记的号没有「官方 / 版主」标记）——建议**照现在**：登记进来的都是品牌自己的号，读号就该是另一个普通号。WP249（官方号在内置浏览器登录）落地后，那边登录的号也并进这张名单。
3. **认不出读号是谁时先不读**——建议**照现在**（宁可这一路不通，也不冒用版主号）。
4. **YouTube 字幕的 UA 照实写我们**（`agentsws-reader/1.0`）——真 YouTube 可能给这种 UA 回一个没有播放器数据的页面，或者字幕轨要额外校验（回空）。建议**先照实**，Fable 真机看；若真拿不到，再定：要不要让这一级改走本机只读浏览器（真 Chrome、真 UA，不伪装）。
5. **网页转文字的第三方（Jina Reader）默认关**，开关在连接页「取数路线」网页那一行——建议**照现在**。
6. **YouTube 字幕挂在哪**：现在只挂 `kol.youtube`、`social.youtube`。要不要给别的红人 / 社媒职责也挂（竞品在 YouTube 上的视频）？建议**先不挂**，挂了会让岗位路由在「字幕」这类词上更难分。
