## 0. 一句话

助理页左边的会话列表去掉了，现在只有一条对话，一直往下聊。往上滚能看到以前所有的话：换了一天，中间有一行日期；换了话题，有一条淡线，线上写着上一个话题的一句话小结。左上角放大镜能搜以前说过的话，点一条就跳过去。右上角「换个话题」可以手动另起一段。聊得再久，助理每次也只看「这个话题的原话 + 最近几个话题的小结 + 记忆」，不会越来越慢、越来越贵。你提到更早的事，它会自己去翻，回答下面带「出处」。

## 1. 做了什么（白话）

**界面**
- 助理页没有左侧会话列表了，只有一条连续对话。以前的多条会话，第一次打开时按时间拼进这一条，每条老会话变成一段。
- 换了一天：两条话中间一行日期（如「10月15日周四」）。
- 换了话题：一条淡线，线上一行是上一个话题的小结；鼠标停上去能看整段小结。刚点完「换个话题」、还没说话时，末尾先画一条线。
- 左上角放大镜：输两个字以上就搜以前说过的原话和话题小结，结果带日期和话题名；点一条跳到那里，那条亮一下。
- 右上角「换个话题」：只在这一段已经说过话时出现。直接说一句「换个话题，……」也一样。
- 助理翻了以前聊过的，回答下面一排小签「出处 · 10月14日」，点了跳到当时那句。
- 带会话编号的老地址（`/assistant/xxx`、`/free-chat/xxx`）都回到 `/assistant`。⌘K 里原来的「新对话」改成「助理：换个话题」。
- 教程「助理」加了一节「一条对话，一直聊下去」（中英）；docs/96 加了这几个组件的出现规则。

**四层上下文（每一轮由服务端拼，不把整条历史给模型）**
1. **当前段原话**：这个话题的原话全带上。超过预算（模型窗口的一半，见 933），就把这一段里较早的那部分压成「段内小结」，最近的原话保留，之后每轮只带「段内小结 + 之后的原话」。
2. **自动分段**：这几种情况另起一段：
   - 隔了 2 小时以上没说话；
   - 跨天（按这台电脑的时区）；
   - 说了「换个话题 / 聊点别的 / 另外一件事……」，或者点了那个钮；
   - 模型判断话题变了：系统提示里告诉它，用户这句和前面完全无关时，在回答最前面写一个记号。服务端看到记号就把这一问一答挪进新的一段，记号不给人看。这样不用为了判断话题多调一次模型。

   旧的一段在后台出一份「话题小结」，分「谁 / 要做什么 / 定了什么 / 派了哪些事 / 还没完的」几节写，存在本机 `free-chat.sqlite`。下一轮的开场上下文里带最近 3 段的小结。
3. **长期记忆**：WP343 的助理记忆不变，每轮只带条目。
4. **按需翻旧账**：助理多了一个只读工具「查以前聊过的」（`recall_conversation`），只有在有更早的话题时才给它。它按关键词和时间搜小结与原话，回片段和出处（哪天、哪个话题）。

**事情的进度不靠对话记**：小结里派出去的事只记编号和一句话；系统提示里写明进度、批次、待确认都要用工具现查。WP343 / WP350 原来的工具不变。

**成本与观测**：每一轮往事件日志写一条 `assistant.context`，记这一轮拼进了几条原话、多少 token、有没有段内小结、带了几段话题小结、几条记忆、系统提示多大、这轮有没有切段、为什么切。一段收起、出了小结，或者段内压了一次，写一条 `assistant.topic`。这两条都不带正文，以后调预算就看它们。

**接口**（契约只加不删）：`GET /v1/free-chat/thread`（那条长对话和各段）、`POST /v1/free-chat/thread/topic`（换个话题）、`GET /v1/free-chat/thread/search?q=`（搜）。每条话多了 `segment_id`；翻过旧账的回答多了 `recalled`。老的会话接口照旧能用。SDK 已重出。

**demo 替身**：「Agents 工坊（用积分）」替身会出话题小结，说「上次 / 上周……」时会去翻旧账（截图就靠它）。

## 2. 我自己定的（白话）

1. **先找现成的，查过这些**：
   - **dsh 官方**：`dsh-compaction`、`dsh-compaction-basic`、`dsh-command-compact`、`dsh-token-meter`、`dsh-experimental-session-search`、`dsh-tool-session-query`、`dsh-session-query-sqlite`，都是 MIT。
   - **社区**：`dsh-context`（Apache-2.0，看上下文的面板）、`dsh-handoff-compaction`、`dsh-context-guardian`、`dsh-context-memory`、`dsh-context-compression-improved`、`dsh-context-actions`、`@2jumpsina/dsh-context-guard`、`dsh-context-xray`、`dsh-context-console`、`dsh-context-milvus`（要自己架 Milvus）、`@goodandready/dsh-context-lens`（压代码），都是 MIT。

   这些插件都挂在一个 dsh 会话上：要用 dsh 的会话存储、token 计量和模型服务。而助理的每一轮从来不是 dsh 会话，是服务端直接调模型网关，stub / direct / dsh 三个运行时都走这一条路。所以它们一个也接不进来，硬接就得把助理整个搬进 dsh 会话。我只**移植了官方 `dsh-compaction-basic` 的小结写法**：固定分节、空节写「无」、保留数字和名字、再压时把旧小结并进来而不是照抄。我把分节改成了生意上的话，在 `assistant-thread.ts` 头注释里写了出处。搜索没用官方的 sqlite 全文索引（它管的是 dsh 会话库，不是我们的对话库），在本机对话里按关键词逐条比；一个人一条对话的量，这样就够快。
2. **话题变了，靠模型在回答开头写记号来判断，不另外问一次**：派工单写的是「便宜的一问或规则」。另外问一次，每句话都要多花一次钱、多等一会儿。写记号不花钱，而且模型本来就看着前面聊了什么。误判了也只是多分一段，不丢话。
3. **小结在后台出，不挡这一轮回答**：小结出来之前，开场上下文里先用规则小结（这段的第一句话 + 交出去的事）顶上。
4. **段内压缩要当场等它**：不压这一轮就可能超窗口。等的时候输入框上一行「在整理前面聊的…」。压失败就退回规则小结，不挡对话。
5. **「查以前聊过的」只在有更早的话题时才给模型**，第一段对话里不给，省一份工具说明的 token。一轮最多翻 3 次。翻到的内容当外部资料围起来交给模型，因为里面夹着当时的原话。
6. **搜索框放左上角**，平时只是一个放大镜，点开才是输入框（界面少字）。
7. **换个话题按钮只在这一段说过话时出现**，免得连点出一串空段。
8. **整条对话一次全读出来**，不分页：一个人的本机对话，量不大。真聊到几千条再加「往上滚再读」。
9. **「回报」和「方案卡汇总」落在正在聊的那一段**，不回到当初派活那一段，免得时间线上跳回旧话题。

## 3. 要 Luoye 定的事（决策 932–936）

| 号 | 要定什么 | 建议 |
|---|---|---|
| **932** | **什么时候自动另起一段**：隔 2 小时以上 / 跨天 / 说或点「换个话题」/ 模型觉得话题变了（在回答开头写记号，不另外花钱问一次）。另一种做法是每句话前先便宜地问一次模型「是不是新话题」（更准一点，但每句多一次钱、多等一会儿） | 同意先这样；真机看切得太碎或太少，再调 2 小时这个数 |
| **933** | **记多少原话**：模型窗口现在拿不到，一律按 64K 算。当前这个话题的原话最多带一半（约 3.2 万 token）；超了就把较早那部分压成小结，最近的原话留约四成。开场再带最近 3 个话题的小结（合计最多约 1500 token） | 同意；以后照 `assistant.context` 事件里的数调 |
| **934** | **小结要花钱**：每个话题收起时、每次段内压缩时，各调一次模型，用这条对话正在用的那个模型，照常记账 / 扣积分（用量算在「助理」里）。没接模型或调失败就用规则小结（第一句话 + 交出去的事）。迁移老会话不调模型，直接用规则小结 | 同意 |
| **935** | **老会话怎么处理**：第一次打开助理页时，你所有的老会话按时间拼成一条，每条变成一段，老的会话条目删掉（话本身不删，都挪进来；交出去的事的回报也跟着挪）。老的会话接口留着，界面不再用 | 同意（还没有真实用户） |
| **936** | **「dsh 会话按段轮换」这条怎么算做完**：助理每一轮本来就是服务端直接调模型的一次性调用，三个运行时都一样，没有一个越聊越长的 dsh 会话可以轮换。所以现在的做法是：每一轮都按「当前段」重新拼上下文，效果就等于每段开一个新会话。官方和社区的压缩 / 会话搜索插件都要挂在 dsh 会话上，所以没接，只搬了官方的小结写法 | 同意；哪天助理真的改成跑在 dsh 会话里，再换成官方的 `dsh-compaction-basic` |
