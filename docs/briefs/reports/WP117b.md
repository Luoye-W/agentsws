## 2. 自主做的决定（白话）

- **#19 的根因不在界面，在装配**。demo 里有两本审批账：模拟世界的一本（演示卡），服务进程自己的一本（运行中的服务 stage 出来的卡，比如红人的开发信）。网关和工作台只读世界那一本，所以开发信卡批都没地方批；批了之后也没人施行——批了 ≠ 发出去，中间还差执行器那一拍，而服务进程这一本从来没人发起施行。修法是三件套：`compositeApprovals`（两本账读合并、决定各回各家）、`Server.drainApprovals()`（把批准了、过了取消窗口的卡施行掉）、demo 的 drain 每两秒两本一起扫。生产没挂模拟世界，走的是原来那一条，一行没动。
- **e2e 的断言只认数字不认文案**：状态带上的「已发 1」「回信 1」只有在信真的进了演练收件箱、回信真的被收回来时才会动，文案对不对让截图说话。
- **追踪链接的 `campaign` 从必填改成可选**（见 5 里的 bug 2），默认值用活动 id / 合作 id，不用人起的名字——UTM 会出现在公开链接上，id 稳定不重复。
- **e2e 脚本可重跑**：每次先清掉上一轮的 `kol-e2e-*` 截图，免得半截的一轮留下孤儿文件冒充证据。
- 顺手修了 `scripts/verify-changed.sh` 在 macOS 自带 bash 3.2 下的解析 bug（变量名后紧跟全角 `）` 被吞进变量名，脚本直接 unbound variable 挂掉），`${workers}` 加了花括号。
