# WP331 报告：周报「能力化」——拆掉专用 Reddit 周报，改成通用积木 + 工坊被几句话自己配出来

分支 `wp/331-reportcap`（从 10-15 main `4a752af8` 建）。没推、没合、没打 tag、没发版。全程没读 `.env*` / `.dev.vars`、没碰任何 key / token / 账号、没调真实付费接口（真模型评测只写好、没跑）、没打开真实 Reddit、没连远程机器、没碰 4317；数据全用替身。WP329 的文件没动。

## 0. 一句话

周报不再是功能：用户在担 Reddit 的岗位里说「每周五下午 5 点给我出一份 r/inmoxr 周报，数据周日到周五：①…②…③…④…」，AI 用**已内置的官方「自动化任务」**建一条每周五 17:00 的定时（提示词 = 这段要求）；到点那次运行里用**四个通用工具**取数、按要求写、发布到报表区；用户再说「把第三节放最前面」，AI 改那条定时的说明，下一份顺序就变了。我们只做积木，不写任何客户 / 平台的专用周报。

## 2. 留了什么（作积木的内部实现，不再有「周报」这个概念）

- 时间窗、计数（按平台上的发出时间进窗口、同一条只算一次、被删的照样计数不引用）、按话题归组（取组里最重的判断档、按严重度排）、回帖子 / 回评论 / 发帖的分法——从 WP330 的纯函数挪成通用的 `packages/social-core/src/watch-query.ts`（`resolvePeriod` / `queryWatchItems` / `summarizeSent`），不认平台。
- WP328 的巡查库 → 通用 `WatchSource`（`apps/server/src/reddit-watch/watch-source.ts` 的 `redditWatchSourceOf`，条目是通用契约 `WatchItem`）；`sweepNow` 留着给「立即巡查」用。
- 记录去处「只有点名才记」（决策 768 的口径）留着，动作改叫 `report`，点名了就记、不再看渠道。
- 「复制整份 / 导出 .md」留着，挪到通用的报告报表块上。

## 3. 四个通用工具与报告卡的接口

定义在 `packages/stand-ins/src/runtime/report.ts`（stub / direct / dsh 同一份；dsh 那一档经 `packages/dsh-adapter/src/tools.ts` 原样转），执行在 `apps/server/src/report-tools.ts`。名字与描述不带平台、不带客户。

| 工具 | 入参（都可选，除注明） | 回什么 | 谁有 |
|---|---|---|---|
| `query_watch_items` 查巡查数据 | `period`（today / yesterday / this_week / last_week / last_7_days / this_month / last_month，默认最近 7 天）、`week_start`（0 周日…6 周六，默认周一）、`since` / `until`（ISO 或本地 `YYYY-MM-DD`）、`platform`、`scope`（own / external）、`assessment[]`（follow_up / no_action / low_relevance）、`topic`、`keyword`、`signal`（voc / ugc / any）、`kind`、`group_by: topic`、`limit` | `window{since,until,start_date,label}`、`sweeps{count,last_at}`、`totals{items,posts,comments,own,external,voc,ugc}`、`items[]` 或 `groups[]{topic,posts,comments,assessment,items[],more}`；每条原文 = 作者、地点、时间、链接、截断过的原话；时间窗认不出回 `problems` | 担巡查的职责（现在 `social.reddit` / `pr.reddit`） |
| `run_watch_now` 立即巡查 | `platform` | `{ok, finished_at, parts[{part,status,fresh,message}]}`；不能现巡 / 没读成回 `ok:false` + 一句人话（报告照样用已入库的出）；最多等 5 分钟 | 同上 |
| `query_sent_records` 查发出记录 | 时间窗同上、`channel`、`actions[]`、`limit` | `totals{all,by_action,replies_to_posts,replies_to_comments,new_posts}`、`records[]{at,channel,action,target,destination,thread_title,thread_url,link,text}`；默认只算已发、报告那一行不算 | 所有职责（接了发出记录才有） |
| `publish_report` 发布报告 | **`title`、`period`、`markdown`**（必填）、`period_start`（YYYY-MM-DD）、`series` | `{ok, report_id, version, recorded?}`；校验不过回 `problems` | 所有职责 |

**报告卡**（报表块）：
- 审批项 `kind: weekly_review`（与经营一页纸同一类，在 `NOT_A_CARD` 里：不进审批队列、出现在这条职责的报表区），`role_id` = 发布它的那次运行的职责，发给那次运行的人，`priority: digest`。
- payload = 契约 `ReportPayload`（`packages/contracts/src/report.ts`）：`{kind:'report', series, title, period, period_start?, markdown, published_at, version}`。
- 去重键 `dk_<品牌>|report|<分配>|<系列>|<周期起点或周期>`：同一系列同一周期再发 = 同一张出新一版（`version` +1）；换了周期就是新的一份。
- 工作台 `apps/workstation/src/components/deck/report-body.tsx`：一行周期（第 2 版起带「第 n 版」）+ 右上「复制整份」「导出 .md」两个小图标 + 正文（工作台唯一的安全 Markdown，不解析 HTML、不加载图片）；超过 1200 字先收一截、点「展开」看全。报表块与卡详情都认它（看 payload 形状，不看卡种）。
- 记录去处：筛选里点名动作 `report` 的去处，每发一版记一行（渠道 `report`、标题带版号、正文 = 整份 Markdown）。

## 4. 验收：场景测试与真模型评测

**一份用例两种跑法**：`evals/report-as-capability/weekly-report.json`（`state` 替身数据 + `turns` + 每轮 `expect`）+ 评测台 `evals/report-as-capability/harness.mjs`（纯 JS，vitest 与 node 脚本共用）。

用例四轮：
1. 说「每周五下午 5 点给我出一份 r/inmoxr 周报，数据周日到周五：①帖子数评论数 ②有效 VOC / UGC ③外部舆情按话题归组带判断和原文链接 ④我们本周回复数和链接」→ 要调 `schedule_create`、只有 1 条定时、每周五 17:00；
2. 到点（周五 17:00）→ 要调 `query_watch_items`、`query_sent_records`、`publish_report`；第 1 版；各节顺序 数据 → VOC/UGC → 外部 → 回复；数据那节有 3（帖）/ 4（评论）、VOC 那节有原帖链接、外部那节有外部原文链接、回复那节有我们两条回复的链接；上周的回复和评论不能出现；
3. 说「把第三节放最前面」→ 要调 `schedule_update`、没再 `schedule_create`、还是那 1 条、说明改了；
4. 再到点 → 同一周期第 2 版，各节顺序 外部 → 数据 → VOC/UGC → 回复。

打分只看结果（建了什么定时、报告的版号、各节顺序、链接在不在）和用到的工具，不看措辞；各节按节标题认（外部 / 舆情 / 话题 → VOC / UGC → 回复 / 我们 → 帖子 / 评论 / 数据）。会往外发的定时按现有规则先出卡时，评测台替用户点「批」并记一笔。

**stub 场景测试**（已跑，全过）：`apps/server/test/wp331-report-scenario.test.ts`——真服务进程 + stub 运行时（脚本化工具调用：`packages/stand-ins/src/runtime/report-playbook.ts`，到点按提示词里编号的几项逐项认要什么数据、按顺序拼；「把第 N 节放最前 / 最后」改提示词重新编号）。28/28 项过；另钉了报表块不进审批队列、挂在发布的职责上、老周报定时重启后取消。

## 6. 自主做的决定（白话）

1. **报表块不新造卡种**：沿用 `weekly_review`（报表、不进审批队列），payload 自己认得出（`kind: report`）。卡详情上的类别字还是「经营一页纸」（见决策 771）。
2. **「立即巡查」由 AI 自己决定调不调**，周五那次不再强制；最多等 5 分钟，没读成照实说、照样出（见决策 772）。
3. **同一份 = 同一个人在同一条职责下的同一系列 + 同一周期起点**：系列名 AI 给（不给用标题），周期起点用查数据工具回的 `window.start_date`。同周再发是新一版，不会一周两张（见决策 777）。
4. **工具分权**：查发出记录、发布报告所有职责都有（和记录去处一样，发出记录本来就是品牌一份、右栏谁都看得到）；查巡查、立即巡查只给担巡查的职责（见决策 775）。
5. **记录去处一版一行**：同一周期再发也写新的一行，标题带「第 n 版」，表里能看出改过（见决策 774）。
6. **报告那一行点名了就记、不看渠道**：报告不属于哪个渠道，筛选里只写了「Reddit」的回复表不会因为点了 `report` 却被渠道挡掉。
7. **契约删了 `reddit-weekly.ts`**：派工单要拆「周报」这个概念；通用接口回到 `report.ts`（见决策 770）。
8. **真模型评测台与 stub 场景测试共用一份用例与打分**：stub 跑过就证明评测台本身没毛病，真模型没过时只可能是模型 / 提示词 / 工具描述的事。
9. **正文超过 1200 字先收一截**（界面少字）；导出文件名用标题。
