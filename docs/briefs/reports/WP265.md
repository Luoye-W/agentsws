# WP265 报告：连接页「连接 Shopify」一键授权（接云 WP263）；老的客户端 ID 表单收进「高级」；账号令牌加 `store`

分支 `wp/265-shopconnect`（worktree `agentsws-wt/wp265-shopconnect`），Claude 子代理。已合 main（含 WP261、WP264），合完 `tsc -b` 后重出 SDK / 本体；未推送、未合并。

## 0. 一句话

连接页 Shopify 卡的主按钮现在是 **「连接 Shopify」**：店铺域名自动带上（品牌档案 → 建站找到 / 选定的店 → CLI 店铺清单 → 老连接），点一下 → 本机用这个品牌的 Agents 工坊账号令牌调云 `oauth/start`（带 `brand`）→ 系统浏览器打开 Shopify 授权页 → 卡上「在浏览器里点『安装』，回来就好」+ 取消，2 秒问一次 → 连上后卡上是店名、域名、能管什么、「测试连接」（云端代发一次只读查询）、「断开」；失效 / 缺权限给「重新授权」并说缺哪项。没登录账号、老令牌缺 `store`、连不上云、云上 501 各一句人话（前两种就地登录）。老的「店铺域名 / 客户端 ID / 客户端密钥」表单收进卡内「高级：用自己的 Shopify 应用」，默认看不到。店铺令牌一个字节都没进本机。

## 2. 自主做的决定（白话）

1. **老令牌缺 `store` 不预先拦**：WP263 上线那一版云查没查 `store` 我看不到（私有仓没碰）。所以本机不凭本地记的动作集先拦，照常去连；云回 403 `required_scope: store` 才在卡上说「账号授权要更新一下」。云没查的话老令牌照样能连——Fable 真机首测不用先重新登录。
2. **「一键重新签发」= 同一个账号重新登录一次**：现有云接口里，换一把带新动作集的令牌必须有账号会话（`renew` 要会话；`sibling` 只复制调用者的动作集）。所以卡上「重新登录」就地出登录表单（验证码 / 密码，邮箱预填），登录成功即换新令牌、撤旧的；登录没成什么都不动。真正不用登录的一键，需要云上加一条（见 §4）。
3. **本机换新令牌时不显式要 `store`**：如果把 `scopes: [...含 store]` 写进 `POST /v1/cloud/links`，而云上的 zod 枚举还不认 `store`，整个关联会 400。所以用云的默认动作集——云上默认集加了 `store` 之后，重新登录就拿得到。
4. **测试连接出错分两种**：没关联 / 缺动作集 / 连不上是整张卡的事（卡换状态）；店这头的问题（失效、Shopify 报错）记成这一家「没通：…」。
5. **断开时云上 404 当已断开**：按钮的意思是「不要它了」。
6. **授权页在新标签 / 系统浏览器**：与已有的 OAuth 卡同一个做法（`openExternal`），旁边留「没弹出来？点这里打开」。
7. **卡上不铺步骤**：一句话 + 一个按钮；「不用建开发者应用、钥匙在云上、AI 改之前出卡」在问号里。权限名翻成「商品、库存、页面和博客、菜单、折扣、订单（只看）、主题（只看）」。

## 4. 云端需要配合的改动（私有仓下一单）

1. **`DEFAULT_CLOUD_SCOPES` 加 `store`**：私有云如果是从开源契约拿默认集，升一下 `@agentsws/contracts` 就好；如果自己抄了一份，补上。不补的话「重新登录」签出来的还是没有 `store` 的令牌。
2. **`/v1/shopify/*` 校验 `store`**：缺的时候回 `403 { code: 'forbidden', details: { required_scope: 'store' } }`（与入口那一层其它动作集同一个信封）——本机就是认这个才说「重新登录」。
3. **（建议）不用登录的一键补签**：加一条 `POST /v1/cloud/links/current/upgrade`（工作区令牌鉴权）：把这条关联的动作集补到现在的默认集（只补「后来才进默认」的那几项，不给 `wallet:admin` / `standby`），换一把新令牌、旧的作废。有了它卡上「重新登录」可以换成一点就好。
4. **回包形状请对一下**（本机按这些读，云上多的字段忽略，少的当没有）：`oauth/start` → `{data:{attempt_id, authorize_url(https), app, scopes, expires_at}}`；`attempts/{id}` → `{data:{status, shop?, message?}}`（没这张单回 404）；`connections` → `{data:{connections:[{shop, brand?, status, reauth_reason?, scopes?, missing_scopes?, shop_name?}]}}` 或直接数组；`graphql` → `{data: <Shopify 的 {data, errors?}>}`；501 带一句人话 `message`。`brand` 存的是本机工作区 id。
5. **GraphQL 改动**：本机运营工具执行批过的卡时带 `allow_mutations: true`；查询不带。云上请对「不带却是 mutation」拒掉（本机也先拒了一道）。GraphQL 的 `errors`（含 `ACCESS_DENIED` / `Required access: \`write_x\``）请原样放在 `data` 里转回，本机靠它认缺哪项权限；店铺令牌失效请回 409 或 `details.reason: 'reauth_required'`。
6. **应用 B / A 的权限补 `read_publications`、`write_publications`**（店铺管理「上架到销售渠道」要；docs/92 那一套没有），发新版本；`connections` 回的 `scopes` / `missing_scopes` 会跟着变，岗位页那一行自然从「缺」变「已授权」。

## 6. 给 Fable 的真机首测步骤（Windows，Rollout `6suegp-md.myshopify.com`）
