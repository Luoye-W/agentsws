## 2. 我自己拍板的（白话）

- **「要不要你」多了一格「只是通知」**。docs/88 §3.1 说只有两种状态，但同一节又说通知「不算没人接」、单独成捆——所以派生值做成三种：没人接 / 只是通知（AI 判了不用回、还没点知道了）/ 已交出去。点了「知道了」就进已交出去。
- **一条会话交给过岗位，就一直算已交出去**，之后同一会话的新来信也不再催（「交出去后只在卡片流里」）；而「只是通知 / 我自己处理 / 回过了」之后对方又来一封，会重新回到没人接——那是新的一件事。
- **交给客服 / 红人 / B2B 仍走 63 的老路**（开事项、判断层、挪信都照旧），其余岗位走 54 的「交给这个岗位一件事」。交出去的事项钉着这条会话，所以卡片证据里能找回原件。
- **类型的把握**：发件人规则给的、你改过的一律不写把握；其余把握低于 80% 写「像是 X · 把握 N%」。
- **「以后这个发件人都这样」默认勾着**（改判层和「交给 X」旁边各一个）。勾了写发件人规则；交给 63 那三条路的岗位时规则里也带路由（下一封直接自动交，与 WP167 的「挪到客服 + 记住」同一效果）；交给其余岗位的规则只让下一封的主按钮直接是那个岗位（第一版除了 63 那三条，其余岗位"只建议"，docs/88 §3.3）。
- **没勾「记住」的纠正进 lesson 池**，技能名 `message-triage`。这个技能还没有可以改的段落，所以夜里的提案会按「没有可落的段」滤掉、不会出卡；它们在「你教过它」里看得见。docs/88 说"同类改动够多了出一张选择卡"——那张卡要等给分拣建一份技能再做。
- **「卡片流里 N 张等你批」只数与消息相关的卡**（卡上钉着的线程 / 事项对得上一封信），不是全部待批卡。链接去首页；「有 N 张卡等你 →」去那件事项的事项页（事项页列着它的卡），docs/88 说"跳到那张卡、高亮"，现在没有按卡 id 定位的深链，先落事项页。
- **「交给 X ▾」里列哪些岗位**：与消息相关的五个常驻（客服 / 红人营销 / B2B / 公共关系 / 社媒运营，没开的灰着），其余岗位开着才列在后面；只有通用职责的岗位（普通成员）不列。
- **「我自己回」**在「没人接的」里点：切到「全部」打开这条会话、写信框直接开好（人自己按发送，发出后这条会话自动算已交出去）。账单与系统通知那一类写「我自己处理」，点了直接记成你自己处理（可撤销）。
- **「只是通知 / 我自己处理」能撤销**；「交给 X」不给撤销——交出去那一刻已经开了事项、可能起了 Run，撤销要连事项一起收，留给后面（见 §5）。
- **提示条改成 `fixed` 贴在窗口底部**：「没人接的」一页很长，原来 `absolute` 贴在页底会看不见。
- **模拟报告**：`kind` 进事件与结果，但不做成指标——基线只比指标，所以三包 × 三运行时零漂移、不用重写基线。

## 3. 需要 Luoye 定的事

1. **「交给 X」要不要能撤销**：现在只有「只是通知 / 我自己处理」能撤销。交给岗位之后已经开了事项、可能起了 Run；要撤就得同时关掉那件事项。要不要做？
2. **交给非 63 岗位时勾「记住」，下次是"直接自动交"还是"只把它做主按钮"**：现在按 docs/88「第一版其余全是只建议」做成后者。要不要给每个类型一档「只建议 / 自动交」（docs/88 §3.3 的信任逐档）？
3. **分拣技能**：没勾「记住」的纠正现在只进 lesson 池、不出卡。要不要建一份 `message-triage` 技能（有段落），让同类纠正够多时出「以后 X 都交给 Y？」那张选择卡？
4. **「负责人」岗位要不要出现在「交给 X ▾」里**：demo 里负责人岗位带着非通用职责，所以列出来了。要不要把负责人整个排除？

## 9. 追加（Fable 09-30 定了四问之后）

Fable 的答复：① 「交给 X」不做撤销，交错了在事项页转岗位（事项页现在已有「路由到 X · 换」换职责；跨岗位转交没有，列进后续）；② **勾了「记住」，下一封直接自动交出去，所有岗位都一样**；③ `message-triage` 技能另开一单；④ 「负责人」不进下拉。三种状态的偏离接受，docs/88 §3.1 / §3.3 各补了一句。

这次做了 ② 和 ④：

- **记住 = 自动交**：客服 / 红人 / B2B 仍靠规则里的 `route`（分拣直接交）；其余岗位新接了一个口——消息同步分拣完、信留在收件箱时（`MailboxSync` 只加 `after_triage`），如果是发件人规则给的岗位，就用教这条规则的人直接交给那个岗位（同一条 `handToPosition`，与人点「交给 X」走同一段代码），信上记 `handled`、钉事项，写一条 `messages.route_confirmed`（`by: 'sender_rule'`）。交不出去（岗位关了、那人名下已没有这个岗位的职责）就留在「没人接的」里，主按钮仍是那个岗位。自动交出去的照常计入「已交给岗位」，阅读区里的类型胶囊照样能改判。
- **「负责人」不进下拉**：岗位 id `owner` 在消息面这一层就滤掉（`NOT_HANDABLE_POSITIONS`）。
- 测试（`apps/server/test/messages.test.ts` 加 3 条）：勾了记住 → 同一发件人下一封直接交给公共关系、不调模型、计数 2、能改判、事件带 `by: sender_rule`；没勾 → 下一封照旧只建议；负责人不在岗位清单里。
