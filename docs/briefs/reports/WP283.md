# WP283 报告：生图收尾——打云带「谁」、圈区域按型号给、gpt-image-1.5 指到 2（决策 310 / 300 / 301）

分支 `wp/283-imgfix`（worktree `agentsws-wt/wp283-imgfix`），Claude 子代理。未推送、未合并。没调任何真实模型或付费接口，私有云只读。

## 0. 一句话

生图、改图、向量打 Agents 工坊云时现在都带 `X-Agentsws-Member` / `X-Agentsws-Position`，和对话那一路一样。插件那一路（reveal 按次扣积分、观测转发）记在配对插件的那个人身上。改图认不认遮罩由**一张型号能力表**判断：经云的型号（OpenRouter 上的 GPT Image 2.5 / 2 / 1 / 1-mini、Nano Banana 2.1，以及 Seedream）都不认；自己的 OpenAI key 直连认。不认的型号，事项里加的图上不出现「圈出要改的地方」；给了遮罩也不往上游带，回话里会说一句。本机设置里存的 `gpt-image-1.5`，读的时候当 `gpt-image-2`，写的时候也不存它；型号清单里不再出现 1.5。

## 2. 自主做的决定（白话）

1. **301 用「读时映射」，不写迁移**：文件里的老值不动，读的时候换成 2；只要有人再存一次，就存成 2。这样「跟随公司默认」、从别的品牌复制设置、导入老工作区，一处函数全管住，也不用动用户文件。测试里钉了：手改文件写回 1.5 再重启，读出来是 2，文件原样。
2. **1.5 对自己的 OpenAI key 也映射到 2**：OpenAI 官方其实还能用 1.5，但决策 301 说的是「指到 2」，同一档价、同一套画布，一条规矩更简单。
3. **Seedream 当「不认遮罩」**（和派工单写的「Seedream 等支持的照旧」不一样）：私有云白名单 Seedream 的 `mask: false`，云端会把遮罩去掉；WP268 调研也写了 Seedream 没有遮罩、New API 豆包插件带遮罩会报错。所以给它入口反而会骗人。结果是**走积分出图时没有任何型号能圈区域**，只有自己的 OpenAI key、或者自定义接口的 `gpt-image-*`，才有入口。
4. **入口放在事项输入框里加的图上**：改图本来就是在事项里说「拿这张图改」。素材库页暂时不加。
5. **「给不给入口」跟着传图回包走，不读生图设置**：`GET /v1/models/image` 要 `store_config.read`，普通成员读不到（和 WP282 撞见的 403 是同一类）。传图本来人人都能做，回包顺带一个布尔就够了。
6. **型号不认时遮罩悄悄去掉，回话里说一句**（不报错）：和云端「差异在云端抹平」的口径一致，人照样拿到图，也知道圈的区域没用上。
7. **插件那一路只记人、不记岗位**：插件令牌上只写了是谁配的对，分不出岗位。

## 3. 要 Luoye 定的事（逐条，附建议）

1. **走积分出图时没人能圈区域（Seedream 也不认遮罩）**：派工单以为 Seedream 支持，实际不支持。**建议**：先这样。等哪天云上有认遮罩的型号（比如 OpenAI 原生渠道恢复、或者接 FLUX Fill），私有云白名单和本机能力表各改一格，入口就会自己出来。
2. **圈区域是这单新做的界面**（原来没有入口，派工单以为有）。**建议**：保留。现在只对自带 OpenAI key 的人可见，成本很低；嫌多余也可以整个拿掉，能力表与「不认就不带」那部分照样有用。
3. **遮罩图进品牌素材库**（用途标 `mask`，素材库页会看到，状态「选中」）。**建议**：下一小单让素材库页默认不显示 `mask` 标的图（加一个筛选就看得到）。
4. **公司级订阅（值守按月座位、托管客服、在线聊天转发）不带归属头**。**建议**：保持算公司。按人记的话，某个成员的月额度用完会挡住全公司的服务。
5. **私有云白名单里 `gpt-image-1.5` 那一行**（WP280：OpenRouter 上没有，走 New API 原生会 4xx）。本机已经不会再发 1.5 了，但没升级的老工作台还会发。**建议**：私有云下一单在白名单把 1.5 指到 `gpt-image-2`（或者直接按 2 转发）。
6. **后台作用域外的打云调用**（不在请求或运行里的那几处定时刷新）仍落进「没标注」。**建议**：保持（本来就是公司的事）；真要细分，合并关口全量跑时列一份清单再定。
