# WP253 报告：建站岗位端到端——AI 用工作台私有 Shopify CLI 改主题（agentsws-theme 起底）→ 未发布预览 → 发布走审批卡

## 0. 一句话

建站岗位的「网页模板」职责现在有了**九个受限主题工具**（不是终端）：从开源主题 agentsws-theme 的钉死版本起底 → 看 / 改工作目录里的文件 → 官方 `theme check` → 推成**未发布**主题拿预览链接 → 想发布只能出一张 `publish_theme` 审批卡，人批了服务端才跑 `theme publish`。CLI 用 WP245 的私有安装与按品牌登录记录；岗位页顶上一行告诉用户还差哪一步（装 / 登录 / 店铺地址），一个按钮补上。

## 3. 自主做的决定（白话）

- **不走终端，走受限工具**：派工单要「受限主题工具，不是任意终端」，而生产里终端那一路本来就没接通（没有 `req.shell`、没有 `stage`）。我没去接终端，九个工具全在服务端执行，AI 摸不到命令行。
- **钉 commit 不钉 tag**：主题仓库没有 tag / release，钉的是 10-06 最新 commit `f6546c2`（package.json 0.8.0），sha256 是两次下载对过的。升级改 `THEME_BASE` 三样。
- **起底包从 GitHub 下**（约 630 KB，服务进程的 fetch，不走系统代理）：没打进安装包（见 §4 第 6 条）。
- **登录凭据不经我们**：主题命令不传任何令牌，靠 CLI 自己 `auth login` 的会话；子进程环境照旧走白名单（测试钉住了 `AGENTSWS_SECRETS_KEY` 等一个都不传）。
- **店铺地址存品牌目录的 `site-theme.json`**，没动品牌档案契约（WP251 在动那块，避免撞车）。
- **「改了哪些文件」相对起底 / 拉下来那一刻**（按 sha256 清单比），不依赖用户机器有 git。
- **核心文件围栏只对 agentsws-theme 起底的目录生效**；拉别的主题下来改时只限主题八个目录。
- **同名再推更新同一份**：免得试几轮就在店里堆到 Shopify 的 20 份上限；推之前先确认那份不是线上的。
- **发布卡路由给 owner**（职责 yml 的 `route_to: owner`），L1，hard_ceiling 由 guardrail 再按一次。
- **网页模板以外的建站职责（整站搭建 / 邮件 / 插件）不给主题工具**；实测「用 agentsws-theme 给我搭个首页」「给我搭个首页」「预览看过了，发布上线」岗位内路由都落到网页模板。

## 4. 要 Luoye 定的事（建议附后）

1. **agentsws-theme 的许可证是 MIT，不是派工单写的 Apache-2.0**（仓库 LICENSE 与 package.json 都是 MIT，也没有 NOTICE）。我们照带 LICENSE，两种都合规。**建议：保持 MIT**，文档口径改成 MIT；若想要专利条款再把主题仓库改成 Apache-2.0 并加 NOTICE（我们这边不用改代码，只改钉子）。
2. **主题仓库打 tag**：现在只能钉 commit。**建议：给 agentsws-theme 打 `v0.8.0` 并发 release，把它登记进 `upstreams.yml`**（以后升级走 docs/42，改 commit + sha256）。
3. **网页模板职责的 Shopify 连接还是「必需」**：岗位页顶上那条黄条「还缺必需的连接：Shopify 店铺」会一直在（见截图 1），可主题这条路有 CLI 登录 + 店铺地址就够了，不需要 Dev Dashboard 应用。**建议：下一单把 `site.shopify-theme` 的 shopify 连接改成可选（或「CLI 好了就算满足」）**，免得用户被引去做技术性的 Dev Dashboard 设置。
4. **一台电脑的 CLI 登录是整机共用的**（WP245 已说）：INMO 与 Rollout 若用不同 Shopify 账号，给一个品牌登录会顶掉另一个，另一个品牌的推送会报没权限。**建议：Luoye 用同一个 Shopify 账号（在两家店都是协作者 / 员工）登录**；真要分账号再开单做「推之前按品牌换会话」。
5. **改样式的边界**：agentsws-theme 的 `assets/app.css` 是 Tailwind 构建产物，AI 不能手改，也没有构建工具——只能用主题已编进去的类（CLASS_VOCAB）与设置。**建议：先这样**（主题的规矩本来就是 L0 设置 / L2 组合优先）；真需要新样式再加一个受限的 `theme_build_css`（用随包 node 跑钉版本 tailwind）。
6. **国内网络下 codeload.github.com 可能下不动**（服务进程 fetch 不走系统代理）。**建议：把钉死的那份 tar.gz（约 630 KB）随安装包带一份作兜底**（体积很小，不违反「不打包重型运行时」），下载失败时用随包那份，sha256 同一个。
7. **终端那一路（WP89 bash 沙箱）要不要继续留**：生产里没接通，发布物化也缺 `stage`。**建议：建站岗位以受限工具为准，终端那一路先停着不接**（等真有「工具做不了」的需求再说）。
