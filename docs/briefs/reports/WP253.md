# WP253 报告：建站岗位端到端——AI 用工作台私有 Shopify CLI 改主题（agentsws-theme 起底）→ 未发布预览 → 发布走审批卡

## 0. 一句话

建站岗位的「网页模板」职责现在有了**九个受限主题工具**（不是终端）：从开源主题 agentsws-theme 的钉死版本起底 → 看 / 改工作目录里的文件 → 官方 `theme check` → 推成**未发布**主题拿预览链接 → 想发布只能出一张 `publish_theme` 审批卡，人批了服务端才跑 `theme publish`。CLI 用 WP245 的私有安装与按品牌登录记录；岗位页顶上一行告诉用户还差哪一步（装 / 登录 / 店铺地址），一个按钮补上。

## 3. 自主做的决定（白话）

- **不走终端，走受限工具**：派工单要「受限主题工具，不是任意终端」，而生产里终端那一路本来就没接通（没有 `req.shell`、没有 `stage`）。我没去接终端，九个工具全在服务端执行，AI 摸不到命令行。
- **钉子只在一处**（第二轮，Luoye 决定 137）：`apps/server/src/theme-base-pin.json`（`repo / tag / version / commit / sha256 / license / bytes`），`THEME_BASE` 直接读它。现在钉 **v0.9.1 → commit `be73de4`**（sha256 `6a1db7e7…`，628,910 字节，按 commit 下两次相同；之前临时钉过 v0.9.0，它主题自己 verify 红，已换掉）；下载按 commit 不按 tag（按 tag 下的包目录名与校验值都不同）。`upstreams.yml` 登记 `agentsws-theme`（`pinned_tag` + `pinned_commit` + `pin_file`），`check-upstreams --check` 对账；docs/42 加「按 tag 钉的上游怎么升」。**换新 tag 只改 `theme-base-pin.json` 一个文件 + `upstreams.yml` 那一条的 tag / commit 两行**（不改两边 `check-upstreams` 就红）。
- **起底包从 GitHub 下**（约 630 KB，服务进程的 fetch，不走系统代理）：没打进安装包（见 §4 第 6 条）。
- **登录凭据不经我们**：主题命令不传任何令牌，靠 CLI 自己 `auth login` 的会话；子进程环境照旧走白名单（测试钉住了 `AGENTSWS_SECRETS_KEY` 等一个都不传）。
- **店铺地址存品牌目录的 `site-theme.json`**，没动品牌档案契约（WP251 在动那块，避免撞车）。
- **「改了哪些文件」相对起底 / 拉下来那一刻**（按 sha256 清单比），不依赖用户机器有 git。
- **核心文件围栏只对 agentsws-theme 起底的目录生效**；拉别的主题下来改时只限主题八个目录。
- **同名再推更新同一份**：免得试几轮就在店里堆到 Shopify 的 20 份上限；推之前先确认那份不是线上的。
- **发布卡路由给 owner**（职责 yml 的 `route_to: owner`），L1，hard_ceiling 由 guardrail 再按一次。
- **网页模板以外的建站职责（整站搭建 / 邮件 / 插件）不给主题工具**；实测「用 agentsws-theme 给我搭个首页」「给我搭个首页」「预览看过了，发布上线」岗位内路由都落到网页模板。

**⑤ 真机 bug：`shopify auth login` 非交互必须带 `--alias`（Fable Windows 真机，CLI 4.8.5）。** 依据（`npm pack @shopify/cli@4.8.5` 到临时目录读发行包，没装）：

- 基类 `parse()` 里 `failMissingNonTTYFlagRequirements`：非 TTY 时 `auth login` 不带 `--alias` 直接抛「Flag not specified: --alias」。
- `auth login --alias X` 的逻辑：X 能在已存会话里按别名 / 用户 id 找到 → 只切「当前会话」、打「Current account: X.」退出；一份会话都没有 → 设备码登录，**存下的别名是账号邮箱**（不是 X）；已有别的会话而 X 找不到 → 弹「Which account would you like to use?」——非 TTY 下抛「Failed to prompt」。
- `theme *` 命令都有 `--auth-alias`（env `SHOPIFY_FLAG_AUTH_ALIAS`）：只在这一条命令里换会话；按别名 / 用户 id 找不到就报「No authenticated account found for alias」。
- 会话存在 `conf` 的 `shopify-cli-kit` 配置里，路径来自 `env-paths`：mac `$HOME/Library/Preferences/shopify-cli-kit-nodejs`、Windows `%APPDATA%\shopify-cli-kit-nodejs\Config`、Linux `$XDG_CONFIG_HOME/…`——**整台电脑默认一份**。

所以「`auth login --alias` 切会话」与「`SHOPIFY_FLAG_AUTH_ALIAS`」在 4.8.5 下都不可靠（第二个品牌登不进去、别名对不上邮箱）。最可靠的是**每个品牌一份 CLI 配置目录**：替用户跑 CLI 时把 `HOME` / `APPDATA` / `LOCALAPPDATA` / `XDG_*` 指到 `<数据目录>/tools/shopify-cli-sessions/<品牌>/`（`platform-cli-session.ts`）。登录照带 `--alias agentsws-<品牌 id>`（满足非交互检查）；每份配置里永远只有本品牌那一个会话，主题命令不用换会话；重登先把原来那份挪成 `.prev`（登好删、没登成挪回）。**决策 138 顺带解决：不同品牌可以用不同的 Shopify 账号。**

- 登录输出：「User verification code: XXXX-XXXX」「Opened link to start the auth process: https://accounts.shopify.com/activate-with-code?…」两行都认（确认码、网址、CLI 自己开了浏览器就不再开），测试照真机原文钉住。
- 老用户：WP253 之前在整台电脑那一份登过的，网页模板会提示再登一次（「登好了」= 记过一笔 **且** 本品牌那一份会话目录在）。连接页 / 岗位设置的 CLI 卡仍按「记过一笔」判，可能显示已登录——点岗位页那一行的「登录 Shopify」即可。
- 假 CLI：非 TTY 不带 `--alias` 照 4.8.5 报那一句退出 1；会话按 HOME 分开、存下的别名是邮箱、已有会话而别名对不上就「Failed to prompt」——「共用一份时第二个品牌登不进去」也有测试。
