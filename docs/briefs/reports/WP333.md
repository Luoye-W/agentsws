## 2 每件做了什么（白话）

**① 700 FAQ 金额不降级**（`packages/knowledge/src/store.ts`）

- 知识卡进库时那道「状态词」闸（47 J2）多认一种情况：卡是从表格导入的 FAQ（`subject.type = 'faq'`）时，**金额那一条不算**——「满 $50 包邮」「运费 9.9 元」照样是事实层，不再降成「当时的情况」。
- 订单号、物流状态、库存数、支付流水照旧降（同一句里又有金额又有订单号，照样降）。别的卡（不是 FAQ 表导入的）带金额照旧降。
- 做法是给 `downgradeOf` 加了一个可选参数「这几类这次不算」，`propose` 按 `subject.type` 传；公开签名只加不改。

**② 584 个人微信卡片链接页**（`apps/workstation/src/pages/card.tsx`）

- 个人微信里卡片那条链接 `/cards/<卡号>?brand=<品牌>`，以前工作台没这条路由、落到首页。现在打开**就是那一张卡**：和首页牌堆同一个卡片样子、同一套按钮；还没定的照常能定（决定带这张卡所在职责的那条分配）。
- 定过的：卡照样能看（状态签是「已处理」、只剩「打开」，不另加一行字）。卡号不对 / 不在这个品牌：一行「找不到这张卡（可能不在这个品牌，或已经撤下）」+ 左上「首页」。
- 品牌那一格照 WP311：外壳先切品牌（或说进不去），再开这一页。

**③ 633 库存告急数**（`apps/server/src/live-data.ts`、`packages/deck/src/queries.ts`）

- 面板活数据在订单拉完之后，看店铺管理授权（云端一键授权优先、CLI 店铺授权其次）里**有没有 `read_inventory`**：有就顺手经只读 Admin GraphQL 拉一轮库存（新查询 `AgentswsLiveInventory`，只要可售数 ≤100 的规格，一页 250、最多 4 页；不跟踪库存的、没上架的丢掉；不带任何顾客数据，库存行只在内存里，事件里只有条数）。
- 读不到（没授权 / 没这个权限 / 撞上授权问题）→「库存告急数」和库存告急表**照实显示没连**（数字块是「去连接」，不再出一个假的 0）；断网 → 留上一份。销售额、订单数那几块不受影响。
- 连接器里的老店铺连接（自定义应用令牌）那条路本来就没有库存动作：订单照旧走它，库存也经店铺管理授权读；两样都没有就是没连。
- 积木那边：命名查询多一个可选的「这份数据有没有」判断，库存两块没有库存来源就出 `not_connected`；日报卡那一行写「没连」而不是「0 个 SKU」。首页岗位卡那一句状态本来就跳过没连的块，所以也不会再出「库存告急 0」。
- 假店替身认这条新查询（演示 / 端到端用）。

**④ 客服起草用上品牌语气**（`apps/server/src/support-voice.ts`）

- 写客服回信的职责（挂了 `customer-care`、没挂 `brand-voice` 的：`dtc.support` 邮件、`dtc.live-chat` 聊天、`amz.support`）每次运行，提示词里多一段**品牌话术**，与社媒（Reddit 起草）是同一个 `voicePrompt`，正文原样引用、一个字不改写。网站聊天窗的那一轮回答材料里也带上。
- 「设置了语气卡」= 这个品牌自己写过 `brand-voice`（公司 / 岗位 / 职责 / 个人任何一层）。**只有随软件带的基础版 = 没写过，照旧一个字不多**。
- 社群客服本来就挂了 `brand-voice` 技能（技能正文里已经有），不重复注。每次现取：话术改了，下一次运行就是新的。

## 3 自主做的决定（白话）

1. 700 只认 `subject.type = 'faq'`：现在只有表格导入会产这种卡，不另加一个「来源」字段。
2. 584 卡片页不放牌堆（不翻页、不出别的卡）：链接就是为这一张来的；看完点「首页」回牌堆。
3. 584 定过的卡还给看，不跳走：人点微信里那条链接时多半想知道「这张后来怎么样了」。
4. 633 只拉可售 ≤100 的规格：面板阈值默认 5、职责里能调高，100 留足余量；全店几万个规格不用全拉。
5. 633 不跟踪库存的规格不算告急（它的数永远是 0）；没上架的也不算。
6. 633 读库存的条件是「授权里有 `read_inventory`」而不是「先试一下」：没权限时不白打一次必然失败的查询。
7. 客服语气只认品牌自己写过的那一份，不把基础版硬塞进客服提示词（派工单「没设置语气卡就照旧」）。
8. 客服语气也接了网站聊天窗（它也是在给客户写回复）。
