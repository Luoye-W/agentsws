## 1 一句话

投放的 Google / Meta 职责页上多了一块「素材流水线」：传一张后台导出的广告表 → 挑出表现差的 → 标题、描述两个子 Agent 各写一份新版本（本地按平台条数 / 字数 / 禁用词过一遍，拆字绕过审核的一律挡下）→ 下载上传表（新建一律「已暂停」，人自己去后台传）/ 交设计岗批量出图（L3 下单 → 设计岗出变体 L2 给人挑 → 入库 L1，广告设计放宽到每单 30、每天 100）→ 每一轮记「假设 / 改了什么 / 结果」，下一轮带进两个子 Agent 的上下文。**全程不碰广告后台。**

## 4 自主做的决定（白话）

- **字数按平台的口径数**：Google 后台中文一个字算 2，所以中文标题最多 15 个汉字；Meta 按字符数。`spec.ts` 里原来的 `checkAgainstSpec` 按字符数，没动它（别处在用），流水线用自己的数法。
- **拆字绕过单独一类**：直接写禁用词叫「禁用词」，拆开 / 换写法叫「绕过」，两句话不一样；都不替它改，只回理由。
- **「表现差」的基准用同一张表的中位数**，不用「行业平均」（没有出处的数不进判断）；样本门槛给了默认值（见决策 620）。
- **没接真模型就不写**：替身档里「出新文案」回一句「没接上」，不拿替身的回话凑文案。
- **一轮最多写 20 条广告**，多的说一句、下一轮写（每条两到四次模型调用）。
- **上传表只出「新建」**、一律暂停：Google 不许就地改在跑的广告文案，正确做法是建新的、跑出数再停旧的（停旧的是另一张卡）。
- **Meta 多标题多正文**：配成几条新广告（第 i 条标题配第 i 段正文），不用 Meta 的「多文案选项」列（没核实列名）。
- **批量出图只把标题上图**；版数默认 = 收下的标题条数（封顶 30）。
- **实验记录的真源放本品牌广告库**：岗位记忆现在没有落盘层（重启即失，WP36 / WP71 都记过），只当同步的副本；岗位记忆是全公司一份（scope = 岗位模板 `ads`），所以标题带品牌名。
- **面板放在职责页**（照 B2B 两块的先例），没放岗位页。
- 子 Agent 用这个品牌的「工作」模型（`run` 档），不用便宜的 `extraction` 档。
