## 1 一句话

投放的 Google / Meta 职责页上多了一块「素材流水线」：传一张后台导出的广告表 → 挑出表现差的 → 标题、描述两个子 Agent 各写一份新版本（本地按平台条数 / 字数 / 禁用词过一遍，拆字绕过审核的一律挡下）→ 下载上传表（新建一律「已暂停」，人自己去后台传）/ 交设计岗批量出图（L3 下单 → 设计岗出变体 L2 给人挑 → 入库 L1，广告设计放宽到每单 30、每天 100）→ 每一轮记「假设 / 改了什么 / 结果」，下一轮带进两个子 Agent 的上下文。**全程不碰广告后台。**

## 3b 与 WP314 的对接（最后怎么做的）

- 上传表只有 WP314 一份生成器；本单只把一轮文案翻成它的 op，再把它的产物投影给人下载。
- 导出表：WP314 的 `decodeExportBytes` → `parseAdsExport` 先走；它只认到 `Headline 1`，所以 Headline 2–15 / Description 1–4 / Title / Body 按原表头从 `raw` 里取；它认不出广告系列 / 广告组时退回本单的中文列名解析。
- 字数常量与数法只用 WP314 的；Meta「每轮最多 5 个标题、5 段正文」是流水线自己的条数（上传表一条广告一个标题一段正文）。

## 4 自主做的决定（白话）

- **字数按平台的口径数**：Google 后台中文一个字算 2，所以中文标题最多 15 个汉字；Meta 按字符数。`spec.ts` 里原来的 `checkAgainstSpec` 按字符数，没动它（别处在用），流水线用自己的数法。
- **拆字绕过单独一类**：直接写禁用词叫「禁用词」，拆开 / 换写法叫「绕过」，两句话不一样；都不替它改，只回理由。
- **「表现差」的基准用同一张表的中位数**，不用「行业平均」（没有出处的数不进判断）；样本门槛给了默认值（见决策 620）。
- **没接真模型就不写**：替身档里「出新文案」回一句「没接上」，不拿替身的回话凑文案。
- **一轮最多写 20 条广告**，多的说一句、下一轮写（每条两到四次模型调用）。
- **上传表只出「新建」**、一律暂停：Google 不许就地改在跑的广告文案，正确做法是建新的、跑出数再停旧的（停旧的是另一张卡）。
- **Meta 多标题多正文**：配成几条新广告（第 i 条标题配第 i 段正文），不用 Meta 的「多文案选项」列（没核实列名）。
- **批量出图只把标题上图**；版数默认 = 收下的标题条数（封顶 30）。
- **实验记录的真源**：第一轮放本品牌广告库、岗位记忆当副本（那时岗位记忆不落盘、不分品牌）；第二轮 WP320 合进来后改成以按品牌的岗位记忆为准（见 §3）。
- **面板放在职责页**（照 B2B 两块的先例），没放岗位页。
- 子 Agent 用这个品牌的「工作」模型（`run` 档），不用便宜的 `extraction` 档。

## 5 要 Luoye 定的事（620–629，10-14 Luoye 已同意；624 / 625 / 626 / 629 已在第二轮照做）

（620–629；630 起 main 上已被 WP319 / WP320 用掉，本单只用这十个号）

- **620 「表现差」怎么判**：同一张表里够样本那些的中位数当基准，差两成算差；判点击率至少 1000 次展示、判转化率 / 单次转化成本 / ROAS 至少 100 次点击，不够的单列「样本不够，先不判」。**建议先用这组**，真店跑两轮再调。
- **621 一轮最多写 20 条广告**（每条要 2–4 次模型调用），多的下一轮。**建议保持**。
- **622 Google 字数按后台口径数：中文一个字算 2**，所以中文标题最多 15 个汉字、描述 45 个。**建议保持**（不这样数，本地说没事、传上去被拒）。
- **623 拆字 / 换写法绕过禁用词一律挡下、单独标「绕过」，不提供「自动改成能过的版本」**。代价：像 `risk-free` 这种正常连字符写法也会被标成绕过（它本来就在禁用词里）。**建议保持**（派工单原话，也对齐 docs/101「规避系统」那条风险）。
- **624 实验记录的真源放本品牌广告库**（重启不丢），投放岗记忆里只是同步的一条副本——现在的岗位记忆没有落盘层、也不分品牌（scope 是岗位模板 `ads`），所以副本标题带品牌名，丢了在列清单时补回；记忆面板里改那条副本不会回写到流水线。**建议保持**；WP320（记忆落盘、按品牌分）合并后，再决定要不要改成以岗位记忆为真源。
- **625 实验副本挂在 `ad-copywriting` 技能下**，所以普通的投放运行加载这个技能时也看得到——WP320 之前包括别的品牌的实验（标题带品牌名）。**建议保持**（个人模式多半一个品牌，受益更大）；介意串品牌就改挂一个只在流水线里读的独立技能名（一行）。
- **626 上传表最小版的列名没对照官方模板逐列核实**（Google：Action / Campaign / Ad group / Ad type / Status / Final URL / Headline 1–15 / Description 1–4；Meta：Campaign Name / Ad Set Name / Ad Name / Ad Status / Title / Body / Link）。**建议 WP314 合并时直接换成它的生成器**（`server.ts` 里传 `uploadSheet:` 一行），最小版留作兜底或删掉。
- **627 Meta 多标题多正文配成几条新广告**（第 i 条标题配第 i 段正文），不用 Meta 的「多文案选项」。**建议先这样**；WP314 若支持多文案选项列再换。
- **628 批量出图只把标题上图**（描述留给平台拼在图下），版数默认 = 收下的标题条数（封顶 30）。**建议保持**。
- **629 面板只放在 Google / Meta 两条职责页上**（照 B2B 两块的先例），岗位页没有入口，TikTok / X 没有。**建议**：下一单在投放岗位页加一个跳到这块的快捷入口（岗位是主入口）；TikTok / X 等有导出表再说。
