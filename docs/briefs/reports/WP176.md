## 2. 我自主做的决定（白话）

1. **冷却存一张新表**（B2B 库 v4），按地址哈希一人一条，再说一次覆盖成翻倍的那一条；同时记联系人 id。这样同一个人换了联系人记录、或从同事邮箱回的「不要」，都认得出。
2. **第三次翻倍到 360 天**（派工单只说第二次 180）：照「每多说一次翻一倍」算，封顶在 16 倍。
3. **说过不感兴趣而停下的那一轮不算「开过序列」**；其余开过的（走完、停了、回了）仍然不自动重开（WP173 的规矩不变）。找不到冷却记录的「不感兴趣」按开过算，宁可不发。
4. **「第二次冷却翻倍，并在卡上提醒」**：说「不感兴趣」那一刻不出卡（没有要人拍板的事），提醒放在**这个人下一次被选进来的那张首封卡**上（「说过 2 次，这一轮再没回音就别再找了」），面板冷却那一行问号里也写次数。
5. **老数据迁移**：WP173 期间因「不感兴趣」进了永久名单的，按 Luoye 的新规矩搬成冷却（从当时起 90 天），并从名单拿掉。退订 / 硬退信不动。
6. **地址搬家**：档案已有地址时以档案为准，旧那一格直接清掉；档案还没建过就不搬（不替人建档案），面板照旧显示旧值、链到公司档案——存一次公司档案之后下一次读到就搬过去（demo 里就是这条路，截图 2 是搬完的样子）。
7. **报价单 / 单证**：现在仓里还没有出报价单、单证文件的地方，没有东西可改；地址的真源已经是公司档案（`brandProfile(ws).postal_address`），以后做报价单 / 单证直接从那里取。
8. **DNS 兜底只看「有没有公钥」**，不验签名；卡上与面板上都写「未经实信验证」，胶囊是黄的不是绿的。查的顺序固定、查到一个就停。
9. **10 分钟怎么「到点」**：测试信发出去时排一个定时（unref，不拦进程退出），另外面板刷新、开一轮、每天巡检时也顺带看一眼——进程重启丢了定时也不会一直卡住。
10. **Run 工具**：开一轮不给 `contact_ids` = 库里所有还没开过的；分回信只判不改（真回信停序列、进冷却 / 名单仍是邮件分拣那一路），避免 Run 里分一次、分拣再分一次两本账。
11. **stub 岔口**：「起草 / 开一轮」→ 先列序列再开一轮；「序列 / 进度 / 冷却」→ 只列；「回信 / 分类」→ 列序列并说明回信是收件时自动分的（stub 手里没有信可分）。
12. 端口加的 `sequences` / `classifyReply` 是**可选**方法、没加新路由（Run 工具直接调端口）；SDK 重出只多了两个字段（档案的 `postal_address`、开发信设置的 `sender_established`）。
