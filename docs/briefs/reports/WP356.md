# WP356 报告：腾讯 BrowserSkill 从 0.3.0 升到 0.3.3

分支 `wp/356-browserskill-033`，只推分支、没合 main（决策 381）。来源：10-16 上游扫描 ⑤-11，决策 918「单独开单」。

## 1. 做了什么（白话）

**这次升级的要害是改名。** 0.3.3 把"我正在用的浏览器"那六个工具全部改了名：`browser_assist / browser_inspect / browser_interact / browser_page / browser_session / browser_tabs` → `bsk_assist / bsk_inspect / bsk_interact / bsk_page / bsk_session / bsk_tabs`。我们的门禁是按名字认这六个工具的，漏改一个，那个工具里带网址的动作就能绕过"这个岗位只许开哪些网站"的白名单。

- **门禁全部换成新名字**（`packages/dsh-adapter/src/browserskill.ts`）：工具表、读写表、三处带网址的白名单检查、"请人接管"的识别、写进提示词的那三句都换了。老名字现在一个都不认了——模型要是还用老名字调，会被当成"不在允许列表里的工具"直接拦下，不会漏过去。
- **测试逐个工具名过一遍**（`browserskill-seam.test.ts`，从 49 条涨到 92 条）：
  - 三处打开网页的动作（`bsk_page` 打开网页、`bsk_session` 开新窗口、`bsk_tabs` 开新标签），外加新增的一处（见下），**每一处**都测"白名单内放行、白名单外拦下"；
  - 另加一条拿**真插件**对账的测试：上游每个工具有哪些动作，必须跟我们"判过是读的"加上"判过是写的"两张表**一个不多、一个不少**；带网址参数的工具必须正好是那四个。上游下次再改名或加动作，这条马上变红，逼着有人来判。
  - 我还做了一次反向验证：故意把一处检查改回老名字，测试当场红了 3 条，确认测试真的拦得住"改漏"。
- **新动作逐个定了读写**（读 = 只看不动，公司档也能用；写 = 会改东西，公司档一律拦，个人档放行但时间线上留一条痕迹）：

| 新动作 | 定成 | 为什么 |
|---|---|---|
| 等某个元素出现 / 消失（`bsk_page` 的 wait-for-element） | 读 | 只是轮询着看 |
| 把页面上的表格 / 列表读成一行一行（`bsk_inspect` 的 extract） | 读；要是让它**存成本机文件**就算写 | 跟"看网页源码"是一回事；存文件是往你电脑上写东西 |
| 网站调试（`bsk_inspect` 的 debug） | 分开判：开关抓包、看请求、看性能这些是读；**拦截 / 改写 / 伪造请求、重发请求、导出到本机文件**是写 | 前者只是看；后者会真的改动网站收发的数据（上游自己写着"重发可能改服务器上的数据"） |
| 录屏（`bsk_inspect` 的 video） | 整个算写 | 录的是你浏览器里的画面，还能存成 MP4 到本机任意位置 |

- **白名单多了一处**：调试里"重发某个请求"可以指定一个网址，这个网址现在也过白名单。
- **二进制 `bsk` 钉到 0.3.3**（`browserskill.lock.json`）：照上游 `cli-v0.3.3` 的 version.json 抄版本和指纹，五个平台的安装包我都下载下来重算了一遍指纹，跟上游写的一字不差。插件也锁到 0.3.3（`packages/dsh-adapter/package.json`、`pnpm-workspace.yaml` 的静默期例外）。
- **依赖那几条"钉版本"的规矩**（`pnpm-workspace.yaml` overrides）核过：上游把兼容范围放宽了一点，但还是不包含我们用的 dsh 测试版，所以那四条规矩**全留**；简报里说可以去掉的 `dsh-client-ui-attachment`，我们本来就没为它写过规矩，没有东西可删，只在注释里记了它已不在上游的依赖表里。装完确认插件用的仍是树里那一份 dsh，没有多装第二份。
- **`lazyTools: false` 仍要显式写**：上游缺省还是"等技能被调用过才出工具"，我们的组合里没有那个触发器，不写的话一个浏览器工具都没有（测试里有一条专门钉着）。
- **登记表与文档同步**：`upstreams.yml`（版本、依赖的上游行为都改成新名字）、docs/55 §10（两张表换名字 + 新增「0.3.3 升级」一小节）、`AGENT-LAYER.md` §9.7、`scripts/dev-browserskill.md`（手工步骤里的工具名和期望输出）、docs/80 一处。

## 3. 我自己拿主意的地方

1. **extract 不带"存文件"时算读。** 简报建议先按写或先不开放；我看了实际内容，它只读页面上已经加载出来的表格 / 列表，不滚动、不翻页，跟现有的"看网页源码"（一直是读）是同一种事。算成写的话，公司档连"把这个达人列表读出来"都做不了。带了"存成文件"那一次照样算写。
2. **debug 按子动作分开判**，而不是整个算写。开关抓包、钉住某条请求、看各种统计算读（上游原话"光抓包不改流量"）；`rule_*`（拦截 / 改写 / 伪造）、`replay`（重发）、`export`（写本机文件）算写。`rule_disable` / `rule_remove`（关掉 / 删掉规则）其实是在"撤销改动"，但我还是一起算写，规则一家子同一个判法更好记。
3. **video 整个算写**，包括"查看录制状态""列出录像"这种只看的子动作——录屏这件事本身就该过一道，简单起见不拆。
4. **"重发请求"的网址也过白名单**（简报只要求那三处）。没给网址时上游会照原样重发抓到的那一条（它只许同源），那个地址我们看不见，靠"重发算写、公司档拦"兜着。
5. `bsk_inspect` 也有一个叫 `url` 的参数，但那是调试时"按网址片段筛请求记录"用的，不打开任何网页，所以**不拦**（有测试钉着：公司档用它照样放行）。
6. 锁文件里顺带多了几行跟本单无关的变动（`dsh-genui` 依赖的 markdown 解析库换了一种写法），是 pnpm 自己重算出来的，不影响装什么；没有手动去掉。

## 4. 要你定的事

1. **extract（读表格 / 列表）不存文件时算"读"，公司档也能用——可以吗？** 不同意就改成整个算写，一行的事。
2. **debug 的"开关抓包 / 钉住请求"算读——可以吗？** 这两个不改网站数据，但抓包会把请求内容（含页面上的数据）记下来留在本机 24 小时。
3. （提醒，不用定）**本机已经装过 bsk 0.3.0 的，要在设置 → 浏览器 → 第 ② 步点一下「重装」**才会换成 0.3.3；现在设置页只显示"已装好：0.3.0"，不会主动说"版本旧了"。还没有真实用户，影响不大；要不要做"版本对不上就提示重装"，见第 6 节。
