## 1. 实现清单

1. **契约（只加）**（`287b4f7e`）：`ModelProvider.capabilities?: { vision; image_generation }`（可选——没验证过就不声明）；`ModelFailureKind` 加第六档 `vision` 与 `NO_VISION_REASON = 'no_vision'`；验证三步类型 `ModelCheckStep` / `ModelCheckStepResult`；`VISION_MODEL_EXAMPLES`（常见能看图的公开型号名，不是推荐）。`ChatMessage.content` 的图片部件沿用 WP122b 那一版，未改。
2. **验证三步**（`862efd25` / `0b814404`）：`@agentsws/model-gateway` 的 `checkModel`——连通 → 一次最小文字请求 → 一次带图的最小请求。测试图是一张几百字节的灰度 PNG，上面用 5×7 点阵写着 `ZEBRA`，要求模型只回这个词（看不了的模型要么上游 400、要么念不出来，都猜不中）。连通不单独发请求：文字那一次回了任何 HTTP 响应就算连上。第 ③ 步是余额 / 超时 / 限流时照原样报那一档，不冤枉成"看不了图"。`apps/server` 的 `test()` 换成它，结果带 `steps` 与 `vision`，看不了图时人话 + 常见型号名。向导第 ① 步与设置页共用同一个接口、同一个三格小清单件（`components/models/model-check-steps.tsx`）。
3. **能力声明落地**：上一次验证的结论（只认测的正是这个模型的那一次）装配成 `capabilities.vision`；网关对声明了 `vision: false` 的 provider **拦下带图请求**（不花钱，说「当前模型看不了图」），降级链上看不了图的备选也跳过；验证那一次标 `capability_probe` 不被拦（否则永远翻不回来）。provider 视图加 `vision_status: ok / no / unchecked`；`ModelsAssembly.visionStatus()`。
4. **官方接口默认型号钉住**：内置价目表加 `vision` 一格（只记官网写明的：`deepseek-flash` ✓、`deepseek-v4-pro` ✗、`gpt-4o(-mini)` ✓），测试钉住云那张卡默认 `deepseek-flash` 写明能看图；云那条 provider 点测试也走同一套三步（测试钉住，不开后门）。
5. **生图单独一档**（`862efd25` / `a34e6ff3` / `9ae91325` / `0b814404`）：`openaiImageProvider`（OpenAI 形态 `/images/generations`，b64 / URL 两种回法都收）；网关 `images` 改 getter，`reconfigure({ images })` 保存即生效（`null` 退回装配时那条：生产是"没配"那句人话，demo 是占位图）；`GET / PUT /v1/models/image`；存在 `defaults.image`（跟"跟随公司默认""从某个品牌复制"一起走），多品牌写保护同 `setDefaults`；只收 OpenAI 兼容口与官方接口，DeepSeek / 订阅登录当场拒。云端 `pricing.json` 加 `ai.image`（0.5 积分 / 张），`cloud-entry` 加 `/v1/ai/images/generations`：按张预扣、按真回来的张数结算、上游拒了一分不扣。`NO_IMAGE_MODEL_ZH/EN` 改成指向设置页「生图」那一块。
6. **去掉「看不了就跳过」**（`a9089429`）：`composeDesignProse` 看图失败不再悄悄 `break`——`vision_note` 明说（「当前模型看不了图……」/「看图那一步没成（原因）」/ 有图没接模型也说），`apps/server/src/brand-design.ts` 两处（官网内容图、PDF 嵌图）把它写进版本历史；配了模型就必走看图。
7. **界面**（`126964f1`）：设置页「模型」分「文字与看图」「生图」两块；顶部老用户提示（默认模型 `unchecked` 请点一次测试 / `no` 明说并列型号，`role=status`，不挡路）；那一行画三步小清单；向导第 ① 步看不了图不放行、说人话、画同一个清单。`lib/i18n.ts`、`lib/api.ts` 只追加（`api.ts` 用接口合并给 `ModelTestResult` / `ModelProviderView` 加字段）。

## 2. 自主做的决定（白话）

- **测试图上写一个词，而不是画个颜色让它猜**：问颜色瞎猜有三分之一蒙对；念一个大写单词，看不了图的模型猜不中。
- **连通不单独发一次请求**：文字那一次回了任何 HTTP 响应就是连上了。多打一次 `/models` 既多花时间，百炼那一路还没有这个口。所以三步只发两次请求。
- **能力声明是可选的、"不知道"不等于"不能"**：没验证过的老配置照常放行，只有验证过看不了的才在网关拦。否则老用户一升级，所有带图的动作都会被拦死。
- **换了模型名，上一次"能看图"的结论作废**：结论只认测的正是这个模型那一次。
- **生图存在 `defaults.image`**：这样"跟随公司默认"与"从某个品牌复制"自动带上它，不用另开一套复制逻辑。
- **官方生图单价先定 0.5 积分 / 张**（见第 3 节），界面常显。
- **向导的官方接口那条路不自动跑一次测试**：那会刚送完 10 积分就替用户花一笔；改为钉住官方默认型号写明能看图，且云那条点测试走同一套三步。
- **其它模板卡的默认型号没改**（见第 3 节）：改动面大、牵动一批测试，属于产品口径，留给 Luoye。

## 3. 需要 Luoye 定的事

1. **官方接口生图单价**：`pricing.json` 的 `ai.image` 先写 0.5 积分 / 张（≈ gpt-image-1 中档成本 × 3 倍率的量级）。是否合适？
2. **官方接口生图用哪个型号**：本地默认填 `gpt-image-1`（汇聚网关后面认这个名字）。它是境外模型——工作区默认驻留 `cn` 时，云端会按 22 §2 拦成 422 人话，除非部署的 `region_map` 把某个境内生图模型标成 `cn`。要不要换成一个境内生图模型当官方默认？
3. **其它模板卡的默认型号多半是纯文字模型**：`deepseek-chat`（DeepSeek 卡，保存时通常会被清单第一个替换）、`moonshot-v1-8k`、`qwen-plus`、`glm-4-plus`、`llama3.1`（Ollama）。按新规则它们会卡在第 ③ 步。建议换成能看图的（如 `deepseek-flash`、`moonshot-v1-8k-vision-preview`、`qwen-vl-plus`、`glm-4v-plus`、`llama3.2-vision`）——要不要换？
4. **订阅登录（ChatGPT / Claude）那两条没有走三步验证**（它们不在 `test()` 那条路上）；默认型号 `gpt-5.4` / `claude-sonnet-4-5` 本身能看图，暂未加校验。

## 5. 偏离

- **`ModelPurpose` 里没有 vision 档的半成品**（WP122b 只在报告里提过、代码没加），无需收掉；docs/71 §9 第 4 条按"文字模型即多模态"收口。
- **能力声明做成可选字段**（派工单写的是 `capabilities: {…}`）：必填会破坏现有所有 provider 实现，违反"只加不删"。
- **"能力声明进 SDK / openapi"**：SDK 的响应体是信封、类型不展开，所以落在路由的 `returns` 描述与新路由的请求体 schema 上；能力声明本体在 `@agentsws/contracts`。
- **截图里"配了看不了图的模型"是浏览器侧路由替身给的**（demo 是 stub 模型，没法真配一个看不了图的上游）；界面是真的。脚本 `scripts/e2e-models-vision-shots.mjs`（端口 4411）可重跑。
- **cloud-entry 的生图口没进 `apps/cloud/openapi.json`**：`/v1/ai/*` 本来就不在那份里（44 条未变）。
- 没碰 `apps/cloud-worker` / `packages/standby` / `packages/chat-relay` / `packages/kol-public` / `extension-contribute.ts`。
