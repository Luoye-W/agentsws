## 2. 我自主做的决定（白话）

1. **询盘不再起 Run，业务那一路一次做完**：分级与首回是确定的几步（查卡、起草、自查、出卡），起 Run 让模型再绕一圈既花钱又可能出第二封回信。往来记录（老客户来信、回我们的信）照旧起 Run。没接业务装配的老调用方（单测）行为不变。
2. **PDF 自己写**（零依赖，几 KB）：照「不打包重型本机方案」，不带无头浏览器，也不为第一个 PDF 运行时依赖走一轮 docs/42（`brand-design/pdf.ts` 读 PDF 同一个理由）。代价：**不嵌字体**，品牌字体映射到最近的内置字体（无衬线 → Helvetica、衬线 → Times、等宽 → Courier），只认西文——报价单是给海外买家的英文文件；有中文会换成 `?` 并在自查里提示「公司名 / 客户名请用英文」。颜色照品牌设计原样。
3. **起草只引事实卡上的英文那一句**（`structured.reply_en`）：卡上的中文句子模板不去翻译（翻错一个数就是承诺）；模型那一版可以读中文句子，但数对不上就退回模板。
4. **首回不报价**（技能原话）：问了价只回「先确认这几点再出正式报价单」；模型那一版出现金额就退回模板。
5. **发给客户的报价单也是 `b2b_reply` 卡**（没新加 ChangeKind）：同一种「对外发信」，承诺词表照样过。只有批过的版本能发；PDF 不落盘，发的时候按那一版现生成（同输入同字节）。
6. **收件人明文不进卡**：询盘回信在发的那一刻从消息库那封信取发件人；报价 / 寄样通知从联系人的加密库那一格取。
7. **样品提醒开待办，不出卡**：提醒不是要人拍板的事（36 §2）；寄样通知才出卡。提醒记在单独一张表里（写九类对象只经卡）。
8. **交接的规则从「接手的人已经在管什么」推**：他名下客户的地区与产品线；都对不上的交给兜底（第一个还在做业务的同事；一个都没有就是老板）。没接组织设置里的「谁管哪片」——现在没有这一格。
9. **交接卡的动词**：`b2b_account_transfer` 在 WP171 被排成「转交」版式，按钮是客服转交那套（认领 / 不是客户问题），这张卡上是错话；加了按 kind 换整排动词的一张小表，只登记这一种。
10. **面板「该唤醒的老客户」**：原来只看客户记录上的 `last_contact_at`（没人写它）。改成「阶段到过成交 + 最近一次来信」算，不回写客户记录。
11. **诈骗嫌疑与「改收款账户」分开**：信里要改账户的仍由 `b2b-mail` 先出那张红卡（WP172），不交给业务；其余诈骗信号（钓鱼链接、先交费、危险附件、免费邮箱冒充大公司）由分级出第二种红卡（同一审批种类，理由 `scam_suspect`）。
12. **WhatsApp 这台机器上还没有入站来源**（服务进程里没有 WhatsApp 的收信 / webhook），所以只做了同一条路的入口 `intakeWhatsApp` 与执行器的发送口（`sendWhatsApp`，生产不接；测试与将来接入用）；三道闸在 guardrail 与适配器各一道。

## 3. 需要 Luoye / Fable 定的事

1. **PDF 不嵌字体、只认西文**：品牌字体用最近的内置字体代替。要真用品牌字体（或中文报价单），得选一个 PDF 库（如 pdf-lib + fontkit，纯 JS 约 1–2 MB）走 docs/42；要不要做？
2. **WhatsApp 入站**：服务进程还没有 WhatsApp 收信（webhook 要公网地址 / 云端转发）。B2B 那一路已备好入口，接收那一跳排哪一单？
3. **交接规则**：现在按「接手的人名下客户」推地区 / 产品线。要不要在组织设置里让老板写「谁管哪片」（显式规则优先）？
4. **诈骗 / 骗样信号词**（`b2b-core/src/inquiry.ts`）请懂外贸的人过一遍，尤其「免费邮箱 + 大公司名」这条。
5. **首回模型写不写**：现在有模型就先让模型按技能写，过不了自查退模板；卡上写明是哪一种。要不要首回一律模板（更稳、更死板）？
