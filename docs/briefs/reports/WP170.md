## 2. 我自主做的决定（白话）

1. **序列只写三封，而且测试钉死**：原版「3–5 封、间隔越拉越长、第 14 / 21–28 天」整段不取；测试里查「3–5 封」这类字样不许出现，免得以后有人照上游改回去。
2. **原版的所有数据表都没取**：回信率、打开率、「2 个词比 5 个词多 60% 打开」、各行业回复率、最佳发送时间（周四）等，和 WP160 一样，没有出处的行业数字不进技能。只留了规矩本身（主题 2–4 个词、小写、不放名字）。
3. **原版的写法框架大全（PAS、BAB、AIDA……十几种）只留四种**：默认观察 → 问题 → 证据 → 请求，另留问题 → 价值 → 请求、触发事件 → 看法 → 请求、案例 → 桥 → 请求。案例能不能说客户名，以事实卡为准。
4. **LinkedIn 私信也不写成「可发送的信」**：cold-email 最后写明只出「请你本人去发」的任务，附草稿参考。
5. **prospecting 的四个分支（SaaS / B2B / 本地小商家 / 需求信号）只取 B2B 这一支**，买的信号换成 3C 外贸的（上新快充、进新市场、展会参展商名录、招采购、公开找供应商）。Truelist、Clay、ZoomInfo 这些具体工具名不写，换成我们的三档数据（自己的 / 官方档 / 自带 key），和 docs/84 §6 对齐。
6. **置信度与证据强弱写成同一套**：技能里写「和客户库的证据分级是同一套，打分的纯函数用的也是这套权重」，为 WP171 / 后续 `b2b-core` 的 `decideEvidence` 留好口径，但技能里没写权重数（那是纯函数的事）。
7. **报价授权的四个数没写进 quotation**：docs/84 §3.2 的默认值（1 万美元 / 20% / 5% / 30 天）在首次设置里、用户可改；技能写「以职责设置里的为准，技能里不写死」，避免两处不一致（BtoBAgents 当初就是两处写得不一样）。
8. **超授权的批准路由写成白话**：「转上级批——这条职责所在部门的负责人；没有上级再转老板」，对应 §11.1 第 3 条的 `scope_manager` → `owner`，技能里不写路由 id。
9. **展前邀约的德奥规矩**：docs/84 说邀约照 §2（含德奥默认排除）。我写成「在这两国、又没有往来的潜在客户默认不发」——已有往来的老客户不是冷邮件，没写默认不发，但照样出卡。见 §3 第 2 条。
10. **展会的收款账户也挂上防诈骗**：展位费收款方以主办方官方渠道核对，邮件里要改收款账户的一律出红卡（和 export-docs 同一条规矩）。
11. **export-docs 写了两个 UCP 600 的惯例**（`about` 上下浮动一成、信用证没写交单期时按装运后 21 天内），都附「以信用证原文与银行意见为准」。这是规则不是生意数字，所以留了；别的银行费用、险别、时限都没写数。
12. **锂电池的危险品运输**（UN38.3、安全数据表、如实申报）写进了 quotation、trade-show、export-docs 三处：充电宝和耳机都带锂电池，报 CIF / DDP、寄展、订舱都会碰到。只写要什么文件，不写运费或限制数值，运费一律「先问货代」。
13. **工作台新手向导的技能显示名（i18n）没加**：WP160 当时加过，但派工单说本单只加技能文件与测试，这六个名字登记进职责是 WP171 的事，显示名一起在那边或合并时补更顺。
14. **每个技能 6–7 道题**（派工单要 4–7），`approval / numbers / compliance` 三类每个技能都有。
