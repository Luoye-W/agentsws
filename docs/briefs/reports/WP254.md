# WP254 报告：npm 随包带、换国内源再试、版务卡与回帖卡的执行器（决策 99 / 100 / 123 / 117）

分支 `wp/254-misc`（worktree `agentsws-wt/wp254-misc`），Claude 子代理。已合最新 main（WP250 / WP252 已进，无冲突）。

## 0. 一句话

装好的桌面版**自带 npm**（与 Node 22.23.2 官方配套的 10.9.8），一键装 Shopify CLI、下载连接器不再先联网下 npm；
这两件事遇到**网络类失败**时，失败那一行多一个「**换国内源再试**」（npmmirror，校验照旧），点过就记住（每台机一份），
设置 · 诊断里能改回官方源；**别的社群的版务卡**改成做之前的改动卡（「批准执行 / 不做」），批了经各渠道适配器真去做；
**社媒回帖卡**批了就经渠道出口发出去（Reddit 走 WP249 的接口优先、官方号浏览器兜底），结果有账、失败照实报不重试。

## 2. 安装包体积变化

| | 增加 |
|---|---|
| npm 10.9.8 的 tgz（registry 实数） | **2.97 MB**（2,973,275 字节） |
| mac dmg / zip、Windows 安装程序（各一个） | **约 +3 MB**（dmg 是 zlib 压缩，与 gzip 相当；NSIS 用 LZMA，通常还小一点） |
| 装好后占的磁盘 | **+11.7 MB**、2009 个文件（`<resources>/node/…/npm`） |
| 换来的 | 第一次一键装 CLI / 下载连接器不再先下约 3 MB 的 npm，也绕开「下 npm 那一步不走系统代理」的老问题（WP245 §3 第 2 条） |

真打包时 `afterPack` 会在日志里打「随包的 npm：10.9.8」「随包 npm 冒烟：10.9.8」。

## 3. 我自主做的决定（白话）

1. **npm 从 registry 取、不从 Node 的发行包里抠**：WP245 报告的建议是「mac 从 tar.gz 多抽、Windows 从 30 MB 的 zip 抽」。
   两者内容一样（Node 的 `deps/npm` 就是 registry 那个 tgz 解开），从 registry 取只下 3 MB、四个平台一份、一个解包器；
   版本仍严格按「这版 Node 官方配的那个」（10.9.8），sha512 钉在锁里。
2. **随包的是 10.9.8，服务端「没带时现下」的钉版本仍是 10.9.9（WP245）**：后者只在开发机没跑过 fetch-node、或服务进程跑在
   Electron 自带 Node 上那一档才用到，没动它（动了老用户缓存目录会变）。两个版本同一代，都满足 Node 22。
3. **「网络类失败」= 连不上 + 超时**：超时在国内网络下多半也是慢；磁盘满 / 没权限 / 校验不对不给这个按钮（换源解决不了）。
4. **国内源优先于环境变量**：用户点过「换国内源」就是明说要它；没点过时公司内网自己设的源照旧生效（诊断里问号提示一句）。
5. **换源的权限与「一键安装」同一档**：能点装的人就能换源；AI 运行改不了。只认两个值，不收任意地址。
6. **版务卡按钮统一成「批准执行 / 不做」**，自家版那一类也一样（WP249 是「批准」，而它的动作里本来就有一个「批准（放回版里）」，
   两个「批准」容易看混）。
7. **「提醒一句」不发话**：它是群规里「第一次轻犯」那一档，平台上没有「警告」动作；要在群里说一句，另出一张回帖卡（人写的话、人批）。
   卡上「将执行」那一行事先写明「只记在工作台里」。
8. **回帖卡的结果记在哪**：回一条评论在 56 §2 里是出站（`outbound_message`），不是一条变更——所以结果记在**这张卡的施行记录**上
   （与客服回信同一处，`approval.applied / apply_failed`），另记一条 `social.reply_sent / reply_failed` 事件；版务卡的结果照旧进变更账本。
9. **回帖卡一律人点（L1）**：职责 yml 里 `reply_thread` 初始 L2，但服务端出卡这条路目前只有人 / API 在用，批了就发出去收不回来，先不自动放行。
10. **补扫挂在定时发布那一轮**：批准那一刻排的计时器随进程重启会丢，定时发布本来就每几分钟按品牌跑一次，顺手扫一遍。

## 4. 要 Luoye 定的事（逐条，附建议）

1. **Shopify CLI 走国内源时的校验来源**：连接器（锁文件）与 npm 本身（钉死 sha512）换源后照样逐个校验；但
   `npm install @shopify/cli@latest` 没有锁文件，校验值来自源自己的元数据——国内源时就是 npmmirror 同步来的那份。
   **建议：接受**（npmmirror 是阿里维护的 npmjs 同步镜像，integrity 原样同步）；要更严就给 CLI 也做一份锁文件（每次 CLI 升级都要重出，成本不小）。
2. **回帖卡要不要按职责等级自动放行**（`reply_thread` 初始 L2，最高 L3）：现在一律人点。**建议：先人点**，等回帖卡跑一两周、
   采纳率够了再接「三道门过了就自动发」（客服回信那一套现成）。
3. **工作台上要不要加「回复」按钮**：本单只补了接口（`POST /v1/social/threads/:id/reply`），工作台里还没有入口（社媒库的线程列表本来就没有界面）。
   **建议：下一单在「自家版待处理」与社群线程列表上各加一个「回复」，出卡走这条接口。**
4. **把随包的 npm 登记进上游名单（`upstreams.yml`）**：Node 与 npm 的钉版本现在只在 `node-runtime.lock.json`，上游评估例程看不到。
   **建议：开一小单登记（Node 22 LTS 出安全版时连 npm 一起升，`fetch-node.mjs --write-lock --all` 一条命令）。**

## 6. 偏离 / 未完成

- 工单写「从官方发行包带 npm」的方式（WP245 报告里的建议）改成了从 registry 取同一份（§3 第 1 条）。
- 没真打安装包、没真下 npm（纪律）；体积按 registry 实数估算（§2）。打包机上第一次跑 `fetch-node.mjs` 时会真下并校验 sha512。
- 「换国内源再试」只在**下载 / 安装**这两处；登录 Shopify 走的是 Shopify 自己的账号服务，与 npm 源无关，没加。
- 回帖卡在工作台上还没有发起入口（§4 第 3 条）。
- 版务卡失败时的那句话用的是适配器原话；Discord / Telegram 等「没连上」那句原文写的是「所以这一块没有数」（读数据时的说法），
  放在执行失败里略别扭，没改适配器（social-core 那张话术表别的单在用）。

## 7. 给 Fable 的真机复测点

- mac / Windows 打包日志里有「随包的 npm：10.9.8」「随包 npm 冒烟：10.9.8」；装好后 `<resources>/node/lib/node_modules/npm`（Windows
  `resources\node\node_modules\npm`）在；**断网**点「一键安装 Shopify CLI」，卡上直接进「安装中」（不再有「下载中」那一步下 npm），
  失败原因是装 CLI 本身连不上而不是下 npm。
- Windows 中文用户名路径下 npm 的深层目录（安装目录 + `node_modules\npm\node_modules\…`）不超 260 字符（Node 官方 zip 是同一布局）。
- 国内网络：点「换国内源再试」→ 装上 / 下好；设置 · 诊断里显示「国内源（npmmirror）」，点「改回官方源」后再装走官方源。
