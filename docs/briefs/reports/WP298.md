## 2 能不能在 Electron 里复现、根因

**没能复现。** 排查过程：

1. 本机用演示服务（`agentsws demo --port 4399`）+ 一个照桌面壳配置起的 Electron 44 窗口（同一份 CSP 覆盖 `withCsp`、`sandbox` / `contextIsolation`、真 `preload.cjs`，桥报 `platform: win32`），从首页点左栏进「消息渠道」→「连接」→「消息渠道」，再直接打开 `/im-channels`：五次都正常画出来，控制台零报错（level error / warning 都没有）。
2. 换成 Windows 那种条件再来一遍：窗口 853×560（1280×840 在 150% 缩放下的 CSS 尺寸）+ 系统「减少动效」（`prefers-reduced-motion: reduce`，Windows 关掉动画时就是这个）：同样正常。
3. 读代码：「消息渠道」页（`pages/im-channels.tsx`、`components/im/team-bot-card.tsx`、`StatusIcons`）没有 `eval` / `new Function` / Worker / 外域请求这类会被壳的 CSP 拦下来的东西，`/v1/im/status` 服务端是同步拼的、不会卡住。
4. **一个值得注意的点**：截图里左栏还在、只有主区空白。React 19 下**没人接住的渲染错误会把整棵树卸掉**，那时左栏也会一起没——所以真机上那一下多半**不是**「整棵树抛错卸掉」，而更像主区的内容没画出来（比如一直停在骨架屏、或页面画了但看不见）。错误边界接不住这一类；但本单加的日志能把「到底有没有抛错」说清楚：有抛错，`server.log` 会有 `[client-error]`、`desktop.log` 会有 `[desktop/renderer] 页面报错`；两边都没有，就是「没出错但没画出来」，下一步查请求（`/v1/im/status` 有没有回来）。

**带日志的验证（Electron 里真走了一遍）**：把 `/v1/im/status` 的回包改坏（让页面把一个对象当文字画，React 真抛错）：主区出兜底卡、左栏在、点「连接」页面复原；`desktop.log` 写了一行 `ERROR [desktop/renderer] 页面报错 message=Error: Minified React error #31 …`。再对**真服务进程**（`apps/server/dist/index.js`，端口 4398、临时数据目录）在 Electron 里抛一个错 + 一个没人接的拒绝：`server.log` 两行 `[client-error] … kind="error" route="/login" app="…" ua="… Electron/44.3.0 …"`，邮箱已换成 `<email>`；`desktop.log` 同样两行。

## 4 我自己定的（白话）

- 接口**不要求登录**、单独一只限流桶：登录页和「会话都没取到」时的错误最需要记；单独的桶让死循环刷错也吃不掉正常请求的额度。
- 演示模式（`agentsws demo`，安静档）不写这行日志（接口照答 `logged:false`）；真安装（桌面壳起的服务进程）照写。
- React 压缩版错误里 `react.dev/errors/31?args[]=…` 的参数也当查询串去掉了——只剩错误号（#31 这类已经够定位是哪一类错）。
- 桌面壳只给**主窗口**挂渲染进程日志，场景窗口（dsh 那几个外部页面）不挂，免得别人的页面刷进我们的日志。
- 「回首页」在页面层走路由（左栏不重挂）；本来就在首页时就地复原再试一次。
