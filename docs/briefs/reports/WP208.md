## 2. 我自己拍板的（白话）

- **标签就是旧 id**。切「设定」里的标签，走的是 `show('memory')` 这条路，由注册表的别名落回「设定」。这样旧入口一个都不用改，上次开到哪个标签也会跟着布局记住。
- **默认开在「角色」**。工作单里的顺序第一个是角色，我照这个顺序排，默认停在第一个。
- **定时任务挪到中组**。数字跟着岗位 / 职责走，放在「这件事的」那组说不通，所以挪到「设定」下面。
- **定时的数只算「自动化任务」建的那种**（`automation.reminder`），和面板里列出来的是同一批。系统巡检（收信、复盘、令牌刷新）不算：那几十条人没设过，数进去会让每个岗位都挂着一个大数。
- **岗位层按分配数，不按职责 id 数**。同一条职责可能挂在两个岗位下，比如网站客服既在「客服」也在「独立站运营」，只按职责 id 数会把别的岗位的也数进来。
- **AI 助手默认展开**。用户点开一封信，服务端会在那一刻生成一次回复建议（有 30 分钟缓存）；以前右栏开着时也一样。收起后就不请求了，分拣那一行收起时也照常显示，它本来就在信上，不花钱。
- **教程的镜像**。文章是各自一个 chunk、点开才下载，右栏排目录时读不到 frontmatter，所以 `lib/help.ts` 里抄了一份 `HELP_SCOPES`，测试逐字对照，两边对不上就红。英文那份不写 frontmatter，跟中文走。
- **教程的归属**是我按内容判断的，比如：「连 Shopify」归独立站运营 / 网站运营 / 客服 / 建站；「聊天窗」归客服 · 网站在线客服；「开发信域名」归 B2B · 开发信；模型、积分、电脑操控、切换场景、消息渠道（微信 / 企微是老板自己的私聊）算通用。完整对照见 `lib/help.ts` 的 `HELP_SCOPES`。
- **设计规范卡放在品牌 tab 最下面**，排在「加一个品牌」后面。个人用户没有公司时，品牌一览那块不显示，但这张卡照样出现，不然他就找不到设计规范了。
- 顺手修了一处：定时面板里 cron 那种任务的「下次」一行，前面多了个「·」，已去掉。

## 9. 补：合 WP204 之后的接缝（Fable 09-30 退回）

**现象**：main 合进来 WP204 以后，`test/messages-buttons.test.tsx`（WP204 的阅读区按钮用例）全红。

**根因**：WP204 写这组用例时，邮件助手还在第三栏，页面上不挂它，所以用例把 `getMailAssistant` 桩成了半个对象 `{ suggestions: [] }`。WP208 把助手搬进阅读区后，看信就会挂载它；读到 `sender.name` 时抛错。页面上没有错误边界，整个阅读区连同那排按钮一起被卸掉，按钮用例全部找不到元素。

**修法**（提交 `38674ba2`）：
- **助手外面包一层错误边界**：助手出错只在它那一块显示一句「AI 助手这会儿出不来，信照常能回、能归档」，阅读区和按钮不受影响；换一封信会重试。这样以后接口形状不对、模型那边出问题，都连累不到 WP204 的按钮。
- **补全 `messages-buttons` 的替身**：换成完整的 `MailAssistantView`。WP204 的断言一条没改，确认、撤销、失败说人话、影子模式置灰、本机代取图片都照旧验到。
- **新增一条用例**：助手回了坏形状时，只折它那一块，「回复」照常能打开写信框。
