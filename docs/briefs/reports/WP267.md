## 2. CLI 4.8.5 的自动升级（`npm pack @shopify/cli@4.8.5` 到临时目录读源码，没装）

- 每条命令跑完的收尾钩子（`chunk-GUPUXFIP.js`）：命令名里不带 `notifications` / `upgrade` / `send-analytics` 才去看要不要升级。
- `versionToAutoUpgrade()`（`chunk-DGMHUJV3.js`）：缓存里有更新的版本才往下走 → `SHOPIFY_CLI_FORCE_AUTO_UPGRADE=1` 强制升级 → 配置 `autoUpgradeEnabled`（`shopify-cli-kit` 那一份 conf，**默认 true**）不是 true 就跳过 → `CI` 为真就跳过 → 预发布版跳过 → 主版本变化跳过。
- 真升级（`runCLIUpgrade`）：全局装的跑 `npm install -g @shopify/cli@latest`（或 `pnpm add -g` / `yarn global add` / `brew upgrade`），项目里装的改项目依赖。
- 环境变量表里**没有**关它的那一个（只有 `SHOPIFY_CLI_FORCE_AUTO_UPGRADE`）；`config autoupgrade off|on|status` 三条命令改 / 看那一格。
- 结论：非交互带 `CI`；交互命令前在本品牌配置目录里跑 `config autoupgrade off`（命令名带 `upgrade`，它自己的收尾不会去升级）。

## 3. 自主做的决定（白话）

1. **补签成了接着做刚才那一步**：只记卡上「连接这家店」「测试连接」两种；卡一打开就是「授权要更新」（没在做什么）时，补完回到能连的样子。
2. **补签顺手补同一家公司别的品牌**：重新登录本来就是整家公司一起换令牌，补签照这个口径；别的品牌补不上不算失败，那个品牌卡上再点一次。
3. **补完令牌里仍没有 `store` 也算没成**：云上默认集还没加 `store` 时，补签回 200 但什么都没补，这时退回重新登录（与 WP265 原来的路一样）。
4. **订单那一路只认云端 + `read_orders`**：没授订单权限就照旧走连接器；云端连着但这次查询失败（失效 / 缺权限 / Shopify 出错）**不偷偷回退连接器**，照实把云端那句话告诉 AI（`not_connected：…` / `upstream_error：…`），免得同一个问题两条路答得不一样。
5. **受保护的顾客数据退一步**：Shopify 对没过审的应用整条查询报错，所以先带顾客那几格查，报这一类错再不带查一次（多一次请求，只在没过审时发生）。
6. **退换只取 `returnStatus`，不取 `returns` 明细**：`returns` 要 `read_returns` 权限，应用 B 没有；`returnStatus` 在订单上，`read_orders` 就够。
7. **「就用这家」算从清单里选**（`source: 'list'`）：之后重找、换账号回来，只要那家还在就不动；与 WP258 的下拉框同一条规则。
8. **内存档不改用户自己的 CLI 配置**：只在我们按品牌建的配置目录里关自动升级。
9. **AI 终端整包带 `CI`**：那里的命令只有 shopify / git / node / npx / pnpm，本来就没人能回答交互提问；副作用是 `pnpm install` 在 `CI` 下默认锁版本（主题工作流用不到）。
10. **素材库只认本机对象存储**：设定了 S3 对象存储（`AGENTSWS_BLOB_URL=s3://…`）时素材没有本机文件，`asset_id` 照实说「素材存在云存储上」传不了。
