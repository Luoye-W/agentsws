# WP216 报告：建站岗位装上 Shopify 官方技能、Dev MCP 加平台闸、Shopify CLI 引导

分支 `wp/216-shopify-skills`（worktree `../agentsws-wt/wp216-shopify-skills`），已合过一次 main。

## 0. 一句话

**这一套东西跟着品牌的建站平台走。** 平台是 Shopify 的品牌才有：Shopify 官方技能、Dev MCP 工具、「Shopify CLI」卡和引导。平台换走了，这几样马上停掉，用户电脑上装好的 CLI 我们不碰。

平台和这几样东西的对应关系写在一张表里（`PLATFORM_KITS`），这一单只填了 Shopify 一行。以后接 WooCommerce、Shopline、Shoplazza，往表里加一行就行，职责逻辑和界面都不用改。

## 2. 怎么装进来的

### 2.1 官方技能：原样收录 + 旁注

装在 `packages/skills/bundled/shopify/`：

- **原样**（一个字节没改，sha256 写在旁注里，测试逐个比）：`SKILL.md`、`references/liquid.md`、`references/custom-data.md`、`references/admin.md`、`LICENSE`。
- **没带**：
  - `scripts/`：search_docs / validate / log_skill_use / log_feedback 这几个脚本都会向 `shopify.dev/mcp/usage` 上报，内容包括查询、代码，以及经 `--user-prompt-base64` 传进去的**用户原话**。按 docs/42 的规矩，这属于"把用户业务数据发给第三方"。
  - `hooks/` 与 SKILL.md frontmatter 里的 `PostToolUse` 钩子：用来跑 `track-telemetry.sh`。
  - `assets/`：约 100 个压缩 schema，单个大到 1 MB。
  - `package.json`：它依赖 theme-check、typescript。
  - 另外 17 个主题的参考（Functions、Polaris、Hydrogen、POS、支付、Partner…）：都是给 App 开发者的，建站岗位用不上。
- **我们这一侧**：
  - `agentsws.json`（旁注）：上游 tag / commit / 每个文件的 sha256，加上 frontmatter 要补的键（`license: MIT`、`tier: open`、`version: 1.17.1`、`display_name`「Shopify 官方技能」、`summary`、`positions: site`），以及收哪几份参考。
  - `AGENTSWS.md`：Agents 工坊的六条规矩。
    1. 官方脚本在这里没有、也不要去跑，查文档改用 `shopify.docs.search`，校验改用 `shopify.graphql.validate` 与 `shopify theme check --output json`。
    2. 用户原话不出门。
    3. 只读 liquid / custom-data / admin 三题。
    4. 终端里只跑 `shopify theme list / pull / check / push --unpublished`，不跑 `auth` 和 `store`。
    5. 出卡；自动化级别不由技能改。
    6. 数字只从事实卡读。
- **入库时拼成一份**（`packages/skills/src/bundled.ts` 的 `composeOfficialSkill`），顺序如下：
  1. frontmatter：官方的 name / description，加上我们的键。官方的 hooks / metadata 不要。
  2. 「Agents 工坊里怎么用这本」：放最前，冲突时以这一段为准。
  3. 官方正文。
  4. 三份官方参考，每份一段。

  官方正文和参考的标题降两级，围栏代码块里的 `#` 不动。这样每份参考在我们的段切分里正好是一段，段名不会互相撞。拼好约 37 KB。
- `THIRD-PARTY-NOTICES` 加了 Shopify 那一节，附 MIT 全文。
- `upstreams.yml` 新登记三条：
  - `shopify-ai-toolkit`（ported，钉提交，盯 releases / readme / wishlist 与五个路径）。
  - `shopify-dev-mcp`（runtime-dep，1.15.0，`lockfile_single: false`，因为它不进 package.json）。
  - `shopify-cli`（reference，盯版本，主要看 Node 门槛有没有变）。

  每周上游例程能看到新版本。升级就是换这几个文件，再改旁注里的 tag / commit / sha256 / version，照 docs/42 走。

### 2.2 平台映射与闸（Luoye 10-05 追加那条）

- `packages/contracts/src/platform-kits.ts`：`PLATFORM_KITS`（平台 → `skills` / `skill_source` / `mcp` / `cli`），只有 Shopify 一行。辅助函数有 `platformKitOf`、`isPlatformSkill`、`skillOnPlatform`、`platformCliTelemetryOffEnv`。**通用代码里没有一处写死 `'shopify'`**。
- 判据只有品牌档案的 `storefront_platform`，每次现取。没设过的老品牌按档案缺省算（Shopify），存量行为不变。
- 几处闸：
  - **运行时**（`apps/server/src/runtime.ts`）：新增 `storefrontPlatform` 选项。平台对不上时，平台专属技能不进提示词、不进按需索引，`read_skill` 读不到；Dev MCP 工具不进工具面，也调不动。
  - **技能页 / 第三栏「设定 → 技能」**（同一个 `GET /v1/skills`）：按这个品牌的平台过滤。
  - **首次设置清单**：技能条目按这个品牌的平台过滤，另加 `platform_cli` 一格。
  - **CLI 卡**（`GET /v1/platform-kit`）：平台没有 CLI 时回 `kit: null`，**一次本机检测都不跑**。

### 2.3 Dev MCP

沿用 WP44 的接法：`AGENTSWS_SHOPIFY_DEVMCP=1` 才起，钉 1.15.0，子进程环境走白名单并关遥测。这一单加了两样：

- **平台闸**：非 Shopify 品牌的运行时里一个 Dev MCP 工具都没有。
- **登记**：出网清单和关遥测变量写进平台表那一行（卡片接口会回）；上游登记；测试钉住"代码里钉的版本 = 平台表里写的版本"。

### 2.4 Shopify CLI 引导

- **卡片**（`apps/workstation/src/components/connections/platform-cli-card.tsx`）：放在**连接页**（「已连接」下面）和**建站岗位页**（「连上这 N 个就能开工」下面）。卡上的名字、命令、教程全从平台表来。
  - 状态是三格图标（docs/36 第四档）：装好（旁边写版本）、Node（旁边写版本，tooltip 写门槛）、登录。
  - 没好的时候只给下一步：
    - 没装：给官方安装命令（可复制）和「装好了，再查一次」；
    - Node 不够：说要 22 或更新；
    - 没登录：给 `shopify auth login`（可复制）和「我登好了」。
  - 另有一句降级说明：没好之前，网页模板先走店铺后台接口，不能本地预览。
  - 好了之后卡上只剩那排图标。
- **登录**：
  - 卡上没有一个输入框。
  - 用户自己在终端跑登录命令，在浏览器里登。
  - 点「我登好了」只往品牌数据目录的 `platform-cli.json` 里记一个时间，没有账号、店铺和令牌。
  - CLI 自己的会话文件我们不读。
- **本机检测**（`apps/server/src/platform-cli.ts`）：
  - 只跑 `<cli> version` 和 `node --version`，结果缓存 5 分钟，「再查一次」不走缓存。
  - 子进程环境走白名单（同 `PASSTHROUGH_ENV`），另加关遥测变量。
  - 只取版本号，原始输出不进事件。
- **教程**：`docs/help/shopify-cli.md` 与 `.en.md`（检查 Node → 安装 → 浏览器登录 → 装好之后会怎样 → 常见问题），归在建站岗位 / 网页模板下。
- **首次设置**：用户选了 Shopify（或官网分析判断出 Shopify）并且勾了建站岗位时，完成屏多一句「建站岗位会用到 Shopify CLI，要现在装吗？」。
  - 「现在装」跳到建站岗位页（本人没拿到那条分配时退回连接页）。
  - 不点就是跳过，下面写着「之后在建站岗位页也能装」。
- **网页模板的命令白名单**（WP89 已有，这一单只核对、补测）：
  - 放行 `shopify theme list / pull / check / info / push --unpublished`。
  - `publish` / `delete` / `rename` / 不带 `--unpublished` 的 push 物化成「发布主题」卡（永远 L1）。
  - `shopify auth …`、`shopify store …` 和任意 shell 一律拒。
  - 这一单补的一处：Agent 在沙箱里跑 CLI 时，环境里带上 `SHOPIFY_CLI_NO_ANALYTICS=1` 与 `OPT_OUT_INSTRUMENTATION=true`（`shellCredentialPlan` 的 literals）。
- **降级**：CLI 不在或没登录时，卡上的 `degraded_roles` 是网页模板那一条，现有的 Admin API 路径照旧能用。

## 5. 我自己做的决定（白话）

1. **装 `shopify` 而不是 `shopify-liquid`**：官方 9 月底把 Liquid 那本并进了总的这一本，旧名已经退役。
2. **原样收录正文，脚本不带**：官方脚本会把用户原话和代码报给 shopify.dev，而我们的岗位面对的是商家的真实业务。查文档和校验的活交给关了遥测的 Dev MCP 与 `shopify theme check`，这条写进了技能最前面的规矩里。
3. **只收三份参考**（liquid / custom-data / admin）：另外 17 份是给 App 开发者看的，收进来只会让模型在建站任务里走岔。
4. **三条职责都按需加载**：37 KB 常驻太重。插件那条不挂。
5. **CLI 只归网页模板**：邮件模板在店铺后台改，不经过 CLI。卡出在建站岗位页和连接页。
6. **「登好了没有」靠用户点一下确认**：要自动判断就得去读 CLI 的会话文件，或者替用户跑一条连店铺的命令。前一种碰凭据，后一种要知道店铺、还会出网。现在只记一个时间，可撤回。
7. **Dev MCP 仍然要 `AGENTSWS_SHOPIFY_DEVMCP=1` 才开**：默认打开的话，每台机器（包括测试）一起来就会去 npx 下载一个依赖很重的包，1.16 版还依赖 `@shopify/cli >=3.93`。这一单只加平台闸，开不开留给 Luoye 定（§6）。
8. **Dev MCP 工具对 Shopify 品牌的所有职责都给，没有只给网页模板 / 邮件模板两条**：这是 WP44 起的现状，运营岗位写 Admin GraphQL 前也靠它查文档，有测试依赖这一点。收窄会让那几条退化，所以只加了平台闸。
9. **向导提示只在"Shopify + 勾了建站岗位"时出**：没勾建站的人看到「建站岗位会用到…」会摸不着头脑。
10. **demo 里 CLI 检测用替身**（当作没装、Node 22.12.0）：截图演的是「第一步：装」那一档，也不在 Luoye 的电脑上跑真 `shopify`。

## 6. 要 Luoye 定的事

## 11. 第二轮（Fable 10-05 改动 + 五问答复）

1. **平台没设 = 不启用任何平台套件**（不再按 Shopify 兜底）。`platformKitOf(undefined)` 回空。
   - 运行时的闸只在接了 `storefrontPlatform` 时生效，老单测与回放的字节不变。
   - 店铺连接那张表（缺省按 Shopify）没动。
2. **没设平台、但连了 Shopify 店铺（有 `shopify_admin` 连接）→ 推断为 Shopify 并写回品牌档案**（`apps/server/src/platform-kit.ts` 的 `resolveBrandPlatform`）。
   - 只有正好连了一个平台的店铺才推断。
   - 写回时记一条事件 `workspace.storefront_platform_set { source: 'inferred_from_connection' }`。
   - 界面上可以改：选平台那一行，或设置里的品牌档案。
3. **建站岗位页的「先选一下你的建站平台」**：一行字加一个下拉。
   - 只在平台没设、而且是建站岗位页时出现，岗位范围取平台表里所有 CLI 的岗位并集。
