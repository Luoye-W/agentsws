### 几个白话说明

- **为什么 mailparser 也得升**：mailparser 自己**钉死**了一版 nodemailer（3.9.23 钉的是 10.0.1，正好在公告范围里）。只升我们自己写的那行 nodemailer，收信那条路上仍然用的是旧的那份。3.9.39 钉的是 10.1.1，和我们一致，pnpm 锁里就只剩一份了。
- **nodemailer 跨了三个大版本（cloud 是 7 → 10），为什么没改代码**：10.0 的破坏性改动只有「要 Node 20 以上」和「改成 TypeScript 写、同时出 ESM / CJS 两种包」，`createTransport` / `sendMail` 这些名字都没变。我们的安装包是 Node 22、云端镜像是 node:22，都满足。cloud 加了一条测试钉住「真 transport 建得起来，失败出在投递而不是加载」。
- **本机连接器那边上游用了 nodemailer 的三处**（发信、飞书邮箱拼信、mailparser 解地址），我在 scratchpad 里用新锁文件真装了一遍（`npm ci --ignore-scripts`，317 个包），三处逐个加载、拼信、发一封不联网的信、再解析回来，都正常；然后按 docs/42 第 5 步起了真宿主脚本：匿名 `/v1/health` 401、带令牌 `/v1/providers` 200、邮箱类 provider 都在。
- **MCP 那条修的是什么**：我们给自定义 MCP 地址带的请求头常常就是密钥。旧版 SDK 遇到「这个地址跳到另一个网站」会照跳，Node 自带的 fetch 只会剥掉 `Authorization` 这一个头，`X-Api-Key` 这类自定义头会跟着送过去。我在本机起了两个端口实测对照：旧行为对面收到了密钥，新版一个请求都没发。用户看到的那句话是：「这个地址会跳到另一个网站（xxx），为了不把请求头里的密钥带过去，工坊不跟着跳。请直接填跳转后的地址。」

## 2. 我自主做的决定（白话）

1. **nodemailer 三处都用 10.1.1，没用派单写的 10.1.0**：10.1.1 是 10-14 出的，只多修了一条「取附件 / 令牌时遇到跨站跳转把凭据剥掉」，和 MCP 那条是同一类问题；而且 mailparser / smtp-server 的新版钉的都是 10.1.1，用同一版 pnpm 锁里才只有一份。（第 923 条请你确认。）
2. **锁文件脚本改成默认「在旧锁上增量解」**：第一次按原脚本从头解，除了 nodemailer 还顺带把 30 个无关的包（aws-sdk、zod、mqtt……）漂到了新版本。安全修复不该夹带这些，所以改成默认只动变了的包，换 OpenConnector 版本时加 `--fresh` 才从头解。
3. **测试用的 smtp-server 也升了**（3.19.9 → 3.19.22，只在测试里用）：它也钉了旧的 nodemailer 10.0.1，不升的话 pnpm 锁里还会留一份带公告的。
4. **`@types/nodemailer` 留着没删**：nodemailer 10 自带类型了，但 `@types/mailparser`、`@types/smtp-server` 本身依赖它，删了也还在树里；编译全过，不折腾。
5. **imapflow 只登记、没升**（钉在现在的 2.0.0，最新 2.4.3）：它没有安全公告，这单只修有公告的；登记进去以后周报会提醒。
6. **MCP 不给「仍然跟着跳」的开关**：上游留了 `redirectPolicy: 'follow'`，但开了就回到会泄露密钥的老样子。真有用户的服务必须跳转再说（第 925 条）。

## 4. 要 Luoye 定的事（每条附建议）

**923. nodemailer 用 10.1.1（派单写的是 10.1.0）可以吗？**
10.1.1 比 10.1.0 多修一条凭据跟着跳转外泄的问题，而且收信用的 mailparser 新版本身就钉 10.1.1，用同一版锁里才只有一份。
**建议：同意，用 10.1.1。**

**924. 已经装过本机连接器 1.8.0 的电脑，不会自动换成新的 nodemailer，怎么办？**
安装器按「版本号」判断装没装好；这次 OpenConnector 还是 1.8.0，只换了里面一个包，所以**已经下载过连接器的电脑会继续用旧的那份**，只有新装的才是 10.1.1。
现在没有真实用户（只有你的 Mac 和 Windows 测试机），手动处理一下就行：设置 · 诊断里「删除下载」，再点一次「连接」，会按新锁文件重新下（约 30 MB，连接和凭据不丢）。
要做成自动的，得给安装器加一个「同版本换了锁文件也重装」的判断，动的是 current.json 和版本目录的规矩，不小。
**建议：这次手动；「同版本换锁也重装」并进 OpenConnector 1.9.0 迁移那一单做**（那单本来就要换版本、动安装器）。

**925. 会跳到另一个网站的 MCP 地址，要不要给用户一个「仍然跟着跳」的开关？**
现在是一律不跟、给一句人话让用户填最终地址。给开关就等于让用户自己选「要不要冒把密钥交给别的网站的风险」，非技术用户判断不了。
**建议：不给。真有哪家 MCP 服务必须跳转，再按那一家单独处理。**

**926. 批量安全查询查出来的另外两条运行时问题，要不要马上开单？**
这单顺手对整个依赖树跑了 `pnpm audit`（只看不修）：严重 4、高危 16，绝大多数在测试 / 打包 / 建站工具里（vitest、wrangler、electron-builder、astro、shadcn 命令行），不进用户手里的程序。**进运行时的有两条**：
- `proxy-addr` 2.0.7（严重，GHSA-jqcg-44mw-7w3h）——MCP SDK 带进来的 express 里的。我们只用 SDK 的客户端、不起它的 express 服务器，实际碰不到，但它在服务进程的依赖树里；
- `compression` 1.8.1（高危，GHSA-vc2v-76pw-4v95）——dsh 的 `dsh-host-webserver` 带进来的，要看我们有没有走到那个 web 服务器。
**建议：另开一个小单，用 pnpm overrides 把这两个顶到修好的版本，并把「运行时依赖的批量安全查询」加进周报**（这次的四件都是因为没登记、哨兵看不到才漏的）。我已在会话里放了一张建议卡。
