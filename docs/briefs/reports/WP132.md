## 2. 我自主做的决定（白话）

1. **按 0.1.7-rc.1 升，不按"0.1.7.2"**：npm 上没有这个号。0.1.7 系列有 alpha.1、alpha.2、rc.1 三个，rc.1 最新也最稳，就升它。
2. **"四个包一起升"实际升了 49 处**：dsh 的几十个包互相依赖、必须同一个版本，只升四个装不上。
3. **cordis / schemastery 跟着升**：新版 dsh 明确要 4.0.4 / 3.18.4，旧号装不进同一棵树；这是 docs/42 说的"必要时"。kernel 等下游测试全过。
4. **给 `verify-changed.sh` 补了一步**：升级后我先跑了一次增量类型检查，它说"全绿"，其实 dsh-adapter 有 14 处类型错误——
   增量检查只看源码有没有改，看不见依赖包的类型变了。这会让以后每个动依赖的派工单都可能"假绿"，所以顺手补上（只在锁文件变了时多跑几秒）。
5. **profile 层多关三行**：它们在我们的运行时里本来就没挂（实测模块图 0 命中），但按红线 7 不能靠"碰巧没挂"；其中 `config-editor` 能改写我们的安全配置，必须关。
6. **preset 定义直接 `register()`，不用官方的"声明行"插件**：我们的 preset 是每次运行按职责现生成的，不是写死在配置里的一行；两种都是官方入口。
7. **收尾重采了一次基线**：合并 main 后那道积分题修好了，就在 main 的树上把"升级前"重采成完整 62 条，免得仓库里留一份带"跳过"的基线。
8. **下载了桌面包需要的捆绑 Node**（`apps/desktop/scripts/fetch-node.mjs`，按锁文件 sha256 校验的官方 Node）：新 worktree 里没有，`package --dir` 缺它会失败。只落在 `vendor/`（已 gitignore）。
