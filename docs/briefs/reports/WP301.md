## 4 自主做的决定（白话）

1. **工具名不改**（仍是 `theme_init_from_base`，只换行为）：旧回放、工具白名单、dsh 那边的名单都不用动；「起底」这个词本来就是「从一个底子开始」。
2. **只认 `theme_name == "Horizon"`**，同一套代码的姊妹主题（主题商店里那几款）先不认——见第 7 节第 2 条。
3. **复制线上那一份**（店家当前的颜色、字体、首页设置一起带上），不是复制一份全新的 Horizon。
4. **不往工作目录写 AGENTS.md**：CLI 现在会把根目录的 AGENTS.md 推进店里；规矩写在系统提示词里就够了。目录文件起名 `CATALOG*.json`，CLI 不推。
5. **模板检查只提醒不拦**：我们的目录算不准的边角（应用块、以后 Horizon 加的新写法）不该把活卡死，官方 `theme check` 再兜一层；真 Horizon 自带模板查出 0 个问题。
6. **旧目录起底时不要求 replace=true**：旧的就是要换掉的，挪去 `legacy/`（不删）；普通工作目录照旧要 replace。
7. **拉线上那一份（`theme_pull`）时也把旧目录先挪开**；拉下来的不是 Horizon（店家自己别的主题）就照 WP253 的老规矩不限改哪几类文件。
8. **契约只加不删的例外**：`THEME_BASE` / `ThemeBasePin` / `ThemeFetch` / `fakeThemeBase` 与 `createServer({ siteTheme: { fetch, base } })` 两格删了——它们就是「钉我们主题、下载起底包」本身，派工单要求删。`SiteThemeView` 只加（`workspace.legacy`、`base.theme_name / source_theme_id / copy_theme_id`），`ShopifyTheme` 只加（`duplicate` / `rename`、`pull` 的 `only` / `path`）。`base.commit` 对店里那一份填空字符串。
9. **测试夹具全是手写的**：`FAKE_HORIZON_FILES`（十几个文件，形状照 Horizon，内容是我们自己写的），不录真 Horizon 的 schema——许可不允许分发它的任何部分。真 Horizon 只在 scratchpad 里浅克隆来量生成器，没进仓库。截图里的目录表是用那份克隆现生成的（只有分区 / 块的 id、英文名、分类，没有代码）。
10. 决策号：派工单说从 400 起，但 main 上 400–417 已经被别的事用了（合 main 时看到），这里从 **418** 起。

## 5 第二期要做的

1. **店里没有 Horizon 的那一类店**（老店线上是 Dawn 等）：现在只会说「请从主题商店加一份」。可选做法：(a) 在岗位页那一行出一个「去主题商店添加 Horizon」的按钮（深链到 `admin.shopify.com/store/<店>/themes` + 主题商店页）；(b) 经 `themeCreate` 用 GitHub 上的 Horizon zip 直接装——许可上属于「给商家在他自己店里用」，但那是 `main` 分支（可能带没发布的功能）、而且等于我们替用户下载分发，**不建议**。
2. **Horizon 的姊妹主题**（同一套代码、主题商店里另外几款）也认作可用的底，目录生成器本来就通用。
3. **自己截图看效果**（Rollout 记录里第一大坑：静态检查查不出白字压浅图、窄屏标题压产品）：推完预览用内置浏览器 1440 / 375 两个宽度各截一张给模型看。
4. **本地图片上传到店铺文件**的通道（Rollout 记录第二大坑；WP268 已有 `fileCreate` 那条，建站岗位里还要接好）。
5. **编辑器「添加区块」视角**（Rollout 记录第 9 节）：Horizon 的 `@theme` 会把所有公开块都放进选择器，这是 Horizon 自己的事、我们不改核心；但可以在目录页提示模型「挑跟这个分区搭的块」。
6. **字体 handle 表**内置进目录（Rollout 记录建议 #2）：`settings_data.json` 里的字体写错了 `theme check` 查不出。
7. **`theme check` 对 Horizon 的规则集**（`ValidBlockTarget`、`JSONMissingBlock` 等）结果直接喂回模型，和我们的 problems 合并去重。
8. **旧 `legacy/` 目录的清理入口**（设置 → 诊断「清理旧主题副本」），同 WP296 决策 378 的口径。
9. dsh 档里网页模板那条职责还带一个终端沙箱，理论上能在工作目录里改核心文件——要不要把商店层规矩也搬进 dsh 的门禁。
