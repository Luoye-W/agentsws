## 2. 调研要点（详见 docs/88 §1）

调研了 16 家：Gmail AI Inbox、Superhuman、Shortwave、HEY、Spark、Notion Mail、Front、Missive、Intercom、Gorgias、Zendesk、Help Scout、Chatwoot、Linear、Outlook、Inbox Zero。只看了公开页和帮助文档，没有注册或登录。其中三家是并行起的子代理查的，出处 URL 写在 docs/88 §1.1 表后面。能拿来用的有五条：

1. 按「AI 做到哪了」组织，渠道只是筛选；
2. 每个判断都带理由和把握，权限一档档放开；
3. 纠正要被学到，而且学到了什么要看得见（Zendesk、Help Scout、Spark 都明说纠正不回流，这正是我们能做得更好的地方）；
4. 噪音成捆处理；
5. 跨渠道认人：强信号自动合、弱信号只提示，合了能拆（Chatwoot、Gorgias、Zendesk 合并后都拆不开）。

## 3. 设计（详见 docs/88 §2–§7）

- **一条流**：邮箱、聊天窗、WhatsApp、社媒私信进同一个收件处，列表上一行就是一段会话；渠道和账号只做筛选与头像角标，账号另用一套专用六色。
- **四格判断 + 一行摘要**：类型（10 个，单选）、岗位（接 54 路由）、要不要你（等你批 / 要你看 / Agent 在办 / 只需知悉）、急不急（客户在等 / 今天 / 不急）。「要不要你」由服务端按事实派生，**不让模型猜**。判断可以一键改：勾上「记住」就写一条发件人规则，不勾的改动进学习回路，攒够了出选择卡问你；右栏「你教过它」把学到的东西摆出来。
- **草稿卡进消息**：卡就是首页那张，同一个 id，在哪批了三处一起消失。按钮文案照 36 的排版规则；岗位对话里没有回复框，只有「教 AI」（36 §13.3）。草稿下面附中文译文，按需生成。
- **同一个人**：自动挂只认三种强信号——同一个邮箱、聊天窗访客留下的邮箱、订单能背书的电话或订单号；其余只出建议卡。合并记 `merged_from`，可以拆开。只在一个品牌工作区内认人，判断只用归一键，不送模型。
- **动作**：归档、删除（先二次确认，删到垃圾箱，能撤销）、稍后（对方有新消息时也回来）、转岗位、改判、批量（整捆 / 多选）。一律遵守「客信怎么动邮箱」开关：影子模式下这些动作只在本地生效。
- **推荐**：A 做消息页默认，点卡片进 B 的对话视图作为展开页。两个方向用的是同一套组件。

## 4. 我自己拍板的（白话）

- 「要不要你」这一格不交给模型判断，只看几件事实：有没有挂卡、事项到了哪一步、分拣有没有判准、这封要不要回。原因是猜错了，人会以为 Agent 在忙。
- 列表上不把跨渠道的会话合并成一行，只在对话视图里把时间线并起来。否则那一行到底从哪个渠道回，就说不清了。
- 类型是单选；原来那 11 个标签降成次要标签，保留不动；「可疑」算一面旗，不算一种类型。
- 看板方向不画：消息的状态是由事实决定的，不该让人拖来拖去。
- 设计稿里的渠道图形是我自己画的通用图形，没有用任何商业产品的图标素材。实现时换成 `<BrandIcon>`。
- 做完合并 main 时看到 Luoye 09-30 的新要求（WP208：邮件助手不放第三栏，要集成在消息里），就把 docs/88 补了一节 §5.1b，设计稿的第三栏图标轨也去掉了邮件助手。

1. 方向：A 做默认、B 做展开页（推荐），还是只要其中一个；
