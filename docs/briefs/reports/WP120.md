## 1. 实现清单

1. **两层 persona 全覆盖**：九个岗位模板（`packages/roles/positions/*.yml`）与四十一条职责（`packages/roles/roles/**/*.yml`）每条都写上六段骨架（你是谁 / 你负责什么 / **你不负责什么、转给哪个岗位** / 怎么做 / 口气 / 必须出卡），中英各一份（`{zh, en}`，老的纯字符串仍兼容）。`packages/roles/src/persona.ts` 是唯一真源（纯函数：取语言、叠覆盖、拼段、校验）；`gen-ontology --check` 把 persona 为空判成失败——不许留空是门禁不是自觉。
2. **接进三个运行时**：装配顺序 品牌 → 岗位段（order 10）→ 职责段（order 20）→ 技能索引 → 47 J3 → 工具；direct 与 stub 共用 `assemblePrompt`（17 §1 的顺序只有一处定义），dsh 写进 `agentsws:persona` 那唯一有效的 complete 段。运行时装提示时**现查**覆盖表——公司在右栏改完，下一次运行就是新的，不用重启。
3. **stub 改成认职责**：按 `role.domain` 选剧本（`kol` 域走红人剧本、`dtc` 的客服三条走客服剧本），**其余三十多条一律没有剧本**——回一句人话说清是哪条职责、这是演示的限制，不调工具、不 stage、不出卡。绝不再拿客服剧本兜底（`dtc` 域故意不整域映射：它是唯一一个"一个域里两种活"的域）。
4. **右栏「角色」面板**（走 `registerPanelBody`，registry 接口未动）：岗位层看定位 + 下属职责清单，职责层看定位 + 属于哪个岗位；公司层可改写（另存覆盖层，**包里的原文一个字不动**、随时还原）、每改一次记审计（`persona.overridden` / `persona.reverted`）。能不能改由服务端说，面板照 36 §10.1 先把按钮画出来。
5. **串岗测试四层**：内容（crosswalk 对着包里真的那几段钉死跨岗位转向，如红人岗不问退款窗口）、装配（direct + dsh 各一组，含替身模型实际收到的 messages）、路由（新场景 `org/positions-stay-in-lane`：五个岗位挂在同一个人身上各发一句典型的活，断言各自待在自己的道上）、服务（看 / 改 / 还原 / 审计 / 两道门 / 晚绑定）。
6. **文档**：`docs/69-岗位与职责的角色定位-v1.md` 新建；`docs/27`、`docs/54` §3、`docs/66` #1 同步。

## 2. 自主做的决定（白话）

- **岗位 persona 的原文以包里的 yml 为准**：`org.positions()` 存下来的行不抄 persona 字段——抄进去等于把原文冻在首次设置那天，包升级了定位不会跟着走。存储行只用来确认"公司确实有这个岗位"，原文每次从 yml 现读。这是 Qwen 接手时修掉的一个真 bug（没修之前岗位那一段整段不出，两层 persona 只剩一层）。
- **写权限的判定口径改成「按人」而不是「按本次绑定的分配」**（本棒修，见 5）：公司层 persona 只有 owner 改得动，这条不变；变的是网关不再拿"当前恰好绑着哪条职责的分配"去判 `policy.stage`——右栏面板挂在职责页上，绑的天然是职责的分配，而职责的 yml 里没有 `policy.stage`，照判连 owner 都进不去。
- **运行时装的是中文那份**：界面语言没有落盘的地方，`docs/69` §3.3 照实说了，没装不懂。
