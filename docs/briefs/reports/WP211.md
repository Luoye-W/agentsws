行为（与企业微信一致）：

- 私聊都收；群里只收 @ 了机器人的（飞书看 mentions 里有没有机器人自己的 open_id，@所有人不算；钉钉看 `isInAtList`）；机器人 / 应用自己发的不理。
- **认人**：工作台点「绑定我的账号」拿 6 位码（10 分钟、一次性），私聊机器人发「绑定 123456」（英文 `bind 123456`）。码只显示给登录了工作台的那个人，所以谁拿着这个聊天账号由他本人证明；同一个聊天账号 10 分钟猜错 5 次就不认。绑定表进本机加密库。认不出的人只回一句「先去绑定」，不代答。
- 按提问人身份问**他自己的**代理（`secretary.ask`，41 §1.3 照常）；推给人的只有「摘要 + 去工作台处理」，不放通过 / 驳回按钮。
- 凭据只经原生表单进本机加密库：不进 React state、不进事件 / 日志 / 响应体 / 状态，提交完 `form.reset()`。
- 连不上给人话：飞书（App ID / Secret 不对、没开长连接或没发布、连接数超限、暂时连不上）；钉钉（凭据不对或没开 Stream、暂时连不上）。凭据错就停，不空转。
- 断线重连：飞书由官方 SDK 管（我们跟它的状态走）；钉钉 1s → 60s 退避、服务端发 `disconnect` 主动换连接。
- 飞书事件回调立刻返回（3 秒内要回执）、钉钉回调先回执再处理（60 秒内要回执），问代理放进 18 §2 管线（去重 / 重试 / 死信）。
- 钉钉回复只许发往 `https://*.dingtalk.com`；群里 @ 回提问人。

## 2. 我自己拍板的（白话）

1. **钉钉不直接用官方 SDK，而是照它移植协议。** 官方 SDK 在凭据填错时会每秒重试、而且不告诉我们错在哪，界面上就只能永远显示「连接中」。移植后的代码不到 300 行，跟企业微信那条长得一样，测试全在内存里跑。等官方 2.1.7 转正（已经在补退避和错误可见），登记表里会提醒重判。
2. **飞书用官方 SDK，但懒加载、不引它的类型。** 包 30 MB（类型声明占 17 MB），静态引入会拖慢全仓类型检查；没配飞书的机器一次都不加载它。
3. **认人用「工作台发码、聊天里发回来」，不用「聊天里发码、工作台填」。** 后者在群里发码时，群里任何人都能拿去在自己的工作台上认领别人的账号；前者的码只有登录了工作台的本人看得见。
4. **企业微信顺手接上真连接。** WP85 只做了注入口，服务进程里没传 `ws`，界面上填了 BotID / Secret 也永远是「连接中」。这次一并接上，并换成同一套绑定认人（原来的 `personByWecomUser` 注入口仍然优先）。
5. **没配时卡上只有一个主按钮「填应用凭据」**，点开才出表单——照 WP210 的少字规矩（名字 + 问号 + 状态 + 主按钮）。「凭据只存本机、不经 AI」挪进 Secret 那一格的问号，没在卡上再放一条安全承诺。
6. **App ID 形状先校验。** 飞书官方 SDK 遇到不是 `cli_` + 16 位的 App ID 会悄悄不连、也不报错；我们在服务端和适配器里都先拦下来给人话。
7. **加了「断开」**（企业微信没有）：断开 = 销毁本机那份应用凭据。
8. **图标 id 用连接目录的 kind**（`feishu_bot` / `dingtalk_bot`），与 WP48 的约定一致；抓取沿用现有的 `scripts/fetch-brand-icons.mjs`（WP210 要新写 `fetch-provider-favicons.mjs`，到时把这两条并过去即可）。

## 3. 要 Luoye 做或定的事

1. **真机走一遍（必须）**：这一单全用替身测，没连过真飞书 / 钉钉。需要你（或指定的人）：
   - 飞书：在 [飞书开放平台](https://open.feishu.cn/app) 建一个企业自建应用 → 加机器人能力 → 开三个权限（单聊消息只读、群 @ 消息只读、以应用身份发消息）→ 复制 App ID / Secret 填进工作台 → 回开放平台把事件订阅方式改成「长连接」并加事件 `im.message.receive_v1` → 发布。飞书保存「长连接」时会检查连接在不在，所以要先填工作台。
   - 钉钉：在 [钉钉开发者后台](https://open-dev.dingtalk.com) 建企业内部应用 → 加机器人、消息接收模式选「Stream 模式」→ 复制 Client ID / Secret 填进工作台 → 发布。
   - 两边各做一遍：私聊（没绑时应回「先去绑定」）→ 绑定 → 私聊提问 → 拉进群 @ 它提问 → 把 Secret 故意填错看卡上的人话。
   教程里就是这些步骤（`docs/help/im-feishu.md` / `im-dingtalk.md`）。
2. **谁能填 / 换公司的应用凭据**：现在与企业微信一致，工作区里登录的人都能填、能断开。要不要收紧到负责人 / 管理员？
3. **飞书 / 钉钉主动推卡**：这一单只做了「问 → 答」。审批卡主动推到飞书 / 钉钉（`deliverCard`）仍只走个人微信；要不要下一单接（飞书需要 `im:message:send_as_bot`，教程里已让开；钉钉要「企业内机器人发送消息」权限）。
4. **个人电脑关机就收不到**：长连接跟着这台电脑走。要不要把团队渠道挪到云端值守，是另一件事。
