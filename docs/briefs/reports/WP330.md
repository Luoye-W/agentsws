# WP330 报告：Reddit 周报（周五下班前出、数据周日—周五）

分支 `wp/330-redditweekly`（从 10-14 main `8ac4c67f` 建）。没推、没合、没打 tag、没发版。全程没读 `.env*` / `.dev.vars`、没碰任何 key / token / 账号、没打开真实 Reddit、没连远程机器、没碰 4317；数据全用替身。

## 1. 做了什么（白话）

每周五 17:00（可改），工坊先让 WP328 做本周最后一次巡查，再出一份 Reddit 周报：

| 节（默认标题，可改） | 内容 | 数据从哪来 |
|---|---|---|
| 自家版块数据 | r/inmoxr 本周帖子数、评论数 | WP328 巡查入库的条目（按 Reddit 上的发出时间进窗口，同一条只算一次；被删的照样算数） |
| 自家版块 VOC 与 UGC | 只列 WP328 判过「有效」的；每条原文 + 作者 + 时间 + 链接 | 同上 |
| 外部社区 VOC 与舆情 | 按话题归组：「话题概括（post × n / comment × n）」+ 评估（日常讨论无需处理 / 相关度不高不建议回复 / 需跟进）；下面列每条原文（作者、版块、时间、链接） | 同上；同一话题跨天合并，评估取组里最重的那一档；按严重度、条数排 |
| 我们本周的回复 | 回帖子 n · 回评论 n（· 发帖 n）+ 链接清单 | WP323 发出记录（渠道 Reddit、已发、窗口内；`t1_` 父级 = 回评论，其余 = 回帖子） |

- **不截图**：一律原文引用 + 链接（被删的原文不引用）。
- **出在哪**：社媒（Reddit 运营）岗位页的「报表」那一块整张摊开（与经营一页纸同一类：看一眼就过，不进审批队列）；卡上一排数，几节按配置顺序，原文默认收着、点开才见；右上两个小图标「复制整份」「导出 .md」。
- **文档格式**：Markdown（飞书 / Notion / Google 文档都能直接贴；`/v1/reddit-weekly/export` 也能拿）。
- **记录去处**：用户在去处的筛选里点名 `weekly_report` 的，记一行（正文 = 整份周报）；没点名的去处不收（周报不混进回复记录表）。
- **分节与措辞几句话就能改**：担 Reddit 运营的岗位里说一句（「外部那节叫『全域 VOC & 舆情监测』放第一」「评估改成 建议跟进」「周四 18:00 出」），AI 先看现在的样子、再只改要改的那几项；四节的顺序 / 标题 / 开关 / 引言、编号、三档评估写法、原文截断、每个话题列几条、时间写法、窗口从周几起、每周几几点出，都能改；认不出的照实回。INMO 只是第一个用户，默认格式是通用说法。
- **没配 Reddit 巡查 / 没人担 Reddit 运营就不出**（不出 0）。
- **关机错过**：周五没开机、周六开机照样补出这一周；跨进下一周头两天才开机，出上一周（周日 00:00 — 周六 23:59:59）。

## 3. 需要 WP328 提供的数据形状

WP330 只认一个口子 `RedditWeekSource`（`apps/server/src/reddit-weekly.ts`，一个品牌一份），由 `createServer({ redditWeekSource: (ws) => … })` 接上；WP328 合进来之前默认是「没配」（周报不出）。WP328 要做的就是在 `server.ts` 里把这一行换成自己的存储：

```ts
interface RedditWeekSource {
  configured(): boolean | Promise<boolean>          // 有自家版块或外部关键词就算配了
  subreddits(): string[] | Promise<string[]>        // 自家版块（用户配的，不带 r/）
  items(window: { since; until }): RedditWatchItem[] | Promise<…>   // 窗口里入库的条目（多给也行）
  sweeps(window: { since; until }): Iso8601[] | Promise<…>          // 窗口里每次巡查跑完的时间
  sweepNow?(): Promise<unknown>                     // 现在巡查一次（周报前的「本周最后一次」）
}

interface RedditWatchItem {                         // packages/contracts/src/reddit-weekly.ts
  id: string                // Reddit 全名 t3_… / t1_…（去重用）
  kind: 'post' | 'comment'
  scope: 'own' | 'external' // 自家版块 / 外部关键词命中
  subreddit: string         // 不带 r/
  author?: string           // 不带 u/
  created_at: Iso8601       // Reddit 上的 created_utc（窗口按它算，不按读到的时间）
  permalink: string         // 完整 https 链接
  title?: string            // 帖子标题；评论给所在帖子的标题
  text: string              // 原文
  deleted?: boolean         // 被删了：照样计数，不引用原话
  signals?: { voc?: boolean; ugc?: boolean; note?: string }   // 自家版块：判过有效才带
  topic?: { key: string; label: string }                       // 外部：话题（key 跨天稳定，label = 话题概括）
  assessment?: 'no_action' | 'low_relevance' | 'follow_up'     // 外部：评估
  keyword?: string                                             // 外部：命中的关键词
}
```

对齐要点：
1. **周五 17:00 那次巡查由周报触发**（`sweepNow`），WP328 不必再单独排一条「周五 17:00 最后一次」——两条各排各的会抢先后。WP328 的每日巡查照旧。
2. **话题 `key` 要跨天稳定**（同一件事这周三天都读到，key 一样才合成一组）；没给 topic 的按关键词归组。
3. VOC / UGC「只记有效的」由 WP328 判：无效的不带 `signals` 或带 `false`。
4. 原文被删时 WP328 标 `deleted: true`（或清空 text），周报不引用。
5. `sweepNow` 抛错不挡周报：照样用已入库的出，并在 `run` 的回包里带 `sweep_failed`。

## 4. 我自主做的决定（白话）

- 周报卡不新造卡种：用经营一页纸那一类（`weekly_review`，报表，不进审批队列、看完归档），payload 自己认得出（`kind: reddit_weekly`）。卡发给担「自家版运营」`social.reddit` 的人，没人担就发给担 `pr.reddit` 的人。
- 同一周再出（手动点 / 补跑）= 同一张卡出新一版，不会一周两张；存着的那一份也覆盖。
- 窗口按 Reddit 上的发出时间（`created_utc`）算，不按我们读到的时间——周日读到周六晚上的帖，不算进新的一周。起点算、出报告那一刻算，之后的不算。
- 被删的帖子 / 评论照样计数（它确实发过），但不引用原文（Reddit 条款）。
- 「我们本周的回复」只认发出记录里渠道 Reddit、状态「已发」的回复 / 评论 / 发帖；回的是 `t1_`（评论）算回评论，其余算回帖子（WP249 起老路回的都是帖子本身）。
- 分节与措辞改了直接生效、不出确认卡：只改我们自己的周报怎么写，不往外发任何东西；AI 回一份小节标题预览，不满意再说一句（见决策 767）。
- 周报不自动进记录去处：去处筛选里点名 `weekly_report` 才写（见决策 768）。
- 导出选 Markdown，不做 docx（见决策 766）。
- 关机补跑：跨进新一周头两天出上一周，超过两天不补（只能手动出这一周）（见决策 769）。
