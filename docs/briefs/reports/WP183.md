## 2. 我自主做的决定（白话）

1. **「整个装进去」直接判不推荐（方案 C）**，理由写成可核对的三条：官方界面是 React 18、要求插槽组件不许 iframe（我们工作台 React 19 + Tailwind，要重画）；
   插件跑在官方桌面端进程里、退出应用就停（巡检、收邮件、聊天窗不成立）；服务端靠 `better-sqlite3` 原生模块，官方桌面端里装包用的 Node 与跑插件的 Electron Node 不是一份，加载风险高。
2. **方案 B 推荐先走 MCP 口而不是插件直连我们的 `/v1`**：插件侧几乎零代码（官方现成的「只带配置的 MCP 组合包」模板），跟官方升级最稳，同一个口 Claude Code / Codex 也能接。
   这会推翻 38 D5 与 53 §5 两条旧决定，所以列进待定（§6 第 4 条），没有替 Luoye 定。
3. **数据边界建议「不去改用户官方应用里的上报开关」**：技术上组合包能覆盖那几行，但那是改用户自己选的应用、且用户 patch 层优先级更高；改为在插件说明页写一句白话。
4. **把「官方桌面端从哪下载」「原生模块能否加载」等五条标为未核实**，不猜。
5. 岗位颗粒度推荐「一个总包、10 个岗位一行一个 preset」，职责作为 preset 里的人设段，而不是 46 个 preset（选择器里放不下，也符合「岗位是主入口」）。
