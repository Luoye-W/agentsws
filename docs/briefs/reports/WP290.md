## 4. 我自己定的（白话）

1. **服务端在冒烟进程里起，不另起一个服务进程**：用的是同一份 `createServer` + 真 HTTP（随机端口、内部令牌只在进程里），这样能直接读事件日志拿原始错误。安装包里的服务进程入口没变。
2. **每条职责都跑一次**：一次运行只用一条职责的工具，要「全部职责的工具都过 dsh」只能每条跑一次。48 条职责 + 每岗位 3 次，本机 40 秒。
3. **「负责人」只验工具**：它在 docs/54 §6.5 是身份、不是干活的岗位（左栏没有它的岗位页，岗位视图也不挂它的卡），所以只做「建岗位 / 工具过 dsh」，其余格写「身份那一行」。「普通成员」只有底座职责，不进表。
4. **WP287 那几格怎么判**：开事项的回包里有没有 `mode` = 服务端有没有 WP287。没有就记「等 WP287」（带上现在看到的样子），不算失败；有了就严格判。这样今天 main 上 CI 不会红，WP287 合了以后自动收紧，不用改脚本。「点卡 403」也按这一条（它是 WP287 第 6 条修的）。
5. **老服务端没挑职责时**：照人会做的那样按候选第一条（没候选就岗位第一条职责）`reroute` 接着做，格子里注明；新服务端如果还没起运行就判红。
6. **自测怎么改坏**：10-09 那种「嵌套对象没写 additionalProperties」现在会被热修的转换器自动补上，原样改坏复现不了；改成 dsh 不认的联合类型（`['object','null']`），同属「dsh 编译不过」一类，冒烟红、报错里带 `parameters.images.items`。自测钉在进程内 dsh（要在本进程里改参数表），实际冒烟用子进程（与安装包一样）。
7. **发版流程也加了门**：`release.yml` 也在打包前跑同一条（mac 两台也跑，顺带）。
8. **假模型的 key**：`smoke-not-a-real-key` 只为过表单校验；临时数据目录的本机加密库钥匙每次现生成、随目录删掉；`DEEPSEEK_API_KEY` 等变量在冒烟进程里只删名字、不读值；云 / 连接器地址指到 `127.0.0.1:9`，局域网发现关掉。
