# WP381 报告：商品信息机器可读体检、网站技术体检（AI 爬虫 / 原始 HTML）、AI 来源流量（决策 1066；待定 1072–1076）

分支 `wp/381-site-health`（worktree `../agentsws-wt/wp381-site-health`），从 main 拉，收尾前合了最新 main。Claude 子代理，2026-10-17 ~ 10-18。
**没合 main、没打 tag、没发版**。没读 `.env*`、没碰任何 key / token、**没调任何付费接口、没连真实店**（店铺、网页、模型全用替身或录好的样本）、没连远程机器、没碰 4317（截图用 4481，拍完 demo 即停、端口已放）、没批量清理、没用 pkill、没写 `.review-ready`。用户看得到的字里不提任何数据商。

**一句话**：现在每周一（或点报表块右上角的刷新钮）工坊会替你给网站做一次「AI 读不读得到你的店」体检——AI 爬虫被 robots.txt 挡没挡、价格库存卖点政策在不跑脚本的页面里有没有、店铺后台和页面 / 结构化数据 / feed / 其他平台上的商品信息对不对得上、够不够格进 ChatGPT 购物；对不上的清单自动交给网站运营去改。另外「内容与搜索」多一个实测数：近 7 天从 ChatGPT、Perplexity 等 AI 来的成交，GEO 周报里和「AI 提没提到你」并排写一行。

## 1. 实现清单（白话）

**① 商品信息机器可读体检**（网站运营看）
- 以店铺后台为准，抽查最近更新的 5 件上架商品（1–20 可调），逐处对：商品页文字、页面里的结构化数据（JSON-LD Product / Offer）、店铺公开商品数据（`/products/<handle>.js`）、商品 feed（Google 商品 feed 那种 XML，填了地址才比）、其他平台上架页（填了才比，抓之前先看那个站的 robots）。
- 对的项：价格、币种、库存（有货 / 缺货）、规格数、退货天数（从退货政策页读）；另数每一处带没带日期，价格有效期过了的标「价格过期」。
- 对不上的（中 / 高）给担「店铺管理」的人开一件事，清单原文写在事项里；网站运营照旧用运营工具出改动卡、你点头才改。同一份清单 7 天内不重派。没人担网站运营就不派，清单留在报表里。
- 「能否进 ChatGPT 购物」：照 OpenAI 公开的商品 feed 规范（我 10-17 读的）逐字段看：9 个必填（id、标题、描述、链接、品牌、店铺名、图片、库存、价格）、开结账要的隐私政策 / 服务条款、多规格要的规格名、几个常用选填（GTIN 校验位、退货政策、退货天数、品类）。结论三档：能进 / 差一点 / 还不行。**只评估，不对接、不生成 feed**。

**② 网站技术体检**（建站、网站运营都看）
- robots.txt 挡没挡 AI 爬虫：19 个，分三类——AI 搜索（OAI-SearchBot、Claude-SearchBot、PerplexityBot、Googlebot、bingbot…）、替用户打开（ChatGPT-User、Claude-User、Perplexity-User、MistralAI-User）、训练（GPTBot、ClaudeBot、Google-Extended、Applebot-Extended、CCBot、Bytespider、meta-externalagent）。抽查首页、两件商品页、合集、退货政策页；整站挡 / 挡一部分 / 放行分开，写出是 robots.txt 第几行挡的。**训练类被挡不算问题**，只列出来。清单是数据（带版本日期），品牌只存加减。
- 关键事实在不在原始 HTML：同一页抓两次，一次不跑脚本、一次用这台电脑上的 Chrome / Edge 跑完脚本；拿后台的价格、库存、卖点（描述第一句）、退货天数去找（看页面文字 + 结构化数据 + meta，这三处不跑脚本的爬虫都读得到）。只有跑完脚本才出现的标「只靠 JS」，两边都没有的标「没写」。找不到浏览器就只比不跑脚本的那份，报表页脚说一句。

**③ AI 来源流量**（内容与搜索看，GEO 周报读）
- 用 Shopify 订单自己记的进店来源（最后一次进店 / 首次进店的来源网址、落地页上的 `utm_source`、Shopify 归的来源名）认 ChatGPT、Perplexity、Gemini、Copilot、Claude、DeepSeek、Meta AI、Grok、Mistral、Kimi、豆包。一单只算一次（最后一次进店优先）。来源清单也是数据、可加减。
- 近 7 天：每个 AI 几单、多少钱、占全部成交几成，和前 7 天比；标「实测」。
- 访问数：店铺授权里有「店铺报表」（`read_reports`）才读（ShopifyQL 按来源域名的真人会话）；现在授权里没有这一项，所以只算成交、不出访问那一列（见 1074）。没有店铺授权时退一步用面板那份订单（连接器拉的，补读了 `referring_site`）。
- GEO 周报（`weekly_geo` 卡）多一格 `ai_traffic`，卡上多一行「AI 带来 3 单 / USD 99.70（实测）· ChatGPT 2 单」；这周没问 AI 也照写；读不到就不写、周报照出。WP380 那边周报模板读这一格。

**④ 界面、文案、帮助**
- 报表（岗位层）多四块：「商品信息对不对得上」「能否进 ChatGPT 购物」「AI 爬虫进不进得来」「不开 JS 看得到吗」（网站运营全有；建站只有后两块）。只列有问题的行，全好一行「都没问题」，没体检过一行「还没体检」，不出空表。块头一个刷新小钮（只有图标，字进 tooltip）= 现在体检。
- 内容与搜索：一个数字块「AI 带来的成交（实测）」（带周变化和逐天小折线）+ 一张表「AI 带来的访问与成交」。
- 新教程「网站体检：AI 读不读得到你的店」（中英），岗位 / 职责上下文里排前面。
- 截图：`docs/assets/wp381/`（浅 / 深各两张）。

## 2. 我自己定的（白话）

1. **先找现成的**：查了 dsh 官方包与社区插件（`npm search dsh-seo / dsh-robots / dsh-geo / dsh-shopify`，dsh-plugin 目录）——只有一个占名字、还没发的 `dsh-seo-agent`，没有能用的。开源库：robots 规则解析用 **robots-parser 3.0.1（MIT，零依赖，按 RFC 分组 + 最长匹配）**，薄包一层（锁文件只加这一个包，手工去掉了 pnpm 顺手改的无关几行）；AI 爬虫清单参考 **ai.robots.txt（MIT）** 的 `robots.json` 挑了 19 个、按我们三类重新分；JSON-LD 抽取、页面文字、抓取口复用我们自己 `brand-intake` 那一套（不新开出网路径）。结构化数据校验没找到合适的轻量 MIT 库（`schema-dts` 只有类型），自己按 schema.org Product / Offer 读几个要用的格子。ChatGPT 购物照 OpenAI 官方规范页逐条写规则，没用第三方。
2. **体检不直接出改动卡，而是给网站运营开一件事**：结构化数据 / feed 多是主题或应用生成的，「改哪里」要人或 AI 判断，体检只负责列清楚；改动照旧走运营工具 → 审批卡。（见 1072）
3. **渲染对比用这台电脑上已有的 Chrome / Edge**，和 Reddit 那个只读浏览器分开：这里必须开脚本，所以单独一套闸——一次性临时目录、只发 GET、主页面跳出自己域名就掐、不收下载、挡 Service Worker、每页最多 20 秒，读完关浏览器删临时目录。托管实例不做。找不到浏览器不报错，照实写。（见 1073）
4. **店铺政策从公开的政策页读**（`/policies/refund-policy` 等），不用 Admin 的政策接口——那个要另一项权限，现在的授权没有。
5. **页面上的金额去掉「满 $50 包邮」这类门槛**再比，不然每家都会误报价格不一致。
6. **周一跑**：挂在内容与搜索每周那一轮前面（体检失败不拦周报），没新开定时任务。
7. **AI 来源流量拉 14 天订单**算本周和上周，单数 / 金额 / 逐天都由规则算、不经模型。
8. **报表减字**：爬虫表只列被挡的，放行的并成一行「其余 17 个放行（ChatGPT、Claude、Perplexity 等）」；商品表三列（商品 / 哪里不对 / 写的 → 后台）；访问数没授权就不出那一列。
9. **网站地址读公司档案里那一格**（向导 / 设置页填的），老数据退到工作区上记的那份。
