# WP118 报告：付费三块 + 红人营销增值服务 + 充值四档

## 1. 实现清单

1. **付费三块分组**：`pricing.json` 每条能力加 `block: 'data' | 'ai' | 'kol_service'`（只加字段）；工作台「账号与积分」按三块出三张小卡（本月各花多少积分 + 次数 / token），运营后台总览 / 用量页同口径。
2. **充值四档**：`packages/metering/src/topup-tiers.json` 数据化（US$20→140、US$50→350、US$100→700、US$200→1400 积分，1 美元 = 7 积分）；`cloud-entry` 的 Stripe Checkout 按档创建，没配 Stripe 仍回 501 人话；工作台充值界面四张档位卡；旧的任意金额充值入口收掉，运营后台手动发积分不受档位限制。
3. **红人营销增值服务（订阅）**：
   - 订阅引擎**通用化**（`metering`）：一份引擎两个服务——红人营销按月扣 30 积分（能力 `kol.service.monthly`，幂等键 = org + cycleStart），客服增值服务只登记不扣费。
   - **云端红人库（租户私有）**：新包 `packages/kol-cloud`；云端两个形态——`KolTenantDO`（每 org 一个 Durable Object）与 Compose 按库文件，同一口子落 sqlite；模型与 `packages/kol-core` 本地同构（红人、观测快照、候选池、活动、合作线程摘要、交付物、追踪链接、备注、往来）。
   - **双向同步**：本地一侧 `apps/server/src/kol-cloud-sync.ts`（变更账本 + 离线队列 + 每对象版本号 + 最后写入者胜；冲突**保留双方版本**并可在界面标掉，不静默丢）；首次开通全量上行；接口 `/v1/cloud/kol/*` 七条（status / sync / subscription POST+DELETE / conflicts/resolve / export / DELETE）。
   - **余额不足**：不删数据、云端同步暂停、进 30 天宽限，宽限过了是 suspended、数据仍不删；可随时取消（当期用完为止）；运营后台可赠送 N 个月。
   - **用户数据权利**：一键导出云端这份（带输掉的那些冲突版本）、一键删除云端这份（本地不动），都写审计。
4. **工作台「增值服务」卡**（`kol-cloud-card.tsx`）：订阅 / 取消 / 立即同步 / 冲突列表与标记已处理 / 导出 / 删除（带确认），未绑定云账号、未订阅、宽限中、不可达各有各的人话。
5. **运营后台**：组织抽屉加「红人营销增值服务」区（订阅状态、到期、云端对象数、冲突数、赠送）；「积分与会员」页订阅列表。
6. **文档**：`docs/67-付费三块与红人营销增值服务-v1.md` 新建（含为云端运行留口的下一步清单）；`docs/21` §4.1 数据边界改为「默认本地优先；开通云端服务后相关数据与上下文上云，按最小必要、传输与静态加密、可导出可删除来管」（**不做端到端加密 / 恢复口令**——云端要能读数据才能替用户跑任务）；`docs/49`（三块 + 四档）、`docs/65`（后台「不做模拟登录」的理由改为「暂不做」）。
