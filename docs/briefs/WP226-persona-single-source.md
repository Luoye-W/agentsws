# WP226 persona 只写一份中文 + 回复语言规则，英文自动生成

worktree `../agentsws-wt/wp226-persona` · 分支 `wp/226-persona`（从 main 新起）。先读 `_common.md`、`docs/69-岗位与职责的角色定位-v1.md`（尤其 §1 为什么中英两份、回落规则、上限 `MAX_PERSONA_CHARS`、公司覆盖那几节）、`packages/roles/src/persona.ts`（`checkPersona`、装配、`applyPersonaOverride`）、persona 进系统提示的各条路（stub / direct / dsh，69 那张表）、`docs/91` §三（14 条英文 persona 混中文的清单）。

## 背景（Luoye 10-05 定）
Luoye 问「persona 为什么要中英两份，这不是多此一举吗」。Fable 建议、Luoye 同意：**只写一份中文**，另加一条「用来信 / 界面的语言回复」的规则；英文用翻译**自动生成**，不再手工维护。两份手工维护已经出了问题：14 条英文 persona 混着中文（docs/91）。

## 要做
1. **真源只有中文**：岗位 / 职责 yml 里 persona 以 `zh` 为准；老的 `{ zh, en }` 写法照样读得进（契约只加不删），但 `en` 不再是手写真源。
2. **回复语言规则**：装配系统提示时，在 persona 后加一条固定规则（中英各一句，按界面语言选那一句）：对外回复用对方来信的语言；对内（给用户的卡片、摘要）用界面语言。三条运行时路（stub / direct / dsh）都要进；dsh 那条照 69 写进唯一的 `complete` 段。
3. **系统提示里送哪一份**：一律送中文 persona + 上面那条规则（Fable 的判断：模型读中文说明、按规则用英文回，比送一份机翻英文更稳）。如果你实测（direct 模拟或评测集）发现英文界面 / 英文客户下串成中文回复，照实写进报告，并给出替代方案（例如英文界面送生成的英文版），先别自己改口径。
4. **英文版自动生成**：给英文界面里要**看**或**改** persona 的地方用（公司页 persona 覆盖、职责详情）。做法：一个生成脚本（调模型翻译，开发者本机跑，key 只从环境变量来，脚本不读 .env*），产物带「来源中文的哈希」提交进仓；`--check` 模式只比哈希、不调模型，中文改了英文没重新生成就报「过期」（门禁里给警告，不卡合并）。这一单把所有现有职责的英文跑一遍生成（含那 14 条混中文的），并保证生成结果里没有汉字。
5. **公司覆盖**：公司改 persona 只改中文；英文显示用生成的（覆盖后的中文没对应英文时，英文界面显示中文原文 + 一个「未翻译」图标，或在保存时调一次翻译——二选一，你判断，写进报告）。
6. **checkPersona**：中文上限 260 不变；英文不再检查字数上限，只检查「没有汉字」「不为空」。
7. docs/69 相应节改写（为什么改、新规则），docs/35 记一行。

## 纪律
不读 .env*；不跑批量清理命令；本机 4317 服务别碰。并行中：WP222 在给投放四条 persona 补一句（中英都补）、WP223 新增 `design.video`、WP224 改 `ads/*.yml` 与 `common.owner`、WP220 改 `pr/*` `social/*` 与技能——你对 persona 的英文字段做的是「整体改由生成」，合并时以你的机制为准、他们新加的中文句子要被生成脚本覆盖到；冲突留给 Fable。
