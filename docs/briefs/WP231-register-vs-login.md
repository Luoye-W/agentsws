# WP231 「用 Agents 工坊的接口」分清「注册」与「登录」（开源 + 私有两仓）

开源 worktree `../agentsws-wt/wp231-signup` · 分支 `wp/231-signup`；私有 worktree `../agentsws-cloud-wt/wp231-signup` · 分支 `wp/231-signup`（都从 main 新起；私有仓 vendor 子模块指开源 main，只从本地开源仓 fetch）。先读 `_common.md`、`apps/workstation/src/components/onboarding/ai-step.tsx`、`apps/server/src/cloud-account.ts`、`packages/contracts/src/cloud-api.ts`、私有仓账号 / 登录信那几条路由与邮件模板、网页版账号页 `/account` 登录页（WP198）、`apps/site/src/content/legal/*`（条款与隐私，WP227 新口径）、docs/70 §2、docs/36 §7（少字）。

## 背景（Luoye 10-05，在 Windows 真机模拟新用户）
「用 Agents 工坊账号这里直接让填邮箱、发登录链接，明显不对：大部分用户都没注册过。应该有两个选项：注册、登录。」
现状：免密码的邮件链接，新邮箱点了链接就自动建号——技术上能用，但界面没说，新用户不知道这就是注册；也**没有注册时同意条款 / 隐私的那一步**（合规上要有）。

## 要做
1. **工作台向导 + 设置页那张卡**：「用 Agents 工坊的接口」展开后是两个页签 / 按钮：**注册新账号**（默认，大多数人）与**已有账号，登录**。
   - 注册：邮箱 + 「我已阅读并同意《用户条款》《隐私政策》」勾选（链接到官网对应页，新窗口；不勾不能发）+ 可选「公司名」。按钮「发注册邮件」。
   - 登录：只填邮箱，按钮「发登录邮件」。
   - 两边都还是**免密码邮件链接**（不加密码），发出后同一个「去邮箱点链接」等待态，文案分别写注册 / 登录。
2. **云端分清两条**（私有仓）：
   - 注册：邮箱已存在 → 不发注册信，回「这个邮箱注册过了，直接登录」（界面给一键切到登录）；新邮箱 → 发**注册确认信**（标题与正文是「欢迎注册」），点链接才真正建号并送 10 积分；**留证**：同意时间、条款版本（取官网条款生效日期）、语言、来源（工作台 / 网页）。
   - 登录：邮箱不存在 → 不偷偷建号，回「这个邮箱还没注册」（给一键切到注册）；存在 → 发登录信。
   - 防探测：注册 / 登录两条都限速；回「已注册 / 未注册」本身会泄露邮箱是否存在——接受（主流产品都这样，便于新用户），但限速要有，写进报告。
3. **网页版账号页 `/account`** 的登录页同样分「注册 / 登录」（同一套后端），不要两处口径不同。
4. 邮件模板中英两套（注册确认 / 登录），发件人与现有一致。
5. 老接口兼容：老客户端调旧的「发链接」接口时行为不变（自动建号），只是新客户端走新的两条；契约只加不删。
6. 少字：卡里每块一行说明，状态用图标（docs/36 §7）。

## 纪律
不读 .env* / .dev.vars；不碰 secret；不部署（Fable 部署）；不推远端；本机 4317 别碰；不跑批量清理命令；私有仓内容不进开源仓。
