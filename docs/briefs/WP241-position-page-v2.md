## Luoye 定的口径（10-06）
- **卡片流管决定，工作管进度**：「要你处理」= 现有卡片流原样（一次一张、翻页、快捷键），不为任何职责另画卡；「工作」只看进度，不放决定动作；分组「进行中 / 排着的（排期、定时）/ 等别人 / 已完成（折叠）」；有卡等你的行尾挂「N 张卡等你」→ 点了滚到卡片流并翻到那张；人手动加的待办是工作里的一类事项（图标区分）。
- 「数字」→ **「数据看板」**。
- #71 职责 `social.reddit` 显示名改「**自家版运营**」（管自己的 subreddit）；`pr.reddit` 保留「Reddit 营销」（外部版口碑）。中文 persona / 描述里对应称呼同步，英文由 `gen-persona-en` 重生成（无 key 照 WP226 的 export → 翻译 → import）。
- #72 设置 · 连接里「可选」收成一行「还有 N 个可选」，点开才展开。
- #73 职责移走 / 拆出时没做完的事**跟着职责走**（核对 WP234 现状，不一致就改）。
- #74 一律默认**列表**视图；社媒类岗位视图栏里把「发帖排期」快捷视图排在最前。视图记在本岗位（本机偏好）。

## 要做
1. **页头**：图标 + 名字 + 一行可点状态（N 张等你定 → 卡片流；N 件在办 → 工作；今天 N 个待办 → 工作筛好）；右侧「⋯ 岗位设置」；真缺必需连接时一行细横幅（复用 WP238 `missing_required`）。
2. **交给它**：一行输入 + 建议芯片，聚焦展开；沿用现有提交 / 路由（WP237）。
3. **要你处理**：嵌入现有 `DeckSection`（本岗位所有分配的卡），外观行为不变。
4. **工作**（新）：服务端出一个本岗位的「工作项」视图（事项 + 待办 + 排期 / 定时任务，统一字段：标题、类型、所属职责、状态分组、截止 / 下次时间、最近一句进展、等你的卡数与卡 id、来源），四种视图：列表（默认，分组）/ 看板（可拖改状态——只对人能改状态的类型生效，AI 事项拖动只改人看的分组标记或不允许，按现有状态机来，写清）/ 日历（月 / 周，只本岗位）/ 表格（列可选）；筛选（职责 / 状态 / 截止 / 来源）、分组、排序；视图与筛选记在本岗位（localStorage，try/catch）。职责专属快捷视图（如自家版待处理、发帖排期、红人工作台、B2B 面板）放视图栏后面，里面要拍板的出卡走卡片流。
5. **数据看板**：每条职责一行 3–4 个关键数 + 涨跌（复用现有 view blocks / stat_tile 数据；接口中台满足的照 WP238 口径），「看图表」展开原图表块。
6. **页签三个**：工作（默认）/ 记录 / 设置。设置：职责（加减、合并 / 拆出 / 移动入口）、连接（必需 / 可选分开，可选收起）、记忆（岗位层 + 职责层）、定时任务、高级（WP238 的人话权限，默认折叠）。原「卡片 / 面板 / 记忆」页签与「在日历里看」链接、CLI 卡挪进相应位置；职责页保留但入口降级。
7. **空岗位**：照 `position-v2-empty.html`。
8. 窄屏 1024 布局、明暗两套照设计稿；docs/54 / docs/36 相应节更新。
