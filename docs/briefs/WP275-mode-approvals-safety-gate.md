# WP275 三种模式 B：审批与安全闸按模式（docs/95 §5 / §7 B 单，决策 222 / 236–243 / 256 / 259）

worktree `../agentsws-wt/wp275-modeB` · 分支 `wp/275-modeB`（从 main 新起，main 已含 WP271 的 `Organization.mode` / `organizationModeOf()` / `useMode()`）。**先完整读 `docs/95-三种使用模式-v1.md`**（尤其 §5 安全闸 vs 审批流那张表、§6 差距清单、§7 A 单「实现口径差别」三条），再读 `docs/briefs/reports/WP271.md`、`_common.md`；然后找现有的审批路由（`scope_manager` / `owner` 路由、卡片上「转给了…」那句、职责分离、24 / 48 工作小时超时升级、策略变更卡、记忆 / 技能提层待审卡）。

## 一句话
**安全闸**是「AI 要做对外、动钱、不可逆的事之前，问这件事是谁的那个人」；**审批流**是「这件事是你的，但要另一个人点头」。① 个人、② 同事互联只有安全闸；③ 公司两样都有。

## 要做
1. **路由按模式**（服务端）：模式读一律过 `organizationModeOf()`。非 `company` 时 `scope_manager` / `owner` 路由一律落到「这件事是谁的」那个人（① 就是本人；② 是这个岗位 / 这件事的人），**不写**卡上「转给了主管 / 老板」那句；B2B 报价超限、动钱超上限在 ① ② 是「再确认一次」，不往上转。③ 行为完全不变。
2. **职责分离**（提的人不能自批）、**没人管的卡超时升级**（24 → 主管、48 → 老板）改问模式：① ② 关闭，只提醒本人。
3. **人自己发起的改动不出卡**：在 ① ② 里，人自己改职责规矩、额度、自动化等级（L1 / L2 / L3）、角色定位、工具箱合并、把记忆 / 技能提到岗位层或职责层——二次确认后**当场生效、不出卡**；② 里改的是共用岗位时，同岗位的人收到通知、可一键撤回（决策 12 口径：留名字、可撤回、不设审批）。**AI 提的**改动（学习回路「以后都这样」、查重合并、技能晋升、知识卡生效）照旧出卡，给这件事是谁的那个人。③ 照旧出策略变更卡 / 待审卡。
4. **硬闸不动**：群发、广播、付款指示、改收款账户这类「一律要人点」的，三种模式都关不掉；硬顶（工作区策略也放不宽的上限、受保护字段）三种模式都有。测试钉住。
5. **决策 259**：① 里「待认领」有活时，直接记到本人名下（不出「待认领」区、不需要认领动作）。
6. **决策 256**：B 合后，第二个人进来（自动变 ②）时界面不应变成公司那套——② 里本单涉及到的卡片词、路由都按 ② 走；② 自己的新界面仍是 C 单。
7. **文案**：① ② 卡片统一「要你确认」系（WP271 两套词），不出现「审批 / 批准 / 主管定 / 老板定 / 转给了 / 上级」。
8. **模拟**：加两条场景——「一个人：没有升级、没有转给老板，超限只再确认一次」；「两个平级：谁也不批谁，各自确认自己的」。放进现有 sims 包（stub / direct / dsh 三种都要过）。
9. 急停与装插件等其余 §5 行，① ② 只要现状不违背表格即可，不新做界面。

## 不做
公司模式本身的开启界面与降级（D 单）；② 的「和同事一起用」入口、交给对方流程、团队页（C 单）。
