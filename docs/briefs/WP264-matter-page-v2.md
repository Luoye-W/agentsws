# WP264 事项页 v2 实现：AI 短标题、一行页头、对话式时间线、Claude 式输入卡 + Tab 建议

worktree `../agentsws-wt/wp264-matter` · 分支 `wp/264-matter`（从 main 新起，含 WP262 设计稿）。先读 `_common.md`、**`docs/design/matter/`（视觉真源：`matter-v2-chat.html`、`matter-v2-states.html`、README、shots）**、WP262 报告、DECISIONS 177–184、现有事项页（`pages/matter*.tsx`、时间线组件、「问 AI」块）、WP259（`task-text.ts`、`run: true`）、WP253 / WP260（`site_theme.preview_ready`、主题审批卡）、卡片流审批 / 选择卡组件、`docs/36`（少字、状态图标）。

## 要做（Luoye 10-08 定 177–184，全照设计稿）
1. **AI 短标题（177 / 184）**：事项首轮开跑时用便宜模型单独起一个中文 ≤16 字左右的总结标题（失败或没模型时先显示原话前 20 字），存为事项标题；用户可点标题就地改，改过的不再被自动覆盖。原话全文作为对话第一条（右侧气泡）。左栏事项名用短标题。WP259 的「首句 ≤40 字」退为起标题前的临时显示。老事项不迁移（可选：打开时若标题 = 原话前缀且较长，后台补起一次）。
2. **一行页头**：短标题 + 灰字行（职责标签可点换 · 状态 · 参与者头像 · 最近活动）；「⋯」收 换职责 / 复制链接 / 归档 / 关闭事项（在跑或有卡等批时归档置灰并说原因）；待办有才出（灰字行尾「N 个待办」点开就地展开）；页头吸顶。
3. **对话式时间线**：用户右气泡（>6 行折叠）；AI 左侧（职责头像 + 名字 + Markdown 渲染：标题、列表、行内代码、链接、颜色块；长回答「展开全文」）；**结果卡**「预览好了」（缩略图可先用占位、主题名、改了几个文件、检查结果、「打开预览」主按钮、「发布上线」次按钮→走现有发布出卡、「看改动」）；**审批卡 / 选择卡 / 卡住卡**内嵌可操作，处理完缩成一行；**过程与系统事件**（跑了一次 / 路由 / 缺连接已解决 / 换职责）缩成居中一行灰字，点开看步骤摘要（读了哪些文件、改了哪些、检查、推送）——默认全收起（182）；**运行中**左侧「正在做…」+ 当前一步，可展开实时步骤；同日只出一次日期分隔。
4. **输入卡（180 / 181 / 183）**：底部固定的圆角输入卡（边框 + 阴影、自动增高到约 10 行）；发送为卡内右下圆形箭头图标（空灰 / 有字主色 / 运行中变「停」），悬停「发送（Enter）」；Enter 发送、Shift+Enter 换行，提示只在聚焦或有字时出；左下「私聊 AI」开关（替代原「问 AI」块，打开后整卡变蓝 + 一行「只你看得见」），私聊问答关掉即不留（178，可「转给 Agent」）；左下预留「+」「@」位（先不接功能，或置灰 tooltip「即将推出」）；已完成事项输入框保留、占位「说一句就重新打开」。
5. **Tab 建议输入（179）**：只认三个来源——AI 回复里**结构化的下一步**（运行输出加一个可选字段 `next_suggestion`，由运行时 / 提示要求模型在交代末尾给一个短句，契约只加）、有卡等你批时卡上主按钮动作的文字、固定规则（如缺连接解决后「连好了，接着做」）；运行中、刚发完、没明确下一步时不给。浅灰 ghost 文字 + 小 Tab 键帽，按 Tab 填入（变正文），打别的字即消失；涉及花钱 / 对外的也只是填入，仍要人按发送。
6. 明暗两套、1440 / 1024 都对；无障碍（键盘可达、aria）。
7. 测试：组件测试覆盖页头、各类时间线条目、结果卡、内嵌卡操作、输入卡（发送 / 停 / 私聊切换 / Tab 建议有无与收下）；服务端短标题生成（成功 / 失败回退 / 用户改过不覆盖）与 `next_suggestion` 契约。拍与设计稿对应的真界面截图（demo 别碰 4317）。
