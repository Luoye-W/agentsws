# WP337 有任务在跑时点「重启并更新」：弹窗三选一，暂停的任务重启后自动接着跑（Luoye 10-15）

worktree `../agentsws-wt/wp337-updatewait` · 分支 `wp/337-updatewait`。先读 `_common.md`、`docs/briefs/reports/WP327.md`（版本目录 + 联接切换、重启流程）、`docs/briefs/reports/WP325.md`（更新小窗）、`apps/desktop`（自动更新、重启按钮）、服务端运行与调度（`apps/server/src/runtime.ts`、`schedule.ts`、`automation.ts`、dsh 官方自动化任务、后台任务 / jobs）、`docs/96`（弹窗也要少字）。

## Luoye 的要求
点「重启并更新」时，如果有任务在执行，要弹窗。任务分三类：
1. 正在对话、AI 还在输出的任务；
2. 后台在跑 / 待触发的任务（后台作业）；
3. 定时任务（自动化任务）。

弹窗选项：
- **现在重启**：自动暂停所有任务 → 重启更新 → 新版起来后**自动恢复所有之前暂停的任务**。
- **空闲时重启**：等到没有正在输出的任务时自动重启（重启前后同样暂停 / 恢复后台与定时任务）。
- **稍后**：这次不重启（Luoye 原话说三个选项、列了两个，第三个按「稍后 / 取消」做，报告里写明，等他确认）。

## 要做
1. 服务端：一个「正在忙什么」的查询（三类各几件、每件一句话）；一个「暂停全部 / 恢复全部」接口——正在输出的运行在安全点停下（不丢已输出的内容，时间线记「因更新暂停」），后台作业与定时任务挂起；状态落盘，重启后读回并恢复（被打断的运行按原话接着做或从断点续，做不到就重跑并照实说；重启期间错过的定时任务恢复后补跑一次）。
2. 桌面壳：点「重启并更新」先问服务端；没任务直接重启；有任务弹三选一（少字：一句「还有 N 件在做」+ 三个按钮，展开可看清单）。「空闲时重启」期间按钮显示「等空闲后重启」并可取消；空闲判定 = 没有正在输出的运行（后台 / 定时的暂停后再重启）。
3. Windows（WP327 切换流程）与 Mac（只提示 → 用户退出安装）两条路都要接上；更新小窗照旧。
4. 测试：三类任务各自暂停 / 恢复；「空闲时重启」等到输出结束才走；重启后恢复且只恢复一次；补跑错过的定时任务；Windows CI 更新端到端加一段「有任务时现在重启 → 新版恢复」。
