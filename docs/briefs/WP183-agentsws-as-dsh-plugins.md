# WP183 调研与设计：把 agentsws 做成一个或多个 DeepSeek harness 插件，官方 DSH 桌面端装上就能用

**只读调研 + 设计稿，不改代码。** 产出一份讨论稿 `docs/85-agentsws作为DSH插件-v1.md`（写在 worktree `../agentsws-wt/wp183-dsh-plugin` · 分支 `wp/183-dsh-plugin`，只提交这一份文档与报告）。

## Luoye 09-29 问
「如果我想把整个 agentsws 做成一个或者多个 deepseek harness 插件，下载了官方 DSH 桌面端也可以很容易集成进去，这个可以做到吗？」

## 要查清
1. **官方插件体系到底支持什么**（以 dsh `0.2.0-rc.1` 为准，读源码与文档：`node_modules/.pnpm/@deepseek-ai+*@0.2.0-rc.1*`，重点 `dsh-plugin-manager`、`dsh-skill`、`dsh-persona`、`dsh-app-boot` / profile、插件开发指引与「创造模式」的 `agent-experience` 技能、0.2.0 的可选插件包是怎么打包分发的）：插件能注册什么（工具、技能、persona、设置页 / 界面、定时任务、后台服务、MCP、上下文注入）；怎么安装（npm？本地目录？官方市场？）；桌面端用户装插件的真实步骤；权限与审阅模型（插件工具的「要人批」怎么做）；插件能不能起常驻后台进程、能不能带原生模块；许可证与分发要求。
2. **agentsws 拆成插件的映射**：我们的每一块（岗位 / 职责 → persona？技能 → dsh-skill；工具（读写店铺、发信、出卡）→ 插件工具；审批卡 / 事项 / txn / 账本 / 学习回路 / 工作台界面 → ？；连接器（OpenConnector）→ ？；官方积分与数据接口 → ？）逐块写「官方插件里有对应物 / 要包一层 / 装不进去」。
3. **推荐方案**：给出一到三个方案（例如 A「技能 + persona 包」轻量版：只带做事方法，官方桌面端开箱即用；B「agentsws 伴生服务 + 插件」：插件是薄客户端，重活（出卡、账本、连接、界面）由本机 agentsws 服务承担，经 MCP 或本机接口对接；C 全部塞进插件），每个写能做到什么、做不到什么、工作量 S / M / L、风险（官方插件 API 还在 rc、升级跟随成本）。
4. **和「官方功能优先」规矩的关系**：反过来想——我们现在自己做了、官方插件体系里已有的，能不能改用官方的。
5. 要 Luoye 定的事（白话，每条给推荐）。

## 纪律
只读；不装真插件、不跑官方桌面端、不联网装包（源码看 `node_modules` 与 `gh api` 读 deepseek-harness 仓库）；不读 .env*；**Luoye 的本机服务在 4317 别碰**。
