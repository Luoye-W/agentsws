## Luoye 10-09 在 Windows 真机（Rollout，个人模式，岗位「独立站搭建与运营」：订单履约 / 店铺管理 / Shopify 整站搭建 / Shopify 网页模板四条职责）遇到的
1. 在岗位输入框问「现在店铺里有哪些产品」——**没有回答**，变成了一件「进行中」的事项，点进去还要他从四条职责里选一条（「这件事像订单履约也像店铺管理，你定」）。四条打分都是 0.25。
2. 选了「店铺管理」后显示「跑完了 · 1 秒」，**还是没有回答**。真实原因是运行一启动就失败（工具参数表 dsh 不认，已由 Fable 热修 `fix(dsh-adapter)`），但界面上看不出失败。
3. 「要你处理」里一堆「今天的复盘：你处理 0 张，AI 0 张；待办完成 0/0，会议 0 个」——**全是 0 也出卡**，而且每条职责每天一张（Windows 上积了 39 张待处理 review 卡），点完一张下一张一模一样。
4. 这张复盘卡下面的键盘提示写「→ 就这条 · ← 都不是 · ↑ 稍后」，和卡上的按钮对不上。
5. 点到最后两张报错「无权限：approval.approve（range=own）」——他是个人模式下唯一的人。
Luoye 原话：「现在整个流程显的很奇怪很乱」。

## 要做（Fable 定的第一版口径，报告里汇总你的自主决定）
1. **问一句答一句**：岗位输入框里的话，AI 先判断是「问」还是「交办」。
   - 问（查店里商品、订单状态、数据、怎么做…只读就能答的）：**当场在岗位页输入框下方回答**（像聊天的一段回复，带「来源」），不建事项、不进「进行中」；回复下方一个小按钮「转成一件事」（需要接着做时再转）。
   - 交办（要动手、要出卡、要多步的）：照旧建事项。
   - 判不准时按「问」处理先答；AI 答的过程中发现要动手，再自动转成事项并告诉人一句。
   - 同一套逻辑接到首页 ⌘K「交给某个岗位一件事」与随便聊里点名岗位的入口（如有）。
2. **不卡在选职责**：岗位入口**永远不出「这件事该走哪条职责」的选择卡**。拿不准时（含四条都 0.25、一个词都没命中）：按分高的取；打平按岗位模板职责顺序；一个都不像就取岗位的第一条职责（或该岗位的通用 / 主职责）。时间线上一行小字「按『店铺管理』做的 · 换一条」（WP237 的 settled 样式）。只读的「问」甚至不用显示这一行。
3. **失败要看得见**：运行 `run.failed`（任何原因）时，事项时间线 / 当场回答处显示「没跑成：<人话原因>」+「重试」，不能显示「跑完了」。内部错误（如 schema、internal）给一句通用人话（「工坊这边出错了，已记下，点重试或稍后再试」），并在本机日志 / 事件里留原始错误。查一遍还有哪些失败会被显示成「跑完了」的路径。
4. **复盘别刷屏**：
   - 当天这条职责**没有任何动静**（处理 0、AI 0、待办 0、会议 0）**不出复盘**。
   - 有动静也**一个岗位一天最多一份**，不是每条职责一份；① 个人模式下默认不出卡，改成岗位页「记录」里一条（或首页一行），需要人确认明天安排时才出卡。
   - 已经积压的老复盘卡（全 0 的、过了当天的）启动时自动过期掉（状态 expired，不删记录），不再占「要你处理」和「N 张等你定」。
5. **键盘提示跟着按钮走**：复盘卡（以及其他非选择题卡）不能用选择题那套「就这条 / 都不是」。把 WP277 的修法推广成通用规则：键盘提示由卡上实际按钮生成，没有对应按钮的方向键不出提示也不做事；加测试遍历所有卡型。
6. **个人模式的权限**：① 里唯一的人对自己工作区的所有卡都能点；查清「approval.approve（range=own）」为什么在 ① 里对 owner 报出来（大概率是复盘卡收件人 / 职责持有人与本人对不上，或 common.owner 范围判定），修掉；通用规则：**发给某人的卡，他必须点得动；点不动的就不该出现在他的「要你处理」里**。加测试。
7. **「N 张等你定」**只数真正要人定的卡（过期 / 已处理 / 通知类不算）。

## 测试
服务端真进程：问一句在岗位入口当场回答且不建事项；交办照旧建事项；四条打平不出选择卡、按顺序取并记 settled；run.failed 时事项 / 回答显示失败与重试；全 0 不出复盘、一天一岗一份、老复盘卡启动过期；① owner 能点所有卡。工作台：岗位页当场回答区、「转成一件事」、失败态、键盘提示遍历卡型。模拟：按需加场景「岗位里问一句当场答」，说明基线变化。
