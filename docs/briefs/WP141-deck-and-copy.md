# WP141 牌堆能直接找到后面的卡 + 屏幕上的裸值与对不上的数字

worktree `../agentsws-wt/wp141-deck` · 分支 `wp/141-deck`（从 main 新起）。先读 `_common.md`、`_beta-fix-common.md`、`docs/36`、`docs/78` §1 #4 与 §2（首页 / 红人 / 客服各条）。

## 要做
1. **牌堆**（`apps/workstation/src/components/deck/deck-section.tsx`）：
   - 「卡型」下拉的选项从**未筛过的全部牌**算（约 175 行），选了一种之后下拉里其他卡型还在；
   - 提示行按**这张卡真有的动作**生成（没有「稍后」就不写 ↑ 稍后）；
   - **所有卡都有「稍后」**：campaign 名单卡等缺 `snooze` 的，补进 `available_actions`（服务端卡片定义里补，别只在界面上硬塞）；
   - 加「下一张 / 上一张」或一个紧凑列表视图，不决定前一张也能直接去后面的卡。
2. **同一屏的卡数对得上**：首页页头「N 张卡等你决定」、筛选「全部 N」、翻页「第 x / N 张」、今天栏「还有 N 张卡」用同一个口径（docs/78 §2 首页）；客服「队列清空了」与页头「3 张待审」不打架。
3. **裸值清掉**（docs/78 §2 列的每一条都过一遍）：`late_return_grace_days: 0 → 7` 这类改动卡用人话字段名 + 单位；日报列头 `date / sales / orders / low_stock`；`kol.contact.source.sandbox` i18n 键；`kol_campaign`；交付期限 ISO 时间；渠道 / 形态原始值 `youtube` / `video`；Meta 权限名（放进「详细」折叠里可以，默认不露）；卡顶「属于：事项 wi_run_demo_42」；「没 · 没写名字」；「导入与 campaign」中英夹杂。
   找一个统一的地方做「字段名 → 人话」「渠道 / 形态 → 中文」，不要每处各写一套。
4. **回执与说法**：开发信 / 验收回执说「在**卡片**里等你批」（不是「待办」）；合作阶段标签「交付中 / 已交付」对齐；「改一下」抽屉提交后给一句「记下了」；点「示例任务」不覆盖已写好的指导（先问或追加）；每个岗位的输入框示例按岗位给（红人、客服不再是「把 A 商品降价 10%」）。
5. 「一比前一天」小徽标窄格里不竖着折行。
6. **守卫测试**：写一个工作台级测试，渲染主要页面的 demo 数据，扫文本里的 snake_case（白名单少量合法的）、ISO 时间戳、`xxx.yyy.zzz` 形态的 i18n 键，出现即失败。
