# WP350 助理一次派给多个岗位、多个岗位一起更新知识库（Luoye 10-16，决策 900）

worktree `../agentsws-wt/wp350-fanout` · 分支 `wp/350-fanout`（从 main 拉；收尾前合一次最新 main）。先读 `_common.md`、`docs/briefs/reports/WP343.md`（我的助理、派活工具、`pickDispatchTarget`、回报）、`WP348.md`（方案卡：AI 先定方案、人确认）、`WP341.md`（genui 按钮 / 表单）、`apps/server/src/brand-knowledge.ts` 与知识库 `propose`（一律 proposed、必带出处）、`apps/workstation/src/components/free-chat/composer.tsx`（附件）。

## Luoye 原话
有时我们和助理沟通一些东西，包括给到助理资料（比如一些会议记录）时，可能需要往多个岗位去派任务，以及让多个岗位去更新他们的知识库。并不是说我派出一个任务，就只有一个岗位去工作。

## 要做
1. **一次拆成多份**：助理读一段话或一份资料（会议记录、文档、聊天记录），按岗位 / 职责拆出两类东西：
   - **要做的事**：每件归到一个岗位 / 职责，带一句为什么、截止（有的话）、原文出处；
   - **要记住的事**：每条归到一个岗位（或品牌公共知识），带出处原文一段。
2. **方案卡确认**（沿用 WP348 方案卡 + WP341 genui）：助理出一张「我打算这样分」：按岗位分组，每组列要做的事和要记的事，逐条可勾掉 / 改归属 / 改文字；底部「就这样」「改一下」。不让人逐个岗位去点。
3. **确认后扇出**：要做的事按岗位各开一件事（走现有交办入口，同一批带同一个「来源批次」，事项里能看到来源原文）；要记的事以 `proposed` 写进对应岗位 / 品牌知识库（必带出处 = 这份资料），各岗位知识库里能看到「待你确认」。
4. **汇总回报**：助理对话里出一张汇总：派了哪几个岗位几件事、各进了几条知识；之后各件事的回报（WP343 三种）照旧回到这段对话，按批次聚在一起。
5. **派活判据放宽**（改决策 861）：话里明确点了多个岗位、或资料明显跨岗位时，直接出多岗位方案卡，不再一律先问；仍然拿不准的那几条在卡上标「归属待定」让人挑。单岗位的老路径不变。
6. **附件**：助理输入框能附文本类资料（.txt / .md / .docx / .pdf / 粘贴长文本）；读不出文字的照实说。凭据类内容不进知识库（沿用 814 的口令识别）。
7. 记忆与知识的边界：个人偏好进助理记忆（WP343），业务口径进岗位 / 品牌知识库；方案卡上分开列。

## 测试
- 服务端：一段替身会议记录 → 拆出 3 个岗位的事 + 2 个岗位的知识；确认后开出 3 件事（同一批次）、知识以 proposed 带出处写入；勾掉的不发；改归属生效；归属待定的不发。
- 端到端（真服务进程 + stub）：附一份 .md 会议记录 → 方案卡 → 就这样 → 三件事开出、知识待确认 → 各件事回报按批次回到对话。
- 工作台：方案卡按岗位分组、逐条勾 / 改；汇总卡。
