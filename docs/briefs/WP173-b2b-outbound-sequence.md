# WP173 B2B 开发信序列：三封节奏、日配额与预热、发信域名建议与体检、页脚与来源、德奥默认不发、回复停序列转业务

worktree `../agentsws-wt/wp173-b2b-outbound` · 分支 `wp/173-b2b-outbound`（从 main 新起）。先读 `_common.md`、**`docs/84-B2B岗位设计-v1.md`**（§2、§11 覆盖前文：**发信域名不强制**、德奥默认不发并告诉原因、日配额）、`docs/briefs/reports/{WP170,WP171,WP172}.md`、`packages/kol-core/src/{outreach,replies,stages}.ts`、`packages/core/src/{suppression,guardrail}.ts`、`packages/b2b-core`、`apps/server/src/{b2b-store,b2b-service,b2b-mail}.ts`、`packages/skills/bundled/{cold-email,prospecting}`。

## 要做
1. **序列与配额提成共用**：从 `kol-core` 把和渠道无关的序列 / 日配额 / 收尾真停函数提到共用处（`core` 或新的小包），红人与 B2B 都用它；红人行为逐字节不变（红人模拟零漂移）。
2. **B2B 开发序列**：一轮三封（第 0 / 3 / 7 天），任何回信停这个人的序列；**每一轮首封批量一张卡**（一次看完这一批），后两封按自动化级别；草稿由模型按 `cold-email` 技能写（没模型用模板），承诺词照 WP171 的 guardrail 拦；发出后调 WP172 的 `noteOutbound` 记下（分拣「线程对上」才有依据）。
3. **日配额与预热**：按发信邮箱算——新域名前两周 20 封 / 天，之后最多 50 封；超了排到明天，面板写明。
4. **发信域名：建议而不强制**（docs/84 §11.1 第 4 条）：初始化 / 第一次开序列时，一张卡**强烈建议**用单独的发信域名并用一两句说明原因（主域名进垃圾箱会连累客服与订单邮件），**由用户选**：①用单独域名（选一个已接的邮箱，或教程教怎么买 / 配）②就用现在的邮箱（卡上留一句风险提示）。**不问不设**。无论选哪个，发信前都做 SPF / DKIM 体检（查 DNS 记录；DKIM 用给自己发一封测试信看头验证），**没过不发**；DMARC 缺了只提示。
5. **页脚与来源**：每封信系统自动加退订方式与公司实体地址（取公司档案，没有就不能发并提示补）；联系人来源 URL 与日期必须有（WP171 已在 guardrail 拦）。退订链接的落地由本机或云端出一个最小退订页——**先查现有能力**（聊天转发 / 云端公开页），能复用就复用，说清方案；没有安全的公网落地就用「回复 unsubscribe 即退订」并在报告写明。
6. **德奥默认不发**：没有往来的德国 / 奥地利潜在客户默认排除，卡上一句原因（「两国法院常把未经同意的 B2B 冷邮件判为违法」），用户勾选并确认风险后才发；已有往来的照常出卡。
7. **回复处理**：回信分类（有意向 / 要资料 / 不感兴趣 / 退订 / 自动回复）——有意向与要资料的**停序列并交给 `b2b.sales`**（落成询盘），退订进抑制名单（WP172 已有）。
8. 面板：今天待发 · 序列漏斗 · 回复待分 · 名单来源（照 docs/84 §1.2，少字）。
9. 模拟：`b2b-3c-3p` 加场景——批量首封一张卡、超配额排明天、SPF 没过不发、德国潜在客户默认拦、回信有意向转业务、退订停序列；红人与 dtc 两个包零漂移。

## 纪律
契约只加不改；不连真邮箱 / 不真发信（替身 SMTP，DNS 查询用替身）；不跑批量清理命令；不读 .env*；**Luoye 的本机服务在 4317 别碰也别重启**。WP174 并行（组织「上级」设置），改共享文件只动你那几处。
