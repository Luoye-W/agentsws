# WP323 发出记录 + 可配置的「记录去处」（docs/102 §5 与附；决策 665 / 666 / 667）

worktree `../agentsws-wt/wp323-sinks` · 分支 `wp/323-sinks`。先读 `_common.md`、`docs/102`（尤其 §5「记录去处」和文末两段 Luoye 10-14 定）、`docs/96`（卡片流与组件化）、`docs/63`（消息与邮箱）、现有各岗位「发出去」的地方（社媒发帖 / Reddit 官方号通道、客服回信、PR、B2B 外发、广告变更账本等）。

## Luoye 定的原则（以此为准）
- **本地发出记录永远有**：工坊替用户发出去的每一条（帖子 / 评论 / 回复 / 邮件 / 消息……）自动记一行：平台、去处（版块 / 收件人）、链接、内容、类型、谁批的、时间；之后对方的回复挂在这一行下面（能跟踪「谁回了我们」）。对方删了原话我们也删原话（667）。
- **外部「记录去处」不内置任何一家**（665）：用户用几句话交代「每发一条记到哪、哪些列、每列填什么、什么格式」，工坊自己配好。飞书只是这个客户的需求；Google Sheets、钉钉在线文档等以后同样靠交代。
- **要求记什么就记什么**（666），不限社媒 / 客服。

## 要做
1. 本地发出记录：统一的记录表（按品牌）、写入点接到现有各「发出去」的地方；查询 / 导出接口。
2. 记录去处框架：交代 → AI 读目标表的表头、生成「列 ← 填什么」映射 → 出「定规矩」卡（配一行预览）给人确认 → 之后每条照映射写；写失败照实说、留本地待补写、可重试；能改 / 停 / 删某个去处。
3. 去处适配器做成可插拔：本单先做**飞书**（电子表格与多维表格；INMO 用我们自己的飞书表，用已有飞书应用，表格共享给它；查清要加哪些权限范围，写进帮助文档，权限由用户在飞书后台勾）。Google Sheets / 钉钉留接口与说明，不实现。
4. 测试：替身的飞书接口；映射生成、确认、写入、失败补写、删除联动。

## 纪律
不读 .env*；不碰 key / token（飞书凭据照旧在本机加密库，由用户填）；不连真实飞书；不连远程机器；不碰本机 4317；不跑批量清理；界面少字。不合 main、不打 tag、不发版。本机负载偏高，测试用 `--maxWorkers=2 --testTimeout=120000`。
