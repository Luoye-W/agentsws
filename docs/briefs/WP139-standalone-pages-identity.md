# WP139 独立页面按「要什么能力」挑自己的分配；403 与 501 分开说；聊天窗常驻入口

worktree `../agentsws-wt/wp139-identity` · 分支 `wp/139-identity`（从 main 新起）。先读 `_common.md`、`_beta-fix-common.md`、`docs/78` §1 #2。

## 问题
`/chat`（试聊）、`/chat-window`（聊天窗）、「连接」页不属于任何岗位，却用全局「当前岗位」（整页刷新后落回店主，`lib/api.ts` `setAssignment`）的 `X-Assignment` 发请求 → 403。
试聊把 403 说成「这个服务进程没有装在线客服」（`lib/i18n.ts` `chat.unavailable` 把 403 / 501 当一回事）；聊天窗对话列表 `GET /v1/chat/sessions` 403 页面不说；连接页 `GET /v1/kol/byo-sources` 每次 403。

## 要做
1. 一个小工具：按「这一页要什么职责 / 能力」从**我名下的分配**里挑一条（如 `dtc.live-chat` → 在线客服那条；`kol.*` → 任一红人职责），挑到就用它的 assignment 发请求，不改全局当前岗位。
   用在：试聊页、聊天窗页、连接页的「自带数据接口」块（以及你在这几页里看到的同类请求）。
2. 挑不到：说人话「你名下没有『网站在线客服』这条职责」+ 去哪加（链接到岗位 / 向导）。
3. 403 与 501 分开两句话：501 = 这台没装；403 = 你没有这条职责 / 权限。检查同类通用错误翻译（`api.ts` 的错误信封 → 文案），别只修这一处。
4. 左栏或「消息」区给**聊天窗**一个常驻入口（在线客服职责存在时出现；按 docs/36 三栏规范放，拿不准放「消息」页顶部一行链接），不再只能从职责面板进。
5. 整页错误（非本单根因，但同一类）：接口报错时保留左栏 + 「重试」按钮，不要白屏一行字——如果 WP140 那边也碰到，以本单为准，WP140 不做这条。
