# WP249 「自家版待处理」：自家 subreddit 的入群申请 / 被举报帖 / 待审新帖队列（决策 81）

worktree `../agentsws-wt/wp249-modqueue` · 分支 `wp/249-modqueue`（从 main 新起）。先读 `_common.md`、WP241 报告（§「自家版待处理」快捷视图没有；职责 `social.reddit` = 自家版运营）、`packages/social-core/src/channels/reddit.ts`（OAuth 适配器、`moderate`、fullname、每分钟 60 跳）、`packages/pr-core/src/subreddits.ts`、卡片流（要拍板的出卡）、岗位页工作视图（职责专属快捷视图挂在视图栏后面）、DECISIONS 81 / 88。

## 背景（Luoye 10-07 定 81：现在就做）
INMO 的官方版 r/inmoxr 是 Luoye 建的，他就是版主。职责「自家版运营」要能看并处理这个版的待处理事项。88 定：版主号只做发帖 / 回复 / 版务这类正式动作，且一律走审批卡；读外部数据不用版主号。

## 要做
1. **先评估接口可用性并写进报告**：Reddit 官方 API 自 2025-11 起新应用需人工审批（第三方实测结论，请据官方文档 / 公开信息核实，**不真去调用**）。写清：已有 OAuth 应用的用户怎么走；拿不到的用户怎么办。
2. **队列（读）**：对自家版拉 `modqueue`（被举报 + 待审）、`unmoderated`（新帖未审）、入群申请（私密 / 受限版的 contributor 申请——若 API 无对应口，写清并只做前两类），统一成「待处理事项」结构：类型、帖 / 评论摘要、作者、举报原因、时间、链接。限速复用适配器的每分钟 60 跳计数；只对**已在本品牌登记、标为自家版**的 subreddit 拉。
3. **快捷视图**：自家版运营职责的视图栏加「自家版待处理」：按类型分组的列表，每条一句摘要 + 举报原因；AI 给出「建议：批准 / 移除 / 忽略 + 一句理由（引用版规）」。
4. **动作一律出卡**：批准 / 移除 / 封禁等版务动作不直接执行，生成审批卡进卡片流（卡上：原文、AI 建议、理由、将执行的动作）；人点同意后经适配器 `moderate` 执行，记变更账本。移除时可选附一条移除理由（版规条目）。
5. **备选路线（只设计、不实现）**：拿不到 OAuth 应用时，用版主号在工作台内置浏览器登录、动作仍走审批卡、驱动层只允许执行审批过的那一个动作——写成设计放报告里，等 Luoye 定。
6. 测试：假 Reddit API（本地）覆盖三类队列、限速、出卡、批准后执行、执行失败照实报。
