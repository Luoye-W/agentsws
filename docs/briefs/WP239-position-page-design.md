## 背景（Luoye 10-06，Windows 真机看「Reddit 运营」岗位页）
「问题很多……岗位里待办应该有多种视图，而不是默认就用日历视图，这里应该学一下 Notion 的 Database 设计方案……面板现在感觉信息层级很乱，一时不知道该如何下手。」
现状（Fable 梳理）：岗位页 = 交给它卡 + 连接卡 + CLI 卡 + 「在日历里看」小链接 + 四页签（卡片 / 面板 / 记录 / 记忆）；面板按「地址栏那一条分配的职责」出数字块；社媒日历 / 群发 / 权限声明在**职责页**；待办不在岗位页，只能跳日历（默认周视图、且不按岗位过滤）。

## 新结构（Fable 定的方向，设计稿照这个画；可在稿里提更好的细节）
层级原则：**先「要我做什么」→ 再「它在做什么」→ 再「做得怎么样」→ 设置往深里藏**。
1. **页头**：岗位图标 + 名字 + 一行状态（「2 张等你批 · 3 件在办 · 今天 1 个待办」，每段可点）；右侧「⋯ 岗位设置」。真缺必需连接时，页头下一行细横幅（一句话 + 去连接），不缺不出。
2. **交给它**：保留输入框 + 建议芯片，收紧高度（一行输入，聚焦展开）。
3. **要你处理**：这个岗位等你批 / 等你选的卡，横向最多 3 张小卡 + 「全部 N 张」→ 卡片流。没有就一行「没有要你处理的」。
4. **工作台（Notion Database 式）**：事项 + 待办 + 排期合成一个「工作」数据集，顶上一条视图栏：**列表（默认）/ 看板 / 日历 / 表格**，右侧「筛选（职责 / 状态 / 截止 / 来源）」「分组」「排序」，视图记住在本岗位。
   - 列表：按状态分组「等你批 / 进行中 / 等别人 / 已完成（折叠）」，每行：标题、职责小标签、状态图标、截止、最近一句进展。
   - 看板：同样四列可拖。
   - 日历：月 / 周切换，只显示本岗位的（不再是全部）。
   - 表格：列可选（标题、职责、状态、截止、花费积分、来源、最近更新）。
5. **数字**：一条紧凑的数字带（每条职责 2–4 个关键数，数据已由接口中台满足的照常出，不催连接），点开看图表。
6. **页签收成三个**：「工作」（上面 2–5，默认）/「记录」/「设置」。「设置」里分节：职责（这个岗位装哪几条、加减、合并拆分入口）、连接（只列与本岗位有关的，必需 / 可选分开）、记忆（岗位层 + 职责层）、定时任务、高级（这条职责能做什么——人话，原始 id 只在开发者视图）。
7. **职责相关的专属工具**（Reddit 的社群待处理 / 群发、红人工作台、B2B 面板、社媒排期日历）不再要用户钻进职责页：在「工作」里作为该职责的**快捷视图**（视图栏后面的「Reddit 社群」「群发」这类标签）出现；职责页保留但入口降级。
