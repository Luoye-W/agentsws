# WP262 事项页重排设计稿：短标题、紧凑页头、对话式时间线（只出设计稿，不改产品代码）

worktree `../agentsws-wt/wp262-matterdesign` · 分支 `wp/262-matterdesign`（从 main 新起）。先读 `_common.md`、`docs/36`（工作台视觉与少字、状态图标 / tooltip / 折叠）、`docs/design/position/*` 与 `docs/design/inbox/*`（设计稿做法：单文件 HTML、内联样式、shots 截图、右侧「设计说明」栏）、`apps/workstation/src/index.css` 与 Tailwind 主题（**照抄真实 token**，不新造视觉）、现有事项页（`pages/matter*.tsx` 与时间线组件、事件种类：用户消息、运行开始 / 完成、Agent 回答、卡片 / 审批、「预览好了」、「卡在缺连接」、待办、换职责）、WP259（标题拆分 `task-text.ts`）、WP253 / WP260（主题运行事件：preview_ready、theme_check、push）。

## 背景（Luoye 10-08，Windows 真机看 Rollout 建站事项，三张截图）
1. 「会话的标题应该是总结性标题，不应该这么长」——现在标题是用户原话前 120 字（四行大字）。
2. 「这里的排版占了太多空间，也不好看」——标题下面「归档 / 关闭事项 / 路由到 Shopify 网页模板 换 / 一句结果 / 参与者 / 这里的待办（这一段是空的）」竖着排了一大块。
3. 「时间线这里我有点没太看懂，而且设计也很丑，所有内容堆叠在一起。应该像 Claude 一样，我们发出去的命令在右边，AI 的回复在左边，包括其他的也一样要优化」。

## Fable 定的方向（稿照这个画，可在稿里提更好的细节）
1. **短标题**：AI 总结的标题（中文 ≤16 字左右，如「Rollout 英文首页 · 深色科技风」），首轮运行开始时用便宜模型起（或从首轮结果里取），用户可点标题改；原话全文作为对话第一条（右侧气泡）。替代 WP259 的「首句 ≤40 字」口径（决策 167 将改）。
2. **页头一行**：短标题 + 一行灰字元信息（职责小标签「Shopify 网页模板 ⇄」可点换 · 状态（进行中 / 等你批 / 已完成）· 参与者头像 · 最近活动）；右侧「⋯」菜单收「归档 / 关闭事项 / 换职责」；待办有才出（右侧窄栏或页头下一行「2 个待办」可展开），没有就不出现。结果摘要不再单独占一行（就在对话里）。
3. **对话式时间线**：
   - 用户的话：右侧气泡；
   - AI：左侧，带岗位 / 职责小头像与名字，正文按 Markdown 排（标题、列表、行内代码、链接可点），长回答可折叠「展开全文」；
   - **结果卡片**：「预览好了」做成一张小卡（主题名、改了几处、「打开预览」主按钮、「发布上线」次按钮→出审批卡）；审批卡 / 选择卡在对话里内嵌成可操作的卡；
   - **过程与系统事件**：「Agent 接着跑了一次」「卡在缺连接」「换了职责」等缩成居中一行小字（可展开看工具调用摘要：读了哪些文件、检查结果、推送）；
   - **运行中**：左侧一条「正在做…」+ 当前一步（如「正在跑主题检查」），可展开实时步骤；
   - 底部固定输入框（像聊天应用），「问 AI」（单轮私聊）作为输入框旁的切换而不是另一块。
4. 明暗两套；桌面 1440 + 窄屏 1024。
