# WP349 品牌分析与竞品分析联网查（Luoye 10-15 改决策 881，这一版就做）

worktree `../agentsws-wt/wp349-brandweb` · 分支 `wp/349-brandweb`（从 main 拉；收尾前合一次最新 main）。先读 `_common.md`、`docs/briefs/reports/WP346.md`、`WP348.md`（它抽出了共用联网搜索 `webSearchOf`、7 天缓存、每卡上限）、`packages/brand-intake/src/insights.ts`、`apps/server/src/brand-intake.ts`、`docs/70` §9。

## Luoye 原话
竞品分析包括品牌分析，这些肯定是要联网去查询的。不可能只靠 AI 原生内置的知识去分析，肯定是要联网的。不用等到下一个，这一版就必须得做。

## 要做
1. **分析时联网**：品牌分析那一轮（首次设置第 ② 步、设置页「重新分析一次」）在抓官网 / Amazon 之外，用官方 web search（复用 WP348 的 `webSearchOf` 与缓存）查：
   - 品牌本身：品牌名 + 品类的评测、媒体报道、社区讨论（用来写定位、人群、卖点、价格带）；
   - 竞品：按品类 / 子品类 / 关键词搜「同类品牌 / alternatives / vs」，得到候选竞品，再对前几个各搜一次核实（官网、价格带、主打卖点）。
   搜索次数设上限（建议品牌 3 次 + 竞品发现 2 次 + 竞品核实每个 1 次、最多 4 个，合计 ≤ 9 次），结果进同一次模型整理。
2. **每一格带来源**：定位、人群、竞品（每个竞品一句理由 + 来源链接）都挂上来源（哪个网页）；档案卡与设置页对比里可点开。没有来源的竞品不收（只出现在模型记忆里的不算），宁缺毋滥。
3. **积分**：搜索按现有价目计入这次分析并沿用封顶思路；封顶装不下时先保官网解析，再竞品，最后品牌评测；照实说哪几格因为额度没查。
4. **没有联网能力时**（没接搜索 / 搜不了）：竞品格留空并说「没联网，查不了竞品」，不再用模型记忆填。
5. 下游（Reddit 巡查 / GEO / 红人 / 广告）不用改，读的仍是档案。
6. docs/70 §9 补联网一节。

## 测试
搜索与模型都用替身：联网结果进了定位 / 人群 / 竞品并带来源；没来源的竞品被丢；封顶时按顺序取舍并照实说；没搜索能力时竞品空着并说明。brand-intake / server / workstation 各补测试；模拟三包照跑。截图：档案卡竞品带来源。
