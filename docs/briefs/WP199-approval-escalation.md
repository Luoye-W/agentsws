# WP199 审批卡升级给上级后施行失败（修 bug）

worktree `../agentsws-wt/wp199-escalation` · 分支 `wp/199-escalation`（从 main 新起）。先读 `_common.md`、`packages/txn`（审批总线、出卡、施行前校验）、`packages/roles/src/supervisor.ts`（上级 / 升级）、`docs/15`、`docs/51` §2.3、WP191 报告 `docs/briefs/reports/WP191.md`「偏离」第 1 条。

## 现象（WP191 实现方报告，main 既有）
15 人包里，发布卡落到运营主管手上，但他没有那条职责、批不了；让它升级给负责人时，升级改动了卡上的**审批人名单**，到施行时的校验（卡的审批人与当初出卡时记的不一致）对不上 → 施行失败。

## 要做
1. 先写一个能复现的测试（替身 + 最小场景），再找根因：升级应当是「在原审批链上追加 / 转交」并留痕，施行校验要认升级后的合法审批人（按升级事件链核对，而不是比对出卡时那一份名单）；**不许放宽成「谁批都行」**——越权批准仍要拒。
2. 顺查同类：转交、代批（秘书代答）、撤回后重开、审批人离职交接这几条路径是否有同样的问题，有就一起修并各补测试。
3. 模拟：给 15 人包加一条场景（发布卡落到没职责的人 → 升级给负责人 → 批 → 施行成功，留痕完整），三运行时都过；其余零漂移。

## 纪律
契约只加不改；不读 .env*；不跑批量清理命令；本机 4317 服务别碰。
