| # | 现象 | 严重 | 状态 |

## 通的部分
岗位页面板能读出红人库、打分与「疑似刷粉」提示、建联漏斗、合作进行中、待审交付物、归因表；`出清单` 的匹配与理由是对的；模拟包里的 kol 场景（接口级）全过。

## 这一轮之后还差什么（给下一单）
1. **付款登记、复盘面板、跟进节奏**三样界面上没有入口（断点 #11 的剩余）；
2. **回信没有归并进「消息」库**——演练里回信落在合作线程上，但 `kolagents` 那个文件夹与合作仍然互不相干（断点 #9 的剩余，63 那条链）；
3. **模拟 DSL 缺三个事件键**（新发现 #14），补上之后「回信 → 意向分类 → 议价」「交付物不合格打回」才写得进接口级场景；
4. **公共红人库**那一档等 WP116（断点 #4 的剩余）；
5. 断点 #2（三处职责数对不上）不在红人这一摊里，该单独收一次。

## 演练模式（WP117 交付 4）
红人营销岗位页「面板」tab 顶上有一个**演练**开关。开了之后：库里铺 24 个合成红人
（六种性格：秒回 / 拖延 / 只谈钱 / 要寄样 / 退信 / 已读不回），数据打 `sandbox` 标记，
顶上一条「演练中 · 不会发出任何真邮件」的状态带，可以「跳到 3 / 7 / 30 天后」触发回信与跟进，
关掉开关一键清空（真数据一条不碰）。

**硬闸不在开关上**：它在服务进程唯一那条真发送路径（`deliverOutbound` 里的
`kolSandboxIntercept`）。界面能被绕过，那一句绕不过去——一封信里混了真人与演练红人也一律拦。
截图在 `docs/assets/workstation/kol-sandbox-*.png`。

## 复测（2026-09-19 下午，WP117 合并后，Fable 在 main 的 demo 上）

**比上午好了一大截，但「全流程」在界面上仍没有被证明走通。**

好了的：
- 红人岗位不再说客服的话：让它找频道，它调的是 `search_creators`，回的是红人的话（断点 #1 修掉）。
- 红人界面有了「候选池 / 活动 / 合作线程」三个子视图。
- 「演练」开关可用：打开后铺 24 个合成红人，顶上一直挂着「演练中 · 不会发出任何真邮件」，有「跳到 3 / 7 / 30 天后」；出站硬闸有测试钉住。
- 接受清单、加联系方式、推进阶段现在有回执，不再吞错。
