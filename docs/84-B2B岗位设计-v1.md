## 0. 结论

1. **新岗位「外贸 B2B」（`b2b`），三条职责**：
   - `b2b.sales` **外贸业务**：询盘、报价、样品、谈判、订单跟进、老客户
   - `b2b.outbound` **主动开发**：找客户、开发信
   - `b2b.marketplace` **B2B 平台运营**：阿里国际站这类平台

   前两条默认都勾，小公司把两条挂给同一个业务员就行。
2. **开发信是这个岗位的核心**。纪律照搬红人建联那一套：一轮三封、每天有上限、第三封发完真停、禁承诺词、抑制名单。另外加三道 B2B 特有的闸：
   - 必须用**独立的发信域名**
   - 每封信都要带退订方式和公司地址
   - 每个联系人都要记下「从哪来的」
3. **邮件分拣**：B2B 的信在收信时就分出来，挪进每个邮箱里的 `BtoBAgents` 文件夹，交给 B2B 这一路。入口和 WP161、WP167 定的一样，不另开。
4. **数据**分三档：
   - 自己的表：免费
   - 官方档：云端替你调 Apify，按条扣积分
   - 自带 key 档：AIsa、海关数据等用你自己的账号

   LinkedIn 只出「请你本人去发」的任务，**不自动抓**。
5. **从 BtoBAgents 能搬的只是判断逻辑和演示数据**：报价授权、证据分级、离职交接、CSV 导入、行业规则、知识六类。开发信、询盘处理、平台运营 BtoBAgents 里本来就没有，要新写。MkSaaS 模板代码一个文件都不搬。
6. **报价永远出卡**，不再有 BtoBAgents 里那种「L3 自动报价」。两套不一致的报价阈值统一成一套（§3.2）。

## 1. 岗位与三条职责

### 1.1 为什么这样切（docs/50 §0）

问的是同一个问题：**在一家中小外贸公司里，这摊活是不是同一个人在干？**

- **询盘、报价、样品、跟单、老客户维护，是业务员一个人的活**，合成一条 `b2b.sales`。不按「询盘」「报价」「样品」再拆：报价出卡、发信出卡本来就在同一条职责里分开管。
- **主动开发单列一条 `b2b.outbound`**。原因是这摊活**常常交给另一个人或外包**：
  - 有的公司专门招开发专员（SDR）
  - 有的把开发信整包给获客服务商
  - 有的让新人先练开发，老业务员只接回复

  它的工具和风险也最集中：名单、数据费、发信域名、反垃圾邮件法。
- **B2B 平台运营单列一条 `b2b.marketplace`**。阿里国际站、中国制造网、环球资源的后台（发产品、调关键词、开直通车、回 RFQ）在多数外贸公司是「平台运营 / 阿里运营」专人在做，和业务员分开。三个平台通常是同一个人在管，所以**合成一条，不按平台拆**。这一点和社媒、红人按渠道拆不同：那边是不同渠道常由不同的人管。

**要 Luoye 定：`sales` 和 `outbound` 合不合并？** 推荐**不合并、默认都勾**。只有一个业务员的公司，两条挂给同一人，用起来和合并一样；公司一旦多招一个开发专员，拆开的好处就出来了。反过来，先合并以后再拆，要迁数据、改面板。

**不在这个岗位里的**：
- 展位、画册、名片的设计 → 已有的 `design.exhibition`
- 买广告位 → 投放岗位
- 零售订单与退款 → 客服岗位
- 单证与跟单（订舱、报关、信用证）也常是另一个人，**先登记为候选职责 `b2b.docs`，第一版不做**

### 1.2 三条职责一览

| | `b2b.sales` 外贸业务 | `b2b.outbound` 主动开发 | `b2b.marketplace` B2B 平台运营 |
|---|---|---|---|
| **管什么** | 询盘接待与回复、需求确认、报价与改价、寄样、谈判记录、订单跟进、沉睡客户唤醒与复购、展会名片录入、业务员离职交接 | 定目标客户画像（ICP）、找公司与联系人、核验与打分、开发信三封序列、回复分类后把有意向的**交给 `b2b.sales`** | 平台上的产品发布与优化、关键词与直通车（P4P）、回 RFQ、平台询盘分给业务员、店铺数据 |
| **要的连接** | `email`（已有）；`whatsapp_business`（已有，沿用 opt-in 与 24 小时窗口三道闸）；日历（**待增加**，目录里还没有） | 发信用的 `email`（**必须是独立发信域名那一个**，§2.3）；数据：官方档走云端 Apify（§6），自带 key 档 AIsa / Hunter / Apollo（**待增加**）；LinkedIn 不接 | 平台后台都没有开放给卖家的接口 → **浏览器模式**（第三栏受控浏览器 + 人接管，同 `social.facebook-group`）；平台通知信靠邮件分拣认出来 |
| **必须出卡** | 回复里有价格、交期、认证、MOQ、独家、账期；发正式报价；折扣或账期超出授权；寄样通知；客户转给别的业务员 | 每一轮序列的首封（批量一张卡，一次看完这一批）；导入或购买名单；查个人联系方式要花钱的那一次；改日配额 | 发布或修改产品；改出价、预算、开直通车（花钱口子永远 L1，同投放）；回 RFQ 报价 |
| **技能** | `b2b-inquiry`（询盘回复写法，自写）、`quotation`（报价单，自写）、`brand-voice`（公司层） | `cold-email`、`prospecting`（改写自 marketingskills，§2.5） | `b2b-listing`（平台产品页写法，自写，第二批） |
| **面板（少字，照「界面少字」）** | 待回询盘 · 报价待审 · 样品在途 · 该唤醒的老客户 | 今天待发 · 序列漏斗 · 回复待分 · 名单来源 | 平台询盘 · 待优化产品 · RFQ |

岗位 persona 一句话：**你是这家工厂 / 外贸公司的业务员，从开发客户到成交到复购；不管零售订单、不管展位设计、不花广告钱。**

## 2. 冷邮件与开发序列（`b2b.outbound`）

### 2.1 照搬红人建联的纪律（`packages/kol-core/src/outreach.ts`）

| 纪律 | 红人那边现在的做法 | B2B 怎么用 |
|---|---|---|
| 一轮只有三封 | 首封 → 第 3 天跟进 → 第 7 天收尾，没有第四封 | 照用。收尾那封写明「不回我就不再打扰」，**发完真停** |
| 每天有上限 | guardrail 的 `max_outreach_per_day` | 照用，**按发信邮箱**算，不按工作区（§2.3 预热） |
| 禁承诺词 | `KOL_OUTREACH_FORBIDDEN`（`core/guardrail.ts`） | 在 `core` 里另加一份 **B2B 承诺词表**：价格、交期、认证、MOQ、独家、「保证」等。出处是 BtoBAgents `domain/policy.ts` 那条「邮件含价格 / 交期 / 认证 / 合同承诺要人审」。开发信里的数字只能引知识库事实卡（`uncitedFigures`，同公关新闻稿） |
| 抑制名单只有一份 | `core/suppression.ts`，客服 / 营销 / 红人共用 | 照用，**不另建**。退订、硬退信、回信里说「别再发」的都自动进名单 |
| 时间由调用方注入 | 没有 `Date.now()` | 照用 |

做法：把序列节奏、日配额、下一封是哪封这几个和渠道无关的函数（`SEQUENCE_DAYS`、`outreachQuota`、`nextInSequence`）从 `kol-core` 提到共用的位置，红人和 B2B 各自 import，**不复制一份**。起草模板是红人专用的（变量是频道、红人名），B2B 另写自己的模板。

### 2.2 回复怎么处理

- 回信由邮件分拣认出来（§5，靠我们发出去那封的 Message-ID 对上线程，不靠猜）。
- 分类沿用 `kol-core/replies.ts` 的形状：有兴趣、要资料、问价、晚点再说、不感兴趣、退订、自动回复、退信。
- **任何一封回信都让这个人的序列立刻停下。**
  - 有兴趣、要资料、问价 → 开一个事项交给 `b2b.sales`（客户卡一起带过去）
  - 退订 → 进抑制名单（永久）
  - 不感兴趣 → **只停这一轮**，进冷却（默认 90 天，职责阈值 `b2b_declined_cooldown_days`；第二次翻倍），期满可以再选进新一轮（Luoye 09-28，WP176 落地；原来写的是进抑制名单）
  - 自动回复（休假）→ 按对方写的回来日期顺延

### 2.3 发信域名：必须独立

冷邮件被投诉多了，**整个域名的信誉会掉**，连带客服回信、营销邮件、报价单都进垃圾箱。所以：

- **强制独立发信域名**：开发序列用的邮箱，域名不能和工作区的主域名、客服邮箱相同。例如主站是 `brand.com`，发信用 `brandmail.com` 或 `trybrand.com`。不满足就**只能起草、不能发**。卡面上一句话说明原因，长说明放教程。
- **发信前的体检**：
  - 查 DNS 里的 SPF 和 DMARC 记录，这一步本机就能查
  - DKIM 是否签上：先给自己发一封测试信，读回信头里的验证结果

  缺了就提示怎么配。**DKIM 或 SPF 不通过不让发**；DMARC 缺了只提示。
- **预热**：新域名前两周每个邮箱每天最多 20 封，之后最多 50 封（具体数见 §10）。每个发信邮箱各自计数。
- 买域名、改 DNS 是用户自己去注册商做，Agent 只给步骤，不代操作。

### 2.4 每封开发信必须带的

| 必带 | 为什么 |
|---|---|
| 真实的发件人名与公司名，主题不误导（不许假 `Re:` / `Fwd:`） | 美国 CAN-SPAM |
| 公司实体地址 | CAN-SPAM 硬要求；加拿大 CASL 也要联系方式 |
| 退订方式（一句「不想再收到就回复 unsubscribe」+ 退订链接）；**10 个工作日内生效**，我们做成立刻生效 | CAN-SPAM / CASL / GDPR 都要 |
| 这个联系人**从哪来的**（来源网址 + 日期），存在联系人记录上 | GDPR 第 14 条：对方问「你怎么有我邮箱」时必须答得上；也是 prospecting 技能的规矩 |

页脚由系统加，模型不写、人也删不掉。guardrail 查到缺页脚就拦下。

### 2.5 两个技能（改写自 marketingskills，MIT）

照 WP160 的规矩：翻译改写成中文 SKILL.md，文件里写「改编自 coreyhaines31/marketingskills（MIT，© 2025 Corey Haines）」，`NOTICE` 加一行，`upstreams.yml` 登记（`kind: ported`，钉提交 `5b2c0007`）。

- **`prospecting` 找客户与打分**：
  - ICP 清单：行业、规模、地区、在用的技术、买的信号、决策人、排除条件
  - 四档：值得马上联系 / 可以联系 / 先放着 / 跳过
  - 置信度：两个以上独立来源才算高
  - 合规八条：不批量爬、不绕验证码、不抓要登录才看得到的、只用公开的商务联系方式、记来源、不用来路不明的库、不按敏感属性分组、守服务商条款

  **打分和 BtoBAgents 的 `decideEvidence` 合成一个**：技能讲「怎么判断」，纯函数算「几分、哪一档、能不能自动写进客户库」，同一套权重。签名、回信、名片算强证据；只知道公司名算弱证据；来源互相矛盾就挂起等人看。
- **`cold-email` 开发信写法**：
  - 一封信一个问题、一个请求
  - 主题 2–4 个词
  - 写法框架：观察→问题→证据→请求
  - 不写「just checking in」、不塞功能清单、不约 30 分钟电话

  **原版是 3–5 封逐步拉长间隔，改成我们的三封**。原版里「给出证据」的部分改成「只引事实卡」。

## 3. 询盘与报价（`b2b.sales`）

### 3.1 询盘

- **询盘从哪来**：
  - 邮件（官网表单、直接来信、平台通知信）
  - WhatsApp
  - 开发信的有意向回复（§2.2）

  都先进 `BtoBAgents` 文件夹（§5），再开事项。
- **怎么答**：复用客服岗位的收件处理管线（`support-core` 的分类、起草、防泄露），换成 B2B 的知识：
  - 知识库里放 **B2B 六类事实卡**：产品线、价格与 MOQ、认证清单、交付能力、样品政策、售后规则。分类照搬 BtoBAgents 的 Company Brain（`demo-data.ts:1017-1047`）。
  - 首次设置时按官网自动判断行业，推荐认证清单和该勾的打法：3C → CE / FCC / RoHS / UKCA / PSE，智能家居加 Matter 等。规则照搬 BtoBAgents `runtime-v2/onboarding.ts`。
- **回复里只要碰到价格、交期、认证、MOQ、账期，就出卡**。这部分由上面那份 B2B 承诺词表在 guardrail 拦。
- 阿里国际站的询盘通知信只有摘要，正文要去后台看。分拣认出来后，开一个「去国际站后台回复」的任务（浏览器模式，§4）。

### 3.2 报价

- **报价永远出卡**，最高 L2（起草好，人点一下才发）。BtoBAgents 里「金额、毛利都在授权内就自动执行（L3）」**不搬**。
- 授权（Mandate）不决定「要不要出卡」，**决定这张卡谁来批**：在授权内，业务员自己批；超出就转给老板（`common.owner`）。
- **两套阈值统一**。BtoBAgents 里两处写的不一样：

| | `domain/policy.ts` | `runtime-v2/runtime.ts:363-367` | **建议统一值** |
|---|---|---|---|
| 单笔金额 | $10,000 | $100,000 | **$10,000** |
| 最低毛利 | 32% | 20% | **20%** |
| 最大折扣 | 8% | 5% | **5%** |
| 最长账期 | 30 天 | 30 天 | **30 天** |

  理由：小厂一张 1 万美元的单已经不小，超了就该老板看；3C 代工毛利常在 15–30%，32% 这条线会让大部分正常报价都转老板，20% 更贴近。四个数都放进首次设置，用户自己改。
- **报价单**：出 PDF，信头用品牌设计里的色和字。报价单一律新建一个版本，不改旧版本（照 BtoBAgents 的 quote / quoteVersion 两张表）。
- **样品**：新对象，状态依次是 待寄 → 已寄（单号）→ 已签收 → 已反馈。超期不寄、超期没反馈出提醒。BtoBAgents 里样品只在演示数据里，要新做。
- **离职交接**：业务员走了，他的客户、商机、未回的询盘按规则（地区 / 产品线）分给接手的人，出一张卡给老板批。规则照搬 BtoBAgents `domain/ownership.ts` 的 `buildTransferPlan`。

## 4. B2B 平台运营（`b2b.marketplace`，第二批）

- 阿里国际站、中国制造网、环球资源**对卖家基本没有开放接口**，平台也不允许机器自动操作。所以走**浏览器模式**：第三栏开受控浏览器，读可以自动；写（发产品、改价、调直通车、回 RFQ）先出卡，人点了再做，失效就停。做法同 `social.facebook-group`。
- 先做**阿里国际站**（用的人最多），另外两家以后照同一套加。
- 平台上的违规词、类目规则写进 `b2b-listing` 技能和知识库。
- BtoBAgents 里**这部分一行代码都没有**，整条新做。

## 5. 邮件分拣与 `BtoBAgents` 文件夹

WP161 已经预留了 `b2b` 路由和 `BTOBAGENTS_FOLDER = 'BtoBAgents'`，WP167 定了「收信只走一个入口：消息同步分拣」。B2B 这一单**只是让分拣器开始产出 `b2b`**：

1. **怎么判成 B2B**（按顺序，前面的命中就不往下）：
   1. 回的是我们发出去的开发信或报价信（线程对得上）→ B2B
   2. 发件人已经在 B2B 客户库里 → B2B
   3. 平台通知信（alibaba.com、made-in-china.com、globalsources.com 的询盘或 RFQ 通知）→ B2B
   4. 模型分类：询价、要目录、问 MOQ、要样品、找代理 / 分销 → B2B

   和客服抢的时候（比如分销商问一笔零售单），前两条已经在库里的人按库里算，其余按模型判，判不准就进「其他」等人看。
2. **判成 B2B 的信挪进这个邮箱里的 `BtoBAgents` 文件夹**，交给 B2B 这一路开事项、起 Run。挪信只由消息同步负责（WP163）。
3. **每个邮箱账号各自处理**：各自找或建自己的 `BtoBAgents` 文件夹；已有的不分大小写就沿用（WP161）。邮箱开关上加一格「这个邮箱收 B2B 信」（WP167 已有开关界面），发信专用的那个邮箱默认也要打开，因为回信会回到它那里。
4. 没开 B2B 岗位的工作区，分拣器不产出 `b2b`，也不建这个文件夹（WP161 原规矩）。
5. 退订回信、硬退信：分拣时直接进抑制名单，不等 Run。

## 6. 数据层与计费

### 6.1 三档

| 档 | 用什么 | 谁付钱 | 说明 |
|---|---|---|---|
| **自己的** | 导入表格（展会名单、老客户、旧 CRM 导出）、手填、名片、打开公司官网看联系页 | 不花积分 | CSV 导入照搬 BtoBAgents `imports/csv.ts` 的中英文表头别名，并入 `kol-core/import.ts` 那一套 |

- **LinkedIn**：
  - 只出「请你本人去 LinkedIn 发」的任务，照 BtoBAgents `policy.ts` 里 LinkedIn 只许人发的规则
  - 用 Apify 查 LinkedIn 资料**默认关**，打开时提示 LinkedIn 条款禁止抓取、有封号和法律风险
  - 不做自动加好友、自动发消息

### 6.2 共享缓存（docs/83 §5）

- **公司层的信息**（官网、行业、规模、地址）在服务商条款允许时可以进共享层：别人查过的再查，命中照收、数据标日期。
- **个人联系方式不进共享层**：姓名 + 邮箱 / 电话、邮箱验证结果都只留在本组织，每次揭示都记审计。
- 自带 key 查的一律不经过云，也就谈不上共享。

### 6.3 账号与积分

以后 B2B 和 agentsws、KOLAgents、KefuAgents 一样，用云端统一账号、**一个积分余额**（docs/83 §0-5、docs/49）。B2B 的数据查询归「数据接口」那一块，模型写信归「AI 使用」那一块，价格由 Luoye 在价目表里定。

## 8. 合规与风险

| 风险 | 怎么处理 |
|---|---|
| **美国 CAN-SPAM**：退订、实体地址、主题不误导 | §2.4 页脚由系统加、guardrail 查；退订立刻进抑制名单 |

| **发信域名信誉** | §2.3：强制独立域名、预热、每邮箱日配额 |
| **数据费**：Apollo / ZoomInfo / 海关数据按席位或按条收费，海关数据尤其贵，很多家禁止转售 | 能转售的（Apify）进官方档按条收；禁止转售的只进自带 key 档；每次花钱先出卡、写明扣多少 |

### 11.2 新职责 `b2b.exhibition`「展会」（Luoye 09-28 加）

展会是 B2B 很重要的获客渠道，而且在中小外贸公司常由专人（市场 / 展会专员）负责一整摊：选展、报名、筹备、现场、会后跟进。按 docs/50 §0 单列一条。

- **管什么**：
  - **选展与策展**：展会日历（广交会、香港电子展、环球资源展、CES、IFA 等按行业与目标市场推荐），每个展的成本估算、往届效果、要不要去的建议
  - **申报与报名**：报名截止日提醒、申请材料清单、展位申请与缴费（**缴费永远出卡**）
  - **筹备**：展位设计**交给 `design.exhibition`**（这一条只开需求单，不做设计）；样品与物料清单、样品寄展运输（交给 `b2b.fulfillment` 或物流）；**展前邀约**：给老客户与潜在客户发邀请（照 §2 的开发信规矩：出卡、配额、退订、德奥默认排除）
  - **现场接待与记录**：名片拍照录入（看图模型走云端，照「不打包重型本机方案」）、每位来访者一句话笔记与意向分级、现场报价只记录不承诺（承诺词照样拦）
  - **会后跟进**：48 小时内的跟进信序列（照 §2）；有意向的交给 `b2b.sales`，没意向的进名单养着；**展会小结**：来访数、有效线索、成本、后续成交（按线索来源归因）
- **要的连接**：`email`；日历（待增加）；名片识别（云端看图模型）
- **必须出卡**：报名与缴费、展前邀约发送、会后跟进发送、把来访者数据导入名单
- **技能**：`trade-show`（自写：选展判断、邀约与跟进写法、现场记录格式）
- **面板（少字）**：下一个展 · 截止日 · 现场线索 · 待跟进

### 11.3 新职责 `b2b.fulfillment`「跟单与单证」（Luoye 09-28：基础工作，要做）

**放在 B2B 岗位里当一条职责，不单开一个岗位**（docs/50：职责是积木、岗位是拼法）。理由：小公司多是业务员自己跟单、做单证，挂给同一个人就行；有专职跟单员 / 单证员的公司，可以把这一条单独组成一个岗位给那个人。默认勾上。

- **管什么**：
  - **生产跟单**：下单后跟工厂 / 供应商要进度、交期预警、验货安排（第三方验货或自检）
  - **订舱与出运**：询价比价货代、订舱、装箱计划、出运通知、船期与到港跟踪、向客户同步节点
  - **单证**：商业发票、装箱单、原产地证、提单核对、信用证单据逐条核对（单证不符点提前列出来）、报关资料交给报关行
  - **收款跟进**：定金 / 尾款 / 信用证交单时间线，尾款未到不放提单的提醒
- **要的连接**：`email`；货代 / 船公司多数没有开放接口 → 读邮件与跟踪页，写动作出卡；日历（待增加）
- **必须出卡**：发单证给客户或银行、订舱确认、放单（电放 / 交提单）、任何付款指示
- **一条硬规矩（防诈骗）**：**收款账户信息只从知识库的事实卡取，任何邮件里要求「改收款账户」的一律出红卡、不采纳**（B2B 最常见的邮件诈骗就是冒充客户或自己人改账户）
- **技能**：`export-docs`（自写：单证清单、信用证核对要点、跟单节点）
- **面板（少字）**：在产订单 · 待出运 · 单证待核 · 尾款待收

### 11.4 海关数据是什么（给 Luoye 的解释，待定）

**海关数据 = 各国进出口报关记录**：哪家公司、从哪个国家、哪家供应商、进口了什么商品、多少量、大概什么时间。外贸用它做三件事：

1. **找真实采购商**：看谁在持续进口你这类产品（比「看网站猜」准得多）
2. **看竞争对手的客户**：同行的货都卖给了谁
3. **判断客户规模和采购周期**：一年进几次、每次多少

常见的服务：ImportGenius、Panjiva（标普旗下）、Volza、腾道 / 外贸通这类国内服务。**特点**：按年订阅，一年几千到几万元；条款多数禁止转售，所以我们没法代买代卖，只能让用户**自带账号**接进来。
