## 6. 额度默认值（T6）

设置批 5 / 天、主题改动 20 / 天、邮件模板 10 / 天、App 改动 5 / 天。

**WP77 实现**：三个新的数原样进三条新 yml 的 `mandate.caps`（`max_setup_batches_per_day` 5 / `max_template_edits_per_day` 10 / `max_app_changes_per_day` 5）；装 / 卸 App 与改 App 配置**共用**最后那一条——在店主那里"今天动了几次插件"就是一个数，拆成两个只会让他要在两处各看一眼。超额一律 `review`（转人审），不是 block。

**与上表的一处出入（故意的）**：网页模板那条**没有** `max_theme_edits_per_day` 这个名字的 cap。`site.shopify-theme` 就是 WP44 的 `site.builder` 原样改名，**内容一个字没动**——它的改副本那条动作叫 `stage_theme_preview`、发布那条叫 `stage_publish_theme`，20 / 天写在 `window.max_count` 上而不是一个具名 cap 上。两条路只能选一条：要么按上表把那条 yml 改了（那就不是"一个字没动"），要么让它照旧、由这一行把差异说清。选了后者——改名迁移这件事的价值全在"已有分配原样还能跑"，动它的额度就等于把回归题变成新功能。


## 7. 平台专属的官方技能、Dev MCP 与 Shopify CLI（WP216，Luoye 10-05）

- **按品牌的建站平台走**（Fable 10-05 改）：**平台没设 = 一样都不启用**；没设而连了 Shopify 店铺（`shopify_admin`）就推断为 Shopify 并写回档案（档案没建过只在这次算数）；建站岗位页上没设平台时出一行「先选一下你的建站平台」+ 下拉（负责人才能选）；CLI 卡只给真有网页模板这条职责的品牌。映射在 `packages/contracts/src/platform-kits.ts` 的 `PLATFORM_KITS`（平台 → 官方技能 / 官方 MCP / 官方 CLI），这一版只有 Shopify 一行。判据是品牌档案的 `storefront_platform`（每次现取）：不是 Shopify 的品牌，官方技能不加载、不进技能页、Dev MCP 工具不进工具面、CLI 卡不出、本机不检测；改平台下一次运行 / 刷新就跟着变，改走时不碰用户本机装好的 CLI。接 WooCommerce / Shopline / Shoplazza 时往表里加一行即可。
- **官方技能**：Shopify-AI-Toolkit v2.0 起把 22 本分题技能（含 `shopify-liquid`）合成一本 `shopify`。我们原样收录 v2.1.0 的 `SKILL.md` 与 `references/{liquid,custom-data,admin}.md`（MIT，sha256 钉在 `packages/skills/bundled/shopify/agentsws.json`），不带 `scripts/`（会把查询、代码和用户原话报给 shopify.dev）与 hooks；我们的话在旁注与 `AGENTSWS.md`，入库时拼成一份（官方正文与参考的标题降两级、各成一段）。挂在网页模板 / 邮件模板 / 整站搭建三条，按需加载；插件那条不挂。
- **Dev MCP**：沿用 WP44 的封装（钉 1.15.0、子进程关遥测），加了平台闸；**默认开**（`AGENTSWS_SHOPIFY_DEVMCP=0` 关），启动时不起，Shopify 品牌第一次跑职责时才在后台下载，下载好之前工具面是空的；出网清单写在平台套件那一行（卡与报告里照实列）。1.16.0 的工具表改了，升级另走 docs/42。
- **Shopify CLI**：连接页与建站岗位页一张卡（`GET /v1/platform-kit`），三格状态图标（装好 / Node / 登录）；没好时只给下一步（安装命令 / Node 门槛 / `shopify auth login`），登录由用户在浏览器里自己做、点「我登好了」只记时间。首次设置完成屏在「Shopify + 勾了建站」时问一句要不要现在装。网页模板的终端命令白名单不变（`shopify theme list / pull / check / push --unpublished`，发布物化成卡），跑 CLI 一律带关遥测变量。教程 `docs/help/shopify-cli.md`。

## 8. 网页模板端到端：AI 用工作台的 Shopify CLI 改主题（WP253，10-07）

- **AI 拿到的是九个受限主题工具，不是终端**（`packages/stand-ins/src/runtime/theme.ts`，只给 `site.shopify-theme` / 旧名 `site.builder`）：`theme_init_from_base`（从 agentsws-theme 钉死的 commit 起底，sha256 校验，LICENSE 原样带上；目录有东西不覆盖，`replace` 挪开不删）、`theme_list` / `theme_pull` / `theme_check`、`theme_files` / `theme_read_file` / `theme_write_file`（只限工作目录；以 agentsws-theme 起底时只许改 `custom-*` / templates / section 组 / locales / `settings_data.json`）、`theme_push_unpublished`（推成未发布主题、回预览链接；同名再推更新同一份）、`theme_publish`（**只出 `publish_theme` 的卡**，L1，卡上写「将把主题 X 设为线上主题」+ 从哪一份换 + 改了哪些文件 + 预览链接）。`theme dev` 不给。
- **服务端**：`apps/server/src/site-theme.ts`（按品牌一份）把 `shopify-theme.ts` 装进来——CLI 起法用 WP245 的私有安装（系统全局的也认）、登录态用 WP245 按品牌记的那一笔（凭据只在 CLI 自己的会话里，不传令牌）、店铺地址取本品牌的 Shopify 连接，没连就用岗位页上填的；工作目录 `<data>/themes/<workspace>/<store>/`（与终端沙箱、变更审阅同一处）。批过的 `publish_theme` 由执行器调 `apply()` 跑 `theme publish`——整条路上唯一换线上主题的地方。
- **界面**：建站岗位页顶上一行「让 AI 改网站还差哪一步」（没装 →「一键安装」、没登录 →「登录 Shopify」，点了在下面展开 WP245 的卡看进度；不知道店 → 一格店铺地址），补上就消失（`GET /v1/site/theme`、`PUT /v1/site/theme/store`）。推好预览时事项时间线一条「预览好了」+「打开预览」。
- **店铺连接改成可选（Fable 10-07）**：建站四条职责的 `shopify` 连接都是 `required: false, recommended: true`——主题走 CLI + 店铺地址就够，另外三条没连也能开工（读不到的照实空着）；建站岗位页不再出「还缺必需的连接」、首次设置清单里对建站不标必须。店铺管理 / 订单履约等 `dtc.*` 照旧必需。
