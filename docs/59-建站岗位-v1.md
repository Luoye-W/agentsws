## 1. 职责骨架（T1）

| 职责 | 读 | 写（→ ChangeKind） | 额度 | 上限 |
|---|---|---|---|---|
| `site.shopify-build` 整站搭建 | 店铺设置、主题列表、页面 / 导航结构、必装清单、上线检查单 | `stage_store_setup`（`store_setup`：导航 / 页面结构 / 基础设置一批）、`stage_theme_install`（`theme_install`）、`run_launch_checklist`（`launch_check`：只读巡检出卡） | `max_setup_batches_per_day` 5 | 装主题 L1；设置批 L2（结账 / 支付 / 税仍无写动作，51 N2）；检查单 L3 |

| `site.shopify-email` 邮件模板 | 通知邮件模板（订单 / 发货 / 退款 …）、营销模板 | `stage_email_template`（`email_template_edit`：草稿 L2；**启用 L1**） | `max_template_edits_per_day` 10 | 启用永远人审——发错模板是发给全部客户 |
| `site.shopify-apps` 插件 | 已装 App、可选 App 目录（连接目录里那些"待增加"）、App 配置 | `stage_app_install`（`app_install` **L1**）、`stage_app_config`（`app_config` L2）、自家 Extension 开发走 `theme_edit` 同一条路 | `max_app_changes_per_day` 5 | 装 / 卸 L1；配置 L2 |

**WP77 实现**：四条 yml 在 `packages/roles/roles/site/`（`shopify-build` / `shopify-theme` / `shopify-email` / `shopify-apps`），岗位模板 `packages/roles/positions/site.yml`（四条 `default: true`）+ `SEED_POSITIONS` + `BUNDLED_ROLES`；`site.builder` → `site.shopify-theme` 是**文件改名、内容一个字没动**，旧 id 进 `packages/roles/src/load.ts` 的 `ROLE_ID_ALIASES`。六个新 ChangeKind（`store_setup` / `theme_install` / `launch_check` / `email_template_edit` / `app_install` / `app_config`）与三个对象（`launch_item` / `email_template` / `shop_app`）在 `packages/contracts/src/{changes,common,site}.ts`。门在 `packages/core/src/guardrail.ts`：`theme_install` / `app_install` 进 `HARD_L1`（yml 的 ceiling 可被工作区策略放宽，硬顶不行）；`store_setup` 命中 `STORE_SETUP_FORBIDDEN_FIELD_PREFIXES`（checkout / payment / tax / gateway / billing）直接 **block**；`email_template_edit` 按 `after.enabled` 分档（草稿 L2 / 启用 L1），缺必需变量 **block**（`EMAIL_TEMPLATE_REQUIRED_VARS` 与 `site-core` 共用同一份）；`launch_check` 的 `items` 为空也 block（"一项都没查"与"全都过了"在界面上长得一样）。Shopify 对照表补行在 `packages/connect-adapter/{action-side-effects.yml,src/shopify-actions.ts}`。

## 2. `site-core`（T2）

`checklist.ts`（上线检查单：域名 / 支付 / 税 / 运费 / 政策页 / 导航 / 必装 App / 主题发布——纯函数出清单与缺项）、`theme.ts`（复用 WP44 的 CLI 封装：拉副本 / 改 / 预览 / 发布）、`email-templates.ts`（Liquid 模板解析与变量校验：缺变量即 block）、`apps.ts`（App 目录、装 / 配的 Admin 动作、与连接目录"待增加"卡的对应）。

**WP77 实现**：`packages/site-core/src/{checklist,theme,email-templates,apps}.ts`，**全是纯函数**（同一份事实每次得到同一张清单）。数据面在 `apps/server/src/site.ts`（三张表按品牌进 `BrandModules`；事实经**只读** Action 读回来 `createConnectSiteFacts`，读不到的那一格记 `unknown` 而**不记 `missing`**——一次令牌过期不该在卡面上写成"这家店没有收款方式"）；`/v1/site/*` 五条在 `packages/api/src/routes/site.ts`（检查单与 App 走 `store_config`，模板走 `content` 两把闸）；记录源 `RecordSitePort` 只给模板与 App，**巡检结论不给**（它已经原样在卡上了）。

## 3. 面板与卡（T3）

分块：上线检查单（缺项高亮）、主题副本与预览、待审改动（主题发布 / 邮件启用 / 装 App 各一车道）、已装 App、邮件模板状态；卡：检查单卡（L3）、主题发布卡（L1，带预览链接）、邮件模板启用卡（L1，带渲染预览）、装 App 卡（L1）。

**WP77 实现**：`packages/deck/src/blocks.ts` 的 `VIEW_BY_ROLE` 四条 `site.*`（四条职责各看自己那几块，**一块店铺后台的积木都不放**——这四条的 scopes 里订单与分析是只读的，19 §3 过滤下推）；数据源 `site` 进 `ALWAYS_CONNECTED`（我们自己的库，永远算连上）；三条待审车道进 `PENDING_LANES`。四张卡不是四个新 kind，都是 `staged_change` 的投影（36 §2），差别在 `packages/deck/src/project.ts` 的 `siteHighlights` 那三个芯片：`preview`（12 §2「预览链接就是审批材料」）/ `gaps`（缺项分两档写，不合成一个健康分）/ `site_target`（这张卡对着哪一封信 / 哪一个 App）。i18n 中英在 `apps/workstation/src/lib/i18n.ts`。截图：`docs/assets/workstation/site-position.png`（demo 的那几行由 `seedDemoSite` 放，故意是一家刚开起来、还差几项的店）。

## 6. 额度默认值（T6）

设置批 5 / 天、主题改动 20 / 天、邮件模板 10 / 天、App 改动 5 / 天。

**WP77 实现**：三个新的数原样进三条新 yml 的 `mandate.caps`（`max_setup_batches_per_day` 5 / `max_template_edits_per_day` 10 / `max_app_changes_per_day` 5）；装 / 卸 App 与改 App 配置**共用**最后那一条——在店主那里"今天动了几次插件"就是一个数，拆成两个只会让他要在两处各看一眼。超额一律 `review`（转人审），不是 block。

**与上表的一处出入（故意的）**：网页模板那条**没有** `max_theme_edits_per_day` 这个名字的 cap。`site.shopify-theme` 就是 WP44 的 `site.builder` 原样改名，**内容一个字没动**——它的改副本那条动作叫 `stage_theme_preview`、发布那条叫 `stage_publish_theme`，20 / 天写在 `window.max_count` 上而不是一个具名 cap 上。两条路只能选一条：要么按上表把那条 yml 改了（那就不是"一个字没动"），要么让它照旧、由这一行把差异说清。选了后者——改名迁移这件事的价值全在"已有分配原样还能跑"，动它的额度就等于把回归题变成新功能。
