# X（Twitter）的两个连接

这篇讲 X 的两个连接：查账号、发推用的 X API，和投放用的 X Ads API。**两者是两套授权**，买了一个管不到另一个。

| 连接 | 一句话 | 要不要审核 / 花不花钱 |
|---|---|---|
| X API | 批量查账号粉丝数；发推与回复 | **付费**，Basic 档起；发推要用户上下文的 OAuth |
| X Ads API | 投放 | 还没接；申请制，要人工审核 |

## X API

X 的官方接口是**付费**的：免费档读不了用户资料。

接上之后，一次能批量查最多 100 个账号名的粉丝数。**互动率这一格我们不给**——单个用户的接口拿不到近期帖子的互动数，编一个不如空着。

**怎么做**

1. 到 [X 开发者后台](https://developer.x.com/en/portal/dashboard) 注册开发者账号。
2. 买一个能读 users 接口的档位（Basic 起；这一步花钱）。
3. 在项目里建一个 App，复制它的 Bearer Token。
4. 把令牌填进表单。它只存在这台电脑上。

**链接**

- [X 开发者后台](https://developer.x.com/en/portal/dashboard)
- [users 接口文档](https://docs.x.com/x-api/users/user-lookup-by-username)

**没买会怎样**

没买档，红人这条职责照样能用：找人靠导入与公共库，建联、合作、审核、归因一样不少。社媒运营的 X 那条职责用的也是同一张卡。

**发推要注意**

发推与回复都已经接上了（`POST /2/tweets`，回复是同一个口子多加一格 `reply`）。但**发推要的是用户上下文的 OAuth**：只填一把 App-only 的 Bearer Token，只读得了、发不了。那时 X 会回 403，我们照实说「这个档买不到这个口子」。

## X Ads API

申请制：要先有广告账户，提交 Ads API 申请、说明用途，再等人工审核。

> **还没接。** 连接目录、职责、额度与面板骨架已经就位，真调用还没做。社媒那条买的 X API **付费档管不到广告这一侧**——是两套授权。在此之前，投放面板上 X 那一块照实说「还没接」。

**怎么做**

1. 暂时没有步骤——这家还没接。

**链接**

- [X Ads API](https://developer.x.com/en/docs/x-ads-api)

## 常见问题

- **发推报 403**：你填的多半是 App-only 的 Bearer Token，它只能读。发推要用户上下文的 OAuth。
- **互动率那一格为什么是空的**：X 的单个用户接口拿不到近期帖子的互动数，我们不编。
- **买了 X API，能不能顺便投广告**：不能。X API 的付费档管不到广告，X Ads API 是另一套授权，而且我们这边还没接。
