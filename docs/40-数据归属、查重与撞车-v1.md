| | |
|---|---|
| 日期 | 2026-09-10 |
| 起因 | Luoye 三问：① 公司希望数据留在公司库，人走了数据不丢；个人数据与公司数据怎么兼顾、关系怎么梳 ② 有人做过的插件 / 自动化别人又做一遍，怎么避免 ③ 一件事大家都以为该自己做，结果都在做；能不能看到谁在做、新任务会不会撞车 |

## 1. 数据归属：公司库是真源，个人是视图 + 私有区

### 1.1 现在的实际情况（诚实）

| 层 | 现状 |
|---|---|
| 存储 | 一个工作区一套 SQLite（`AGENTSWS_DATA_DIR`），在**跑服务进程的那台机器**上。单人公司 = 你自己电脑；多人公司现在**没有**"服务进程在公司机器、员工电脑只连它"的打包（13 §5 定的三档部署里，公司 Docker 档与托管档还没落，桌面壳只会把服务进程当本机 sidecar 拉起） |
| 归属字段 | 事件日志、审批、账本、事项、待办、会议、知识事实卡都带 `workspace_id`；个人化的东西（技能个人层 overlay、个人记忆、首页数字块偏好、对话定制卡）带 `owner: person_id` 但**同样存在工作区库里** |
| 人走了 | 05 有 `handover`（接手人 / 兜底）但只透传，没真把在办事项转过去；21 有 `PrivacyErase`（删主体 = 销毁密钥 + 删行）；没有"离职"这个动作 |
| 搬家 | 33 说了"双向搬家"（导出 / 导入工作区），没实现 |

所以你担心的"人离开数据会不会丢"，答案取决于部署档：**单人档不会丢（库就在公司电脑上）；多人公司今天还没有正确的部署形态**，这是第一个要补的洞。

### 1.2 梳理：三类数据、一个真源

```
公司库（唯一真源，跑在公司控制的机器上：单机 / 公司 Docker / 托管）
├─ 公司数据：对话线程、订单快照、事项、待办、审批与账本、事件日志、会议与记录、
│            知识库、技能公司层与部门层、定时任务与流程、连接与凭据、制度（职责 / 岗位 / 分配）
├─ 个人数据（owner = 某人，仍在公司库里，受 21 敏感级与授权保护）：
│   ├─ 技能个人层 overlay、个人记忆、个人偏好（数字块、语言）、个人定制卡
│   └─ 管理员看不到内容，但能做三件事：迁移给接手人 / 归档只读 / 销毁
└─ 私人（不属于公司）：**不进公司库**——个人的其他公司工作区（20 Join）、个人电脑上的浏览器登录态
```

三条规则：
1. **个人电脑上不存真源**。桌面壳和浏览器只是客户端；离线草稿只在本机缓存，联网即同步。单人公司例外：那台电脑就是公司机器。
2. **个人数据也在公司库，但按 21 的敏感级隔离**：默认 `confidential`，只有本人可读；管理员只有"迁移 / 归档 / 销毁"三个动作，没有"读"。这样既不丢，又不会变成监控。
3. **离职是一个正式动作**（`POST /v1/workspaces/:id/members/:person/offboard`）：撤销全部分配 → 在办事项、未完待办、定时任务按 05 `handover` 转接手人（真转，不只透传）→ 个人层 overlay 归档成"前员工层"只读，接手人可一键"采纳进部门层"（走 `policy_change` 审批）→ 个人记忆里工作相关的可迁给接手人（审批），其余按 21 擦除 → token 立即失效 → 出一份离职报告卡给 owner。

### 1.3 要补的东西（部署与搬家）

| 缺口 | 做法 |
|---|---|
| **公司 Docker 档** | `docker-compose.yml`：服务进程 + OpenConnector + 数据卷，跑在公司 NAS / 云主机；员工电脑的桌面壳加"连接公司服务器"模式（读 `AGENTSWS_SERVER_URL`，不再本机拉 sidecar），登录走 20 的 magic-link / 邀请 |
| Postgres 档 | 多人并发到一定量 SQLite 会吃力；21 已为 Postgres 方言留位，后置到有真实压力再做 |
| **导出 / 导入** | `agentsws export --workspace` 出一个带清单与哈希的包（事件日志 + 各库 + 密钥环的**包裹后**密钥），`import` 校验后导入；33 的"双向搬家"与备份都靠它；备份恢复后自动走 WP34 的"先对账再放开出站" |
| 备份 | 定时任务每天 `export` 到指定目录 / 对象存储（凭据不导出明文，只导出包裹密文） |

## 2. 重复造轮子：建之前先查，好东西往上浮

### 2.1 为什么会重复

一个人做了个定时任务 / 流程 / 技能 / 定制卡，别人**看不见**（现在各自岗位页里），也没有"建之前查一下"的环节。

### 2.2 做法

1. **公司目录页**（"公司"页第四个 Tab「工具箱」）：本公司所有已装应用、技能（三层）、流程、定时任务、定制卡，每条带：谁建的、哪些岗位在用、上次运行、最近 30 天用了几次、评分。按用途搜索（⌘K 同源）。
2. **建之前先查**：任何"建"的入口（新建定时任务 / 流程 / 技能副本 / 定制卡 / 指导里的 global_rule）在保存前调 `POST /v1/catalog/similar`：用 WP29 的语义键（去停用词词袋哈希）+ 相同触发器 / 相同目标对象做相似匹配 → 有相似的就出一张选择题卡：「已有『每天早上汇总退款单』（李默建，运营在用）：复用它 / 合并进它 / 我这个不一样，仍新建（要写一句为什么）」。选"仍新建"必须写理由，理由进目录，下次别人查得到。
3. **往上浮**：个人建的东西默认个人层；被两个岗位以上采用或周复盘里被点名 → 系统出一张"晋升到部门 / 公司层"卡（复用 24 的晋升机制与 Wilson 门槛）；晋升后个人副本自动指向公司版，不再各存一份。
4. **周复盘里报重复**：WP27 的周复盘加一段"疑似重复"（相似度高但都在用的成对列出），owner 一键合并。
5. **开源社区层**：市场（23，二阶段）上线后，目录页的"先查"扩到社区注册表——本公司没有，社区可能已有。

## 3. 任务撞车：一件事一个主人，认领即锁，先看再做

### 3.1 现状

工作模型（37）里待办有 `owner`，事项有 `participants`；会议产出的待办走认领卡；但**没有**"创建时检查是否已有人在做"，也没有"正在做"的总览，一件事完全可以被两个人各建一条。

### 3.2 做法

1. **撞车检测**：`POST /v1/todos` / 新建事项 / 认领时，服务端按三把钥匙找相似的**进行中**项：① 同一个主题对象（同订单 / 同客户 / 同会议 / 同店铺）② 语义键相似 ③ 同岗位同日。有命中 → 不直接建，回 `409 similar_in_progress` + 候选 → 界面出选择题：「李默正在做『核对昨天的退款单』（进行中，2 张卡等他定）：加入协作 / 交给他 / 我这个不一样，仍新建」。"仍新建"要写一句区别。
2. **认领即锁**：来自会议 / 计划 / 告警的任务先进**待认领池**，谁点"我来"谁是主人，其他人看到的立刻变成"李默已认领"；主人可以"转交"或"加协作者"。这就是 06 §2 认领管道的正式落地。
3. **看得见谁在做**：首页「今天」右栏加"正在进行"（本岗位 + 相关岗位的进行中事项，主人头像、开始时间、卡数）；公司页加"进行中"看板（按岗位分列，owner 视角）；事项页显示参与者与最近活动。WP33 的 WebSocket 已经推 `todo.* / matter.*` 摘要，界面实时变。
4. **分配任务时就防撞**：每日计划卡里 Agent 建议的任务先查撞车，撞的不建议；会议纪要抽出的待办若与已有进行中项相似，认领卡上直接写"可能与 X 重复"。
5. **闲置回收**：认领了 N 天没动静（无卡、无时间线）→ 提醒主人；再不动 → 回到待认领池，owner 收通知。

## 4. 派工

| WP | 内容 | 验收 |
|---|---|---|
| **WP36 数据归属与部署档** | 离职动作（撤分配 → 真交接 → 个人层归档 / 采纳 / 迁移 / 擦除 → 离职报告卡）；`export / import` 与每日备份任务；`docker-compose` 公司档；桌面壳"连接公司服务器"模式；管理员对个人数据只有迁移 / 归档 / 销毁三动作（测试断言读不到内容） | 模拟：一人离职，在办事项全到接手人、他的 overlay 变只读、擦除后库文件里找不到他的私有内容；导出再导入的工作区事件链完整；两台机器一台跑服务一台只跑桌面壳能登录 |

| **WP38 认领与撞车** | 待认领池 + 认领即锁 + 转交 / 协作；`409 similar_in_progress` 三把钥匙；首页"正在进行" + 公司页看板 + 事项参与者；计划卡与认领卡的撞车提示；闲置回收 | 模拟 15 人 pack：两人同时建同一订单的待办，第二个人看到"李默正在做"；会议产出的待办一人认领后其他人看到已认领 |

## 5. 自主决定（待 Luoye 审）

- E1 公司库是唯一真源；个人数据也在公司库，按敏感级隔离，管理员只有迁移 / 归档 / 销毁三动作、没有读
- E2 离职是正式动作，交接必须真转；个人层 overlay 默认归档只读而不是删
- E3 多人公司必须跑公司 Docker 档；个人电脑不存真源；Postgres 后置
- E4 "建之前先查"用选择题卡，选"仍新建"必须写理由
- E5 撞车检测放在创建路径上回 409 + 候选，不做事后提醒
- E6 认领即锁；闲置回收回池
