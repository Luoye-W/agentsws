| | |
|---|---|
| 日期 | 2026-09-10 |
| 起因 | Luoye 三问：① 公司希望数据留在公司库，人走了数据不丢；个人数据与公司数据怎么兼顾、关系怎么梳 ② 有人做过的插件 / 自动化别人又做一遍，怎么避免 ③ 一件事大家都以为该自己做，结果都在做；能不能看到谁在做、新任务会不会撞车 |

## 1. 数据归属：公司库是真源，个人是视图 + 私有区

### 1.1 现在的实际情况（诚实）

| 层 | 现状 |
|---|---|
| 存储 | 一个工作区一套 SQLite（`AGENTSWS_DATA_DIR`），在**跑服务进程的那台机器**上。单人公司 = 你自己电脑；多人公司现在**没有**"服务进程在公司机器、员工电脑只连它"的打包（13 §5 定的三档部署里，公司 Docker 档与托管档还没落，桌面壳只会把服务进程当本机 sidecar 拉起） |
| 归属字段 | 事件日志、审批、账本、事项、待办、会议、知识事实卡都带 `workspace_id`；个人化的东西（技能个人层 overlay、个人记忆、首页数字块偏好、对话定制卡）带 `owner: person_id` 但**同样存在工作区库里** |
| 人走了 | 05 有 `handover`（接手人 / 兜底）但只透传，没真把在办事项转过去；21 有 `PrivacyErase`（删主体 = 销毁密钥 + 删行）；没有"离职"这个动作 |
| 搬家 | 33 说了"双向搬家"（导出 / 导入工作区），没实现 |

所以你担心的"人离开数据会不会丢"，答案取决于部署档：**单人档不会丢（库就在公司电脑上）；多人公司今天还没有正确的部署形态**，这是第一个要补的洞。

### 1.2 梳理：三类数据、一个真源

```
公司库（唯一真源，跑在公司控制的机器上：单机 / 公司 Docker / 托管）
├─ 公司数据：对话线程、订单快照、事项、待办、审批与账本、事件日志、会议与记录、
│            知识库、技能公司层与部门层、定时任务与流程、连接与凭据、制度（职责 / 岗位 / 分配）
├─ 个人数据（owner = 某人，仍在公司库里，受 21 敏感级与授权保护）：
│   ├─ 技能个人层 overlay、个人记忆、个人偏好（数字块、语言）、个人定制卡
│   └─ 管理员看不到内容，但能做三件事：迁移给接手人 / 归档只读 / 销毁
└─ 私人（不属于公司）：**不进公司库**——个人的其他公司工作区（20 Join）、个人电脑上的浏览器登录态
```

三条规则：
1. **个人电脑上不存真源**。桌面壳和浏览器只是客户端；离线草稿只在本机缓存，联网即同步。单人公司例外：那台电脑就是公司机器。
2. **个人数据也在公司库，但按 21 的敏感级隔离**：默认 `confidential`，只有本人可读；管理员只有"迁移 / 归档 / 销毁"三个动作，没有"读"。这样既不丢，又不会变成监控。
3. **离职是一个正式动作**（`POST /v1/workspaces/:id/members/:person/offboard`）：撤销全部分配 → 在办事项、未完待办、定时任务按 05 `handover` 转接手人（真转，不只透传）→ 个人层 overlay 归档成"前员工层"只读，接手人可一键"采纳进部门层"（走 `policy_change` 审批）→ 个人记忆里工作相关的可迁给接手人（审批），其余按 21 擦除 → token 立即失效 → 出一份离职报告卡给 owner。

### 1.3 要补的东西（部署与搬家）

| 缺口 | 做法 | 状态（2026-09-10，WP36） |
|---|---|---|
| **公司 Docker 档** | `docker-compose.yml`：服务进程 + OpenConnector + 数据卷，跑在公司 NAS / 云主机；员工电脑的桌面壳加"连接公司服务器"模式（读 `AGENTSWS_SERVER_URL`，不再本机拉 sidecar），登录走 20 的 magic-link / 邀请 | 桌面壳那一半 **✅**（`mode: 'local' \| 'remote'`、不拉 sidecar、不生成本机密钥、托盘「已连接 X」、首启向导二选一、playwright 冒烟两台机器）；`docker-compose.yml` 归 **WP40** |
| Postgres 档 | 多人并发到一定量 SQLite 会吃力；21 已为 Postgres 方言留位，后置到有真实压力再做 | 归 **WP40**（后置） |
| **导出 / 导入** | `agentsws export --workspace` 出一个带清单与哈希的包（事件日志 + 各库 + 密钥环的**包裹后**密钥），`import` 校验后导入；33 的"双向搬家"与备份都靠它；备份恢复后自动走 WP34 的"先对账再放开出站" | **✅** `agentsws export --workspace <id> --out <dir\|zip>` / `agentsws import <pkg> --data-dir <dir>`；各库走 `VACUUM INTO` 拿一致性快照，`manifest.json` 带版本 / 包清单 / 每文件 sha256 / 事件链头尾 / 密钥环包裹情况；导入先核对哈希、再 `verifyChain` + 逐条 upcast，然后起一次服务进程跑 WP34 对账 |
| 备份 | 定时任务每天 `export` 到指定目录 / 对象存储（凭据不导出明文，只导出包裹密文） | **✅** 每天 04:00 `sched_backup`（排在 03:00 保留期清理之后）+ `POST /v1/backup/export`（owner）；目录 `AGENTSWS_BACKUP_DIR`（缺省 `<数据目录>/backups`），保留份数 `AGENTSWS_BACKUP_KEEP`（缺省 7）。对象存储归 **WP40** 的 `BlobStore` |
| **离职动作** | （§1.2 第三条规则） | **✅** `POST /v1/workspaces/:id/members/:person/offboard`：撤全部分配 → 在办事项 / 未完待办 / 定时任务真转接手人（时间线留痕，发 `matter.handover`）→ 个人层 overlay 归档成只读的前员工层（接手人可一键采纳，走 `policy_change`）→ 个人记忆按 `migrate_work` / `erase` 处置 → 离职报告 + `member.offboarded`。每步幂等，任一步失败整体 `partial` 可重跑 |
| **管理员对个人数据没有"读"** | （§1.2 第二条规则、E1） | **✅** 个人层 overlay 的读路径按 `person_id === actor` 收窄（技能页曾把工作区里每个人的个人层正文都端出来）；个人记忆只开 `countSubject / migrateSubject / eraseSubject` 三个**只回条数**的方法；owner 能做的只有迁移 / 归档 / 销毁 |
| **本机不存真源** | （§1.2 第一条规则） | **✅** 工作台一行 IndexedDB 都不用；`localStorage` 只有主题、语言、会话凭据三个键 + `agentsws.draft.*` 前缀（未发送草稿），有一组用例钉住这条边界 |

## 2. 重复造轮子：建之前先查，好东西往上浮

### 2.1 为什么会重复

一个人做了个定时任务 / 流程 / 技能 / 定制卡，别人**看不见**（现在各自岗位页里），也没有"建之前查一下"的环节。

### 2.2 做法（WP37 已落地，✅ = 有实现 + 有测试）

1. ✅ **公司目录页**（"公司"页第四个 Tab「工具箱」）：本公司所有已装应用、技能（三层）、流程、定时任务、定制卡、规矩，每条带：谁建的、哪些岗位在用、上次运行、跑了几次、在哪一层。按用途搜索（⌘K 同源，都打 `GET /v1/catalog?q=`）。**评分未做**（没有打分入口，硬凑一个数不如不给）；"最近 30 天次数"目前用调度库的累计触发数近似，界面上写"累计"。
2. ✅ **建之前先查**：五个"建"的入口——`POST /v1/schedules`、`POST /v1/workflows`、`PUT /v1/skills/:name/overlay`（第一次开个人副本）、`POST /v1/blocks/propose`、指导里的 `global_rule`——保存前都过同一个 `guardSimilar`：语义键（复用 WP29 的去停用词词袋）+ 相同触发器 / 相同目标对象，**同 kind 是道门**。查到像的回 `409 similar_exists` + 候选，界面出选择题卡「复用它 / 合并进它 / 我这个不一样，仍新建」；"仍新建"必须写 ≥ 8 个字的理由，否则 400；理由进目录，下次别人查得到（也是晋升判据里的负样本）。
3. ✅ **往上浮**：个人建的东西默认个人层；被 ≥ 2 个岗位采用或周复盘点名 → 进候选，再用 24 的 Wilson 单侧 95% 下界（≥ 0.9）判要不要出卡：技能出 `skill_promotion`，其余出 `policy_change`。批准后条目升层、被合并的个人副本记 `superseded_by` 指向它，不再各存一份。
4. ✅ **周复盘里报重复**：周 / 月复盘加一段"疑似重复"（相似度 ≥ 0.7 且**两条都还在用**的成对），复盘卡与工具箱都给一个"合并"——`POST /v1/catalog/merge` 出一张 `policy_change` 卡，批了才合。日复盘不报（天天提醒同一对就是噪音）。
5. ⬜ **开源社区层**：市场（23，二阶段）上线后，目录页的"先查"扩到社区注册表——本公司没有，社区可能已有。

## 3. 任务撞车：一件事一个主人，认领即锁，先看再做

### 3.1 现状

工作模型（37）里待办有 `owner`，事项有 `participants`；会议产出的待办走认领卡；但**没有**"创建时检查是否已有人在做"，也没有"正在做"的总览，一件事完全可以被两个人各建一条。

### 3.2 做法

1. **撞车检测**：`POST /v1/todos` / 新建事项 / 认领时，服务端按三把钥匙找相似的**进行中**项：① 同一个主题对象（同订单 / 同客户 / 同会议 / 同店铺）② 语义键相似 ③ 同岗位同日。有命中 → 不直接建，回 `409 similar_in_progress` + 候选 → 界面出选择题：「李默正在做『核对昨天的退款单』（进行中，2 张卡等他定）：加入协作 / 交给他 / 我这个不一样，仍新建」。"仍新建"要写一句区别。
2. **认领即锁**：来自会议 / 计划 / 告警的任务先进**待认领池**，谁点"我来"谁是主人，其他人看到的立刻变成"李默已认领"；主人可以"转交"或"加协作者"。这就是 06 §2 认领管道的正式落地。
3. **看得见谁在做**：首页「今天」右栏加"正在进行"（本岗位 + 相关岗位的进行中事项，主人头像、开始时间、卡数）；公司页加"进行中"看板（按岗位分列，owner 视角）；事项页显示参与者与最近活动。WP33 的 WebSocket 已经推 `todo.* / matter.*` 摘要，界面实时变。
4. **分配任务时就防撞**：每日计划卡里 Agent 建议的任务先查撞车，撞的不建议；会议纪要抽出的待办若与已有进行中项相似，认领卡上直接写"可能与 X 重复"。
5. **闲置回收**：认领了 N 天没动静（无卡、无时间线）→ 提醒主人；再不动 → 回到待认领池，owner 收通知。

## 5. 自主决定（待 Luoye 审）

- E1 公司库是唯一真源；个人数据也在公司库，按敏感级隔离，管理员只有迁移 / 归档 / 销毁三动作、没有读
- E2 离职是正式动作，交接必须真转；个人层 overlay 默认归档只读而不是删
- E3 多人公司必须跑公司 Docker 档；个人电脑不存真源；Postgres 后置
- E4 "建之前先查"用选择题卡，选"仍新建"必须写理由 —— ✅ 已落地（理由 ≥ 8 字，进目录）
- E5 撞车检测放在创建路径上回 409 + 候选，不做事后提醒
- E6 认领即锁；闲置回收回池
