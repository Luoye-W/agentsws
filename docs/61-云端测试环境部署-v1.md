## 0. 一句话

**一台 2 核 4G 的小机器，三个容器，一条 DNS 记录，一份 `.env`。** 装完之后你的内测朋友在自己电脑上的 agentsws 里点一次「关联账号」，收一封信，就能用积分跑模型、查公共红人库、开在线值守。

这篇是**给非运维看的**。每一步都写了"为什么"与"没做对会怎样"，照着抄就行。不需要懂 Docker，但需要会用 SSH 登录一台服务器。

## 1. 先准备什么

### 1.1 一台服务器

| 项 | 要什么 | 为什么 |
|---|---|---|
| 配置 | **2 核 4G**，40G 以上硬盘 | 三个容器：云进程、New API、Caddy。值守（WP60）每开通一个工作区会再起一个 Node 子进程，内测阶段开不了几个，4G 够 |
| 地区 | **香港 / 新加坡** | 内测朋友多在国内，但云要打 DeepSeek / OpenAI 这些上游。境内机器出海不稳、境外机器国内访问慢，港新是折中。**不要选需要备案的境内机房**——域名没备案，80 端口会被拦 |
| 系统 | **Ubuntu 24.04 LTS** | 下面每条命令都是按它写的 |
| 防火墙 | **开 80 与 443**（TCP，另外 443 的 UDP 也开上，走 HTTP/3） | 80 不开的话 Let's Encrypt 签不了证书；只开 443 会卡在"一直申请不下来" |
| SSH | 开 22（或你改过的那个口） | 后面要用 SSH 隧道开 New API 的后台 |

> 别买"共享 vCPU 的最便宜那一档"。`better-sqlite3` 与值守子进程都吃 CPU，超卖机器上 `docker compose up -d --build` 那一步可能要跑半小时。

### 1.2 一个域名与一条 DNS 记录

域名已经有了（`agentsws.com`）。去域名商的 DNS 面板加**一条**记录：

| 类型 | 主机记录 | 值 | TTL |
|---|---|---|---|
| `A` | `cloud` | 你服务器的公网 IPv4 | 默认（10 分钟）就行 |

加完之后本机验一下（看到你那台机器的 IP 才算好了）：

```sh
dig +short cloud.agentsws.com
```

> **等它生效再往下走**。DNS 还没指过来就 `docker compose up`，Caddy 会去申请证书、失败、然后退避重试——Let's Encrypt 对失败次数有限制，连着撞几次会被锁一小时。

### 1.3 一个能发信的 SMTP 账号

云侧**唯一**的登录方式是 magic link（一封信里一条一次性链接）。发不出信 = 没人登得进来，所以这一步不能跳。

找一家 SMTP 服务商开个账号（阿里云邮件推送、腾讯云 SES、Resend、Postmark 都行），然后在**它的**后台里：

1. 把发信域名设成 `agentsws.com`；
2. 按它给的值，在域名商的 DNS 里加 **SPF** 与 **DKIM** 两条记录；
3. 拿到一串 SMTP 连接信息（主机、端口、用户名、口令）。

> SPF / DKIM 不配也能发出去，但十有八九进垃圾箱。内测朋友收不到信只会以为"这东西是坏的"。

## 2. 服务器上五步

全程用 SSH 登录那台机器操作。

### 第 ① 步 装 Docker

```sh
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker "$USER"
# 退出重新登录一次，让上面那行生效
exit
```

重新 SSH 上去，验一下：

```sh
docker version && docker compose version
```

### 第 ② 步 拉仓库

```sh
git clone https://github.com/Luoye-W/agentsws.git
cd agentsws
```

### 第 ③ 步 填 `.env`

```sh
cd deploy
cp .env.example .env
chmod 600 .env
nano .env
```

`.env.example` 里每一行都有注释说明。**必填的只有四项**：

| 变量 | 填什么 |
|---|---|
| `CLOUD_DOMAIN` | `cloud.agentsws.com`（样板里已经填好了，除非你用别的域名） |
| `ACME_EMAIL` | 一个你真会看的邮箱（证书快过期时 Let's Encrypt 往这里发提醒） |
| `AGENTSWS_CLOUD_SMTP_URL` | 第 1.3 步那家服务商给的连接串，形如 `smtps://用户名:口令@smtp.xxx.com:465`。**口令里有 `@ : / ?` 这些字符要先做 URL 编码** |
| `AGENTSWS_CLOUD_MAIL_FROM` | 发件地址，形如 `agentsws <no-reply@agentsws.com>`。要用配过 SPF 的那个域名 |

强烈建议再填这两项（不填也起得来）：

| 变量 | 填什么 | 不填会怎样 |
|---|---|---|
| `AGENTSWS_CLOUD_ADMIN_TOKEN` | `openssl rand -base64 48` 生成一串 | **发不了内测额度**（`/v1/admin/topup` 这条路由根本不挂） |
| `AGENTSWS_KOL_EMAIL_KEY` | `openssl rand -base64 32` 生成一串 | 公共红人库存不了红人的联系邮箱（其余功能照常）。**这把钥匙生成一次就别再改**——换了之后已经存进去的邮箱就解不出来了 |

`AGENTSWS_NEWAPI_KEY` 现在还拿不到（要先把 New API 起来），**先留空**，第 ④ 步回来补。

> **`.env` 不会进 git**（仓库的 `.gitignore` 挡着）。也别把它贴进任何聊天窗口。

### 第 ④ 步 起起来

```sh
cd ~/agentsws/deploy
docker compose up -d --build
```

第一次要编译整个 TypeScript 工程 + `better-sqlite3`，**十几分钟很正常**。跑完看一眼：

```sh
docker compose ps
```

四个服务（`caddy` / `cloud` / `newapi` / `backup`）都该是 `running`。哪个不是就看它的日志：

```sh
docker compose logs --tail 50 cloud
```

> 常见的两条：
> - `这是生产档（NODE_ENV=production）但没配 AGENTSWS_CLOUD_SMTP_URL` —— 第 ③ 步的 SMTP 没填。这是**故意**不让它起来的：没配 SMTP 的话登录链接会被打进容器日志，谁能看日志谁就能登进任何人的账号。实在想先起来看看，在 `.env` 里把 `AGENTSWS_CLOUD_ALLOW_CONSOLE_MAIL=1` 那行取消注释（配好 SMTP 后立刻删掉）。
> - `AGENTSWS_CLOUD_ADMIN_TOKEN 太短（至少 32 字节）` —— 别自己编一个短口令，用 `openssl rand -base64 48`。

### 第 ⑤ 步 冒烟

**从你自己的笔记本上**（不是服务器上）跑：

```sh
cd 你本地的 agentsws 仓库
./deploy/smoke.sh https://cloud.agentsws.com
```

它只用公开路由，不需要任何密钥。全绿就算装好了。

要连"信真的发得出去"一起验（最容易出问题的就是这一步）：

```sh
SMOKE_EMAIL=你自己的邮箱 ./deploy/smoke.sh https://cloud.agentsws.com
```

会真发一封信到那个地址。收到了就点开——应该看到一页"已登录"。收不到就先翻垃圾箱，再回头查 SPF / DKIM。

> 限流是**每邮箱 5 次 / 小时**，别连着跑六遍。

## 3. 装完之后长什么样

```
                 公网
                  │  443（HTTPS，Caddy 自动签证书）
            ┌─────▼─────┐
            │   caddy   │  ← 唯一对公网开的容器
            └─────┬─────┘
                  │ 内网
            ┌─────▼──────────────────────────┐
            │  cloud（apps/cloud，4400）      │  ← 一个端口都不发布
            │  账号 / 令牌 / 钱包 / 值守 / 红人库 │
            └─────┬───────────────┬──────────┘
                  │ 内网           │
            ┌─────▼─────┐   ┌─────▼─────┐
            │  newapi   │   │  /data 卷  │ ← cloud.sqlite / wallet.sqlite /
            │ 模型汇聚层 │   │           │   kol-public.sqlite / standby/ /
            └───────────┘   └─────┬─────┘   idempotency.sqlite
             ↑ 只绑 127.0.0.1:3000 │
             （SSH 隧道才进得去）   │ 每天
                            ┌──────▼──────┐
                            │   backup    │ → /data/backups
                            └─────────────┘
```

**一条要记住的纪律**：`cloud` 与 `newapi` 都不对公网开端口。云进程的限流按来源 IP 算，而那个 IP 是 Caddy 填进去的；哪天有人图省事把 4400 直接映射出去，限流当场就废了。

## 4. 给 New API 填上游模型 key

New API 是**模型汇聚层**（49 §1）：一把内部令牌 → 几十家模型、格式互转、渠道轮换。**它自己的用户体系与我们的账号是两套**（49 M6：不把它暴露给用户），所以它的后台不对公网开，只经 SSH 隧道进。

### 4.1 打开它的后台

**在你自己的笔记本上**开一个终端，让它一直挂着：

```sh
ssh -N -L 3000:127.0.0.1:3000 你的用户名@你服务器的IP
```

（`-N` 的意思是"只做转发，不开 shell"。这个窗口关掉隧道就断了。）

然后本机浏览器打开：**<http://127.0.0.1:3000>**

第一次进去用默认账号 `root` / `123456` 登录，**进去第一件事就是改口令**。

### 4.2 加一个上游渠道

在后台的「渠道」页 → 新建：

- 类型选 DeepSeek（或你要用的那家）；
- 密钥填**你在 DeepSeek 开放平台拿到的 API key**；
- 模型列表按它的提示填（`deepseek-chat` 之类）。

建完点一下「测试」，通了再往下。

> **这些上游 key 一个都不进我们的 `.env`**。它们只活在 New API 自己的库里（`newapi-data` 卷）。我们这边只拿一把它的内部令牌，见下一步。

### 4.3 拿一把内部令牌给云进程用

同一个后台 → 「令牌」页 → 新建一个，额度设成无限，复制那一串（形如 `sk-…`）。

回到服务器：

```sh
cd ~/agentsws/deploy
nano .env        # 把 AGENTSWS_NEWAPI_KEY= 后面补上刚才那一串
docker compose up -d cloud
```

验一下（`reachable` 应该是 `true`）：

```sh
curl -s https://cloud.agentsws.com/v1/cloud/health
```

隧道那个窗口现在可以关掉了。

## 5. 给内测朋友发积分

**测试环境不开 Stripe**（`.env` 里没给 Stripe 密钥时，充值接口回一句"还没接这个支付方式"的人话）。内测期的额度由你手动发。

### 5.1 让他先关联一次账号

他在自己电脑上的 agentsws 里：**设置 → 账号与积分 → 关联账号**，填自己的邮箱 → 收信 → 点链接。

这一步走完，云上才有他这个账号（与一个隐式建的组织，49 M1 / 52 O3）。**没走这一步，下面那条命令会回 404**。

### 5.2 发

在服务器上（`$ADMIN` 换成 `.env` 里 `AGENTSWS_CLOUD_ADMIN_TOKEN` 那一串）：

```sh
curl -s -X POST https://cloud.agentsws.com/v1/admin/topup \
  -H "Authorization: Bearer $ADMIN" \
  -H 'content-type: application/json' \
  -d '{"email":"朋友的邮箱@example.com","credits":200,"expires_in_days":90,"source_ref":"neice-001"}'
```

- **1 积分 = ¥1**（49 M4）。200 积分够跑很久的 DeepSeek。
- 发的是 **`granted`** 那一类积分：到期清零，不是"永不过期的钱"。默认 90 天。
- `source_ref` 是幂等键：**同一个串只入一次**。网络抖了重发一遍，不会变成第二笔。给每个人编一个（`neice-001`、`neice-002`…）。

回执里有 `org_id` 与 `expires_at`。他在自己的「设置 → 账号与积分」里当场就能看到余额。

> 这条命令会在 `docker compose logs cloud` 里留一行审计：组织、积分、到期、请求号。**令牌不会进日志，邮箱只留域名。**

### 5.3 想给整个组织发而不是按邮箱

把 `"email"` 换成 `"org_id"` 就行（`org_id` 从上一次的回执里抄）。

## 6. 日常维护

### 6.1 看状态

```sh
cd ~/agentsws/deploy
docker compose ps                     # 谁活着
docker compose logs --tail 100 cloud  # 云进程在说什么
curl -s https://cloud.agentsws.com/v1/cloud/health
```

`health` 回的是：版本、各模块挂没挂上、New API 通不通。**它不回任何密钥，也不回任何内网地址**，所以贴出来给人看是安全的。

### 6.2 备份

`backup` 容器每 24 小时跑一次，用 `sqlite3 .backup`（不是 `cp` —— 库开着 WAL，直接拷文件可能拷到一个缺半条事务的快照）。产物在卷里的 `/data/backups`，默认留 14 天（`.env` 里 `BACKUP_KEEP_DAYS` 可改）。

想立刻跑一次：

```sh
docker compose exec backup sh /backup.sh
```

**把备份取到服务器之外**（卷和服务器是同生共死的）：

```sh
docker compose cp backup:/data/backups ./backups-$(date +%F)
# 然后 scp / rclone 到别处
```

> 备份**没有加密**。里面有账号邮箱与账本。要往外放就在外面那一层加密（`age` / `rclone crypt`），别在服务器上明文同步到公开的地方。

### 6.3 升级

```sh
cd ~/agentsws
git pull
cd deploy
docker compose up -d --build
```

**库迁移在进程启动时自动跑**，不用手动执行任何 SQL。

升级前先备份一次（`docker compose exec backup sh /backup.sh`）——这是唯一的后悔药。

### 6.4 回滚

```sh
cd ~/agentsws
git log --oneline -10        # 找到上一个好的提交
git checkout <那个提交的哈希>
cd deploy
docker compose up -d --build
```

**注意**：代码能回滚，**库迁移回不去**。如果那一版之后加过表或列，旧代码读新库多半还能跑（我们只加不删），但反过来不成立。真的回不去时，用备份恢复：

```sh
docker compose stop cloud
docker compose cp ./你的备份/cloud-2026….sqlite cloud:/data/cloud.sqlite
docker compose start cloud
```

### 6.5 换域名 / 换服务器

- 换域名：改 `.env` 里的 `CLOUD_DOMAIN`，改 DNS，`docker compose up -d`。Caddy 会自己去签新证书。**同时要改代码里的默认地址**（`packages/contracts/src/cloud.ts` 的 `DEFAULT_CLOUD_BASE_URL`，全仓只有那一处），否则没配环境变量的本地端还会指向老域名。
- 换服务器：把四个卷（`cloud-data` / `newapi-data` / `caddy-data` / `caddy-config`）整个搬过去，或者用备份重建。搬之前先把 DNS 的 TTL 调短。

## 7. 这一版**没做**的（上真人之前要知道）

| 没做 | 后果 | 什么时候要做 |
|---|---|---|
| **多实例** | `sweepReservations` 与那个每 10 分钟的进程内定时没有分布式锁；两个实例的钟不一样会互相把对方正在进行中的预扣扫掉 | 一台机器扛不住的时候。先给定时加一把锁（Redis / Postgres advisory lock），再谈水平扩 |
| **Stripe** | 用户自己充不了值，额度只能手动发（§5） | 内测转公测时 |
| **微信 / 支付宝** | 同上，接口现在回一句人话不是 500 | 同上 |
| **`/v1/ai/*` 的幂等** | 那条路是流式的，缓进幂等表等于把"流式"变成"假流式"。它自己有预扣 → 结算那一套幂等语义，所以不是裸着 | 有人真的因为重试被重复计费时 |
| **监控与告警** | 服务挂了没人主动告诉你，只能自己跑 `smoke.sh` | 有真实用户依赖它的时候。最省事的是挂一个外部拨测服务打 `/v1/cloud/health` |
| **备份异地** | 备份和服务器同生共死 | 现在就该做（§6.2 最后那一段） |
| **New API 后台的强口令与 2FA** | 默认口令 `123456` 不改的话，谁能建 SSH 隧道谁就能拿走全部上游 key | 第 ④ 步进去的第一件事 |
| **值守的资源上限** | 每开通一个工作区起一个 Node 子进程，没有 cgroup 限额；开多了会把机器吃满 | 内测超过几个人用值守时 |

## 8. 出问题先看哪儿

| 现象 | 多半是 | 怎么查 |
|---|---|---|
| 浏览器打不开 `https://cloud.agentsws.com` | DNS 没生效，或 80 / 443 没开 | `dig +short cloud.agentsws.com`；`docker compose logs caddy` 里会说证书申请失败 |
| 证书一直签不下来 | 80 端口被防火墙 / 安全组拦了 | 云厂商的安全组里放行 80 与 443 |
| `cloud` 容器起不来 | `.env` 少了必填项 | `docker compose logs --tail 30 cloud`，第一行就写着少了哪个 |
| 收不到登录信 | SPF / DKIM 没配，或 SMTP 连接串写错 | `docker compose logs cloud` 里有 `[cloud-mail] 投递失败 to=<域名>` 那一行；再去 SMTP 服务商后台看发信记录 |
| `health` 里 `newapi.reachable: false` | New API 没起来或还在初始化 | `docker compose logs --tail 50 newapi` |
| 模型调用回 402 | 那个组织的积分不够 | 按 §5 给他发一点 |
| magic-link 回 429 | 限流（每邮箱 5 次 / 小时、每 IP 20 次 / 小时） | 等一小时，或换个邮箱试 |
| `/v1/admin/topup` 回 404 | `.env` 里没配 `AGENTSWS_CLOUD_ADMIN_TOKEN`，这条路由根本没挂 | 填上，`docker compose up -d cloud` |

## 9. 相关文件

| 文件 | 是什么 |
|---|---|
| `deploy/docker-compose.yml` | 三个容器 + 备份 sidecar 的编排。文件头写了端口纪律与"不做什么" |
| `deploy/Dockerfile.cloud` | 云镜像（多阶段，`better-sqlite3` 在镜像里编） |
| `deploy/Caddyfile` | 反代 + 自动 HTTPS + 安全头 + 流式不缓冲 |
| `deploy/.env.example` | 全是空值与注释的样板。**真 `.env` 只活在服务器上** |
| `deploy/backup.sh` | 每日 `sqlite3 .backup` |
| `deploy/smoke.sh` | 冒烟检查（只用公开路由，从本机跑） |
| `deploy/nas/` | **另一件事**：本地服务进程的 NAS 部署（40 §1.3），与云侧无关 |
