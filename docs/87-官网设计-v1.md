## 0. 一句话

**官网就是一张「岗位 + 出卡审批 + 本地优先」的说明书，按 KOLAgents 那套「先亮产品、再讲链路、再表立场、最后给价钱」的顺序讲，但字数砍到它的三分之一。**
首页 10 屏，价格、下载各一页；视觉给两个方向：A「纸与绿」（和工作台一个样子），B「夜航」（深色为主、编辑排版、大号动态标记当主图）。我推荐 A 做正式站、B 的首屏主图思路并进 A（§5.3）。

**学到的三件事**

1. **叙事顺序**：产品长什么样（首屏示意）→ 它怎么干活（链路）→ 我们的立场（不做什么）→ 和别人比 → 技术底座 → 价钱 → 答疑 → 再给一次按钮。这个顺序我们原样用。
2. **每屏都有一张「看得见的东西」**：示意卡、表、终端。我们的稿每屏至少一个可见物（截图、卡、表、终端、标记）。
3. **按钮永远成对**：一个要钱（或要下载）、一个不要（看 GitHub / 看教程）。

**不学的**：KOLAgents 首页一屏常有 3–5 段话（它的受众要被说服「为什么需要红人营销」）。Luoye 定过**界面少字**（docs/36 §7），官网同样适用：**每屏一个标题 + 一句副标题 + 可见物**，长的解释进教程文章，短的进问号（稿里的 `?` 悬停提示就是这一条）。

**几处刻意的措辞**

- 「AI 同事」而不是「Agent」「智能体」：用户是非开发者（`_common.md`）；「Agent」只出现在底座那屏。

- 下载页的「没签名」提示压成一行 + 问号（docs/36 §7 的安全承诺规矩：必须可见，但压到一句）。

## 5. 两个视觉方向

两个方向**同内容、同令牌、同标记**，只换视觉语言。令牌全部来自 docs/36 §1.1（`--ws-paper / card / line / ink / brand / tint / good / warn / info …`，明暗两套一个值没改），卡的阴影、选中光晕、圆角 16 也照原样。

### 5.1 方向 A「纸与绿」（`home.html`）

- **像工作台本身**：纸色底 `#F3F5F2`、白卡、两层浅阴影、品牌绿 `#007B67`；深色照 Linear 克制版，霓虹绿 `#76FB91` 只上按钮与强调。
- **产品真截图当首屏主图**，左下压一张浮起来的「客服 · 回信」待批卡（选中光晕），3 秒讲清「它会给我出卡」。
- 岗位是十张小卡网格；出卡审批是一条五步横轨 + 三张真实形状的卡（客服回信 / 红人开发信 / B2B 报价超授权）；底座一屏整块深色 + 终端。
- 优点：和装上之后看到的东西一模一样，零「货不对板」；亲和、适合非开发者。缺点：安静，第一眼不够「酷」。

### 5.2 方向 B「夜航」（`home-b.html`）

- **深色为主设计**（没有系统偏好时默认深色；也跟随系统出浅色）；背景一层 64px 细线网格。
- **编辑排版**：每节左栏一个大号淡色编号（01–08）+ 等宽小标签，右栏正文；分节之间一条细线，几乎不用阴影。
- **首屏主图是 360px 的动态标记**：先「集结」，停住后进入待机；标题 84px。岗位做成两栏列表行（悬停箭头变绿）；出卡审批左边编号步骤、右边三张叠放的卡（最上面一张带光晕）；「别处 vs 这里」做成左右两栏、左栏价格划线。
- 优点：有辨识度、开发者与 build-in-public 的气质强，截图发朋友圈好看。缺点：离工作台的样子远一点；深色大面积对部分非技术用户显得「硬」。

### 5.3 我的推荐

**正式站用 A**：目标用户是非开发者，官网和产品一个样子最省解释。**把 B 的两样并进 A**：① 首屏左上加动态标记（A 稿已加 56px 的「集结 + 待机」）；② 「底座」那一屏用 B 的编辑排版（编号 + 细线），让开发者那一屏有点不一样。Luoye 要是更喜欢 B，价格页、下载页照 B 重画一遍即可（结构不变，约半天）。

## 6. 品牌标记动效在官网上怎么用（Luoye 09-29 追加）

参数**照抄** `apps/workstation/src/index.css` 的 `ws-bm-*` 与 `packages/brand`（母品牌规范 §3.2 / §3.3），一个没改：

| 位置 | 姿态 | 参数 |
|---|---|---|
| 页头 logo（26 / 24px） | 进场播一次「集结」，停住后待机 | 五块延迟 0 / 100 / 160 / 240 / 300ms，1.2s `cubic-bezier(.22,1,.36,1)`；领头 380ms 起、0.9s 回弹 `cubic-bezier(.34,1.56,.64,1)` |
| 首屏主视觉（A 56px / B 360px） | 同上：集结 → 待机 | 同上 |
| 岗位一屏（「一个人变一队」） | 「一变一队」，**滚到眼前才播一次** | 领头 0.5s 先出现；其余五块从领头位置分出去，300ms 起每块隔 100ms，0.55s |
| 收尾、页脚 | 静态 | 「就是这个牌子」 |

- 动效时**每块自己一条渐变**（`objectBoundingBox`，12 个起止色照 `--ws-brand-mark-b*-from/to` 明暗两套）；静态时一条整体渐变。`transform-box: fill-box` + `transform-origin: center`。
- **系统开了「减少动态效果」一律静态**（CSS 双保险，已用 Playwright 的 `reducedMotion: 'reduce'` 核过：六块不透明度全是 1）。
- **待机动效是官网暂用的**：集结停住后，六块沿渐变方向依次微微一暗（只动透明度 1 → 0.62 → 1，5.2s 一轮，块间隔 180ms），像一队人依次报到。刻意**不用「呼吸」**——docs/36 §12.2 定了呼吸只代表「Agent 正在替你干活」。**WP195 定了工作台的常驻待机动效之后，官网换成同一个**（§8 第 4 条）。
- 页头与首屏两个标记同时在待机，首屏滚走之后只剩页头那个在动。

## 7. 技术选型建议

### 7.1 放哪个仓：**开源仓 `apps/site`**

- 官网文案、教程、截图本来就在开源仓（`docs/help`、`docs/assets`），放一起「改教程 = 改官网」，不用两边同步；build in public 也要求官网本身是公开的。
- 官网只是静态页：**不含**价格数据（运行时读云上公开价目）、不含支付代码、不 import 任何云端包——落进 `scripts/open-repo-boundary.test.mjs` 的开源这一侧（到时把 `site` 加进 `OPEN_APPS`）。
- 不放私有仓 `agentsws-cloud` 的理由：那边是收钱的服务，官网改一个错字不该要进私有仓的门禁。

### 7.2 框架：**Astro + Starlight（文档区）**

| 选项 | 结论 | 理由 |
|---|---|---|
| **Astro**（MIT）+ **Starlight**（MIT） | **推荐** | 纯静态出 HTML，默认零 JS；内建 i18n 路由（`/` 中文、`/en/` 英文）；Starlight 直接吃 Markdown 做文档区、自带搜索（Pagefind，本地索引，不用第三方服务）；动效与明暗照稿子写 CSS 就行 |
| Next.js（KOLAgents 用的） | 不选 | 官网不需要 SSR；更要紧的是 KOLAgents 那套是 MkSaaS 模板，照着搭很容易把模板的结构与组件带进开源仓 |
| Vite + React（和工作台同栈） | 备选 | 能共用组件，但要自己做路由、i18n、SEO、文档区，官网得不偿失 |
| VitePress | 备选 | 文档很好，营销页写起来别扭 |

新依赖（astro、@astrojs/starlight）进仓前按 docs/42 走一遍上游评估、登记 `upstreams.yml`。

### 7.3 部署：**Cloudflare**（Workers 静态资源）

- 我们的域名、邮件、云端全在 Cloudflare（docs/35 09-24 起）；静态站走 Workers Static Assets（或 Pages），不花钱、全球缓存。
- 构建：GitHub Actions 在 `main` 上 `pnpm --filter site build` → `wrangler deploy`（部署由 Fable 做，照 09-29 的部署授权）。
- 统计：Cloudflare Web Analytics（不用 cookie、不弹同意框）。

### 7.4 与 `cloud.agentsws.com` 的衔接

| 动作 | 现状 | 建议 |
|---|---|---|
| 登录 | 云上有 `/login` 落地页（magic link，WP110），**没有网页版「账号与积分」**，余额 / 充值 / 用量都在工作台里 | 首版：官网「登录」直接跳 `cloud.agentsws.com/login`，登录后落一个**极简网页账号页**（余额、充值四档、用量三块）——这一页要在私有仓新做（§8 第 6 条）。不做的话官网「充值」只能写「在工作台 → 账号与积分里充」 |
| 充值 | 收款已照 KOLAgents 接了 Waffo / Creem / Stripe（私有仓 WP190），入口在工作台 | 官网四档按钮 → 登录 → 收银台 → 回到账号页；**官网本身不碰支付**，也不点名支付商 |
| 价目表 | 云上公开只读 `GET /v1/pricing`（WP165，不要令牌、缓存 5 分钟） | 构建时取一份做静态兜底，页面加载时再取一次最新的；取不到显示「价目暂时拿不到」，**不编数** |
| 注册赠送 | 10 积分，点开登录信那一刻到账（WP121） | 价格页写明，数字从同一份配置来（`bonuses.json` 在私有仓，官网只照抄现数） |

### 7.5 文档区怎么复用 `docs/help`

- **原文件不挪**：`docs/help/<slug>.md`（中文）与 `<slug>.en.md`（英文）继续是唯一真源，工作台右栏「教程」和官网 `/docs/<slug>` 读同一份。
- 构建时由一个小加载器把 22 篇收进 Starlight，按 `apps/workstation/src/lib/help.ts` 的 `HELP_SLUGS` 排目录（加一篇只在那一处加）。
- 三类链接要改写：`help:<slug>` → `/docs/<slug>`；工作台站内路径（如 `/settings/credits`）→ 改成一句「在工作台 → 设置 → 账号与积分」；外链原样。改写规则写成测试，和工作台的 `SafeMarkdown` 同一套白名单（不插 HTML、不加载图片）。
- 教程里提到「演示数据」「本机 127.0.0.1」的地方不用改——官网读者本来就是要装的人。

### 7.6 其余

- **下载链接**：构建时查 GitHub Releases 最新版拼出三个文件名；首屏按钮按访客系统（UA）选默认那一个。
- **更新日志**：取 `CHANGELOG.md` 与 Releases，**不取 docs/35**（那是派工记录，太内部）。首页「公开地做」取最新三条。
- **SEO**：每页 `title` / `description` 中英各一套、`hreflang`、站点地图、Open Graph 图（静态标记 + 标题，构建时生成）。
- **官网不收任何表单**：没有「留邮箱」「预约演示」；联系方式走邮箱与 GitHub Issues。

## 9. 我自主决定的（白话）

- 首页不做「产品里面」那种多 tab 大示意：放到每个岗位的子页，首页保持 10 屏。
- 首屏标题不用对立式（「别人给你 X，我们给你 Y」）：我们的对手不是一个品类，是「没人手」。
- 「立场」一屏讲**永远人审**，不照搬 KOLAgents 的「采纳率到阈值就全自动」刻度盘——那和我们的安全承诺相反。
- 价格页里所有单价都是灰条，只写已经公开的数字；稿里留了一行虚线框的「设计注」说明这件事（上线时删掉）。
- 首页「公开地做」用 09-27 / 09-29 三条真实更新；上线时改成自动取最新三条。
- 价格页、下载页先按 A 画（A 是推荐方向）；B 被选中再重画。
- 下载页的系统要求只写芯片 / 位数（Apple 芯片、Intel、64 位 Windows），没写最低系统版本——这个要等打包那边核实。
- 下载页的截图只有浅色一张（初始化「选岗位」），深色模式下也用它；正式站可以补一张深色截图。
