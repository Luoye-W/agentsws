## 1. 流程定义与实例

```ts
type WorkflowDef = { id; version; name; role_id; trigger: { event: string } | { manual: true } | { schedule: Cron }; steps: Step[]; compensation?: Record<step_id, Step>; sla?: { total_days } }
type Step = { id; kind: 'run' | 'approval' | 'wait_event' | 'sleep' | 'action' | 'branch' | 'human_task'; params; retry?: { max; backoff }; on_fail?: 'retry' | 'compensate' | 'escalate' | 'skip' }
type WorkflowInstance = { id; def: {id, version}; workspace_id; role_id; subject: ObjectRef; conversation_id?; state: 'running' | 'waiting' | 'paused' | 'done' | 'failed' | 'compensated'; cursor: step_id; history: StepRecord[]; started_at; due_at? }
```

步骤语义：`run` = 发 RunRequest 等 RunResult；`approval` = 建审批项等决定；`wait_event` = 等入站 / 系统事件（签收、付款）带超时；`sleep` = 等时长（天级，不占进程）；`action` = 执行器 apply 已批变更；`branch` = 按上一步结果分流；`human_task` = 队列里一条待办。失败按 `on_fail`，`compensate` 执行补偿步（重寄、撤回通知）。

首批流程定义（包里提供）：红人合作（寄样 → 签收 → 发布 → 检查 → 结算 → 回访）、订单里程碑（PI → 定金 → 生产 → 验货 → 发运 → 清关 → 尾款）、邮件序列（Day0 / 2 / 5 / 8 / 12，任一回复即停）、Join 迁移、应用升级（沙盒 → 审批 → 施行 → 回滚）。

## 2. 引擎契约

```ts
interface WorkflowEngine { start(def, subject, ctx): instance_id; signal(instance_id, event); pause / resume / cancel(instance_id); status(instance_id); list(filter) }
```
默认实现 Inngest 自托管（步骤 = `step.run`，`sleep` = `step.sleep`，`wait_event` = `step.waitForEvent`）；替身 = 内存引擎 + 合成时钟；契约不暴露 Inngest 类型。

## 3. 定时任务（ScheduledTask，13 §1.3 定稿）

- 一等对象，字段见 13；`created_by: agent` 且 action 会写 / 会发 → `scheduled_task` 审批项；只读 / 提醒类直接 active 并在对话里出卡
- 触发 → 调度 #13 发 `schedule.fired` 事件 → 按 `context_policy` 生成 RunRequest（`resume_conversation` 带 conversation_id，`fresh_with_summary` 带 summary ContextItem）
- 可见：对话内"本对话的定时"、职责工作面"定时"面板、owner 全局视图；操作：暂停 / 改时间 / 删除 / 立即运行 / 看历史
- 归档对话 → 提示停掉其定时；撤销职责 → 随交接（05 handover.scheduled_tasks）
- 错过触发（机器关机）：`misfire_policy: 'run_once_now' | 'skip'`，默认 run_once_now 且记事件

## 4. 调度（#13）

```ts
interface Scheduler { schedule(task): id; cancel(id); next(id); now(): Clock }
```
持久（SQLite 表），重启不丢；精度分钟；tz 按任务；时钟可替换（合成时钟快进）。dsh 自带 schedule 包不用。

## 5. API

`POST /workflows/{def}/start`、`POST /workflows/instances/{id}/signal|pause|resume|cancel`、`GET /workflows/instances?subject=&state=`、`POST /scheduled-tasks`、`GET /scheduled-tasks?conversation=&role=&owner=`、`PATCH /scheduled-tasks/{id}`、`POST /scheduled-tasks/{id}/run-now`。事件：`workflow.started / step.completed / waiting / failed / compensated / done`、`schedule.created / fired / misfired / paused / deleted`。

## 6. 一致性用例

1. 邮件序列第 3 天客户回信 → 实例 waiting→done，后续步骤不再发
2. 进程重启后 sleep 5 天的实例按原时间继续
3. `wait_event` 超时 → 走 on_fail=escalate 生成 human_task
4. Agent 创建"每天 9 点发日报"（只读）→ 直接 active + 对话卡；创建"每周一给客户发跟进"（会发）→ 审批项
5. 合成时钟快进 30 天 → 红人流程全部步骤按序发生，事件时间戳单调
6. 关机错过触发 → 开机后立即补跑一次并记 misfired
7. 对话归档提示含其定时任务数
