## 1. 仓库拓扑

| 仓库 | 内容 | 许可证 |
|---|---|---|
| `Luoye-W/agentsws` | 平台 monorepo（本仓） | Apache-2.0 |
| `Luoye-W/deepseek-harness`（fork 改名） | 上游镜像：提 PR、补丁、bisect | MIT（上游） |
| `Luoye-W/dsh-channels`、`Luoye-W/open-connector`（fork） | 贡献上游的干净分支；本仓 `vendor/` 以子树引用 | 上游许可证 |
| `agentsws-apps`（后拆） | 社区职责包 / 技能 / 模板；起步阶段在本仓 `role-packs/` | Apache-2.0 |

| 私有仓 | 托管 Connect（OAuth 应用、运维）、钱包计费、托管配置 | — |
| `KefuAgent`、`KOLAgents` | 不动；依赖 npm `@agentsws/*` 共享包 | — |

npm scope：`@agentsws`（需注册 npm org）。

## 2. monorepo 布局（目标）

```
agentsws/
  package.json · pnpm-workspace.yaml · tsconfig.base.json · biome.json · vitest.workspace.ts
  packages/
    contracts/        18 份契约：类型、事件、错误码、一致性套件（纯 TS，无实现）
    core/             框架无关纯规则：fencing、gates、guardrail、账本类型（Commerce Agents 移植）
    kernel/           @deepseek-ai/cordis 容器、模块清单与签名、事件日志、config、halt、trace
    txn/              交易控制模块（审批 #3 + 账本 #4 + 执行器 #5，一个事务边界）
    channels/         入站 #9 + 投递 #14（dsh-channels 契约）
    connect-adapter/  OpenConnector 封装（唯一 import 其 SDK 处）
    dsh-adapter/      dsh SDK 封装（唯一 import dsh 处）
    runtime-direct/   direct-llm 运行时
    model-gateway/    #7
    knowledge/        #10（v1 只检索）
    identity/         #1（v1 local）
    roles/            #2 职责与分配、Casbin 策略编译
    packages-local/   #11 本地包管理（package.yml、安装、叠加）
    blocks/           #15 积木注册表与命名查询
    stand-ins/        全部替身：mock OpenConnector、stub / replay 模型、合成人、合成时钟、收件箱、假 registry、假编码执行器
    simulation/       场景 DSL、synth 生成器、runner、报告
    api/              API 网关：HTTP / WS / OpenAPI / 鉴权 / 幂等
  apps/
    server/           协同服务进程（装配全部模块）
    workstation/      Web 工作台
    desktop/          Electron 托盘壳
    cli/              agentsws CLI（init / doctor / simulate / synth / test）
  role-packs/         官方应用：dtc-customer-care …（package.yml + roles + skills + scenarios）
  skills/             共享 skill（Agent Skills 格式）
  profiles/agentsws/  dsh profile（bundles 版本锁定、cordis.patch.yml）
  vendor/             dsh-channels、providers-contrib（子树）
  packs/              合成公司数据集
  docs/
```

## 3. 工具链

- Node **≥ 22**（`engines`；OpenConnector 与 Electron 44 的要求），pnpm 11 workspaces
- TypeScript 5，`tsconfig.base.json` + 各包 project references；ESM
- 测试 vitest；lint / format biome（三个 SaaS 已在用）
- 每包 100% 行覆盖（沿 dsh 纪律；先对 `contracts` `core` `kernel` `txn` 强制）
- 提交 `-s`（DCO）；conventional commits

## 4. 1a 的实施顺序（框架骨架）

1. 根配置 + `contracts`：把 14–29 的类型逐份落成 `.ts`（先 #3 #4 #5 #6 #16 与事件）
2. `core`：移植 fencing、gates、guardrail 评估、账本类型，带 Commerce Agents 的测试用例
3. `kernel`：Cordis 容器装配、模块清单、事件日志（SQLite）、halt
4. `stand-ins`：mock OpenConnector、stub 模型、合成人、合成时钟、收件箱
5. `txn`：审批 + 账本 + 执行器（含 31 §3 快照、预占、unknown、关系授权）
6. `simulation`：场景 DSL、synth、runner；跑通 26 §1 的"退货窗口内"场景（全替身）
7. `api` + `apps/server`：把上述装配成一个进程，`/v1` 可调
→ 1a 完成标准：`pnpm simulate --tier fast` 全绿，事件日志能重组 prompt
