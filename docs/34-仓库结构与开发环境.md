### 2.1 与原规划的四处出入（2026-09-10 WP26 核实后改正）

原表里有四个包目录始终只有一份 README，没有 `package.json`、没有实现。逐个核实后：

| 原目录 | 处置 | 实际在哪 |
|---|---|---|
| `identity/`（#1） | **删除** | 本地 magic-link 身份在 `packages/api/src/identity.ts` 与 `sqlite-identity.ts`；契约在 `contracts/src/identity.ts`。多人邀请与 Join 仍未做（38 §1） |
| `blocks/`（#15） | **删除** | 积木注册表、命名查询、数字块在 `packages/deck`（`src/sources.ts`、`src/types.ts`）；契约在 `contracts/src/blocks.ts` |
| `dsh-plugins/` | **删除** | 它列的四件东西：approval-answerer 与 presenters 已经在 `packages/dsh-adapter/src/gate.ts`（五个 seam）与 `packages/deck` 里；sync-client（个人端同步）随同步引擎选型延后到 v2（32）；cloud-brain-llm-adapter 属商业化，32 §5 全部后置。它本来也不是 18 份契约之一 |
| `packages-local/`（#11） | **保留占位** | 契约有、实现无（38 §1）。目录里留一份 README 写明「占位，二阶段实现，契约在 `contracts/src/packages.ts`」 |

四个目录都没有 `package.json`，因此本来就不在 pnpm workspace（`packages/*` 只收有
`package.json` 的目录）、也不在根 `tsconfig.json` 的 references 里——删除与保留都不需要
改根配置。

## 3. 工具链

- Node **≥ 22**（`engines`；OpenConnector 与 Electron 44 的要求），pnpm 11 workspaces
- TypeScript 5，`tsconfig.base.json` + 各包 project references；ESM
- 测试 vitest；lint / format biome（三个 SaaS 已在用）
- 每包 100% 行覆盖（沿 dsh 纪律；先对 `contracts` `core` `kernel` `txn` 强制）
- 提交 `-s`（DCO）；conventional commits
- CI：`.github/workflows/ci.yml`，ubuntu + macOS 两个矩阵、Node 22 / pnpm 11，顺序
  `pnpm install --frozen-lockfile` → `tsc -b --force` → `biome check .` → `vitest run --coverage`
  → `simulate --tier fast`（合并门禁，任一步非 0 即红）。覆盖率与模拟报告作为 artifact 上传；
  桌面壳只做 tsc 与单元测试，不 electron-builder 打包（`ELECTRON_SKIP_BINARY_DOWNLOAD=1`）
- `.github/workflows/dco.yml`：PR 里每个非合并提交都要有 `Signed-off-by`
- 面向外部的英文入口：`README.md`（中文为主 + 英文摘要）、`docs/ARCHITECTURE.md`、
  `SECURITY.md`、`CODE_OF_CONDUCT.md`、issue / PR 模板；`docs/README.md` 是 38 份中文文档的索引
- 发版：`scripts/release.sh`（版本号 → CHANGELOG → tag），`CHANGELOG.md` 按 35 §4 的合并记录归纳

## 4. 1a 的实施顺序（框架骨架）

1. 根配置 + `contracts`：把 14–29 的类型逐份落成 `.ts`（先 #3 #4 #5 #6 #16 与事件）
2. `core`：移植 fencing、gates、guardrail 评估、账本类型，带 Commerce Agents 的测试用例
3. `kernel`：Cordis 容器装配、模块清单、事件日志（SQLite）、halt
4. `stand-ins`：mock OpenConnector、stub 模型、合成人、合成时钟、收件箱
5. `txn`：审批 + 账本 + 执行器（含 31 §3 快照、预占、unknown、关系授权）
6. `simulation`：场景 DSL、synth、runner；跑通 26 §1 的"退货窗口内"场景（全替身）
7. `api` + `apps/server`：把上述装配成一个进程，`/v1` 可调
→ 1a 完成标准：`pnpm simulate --tier fast` 全绿，事件日志能重组 prompt
