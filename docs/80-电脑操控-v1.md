# 80 · 电脑操控 v1（WP144，2026-09-24）

> Luoye 09-24 定：电脑操控「先加进来，和官方一起同步更新」。
> Fable 定形态：用官方 **MCP 提供方**（驱动是独立进程），不用 native；驱动钉版本 + sha256 下载。
> 这份文件写形态、三层开关、门禁、隐私、与浏览器两条腿的关系、平台差异，以及实现时实测到的几件事。

## 0. 一句话

有些活只能在电脑上的某个应用里干（只有桌面版的软件、系统对话框）。我们挂官方
`@deepseek-ai/dsh-computer-use` + `@deepseek-ai/dsh-experimental-computer-use-cua-driver-mcp`，
驱动是开源的 Cua Driver（trycua/cua 的 `libs/cua-driver`，MIT）。**默认关、按职责开、每次运行先授权**，
只在装在用户自己电脑上的 Agents 工坊（本机档）里有。

## 1. 形态：为什么是 MCP 提供方，为什么是 `--direct`

| 选择 | 做法 | 理由 |
|---|---|---|
| 提供方 | **MCP 那一种**（`cua-driver mcp` 是独立进程，官方经 `dsh-mcp-client` 把它报的工具原样挂成 `mcp__cua-driver-mcp__<tool>`） | native 那一种在我们的服务进程里跑原生模块，上游原话「原生崩溃可能终止该进程」；而且它经 npm 可选依赖拉平台二进制，我们的依赖树不要它 |
| 驱动来源 | 我们钉版本 + sha256 从上游 GitHub Release 下载，装在数据目录（`AGENTSWS_DATA_DIR/computer-use/cua-driver-<版本>/`），**不进 PATH、不用上游 `install.sh` / `install.ps1`**、不打进安装包 | 照 WP92 的 `browserskill.lock.json`；上游脚本装 `CuaDriver.app` 到 `/Applications`、改 PATH，驱动自带的 `update --apply` 就是再跑一次它 |
| 版本 | `cua-driver-rs-v0.28.0`（dsh 0.1.7-rc.1 提供方 README 链接的那一版；native 提供方也精确钉 `@trycua/cua-driver 0.28.0`） | 上游 `cua-driver-rs-v*` 在 GitHub 上一律标 prerelease——那是常态，不是 nightly（nightly 另有 `nightly-cua-driver-rs-v*`） |
| 包 | 只用扁平的 `*-binary` 包（macOS 是 universal，arm64 / x64 同一个） | 不要装 `.app` 的那种；sha256 逐字抄上游 `checksums.txt`（`computer-use.lock.json`） |
| 启动参数 | macOS `mcp --direct`；Windows / Linux `mcp` | 见下 |

**`--direct` 是这一版最要紧的一个决定**（上游 README「macOS process identity and permissions」）：
macOS 把「辅助功能」「屏幕录制」记在**负责的那个应用**身上，不是记在某个可执行文件路径上。

- 不加 `--direct`：`cua-driver mcp` 在 macOS 上会经 LaunchServices 去起 `/Applications/CuaDriver.app` 的常驻进程并把请求转过去——要装那个 `.app`（系统目录），它也不随我们的运行退出（「点停止 = 驱动断开」就做不到）；
- 加 `--direct`：驱动进程自己跑，权限记在**启动它的那个应用**上——桌面版「Agents 工坊」（驱动由服务进程 spawn，服务进程由桌面壳 spawn，都在它的责任链里）。运行一结束、stdin 一关它就退出。上游原话：「In `cua-driver mcp --direct`, the embedding host owns permission UX」。

代价写在明处：权限给的是整个「Agents 工坊」（不只是驱动）；`--direct` 下没有驱动那个 AppKit 光标覆盖层。
另一种（给 `CuaDriver.app` 权限、我们只当客户端）列给 Luoye 定（报告「需要 Luoye 定的事」）。

## 2. 挂在哪（`packages/dsh-adapter`）

与浏览器同一位置同一顺序：**mount → installGate → 浏览器 → 电脑操控**（`harness.ts` 的 `setup`）。

- `RunRequest.computer_use` 不在 → 什么都不挂，连「请求操作电脑」那个工具都没有；
- 在、但没有 `granted_until`（或已过期）→ **提供方不挂**、`computerUse` 服务不挂、驱动一个进程都不起；模型只看得见我们自己的 `request_computer_use`；
- 在、而且 `granted_until` 没过 → `root.plugin(dsh-computer-use)` + `agentCtx.plugin(cua-driver-mcp, { command: <数据目录里的驱动>, args, toolCallTimeoutMs: 60000, reconnect: { enabled: false } })`，再加一个 `computer_handoff`。

**装好了才挂**（WP92 那条坑的同一条纪律）：驱动路径不在 / 不可执行时 `harness` 在挂之前就让这次运行失败；
服务端 `forRun()` 更早一步，没装根本不给 `computer_use`。实测：路径指错、或驱动起来就退（不讲 MCP），
官方提供方都是「激活失败、回滚」，**不会**像 BrowserSkill 插件那样把信号打到我们自己的进程组上。

两档运行时（进程内 / 子进程）都挂得上：子进程档多一条宿主回调 `agentsws/host/computer-use`（出卡）。
完整 profile（`dsh --profile agentsws`）走 docs/42 红线 7 的路线 (b)：`profiles/agentsws/cordis.patch.yml`
**插进**这两行并写死 `disabled: true`，选了才叠 `computer-use.on.patch.yml`；`profile-lockdown.test.ts`
按 `--dump-config-schema` 校验两个 id 存在、插件没换人、`command` / `args` 字段还在提供方的 schema 里。

**服务端现在的真实路径**：服务进程平时走 direct 运行时（不经 dsh）；**只有带 `computer_use` 的运行改走 dsh 运行时**
（官方提供方只在那条路上挂），别的运行一个字节不变。

## 3. 三层开关

| 层 | 在哪 | 默认 |
|---|---|---|
| ① 总开关 | 设置页「电脑操控」（`PUT /v1/settings/computer-use`，一台机器一份，与浏览器设置同一条理由） | **关**。打开前那段白话把风险说清：能看屏幕、点、输入；遇到密码 / 支付 / 验证码会停下；截图不发给模型；托盘变红、随时能停 |
| ② 哪几条职责可以 | 同一张卡里勾（`roles`） | **一条都不勾**。没勾的职责连 `request_computer_use` 都不会出现 |
| ③ 每次运行先授权 | Agent 第一次要动电脑时调 `request_computer_use` → 出一张 `computer_use` 卡「让它在接下来 N 分钟操作这台电脑？」（N 默认 10，设置页可改 1–60） | 批了服务端记一次授权（这件事、N 分钟），**带着授权重跑这件事**——批了这次运行才挂提供方。**一次授权只给下一次运行用一回**；过期不给；驳回什么都不发生 |

只在本机档（`runtimeMode() === 'local'`）：Docker / 托管 / 公司服务器上总开关打不开、勾不上、装不了、`forRun()` 永远不给。
关总开关 = 没用掉的授权一起作废 + 正在操作的那次也停下。

## 4. 门禁（`dsh-adapter/src/computer-use.ts`，接在 `gate.ts` 的 `tools/pre-execute`）

- 驱动的工具**全部按 `write_external`**：截图、列窗口这类只读也要在授权窗口内（整屏截图是隐私，与点击同一档）；上游新加的工具同样；
- 只看授权窗口：没授权 → 拒；`granted_until` 过了 → **立刻拒**（按**墙钟**判，合成时钟 / 子进程镜像时钟不走的时候它也得走）；调过 `computer_handoff` → 这次运行再碰电脑一律拒；
- 授权中也硬拒：`check_for_update`（出网查新版本）、`set_config` / `get_config`（驱动的持久配置里就有遥测开关）、名字带 update / telemetry / autostart / install 的；带 `screenshot_out_file` 入参的（把 PNG 写到任意路径）；
- 放行也留痕：`progress{step:'computer_use', note:<工具名>}`；出卡 `proposal.created{kind:'computer_use'}`；接手 `progress{step:'computer_handoff'}`；
- 这一关**不看 `side_effect_policy`**：服务端现在所有运行都是 `executor` 档，按字面「executor 永远不给」电脑操控就永远用不上。「公司端不给」落在服务端那一层（只本机档给、公司服务器 / 托管一律不给）。

**不许 Agent 代输密码**：提示词（persona 的 `complete` 段，官方提供方自己一句指导都不写）写明
「遇到登录、密码、支付、验证码（短信 / 邮件 / 二次验证）、银行卡或证件号：立刻停下，调 `computer_handoff`
写清楚要用户做什么。不许自己输入、不许猜、不许从别处复制」——照浏览器的 `browser_handoff`。
接手卡批了（「好了，接着做」）= 再授权 N 分钟并接着跑。

## 5. 隐私与「看得见、停得住」

- **截图不进模型**（v1）：我们的树里没挂附件库、网关路由也不声明图片输入，官方 MCP 桥本来就会把图片块换成诊断文字；
  但规范值里仍然留着原始 base64，所以 `tools/post-execute` 再扫一遍，图片块与长 base64 串换成一句说明。模型靠无障碍树文字（`tree_markdown`）干活。
  要不要让截图进模型（图片输入的模型 + 附件库，WP143 那条路）列给 Luoye 定；
- **驱动的遥测与查更新都关**：上游遥测**默认开**（PostHog，只发事件名与分桶计数，`telemetry.rs`：环境变量 → 持久配置 → 默认开），
  我们设 `CUA_DRIVER_RS_TELEMETRY_ENABLED=false`（与兼容名 `CUA_TELEMETRY_ENABLED`）；`mcp` 一起就在后台去 GitHub 查新版本（`version_check.rs`，20 小时一次），
  我们设 `CUA_DRIVER_RS_UPDATE_CHECK=false`。提供方不收 `env`，驱动继承我们进程的环境，所以挂之前写进 `process.env`；自检那一次同样带着；
- **看得见**：带授权的运行登记成「正在操作」——桌面壳托盘图标变红（非 template，否则系统会反色成黑白）+ 菜单最上面一行「AI 正在操作电脑（到 HH:MM）· 停止」；工作台第三栏同样一行；事项时间线记一句「AI 正在操作这台电脑（授权到 HH:MM）」；
- **停得住**：点「停止」= 撤销所有授权 + 中断那次运行（dsh 那棵树 dispose，驱动 stdin 一关随之退出）。

## 6. 权限引导（设置页三步向导，照 WP92）

| 步 | macOS | Windows |
|---|---|---|
| ① 下载驱动 | 一键：钉版本 + sha256，校验不过什么都不装 | 同左（`.zip` 用系统自带的 `tar` 解，Windows 10+ 的 `tar` 是 bsdtar） |
| ② 授权系统权限 | 给「Agents 工坊」打开「辅助功能」+「录屏与系统录音」。按钮只**打开那一页**（`x-apple.systempreferences:…Privacy_Accessibility` / `…Privacy_ScreenCapture`），开关要人自己点，改完重开 Agents 工坊 | 没有 TCC 那一套，不需要额外授权（上游 WINDOWS.md：标准用户令牌即可）；第一次运行若被 SmartScreen 拦，点「更多信息 → 仍要运行」 |
| ③ 自检 | 起一次驱动、调**一次** `check_permissions {prompt:false}`（只读 TCC 状态，不弹系统框、不截屏、不点），结果原样列出 + 怎么修 | 同左（上游说 `prompt` 只在 macOS 有意义） |

## 7. 与浏览器两条腿的关系

| | 浏览器（WP82 Playwright / WP92 BrowserSkill） | 电脑操控（WP144） |
|---|---|---|
| 操作对象 | 网页 | 整台电脑上的任何应用 |
| 能不能跑在公司服务器上 | Playwright 能（独立 Chrome） | **不能**，只本机档 |
| 读写分类 | 按工具 / `action` 分读写 | **一律按写**，只看授权窗口 |
| 范围 | 域名白名单（`browser_scope`） | 职责勾选 + 每次运行授权 N 分钟 |
| 人接管 | `browser_assist{request-help}` / 提示词 | `computer_handoff` 出卡 |

能用浏览器干的活优先用浏览器（有域名白名单、能在公司端跑）；电脑操控只给「非得在桌面应用里点」的那几条职责。
两者可以在同一次运行里并存（浏览器先挂、电脑操控后挂），互不占对方的槽。

## 10. 实测到的几件事（与预判不同的）

1. **服务端平时不跑 dsh 运行时**（direct），所以只把带 `computer_use` 的运行改走 dsh——否则设置页开了也没有任何一次运行挂得上提供方。
2. **官方 MCP 提供方对坏驱动是安全的**：路径不存在 / 起来就退，都是激活失败 + 回滚，我们的进程不受影响（与 WP92 的 BrowserSkill 插件相反）。仍然保留「装好了才挂」。
3. **dsh-base 里没有电脑操控的行**，所以 profile 层破例有一处 `insert`（写死 `disabled: true`），opt-in 文件只写 `disabled: false`；profile 目录要装得到这两个包（`profiles/agentsws/package.json` 列着），测试把本仓已装的同版本链进一次性 profile 目录再导 schema。
4. **截图的 base64 留在规范值里**：MCP 桥给模型的是诊断文字，但我们在 post-execute 接受的是值——不扫就会把整屏像素当文字塞进上下文。
