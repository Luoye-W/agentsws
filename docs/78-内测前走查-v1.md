## 1. 阻断清单（内测朋友会卡住的，按严重排序）

### #1 向导建出来的职责「范围为空」→ 红人工作台、聊天窗入口整块看不见【阻断 · M】

- **现象**：新用户在向导里勾「红人营销」，第 ④ 步不连 Shopify（红人线本来就标「可选」），完成。进「红人营销」→ 向导新建的那几条职责（Instagram 红人 / TikTok 红人…）的「面板」tab 只有一张卡：「这个岗位还没分配店铺 / 品牌 / 产品线 · 范围是空的」。**候选池 / 活动 / 合作线程 / 演练开关一样都没有。** 客服那边同理：向导新建的「网站在线客服」面板被同一张卡替换，「聊天窗」「试聊」两个入口都不出现，而全站没有别的链接通到 `/chat-window`。
- **复现**：走查第 12 步（`12-new-kol-duty.png`）与第 41 步（`41-chat-entry.png`）。demo 里「YouTube 红人」是种子数据带范围的，所以老截图一直是好的；向导新建的职责才暴露。
- **根因**：
  - `apps/server/src/onboarding.ts` `apply()`（约 702 行）：范围只取已连上的 Shopify 店，**「没连就挂空」**；
  - `apps/workstation/src/pages/position.tsx` `ViewTab`（约 139 行）：`here.ranges.length === 0` 时直接 `return <NoRangeNotice/>`，把排在它后面的 `ChatWindowEntry` / `ChatSandboxEntry` / `KolPanel` 一起吞掉；
  - 接口侧也按 `range=assigned` 判：空范围职责去读 `customer.*` 被 403（第 42、43 步的 403 就是它；`creator.*` 同理，推断）。
- **建议修法**：向导没连店时把新职责挂到**品牌 / 工作区**范围（红人与在线客服本来就不是按店划的）；`ViewTab` 里 NoRangeNotice 只挡「店铺数据」那几块，不挡红人工作台与聊天入口；`NoRangeNotice` 的「去分配」在店主本人时直接给一键「给我自己挂上这个品牌」。
- **验收**：走查第 12、41 步变「通」。

### #2 独立页面用错身份：试聊 / 聊天窗 / 连接页「自带数据接口」被 403，话还说错【阻断 · M】

- **现象**：
  - 打开「试聊」（`/chat`）只有一句红字「这个服务进程没有装在线客服。」——服务其实装了，是请求带的身份（`X-Assignment`）是**店主**那条分配，没有 `customer.read`，建会话被 403（第 33、43 步）；
  - 「聊天窗」页（`/chat-window`）能打开，但对话列表 `GET /v1/chat/sessions` 403，页面不说；
  - 「连接」页每次打开都有 `GET /v1/kol/byo-sources` 403（第 32 步）——红人「自带数据接口」那块读不出来。docs/75 的四级路由里第 ② 级就靠它。
- **根因**：工作台「当前岗位」是全局的（`apps/workstation/src/lib/api.ts` `setAssignment`），整页刷新后落回店主；这三个页面不属于任何一个岗位，却用当前岗位的身份发请求。话术错在 `lib/i18n.ts` `chat.unavailable` 把 403 与 501 当成一回事。
- **建议修法**：这几页按「要什么能力」挑自己名下持有该职责的分配（`dtc.live-chat` / `kol.*`），挑不到就说「你名下没有网站在线客服这条职责，去哪加」；403 与 501 分开两句话。
- **验收**：第 32、33、42、43 步没有 403；试聊能一问一答。

### #3 demo 的限流挂在合成时钟上，额度用完永不回血【阻断（演示 / 回归）· S】

- **现象**：一个 demo 进程大约 115–240 次接口调用之后，整个工作台变成白底一行红字「出错了：请求过于频繁」（`51-demo-quota.png`），等多久都不恢复，只能重启 demo。首页一次加载约 16–46 个请求，**点十来个页面就锁死**。docs/66 #12 说的「demo 请求配额用完」就是它，Fable 前两次亲测「内置浏览器不可靠」大概率也有它一份。
- **根因**：`packages/api/src/app.ts` 第 229 行 `nowMs = Date.parse(deps.clock.now())`，令牌桶按注入的时钟回血；demo 注入的是合成时钟（`apps/cli/src/demo.ts`），它只在批卡 / 跳时间时往前推。真安装用系统时钟，不受影响。
- **建议修法**：限流桶一律用墙钟（它防的是真实世界的刷接口，与合成时间无关）；或 demo 把 `default` 放到很大。另外整页报错应当留着左栏与「重试」，不是白屏一行字。
- **验收**：走查脚本不再需要分五段起 demo；第 51 步「通」。

### #4 牌堆一次只露一张，后面的卡被前面挡住，而「卡型」筛选会自己缩成一项【高 · S】

- **现象**：红人岗位「卡片」tab 里，接受过的 campaign 名单卡排在第一张，议价卡在第二张；想先批议价卡——
  - 「卡型」下拉在这时**只有「所有卡型」一项**；在客服岗位上选了一种卡型之后，下拉里**只剩这一种**，要先切回「所有卡型」才能换；
  - 这张 campaign 卡只有「通过 / 拒绝」和「需要补素材」，**没有「稍后」**，底下提示行却写着「↑ 稍后 · ↓ 指导」；
  - 于是只能先把 campaign 卡批掉才看得到议价卡（第 14 / 26 步，脚本就是这样绕过去的）。
- **根因**：`apps/workstation/src/components/deck/deck-section.tsx` 第 175 行 `kinds` 从**筛过的**牌里算；提示行不按卡给；campaign 名单卡的 `available_actions` 没有 `snooze`。
- **建议修法**：`kinds` 从未筛的全部牌算；提示行按这张卡真有的动作生成；所有卡都给「稍后」；牌堆加「下一张」或列表视图。
- **验收**：不用决定前一张也能直接找到议价卡。

### #5 「交给它一件事」找红人：说找到了 2 个，但不说是谁、为什么不够 20 个、下一步怎么办【高 · S】

- **现象**：红人岗位交给它「找 20 个 1 万到 10 万粉的 YouTube 频道」→ 事项页时间线只有一行「youtube 这条渠道上，按粉丝 10,000–100,000 这个区间，我做了这几件事：- 找人：2 条。」摘要行还露出工具名「查了 search_creators」。没有名单、没有去候选池的链接、没说「库里只有 2 个在区间内；接 YouTube key / 关联官方数据接口能搜更多」（第 14 步）。
- 候选池里直接搜关键词，没接数据源时回一大段两百字的话（第 15 步），真正要做的两件事（关联账号 / 接自己的接口）埋在中间。
- 「活动」里要 5 个，清单只出 2 个且都已在合作里，「接受这份清单」回「一条都没新建」，接受了等于什么都没发生（第 17 步）。
- **根因**：`packages/kol-core/src/playbook.ts` 的回话模板只报计数（约 381 行起），事项摘要在第 371 行直接拼工具名（`查了 ${readTools}`）。
- **建议修法**：回话里列前 5 个名字 + 「去候选池看全部」链接；不够数时说原因并给两个按钮（关联官方数据接口 / 导入一张表）；摘要里的工具名换成人话。
- **验收**：第 14、15、17 步「通」。

### #6 官方云那一跳：等待时没有任何提示，失败时报一个网址【高 · S】

- **现象**：向导第 ① 步「用 Agents 工坊的接口」→ 填邮箱 → 发登录信。走查时两次：一次 3.5 秒后「连不上 agentsws 云（https://cloud.agentsws.com）」（`POST /v1/cloud/account/link` 503），一次 4.5 秒后「信发出去了」。**两次等待期间都只有按钮变灰**，没有转圈、没有「正在连云」；失败那句话只给网址，不给「再试一次 / 先逛演示数据」。朋友里没有自己模型 key 的人全靠这一跳，也靠它开官方数据接口搜红人。
- 同一件事在「设置 → 账号与积分」：没关联时，**三块分组、充值四档、增值服务卡一样都不显示**，只有一行「还没关联」和一个折起来的价目表（第 44 步）——朋友看不到要花多少钱。
- **另外**：demo（合成世界）点「发登录信」**真的会打生产云**，云账号那一跳没有替身。走查脚本默认不点（`--live-cloud` 才点）；WP135 手测那两次收件人是 `tester@example.com`（保留域名，不投递）。
- **根因**：`apps/workstation/src/components/onboarding/ai-step.tsx`（发送中态）、`apps/server/src/cloud-account.ts` 第 209 行（报错话术）、`components/settings/credits-panel.tsx`（未关联时整块不渲染）。
- **建议修法**：发送中给一句「正在连 Agents 工坊云…」；失败给「网络不通，再试一次」按钮 + 「先逛演示数据」；未关联时价目三块与充值四档照常展示，只把「充值」按钮换成「先关联」。demo 里云账号换替身。

### #7 向导对「红人为主」的朋友不友好【高 · S】

- 第 ③ 步按网址预勾「客服 + 网站运营」，**红人营销从不预勾**（按设计：`preset-roles.ts` 只看官网 / Amazon / 社媒链接）；「自定义岗位叫什么」框里预填了「社媒运营」（第 7 步）。
- 第 ④ 步列了 **16 个连接、13 个标「可选」，全部平铺**，技能包显示内部名 `brand-voice`、`chargeback-evidence`、`workspace-basics`（第 8 步）。docs/73 #4 说的「只列必需的、可选折成一行」没做到这一页。
- 完成屏说「16 条职责已经配好」，第 ④ 步各岗位「已勾」加起来 18 条（已经有的 2 条被跳过，没说）（第 9 步）。
- 完成后左栏多出一个没勾过的「普通成员」岗位（第 10 步）。
- **建议修法**：第 ③ 步前问一句「你这次主要想让它干什么」（红人 / 客服 / 都要），按答案预勾；第 ④ 步只列必需，可选折成「还有 N 个可选」；技能包用中文名；完成屏数字与第 ④ 步同口径。

## 6. 走查脚本怎么重跑

```
npx tsc -b && pnpm -F @agentsws/workstation exec vite build   # demo 服务的是 dist，不重建就测到旧界面
node scripts/walkthrough-beta.mjs                               # 全部五段，约 8 分钟
node scripts/walkthrough-beta.mjs --only B                      # 只跑红人
node scripts/walkthrough-beta.mjs --live-cloud                  # 连「发登录信」那一跳也点（会打生产云）
```

- 每次重跑先清空 `docs/assets/walkthrough/` 里的截图与 `results.json`；退出码恒为 0（走查不是断言），看控制台最后一行「通 / 部分 / 不通」与 `results.json` 的 `tally`。
- 端口上已有服务在跑会直接报错退出（旧 demo 的配额早用完了，打过去全是 429）。
- 入库的截图用 PIL 压成 256 色（17 MB → 7 MB，界面字迹不受影响）；脚本本身存原图，重跑后要入库的话照做一遍。
- 判定是写在每一步里的（`ok` / `part` / `fail`）；修好一条后把那一步的判定一起收紧，别让「部分」一直是「部分」。
