## 0. 一句话

**用户永远只有一个 agentsws 账号、一个余额；每项增值能力都是同一个开关："用我的 / 用 agentsws 的"。** 用我的 = 本地直连、不经我们、不扣积分；用 agentsws 的 = 走我们云上的"服务入口"，按动作定价、预扣后结算、从余额扣。AI 模型是其中一类能力，不是特例：云上用 New API 做模型汇聚层，但**计费在我们自己的入口，不在 New API 里**——因为社媒数据、公共红人库、值守这些不是 AI 调用，账本却必须是同一本。

## 1. 那个开源项目是什么，用不用

| 项目 | 是什么 | 许可证 | 我们的判断 |
|---|---|---|---|
| **One API**（songquanpeng） | 2023 年起的 OpenAI 兼容网关：多家模型、渠道、令牌、额度、用户，34k+ star | **MIT** | 原版更新已慢；社区主力转到下面那个 |
| **New API**（QuantumNous，One API 的分支） | 同一套东西的增强版：新界面、更多模型、OpenAI / Claude / Gemini 三种格式互转、计费与用量分析，39k star | **AGPL-3.0** | 功能最全；AGPL 意味着我们**作为服务提供者**必须公开我们对它的改动——只要不改它的源码、当独立进程用，没有问题 |
| **LiteLLM Proxy** | Python 网关，100+ provider、虚拟 key 预算、团队用量 | MIT（企业功能另收） | 最广的 provider 覆盖；Python 高负载慢，且它的"预算"也是自己一本账 |

**结论：用 New API，但只当"模型汇聚层"，不当计费层。** 理由三条：
1. 它解决的是"一把内部密钥 → 几十家模型、格式互转、渠道轮换、模型清单、故障切换"，这块自己写没有意义；
2. 它的额度 / 用户 / 令牌体系是**给它自己的用户**设计的——我们的用户账号、余额、社媒数据接口、值守订阅都不在它里面，两本账必然对不上；
3. 我们本地已经有 `packages/model-gateway`（22：路由、驻留、价目、预扣 → 结算的 `BudgetLedger`），云上的计费直接复用这一套，不再学一套。

Sources：[New API 项目页](https://github.com/QuantumNous/new-api)、[Laisky/one-api（OpenRouter 开源替代的说法）](https://github.com/Laisky/one-api)、[LiteLLM](https://www.litellm.ai/)、[Vercel 开源 AI 网关对比](https://vercel.com/i/open-source-ai-gateways)。

### M1 一个账号

- agentsws 云账号 = 首次设置里的登录邮箱（46）。本地工作区"关联"一次，拿到一把**工作区服务令牌**（绑定工作区，可撤，只在本机加密库）。
- 一个账号一个余额（12 §4 的钱包）；一个账单页；团队版由 owner 一个账号付，成员用工作区令牌。
- 旧 SaaS 的积分账户在 D 期"余额合并"进来（12 §4 定过）。

#### WP58 实现落点

| 对象 | 在哪 | 关键字段 |
|---|---|---|
| **云账号 `CloudAccount`**（人） | `packages/contracts/src/cloud.ts`；库在 `apps/cloud`（`cloud_accounts`） | `id` / `email`（唯一）/ `created_at`。没有口令——登录只有 magic link |
| **云侧组织 `CloudOrg`**（计费主体，52 O3） | 同上（`cloud_orgs` + `cloud_org_members`） | `id` / `name`（= 邮箱，第一次登录时**隐式**建）/ `owner_account_id` / `members[]`。界面上不露"组织"这个词 |
| **工作区关联 `WorkspaceLink`** | 同上（`workspace_links`） | `workspace_id` + `cloud_org_id` + `label` + `token_sha256` + `scopes[]` + `expires_at` + `revoked_at`。一个工作区同时只能有一条活着的关联 |

| 路由 | 鉴权 | 做什么 |
|---|---|---|
| `POST /v1/cloud/auth/magic-link` | 公开 | 发登录邮件。一次性 token **只进邮件**，不进响应；`callback_url` 走白名单（只认本机回环与云自己的地址） |
| `POST /v1/cloud/auth/verify` | 公开 | 一次性 token → 云账号会话 |
| `GET /v1/cloud/me`、`POST /v1/cloud/auth/logout` | 会话 | 我是谁 / 注销这一张 |
| `POST /v1/cloud/links`、`GET /v1/cloud/links` | 会话 | 签一把工作区服务令牌（明文只回一次）/ 本组织的关联清单（无令牌、无哈希） |
| `POST /v1/cloud/links/:id/renew`、`/revoke` | 会话 | 续期 = 换一把新的（旧明文当场作废）/ 撤销（写 `revoked_at`，不删行） |
| `GET /v1/cloud/links/current`、`POST /v1/cloud/links/current/revoke` | 工作区令牌 | 认自己 / 撤自己（本地"解除关联"走这条），不要求任何 scope |
| **本地** `GET /v1/cloud/account` | `store_config.read@workspace` | 关联状态：邮箱、账号名、令牌到期、动作集。**不回令牌** |
| **本地** `POST /v1/cloud/account/link` / `/unlink` | `policy.stage@workspace` | 起关联（发信）/ 解除（本机删 + 云侧撤） |
| **本地** `GET /v1/cloud/account/callback` | 公开 + 一次性 `state` | 邮件链接的落点，浏览器打开；`state` 对不上就当没发生 |

**令牌规则**（18 §1 逐条）：前缀 `wst_`；默认 90 天、最长 365，没有"永不过期"这一档；
`scopes` 本版只有 `ai` / `wallet:read` / `standby`，新签默认给前两个；库里只存 `sha256`，
明文只在签发与续期的返回值里出现一次；撤销写 `revoked_at`（不删行）；撤销 / 过期 / 不存在
验起来一律回 `undefined`，**不区分**。验证口是一个纯函数 `CloudTokenVerifier`
（`apps/cloud` 里的 `sqliteTokenVerifier(db)`）——WP59 的服务入口路由包只依赖它。

本地令牌进本机加密库（`secret-store`，key 名 `cloud.workspace_token`），
云侧库与本地库**完全分开**（`AGENTSWS_CLOUD_DATA_DIR`）。
WP59 的 `/v1/ai/*`、`/v1/wallet/*` 以路由包形式挂进
`createCloudServer({ modules })`——网关不认识模块的形状，挂一个只是往数组里多塞一项。

### M2 每项能力一个开关："用我的 / 用 agentsws 的"

| 能力 | 用我的 | 用 agentsws 的 |
|---|---|---|
| 模型（DeepSeek / OpenAI 兼容 / Ollama…） | 填自己的 key，本地直连（现在的做法） | 一键，不填 key；本地 `model-gateway` 的 provider 指向 `/v1/ai`，带工作区令牌 |
| 公共红人库 / 邮箱抓取 / 体检报告 | 没有"我的"（数据在我们云上） | 按次计价 |
| 社媒数据（YouTube / IG / TikTok 抓取与配额） | 填自己的平台 token，本地直连 | 用我们的配额池，按次计价 |
| 官网爬取 / 知识引导 | 本地跑（网络不稳） | 云上跑，按页计价 |
| 在线值守 / 聊天窗托管 / 公网回调 | 无 | 订阅（座位 / 月）|
| 转写（会议） | 本地模型 | 云上按分钟 |

- 开关在连接页每张卡上，默认**用我的**（开源本地优先，40 §1）；没配自己的就提示"没有 key，可以用 agentsws 的（按积分）"。
- 切换即时生效，随时切回；切回后不再产生扣费。

### M3 服务入口 = 我们自己的一个薄网关，不是 New API

- 一个 Node 服务（复用 `packages/model-gateway` 的价目、`BudgetLedger`、驻留策略；复用 18 的令牌纪律：短期、最小动作集、可撤）。
- 每个请求：验令牌 → 查价目算预扣 → 余额够就放行 → 转发到后端（New API / 公共库服务 / 配额池）→ 按实际用量结算 → 记一条计量事件（**只记计量，不记正文**）。
- `/v1/ai/*` 是 **OpenAI 兼容口**（chat / embeddings / models）——本地那边不用改 provider 代码，就是换个 `base_url` + 令牌；New API 在它后面做汇聚。
- 数据驻留（22）：`region: cn` 的请求只路由到境内可用的模型与后端。


> **WP59 实现落点**：`packages/cloud-entry`（**路由包，不起服务**：导出 `entryRoutes(deps)` /
> `mountEntryRoutes(app, deps)`，由 WP58 的 `apps/cloud` 挂上去；本地联调用 `bin/dev.mjs`，
> 内存令牌 + 内存钱包 + 假上游，不需要任何密钥）。
>
> - 中间件 `src/routes.ts`：`Bearer wst_…` → `verifier` → org / workspace / scopes。令牌明文只
>   在一行里出现，之后没人再引用；形状不对与验不过回**同一句话同一个码**（分开说等于告诉
>   试探的人前缀猜对了）。每条路由声明自己要哪个 scope，没有就 403（18 §1 最小动作集）。
> - `src/ai.ts`：`/v1/ai/chat/completions`、`/v1/ai/embeddings`、`/v1/ai/models`。五步顺序不能换——
>   查价算预扣 → 余额够才放行 → 驻留判定 → 转发 → 按 `usage` 结算并记一条计量事件。流式
>   出站替用户带上 `stream_options.include_usage`，边转发边扫最后那个 `usage`（不缓冲整条流，
>   那会把"流式"变成"假流式"）。上游出错**原样透传状态码**，预扣整笔释放。`/v1/ai/models`
>   不扣积分——它不产生任何上游成本。
> - 驻留：`X-Agentsws-Region: cn` 只允许境内可用的模型，否则 **422 + 一句人话**。判据先看装配方
>   给的 `region_map`，没有就退回价目表的 `cn` 标记（`pricing.json` 的 `cn_vendors`）——两边都
>   说不出来的一律不允许。
> - env 名（值一律不写进代码，README 列全）：`AGENTSWS_NEWAPI_KEY`、`AGENTSWS_NEWAPI_BASE_URL`、
>   `STRIPE_SECRET_KEY`、`STRIPE_WEBHOOK_SECRET`、`AGENTSWS_CLOUD_PUBLIC_URL`、`PORT`。

## 3. 积分（M4）

- **1 积分 = ¥1**（Luoye 09-15 定：前期主要客户是中国用户，1 积分 = 1 元人民币，用户一眼看得懂自己的消耗）。账本记人民币；境外用户充值按当日汇率折算成积分，扣费口径不变。旧 SaaS 的积分（1 = $0.01）在 D 期"余额合并"时按当日汇率换成新积分，换算规则与截止汇率写进合并公告。
- **定价表是数据不是代码**：`pricing.json`（能力 → 单位 → 积分），随版本走，界面上一张"价目表"页可看；AI 按 token 计（成本 × 倍率，倍率默认 3，对用户只显示最终价，同旧 SaaS）；数据类按次；订阅按月。
- **预扣 → 结算**：调用前按估算预扣（`BudgetLedger.reserve`），完成后按实际结算（`settle`），失败退回；余额不足只拒这一次不冻结（22 §3 的并发保护）。
- **两类积分**：充值买的永不过期；套餐 / 活动送的按周期清零；扣费先扣有期限的（旧 SaaS 已验证的规则）。
- **用户自带 key 的调用一分不扣**——它根本不经过入口。
- 余额低于阈值出一张卡（14，同 KefuAgents 的 `low_credit`），不弹窗。
- 支付：先 Stripe（境外）+ 微信 / 支付宝（境内，经聚合商），充值包与订阅走同一个钱包。


> **WP59 实现落点**：`packages/metering`（**纯逻辑无 IO**：存储经 `WalletStore` 注入，时间与 id
> 经回调注入，整个包里没有一处 `Date.now()` / `Math.random()`）。
>
> - `src/pricing.json`：首批八条能力 —— `ai.chat`、`ai.embeddings`、`data.kol.lookup`、
>   `data.kol.audit`、`social.fetch`、`crawl.page`、`transcribe.minute`、`standby.seat.month`。
>   **AI 单价不手写**：从 `model-gateway/pricing/catalog.json` 拼出来，各家币种按 json 里那张
>   带 `as_of` 的参考汇率表 `fx` 折成人民币再 × 倍率 3。为什么汇率写死而不拉实时：积分价必须
>   稳定——汇率每天动一点，用户看到的单价就每天动一点，账对不上也说不清。**对用户只显示
>   最终积分价**，成本、倍率、汇率都是中间量，一个都不进界面。
> - `src/wallet.ts`：两类积分（`purchased` 永不过期 / `granted` 到期清零），**先扣有期限的**；
>   `reserve → settle | release` 逐条对齐 `BudgetLedger`；余额不足**只拒这一次不冻结**（预算越线
>   才冻结——那是策略，钱不够不是，充了就能用，不需要谁来解冻）；低于阈值（默认 50）出一个
>   `wallet.low_balance` 事件且只出一次。
> - 两份 store：内存 + sqlite（`wallet_lots` / `wallet_reservations` / `metering_events`）。
> - `packages/cloud-entry` 的 `/v1/wallet`、`/v1/wallet/usage`、`/v1/wallet/pricing`、
>   `/v1/wallet/topup` 与 Stripe webhook。**1 积分 = ¥1** 所以 Stripe 的 `unit_amount = credits × 100`；
>   幂等靠 `session_id`（Stripe 会重投，重投不该变成重复充值）；微信 / 支付宝回一句人话不是 500。
> - lot 与计量事件都按 `org_id` 存（52 §2 O3 钱在组织级），`workspace_id` 只做分组维度。

## 4. 本地端怎么呈现（M5）

- 设置 → 模型：现有两张卡（DeepSeek 官方 / OpenAI 兼容）旁加第三张 **"agentsws 云（用积分）"**：一键启用，显示"本月用了 N 积分、余额 M"，不填 key。
- 连接页每张数据类卡加同一个开关；数据后端三档下的"在线值守"入口（48 L7）就是订阅的入口。
- 设置 → 账号与积分：余额、用量明细（按能力 / 按岗位 / 按天）、充值、发票；owner 才能看整个工作区的。
- 岗位面板：数字块可选"本周积分消耗"。


> **WP59 实现落点**：`/v1/cloud/credits`（余额 + 本月用量，缓存 60 秒）、`/v1/cloud/pricing`、
> `/v1/cloud/usage?group=capability|workspace|day`（`packages/api/src/routes/cloud.ts` +
> `apps/server/src/cloud.ts`）。**本地不记账**——每个数字都是云上那份的透传，本地一个都不自己算
> （自己算就是第二本账，两本账必然对不上）。没关联账号 / 云连不上都不是错：回
> `linked: false` + 一句人话，界面据此把按钮变成"先关联账号"，而不是画一堆 0；价目表取不到
> 就回本地内置那份，不该因为断网就一片空白。
>
> 界面两处：`components/settings/model-cloud-card.tsx`（设置 → 模型第三张卡，
> `docs/assets/workstation/model-cloud-card.png`）与 `components/settings/credits-panel.tsx`
> （余额两类分开、即将过期、用量三个切换、价目表折叠，`docs/assets/workstation/credits.png`）。
> 后者由 WP58 的"账号与积分"tab 渲染。
>
> 一个顺手修掉的真 bug：本地**不再把自己的"现在"当上界发给云侧**。两个钟不是一个钟
> （时区、NTP 漂移、虚拟机挂起），用慢几秒的钟去裁云上的账，最近那几笔会凭空消失，
> 而用户看到的是"我明明刚用过"。上界由云侧自己定。

## 5. 不做什么（M6）

- 不把 New API 直接暴露给用户（它的用户体系与我们的账号是两套）。
- 不做"我们代持用户的模型 key"：用我的 = key 在本机加密库；用 agentsws 的 = 用我们的 key。
- 不做通用"API 市场"；伙伴的付费能力仍按 12 §4 第四步（先自收自付，有对账再进钱包）。
- 不在入口存任何正文、附件、订单内容；计量事件只有能力、单位、数量、积分、时间、工作区。


> **WP59 实现落点**：`MeteringEvent` **只有八个字段**（能力、单位、数量、积分、时间、组织、
> 工作区、请求号），契约 `cloud-entry.ts` 里另有 `METERING_EVENT_FIELDS` 白名单，
> `packages/metering` 的 `assertMeteringEvent` 拿它做运行时断言：多一个键就抛。这是"入口不存
> 正文"**唯一可执行的形式**——类型挡住笔误，断言挡住"从上游响应里 spread 一把过来"。
> sqlite 的 `metering_events` 表也**只有八列**：想存正文也没地方存。
>
> 没做（照 M6）：New API 不暴露给用户、不代持用户的模型 key、没有通用 API 市场。

> **WP60 实现落点**：`packages/standby`（库 + 路由包，不起服务）挂进 `apps/cloud`
> （`src/standby.ts`，照 `entry.ts` 的写法）；本地那一面是 `/v1/standby*`
> （`packages/api/src/routes/standby.ts` + `apps/server/src/standby.ts`）。
> 详细落点见 48 §6 L6 与 §7 L7 两处的实现落点表。这里只记与 49 直接相关的三条：
>
> - **订阅接的是钱包，不是第二本账**（12 §4）：开通 = 一次 `reserve → settle`，
>   能力名 `standby.seat.month`（价目表里本来就有那一条，WP59 留的），
>   `quantity` = 座位数，账落 `org_id`（52 O3）。于是余额、预扣中、计量事件三处
>   看到的都是同一种形状的记录，用量页按能力分组时值守和模型调用并排站。
> - **余额不足只拒这一次不冻结**（与 22 §3 / 钱包逐字同一条）：402 + 一句人话。
>   到期那天先试着续一期，钱不够才停成 `expired`——**数据不删，导出照常**。
> - **`standby` 动作集真的被用上了**（18 §1 最小动作集）：控制面五条都要它，
>   缺了是 403 而不是 401；而云上起的那个子进程拿的是值守自己签的另一把，
>   动作集只有 `ai` + `wallet:read`，**没有 `standby`**——它不该能开 / 停 / 导出
>   任何工作区的值守，包括它自己的。
>
> 一处顺手的接线：`apps/cloud/src/entry.ts` 多一个可选 `verifier`（默认还是账号库那个），
> `index.ts` 里晚绑定成"先账号库、后子进程"。两个模块互相要对方一样东西
> （入口要子进程令牌的验证器，值守要入口的钱包与价目），解法是**晚绑那一跳**，
> 不是把它们合并成一个模块。
