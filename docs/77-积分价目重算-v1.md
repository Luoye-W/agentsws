### 1.1 云端摊销（Workers / DO / R2）

每一次数据接口调用在云上走的是：入口 Worker 1 次请求 + `KolPublicDO` 1 次 + `WalletDO` 预扣与结算 2 次
（Workers Paid 公开价：请求 $0.30 / 百万、CPU $0.02 / 百万 CPU 毫秒；DO 请求 $0.15 / 百万、时长
$12.50 / 百万 GB·秒、SQLite 写行 $1 / 百万行；R2 这条路不碰）。按每次 ~5 ms CPU、~10 ms DO 时长、
~10 行写入算，**一次约 $0.00001（¥0.0001）**；再把 Workers Paid 每月 $5 的底费摊进来，表里一律按
**每次 ¥0.001** 记（估高了十倍，只让毛利显得保守）。**未核**：没有真部署的账单可对，是公开价 × 估的用量。

### 2.1 联系方式揭示（单列）

| | 数 | ¥ |
|---|---|---|
| KOLAgents 从库里取一个已有邮箱 | 12 积分（$0.12） | **¥0.85** |
| KOLAgents 现场抓一个邮箱（成本 12 美分） | 40 积分 | ¥2.84 |
| 我们现在 | 0.2 积分（与浏览同一条能力 `data.kol.lookup`，docs/75 §2） | ¥0.2 |
| 我方成本 | 库里已有的：¥0.001（读 + 摊销）；插件贡献 09-23 起不发积分，拿进库也是 0 | ¥0.001 |

依据：一个能直接发信的商务邮箱是整个产品里单次价值最高的东西，0.2 比 KOLAgents 便宜了四倍多，
而那边 12 积分（¥0.85）是 Luoye 在 v3.1 / v3.2 两次签过的「库里取」价。0.8 与它对齐、又留在 1 积分
确认线以下（每取一个都弹确认会很烦）。毛利 99.9%。30 天内重看不另收、本机已有的永远 0 积分——这两条不变。
**要改代码**：揭示现在与浏览共用 `data.kol.lookup`，单独定价要给它一个新能力 id（建议 `data.kol.reveal`，
`charge-map.ts` 的 `reveal` 改指它，两形态计费点各改一行）。Luoye 定了再开单。
