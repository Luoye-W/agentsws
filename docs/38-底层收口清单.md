## 1. 诚实盘点：18 份契约与底座各到哪了

| 层 | 契约 | 实现 | 状态 | 缺口 |
|---|---|---|---|---|
| 内核（Cordis、事件日志、急停、模块清单） | ✅ | `kernel` | **通** | 模块热替换 / 动态 entry；Postgres 档；`Halt.set` 可持久化写进契约 |
| 数据层（授权下推、敏感度、擦除） | ✅ | `data` | **通** | Postgres 方言；**原始材料区加密**（channels / meetings 各自一份，靠 data 的主体密钥环跨包接线没做） |
| 制度（职责 / 岗位 / 分配 / 授权） | ✅ | `roles` | **通** | **没有管理界面**：真实模式只有"工作区所有者"，建不了岗位、分配不了人、邀请不了同事——公司制度这一层用户摸不到 |
| 审核机制（审批项、账本、Guardrail、执行器） | ✅ | `txn` | **通** | 跨进程施行锁；`decideBatch`（合并卡整组决定）；知识 / 技能 / 应用类专属预检；`ApprovalBus.create` 的 `context`（收件人门禁输入现靠 txn 交叉类型） |
| 知识与记忆 | ✅ | `knowledge` | **通** | 缺口队列、verified 晋升、sqlite-vec、simple 分词 |
| 技能与学习回路 | ✅ | `skills` + `support-core` | **半通** | **lesson → 次日提案 → overlay 审批 → 技能新版本这条回路没端到端接上**（只有"指导"能产 skill_lesson 卡）；周合并、晋升未接调度 |
| 模型网关 | ✅ | `model-gateway` | **通** | rerank、流式、replay provider；用量告警、密钥轮换 |
| 运行协议（dsh / direct / stub） | ✅ | `dsh-adapter` `runtime-direct` `stand-ins` | **半通** | **dsh 是进程内装配不是真 headless 子进程**（要 IPC 桥）；dsh-adapter ↔ simulation 依赖环；dsh / direct 没有 `createPolicyQuestion` 口子（边界提问只在 stub 里）；stub 的事项摘要不像人话 |
| 连接器（OpenConnector） | ✅ | `connect-adapter` | **通** | 真 provider 实机零次；OAuth 真回调；跨 runtime 转移；目录 token 复用；上游 run log |
| 渠道（邮件） | ✅ | `channels` | **通** | IMAP IDLE / Gmail push；附件；**IMAP 轮询与发信在服务进程里还没装配**（凭据来源接好了，管线没起） |
| **定时与流程（25）** | ✅ | **无** | **没做** | 契约 98 行，一行实现都没有。后果：每日计划 / 复盘没有定时触发、会议记录源没有轮询、幂等表没有定时清理、Shopify 令牌刷新靠各自 setTimeout、技能周合并没人调 |
| 通知路由与投递 | ✅（roles / channels） | 部分 | **半通** | 规则引擎（immediate / digest / 升级链）只在 txn 里有雏形；IM 投递没有 |
| 身份与 Join（20） | ✅ | `api/identity` | **半通** | 本地 magic-link 单人；多人（邀请同事、按邮箱登录）没有；Join 二阶段 |
| API 网关 | ✅ | `api` + `server` | **通** | WebSocket / MCP 面；`POST /v1/approvals`、知识 sources / cite / gaps、技能 promote / exclude、流程与定时路由；logout；`/v1/events` 非 owner 403 |
| 工作台积木 | ✅ | `deck` `work` `workstation` | **通** | 两套 BattleReport 字段名要合一；自适应重排；bundle 未拆 |
| 应用包与市场（23） | ✅ | `packages-local`（空壳） | **没做**（31 定为二阶段） | 扩展点只有会议两个；安装 / 卸载 / 升级审批项没有执行器 |
| 桌面壳 | — | `desktop` | **通** | 装机需 Node 22（better-sqlite3 编不过 Electron 44）；签名公证；更新源；**还没接 `PUT /v1/halt` / 会话 cookie / `AGENTSWS_CONNECT_URL`**；OpenConnector 与 dsh sidecar 拉起 |
| 模拟回路 | ✅ | `simulation` | **通** | 只有 fast 档；realistic（真模型可选）/ soak 档；judge；15 / 50 人 pack；升级链与抽检进 tick 循环；**合并门禁没进 CI** |
| 开源就绪 | — | — | **没做** | **没有 CI**（`.github/` 不存在）；README 状态停在 1a；无 ARCHITECTURE / SECURITY.md / 英文入口 / issue 模板 / release 流程 / DCO 检查；`data/test/authz.test.ts` 有已知 flake；`blocks` `identity` `dsh-plugins` `packages-local` 四个空壳包 |

一句话：**十八份契约都有实现的只有十六份，真正"没做"的是定时与流程、应用包执行；"半通"的是学习回路、dsh 真 headless、制度管理界面、多人身份、通知投递；开源基建是零。**

## 2. 收口顺序（不做新功能，只补底座）

按"陌生开发者能跑通 → 公司能真用 → 安全底座补完 → 与 DSH 生态对齐"排：

| 波次 | WP | 内容 | 验收 |
|---|---|---|---|
| 七 | **WP26 开源基建** | GitHub Actions（install / tsc / biome / vitest / `simulate --tier fast` 合并门禁；DCO 检查）；README 重写（是什么、30 分钟跑通、架构图、状态）；`docs/ARCHITECTURE.md`（英文，从 09 提炼，配 assets 里的画布）；`SECURITY.md`；issue / PR 模板；release 脚本与 CHANGELOG；修 flake；删四个空壳包或写明用途 | 新 clone 按 README 30 分钟跑通模拟；CI 绿 |
| 七 | **WP27 定时与流程（25）** | `packages/schedule`：Scheduler（cron / interval / at，SQLite 落盘，重启续跑，Clock 注入）+ WorkflowEngine 最小实现（步骤、重试、幂等、事件）；接四个消费者：每日计划与复盘、会议记录源轮询、幂等表 sweep、Shopify 令牌刷新与技能周合并；`/v1/schedules` 路由；模拟回路里时间推进能触发它 | 场景"一天走完"里计划卡早上出、复盘卡晚上出；重启后到期任务不丢 |
| 七 | **WP28 制度管理界面 + 多人身份** | 岗位 / 分配 / 职责 CRUD 页面（对着 05 的 schema，走 14 的 `policy_change` 审批）；邀请同事（邮箱 magic-link 多人、本地 SQLite）；换岗位 = 换 Assignment；模拟回路里 3 人 pack 走一遍 | 非技术用户能在界面上把"独立站售后客服"分给一个同事 |
| 八 | **WP29 学习回路闭环** | lesson 池 → 次日提案（skill_lesson 卡）→ 采纳写 overlay → 技能新版本 → 下次运行用新版；周合并 / 晋升接 WP27 调度；两条新场景（学到一条、驳回一条不再提） | 24 §一致性用例全过；对照场景证明"不批不生效" |
| 八 | **WP30 运行时对齐** | dsh 真 headless（SDK 起子进程 + IPC 桥，seam 不变）；解依赖环；dsh / direct 补 `createPolicyQuestion`；三个运行时跑同一批场景 8/8 | `runtime: dsh` 在子进程里过八条场景 |
| 八 | **WP31 安全底座补完** | 原始材料区经 data 密钥环加密（channels / meetings）；跨进程施行锁；`ApprovalBus.create.context` 进契约；desktop 接 `PUT /v1/halt` / 会话 cookie / `AGENTSWS_CONNECT_URL`；秘密模式表单一出处；密钥轮换 | 31 §3 逐条打勾；桌面壳暂停不再重启进程 |
| 九 | **WP32 模拟回路加强** | realistic 档（真模型可选、按预算）/ soak 档；judge；15 人 pack；升级链与抽检进 tick；门禁进 CI（fast 每次，realistic 每夜） | 每夜跑一次有报告 |
| 九 | **WP33 API 面补齐** | 缺的路由；WebSocket 事件流（工作台实时刷新）；logout；`/v1/events` 按岗位可读；OpenAPI 完整；SDK 生成 | 第三方前端只靠 OpenAPI 能接 |
| 后 | 应用包执行器、IM 投递、MCP 面、Postgres 档 | 等开源后按用户需求排 | |

**1d 真账号验收怎么办**：它不是功能，是"契约的验收"（32 §5）——真店真信跑通一次能证明底座是真的。凭据已经能填了，随时可做，但不挡收口；建议在 WP26–28 合入后做一次，顺带验 README 的 30 分钟路径。

## 3. 自主决定（待 Luoye 审）

- D1 收口期不派任何新业务功能；对外承诺的钩子 A 只靠 1d 验一次
- D2 定时与流程（WP27）是收口第一优先级——它是唯一"契约有、实现无"的核心层，且七个消费者都在等
- D3 制度管理界面归底层不归功能：没有它，"公司制度"这层用户碰不到，开源后的反馈也拿不到
- D4 开源基建（WP26）与 WP27、WP28 并行派
- D5 应用包执行器、IM 投递、MCP、Postgres 明确后置到开源后
