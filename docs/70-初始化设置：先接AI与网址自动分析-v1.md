## 0. 一句话

**原来的向导问"你们公司叫什么"，新的向导问"你的网址是什么"。** 前者要人打十几个字段，后者要人贴一个链接——剩下的我们填，填错了他改。

## 1. 新的四步

进度条仍然是四格（46 §1 的形状不变，内容换掉）：

| | 步 | 问什么 | 不能跳过？ |
|---|---|---|---|
| ① | **接上 AI** | 用我们的官方接口、你自己的模型接口，还是用你的 DeepSeek 账号登录（WP134） | **是**（但有「先逛逛演示数据」的旁路） |
| ② | **你的生意** | 贴一个网址 | 否（有「还没有网站」旁路） |
| ③ | **选岗位** | 你要哪几个岗 | 否 |
| ④ | **连接与开工** | 不问，只列清单 | — |

原来的「公司设置」与「个人设置」**不再单独占步**，并进 ②：分析结果里顺带确认公司名与你的称呼。理由是这两步问的东西，②那一轮分析八成已经替用户填好了；让他先填一遍再让分析覆盖掉，是把同一件事问了两遍。

## 2. 第 ① 步：接上 AI

~~两张大卡，二选一。~~ **三张大卡，三选一**（WP134 加第三张「用我的 DeepSeek 账号登录」，见 §2.3）。**没接上就不往下走**——这个产品的每一个岗位都靠模型干活，接不上 AI 的向导走完也是个空壳。

### 2.1 用 Agents 工坊官方接口（推荐，送 10 积分）

输邮箱 → 发登录信 → 点链接回到应用（沿用现有 magic link + 本机回环，WP58）→ 自动建云账号与组织、签工作区令牌、把各能力开关切到「用 Agents 工坊的」→ **到账 10 积分**。

**送的那一刻是点开登录信、`/v1/cloud/auth/verify` 过了的那一刻**，不是发信的那一刻。发信只证明有人在输入框里打了一串字；点开链接才证明这个邮箱是真的、而且这个人拿得到它。

**金额是数据，幂等键是代码。** 金额写在 `packages/metering/src/bonuses.json`（改成 20 不用动一行代码）；幂等键的算法留在代码里，因为它一旦变了，已经发过的那些会被当成没发过再发一遍。数据文件里**没有任何东西参与幂等键的计算**。

三道闸，各挡一种：

| 闸 | 挡什么 | 在哪 |
|---|---|---|
| 钱包 `(org_id, source_ref)` 唯一索引 | 同一个账号反复点登录信 | `signup_bonus:<account_id>` |
| `signup_bonuses.alias_sha256` | 换个 `+tag` 再注册一个账号 | `normalizeEmailAlias`（WP115） |
| `emailBanned` | 删号封邮箱之后又回来的 | 黑名单 |

第二道非有不可：`a.b+x@gmail.com` 与 `ab@gmail.com` 是**两个账号**，两个 account_id，两串 source_ref——只靠第一道的话同一个人想领几份领几份。这张表**只存哈希**，与黑名单同一条纪律（21 §1）。

`granted` 那一类，**90 天到期清零**（49 §3）。

**送不出去不影响登录。** 用户是来登录的，积分是我们送的；送不出去就如实记一条 `failed` 审计，界面上那句「到账 10 积分」也就不出现。五种没送成的原因都对用户说得出口，所以它们进响应而不只进日志：`already`（这个邮箱已经领过）、`blocked`、`unavailable`（这个节点没装钱包）、`disabled`（这个部署不送）、`failed`。

两种云形态（Compose 61 / Workers 64）**同一个 `grantSignupBonus`**，差的只有"钱在哪"：Compose 是进程内钱包，Workers 是跨对象敲 `WalletDO(org_id)` 那一跳。

运营后台「积分与会员」里**单独一格**看得到（`/v1/admin/credits` 的 `signup_bonus`）。不混进那张发放流水：那张表答的是"谁按了发放按钮"，这一格答的是"系统自己送出去了多少"——运营看的是两个数（这个月烧了多少拉新钱 / 手动发了多少）。

### 2.2 用我自己的模型接口

沿用现有模型表单（`components/models/model-form.tsx`）。三条纪律不变：密钥只进本机加密库、在原生表单里填、**不经 AI**。

填完**当场验证三步**（`POST /v1/models/providers/:id/test`，purpose=judge；WP127 起）：

1. **连得上**——不单独发请求，文字那一次回了任何 HTTP 响应（哪怕 401）就算连上；
2. **文字能回**——一次最小文字请求（十来个 token）；
3. **看得懂图**——一次带图的最小请求：内置一张几百字节的灰度测试图，上面用点阵写着一个
   大写单词，要求模型只回这个词。看不了图的模型要么被上游 400（`image_url` 不认），要么
   念不出来——**都不通过**。Luoye 09-23 定：Agents 工坊**只支持多模态模型**，读品牌手册、
   看图片风格都靠它。

三步都过才亮「下一步」。向导第 ① 步与设置页「测试」**共用同一个** `checkModel`
（`@agentsws/model-gateway`），画的也是同一个三格小清单（`components/models/model-check-steps.tsx`）。
官方接口那一侧不开后门：云那条 provider 点「测试」走同一套三步；它的默认型号
`deepseek-flash` 在内置价目表里写明能看图（官网价目页 FEATURES 的 Vision 一行），测试钉住。

不通说人话：

| 实际情况 | 界面上那句话 |
|---|---|
| 401 / 403 | 密钥不对，或者这把密钥没开通这个模型 |
| 402 / 余额相关 | 这个账户余额不足 |
| 404 / DNS / 连不上 | 接口地址填错了，或者这台机器连不上它 |
| 超时 | 连上了但一直没回，可能要走代理 |
| 文字通了、图看不了（WP127） | 这个模型看不了图，Agents 工坊要求模型能看图。换一个能看图的再试，常见的有：gpt-4o、gpt-4o-mini、claude-sonnet-4-5、qwen-vl-max…（**只列公开型号名，不是推荐**，契约 `VISION_MODEL_EXAMPLES`） |

第 ③ 步上游回的是余额不足 / 超时 / 限流时，照原样报那一档——把"余额不足"说成"看不了图"，
用户会去换一个本来就能用的模型。

**能力声明**（WP127，契约 `ModelProvider.capabilities: { vision; image_generation }`，只加）：
上一次验证的结论就是这条 provider 的 `vision` 声明，装配时带上；没验证过就不声明（"不知道"
不等于"不能"）。声明了 `vision: false` 的，带图的请求在网关就拦下并说「当前模型看不了图」，
不花钱。换了模型名，上一次的结论不算数。

**老用户**（升级前配的模型没按三步验证过）：设置页「模型」顶部一条提示——还没验证过就请他点
一次「测试」，验证过看不了就明说并列常见能看图的型号。**岗位卡上不阻塞**：岗位照常干活，
只有需要看图的那一步（读手册、看图片风格）如实说「当前模型看不了图」。

**生图单独一档**（WP127）：设置页「模型」分两块——「文字与看图」「生图」。生图可以不配
（要出图的岗位出图时说一句人话让人去配，`NO_IMAGE_MODEL_ZH`）；能选的只有接上了、有生图口的
那几条（Agents 工坊官方接口 / OpenAI 兼容口，走 `/images/generations`）。官方接口出图按张扣积分，
单价在 `pricing.json` 的 `ai.image`，设置页上**常显**；上游只回了几张就只收几张，一张没回一分不扣
（`packages/cloud-entry` 的 `/v1/ai/images/generations`）。生图那一档存在工作区模型设置的
`defaults.image` 里，跟"跟随公司默认"与"从某个品牌复制"一起走。

### 2.3 用我的 DeepSeek 账号登录（WP134，Luoye 09-24 定）

第三种模型来源：**不用建 key**，用 DeepSeek 账号在系统浏览器里登录一次，按账号里的余额扣。
按 09-16「能用 dsh 官方方案的都用官方」，登录流程是 dsh 0.1.7 官方的
`@deepseek-ai/dsh-deepseek-account-platform`（系统浏览器 PKCE），我们一行 OAuth 都没写。

一条线走下来，卡上只说当前这一步（向导的第三张大卡与设置页「模型」的第三张卡**是同一个件**，
`components/models/deepseek-account-login.tsx`）：

1. **点「用 DeepSeek 账号登录」**——服务进程这时才挂上官方模块（默认关，见下），起一次登录，
   拿到授权页地址交给**系统浏览器**（桌面壳里走现有的 `openExternal`，普通浏览器里是新标签页）；
2. **「已在浏览器里打开 DeepSeek 的登录页。登录并点同意，这一页会自己接上。」**——外加「没看到浏览器？再打开一次」
   与「取消」。浏览器点完同意，平台把它带回**服务进程自己的端口**上的 `/oauth/callback`
   （官方模块注册的路由，自己校验 state + PKCE；不另开端口）；
3. **登上了**：「已登录：{账号名}」「余额 ¥42.50 · 另有赠送 ¥10.00」，接着**自动**存这条模型来源、
   跑 §2.2 那三步验证——三步都过才亮「下一步」。默认型号是官方目录里能看图的那一档
   `deepseek-flash`（出处与"未核"见 `packages/model-gateway/src/providers/deepseek-account.ts`）。

说人话：

| 情况 | 那句话 |
|---|---|
| 余额查不到 | 余额暂时查不到——DeepSeek 那边这会儿没回话。不影响用它干活……（**不显示成 0**） |
| 登录失败：网络 / 协议 / 过期 / 存储 | 连不上 DeepSeek…… / DeepSeek 那边的回应不对…… / 浏览器里一直没点完，这次登录过期了…… / 这台电脑上存登录凭据的地方写不进去…… |
| 取消 | 已取消。（迟到的浏览器回调不会再把人登进去——官方保证） |
| 验证时 401 / 403 | DeepSeek 账号的登录失效了。点登出，再登录一次。 |
| 验证时余额不足 | DeepSeek 账号余额不足，去开放平台充值后再测。 |
| 不是本机档（Docker / 托管） | 卡上只有一句为什么不能用：授权完浏览器要回到这台电脑上的 Agents 工坊，放在服务器上的回不来 |

**数据驻留：境内**（卡上一个小标签）。**凭据**：令牌只进 dsh 自己的本机凭据库
（`<DSH_HOME>/.credentials.yaml`，`DSH_HOME` 在数据目录**旁边**、所有 dsh 场景共用一份，见 docs/79），不经过 AI、不进日志、不进我们的库、不上云；
界面与 `/v1` 只看得到「登录了没有 / 账号名 / 余额」。**登出** = 官方先删本机凭据、再在后台调平台
logout；这条模型来源随之摘掉。推理走 `api.deepseek.com` 的 Messages 口、令牌放 `x-dsh-auth-token` 头
（官方写法），**不走**我们的 OpenAI 兼容客户端。

**默认关**：没人点这张卡，服务进程里一行官方账号模块的代码都没有；profile 层（`profiles/agentsws/cordis.patch.yml`）
那一行仍写死关着（docs/42 红线 7 的 WP134 补注）。截图：`docs/assets/workstation/deepseek-login-*.png`（替身账号）。

「还没接模型」那条黄条（`no-model-banner.tsx`）**在向导期间不出现**——向导第 ① 步问的就是这件事，再顶一条黄条等于同一句话说两遍。向导完成后若仍没接（走了演示旁路）才出现。

## 3. 第 ② 步：贴一个网址，剩下我们填

一个输入框：**官网网址或 Amazon 商品 / 店铺链接**（可再加一条）。另有「还没有网站」旁路（沿用 WP79 的 `none`，退回最少的手填）。

### 3.1 花多少钱

用官方接口时这一步**计入那 10 积分**，所以：

- 开跑前显示预估（`estimateCredits`）；
- **封顶 `DEFAULT_BRAND_INTAKE_CAP_CREDITS = 2`**，超了就停，不问、不续；
- 停下来的时候**已经抓到的照样交**。一个填了一半的档案卡仍然帮用户省了事，而"超预算了所以什么都不给你"是两头落空。

2 这个数是对着 10 定的：分析花掉 2，剩 8 还够几十轮便宜档对话。一个新用户不该在第一分钟就把赠送的额度烧光——那样"送 10 积分"反而变成一个坏印象。

单价 `CREDITS_PER_PAGE = 0.15`（抓取本身不要钱，要钱的是喂给便宜档模型的那些 token）。官网一轮最多 12 页 ≈ 1.8，正好压在封顶下面：封顶不是摆设，但也不该在正常情况下就撞上。

### 3.2 抓哪几个页面，为什么就这几个

**官网：**

| 页面 | 为什么非它不可 |
|---|---|
| 首页 | 品牌名、logo、主色、一句话定位、社媒链接，八成都在这一页 |
| 关于 | 一句话定位与口吻样例最好的来源（首页是广告词，关于页是人话） |
| 联系 | 客服邮箱 |
| 政策页 ×4 | 退换货 / 物流 / 保修 —— 客服岗第一天就要用 |
| 商品页 ×N | 主打商品、币种、价格 |

**政策页要硬探那几条固定路径，不能只信 sitemap**：Shopify 的 `sitemap.xml` 里**没有** `/policies/*`，但那几条固定路径全都 200。只走 sitemap 的结果是一条政策知识都建不起来——而那恰恰是客服岗最要的东西。

**Amazon：**

| 贴进来的 | 拿到的 |
|---|---|
| 商品链接 / ASIN | 这一个 listing 的全部（标题、品牌、五点、价、评分与评论数、类目、变体） |
| 店铺链接 | 前 N 个商品的卡片（标题 + 价 + 图），**不逐个进 listing 页** |

"不逐个进"是有意的：一个店铺 20 个商品就是 20 次请求，第一版档案根本用不上那么细。要细的，用户确认完之后再单独跑。

### 3.3 字段表

每一格都是 `BrandIntakeField<T>`，**没有裸值**。抓不到的字段**不出现**，而不是出现一个空字符串——界面按"在不在"决定画不画那一行，空字符串会画出一行空格子，比没有更糟。

| 字段 | 从哪来 | 典型把握度 |
|---|---|---|
| `brand_name` | `jsonld:Organization.name` → `og:site_name` → `<title>` 第一段 | high / medium |
| `legal_name` | `jsonld:Organization.legalName` | high |
| `logo_url` | `jsonld:Organization.logo` → `apple-touch-icon` / `icon` | high / medium |
| `primary_color` | `meta[theme-color]` → CSS 变量里的 `--brand-*` | medium |
| `one_liner` | `og:description` | high |
| `category` | Amazon 面包屑 | medium |
| `storefront_platform` | 页面自己漏出来的（`cdn.shopify.com` / `woocommerce` / Magento） | medium |
| `products[]` | `jsonld:Product` / Amazon `#productTitle` + `data-asin` 卡片 | high / medium |
| `markets[]` | Amazon 域名后缀 → 国家码 | medium |
| `languages[]` | `og:locale` | high |
| `currency` | `jsonld:Offer.priceCurrency` | high |
| `social_links[]` | 首页上指向那几个域的链接 | medium |
| `support_email` | 联系页的 `mailto:` | medium |
| `policies[]` | 硬探 `/policies/*`，**按内容判** | medium |
| `tone_samples[]` | 关于页正文 | medium |
| `rating` / `reviews_count` | Amazon listing | medium |

价格一律**原样存**那串字（`$19.99`、`¥129`）：不换算、不补币种、不猜。

### 3.4 出处与把握度

每一格拖着三样东西走：

- **`evidence`** —— 哪个网址的哪一段。`quote` 是页面上的原文片段（截到 200 字），不是我们的复述:人核对的时候要能在页面上搜到这串字。`locator` 说"从哪一层拿的"（`jsonld:…` / `og:…` / `selector:…` / `model`）。
- **`confidence`** —— 三档，因为界面上只分三种画法：

| 档 | 什么情况 | 界面 |
|---|---|---|
| `high` | 结构化数据里明写的（JSON-LD、og） | 直接显示 |
| `medium` | 从页面结构推出来的 | 显示 |
| `low` | 模型从正文里抽的，或只有一处弱证据 | 显示并标**「请确认」** |

- **`edited`** —— 用户手改过没有。

第三样是最容易漏又最伤人的那一样。`mergeProfile` 只有一条规则：

> **用户改过的格子，整格不动。**

不是"新值把握度更高就覆盖"，也不是"新值非空才覆盖"——就是不动。用户上周把品牌名改对了，这周换了新品重跑一次，我们又把它覆盖回错的，这种事只要发生一次，「重新分析」这个按钮就再没有人敢按。**一个按钮只要有一次吃掉过你的手工修改，它就死了。**

另外两条：这一轮没抓到、上一轮有的，**留着上一轮的**（抓不到不等于"这一格现在是空的"，可能只是那天那个页面 502 了）；改成空 = 这一格我不要，删掉而不是留个空值。

### 3.5 结果页 = 一张可编辑的品牌档案卡

图形化（logo、色块、商品缩略图、标签），字段旁一个小铅笔即改，「看着没问题」一键确认。确认后写入：

- 组织 / 品牌（工作区）名与基本信息（52 O4）；
- `packages/knowledge` 里生成首批知识条目（政策要点、商品卡），**标来源「自动分析，待核」**——知识卡一律以 `proposed` 落地，人来激活；承诺类（定价 / 政策 / 边界）永不自动激活；
- WP120 persona 要用的品牌上下文；
- 各岗位首页数字块的默认币种 / 市场。

任何一条之后都能在对应设置页手改。「**重新分析**」按钮保留（改了网址或换了新品时用），按 §3.4 那条规则重跑。

分析在后台跑（通常几十秒）：用户可以先去 ③ 选岗位，回来看结果；用呼吸标记表示「Agent 在干活」（36 §12）。

## 4. 抓取边界与隐私

1. **只抓公开页面。** 跟用户在浏览器里看到的是同一份 HTML。不登录、不用任何卖家 API、不碰 Seller Central。
2. **不带凭据。** 请求上只有 `User-Agent` 与 `Accept`，一个 header 都不多。UA 认得出是我们（`agentsws-brand-intake/1.0 (+…)`）——被站长封是他的权利，但他得先知道要封谁。
3. **遵 robots。** `Disallow` 的路径一个都不抓。robots 读不到就按"可以抓"走（读不到不等于禁止，但读到了就算数）。通配符**整条编译成正则**：取"第一个 `*` 之前的前缀"的话，Shopify 那条 `/*/cart/` 等于 `/`，每一家 Shopify 店都会被判成整站禁抓。
4. **合理频率。** 页面预算封顶（`BRAND_INTAKE_MAX_PAGES = 12`），超时 10 秒，不重试。
5. **抓不到就说抓不到，不编。** 每一页的成败都如实进 `pages`，失败带一句人话（`这个页面不存在（404）`、`Amazon 把我们挡住了（验证码）`）。
6. **外部文本是数据，不是指令。** 进知识库的那一份走 `EXTERNAL_FENCE` 围栏。

关于数据去哪（Luoye 09-19 的边界）：默认本地优先；用户**开通云端服务或跑长程任务时**，数据与上下文会上云，按最小必要、加密、可导出可删除来管。这一步用官方接口跑分析，抓回来的页面正文就会经过云端——这不违反任何规则，但要让用户知道：档案卡上那句话说明白"这一轮分析用的是 Agents 工坊的接口"。用自己的模型接口时，这一步不经我们的云。

## 7. 还没定的

- **10 够不够。** 按 `pricing.json` 的单价，一次基础分析封顶 2 积分，剩 8 够几十轮便宜档对话。真实转化率出来之后这个数要复议（`bonuses.json` 的 `needs_decision` 里也记了一份）。
- **模型抽取那一层**目前只在契约与把握度上留了 `model` 这一档，解析器本身还全是结构化读取（JSON-LD / og / selector）。结构化读不到的站（纯图片站、SPA）现在会得到一张很空的档案卡——那一层要不要补、用哪一档模型，等第一批真实网址试过再定。

## 8. WP122 在这一条链路上加了什么（2026-09-19）

`analyzeSite` / `analyzeBrand` 多了一个**可选的 `keepHtml`**（只加不改）：开着才把
抓回来的 HTML 原文留在结果的 `documents` 里。

为什么是个开关：一页 HTML 最多 400 KB，一轮 12 页就是 5 MB。**品牌档案那条路
解析完就不要它了**，让它跟着结果一路传到界面是白费内存。要它的只有一个调用方——
设计规范抽取（71 §2 第一条）要在**同一次抓取**上再读一遍 CSS，重抓一遍别人的站
是我们不该做的事。

`apps/server` 这一侧：`createBrandIntake` 把最近那一轮的 `documents` 按工作区记在
内存里（`latestDocuments`），与 run 同一条命——进程重启就没了，那时候设计规范
那一侧会如实说「还没有抓回来的页面」，**不偷偷去抓**。

档案卡上多了一行「设计规范：已抓到 N 色 · N 字体 · N 个 logo」+「上传品牌手册」。
那一行自己取数，查不到就整行不出现（见 `components/design-md/design-spec-row.tsx`）。
