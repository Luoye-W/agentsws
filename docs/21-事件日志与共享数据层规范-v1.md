## 1. 事件日志

```ts
type Event = {
  id: string /* ULID，时间有序 */; schema_version: number
  workspace_id: string; type: string /* 'approval.decided' */
  at: string; actor: { kind: 'person' | 'agent' | 'system' | 'sentinel'; id: string; run_id?: string }
  subject?: ObjectRef; correlation: { trace_id: string; run_id?: string; work_item_id?: string; change_id?: string; execution_id?: string }
  payload: unknown /* 已脱敏；秘密从不进 */; payload_encrypted?: { key_id: string; blob: string } /* 含个人数据的部分 */
  prev_hash?: string /* 可选链式校验 */
}
```

- 存储：SQLite 表（本地）/ Postgres（托管）；按 workspace 分区；**从不 UPDATE / DELETE**（删除请求走 §4）
- 回放：`replay(run_id)` 重组 prompt（17 §6 用例 1）；`replay(work_item)` 重建工作项时间线
- 版本：`type@version`；读取器按版本分派到迁移器；写入永远最新版
- 保留：默认永久；`payload_encrypted` 的密钥按 §4 可销毁
- 统计数据（干预计数、召回计数）是事件的聚合表，可重建，不进内容仓

## 2. 共享数据层基础对象

所有业务记录共用信封：

```ts
type Record<T> = { id; schema_version; workspace_id; owners: person_id[] /* 首位为主 owner；授权关系另建表 */; scope: RangeRef[]; sensitivity: Sensitivity; source?: { package?: string; connector?: string; external_id?: string }; created_at; updated_at; version: string /* 乐观锁 */ } & T
```

核心实体（v1）：Customer、Contact、Company、Thread、Message（引用事件）、Order（投影，Shopify 为真源）、Shipment、Product（投影）、Creator（红人）、Campaign、WorkItem、ScheduledTask、WorkflowInstance、FactCard、Skill（元数据，正文在内容仓）、Package（已装）、ApprovalItem、StagedChange。

字段分级在实体 schema 上声明：`cost_price: confidential`、`customer.phone: confidential`、`supplier_quote: confidential`；默认 internal。

## 3. 访问

- 所有读写经服务契约；**没有直接 SQL 面向业务代码**；分析子代理的 SQL 只读白名单（Commerce Agents A10）
- ACL：Casbin 策略由 05 scopes 编译；查询在数据层加过滤（不是应用层过滤）
- 存储档切换只换配置：SQLite ↔ Postgres 用同一 migration 集（SQL 方言差异在 driver 层）

## 4. 删除与遗忘（GDPR）

- 个人数据字段加密存储，每个主体一把**独立随机生成、不可从主密钥重派生**的主体密钥；"删除某客户"= 销毁该密钥 + 记 `privacy.erased` 墓碑；删除必须覆盖：事件日志密文、raw 原始材料区、dsh 会话文件、trace、向量索引、缓存、备份（恢复后重放墓碑）、远程 Backend / SaaS（通知删除）（09-08 改，评审 I10）
- 保留期：工作区策略可设（如客户 3 年无交互自动匿名化）
- 导出：`export(subject)` 给出该主体的全部记录（可携带权）

## 5. 版本与迁移策略

- 记录与事件都有 `schema_version`；升 major 时提供迁移器；**迁移器链（upcaster chain）永久保留**，任何历史版本都能读到最新形状（09-08 改）
- 合成数据集随 schema 版本一起发布（模拟回路的基线不废）
- 备份：SQLite 夜间快照 + 事件日志追加式复制；恢复 runbook = 02 文档

## 6. 一致性用例

1. 任何对事件表的 UPDATE / DELETE 被数据层拒绝
2. 写入旧版 schema 的记录被拒；读旧版记录经迁移器返回最新形状
3. 无 workspace_id 的记录写入被拒
4. 销毁密钥后，该客户的历史事件 payload 不可解密但事件仍在
5. 售后客服查询 Product 不返回 cost_price（过滤在数据层，SQL 层面验证）
6. 乐观锁：并发写同一记录第二个 409
