# 开工顺序

> **2026-09-08：本文第一至第五阶段被 `31-独立评审回应与修订计划.md` §2 取代。** 保留作历史。第一阶段 = 一个真实业务闭环（独立站售后客服 L1）+ 最小安全底座；个人端不再用 dsh 原生 UI。

只讲先后与依赖，不排日期。每一步的产出是下一步的前提；标 ∥ 的可以并行。

## 第一阶段：地基（不碰业务）

1. **仓库与版本锁定** —— 本仓建立；`profiles/agentsws/package.json` 锁定 `@deepseek-ai/dsh-*` 到 `0.1.3-alpha.1`；选定许可证；`agentsws init` 能拉起一个空的 dsh profile。
   *为什么先做*：所有后续代码都依赖一个确定的 dsh 版本。
2. **dsh-adapter + 契约测试** —— 封装我们依赖的每个 seam：`tools/pre-execute`、`tools/post-execute`、`ctx.approval` answerer、`systemPrompt.section/context`、`ctx.tools.restrict`、SDK client、preset 挂载。每个 seam 一组契约测试。
   *为什么第二*：这是第一行业务代码之前的保险；以后升级 dsh 只看这里红不红。
3. **core 包（框架无关）** —— 借 Commerce Agents：Backend 角色契约基类（读免费 / 写只 stage / None 不伪造）、gates（provenance、guardrail）、fencing、事件类型。纯 TypeScript，不 import dsh。∥ 可与 2 并行。
4. **外部 MCP server 三个** —— 知识库检索（先接一个本地 markdown 目录）、Shopify 只读、飞书文档只读。每个员工实例配一条 `mcp-client` entry 即可用。
   *为什么这么早*：一行 dsh 源码不碰就能演示价值；Claude Code / Codex 也能接，天然引流。

## 第二阶段：让一个人用起来（个人端）

5. **职责 preset 两个 + 开源 skill 初版** —— `presets/kefu`、`presets/kol`，各挂 customer-care / kol-outreach skill（L1：起草、人批）。preset 里用 `ctx.tools.restrict` 限工具集，用 `deployment:persona` 遮蔽人设。
6. **个人端积木** —— 装 dsh-genui 做展示类积木；我们自己写审批卡插件（动作回宿主执行器，不回模型）。
7. **换机迁移的目录纪律** —— 从这一步起所有用户态写入 `~/.agentsws/` 四区结构（见 02 文档）。export/import 命令可以晚做，**目录纪律不能晚**。

到这里一个人已经能在自己电脑上用 agentsws 干客服和红人的活（L1）。

## 第三阶段：让一家公司用起来（公司公共层）

8. **协同服务 MVP** —— 身份与职责模型（复用飞书通讯录）→ 共享数据层（Postgres，SQLite 起步）→ 事件日志。职责四件套（权限作用域 / 首页积木 / 技能包 / 通知路由）在此落表。
9. **审批总线** —— dsh answerer 插件 → 协同服务 → 飞书卡片；卡片回调写 `approved_change_ids` → 调执行器 apply；apply 时重跑 guardrail。所有改变 Agent 行为的东西走这一条队列。
10. **渠道** —— fork `dsh-channels`，采用其 `ctx.channels` 契约；贡献 WhatsApp Business 与 email 适配器（评估 dsh-email 能否改造为 email 适配器）；出站能力挂在契约的 `send` 上。外部接收层做去重 / 队列 / 重试，最后一跳才落 dsh。∥ 可与 8–9 并行。
11. **持久调度器** —— 外部（BullMQ / Temporal 级别即可）；到点用 SDK 起 headless run 或唤醒 session。依赖 8（要知道给谁跑）。
12. **两层同步协议** —— 个人端上交摘要 / 事实、公司下发知识 / 任务 / 技能；同步引擎选型在此定（收在接口后）。依赖 8。

## 第四阶段：知识与界面

13. **内容仓 + 权限感知检索** —— git 隐藏在知识库 UI 之下；草稿 CRDT、发布才提交；深读 Co-Engram 决定 vendored 还是借数据模型自写。依赖 8（ACL）与 9（提议走审批）。
14. **工作台前端** —— 独立壳，经 SDK/ACP 对接；第一屏 = 审批队列 + 日报；职责积木注册表；自适应层先只做"建议"。依赖 8、9。∥ 可与 13 并行。
15. **技能公司库** —— registry、semver、作用域、晋升走审批队列、按作用域分发到个人端。依赖 9、12。

## 第五阶段：变现与发布

16. **换机迁移 export/import** —— 加密包、manifest、schema 版本迁移、"需重新授权项"清单；公司实例一键恢复 runbook。
17. **付费插件壳 + 云端大脑** —— `LlmAdapter` 路由领域推理到云端；替换职责包 Backend provider；高级 skill 包。开源版与付费版跑同一套 evals，差距即卖点。
18. **开源发布** —— 一键安装包（Docker Compose / 单二进制）、BYOC 配置向导（Supabase/Turso）、文档站（agentsws.com）、贡献指南、上游 PR（dsh-channels 适配器）。

## 贯穿全程

- 每周 diff 上游 `.agents/notes/`（dsh 没有 CHANGELOG）。
- 不依赖 `experimental/*`、`e2b`。
- evals 从第 5 步起就写，每个职责包一组；L1→L2 的晋级以 eval 与采纳率为据。
