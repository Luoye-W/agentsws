# 技能分层与学习回路规范 v1（契约 #11 技能部分 · #12）

| | |
|---|---|
| 日期 | 2026-09-08 |
| 对应 | 06 §3、§5.1、§5.2（不自动改，次日审批项）；07 §1 摩擦信号与晋升判据；05 §1.4 AutomationSpec；Agent Skills 规范 |
| 原则 | ① skill = Agent Skills 格式 + 段级元数据 ② 三层叠加按段 ③ 每个共享 skill 有负责人 ④ 学习只产提议，不自动改 ⑤ 每条修改带出处，可回滚 |

## 1. 对象

```ts
type Skill = { name: string; tier: 'package' | 'company' | 'department' | 'personal'; owner: person_id | 'package'; version: string; base?: { tier; version }; sections: Section[]; evals: string[]; source?: { package, version } }
type Section = { id: string /* 隐藏 ULID，首次保存分配，存 sidecar */; heading: string; body: string; origin: 'authored' | 'learned'; learned_from?: { lessons: string[]; at } }
type Overlay = { skill: string; tier; ops: ({ op: 'replace' | 'append' | 'remove'; section_id; body? })[]; base_version: string }
type Lesson = { id; run_id; assignment_id; skill; section_id?; signal: 'edit_diff' | 'reject' | 'redirect' | 'guardrail_hit' | 'tool_retry' | 'reflection'; strength: 'strong' | 'medium' | 'weak'; text: string; confidence: number; confirmations: number; status: 'pooled' | 'proposed' | 'accepted' | 'ignored' | 'refuted' }
```

解析：`resolve(name, actor)` = 包基础版 → 公司 overlay → 部门 overlay → 个人 overlay 依次按段应用；同段冲突（上游改了我也改过的段）→ 生成 `skill_conflict` 通知（个人队列）二选一或手合。

## 2. 操作

| 操作 | 谁 | 走什么 |
|---|---|---|
| 个人化修改 | 本人 | 直接写个人 overlay，版本 +1，可回滚 |
| 晋升 | 本人 / 每周巩固 | `skill_promotion` 审批项（14）→ 目标负责人；eval 不回归；通过后目标版本 +1，源 overlay 移除已合并段 |
| 下沉 | 系统 | 上游新版 → 各层 overlay rebase；冲突进队列 |
| 排除 | 本人 | 个人 exclude 列表，不影响他人（teamai） |
| 发布到市场 | 公司负责人 | 打成 `kind: skill` 包（23） |

## 3. 学习回路

```
信号（14 §9 的决定事件、17 的 tool.result{error}、guardrail.hit、运行后反思步骤）
 → Lesson 池（每人，零打扰）
 → 夜间整理：聚类、去重、与现有段比对、置信度过线（默认 0.6）→ 生成 skill_lesson 审批项（"建议给你的 X 改一段" + 证据）
 → 人：接受 → 写个人 overlay（origin: learned）；忽略 → 置信度衰减；驳回 → refuted
 → 每周巩固：跨人聚类，同一段 ≥ 2 人接受相似修改 → 自动生成 skill_promotion 提议给部门负责人
```

置信度：确认 +0.15、忽略 ×0.7、驳回 → 0；晋升判据（07 §1 第 3 条）：≥ 0.9、≥ 5 次采用、≥ 2 个贡献者、≥ 14 天。策略层永不进学习回路（连提议都不给，只有 owner 手改）。

## 4. 健康指标（Agent 健康看板输入）

按 (skill, tier, assignment)：干预率（edited + rejected）/ total、采纳率、guardrail 命中、lesson 池大小、接受率、沉默段（从未被引用的段）、上游冲突数。

## 5. API

`GET /skills?tier=`、`GET /skills/{name}/resolved?actor=`、`PUT /skills/{name}/overlay`（个人）、`POST /skills/{name}/promote`、`POST /skills/{name}/exclude`、`GET /lessons?status=`、`POST /learning/consolidate`（手动触发夜间整理）、`GET /health/skills`。事件：`skill.overlay.changed / promoted / rebased / conflict`、`lesson.pooled / proposed / accepted / ignored`。

## 6. 一致性用例

1. 公司版改标题不改段 id → 个人 overlay 仍叠上
2. 同段两边都改 → conflict 通知，不自动合
3. 五次相同纠正 → 一条 lesson，confirmations=5，次日一条审批项；夜里没有任何 overlay 变化
4. 策略层 skill 段被学习回路选中 → 被过滤，不生成提议
5. 三人接受相似修改 → 周巩固生成一条晋升提议且 evidence 含三人
6. 晋升 eval 红 → 预检 blocked
7. 排除某 skill → 该人的 RunRequest.skills 不含它
