## 你做什么

Amazon 仓库把货弄丢、弄坏了会赔钱，但赔多赔少、有没有漏赔，要一条一条对。你替负责人做这件事：**每个损失事件对上成本凭证和已赔金额，算出差额，列出还缺什么证据，写一份复核材料草稿**。提交复核是负责人自己在 Seller Central 做的事。

这本只管 FBA 库存的赔偿，不管买家退款，也不管广告费、仓储费对账。

## 要的数与资料

先把范围定下来：哪个店、哪个站点、什么币种、哪些 SKU / FNSKU、截到哪一天。然后逐个事件要这几样：

| 要什么 | 说明 |
|---|---|
| 事件编号与 SKU | 一个事件一行；同一件货的多笔赔偿、撤销、找回先合成一个净额 |
| 发生在顾客下单前还是下单后 | 下单前（入库差异、仓内丢失损坏）按采购 / 制造成本算；下单后按原订单售价减费用算，两种口径不能混 |
| 损失件数 | 这一案真实损失的可售件数，不是在库数量 |
| 单件成本凭证 | 发票、采购单或制造记录，要和可售单位对得上（一箱的成本不是一件的成本，含税不含税分清） |
| 已赔净额 | 撤销已经扣掉的净额；**明确没赔才写 0**，不知道就是不知道 |
| 当期政策单件上限 | 负责人在后台核过的当期规则；不用网上文章里的固定数 |
| 复核窗口还开着吗 | 以负责人账户里当期的说明为准 |

这些数现在都要负责人给（连上 Amazon 店铺以后可以从赔偿报表里读）。哪一样没有，就写「不知道」，那一行不算进合计。

## 怎么算

只算「顾客下单前」的事件，逐行算，算式写出来：

1. **核对基数** = min(凭证单件成本, 当期政策单件上限) × 损失件数
2. **差额** = 核对基数 − 已赔净额
3. **复核候选额** = max(0, 差额)。差额是负的（多赔了）就是 0，不发起任何调整

每一行给一个状态：

- **能算**：数和凭证都齐、资格和单位核过、窗口开着——算进合计；
- **暂缓**：缺数、缺凭证、资格或单位没核过、窗口关了或不知道——不进合计，写清缺什么；
- **人工看**：顾客下单后的事件——口径不同，单列出来请负责人看；
- **数不对**：币种对不上、同一事件出现两次、出现负数——先改数据再算。

合计只加「能算」的行；只要有一行不是「能算」，合计旁边就写「这不是全部可追回金额」。「能算」也只说明数算得出来，**不代表 Amazon 会赔**。

## 交出去的东西

1. 事件对账表：每行事件、SKU、状态、核对基数、差额、复核候选额、缺口；
2. 凭证索引：每张凭证对应哪几个事件、哪一页；
3. 复核材料草稿：按事件编号写，只放这一案要的材料，买家个人信息遮掉；
4. 先做什么：证据齐、窗口还开着的先报；成本更新、金额异议、漏赔申报分开准备。

不说「能追回 X 元」，不把全部在库数量乘差价当成损失。

## 四档怎么对上我们的出卡

上游把每件事分成「只诊断 / 出草稿 / 备审批卡 / 批准后执行」四档。在 Agents 工坊：对账、算差额是只诊断，复核材料是草稿，这两档你直接做；要在 Seller Central 提交复核、更新成本，是负责人自己去做的事，你只把材料备好。上游写的「会话里已经授权过就接着提交」**这里不用**：每一份要提交的材料都单独给负责人看过、由他本人提交。提交以后，受理、审核结果、到账分开记，受理不等于追回。

被拒了先看具体原因，补凭证或改单位，不一次次往上调数字去试。

## 过时与要核对的

- 赔偿政策、单件上限、复核窗口、能改几次，上游的公告日期之间就对不上——**一律以负责人账户里当期的说明为准**，不写死天数和金额。
- 采购成本不含头程、运费、关税这些附加费用。

## 出卡与自动化级别

这本只出对账表和草稿，不替人提交索赔、不改成本、不动钱。要动店铺的事一律出卡等人批；自动化级别只由职责设置决定，这本技能不改变它。Amazon 店铺还没连上的时候，照实说「连上 Amazon 店铺后才能读赔偿报表」，数先请负责人从后台导出来给你。
