## 你做什么

把「英文翻成目标语言」换成一件能追溯的事：**商品事实一字不改，当地买家怎么搜、怎么说、担心什么、在什么场景用，全部按目标站点重来**，再用当期站点规则检查、小范围验证。

- 只管 Listing 文字、后台关键词、图片和视频的本土化。广告怎么投交给「亚马逊广告」职责（还没有这条职责时请负责人自己定）。
- 品牌刚起步、要从零准备页面，用 `amazon-brand-prep-listing`；单个站点的页面体检，用 `amazon-listing-optimizer`。

## 要的数与资料

先记下：从哪个站点、哪种语言，改到哪个站点、哪种语言；ASIN / SKU、商品类型、变体、计划上线日、谁负责审。

**源文案不是事实来源。**另建一张产品事实表：单位、兼容、材料、认证、警告、哪些说法不能用。事实表只认实物、说明书、检测报告这类凭证。

当地证据按这个顺序找，每条记下来源、日期、站点、数和样本范围：

| 来源 | 标成 |
|---|---|
| 目标站点的品牌分析、搜索词表现（Search Query Performance） | 店铺实数 |
| 目标站点的商机探测器（Product Opportunity Explorer） | 店铺实数 |
| 目标站点的评论、客服、退货主题 | 店铺实数 / 你给的数 |
| 目标站点当前的竞品页面 | 推断（记下看的日期） |
| 机器翻译出的词、词典里的词、第三方估的搜索量 | 推断 |

目标站点的数拿不到就写「不知道」，不拿美国站的数顶上，也不填 0。第三方搜索量和 AI 建议只算旁证，替代不了当地真实的搜索行为。

## 每个字段先定怎么处理

不全文统一机器翻，每个字段先选一种：

| 处理 | 什么时候用 |
|---|---|
| **直译** | 事实和说法能一一对上，比如纯规格；单位仍要检查 |
| **改写** | 事实不变，但术语、单位、语序、场景、说服方式按当地重写；标题、五点多数是这种 |
| **重做** | 原来的创意概念在当地不成立，要重新写需求；节日素材、靠人物和生活场景的视频常常是这种 |

商品事实只能直译或改写，不能重做。

## 当地关键词

按这几组整理：核心品类（当地人指这个东西用的词）/ 功能和结果（只写能证明的）/ 场景和人群 / 规格和兼容（单位、型号、拼写要精确）/ 口语和同义（地区差异、复合词、性数变化）/ 季节和节日（只在相关时段用）/ 不用的（别家商标、无关的大流量词、没证据的说法）。

| 当地原词 | 中文意思 | 意图 | 来源和日期 | 数 | 放哪 | 状态 |
|---|---|---|---|---|---|---|
| | | 品类 / 功能 / 场景 / 问题 / 规格 | | 标成哪类 | 标题 / 五点 / 后台 | 用 / 测 / 不用 |

不把美国站的长尾结构硬套到别的站点。优先留目标站点里真有人搜的词。

## 改写文字和图片

**文字**按这个顺序改，每个字段各管一段，不重复堆词：

1. 商品类型和必填属性；
2. 标题：说清是什么、最关键的差异；长度和规则以当期 Seller Central 帮助页和这个商品类型的要求为准；
3. 五点：场景、功能、证据、尺寸和兼容、怎么避免用错；
4. 描述和 A+ 文字：解释、选型标准；
5. 后台关键词：补可见字段没覆盖的自然变体；后台关键词不放别家的品牌名，不放 ASIN，不放重复词；多字节语言按字节数算。

检查拼写、语法、自然不自然、有没有说服力；商品事实和数字逐项对着事实表核；手机首屏能读；同一个说法在标题、图片里一致。

**图片和视频**语言对了不等于文化对了，逐项看：

- 当地人真会这么说，还是只是看得懂？
- 人物、住宅、道路、插座、服装、尺寸、日期、季节对不对？
- 手势、颜色、玩笑、送礼习惯、家庭角色会不会被误读？
- 字在安全区里读得清吗？
- 原创意靠的价格、优惠、评论、排名现在还是真的吗？
- 画面里是不是目标市场不卖、不送或不兼容的版本？

不合适就选「重做」，**向设计岗下需求单**：写清哪个素材、原来想说什么、当地版本怎么说、当地证据、事实依据、谁来母语审。

**安全底线**：不新增商品属性，不弱化警告；单位换算保留精度，按当地习惯写；不自己换算或补认证；受监管的说法要有目标国家的证据。

## 三道审核

1. **事实**：没有新增或弱化商品事实和安全信息；
2. **母语**：由懂目标语言的人确认自然、清楚、有说服力；
3. **政策**：目标站点当期的 Listing、知识产权和类目规则。

三道都过才算能送审。AI、翻译工具、代理商都不能替代卖家自己最后负责和审批。工具显示「翻译成功」只说明任务跑完了，不说明自然、合规或已经上线。

## 交出去的东西

1. 源和目标的范围表、产品事实表；
2. 当地关键词表，每个词标清来源和标成哪类；
3. 每个字段的处理决定：直译 / 改写 / 重做；
4. 本土化后的文字草稿、给设计岗的素材需求单、三道审核的状态；
5. 一个单变量验证（比如只换标题说法、主图文字层或一组关键词），写清基线、看哪个数、什么时候停、怎么退回。

## 四档怎么对上我们的出卡

上游把每件事分成「只诊断 / 出草稿 / 备审批卡 / 批准后执行」四档。在 Agents 工坊：查当地证据、定处理方式是诊断，文字和需求单是草稿，这两档你直接做；要替换某个站点的页面时备一张审批卡，逐字段列旧值、新值、证据和怎么退回；执行只在负责人点了这张卡之后——改之前存旧值，改完回读。上游那种「会话里已经授权就接着提交」的做法**这里不用**：每一处碰店铺的改动都是单独一张卡。

## 过时与要核对的

- 课程里讲的工具是否免费、在哪个入口、支持哪些语言、几天交付、准确率多少、覆盖哪些站点、字符上限，都是当时的快照，用前到当期官方页面和后台重核。
- 课程里「标题多少字、前多少字放主词」这类说法是讲师建议或旧规则，不同商品类型和站点不一样；Amazon 标题规则也已经改过，以当期 Seller Central 帮助页为准。
- 课程里准确率提升、曝光增长这类案例数，不写成工具的承诺；案例里的关键词也不替代你对这个 ASIN 的当地研究。

## 出卡与自动化级别

替换任何站点的页面一律出卡等人批；自动化级别只由职责设置决定，这本技能不改变它。真要写进店铺时，先用 `amazon-sp-listing-compliance` 做合规预检，再走 `amazon-sp-listing-issues` 或 `amazon-sp-listing-searchability`：先预览、等人批、写完回读。图片和视频向设计岗下需求单。目标站点的店铺还没连上时，照实说「连上 Amazon 店铺后才能读目标站点的搜索词和品牌分析报表」，先请负责人从后台导出来给你。
