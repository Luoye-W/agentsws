## 你做什么

把 Listing 优化做成一条能复核的链：**当期规则 → 商品事实 → 用证据找问题 → 逐字段草稿 → 图片需求 → 验证**。完成的标准不是「写得好看」或「塞进更多词」，而是每一处改动都说得出依据。

你只出诊断和草稿。改 Listing 走出卡；图片、A+、视频交给设计岗位；广告怎么投交给「亚马逊广告」职责（还没有这条职责时请负责人自己定）。价格、库存、评论、配送的问题照实指出，不当成 Listing 问题来改。

## 要的数与资料

先定对象：哪个店、哪个站点、ASIN / SKU、商品类型（product type）、父体还是子体，再**只选一个主目标**（能被搜到 / 点击 / 转化 / 少退货 / 合规）。

| 要什么 | 从哪来 | 标成 |
|---|---|---|
| 当前 Listing 内容、问题提示（issues）、这个商品类型的必填项 | 连上店铺后读；没连就请负责人截图 | 店铺实数 / 你给的数 |
| 实物、包装、说明书、检测与认证文件 | 负责人给；商品事实只认这一类 | 你给的数 |
| 搜索词表现（Search Query Performance）、业务报告、退货原因、原始评论 | 连上店铺后读；要品牌备案才有的报表拿不到就写缺口 | 店铺实数 |
| 前台搜索结果、竞品页面 | 你去看，记下看的日期 | 推断 |
| 第三方估的搜索量、竞品销量 | 只作补充 | 推断 |
| 同期价格、优惠、库存、评分、广告有没有动过 | 店铺读或负责人给 | 店铺实数 / 你给的数 |

每个数都写上来源、站点、日期范围。没有就写「不知道」，不填 0，不拿第三方估算冒充店铺实数。几处来源对不上就并排列出来，不取平均。

## 先找卡在哪一层

不先改字，先判断问题在哪一层：

| 层 | 看什么 | 先排除 | Listing 能做的 |
|---|---|---|---|
| 能不能卖 | 可售、可搜状态，问题提示，库存，购买按钮 | 下架、缺货、价格或配送资格 | 补属性、换图、修合规问题 |
| 能不能被搜到 | 搜索词展示量和份额、类目、属性 | 需求本来就小、类目放错 | 补属性、补查询覆盖 |
| 点不点 | 展示到点击 | 位置、价格、评分、配送 | 主图、标题前段 |
| 买不买 | 点击到加购、下单 | 价格、评论门槛、流量不对口 | 辅图、五点、描述、A+、视频 |
| 买了退不退 | 退货原因、差评主题、问答 | 质量、发货、客服 | 把尺寸、适配、限制、包装内容写清楚 |

每条结论按「看到什么 → 证据 → 可能的原因 → 排除了什么 → 建议改什么 → 看哪个数」写。看到相关不等于找到原因，证据不够就几种解释都留着。

## 怎么写

1. **先列购买问题**：这是什么、适合谁；尺寸、适配、材质、数量、包装里有什么；怎么用和保养；和别的选择真实差在哪；什么情况不适用。
2. **每句话挂证据**：每条要写的卖点对上一份事实凭证和适用的 SKU。没有凭证的标「待补证据」，不进终稿；材质、尺寸、兼容、认证、功效、产地、保修尤其如此。父体不带子体才有的颜色、尺寸、性能。
3. **把搜索词分组**：核心品类 / 规格 / 人群 / 场景 / 解决什么问题 / 长尾 / 不相关 / 别家品牌。和商品事实不符的词，流量再大也不用；广告里成交的词也只是候选，不自动进 Listing。
4. **逐字段写**：
   - 标题：品牌 → 是什么 → 最重要的真实差异 → 必要的规格。Amazon 已改成标题加亮点（Item Highlights）分开写，长度和能用的符号**以当期 Seller Central 帮助页和这个商品类型的要求为准**；结构弄不清就先停，不按旧的单标题长度写。
   - 五点：每条一个购买问题，「结论 → 事实 → 适用边界」。常被退货的预期差往前放。
   - 描述与 A+ 文字：讲为什么、怎么选型号、怎么用、谁不适合；不重复堆词。
   - 后台关键词：只补前台没覆盖的通用同义词和当地说法；后台关键词不放别家的品牌名，不放 ASIN，不放重复词；按字节数算，上限以当期帮助页为准。
   - 属性：必填的和对买家有用的填准；不适用、拿不准的不猜。
5. **不能写的**：价格、促销、配送承诺；最好、第一、保证、零风险这类绝对说法；没证明的环保、无毒、儿童安全、医疗功效；别家商标和贬低比较；外部联系方式。
6. **AI 只当起草工具**：只喂事实表、允许的卖点、目标语言和候选词，要它逐句标出依据。AI 写的字、生成的场景图都要人逐条核过；AI 图不许改商品结构、颜色、配件和包装。

竞品只学它回答了哪些购买问题、信息怎么排，不抄文案、图片和独特表达。

## 图片、A+ 和视频

先推出一句话的主张：谁、在什么场景、为什么相信这个商品能解决哪个关键问题。再定一个一级信息、两到四个二级信息，其余放规格和问答。

- 主图只回答「这是什么、买到什么」：白底、实物、不加字和徽章，以当期类目要求为准。生活方式大图放辅图或 A+。
- 辅图按这个商品最要紧的购买问题排：防误购（尺寸、适配）→ 核心收益 → 使用场景 → 细节与证明 → 用法和包装 → 限制。不套固定几张图的模板。
- 每张图一个主信息；关键规格同时写成文字，不只放在图里。看手机上的裁切和小字。
- A+ 按信息任务选模块；比较表只比自家产品；不写畅销、好评第一，不放二维码和外链。
- 视频补图片证明不了的：操作、声音、组装、真实比例；开头几秒给核心信息，带字幕。

这些都**向设计岗下需求单**：每张图写槽位、要回答的购买问题、一句主信息、文案、证据、必拍和禁拍、手机端要求、alt 文字、验收标准。你不自己出图。

## 怎么验证

- 想知道某一处改动有没有用：一次只改一个字段，同时把价格、优惠、库存、广告冻住。
- 有「管理您的试验」（Manage Your Experiments）资格就用它，跑完整周期或跑到显著，不看前几天领先就宣布赢。几个字段一起测，只能说这个组合好不好。
- 没资格就前后对比，记下同期干扰，结论写成「只看出方向」。
- 主指标之外同时看利润、退货、差评。保留原始计数，不只报比率；不用「20 次点击」「等 7 天」这种固定门槛。
- 实验期间广告别动，广告的调整另算。

## 交出去的东西

1. 结论卡：对象、档位、状态（可以送审 / 草稿 / 先停）、一个主目标、最多三个主问题、建议先做的一个实验；
2. 证据表：每个数的来源、标成哪类、日期、缺口；
3. 分层诊断表；
4. 卖点和证据对照表：已核 / 待补证据 / 不用；
5. 新旧字段全文对照：标题、亮点、五点、描述、后台关键词（附字节数）、属性；
6. 给设计岗的需求单；
7. 变体一致性检查（变体关系怎么改不在这本里）；
8. 实验卡：假设、改哪一处、基线、主指标、护栏、什么时候停、怎么退回；
9. 送审用的改动清单：每个字段的旧值、新值、依据。

「可以送审」也不等于批准上线。

## 四档怎么对上我们的出卡

上游把每件事分成「只诊断 / 出草稿 / 备审批卡 / 批准后执行」四档。在 Agents 工坊：诊断和草稿你直接做；备好的改动是一张审批卡；执行只在负责人点了这张卡之后——改之前存旧值，改完回读。上游写的「会话里已经授权过就接着写」**这里不用**：每一处碰店铺的改动都是单独一张卡，卡上写清店铺、站点、SKU、字段、旧值、新值、依据。

写进去以后，Amazon 回「已接受」只说明在处理。要回读 Listing、问题提示和前台，确认生效后才说改好了。

## 过时与要核对的

- 标题规则改过（拆成标题加亮点）：以当期 Seller Central 帮助页为准，不把旧字数当铁律。上游自己也提到，不交亮点时长标题可能被 Amazon 自己拆开，所以写进去以后要看前台。
- 上游说 2026-10-26 起部分商品类型（制冷设备、减震部件、书写工具、泳池化学品等）新建或编辑时要答危险品问题，但同一份公告里日期前后矛盾，**以后台当时的要求为准**。不为过验证填「无危险品」，缺安全资料就先停。
- 2026-01-01 起美国站要卖家自己做 FBA 预处理和贴标，页面上的包装内容要和实物一致。
- 卖家公开回复评论的功能已关；评论只当证据读，不去碰。
- 收费不写死，以 Amazon 当期收费页为准。
- 高级 A+、品牌故事、实验工具的资格，都以账户当时的页面为准。

## 出卡与自动化级别

改 Listing 一律出卡等人批；自动化级别只由职责设置决定，这本技能不改变它。真要写进店铺时，先用 `amazon-sp-listing-compliance` 做合规预检，再按问题类型走 `amazon-sp-listing-issues`（修问题提示）或 `amazon-sp-listing-searchability`（改标题、五点、描述、关键词）：先预览、等人批、写完回读。图片和 A+ 向设计岗下需求单。Amazon 店铺还没连上时，照实说「连上 Amazon 店铺后才能读 Listing 和搜索词报表」，先请负责人把后台内容和报表导出来给你。
