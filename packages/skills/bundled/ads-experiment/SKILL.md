## 你做什么

用户想知道「这一版是不是更好」。你先把实验**定好再开始**，跑满了再读结果，读完出一张卡请他选：保留 / 停 / 再测。

- 设计用 `design_ads_experiment`，读结果用 `read_ads_experiment`。**数全由工具算**：样本量、天数、p 值、提升多少，照工具回的抄，不要自己估。
- 实验本身在平台后台跑（平台自带的 A/B 工具或两版并排）。要新建 / 暂停 / 换素材，照旧走改广告那几张卡，这个技能不碰账户。

## 先定好这几样

1. **假设**：一句话，带因果——「标题里写价格，点击率会更高」。
2. **只变一样**：只换图、只换标题、或只换主文案。同时换两样，跑完分不清是哪一样起的作用；要变体就用变体计划，一版只改一维。
3. **按什么拆**：同一个人只该看到一版。平台的 A/B 工具一般按人拆；没有就按广告组并排，写明会有串流量。
4. **主指标**：只选一个。量小的账户先看点击率（量大，好判），量够再看转化率。
5. **最小提升**：提升多少才值得换。**这个数由用户定**——你先给一个建议（比如两成），说清楚越小要跑越久，请他点头。
6. **护栏**：哪几样不许变差、最多容忍差多少（CPA、ROAS、退货率…）。数同样由用户定，你给建议。

缺基准比例、每天的量时，工具会从已入库的近 30 天数里算，并告诉你从哪来；算不出就照实问，**不拿行业平均顶上**。

## 要跑多少、多久

- 工具按「显著性 0.05、把握 0.8」算每版要多少次展示 / 点击，再除以每天的量得出天数，**至少跑 7 天**（盖住一周里的起伏）。这几个都是统计上的常用默认，用户要改就改。
- 原样告诉用户：每版要多少、要跑几天、什么结果算赢。工具提醒「跑太久」时，建议把最小提升放大，或者先看量大的指标。
- **没跑满不看结果、不中途叫停。** 眼下差得再多，也可能是运气；用户问「能不能提前收」，告诉他没跑满看到的赢面靠不住。

## 读结果：保留 / 停 / 再测

跑满之后，用 `read_ads_experiment` 把每一版的单位数和成功数（第一版是基准）、护栏那几样的值交给工具。工具按设计时定的门槛判，并出一张卡：

| 工具判的 | 卡上建议 | 意思 |
|---|---|---|
| 有一版没跑满 | 再测 | 跑满再看 |
| 护栏破了 | 停 | 赢了主指标也不换 |
| 显著变好 | 保留 | 换成赢的那版 |
| 显著变差 | 停 | 留基准版 |
| 跑满了没分出高下，差别的上限也够不着最小提升 | 停 | 不值得换 |
| 跑满了没分出高下，但还可能够得着 | 再测 | 加量或延长 |

- 卡是给人选的，**出卡后等用户选**；他选了哪个，结论写回投放岗记忆里这一笔实验。选「保留」或「停」之后真去改广告，照旧是改广告那张卡、要人批。
- 卡上的建议照工具的抄。用户选了和建议不一样的，照他的记，不争辩。

## 写给人看的那几句

- 先说结论，再说数：「新标题点击率 2.48%，基准 2.00%，高了 24%，p = 0.001；CPA 没变差。建议保留。」
- 数字照工具回的抄，不四舍五入成好看的数；p 值、置信区间不懂就不提，换成「差得够不够确定」。
- 只说测过的那一群人：在美国电脑端测出来的，不说「全球都这样」。

## 自动化级别

这个技能不授权任何自动动作。实验卡、改广告的卡都由人点；技能写的是怎么判，不改职责的自动化级别。

## 不做的事

- 不偷看、不中途叫停、不把没跑满的结果叫赢。
- 不替用户定最小提升和护栏的数。
- 不自己算样本量、不估 p 值——用工具。
- 不改广告：读结果只出「保留 / 停 / 再测」卡。
