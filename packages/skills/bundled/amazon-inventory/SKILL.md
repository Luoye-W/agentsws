## 你做什么

负责人问「我该补货了吗」「还能卖几天」「这批补多少」，你**按下面的公式算给他看**：每一步写算式、每个数写出处。模型只做判断和解释，**数一律用公式算，不估**——估出来的数看着合理，却没法复现、没法追。

## 要的数

| 数 | 从哪来 | 拿不到怎么办 |
|---|---|---|
| 可售件数（FBA fulfillable） | 连上 Amazon 店铺后从库存读；之前请负责人从后台看了告诉你 | 写「不知道」，不往下算 |
| 在途件数 | 已发出、还没上架的入库货件 | 没有就问；确认没有才按 0 |
| 最近 30 天每天卖了几件，哪几天断货 | 销量报表；断货日要标出来 | 只有总数时只能算日均、算不了波动，照实说 |
| Lead Time（下单到能卖的天数，含入仓） | 负责人给最近 3–5 次实际用了几天 | 不知道就问，不用「一般 30 天」顶上 |
| 到货后还想撑多少天 | 负责人定（下一次补货的间隔） | 问 |
| 库龄 | 库存报表 | 不知道就不提超龄 |

## 公式

1. **日均（剔除断货日）**：只用有货的那几天算日均。断货那几天卖 0 不代表没人要；负责人标了断货的日子剔除，没标的连续 3 天以上卖 0 也按断货剔除，并说明剔了哪几天。
2. **可售天数** = (可售 + 在途) ÷ 日均。日均是 0 时天数算不出来，说「最近没卖动」，不说 0 天。
3. **安全库存** = Z × σ × √L。σ 是有货那几天日销量的波动（标准差），L 是 Lead Time 天数；Z 按服务水平取：90% → 1.28，95% → 1.65（默认），97.5% → 1.96，99% → 2.33。
4. **补货点** = 日均 × L + 安全库存。可售 + 在途 ≤ 补货点，就是现在该下单了。
5. **补货量** = 日均 × (L + 到货后要撑的天数) + 安全库存 − 可售 − 在途，向上取整；算出负数就是现在不用补。
6. **计划用的 Lead Time**：取最近 3–5 次实际值里**最长**的那次，不取平均；旺季另加 7–14 天缓冲（加多少问负责人）。

每一步照这个样子写出来：「安全库存 = 1.65 × 2 × √25 = 16.5」。

## 怎么说结论

- **断货线统一按 14 天**：可售天数少于 14 天，说「有断货风险」；14 到 21 天说「快到了」；21 天以上说「看着没事」，不制造风险。别处看到的 7 天、21 天分档只当提前预警。
- 有在途货时，再比一下到货日和断货日：断货日 = 今天 + 可售天数；到货晚于断货日，就说「大约会断 N 天货」。
- **库龄**：181 天起有超龄附加费，365 天起更高；90 天开始盯、120 天考虑清货方案。附加费、仓储费、低库存费**多少钱不写死**，请负责人看 Amazon 当期收费页。
- 解决断货先说「尽快补货进仓」和「接受断货、安排恢复」两条路；**不拿改价当办法**，不给定价建议（和 Amazon 官方断货预防技能一致）。

## 拿不到数的时候

Amazon 店铺还没连上、负责人也没给数时，照实说：「连上 Amazon 店铺后才能算出具体数」。然后把上面的公式讲一遍，告诉他要准备哪几样数（可售、在途、最近 30 天每天销量和断货日、最近几次 Lead Time），他给了就当场算。缺哪一样就写哪一样「不知道」，不按 0 算进结论。

## 出卡与自动化级别

这本只算数、出补货建议。下采购单、建 FBA 入库计划、确认分仓和运费都要出卡等人批（入库那一套见 `amazon-sp-fba-inbound-management`：金额写清楚、人手动确认）。自动化级别只由职责设置决定，这本技能不改变它。
