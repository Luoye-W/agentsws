## 你做什么

品牌刚起步时，页面要回答四件事：**页面怎么说、谁在买、为什么买、换个语言怎么说**。你先把证据链立起来，再让 AI 动笔，最后用一个小验证看改得对不对。

- 团队几个人只是背景，不用来判断是不是「起步阶段」；成熟品牌的单个新品也可以照这本准备页面。
- 已有页面的体检和逐字段改写，用 `amazon-listing-optimizer`；跨站点的深度本土化，用 `amazon-localization`。
- 广告怎么投交给「亚马逊广告」职责（还没有这条职责时请负责人自己定）。

## 要的数与资料

| 要什么 | 从哪来 | 标成 |
|---|---|---|
| 产品规格、限制、不能改的参数 | 负责人给 | 你给的数 |
| 能证明的卖点和凭证（检测、说明书、实物照片） | 负责人给 | 你给的数 |
| 品牌定位和说话的语气 | 负责人给 | 你给的数 |
| 目标站点和语言 | 负责人定 | — |
| 现有 Listing 和 A+ | 连上店铺后读，没连就请负责人截图 | 店铺实数 / 你给的数 |
| 聚合的买家画像（品牌分析里的人口统计） | 要有品牌备案和对应权限 | 店铺实数 |
| 评论、客服、退货里的真实反馈 | 店铺读或负责人给 | 店铺实数 / 你给的数 |
| 关键词和当期的内容规范 | 店铺读、负责人给，或你从前台看 | 店铺实数 / 推断 |

先把店铺、站点、ASIN、币种、数据时间段定下来。缺的写「不知道」，不补 0。课程、文章里的比例和时间表不当成这家店的数；你从评论里归纳的是「推断」，要写清看了多少条。

## 先弄清谁在买、为什么买

只看年龄、收入，容易想错场景。从「谁买」接着往下问，每条都记下证据在哪：

| 问 | 例子里要写的 |
|---|---|
| 谁在用 | 买的人和用的人可能不是同一个 |
| 在哪用、什么时候用 | 家里、户外、通勤、节日送礼 |
| 要完成什么事 | 真正想解决的那件事 |
| 期待得到什么 | 省时间、更安全、更好看 |
| 受什么限制 | 空间、预算、会不会装 |

- 用评论、客服记录、退货原因去**反驳**最初的想象；对不上的矛盾留着，写出来给负责人看。
- 第三方画像只算旁证；不同维度的占比不能相加，也不能当成整个品牌的画像。
- 没有人口统计报表权限时列缺口，改用合法拿到的聚合数据，不编比例。
- 不拿敏感属性给人贴标签。

## 卖点矩阵和页面怎么排

先补齐最可信的底子：规格、兼容、限制、品牌信息。再把每个卖点排成一行：

| 卖点 | 事实与来源 | 对应的场景 | 限制 | 放在哪 |
|---|---|---|---|---|
| 一句话 | 凭证编号 | 上一节的哪个场景 | 不适用的情况 | 标题 / 五点 / 图 / A+ |

页面按这个顺序说：

1. 用产品事实回答最要紧的购买问题；
2. 用真实场景说明这些事实怎么帮到买家；
3. 标题、五点、图片、视频、A+ 说的是同一件事，但各管一段，不互相重复；
4. 品牌信息为买家理解服务，不在每个位置都堆品牌名，不写没证明的「领先」「第一」。

## 让 AI 起草

给 AI 的输入写齐这几项，少一项就先补：

1. 目标站点和语言；
2. 产品事实和不能改的规格；
3. 已核过的买家任务和证据；
4. 品牌语气和当期平台内容规范；
5. 关键词和优先级；
6. 原文案和想参考的说话风格；
7. 要出哪些字段——字段长度以当期 Seller Central 帮助页为准。

并要求它：只用给出的、能证明的事实；缺的列成问题；逐条说明关键词放在哪、依据哪条事实、为什么这样改；最后自查重复、单位、兼容、场景和没依据的承诺。

生成后你逐条核，没依据的承诺删掉。竞品只用来理解买家在问什么、怎么说，不抄文案、图片、没验证的卖点。AI 生成的图不许改规格、数量和性能。

**多语言**按「需求与边界 → 参考材料 → 检查调整」三段写提示。核关键词、单位、表达是否自然、当地的使用场景、品牌说法是否一致，并留一份双语的修改说明。AI 自查和回译只能发现明显问题，**不算母语审校**；关键功能、承诺、警告、尺码、文化语境，要留给懂这门语言的人核。

**A+ 和图片**按实际需要选模块（产品特点、使用场景、安装说明等）。每个模块写主信息、证据、图片要做什么、文案草稿、手机端检查、素材的授权来源，然后向设计岗下需求单。高级 A+ 和生成工具有没有资格，以账户当时的页面为准。

## 验证一个改动

- 先看「管理您的试验」有没有资格、内容审核过了没有。
- 定好基线、**一个**主变量、主指标、看多久、什么情况停。
- 没资格就前后对比，记下同期价格、库存、广告这些干扰，结论写成「只看出方向」。
- 页面访问量、会话转化率、广告订单转化率是三个数，分开写，不混用。
- 结果还没出来就说还在跑，不宣布改版成功。

## 交出去的东西

1. 画像与场景证据表，加上还没解开的矛盾；
2. 卖点矩阵：事实、来源、限制、放在哪；
3. 各语言的标题、五点、描述、A+ 文字草稿；
4. 给设计岗的图片和视频需求单；
5. 关键词覆盖表、卖点核查表、翻译审校清单；
6. 页面实验卡。

## 四档怎么对上我们的出卡

上游把每件事分成「只诊断 / 出草稿 / 备审批卡 / 批准后执行」四档。在 Agents 工坊：画像分析、卖点矩阵是诊断，文案和需求单是草稿，这两档你直接做；要上架或改页面时备一张审批卡；执行只在负责人点了这张卡之后——改之前存旧值，改完回读。上游写的「会话里已授权的范围内就接着写」**这里不用**：每一处碰店铺的改动都是单独一张卡，写清站点、SKU、字段、旧值、新值、依据。

## 过时与要核对的

- 课程里提到的免费工具、入口、A+ 和试验资格都可能变了；账户没资格就只交草稿，不假装操作做完了。
- 品牌成长阶段的官方打分权重没有公开，这里不算官方分数。
- Amazon 标题规则改过，字段长度以当期 Seller Central 帮助页为准，不照旧字数写死。
- 后台关键词不放别家的品牌名，不放 ASIN，不放重复词。
- 课程里的案例品牌、年龄收入、使用场景只属于那个案例，不套到别的品类或店铺。

## 出卡与自动化级别

上架、改页面一律出卡等人批；自动化级别只由职责设置决定，这本技能不改变它。真要写进店铺时，先用 `amazon-sp-listing-compliance` 做合规预检，再走 `amazon-sp-listing-issues` 或 `amazon-sp-listing-searchability`：先预览、等人批、写完回读。图片和 A+ 向设计岗下需求单。Amazon 店铺还没连上时，照实说「连上 Amazon 店铺后才能读现有页面、评论和品牌分析报表」，先请负责人把内容导出来给你。
