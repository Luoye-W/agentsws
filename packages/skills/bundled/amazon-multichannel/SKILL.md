## 你做什么

同一批货在 Amazon 和别的渠道一起卖，最怕两件事：超卖，和对不上账。你替负责人**先把每个渠道的商品对上内部 SKU、说清库存归谁管，再规划一个小范围试点，最后按订单逐行对账**。上线同步、改库存、改价格都要负责人批。

官方公布了不等于这个账户已经能用：每个功能都要在账户里核过。

## 要的数与资料

| 要什么 | 说明 |
|---|---|
| 渠道清单 | 哪些渠道、哪个店铺账号、哪个站点 |
| 账户里开了什么 | 商品、库存、订单、价格、退款，各自开没开——逐项看，不从一个开关推断全开 |
| 商品对照 | 渠道商品编号、变体编号、卖家 SKU、内部 SKU、一个报价含几件、套装由哪些件组成、币种 |
| 对照的依据 | 凭什么说这两个是同一个货；名字一样不算，平台商品编号也不等于内部 SKU |
| 库存 | 权威库存池的可售、预留、在途、各渠道安全库存、已接还没发的订单 |
| 履约方式与费用 | 每个渠道允许怎么发货；MCF 和第三方仓的实际费率 |

每个数标来源：店铺实数 / 你给的数 / 推断 / 不知道。重量、费率、库存缺了就写「不知道」，不按 0 算。

## 怎么做

1. 在账户里逐项核对多渠道工具的功能，列一张「开了 / 没开 / 不知道」的表。
2. 建商品对照表，核对变体、件数、套装、单位、币种。对不上的单列出来，不硬配。
3. 每类数据定一个权威系统：库存以谁为准、价格以谁为准、往哪个方向同步、多久一次、冲突听谁的。价格和库存要双向同步，必须先有防止来回覆盖的办法；说不清就只读对账，不同步。
4. 核对每个渠道的履约、包装、物流追踪、取消、退款和配送时效要求。接上了不等于这个渠道允许所有发货方式。
5. 按实际费率算履约成本。MCF 费用不写死，以 Amazon 当期的 MCF 费用说明页为准；第三方仓以合同为准。

## 共享库存怎么算

- **可分配数 = 权威库存池的可售数 − 还没从可售里扣掉的已接未发订单 − 安全库存**
- 已经在可售里扣过的预留，不再扣一次。
- **各渠道上架数加起来不超过可分配数**；同一个仓的货不能每个渠道各算一遍。
- 同步消息到达的顺序可能是乱的：按版本号或时间判断谁新，不让后到的旧消息盖掉新的。
- 断货风险线按可售天数 14 天算；低于这条线，先提醒负责人收紧各渠道的上架数。

## 小范围试点

1. 挑少量 SKU，由负责人批准试点范围。
2. 逐个环节验收：商品对上、下单、库存占用、发货、物流追踪、取消、退款。
3. 没有负责人批准的真实测试，就只写测试计划，**不造订单**。模拟出来的结果标「模拟」，不当成真的。
4. 订单用「渠道 + 订单号 + 行号」当唯一键对账；拆包裹、部分退款要留着件数，不整单覆盖。
5. 写入超时：先去目标渠道查订单和同步记录。分不清成没成功就停下，**不重放可能已经成功的订单**。
6. 准时率、超卖、异常单、费用和净贡献达到负责人定的标准，才扩大范围。
7. 断开连接不等于撤销已经接下的订单：退出前先安排好没发完的订单和库存归谁管。

## 交出去的东西

1. 功能核对表：每个渠道、每项功能开没开、什么时候核的；
2. 商品对照表与依据；
3. 库存和价格的权威表：以谁为准、往哪同步、冲突怎么办；
4. 逐订单差异表；
5. 试点验收记录、费用测算、退出方案。

草稿就是草稿，不说成「已经接通」。

## 四档怎么对上我们的出卡

上游把事情分成「只诊断 / 出草稿 / 备审批卡 / 批准后执行」四档。核功能、对 SKU、对账是只诊断，同步方案、试点计划、退出方案是草稿，这两档你直接做。打开同步、改库存数、改价格、下试点订单，都碰店铺，是第三档：一件事出一张卡，等负责人点。第四档只在点卡以后做：先存下旧值，做完读回来核对。上游写「在批准的范围内试点」，默认批过一次就能接着做，**这里不用**：每一个碰店铺的改动都单独出一张卡。

## 过时与要核对的

- 上游记的是：2026 年 9 月 Amazon 介绍了 Seller Central 多渠道工具，说向美国站卖家逐步开放。计划里的渠道和功能不等于这个账户已经有，以账户里看到的为准。
- 各平台自己的规则（上架、履约时效、退款）以各平台当期规则为准。
- 不同渠道的税费怎么算交给会计或税务顾问。

## 出卡与自动化级别

这本出核对表、对照表和方案，不打开同步、不改库存和价格、不下单。要碰店铺的事一律出卡等人批；自动化级别只由职责设置决定，这本技能不改变它。Amazon 店铺还没连上的时候，照实说「连上 Amazon 店铺后才能读库存和订单」，先请负责人从各渠道后台导出商品、库存和订单表给你。
