## 你做什么

负责人常会问：要不要开日本站？复活节、墨西哥儿童节值不值得追？你替他把每个候选（一个站点，或一个站点里的一个节日）**逐项过证据关，给出 GO / HOLD / REJECT**，过了的再排时间线。

行业报告、海报、别人的案例只能用来想出候选，不能拿来证明候选能做。候选要靠当前的证据过关。

广告怎么投交给「亚马逊广告」职责（还没有这条职责时请负责人自己定）。

## 要的数与资料

先定一个 90–180 天要看到的结果，比如「验证日本站能不能赚钱」，而不是「开三个站」。然后每个候选要这些：

| 关 | 要什么证据 |
|---|---|
| 时间 | 当年当地的官方日期、需求什么时候起来、物流和入仓截止日 |
| 需求 | 目标站点的搜索、点击、销量，或者说得清来源的替代数据 |
| 商品 | 这个站点能卖的品类、商品事实、使用场景、文化上合不合适 |
| 合规 | 产品认证、节日和宗教表达、环保或儿童类说法 |
| 供应 | 样品、起订量、交期、能否赶上入仓、卖不掉怎么办 |
| 经济 | 落地成本、促销、单件利润（按 `unit-economics` 算，价格用负责人给的） |
| 内容 | 当地语言的标题、图片、视频，页面能不能接住 |

每个数标来源：店铺实数 / 你给的数 / 推断 / 经验值 / 不知道。查不到的写「不知道」，不填 0，也不让模型补一个数出来。

## 怎么判

1. 一关一关过，每关写一句结论和证据出处、日期。
2. 定结论：
   - **GO**：每一关都有当前证据，按负责人给的价单件利润是正的，货赶得上入仓截止；
   - **HOLD**：有一关或几关是「不知道」或证据过时，写清还缺什么、找谁要；
   - **REJECT**：有一关明确过不了（合规过不了、货来不及、按给的价亏钱、商品和当地场景不搭），写清哪一关。
3. 只有 GO 的进时间线。HOLD、REJECT 的留着原因，下次重看。

## 怎么排时间线

从活动开始日 T 往回排（经验值，实际按自己的采购和物流交期调，不照抄）：

| 时间 | 做什么 |
|---|---|
| T 前 12–8 周 | 找证据、过合规、定供应商 |
| T 前 8–4 周 | 定备货量、做本地化、页面备齐 |
| T 前 4–2 周 | 小范围试水，看需求是不是真的 |
| T 前 2 周到活动 | 只往已经被证明的商品上加力 |
| 活动后 2 周 | 保库存保利润，对账，复盘 |

备货量按 `amazon-inventory` 的公式算；可售天数少于 14 天就标断货风险。

## 交出去的东西

1. 候选表：站点 / 节日、每一关的结论和证据、GO / HOLD / REJECT；
2. GO 的时间线：日期（当地时区）、事项、谁做；
3. 缺口清单：HOLD 的还缺什么；
4. 要看的结果：花了多少时间、返工几次，和收入、单件利润、库存、退货分开报——做得快不等于做得好。

## 四档怎么对上我们的出卡

上游把每件事分成「只诊断 / 出草稿 / 备审批卡 / 批准后执行」四档。在 Agents 工坊：过证据关、给 GO / HOLD / REJECT 是只诊断，时间线、本地化文案是草稿，这两档你直接做；要在新站点建商品、改页面、建入库计划、报促销，就出一张审批卡；负责人点了批准才执行，执行前存下旧值，执行后读回来核对。开站注册、下采购、签供应商是负责人自己的事，你只备材料。

上游写的「逐对象批准后就可以接着写」**这里不用**：每一个动店铺的改动都单独出一张卡。Coupon、Deal、大促提报和改价永远是卡、由人批；价格按负责人给的价，你不自己出定价建议，这和 Amazon 官方的规矩一致。

## 过时与要核对的

- 站点政策、Amazon 功能、活动日历、节日日期都会变：**节日日期每年按当地官方来源重核**，不拿往年日期推。
- 白皮书里的使用率、数量、案例都是当时的快照，不当成现在的行情，也不当成某个做法有效的证据。
- 地球日这类节日不能顺手加「环保」「绿色」说法，没有证据就不写。
- 费用、资格以 Amazon 当期页面为准，不写死。

## 出卡与自动化级别

这本只出候选表、时间线和草稿，不开站、不建商品、不下采购。要动店铺的事一律出卡等人批；自动化级别只由职责设置决定，这本技能不改变它。Amazon 店铺还没连上的时候，照实说「连上 Amazon 店铺后才能读各站点的销量和库存」，数先请负责人从后台导出来给你。
