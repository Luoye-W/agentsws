> Agents 工坊自带的基础版。这家公司在公司层写了自己的信息监控规矩，以公司层为准；本文只管公司层没写到的地方。

## 什么时候用

信息监控的主来源是 Google 提醒：每条提醒盯一句查询语句，投递到 RSS 之后，工坊每天去拉那条 RSS。用户在配置卡上确认了要盯的清单、点了「让工坊替你建」，并在那张「要在你的 Google 账号里建 N 条提醒」的卡上**同意**之后，你会收到一件事：清单里每一行有行号（`ga_1`…）、查询语句、语言、地区。你在**用户自己的浏览器**里照下面的步骤做，做完调一次 `report_google_alerts` 交代结果。

另一种情况是「读一遍已有的提醒」：只看、不点任何创建 / 修改 / 删除，把每条的查询语句、投递方式、RSS 链接读出来交回去。

- 没有同意过的卡，你在提醒页上点不了任何东西（门禁会拦下，理由是「改你 Google 账号里的提醒要先在卡上同意」）。被拦了就停下照实说，**不要换个法子绕过去**。
- 本技能只管怎么在页面上做、怎么认页面，不给任何动作授权：出卡、同意、自动化级别都由工坊和职责设置说了算。
- 查询语句、语言、地区都以卡上为准，一个字不改；卡上没有的提醒不建。数字类的东西（比如条数）只照卡上和页面上看到的说，不估；要引用品牌的数字只从事实卡里取。

## 每一条怎么建

先 `bsk_page` 打开 `https://www.google.com/alerts`（直接打开这个地址，不要从别的页面点链接进去），然后**一条一条来**，每条之间停一两秒，不并发、不开多个标签同时建：

1. **先查重**：在「我的提醒」列表里找有没有查询语句完全一样的（大小写、引号样式、多余空格不算差别）。
   - 已经有、投递是 RSS：不重复建，直接读它的 RSS 链接，这一行交代成 `existing`。
   - 已经有、投递是邮箱：不重复建，也不在这一趟里改它，这一行交代成 `existing_email`（工坊会另出一张「改成 RSS」的卡）。
2. 在顶上的输入框里填这一行的查询语句（原样）。
3. 点「显示选项」，把下面几项设好：
   - **频率**：即时（先选这个，RSS 那一项才选得上）；
   - **来源**：自动；
   - **语言**：按这一行（`any` = 任意语言）；
   - **地区**：按这一行（`any` = 任何地区）；
   - **数量**：所有结果（默认是「只显示最佳结果」，会漏很多，必须改）；
   - **发送至 / 投递**：RSS 供稿（不许选邮箱）。
4. 点「创建提醒」。
5. 回到列表，找到刚建好的那一条，读它旁边 RSS 图标的链接（`https://www.google.com/alerts/feeds/…`）。读不到链接就算没成，写清原因。

全部做完（或者停下了）再统一交代，不要建一条交代一条。

## 页面上怎么认

Google 会改版，认页面靠下面这些**看得见的字和样子**，不靠固定的元素编号。每次动手前先 `bsk_inspect` 看一眼页面（snapshot 就够），对上了再点。英文界面和中文界面都列了：

| 要找的 | 英文界面 | 中文界面 | 样子 |
|---|---|---|---|
| 新建的输入框 | Create an alert about… | 创建与以下内容相关的快讯 / 提醒… | 页面最上面一个长输入框 |
| 显示选项 | Show options | 显示选项 | 输入框下面一行小字链接，带个向下的小箭头 |
| 频率 | How often → As-it-happens | 发送频率 → 即时 | 下拉框 |
| 来源 | Sources → Automatic | 来源 → 自动 | 下拉框 |
| 语言 / 地区 | Language / Region → Any Region | 语言 / 地区 → 任何地区 | 下拉框 |
| 数量 | How many → All results | 数量 → 所有结果 | 下拉框 |
| 投递 | Deliver to → RSS feed | 发送至 → RSS 供稿 | 下拉框，默认是邮箱地址 |
| 创建 | Create Alert | 创建快讯 / 创建提醒 | 蓝色按钮 |
| 我的提醒列表 | My alerts | 我的快讯 / 我的提醒 | 一行一条：左边是查询语句，右边几个小图标 |
| RSS 链接 | RSS 图标 | RSS 图标 | 橙色小图标，链接地址以 `/alerts/feeds/` 开头 |
| 编辑一条 | 铅笔图标 | 铅笔图标 | 点开后出现和「显示选项」一样的几个下拉框，按钮变成 Update alert / 更新快讯 |

判断「投递是邮箱还是 RSS」：那一行旁边有 RSS 图标、链接以 `/alerts/feeds/` 开头 = RSS；没有 RSS 图标、编辑时「发送至」显示一个邮箱地址 = 邮箱。

**认不出就停**：上面的东西有一样对不上（找不到输入框、找不到「显示选项」、下拉框里没有「所有结果」或「RSS」），就停下，不要瞎点、不要猜着试。

## 把已有的改成 RSS

只有卡上写的是「把 N 条提醒的投递改成 RSS」、而且用户同意过，才做这一步：

1. 在列表里按查询语句找到那一条（找不到就这一行交代成 `failed`，原因写「列表里没找到这一条」）；
2. 点铅笔图标，把「发送至」改成 RSS 供稿（频率不是即时的先改成即时），其余几项不动；
3. 点「更新」，回到列表读它的 RSS 链接，这一行交代成 `switched`。

只改卡上那几条：别的提醒不删、不改、不重排。

## 读已有的提醒

只看：打开提醒页，把「我的提醒」列表从上到下读一遍，每条记下查询语句、投递（`rss` / `email`，认不出写 `unknown`）、RSS 链接（只有 RSS 投递才有）。列表很长就往下滚着读完，不要只读第一屏。读完调 `report_google_alerts`，`change_id` 不填，读到的放进 `existing`，`lines` 留空，`stop` 填 `done`。

## 出岔子怎么办

| 看到的 | 怎么做 | 交代成 |
|---|---|---|
| 要登录（Sign in / 登录） | `bsk_assist` 的 request-help，请用户在浏览器里登录好；**不替他输密码** | 处理完接着做；没处理完 `stop: not_signed_in` |
| 验证码、人机验证（unusual traffic / 我不是机器人） | 同上，请用户自己做；不替他点、不绕 | 处理完接着做；没处理完 `stop: captcha` |
| 页面认不出（上面那张表对不上） | 停下，不再往下建 | `stop: page_changed`，`note` 写哪一步对不上 |
| 某一条点了「创建」没反应 / 报错 | 这一条算没成，接着做下一条 | 这一行 `failed`，`reason` 写原话 |

- 已经建好的照常交代（带链接），没轮到的交代成 `not_attempted`。
- **不自动重试第二轮**：没成的交给用户手动贴链接（配置卡上有教程）。
- 用户看到的话里只说「你的浏览器」，不提工具和插件的名字。

## 交代结果

调 `report_google_alerts` 一次：

- `change_id`：任务说明里给的那个（读已有的那一趟不填）；
- `lines`：卡上每一行一条，`id` 用卡上的行号，`outcome` 是 `created` / `existing` / `switched` / `existing_email` / `failed` / `not_attempted`，读到了就带 `feed_url`，没成带一句 `reason`；
- `existing`：顺手读到的账号里已有的提醒（可选）；
- `stop`：`done` / `not_signed_in` / `captcha` / `page_changed` / `other`，停下了写一句 `note`。

工具回来的那段话（建好几条、哪几条没成、要不要另出卡）原样转述给用户，不加不减，不说「全部成功」除非工具这么说。
